# 功能使用情况分析 业务规则

> 基于 [SKILL.md](../SKILL.md) 整理后端判定口径与边界处理。

## 1. 埋点上报规则

### 1.1 事件类型与触发时机

| 事件类型 | 触发位置 | 功能编码取值策略 |
|----------|----------|------------------|
| `VIEW`（页面浏览） | 路由切换 / 页面可见 | 路由对应的主功能（按功能目录登记的路由精确匹配） |
| `CLICK`（点击） | 已声明功能编码的元素被点击 | 元素上声明的功能编码 |
| `SUBMIT`（提交） | 表单成功提交 / 业务操作调用成功 | 表单根节点声明的功能编码 |

**未声明功能编码的点击不采集**（避免噪声）。

### 1.2 批量与防抖

| 场景 | 规则 |
|------|------|
| 批量策略 | 本地队列 **≤ 20 条或 ≤ 5 秒** 触发一次上报 |
| 防抖 | 同一元素 3 秒内重复触发视为同一次（前端防抖，避免连点污染频次） |
| 失败容错 | 网络异常时事件暂存本地队列，下次加载自动重试 |
| 队列上限 | 500 条，溢出按先进先出丢弃最早记录 |
| 单次上报上限 | 单次上报最多 50 条事件，超出整批拒绝 |
| 限流 | 单用户每秒最多 10 次上报请求，超限拒绝 |

### 1.3 信息来源与信任边界

| 信息 | 来源 | 信任 |
|------|------|------|
| 端类型、页面路由、功能编码、功能名称、事件类型、事件时间 | 前端上报 | 采信前端传值 |
| 账套与用户、角色等身份信息 | 后端从登录凭证注入 | **前端传值不采信**，以登录凭证为准 |

### 1.4 功能编码命名规范

- **格式**：功能编码采用「模块.页面.动作」三段式，全大写、点号分隔；需定位到组件时可扩展为「模块.页面.子区域.动作」四段
- **模块段选取原则**：与菜单权限同源。以本模块为例，父权限 `MENU:RND:MANAGE` 对应编码前两段 `RND.MANAGE`；其他模块（如 `INVENTORY.REPORT.*`、`ANALYSIS.NEG_GP.*`）的模块段为业务域名，与菜单树上一级节点一一对应
- **App 端前缀**：App 端上报的功能编码统一加 `APP` 前缀（**硬性约束，未加为违反规范**），用于区分 Web/App 来源；Web 端不加前缀
- **本模块编码（三条）**：
  - `RND.MANAGE.USAGE_EVENTS.<动作>` —— 事务流水明细页（路由 `/portal/usage-events`，权限 `MENU:RND:MANAGE:USAGE_EVENTS`）
  - `RND.MANAGE.USAGE_REPORT.<动作>` —— 使用情况报表页（路由 `/portal/usage-report`，权限 `MENU:RND:MANAGE:USAGE_REPORT`）
  - `RND.MANAGE.USAGE_CATALOG.<动作>` —— 功能目录管理页（路由 `/portal/usage-catalog`，权限 `MENU:RND:MANAGE:USAGE_CATALOG`）
- **其他模块示例**：
  - Web：`INVENTORY.REPORT.EXPORT`、`ANALYSIS.NEG_GP.QUERY`、`PRODUCT_APPLY.LIST.CREATE_NEW`
  - App：`APP.STORE_REQUEST.PRODUCT.ADD_TO_CART`、`APP.HARDWARE.MANAGE.BATCH_SEND`、`APP.WORKBENCH.NAV.CLICK`
- **入库校验**（建议）：功能目录登记与事件流水写入时，按上述格式校验功能编码——三段或四段、每段以大写字母开头且仅含大写字母 / 数字 / 下划线，可带 `APP` 前缀
- **未注册编码**：上报的功能编码不在功能目录时走「自动注册」（§11），在同一事务内登记，事件流水仍记录真实功能编码。仅当前端未上报功能编码（空值）时记为空、报表归入「未归类」桶
- **埋点方式**：
  - **页面浏览自动上报**：Web 与 App 均在路由 / 页面切换时由 SDK 统一上报页面浏览事件，**不需逐页 / 逐屏手工埋页面浏览**
  - **点击仅对已声明元素采集**：Web 在元素上声明功能编码；App 两种方式二选一——以埋点组件包裹触发元素（单按钮场景，首选），或在点击回调中以函数方式上报（适用于回调内有多个副作用、组件包裹会产生歧义的场景）

## 2. 打标算法（三维度独立判定）

聚合数据源：当前周期内的事件流水，按功能编码分组。

### 2.1 频次标签

按周期内该功能的事件总数与阈值比较判定：事件总数 ≥ 高频阈值为高频（`HIGH`），< 低频阈值为低频（`LOW`），其余为中频（`MID`）。

阈值（固定）：高频阈值 500，低频阈值 50。

### 2.2 人次标签

按周期内使用该功能的去重用户数与阈值比较判定：去重用户数 ≥ 广度上阈值为广（`WIDE`），< 广度下阈值为窄（`NARROW`），其余为中（`MID`）。

阈值（固定）：广度上阈值 20，广度下阈值 3。

### 2.3 角色偏好标签

按角色统计该功能在周期内的事件数，事件数最多的角色为头部角色；头部角色事件数占该功能事件总数之比 ≥ 角色主导比例时判定为角色偏好（`ROLE_BIASED`），并记录头部角色；否则为均衡（`BALANCED`），头部角色仍记录但不展示徽章。

阈值（固定）：角色主导比例 0.70。

### 2.4 边界与约定

| 场景 | 处理 |
|------|------|
| 周期内事件总数为 0 | 不参与打标，打标结果中无该功能 |
| 功能编码为空（未归类） | **不**参与打标 |
| 并列第一（两个角色占比相同） | 按角色编码字典序取第一个，保证幂等 |
| 某条快照缺失 | 下钻用功能目录兜底：事件数 / 用户数仍可计算，三维标签为空，前端展示「—」 |
| 角色在事件发生后被删除 | 仍按事件发生时记录的角色聚合（不回查当前角色） |

## 3. 聚合周期

| 周期 | 起止 |
|------|------|
| `DAY` | 自然日 00:00:00.000 ~ 23:59:59.999 |
| `WEEK`（默认） | 周一 00:00 ~ 周日 23:59 |
| `MONTH` | 自然月首日 00:00 ~ 末日 23:59 |

- 默认使用 `WEEK`，周期不对外开放配置；如需调整需发版。
- **跨周期查询**：路由下钻取与查询区间相交的周期中**最新一期快照**；打标清单默认取当前周期

## 4. 打标重算策略

| 触发时机 | 范围 | 方式 |
|---------|------|------|
| 每日 01:00 定时任务 | 前一日数据 + **滚动覆盖当前周期** | 以「存在即更新」方式写入打标结果 |
| 首次部署 / 数据补录 | 手动触发 | 不提供页面入口，由运维执行补数 |

**关键约定**：阈值采用固定值（见 §2），不对外开放运行时调整；历史快照保留原有标签语义。

## 5. 报表计算规则

### 5.1 KPI 卡

| 指标 | 口径 |
|------|------|
| 总事件数 | 查询区间内的事件条数 |
| 活跃用户数 | 查询区间内的去重用户数 |
| 活跃功能数 | 查询区间内的去重功能数（不含未归类） |
| 角色偏好功能数 | 当前周期打标结果中角色偏好（`ROLE_BIASED`）的功能数 |

### 5.2 趋势图

- 固定按**自然日**切片，即使跨度 < 1 天也至少返回 1 个点
- 双 Y 轴切换：事件数 / 活跃用户数

### 5.3 TOP 功能柱状

- 默认按事件总数降序，取 **Top10**
- 功能编码为空的事件合并为一行「未归类」，参与排名

### 5.4 路由聚合主表

| 列 | 计算 |
|------|------|
| 路由 | 按页面路由分组 |
| 功能数 | 该路由下出现过的去重功能数（未归类桶按 0 计） |
| 事件数 | 该路由下事件总数 |
| 用户数 | 该路由下去重用户数 |
| 占比 | 该路由事件数 ÷ 总事件数，保留 4 位小数 |

### 5.5 路由下钻

- **交互方式**：在路由聚合表当前行下方展开嵌套二级表，不跳转页面
- **触发**：点击操作列「下钻」按钮或表格内置展开 / 收起按钮，切换展开 / 收起
- **数据加载**：展开时按该路由与当前查询区间异步加载
- 返回该路由下全部功能明细（含功能编码为空的一行「未归类」）
- **嵌套表列**：功能编码 | 功能名称 | 事件数 | 用户数
- 三维标签取打标结果的**当前周期**快照，缺失为空

## 6. 流水查询边界

| 场景 | 处理 |
|------|------|
| 未指定时间范围 | 默认近 24 小时 |
| 跨度 > 90 天 | 拒绝查询（避免全量扫描） |
| 路由关键词模糊查询 | 仅支持前缀匹配，不支持任意位置模糊匹配 |
| 功能筛选选择「未归类」 | 筛选功能编码为空的事件 |
| 导出 > 5 万行 | 拒绝直接导出，前端引导至「离线导出中心」（export-center 模块） |

## 7. 权限与可见性

| 能力 | 权限编码 |
|------|---------|
| 埋点批量上报 | 仅校验登录有效 |
| 流水查询 / 导出 | `MENU:RND:MANAGE:USAGE_EVENTS` |
| 使用情况报表 / 路由下钻 / 打标清单 / 功能目录下拉 | `MENU:RND:MANAGE:USAGE_REPORT` |

**授权建议**（最小授予原则）：

- `ADMIN`：三个权限全部授予
- `DATA_ANALYST`：授予 `EVENTS` + `REPORT`
- `WAREHOUSE_OPS`：均不授予（非数据岗位）
- `VIEWER`：仅授予 `REPORT`

**账套隔离**：所有查询必须限定在当前账套内，账套取自登录凭证，不采信前端传值。

## 8. 未归类事件处理

| 场景 | 处理 |
|------|------|
| 上报时功能编码为空 | 功能编码记为空入库 |
| 上报时功能编码不在功能目录 | **不拒绝**，按自动注册（§11）登记后以真实功能编码入库 |
| 报表 / 流水展示 | 功能编码为空的事件独立呈现为「未归类」桶 |
| 打标 | 不参与（跳过功能编码为空的事件） |
| 产品侧处置 | 看到「未归类」数量 → 回功能目录补录 |

## 9. 异常与降级

| 场景 | 处理 |
|------|------|
| 埋点上报超时 | 前端重试 3 次，仍失败暂存本地队列 |
| 单批事件部分字段非法 | **整批拒绝**（前端需保证质量，避免拆分重试逻辑复杂化） |
| 打标任务超时 | 单条重试由任务内部控制，仍失败则置为失败状态并告警 |
| 打标结果为空 | 报表降级，三维标签全部为空，前端展示「尚未生成标签」 |

## 11. 功能目录自动注册机制

功能目录在本模块中不仅作为功能下拉字典，还承担「首次出现即入库」的自动注册职责。

| 维度 | 说明 |
|------|------|
| 触发点 | 埋点事件批量写入事件流水前，在同一事务内执行功能目录自动注册 |
| 注册条件 | 本批事件中出现的功能编码既不在已加载的功能目录中，也不在本批待注册集合中 |
| 写入方式 | 按「账套 + 功能编码」唯一去重，已存在则忽略、不报错 |
| 功能名称兜底链 | 埋点上报值 → 前端自动推导 → 以功能编码占位（运营可在管理页人工补全） |
| 错误处理 | 最佳努力原则：注册失败仅记录告警日志，**不阻塞埋点主链路** |
| 默认值 | 默认启用、排序为 0、所属菜单权限为空（由运营手动关联菜单） |
| 账套 | 与当前登录用户的账套一致；缺省时回退系统默认账套 |

**设计取舍**：自动注册采用同步登记而非异步队列，以降低运维复杂度。

**管理页与自动注册的分工**：自动注册只负责「有就不插、没有就插」的基础登记；人工运营通过功能目录管理页（[page-structure.md §3](./page-structure.md#3-功能目录管理)）补全功能名称 / 所属菜单权限 / 排序并按需启停。两者互不冲突：管理页不开放新增 / 物理删除，避免与自动注册冲突。

## 12. SDK 接入与运维

本节说明双端埋点 SDK 的接入开关、本地模式、紧急熄火、后端限流熔断、新增 / 删除埋点流程与铺点优先级。在「自动注册」（§11）机制下，不另维护前端逐条埋点清单，功能目录即为事实来源。

### 12.1 SDK 首次开启（真实上报）

**Web 端**：SDK 随应用启动自动初始化并挂载全局点击埋点委托，开启后按批量策略（每批 ≤ 20 条 / 5 秒）向后端批量上报。

**App 端**：应用启动时初始化 SDK 并声明端类型为 App；未配置上报地址时走本地模式；应用切到后台时 SDK 自动发送队列中的剩余事件。

### 12.2 本地模式（默认，零网络副作用）

- 未配置上报地址时，Web 与 App 均只将事件输出到调试日志并暂存本地队列，不发起网络请求
- 用途：前端铺点阶段未接后端、非生产环境调试、合规审计期「静默采集」

### 12.3 紧急熄火（运行时，不用发版）

| 端 | 操作 | 效果 |
|---|---|---|
| Web | 在浏览器本地存储写入 SDK 禁用标记后刷新 | SDK 初始化直接退出，零采集零网络 |
| App | 远端下发或本地写入 SDK 禁用标记后冷启动 | 同上 |
| 恢复 | 清除禁用标记后刷新 / 冷启动 | 恢复正常采集 |

**编译期完全移除**（Web）：生产构建关闭 SDK 开关后重新构建，SDK 代码不进入产物。

### 12.4 后端限流 / 应急熔断（配置热更新）

单用户上报限流阈值通过配置中心热更新：

| 场景 | 限流阈值 | 接口行为 |
|---|---|---|
| 正常 | 每秒 10 次（默认） | 单用户 ≤ 10 次/秒正常落库；超限拒绝 |
| 压力偏高 | 每秒 3 或 5 次 | 降低写库压力；超限拒绝 |
| **应急熔断** | **0** | 请求返回成功但全部事件标记为未接收；完全不落库、不触发前端重试 |

修改立即生效，无需重启。前端 SDK 收到「全部未接收」的回执后暂停上报 5 分钟（自愈熔断）。

### 12.5 新增 / 删除埋点流程

**新增——Web**：在触发元素上声明功能编码（大写三段式），不改业务逻辑；首次上报后后端自动注册到功能目录，运营在功能目录管理页补全功能名称即可。

**新增——App（组件包裹首选）**：用埋点组件包裹触发元素，声明功能编码与中文描述。

**新增——App（函数式兜底）**：在点击回调首行上报，必须容错兜底、不阻断业务逻辑。

**删除**：仅需移除页面中的埋点声明或上报调用；功能目录**保留记录**（仅改状态为停用），避免历史数据失联。

### 12.6 铺点优先级与命名检查

| 优先级 | 动作类型 | 原因 |
|---|---|---|
| 高 | 提交 / 保存 / 审核 / 删除 / 导出 / 分享 | 业务价值高，分析核心动作 |
| 中 | 查询 / 筛选 / 重置 / 刷新 | 反映使用频次 |
| 低 | 详情 / 跳转 / 展开 | 页面浏览已自动上报，点击埋点可选 |
| 不铺 | 翻页 / 排序 / 纯 UI 开关 / 关闭弹窗 | 噪声大、价值低 |

**命名检查清单**（参 §1.4）：三段式 / 全大写 / 与同模块动词风格一致 / 与功能目录中同名编码一致。
