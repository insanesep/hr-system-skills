# 功能使用情况管理

> 对应脑图「功能使用情况管理」节点，数据来源三通道：log、前端埋点、db。

面向产品与管理侧的功能分析模块：量化衡量每个功能被使用的程度，支撑产品侧对功能价值的判断、运营侧对用户行为的洞察、管理侧对角色权限包的复核。RBAC 只规定「谁能用」，本模块补上「谁真的在用、用得多还是少」的行为事实层。

## 服务对象与端

- **服务对象**：产品、运营、权限管理员
- **仅 Web 端**：流水查询与统计报表仅管理后台呈现；数据采集覆盖 Web + App 全部业务页面

## 核心逻辑

### 数据源三通道（对应脑图）

| 通道 | 职责 |
| ---- | ---- |
| 前端埋点（主） | 页面浏览与点击事件按协议批量上报（`{MODULE}.{PAGE}.{ACTION}` 三段式功能码，App 加前缀；批量 + 防抖 + 去重策略） |
| log（服务端日志） | 写操作/高风险查询等服务端行为事实（复用统一操作日志类能力） |
| db（业务数据） | 单据/记录创建事实作为功能使用的业务侧佐证 |

### 功能目录自动注册

- 埋点上报新功能码时同事务 `INSERT IGNORE` 落库功能目录（唯一键去重，最佳努力不阻塞主链路）；功能名称走「上报值 → 前端推导 → 功能码占位」三级兜底，运营在管理页人工补全
- 登记一致性硬约束：新增菜单时权限表 / 功能目录 / 前端路由表三处必须同步登记

### 使用报表与打标

- **使用报表**：全局筛选（时间范围 / 端 / 角色 / 功能 / 聚合粒度）驱动 KPI、趋势、TOP 高频功能、角色偏好分布、路由聚合下钻；路由统一到二级，路由聚合表必须含 0 触发项（打未触发标签，支持「仅未触发」筛选）
- **三维度自动打标**：频次（高/中/低）、人次（广度）、角色偏好，固定阈值每日定时重算，结果快照按功能 + 周期唯一；徽章辅助功能去留与权限包复核
- **流水查询**：原始事件按筛选查看、抽屉详情、CSV 导出；用户身份信息一律后端从会话注入，前端不传不信任

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 页面 | 职责 |
| ---- | ---- |
| 事务流水明细 | 原始事件筛选查询、详情抽屉、CSV 导出 |
| 使用情况报表 | 全局筛选 + KPI + 趋势/TOP/角色偏好三图 + 路由聚合下钻（含 0 触发） |
| 功能目录管理 | 自动注册表查询、元数据编辑、启停（不开放新增/物理删除） |

## 关键约束

- 事件流水体量大：保留期与清理策略由运维侧按需执行（删除+优化或归档），不做分区滚动强约束
- 快照 + 实时增量结合：周期性聚合读快照、当日读实时，保证人数类指标精确
- 埋点接入须有紧急熄火与限流熔断开关；新增/删除埋点走登记流程
