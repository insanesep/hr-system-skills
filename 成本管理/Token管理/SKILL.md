# Token 管理

> 对应脑图「Token管理」节点：模型 / 时段 / 用量监控。

面向团队管理者的 AI 用量监控仪表盘：通过模型服务平台（如 Qoder Teams OpenAPI）按组织 → 成员维度聚合 Credits/Token 消耗，回答「总量多少、谁在消耗、消耗的什么模型、什么时候消耗的」。

## 服务对象与端

- **服务对象**：团队管理者、研发主管
- **Web 管理端**：完整分析仪表盘
- **App 端**：元素与 Web 对齐的移动概览（布局自适应）

## 核心逻辑

### 三维度监控（对应脑图）

- **模型维度**：按模型/模型等级分段（如 Auto / 旗舰 / 性能档）统计消耗结构，日消耗趋势按模型堆叠呈现
- **时段维度**：日期范围筛选 + 日消耗趋势（含周环比）；用量透视按日期 × 成员展开
- **成员维度**：KPI（总用量 / 总请求数 / 次均消耗 / 人均用量 / 活跃成员，含周环比）+ 成员 × 模型等级透视表

### 数据规则

- 纯只读分析页，无单据与写操作；数据来自模型服务平台 OpenAPI 的分页拉取（游标与错误码以平台契约为准）
- 用户身份信息由后端从会话注入，前端不传不信任
- 聚合口径（KPI 计算、排序、精度、空值规则）收口于 `references/business-rule.md`（立项后补充），页面不复述

### 用量预警

- 日/周用量超阈值（绝对值或环比突增）时通知管理者；阈值与通知对象可配
- 与 `成本管理/项目成本管理` 联动：Token 成本按周期汇入项目成本的人员成本科目

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 区域 | 职责 |
| ---- | ---- |
| 公共筛选区 | 日期范围 + 成员多选 + 查询/重置，驱动全部视图 |

## 关键约束

- 模型分类桶随平台侧枚举演进，分类映射收口配置而非写死
- 双端元素保持一致，仅做布局适配
