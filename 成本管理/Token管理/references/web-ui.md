# Web 端 UI 描述（Token管理）

> 页面通用硬约束以 busyming-skills-design 的 page-blueprint 页面生成提示词【2. 硬约束】为准，此处仅描述产品侧元信息。

## 页面清单

### Qoder 用量分析

- **页面路径**：`/subapp/devhub/rnd/qoder-usage`
- **权限编码**：
  - 路由：`devhubQoderUsage`
- **页面类型**：`report`
- **区块职责**：
  - 筛选区（公共筛选，驱动全部视图）：日期范围选择器（单个范围控件，默认前 7 天，不含今天，跨度上限见 business-rule.md §1）、部门（单选：全部 / 数字化中心 / 创新业务部，默认全部）、统计范围（单选：研发团队 / 全部成员，默认研发团队）、成员多选下拉（默认当前部门与统计范围交集内全部成员）、查询按钮（主色）、重置按钮
  - 研发团队范围下名单为空或名单内无 Qoder 成员时，筛选区下方展示提示「研发团队人员范围为空或名单内无 Qoder 成员，请到「报告配置 → 人员范围」维护」
  - KPI 卡片行（5 列）：总用量（Credits + 周环比，含口径悬浮说明）、总请求数（次 + 周环比）、次均消耗（Credits/次 + 周环比）、人均用量（Credits + 周环比）、活跃成员（人 + 周环比）
  - 日 Credits 消耗堆叠柱形图：面板标题「日 Credits 消耗趋势」，头部右侧图例为各模型分类；每日一根堆叠柱、按模型分段堆叠（分类归并与配色规则见 business-rule.md §6），Y 轴刻度 0-1000，X 轴为筛选期内每日日期
  - Credits 用量透视表：列 = 成员 | 日期列（按天升序，排序规则见 business-rule.md §3）| 合计；每成员一行 + 合计行
  - 模型用量透视表：面板标题「模型用量透视表」，头部 hint「成员 × 模型等级 · 单位 Credits（保留两位小数） · 复用顶部公共筛选」；列 = 成员 | 模型等级列（排序与空值规则见 business-rule.md §4）| 合计；每成员一行 + 合计行；数值两位小数
- **布局引用**：参见原型 `assets/web/qoder-usage-analysis.html`（页面类型 `report`：整页范例 busyming-skills-design/web/templates/report.html，DOM 依据 skeletons/web/dashboard-multi.vue.tpl）

#### 导航关系

- 来源页：管理后台侧边菜单「研发管理 → Qoder 用量分析」点击进入
- 去向页：无（只读单页，无下钻跳转）
- 返回行为：浏览器返回 / 顶栏面包屑返回上级菜单
- 面包屑：首页 / 研发管理 / Qoder 用量分析（由后台统一布局渲染，页面内不出现）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 查询 | 点击查询按钮 | 否 | 全页面板骨架屏 | 静默刷新全部视图 → 停留本页 | 面板内错误提示条 + 重试按钮 |
| 重置 | 点击重置按钮 | 否 | 无 | 筛选恢复默认（前 7 天 + 部门=全部 + 研发团队 + 交集内全部成员）并自动重查 → 停留本页 | 同查询失败 |
| 切换部门 | 部门单选变更 | 否 | 成员下拉刷新 | 清空已选成员，成员清单与全部视图按新部门重查 | 同查询失败 |
| 切换统计范围 | 统计范围下拉变更 | 否 | 成员下拉刷新 | 清空已选成员，成员清单与全部视图按新范围重查 | 同查询失败 |

#### 三态

- 加载态：各面板骨架屏
- 空态：筛选范围内无事件 → 图表与表格区居中「暂无用量数据」
- 错误态：上游调用失败 → 错误提示条 + 重试，不暴露内部细节
