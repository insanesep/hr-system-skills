# 报告配置 · 数据定义

> 面向产品视角定义研发报告子域实体、字段语义与实体关系；表结构以代码仓为准，不在此描述。
> 业务规则真源见 [business-rule.md](business-rule.md)。

---

## 1. 实体关系

- 项目管理项目与报告范围扩展一对一，基础项目只读引用；项目与人员通过成员关系多对多关联，人员档案不在报告复制
- 报告触发配置对应多个生成任务，研发报告对应多个历史版本；一般成功任务关联一个产出版本，项目进度成功任务关联 FULL、SIMPLE 两个具体版本，可引用内容未变的已有版本
- 项目管理的有效人员和成员关系形成 FULL 及人员产出报告的生成名单快照；项目进度任务另冻结全部成员身份档案供 SIMPLE 按提交唯一识别，随任务及各形态版本留档，不修改成员实体
- 启用项目自动派生「报告范围扩展」，基础资料只读引用 [项目管理实体](../../../研发管理/项目管理/references/data.md#entities)；扩展 key 供报告命名与归档引用，沿用既有「项目标识」字段名
- 报告项（报告类型 + 项目标识）对应一条「触发配置」，驱动定时 / 手动「生成任务」；项目进度报告的周报与月报分别对应独立配置，可同时调度，每次仅一个双形态任务，不按域或形态增加配置
- 一般报告由（报告类型 + 项目标识 + 发报日）唯一确定；研发周报由（报告类型 + 统计区间）唯一确定，每个统计自然周一份，发报日仅作元数据；项目进度报告由（报告类型 + `_all` + 统计周期类型 + 统计区间 + 报告形态）唯一确定，每个自然周或自然月 FULL、SIMPLE 各有独立报告身份、版本序列与当前版本，同周期索引合为一行两形态。历史单组与 历史旧完整版 保留原归档，不转换为 SIMPLE，也不填充简化版缺口

## 2. 报告范围扩展

| 字段名 | 业务含义 | 类型（产品语义） | 必填 | 取值规则 |
|--------|---------|----------------|------|---------|
| 扩展 ID | 报告专属扩展标识 | 标识 | 是 | 系统生成，不作为基础项目 ID |
| 范围类型 | 基础实体类别 | 枚举 | 是 | 项目；历史范围类别随归档保留，不重解释 |
| 稳定项目引用 | 关联项目管理的项目 | 引用 | 是 | 每项目一条扩展，不按名称匹配 |
| key（兼容项目 key） | 报告文件命名与报告项标识 | 文本 | 启用前必填 | 小写字母 / 数字 / 连字符，全局唯一；首次保存锁定，沿用历史 key |
| 分支策略 | 文档一致性与健康度评估的基准分支 | 枚举 | 启用前必填 | `master` / 最近 `release/*` 且防回退落后主干；人员产出与项目进度 Git 统计固定为 `master + feature/*` |
| 启停状态 | 报告扩展启停 | 枚举 | 是 | 项目停用联动停用扩展与触发；历史归档不删除 |
| 创建时间 / 更新时间 | 审计字段 | 时间 | 是 | 东八区 |

项目、仓库及成员关系字段只在 [项目管理实体](../../../研发管理/项目管理/references/data.md#entities) 定义。范围快照留存当次 harness 工程、代码服务仓与来源结果，不另建目录映射，消费规则见 [#consumption](../../../研发管理/项目管理/references/business-rule.md#consumption)。

## 3. 报告触发配置

| 字段名 | 业务含义 | 类型（产品语义） | 必填 | 取值规则 |
|--------|---------|----------------|------|---------|
| 配置 ID | 主键 | 标识 | 是 | 系统生成 |
| 报告类型 | 五类报告之一 | 枚举 | 是 | `WEEKLY_DEV` / `DAILY_DEV` / `CONSISTENCY` / `DOC_HEALTH` / `PROJECT_PROGRESS`，见 [business-rule.md §1](business-rule.md#1-报告类型与文件命名) |
| 项目标识 | 项目维度 | 文本 | 项目维度类型必填 | 范围类报告关联「报告范围扩展」启用数据的项目 key；`PROJECT_PROGRESS` 固定 `_all`，周报与月报各内置一条独立配置行，不随域扩展联动 |
| 定时触发开关 | 是否参与定时调度 | 开关 | 是 | 与手动触发开关至少启用一种 |
| 定时规则 | 调度周期 | 结构化文本 | 定时开关启用时必填 | 周期（每日 / 每周 / 每月）+ 星期或号（每日无需）+ 时间（东八区） |
| 手动触发开关 | 是否允许「立即生成」 | 开关 | 是 | — |
| 类型参数 | 报告类型差异参数 | 结构化文本 | 否 | 一致性校验：回看天数；产品文档健康度：无（每周全量评估）；项目进度报告：统计周期（周 / 月） |
| 启停状态 | 配置整体启停 | 枚举 | 是 | 停用即不再定时触发且手动禁用；历史数据保留 |
| 最近生成任务 ID | 最近一次任务 | 标识 | 否 | 冗余展示字段 |
| 创建时间 / 更新时间 | 审计字段 | 时间 | 是 | 东八区 |

## 4. 报告生成任务

| 字段名 | 业务含义 | 类型（产品语义） | 必填 | 取值规则 |
|--------|---------|----------------|------|---------|
| 任务 ID | 主键 | 标识 | 是 | 系统生成 |
| 触发配置 ID | 归属配置 | 标识 | 是 | 外键关联报告触发配置 |
| 触发来源 | 任务来源 | 枚举 | 是 | `SCHEDULED`（定时到点）/ `MANUAL`（手动立即生成） |
| 范围快照引用 | 本次项目及仓映射 | 引用 | 范围类必填 | 稳定项目引用；`PROJECT_PROGRESS` 固定 `_all`，保存全部可生成域的稳定项目标识、项目名称、仓映射与报告扩展快照，域标签按名称快照展示，更名不改写历史 |
| 生成名单快照引用 | 本次人员与项目关系依据 | 引用 | 人员产出报告、项目进度报告必填 | 来自项目管理；人员产出及 FULL 使用有效配置成员快照，SIMPLE 另用同任务冻结的全部身份档案按有效提交识别；空名单和源缺失区别处理 |
| 全部成员身份档案快照引用 | SIMPLE 的作者识别依据 | 引用 | `PROJECT_PROGRESS` 必填 | 冻结全部成员的稳定标识、姓名、角色及身份别名，不因配置成员关系或启停过滤作者识别，不写回人员实体 |
| 生成批次 ID | 一次双形态任务的独立身份 | 标识 | `PROJECT_PROGRESS` 必填 | 每个新任务取得独立批次 ID，重试为新批次；不从版本号推定，成功关联两个实际版本 |
| 统计区间起 / 止 | 本次统计窗口 | 日期 | 是 | 按报告类型口径计算后随任务入参下发 |
| 状态 | 任务状态 | 枚举 | 是 | `RUNNING`（生成中）/ `SUCCESS`（成功）/ `FAILED`（失败）；项目进度两份生成、校验和渲染均通过后才成功成对发布，任一失败则整个任务失败，不发布半份 |
| 失败原因 | 失败说明 | 文本 | 否 | 失败时必填 |
| 产出报告版本 ID | 一般报告生成产物 | 标识 | 否 | 非项目进度任务成功时关联报告版本 |
| FULL / SIMPLE 产出版本引用 | 双形态具体产物 | 引用 | 项目进度任务成功时必填 | 各含报告身份与版本 ID，允许复用本形态已有版本；两个编号不要求相同，两份重复均复用，仅一份变化仅该形态新增版本 |
| 重试来源任务 ID | 重试链 | 标识 | 否 | 重试产生新任务并关联原任务 |
| 操作人 | 触发者 | 文本 | 是 | 手动触发记操作人姓名；定时记「定时调度」 |
| 开始时间 / 结束时间 | 执行耗时 | 时间 | 是 | 东八区；结束时间为终态时间 |

**关系约束：**

- 同一报告项同时刻仅允许一个 `RUNNING` 任务；项目进度按 `_all` 与统计周期类型控制同一双形态任务，周、月配置独立，不按形态另建进行中任务（见 [business-rule.md §5.2](business-rule.md#52-服务端生成主通道)）
- 任务记录不允许删除（审计留痕）

## 5. 研发报告（主表）

| 字段名 | 业务含义 | 类型（产品语义） | 必填 | 取值规则 |
|--------|---------|----------------|------|---------|
| 报告 ID | 主键 | 标识 | 是 | 系统生成 |
| 报告类型 | 五类报告之一 | 枚举 | 是 | `WEEKLY_DEV` / `DAILY_DEV` / `CONSISTENCY` / `DOC_HEALTH` / `PROJECT_PROGRESS`，见 [business-rule.md §1](business-rule.md#1-报告类型与文件命名) |
| 项目标识（兼容 key） | 报告范围命名标识 | 文本 | 范围类必填 | 范围类报告关联报告范围扩展 key；`PROJECT_PROGRESS` 固定 `_all`，域仅作正文分组 |
| 范围类型 / 稳定项目引用 | 基础项目关联 | 枚举 / 引用 | 单范围类必填 | 只读引用项目管理，历史停用不删除关联；`PROJECT_PROGRESS` 保存全部可生成域快照，无单组关联 |
| 报告标题 | md 首个一级标题 | 文本 | 是 | 缺失时以「类型名 + 发报日」兜底 |
| 发报日 | 报告生成日期 | 日期 | 是 | 服务端生成时由任务给定；推送与补传取自文件名 `yyyyMMdd`，不可晚于今天 |
| 所属周起 | `WEEKLY_DEV` 与项目进度周报两形态取统计自然周周一，文档一致性与健康度取发报日所在周周一 | 日期 | 周索引报告必填 | 东八区，供周索引；项目进度 MONTH 月报不填、不入周索引，按统计自然月归集 |
| 所属周止 | `WEEKLY_DEV` 与项目进度周报两形态取统计自然周周日，文档一致性与健康度取发报日所在周周日 | 日期 | 周索引报告必填 | 同上；项目进度月报仅入月索引，不按发报日归周 |
| 统计区间起 | 报告统计窗口起点 | 日期 | `WEEKLY_DEV` 与 `PROJECT_PROGRESS` 必填 | 从正文解析；研发周报与项目进度必须满足完整统计周期并与任务窗口一致，否则拒绝入库；日报解析失败可为空 |
| 统计区间止 | 报告统计窗口终点 | 日期 | `WEEKLY_DEV` 与 `PROJECT_PROGRESS` 必填 | 同上 |
| 统计周期类型 | 周期报告的时间粒度 | 枚举 | `PROJECT_PROGRESS` 必填 | 周 / 月；与 `_all`、统计区间及形态共同确定独立报告身份，MONTH 不入周索引 |
| 报告形态 | 项目进度的内容形态 | 枚举 | `PROJECT_PROGRESS` 必填 | FULL 完整版 / SIMPLE 简化版；不增加报告类型，旧单形态归档保留 FULL 形态，不转换 SIMPLE |
| 当前版本 ID / 当前版本号 | 本报告身份实际指向的最新版本 | 引用 / 数值 | 是 | 版本号从 1 起递增；项目进度每形态独立 current 与版本序列，重复内容复用，不以另一形态版本补齐 |
| 来源 | 最近版本的入库通道 | 枚举 | 是 | `GENERATED`（服务端生成）/ `PUSH`（推送上报）/ `MANUAL`（手动补传） |
| 创建时间 / 更新时间 | 审计字段 | 时间 | 是 | 东八区 |

## 6. 报告版本（从表）

| 字段名 | 业务含义 | 类型（产品语义） | 必填 | 取值规则 |
|--------|---------|----------------|------|---------|
| 版本 ID | 主键 | 标识 | 是 | 系统生成 |
| 报告 ID | 归属主表 | 标识 | 是 | 外键关联研发报告 |
| 版本号 | 版本序号 | 数值 | 是 | 本报告身份内从 1 递增，项目进度两形态独立，不要求同批编号相同 |
| 报告形态 / 归档标识 | 本版本内容归属 | 枚举 / 标识 | `PROJECT_PROGRESS` 必填 | 与所属 FULL 或 SIMPLE 报告身份一致；旧完整版保留 历史旧完整版，不转换或生成 SIMPLE |
| 首次来源批次 ID | 本版本首次生成的来源 | 标识 | 新生成项目进度版本必填 | 仅记录首次来源，后续任务复用不改写；补传和历史无可核验来源时保留实际来源，不伪造双产物批次 |
| 本期概览快照 | 本形态已计算的概览及覆盖信息 | 归档快照 | 新生成项目进度版本必填 | 与本形态正文共用冻结结果，渲染和查阅不重算、不从另一形态补值 |
| 同形态上期 / 回看基线快照 | 比较依据与结果 | 归档快照 | 新生成项目进度版本必填 | 上一自然周或月的同周期类型、同形态 current 实际版本，或本形态冻结范围回看事实；保留来源引用、首次来源批次、覆盖与缺失原因，不跨形态借值 |
| 范围 / 名单快照引用 | 当次生成范围与人员依据 | 引用 | 按报告类型必填 | 与任务同源留档；FULL 保留有效配置成员与关系，SIMPLE 保留全部身份档案与提交挂靠依据，外部会话随产物关联，不按当前实体或名单改写历史 |
| 原始文件名 | 入库时的文件名 | 文本 | 是 | 原样保留，沿用既有 key 与 `_all` 命名 |
| 文件存储键 | 原始 .md 的对象存储位置 | 文本 | 是 | 只存键不存内容 |
| 渲染产物存储键 | md 渲染后 HTML 的对象存储位置 | 文本 | 是 | 入库时生成，见 [business-rule.md §6](business-rule.md#6-markdown-渲染规则) |
| 大纲目录 | 从渲染产物提取的章节目录 | 结构化文本 | 否 | h2/h3 锚点列表，正文为空时为空 |
| 文件哈希 | 内容指纹 | 文本 | 是 | 推送上报幂等判重依据 |
| 文件大小 | 原始文件字节数 | 数值 | 是 | ≤ 2MB |
| 来源 | 本版本入库通道 | 枚举 | 是 | `GENERATED` / `PUSH` / `MANUAL` |
| 操作人 | 入库触发者 | 文本 | 是 | 服务端生成记「生成服务」；推送上报记外部生成方标识；手动补传记上传人姓名 |
| 入库时间 | 版本创建时间 | 时间 | 是 | 东八区 |

**关系约束：**

- 版本从属于报告，删除报告版本不被允许（审计留痕）
- 报告的「来源 / 当前版本 ID / 当前版本号」始终跟随本报告身份的最新版本；项目进度 FULL 与 SIMPLE 的 current 独立，不混用同编号版本
- 生成任务成功必须引用实际产出版本；项目进度成功批次必须同时引用 FULL、SIMPLE 的具体报告及版本，可有不同编号，多个任务可复用同一已有版本。批次保存本次两个引用，版本保留其首次来源批次、概览与基线，不因复用改写
- 两形态均完成生成、命名与窗口校验、正文校验及渲染后才成对发布，任一失败不产生新可查版本或半份 current；两份内容不变均复用，仅一份变化只递增该形态，单形态补传只修正所选身份，不伪造成功双产物批次

## 7. 报告统计人员范围

只读引用 [项目管理有效成员范围](../../../研发管理/项目管理/references/business-rule.md#report-scope)、[身份](../../../研发管理/项目管理/references/business-rule.md#identity) 与 [项目成员关系](../../../研发管理/项目管理/references/business-rule.md#membership)。本模块不保留人员实体或维护表单。

快照保留人员稳定标识、角色、姓名/别名依据及所属项目关系，随任务和报告版本留档。人员产出周/日报及 Qoder 产研团队仍使用全部启用项目有效成员去重并集；项目进度 FULL 以各项目有效配置成员为候选，仅保留窗口内有本项目有效提交且经作者识别和校验的人员。SIMPLE 使用同任务冻结的全部身份档案唯一识别映射仓有效提交作者，包含非配置作者；未知或多重匹配作者提交保留项目总量，仅作审计与待核对人数，不公开名单、不计入角色指标。两形态均不从 Git 建立、迁移或修改成员关系和启停，产品、研发与架构各自按稳定人员标识去重，不跨角色相加。

成员明确为空与来源未取得区分；人员产出空名单或未取得仍拒绝生成，FULL 在成员与 Git 来源完整且确认无有效提交人员时团队计 0，零人数的人均指标为 ASCII「-」；SIMPLE 不展示个人明细，Git 完整且无提交时对应人数、提交为 0，身份未知保留待核对人数。成员身份、角色或 Git 来源不完整时相关团队、角色及提交指标标「未取得」，不以配置人数或部分合计兜底。FULL Qoder 继续按有效配置成员取数，不按 Git 作者集合过滤；SIMPLE 只在概览对提交挂靠且唯一识别的人员按角色、稳定人员及自然日来源快照去重，不按项目分摊，不展示个人用量、未取得人员列表或个人周报弹窗。SIMPLE 整体未取得为「-」，部分覆盖保留已取得合计、覆盖人数及非全量说明，明确零值为 0；其余身份、零用量及部分覆盖规则引用 [共享人员规则](business-rule.md#33-统计人员范围)。项目仓 Git、需求吞吐及仓库清单保持自身范围，人员产出与 FULL 名单外不计入个人产出、不点名。
