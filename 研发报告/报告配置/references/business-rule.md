# 报告配置 业务规则字典

> 本文件为研发报告子域的规则真源：报告类型与命名、周期归属、触发生成入库、版本、渲染、权限、异常场景，以及本模块承载的报告范围配置与报告触发配置。各报告模块 SKILL.md 仅做导航，规则细节全部在此。

---

## 1. 报告类型与文件命名

子域固定承接五类报告，类型枚举不变。**范围集合不写死**：范围类报告由「报告范围配置」生效数据驱动（见 §3）。报告「项目维度/项目标识/项目key」用于报告项命名，基础归属以项目管理的稳定项目引用确定，不另建项目实体；文件名继续使用已锁定 key，不按 key 或名称猜测仓范围。故障报告仍为人工事件闭环，不新增为第六类自动报告。

| 类型编码 | 报告名称 | 项目维度 | 标准文件命名 | 内容梗概 |
|---------|---------|---------|-------------|---------|
| `WEEKLY_DEV` | 研发周报 | 无 | `weekly_dev_{yyyyMMdd}.md` | 提交统计、AI 分析总结、按人员分析、功能进展追踪、仓库分布、功能使用量（数据可得时）、MCP 工具用量（数据可得时） |
| `DAILY_DEV` | 研发日报 | 无 | `daily_dev_{yyyyMMdd}.md` | 前一自然日产出摘要：提交统计（次数与行数）、按人员分析、功能排期卡片流转、Qoder 用量（统计日自然日快照） |
| `CONSISTENCY` | 文档一致性校验 | 有（项目 key） | `consistency_{yyyyMMdd}_{项目key}.md` | 按项目校验全模块文档与代码对齐 |
| `DOC_HEALTH` | 产品文档健康度 | 有（项目 key） | `doc_health_{yyyyMMdd}_{项目key}.md` | 全量评估需求文档质量、仓库治理、环比与修复建议 |
| `PROJECT_PROGRESS` | 项目进度报告 | 无（固定 `_all`，项目组仅作正文分组） | `progress_{yyyyMMdd}__all.md` | 单份周期报告，按组展示项目核心进展、团队人员、功能排期、代码提交与 Qoder 使用，按仓库展示 harness 文档健康度 |

**固定标识 `_all`**：仅 `PROJECT_PROGRESS` 使用，是其唯一新生成报告项，不对应单个基础项目；实际范围为全部可生成项目组的去重并集（§3.2）。真实 key 不含下划线，不可占用 `_all`；`_all` 本身不命中范围扩展，但必须核验全部参与范围，空范围不生成。历史单组报告仍可查阅，不再按组生成新报告。

**文件命名判定规则：**

- `yyyyMMdd` 为**发报日**（报告生成日期），非统计区间
- 服务端生成落库时，报告类型、项目标识与发报日由生成任务直接给定，文件名按上表规范生成
- 推送上报与手动补传入库时按文件名解析类型、项目与发报日；范围类报告的项目 key 必须命中「报告范围配置」生效数据，`PROJECT_PROGRESS` 则必须命中固定标识 `_all`，未命中或文件名不符合上述模式时按「无法识别」处理，需人工指定（见 §5.4）
- 历史遗留命名 `consistency_{yyyyMMdd}.md`（无项目后缀）按「无法识别」处理，人工指定类型与项目后兼容入库

## 2. 周期归属与周索引

| 概念 | 定义 | 用途 |
|------|------|------|
| 报告项 | 报告类型 + 项目标识（无项目维度的类型一项即一类） | 触发配置与齐全度统计的最小单位 |
| 发报日 | 报告生成日期 | 文件命名与元信息；研发周报及项目进度报告不以发报日确定唯一报告项 |
| 所属周 | 研发周报及项目进度周报取统计自然周，文档一致性与健康度报告取发报日所在自然周（周一至周日，东八区） | 周索引分组依据；项目进度月报不入周索引 |
| 所属日 | 发报日当日（东八区） | 日索引分组的唯一依据（仅 `DAILY_DEV`） |
| 统计区间 | 仅 `WEEKLY_DEV`、`DAILY_DEV` 与 `PROJECT_PROGRESS` 有：报告正文首部声明的统计窗口 | `WEEKLY_DEV` 与 `PROJECT_PROGRESS` 用于确定唯一报告项及周期索引；其余作为详情页元信息 |

规则：

1. 周索引 = 按「所属周」倒序分组；组内先按类型固定顺序排列：`WEEKLY_DEV` → `CONSISTENCY` → `DOC_HEALTH` → `PROJECT_PROGRESS`，其中 `WEEKLY_DEV` 每个统计周一条，`PROJECT_PROGRESS` 周报每个统计周最多一条 `_all` 报告，月报独立按月索引，不再按项目组排列；`DAILY_DEV` 不入周索引，走日索引 = 按「所属日」倒序逐日成行，当日行固定置顶（未入库也成行）
2. 每周齐全度 = 该周启用触发配置的报告项中已入库份数 / 应入库份数；某报告项缺失时该周标记「待补」，缺口展示快捷入口（立即生成 / 补传，仅 Web 且受按钮权限控制；`DOC_HEALTH` 仅提供立即生成）；日报齐全度按日统计 = 当日已入库 `1/1`，当日未入库展示 `0/1` 但不标「待补」，昨日及更早缺失日标 `0/1 待补`
3. 周标签格式：`2026 年第 36 周（08-31 ~ 09-06）`，周序号按 ISO 8601 周历计算；日索引行标签格式：`2026-10-20 周二`
4. 本周行仅周日（东八区）当天起展示：周中（周一至周六）周索引窗口上界收敛为上周，避免「待补」进行态噪音；研发周报及项目进度周报按统计周归集，周中补跑上周报告立即归入上周，不因当前发报日被隐藏。同统计周再次入库进入原报告项版本流程；统计范围为本周的报告在周日进入索引。日报不收敛：当日行始终置顶展示，无论是否已入库都提供「立即生成 / 补传」快捷入口（受按钮权限与触发配置启停约束；当日快照可持续刷新，重复入库走版本递增）；未入库时灰显「未入库」，齐全度只显示 `0/1` 不标「待补」（当日数据持续产生中）；昨日及更早缺失日灰显「待补」+ 快捷入口
5. 研发周报与项目进度报告必须在正文首部声明可解析的统计区间：周周期为周一至周日的完整自然周，项目进度月周期为完整自然月；统计区间缺失、日期非法、周期不完整或与生成任务窗口不一致时拒绝入库。研发日报统计区间为前一自然日全天，起止同日，报告日期即统计日；日报解析失败时仅元信息降级为「—」，不阻断入库
6. 项目进度月报按统计自然月建立独立月索引，同月重复入库递增原报告项版本，不按发报日拆分；发报日作为元数据展示，不用于周索引分组

## 3. 报告范围配置

### 3.1 职责边界

| 数据 | 真源 | 本模块职责 |
|------|------|-----------|
| 项目清单、状态、harness 工程与代码服务仓 | [项目管理](../../../研发管理/项目管理/references/business-rule.md#source) | 与功能排期共用稳定项目引用，只读消费，不维护基础项目或仓配置 |
| 成员、角色、别名、人员状态与项目成员关系 | [项目成员管理](../../../研发管理/项目管理/references/business-rule.md#membership) | 不设人员维护页签、不复制成员档案；只读消费有效名单 |
| 排期卡片与流水 | [功能排期管理](../../../研发管理/功能排期管理/SKILL.md) | 消费事实，不迁移排期职责 |
| 全局 key、分支策略、报告扩展启停 | 本模块「报告范围配置」生效数据 | 维护报告专属扩展 |

### 3.2 扩展规则

1. 扩展以稳定项目引用关联项目管理的启用项目并自动成行；本页不手工新增或删除基础项目。新行仅为待配置，不表示已经可以报告
2. **key**：范围类报告的文件命名与报告项标识；小写字母 / 数字 / 连字符，全局唯一，**首次保存后锁定**。项目进度报告仅使用固定 `_all`，各组 key 只用于正文排序和范围引用，不生成单组文件
3. **分支策略**：文档一致性与健康度评估的基准分支，二选一：`master` / 最近 `release/*` 且防回退落后主干；人员产出与项目进度的 Git 提交统计固定采用 `master + feature/*`，不随此策略收窄为单分支。key 与分支策略齐备且扩展启用后，才联动对应报告触发配置
4. **范围消费**：遵守 [项目管理消费规则](../../../研发管理/项目管理/references/business-rule.md#consumption)，采用项目配置的 harness 工程与代码服务仓；本页不维护目录范围或另建执行映射，不按名称猜仓
5. 生成时保存稳定项目引用、当次仓映射以及 key、分支策略快照。项目停用同步停用该项目扩展及按项目建立的文档一致性、文档健康度触发，不删除归档；共享 `_all` 和人员产出周/日报触发不随单项目连停，只在下一任务重新计算范围，空范围或空名单按各类型规则处理。恢复保留原 key，核验后再启用扩展。仓读取失败标「未取得」，不当作零提交或项目被删除
6. 已有扩展沿用原稳定项目引用和已锁定 key，不根据更名或成员变更重建报告项；无法核对的历史引用保留归档并标「待核对」，不猜测对应、不复制报告
7. `_all` 取全部项目启用且报告扩展已配置启用范围的并集，按项目、卡片、成员稳定 ID 及源仓稳定 ID + commit SHA 去重后汇总。Qoder 按成员和自然日来源快照去重，各项目明细不直接相加，比率与人均指标按汇总分子、分母重算
8. 新范围不增加报告种类；产品文档健康度仍排除 common/design，其余报告保留自身生成、计数与查阅口径

### 3.3 统计人员范围

唯一真源为 [项目管理成员范围](../../../研发管理/项目管理/references/business-rule.md#report-scope)，身份匹配见 [#identity](../../../研发管理/项目管理/references/business-rule.md#identity)，关系维护见 [#membership](../../../研发管理/项目管理/references/business-rule.md#membership)。成员必须在具体项目内新增或关联，一人可属于多个项目；报告配置不提供新增、编辑、关联或启停成员的操作。

- 人员产出周报、日报与 Qoder 产研团队采用全部启用项目有效成员的去重并集；按稳定成员 ID 去重，不按项目拆分或另建角色名单
- 项目进度报告以该项目有效成员为候选，仅保留统计窗口内在项目映射仓有有效提交的人员进入团队人数与姓名明细；产品、研发与架构按角色分别计数，同人多角色在对应角色各计一次，全量仅保留任一参与项目有有效提交的人员并按人员稳定 ID 去重。人员产出仍按项目仓 Git 事实归集，不能因有提交自动新增或迁移成员
- Git、卡片及 Qoder 人员维度只采用任务创建时的成员和项目关系快照；人员产出报告使用全量去重名单，项目进度报告使用该项目名单。名单外不计入个人产出、不点名；需求吞吐和项目仓库清单保留自身全量口径
- 项目停用、人员停用或本项目关系停用只影响后续生成；人员在其他启用项目的有效关系继续计入并集。外部会话与服务端共用同源快照，归档不按当前名单重新过滤
- 全量名单为空或来源未取得时拒绝生成人员产出报告，提示到项目管理核验；项目进度在成员与 Git 来源完整且确认候选名单为空或无有效提交人员时，团队计 0、人员明细为「无」，研发人数为 0 的人均功能数显示「-」，产品、研发或架构人数为 0 时对应角色人均提交行数显示「-」；成员身份、角色或 Git 来源失败时相关团队与提交指标标「未取得」，不以候选配置人数或部分合计兜底
- Qoder 使用本项目成员，不以 Git 作者集合过滤。同人多项目可在各组重复展示个人用量，不表示按项目分摊；全量按成员与自然日来源快照去重。无账号、身份歧义、记录非法或来源查询失败标「未取得」，不补 0；成功查询且 Qoder 账号、稳定身份均已确认的成员在自然日无快照记录时按无用量明确补 0，部分成员未匹配时保留已匹配成员数据，展示已匹配/总人数与未匹配名单，合计明确标为已匹配成员非全量，仅未匹配成员标「未取得」，不冒充完整团队总量或清空全部用量
- 功能使用量与 MCP 工具用量只有聚合值，不做人员名单过滤，不在按人员章节点名；多角色的职责分析保留各报告自身证据口径，不混算职责

## 4. 报告触发配置

### 4.1 配置项

每个报告项维护一条触发配置，真源为本模块「报告触发配置」页生效数据（变更留痕可溯），不引用仓库内或本机配置文件：

| 配置项 | 说明 |
|--------|------|
| 报告项 | 报告类型 + 项目标识（`WEEKLY_DEV` / `DAILY_DEV` 无项目维度） |
| 触发方式 | 定时 / 手动，至少启用一种，可同时启用 |
| 定时规则 | 周期（每日 / 每周 / 每月）+ 星期或号（每日无需）+ 时间（东八区）；到点自动创建生成任务。计划点短暂不可用时，恢复后在下一计划点之前补跑最近一次，补跑报告的发报日与统计窗口仍按原计划点计算 |
| 类型参数 | 文档一致性校验：回看天数（增量划定检查范围）；产品文档健康度：无类型参数（每周全量评估）；项目进度报告：统计周期（周 / 月） |
| 启停 | 停用即不再定时触发，手动触发同步禁用；历史报告与生成记录保留可查 |

### 4.2 联动规则

项目维度报告类型（`CONSISTENCY` / `DOC_HEALTH`）的配置行随「报告范围配置」联动——扩展启用即按类型各生成一条配置行（默认定时每周），扩展停用同步停用；该类配置行不可手工新增或删除，仅可编辑规则、参数与启停。`WEEKLY_DEV` 与 `DAILY_DEV` 配置行各内置唯一，不随扩展联动；`PROJECT_PROGRESS` 的周报与月报各内置一条独立 `_all` 配置行，分别使用每周 / 每月定时规则，可同时调度、分别生成，不随项目组扩展新增配置行、不可删除，仅可编辑规则与启停。

### 4.3 立即生成与失败重试

- 「立即生成」手动触发创建生成任务，成功反馈后跳转生成记录；同一报告项存在进行中任务时提示并拒绝（见 §5.2）
- 生成记录按配置行归集：触发来源 / 状态 / 统计窗口 / 耗时 / 失败原因 / 产出版本；失败任务可「重试」，重试即新建任务并关联原任务

## 5. 触发、生成与入库

### 5.1 触发入口

触发入口为 §4 触发配置（定时到点或 Web 端「立即生成」），触发配置生效数据是生成流程的输入。

### 5.2 服务端生成（主通道）

1. 触发（定时到点，或 Web 端「立即生成」手动触发）创建生成任务，携带报告项、计划发报日、统计窗口、类型参数、稳定项目引用与仓映射快照；人员产出报告与项目进度报告另带项目管理的人员和成员关系快照。`PROJECT_PROGRESS` 每次触发只创建一个任务，携带全部可生成项目组快照和各项目有效成员，按 §3.2 去重后生成一份按组展示的报告
2. 服务端通过 Qoder SDK 创建生成会话，工作区挂载报告类型对应的生成 skill（研发周报：[`../人员产出报告/references/dev-report.md`](../../人员产出报告/references/dev-report.md)；研发日报：[`../人员产出报告/references/daily-report.md`](../../人员产出报告/references/daily-report.md)；一致性校验：[`../文档一致性报告/references/consistency-report.md`](../../文档一致性报告/references/consistency-report.md)；产品文档健康度：[`../产品文档健康度报告/references/health-report.md`](../../产品文档健康度报告/references/health-report.md)；项目进度报告：[`../项目进度报告/references/progress-report.md`](../../项目进度报告/references/progress-report.md)，各为该类报告生成逻辑唯一真源）；生成所需配置（工作区、项目映射、数据源基址与令牌）由服务端注入
3. 会话产出报告文件由服务端直接落库：校验命名 → 解析标题与统计区间 → 渲染 HTML 并提取大纲（§6）→ 版本递增入库（§5.5）
4. 任务状态机：`生成中 → 成功（关联产出版本）/ 失败（记录失败原因）`；失败任务可在生成记录中重试，重试即新建任务并关联原任务
5. 同一报告项同时刻仅允许一个进行中任务：定时到点时上一任务未完成则本次不并发，后续扫描在宽限窗口内继续尝试；手动触发遇进行中任务时提示并拒绝
6. 生成耗时超上限（2 小时）判定失败，不产出报告版本

### 5.3 推送上报（旁路通道）

外部生成会话（如本地排障重跑）产出的报告经推送上报入库：

- 携带：md 文件、报告类型、发报日（项目类报告带项目标识）
- 服务端按 §1 命名规则二次校验类型与发报日，不一致时**以文件名为准**并记录告警日志
- 幂等：同报告项同发报日同内容（文件哈希一致）重复上报不产生新版本，直接返回已有报告；`WEEKLY_DEV` 与 `PROJECT_PROGRESS` 按统计周期判重，同周期重复上报进入同一报告项的版本流程
- 鉴权失败：401（token 不匹配）/ 403（服务端未配置 token，fail-closed）

### 5.4 手动补传（兜底通道）

- 仅 Web 端开放，权限 `devhubReportUpload`；`DOC_HEALTH` 不开放手动补传，缺失报告通过立即生成或外部生成会话推送上报入库
- 上传时系统按文件名自动识别类型与发报日；识别失败时由用户在表单中手动指定
- 手动补传记录上传人，来源标记为「手动补传」

### 5.5 版本规则

- 唯一键 =（报告类型 + 项目标识 + 发报日）；`WEEKLY_DEV` 例外为（报告类型 + 统计区间），每个统计自然周仅一条报告项，发报日仅作为元数据；`PROJECT_PROGRESS` 例外为（报告类型 + `_all` + 统计周期类型 + 统计区间），每个自然周或自然月仅一条报告项，同周期重复入库 → 版本号递增，旧版本保留可查
- 列表与详情默认展示**最新版本**；详情页可切换历史版本（只读）
- 版本内记录：文件名、文件哈希、来源（服务端生成 / 推送上报 / 手动补传）、入库时间、操作人
- 报告**不允许删除**（审计留痕）；错误入库的报告以新版本修正

### 5.6 文件约束

| 约束项 | 规则 | 超限处理 |
|--------|------|---------|
| 格式 | 仅 `.md`（UTF-8） | 拒绝入库，提示「仅支持 Markdown 文件」 |
| 大小 | ≤ 2MB | 拒绝入库，提示压缩图片或拆分 |
| 标题 | md 首个 `#` 一级标题作为报告标题 | 缺失时以「类型名 + 发报日」兜底 |

## 6. Markdown 渲染规则

1. **渲染时机**：入库时一次性渲染为 HTML 并随版本持久化，Web 详情页与 App WebView 均消费服务端产物，页面仅提供排版样式，不重新渲染原始 Markdown；评分摘要等结构化内容可从原始报告提取，不替代正文渲染。大纲与图片移除口径由同一服务端渲染管线生成，避免端间分叉。
2. **大纲提取**：从渲染产物的 `h2` / `h3` 标题提取锚点目录，详情页侧边（Web）/ 抽屉（App）展示，点击滚动定位；项目进度报告 Web 详情不展示大纲，正文占满内容区宽度
3. **安全**：渲染产物必须经 XSS 白名单过滤（仅保留排版标签与表格 / 代码块 / 列表），剥离 `<script>`、内联事件与外部资源引用；md 中的图片若为外链直接丢弃并占位「[图片已移除]」
4. **表格与代码块**：表格横向滚动容器包裹；代码块保留语言标记与等宽字体，不换行
5. 重新渲染仅发生在管理端「重新渲染」运维动作（如渲染器升级），不产生新版本号

### 项目进度报告渲染差异

仅适用于 `PROJECT_PROGRESS`，不改变其他报告的大纲与渲染规则；指标、列组合与原件模板以 [项目进度报告 · 呈现与归档规则](../../项目进度报告/references/progress-report.md#呈现与归档规则) 为单源。

- Web 详情不展示大纲，正文占满内容区；表格仅在正文容器横向滚动，首列（项目组 / 仓库）固定，表头按词换行，数值右对齐并使用等宽数字。数值千分位保留原件已有精度、正负号与单位，不处理日期、ID、文件名、链接或缺失符，不修改计量。
- 核心进展单元格保留安全 HTML `ul` / `li` 无序列表，每点正文不超过 50 字，折行悬挂缩进；成功读取后无同周周报、核心进展章节或本项目明确内容为 ASCII「-」，读取异常或边界未知为「未取得」并说明原因。列表正文转义、白名单过滤仍沿用本节安全规则，不接收脚本、内联事件或私有样式。
- 团队人员本期新增标记由生成侧按项目、角色与统计窗口的首次有效提交判定并随版本归档；全量按人员稳定 ID 去重，任一参与项目符合即保留。Markdown 原件仅保留「姓名（新）」纯文本，入库渲染时将该标记转换为姓名旁的公共 `u-success` 文字「（新）」，不使用 Tag 边框、底色或额外标签留白，PNG 使用同一文本；不由前端按加入时间或历史版本推测，具体口径以 [项目进度报告 · 团队人员](../../项目进度报告/references/progress-report.md#章节规范) 为单源。
- 代码提交按产品 → 研发 → 架构各三列连续排列，Qoder 产品与研发表按产品 → 研发各五列连续排列，架构单独表保留五列。原件仍为带角色前缀的平面表头；服务端在入库时按单源中确定的完整列组合生成双层表头并随版本持久化，上层角色分别 `colspan=3` / `colspan=5`，下层指标，首列「项目组」`rowspan=2`。白名单保留这些安全表格合并属性，HTML 与 PNG 均消费完整双层表头，不由前端重组原件、不删指标；未匹配完整组合时保留所有原有列，不猜测分组。
- 健康度较上期正值「↑ +X.X」用公共成功色，负值「↓ -X.X」用公共危险色，零「0.0」用公共中性色，成功读取后无归档、评分待定或不可比为「-」，查询失败、已有 current version 缺失或仓边界未知为「未取得」并说明原因，均不标涨跌；只采用同仓同周可确定单仓域报告中实际入库最新的 current 归档，不混入跨域或子范围；原件、HTML 与 PNG 一致，不改评分公式。
- 统计区间后、六章前的加粗文本「本期概览」不是新增章节；服务端从原件固定「指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比」四行五列表抽取生成时已计算的同版本 `_all` 去重结果、辅助信息及比较结果，并将对比快照随版本持久化，以四个公共 KPI 卡替代详情中的概览表，不重复展示或重算。完成率、延期率合并为功能排期卡，卡内分行展示并各自保留较上期对比，不合并计算；活跃人数合为一张卡，按产品、研发、架构分行展示对应角色的去重人数；仅统计本周期有有效提交的人员，同人多角色在对应角色各展示一次，不将角色人数相加为概览指标；Qoder 用量合为一张卡，按产品、研发、架构分别展示总使用量及对应平均单次 Credits；代码提交行数（+ / -）另设一张卡，按三角色分别展示新增 / 删除行数。角色独立去重、严禁跨角色求和；成功读取后对应角色、列确无归档值为「-」，取数异常仍为「未取得」并说明原因，零人数的人均与零请求的平均单次 Credits 为「-」，已取得零计数或零 Credits 仍为 0；部分合计标「已匹配」而非全量，无权限仍为「无查看权限」。
- 「较上期」的上期为同报告周期类型的上一自然周 / 月，不是历史版本 v-1；当前版本生成时读取上一期同类型 `_all` 全量报告当前归档结果形成对比快照并随本版本归档，版本切换只读各自快照，成功读取后确认无同周期上期、上期原件无概览或角色、列无归档基线时，对应项为 ASCII「-」；查询失败、已有 current version 缺失、成员或仓边界未知、账号或稳定身份未匹配、格式破损不能可靠读取时，受影响项为「未取得」并说明原因，不把失败变成 0 或「-」，也不从旧六章、v-1 或实时来源补值。增减值、百分比公式、单位与角色格式以 [项目进度报告 · 本期概览](../../项目进度报告/references/progress-report.md#本期概览) 为单源；HTML 四卡显示「较上期」及与原件相同的数据，正值用公共成功色、负值用公共危险色、零值用公共中性色，PNG 与 HTML 一致。版本切换时元信息、概览、正文同步切换，不从其他版本或实时来源补值。
- 元信息使用公共 `tpl-overview__meta` 自动响应式多列网格和公共版本下拉，尺寸与入库时间作为次要信息保留，不使用四行 Descriptions；页头保留返回链接与面包屑，右侧仅分页 PNG 导出与获取原件。公共骨架、固定普通分辨率 1600×2000 分页、完整行与表头续页、页码、PNG 打包 ZIP 一次下载及导出期间禁止版本切换等呈现交互以 [项目进度报告 · Web 详情](../../项目进度报告/references/web-ui.md#report-detail) 为真源，不接入异步导出中心，不扩大权限。

## 9. 异常与边界场景

| 场景 | 处理 |
|------|------|
| 某周部分报告项未入库 | 周分组正常展示已入库报告，缺失项灰显「未入库」+ 立即生成 / 补传入口（Web，受按钮权限控制；`DOC_HEALTH` 仅提供立即生成） |
| 日报当日未入库 | 当日行始终置顶展示为「未入库」+ `0/1`（不标「待补」，当日行统计窗口为当日 00:00 ~ 24:00，数据持续产生中），提供立即生成 / 补传入口；昨日及更早缺失日灰显「未入库」+ `0/1 待补` + 立即生成 / 补传入口 |
| 日报当日已入库需刷新 | 当日行保留立即生成 / 补传入口；重新生成或补传按版本递增产生新版本，索引默认展示最新版本 |
| 生成任务失败 | 任务标记失败并记录原因，不产生报告版本；生成记录中可重试 |
| 定时到点时同报告项存在进行中任务 | 本次不并发，后续分钟继续尝试；超过该计划点的下一计划点后不再补跑 |
| 调度服务在计划点短暂不可用 | 恢复后在下一计划点前补跑最近一次，报告按原计划发报日归档；不回溯多个周期 |
| 触发配置在计划点之后变更 | 本周期不补跑，变更从下一个计划点起生效 |
| 触发配置停用 | 不再定时触发且手动生成禁用；历史报告与生成记录保留可查 |
| 项目管理新增或启用项目 | 报告范围扩展自动成行，key / 分支策略待补（标「待配置」），不立即生成报告 |
| key 重复或格式非法 | 拒绝保存并提示；首次保存后不可改 |
| 人员身份存在冲突 | 按人员真源 #identity 裁决；报告不按名单顺序归人 |
| 全量有效成员范围为空或真源未取得 | 人员产出报告拒绝生成，提示核验项目管理成员关系；Qoder 团队范围返回空并标明原因，不扩大为组织全量 |
| 名单内人员无 Qoder 账号、身份歧义、记录非法或来源查询失败 | 标「未取得」，不补 0；成功查询且账号、稳定身份均已确认的自然日缺行按无用量补 0，部分成员未匹配时保留已匹配成员数据并标注非全量合计与未匹配名单，仅未匹配成员标「未取得」，不冒充完整团队总量或清空全部用量 |
| 项目停用 | 扩展及关联触发同步停用，项目成员退出后续有效范围；其他启用项目关系和历史归档保留 |
| 仓来源不可达 | 对应事实标「未取得」，不当作零提交或项目删除，不擅自改选仓 |
| 历史项目引用无法核对 | 只保留原归档及稳定引用，未核对不生成，不按名称猜测或复制到其他项目 |
| 扩展停用 | 关联触发配置行同步停用（不再定时触发且手动禁用）；历史报告与生成记录保留可查 |
| 发报日落在未来 | 拒绝入库（防文件名笔误），提示「发报日不可晚于今天」 |
| 补传 / 推送项目进度报告文件标识为 `_all` | 按唯一周期总报告入库，不校验单组 key；其他类型使用 `_all` 或项目进度报告使用单组 key 均按「无法识别」处理，历史单组归档除外 |
| 同一统计周出现两个不同发报日的同报告项报告（如周一补发） | 研发周报与项目进度报告不按发报日拆分，同统计周期进入同一报告项的版本流程；文档一致性与健康度报告仍按发报日独立归档 |
| 研发周报或项目进度报告的统计区间缺失、非法或与任务窗口不一致 | 拒绝入库并说明统计周期或窗口错误，不生成报告版本 |
| md 正文为空或仅标题 | 研发周报与项目进度报告因缺少必需统计区间拒绝入库；其它类型按自身入库校验处理，允许入库的空正文展示「报告内容为空」 |
| 服务端生成、推送上报与手动补传并发同唯一键 | 以先落库者为当前版本，后到的递增为新版本，不报错 |
| 时区 | 全部日期口径为东八区；周归属、发报日均按东八区零点切分 |
