# 报告配置 业务规则字典

> 本文件为研发报告子域的规则真源：报告类型与命名、周期归属、触发生成入库、版本、渲染、权限、异常场景，以及本模块承载的报告项目配置与报告触发配置。各报告模块 SKILL.md 仅做导航，规则细节全部在此。

---

## 1. 报告类型与文件命名

子域固定承接四类报告，类型枚举不可扩展（新增报告类型须先改本字典）。**项目集合不写死**：项目维度报告的报告项由「报告项目配置」生效数据驱动（见 §3）：

| 类型编码 | 报告名称 | 项目维度 | 标准文件命名 | 内容梗概 |
|---------|---------|---------|-------------|---------|
| `WEEKLY_DEV` | 研发周报 | 无 | `weekly_dev_{yyyyMMdd}.md` | 提交统计、AI 分析总结、按人员分析、功能进展追踪、仓库分布、功能使用量（数据可得时）、MCP 工具用量（数据可得时） |
| `DAILY_DEV` | 研发日报 | 无 | `daily_dev_{yyyyMMdd}.md` | 当日实时产出摘要：提交统计、按人员分析、卡片流转；用量类指标当天未入库，不含该维度 |
| `CONSISTENCY` | 文档一致性校验 | 有（项目 key） | `consistency_{yyyyMMdd}_{项目key}.md` | 按项目校验全模块文档与代码对齐 |
| `PROJECT_PROGRESS` | 项目进度报告 | 有（项目 key；`_all` 为全部项目汇总） | `progress_{yyyyMMdd}_{项目key}.md` | 排期进度总览、需求吞吐、实施进度、延期清单、发版回顾 |

**保留项目标识 `_all`**：仅 `PROJECT_PROGRESS` 可用的虚拟项目维度，含义为「全部启用项目汇总」。真实项目 key 格式（小写字母 / 数字 / 连字符）天然不含下划线，`_all` 不可被真实项目占用；`_all` 报告项不校验「报告项目配置」命中，其生成入参 = 全部启用项目的映射集合。

**文件命名判定规则：**

- `yyyyMMdd` 为**发报日**（报告生成日期），非统计区间
- 服务端生成落库时，报告类型、项目标识与发报日由生成任务直接给定，文件名按上表规范生成
- 推送上报与手动补传入库时按文件名解析类型、项目与发报日；项目 key 必须命中「报告项目配置」生效数据（保留标识 `_all` 除外），未命中或文件名不符合上述模式时按「无法识别」处理，需人工指定（见 §5.4）
- 历史遗留命名 `consistency_{yyyyMMdd}.md`（无项目后缀）按「无法识别」处理，人工指定类型与项目后兼容入库

## 2. 周期归属与周索引

| 概念 | 定义 | 用途 |
|------|------|------|
| 报告项 | 报告类型 + 项目标识（无项目维度的类型一项即一类） | 触发配置与齐全度统计的最小单位 |
| 发报日 | 报告生成日期 | 报告的唯一日期身份 |
| 所属周 | 发报日所在的**自然周**（周一 00:00 ~ 周日 24:00，东八区） | 周索引分组的唯一依据 |
| 所属日 | 发报日当日（东八区） | 日索引分组的唯一依据（仅 `DAILY_DEV`） |
| 统计区间 | 仅 `WEEKLY_DEV`、`DAILY_DEV` 与 `PROJECT_PROGRESS` 有：报告正文首部声明的统计窗口 | 详情页元信息展示，不参与分组 |

规则：

1. 周索引 = 按「所属周」倒序分组；组内先按类型固定顺序排列：`WEEKLY_DEV` → `CONSISTENCY` → `PROJECT_PROGRESS`，同类型多份报告中 `_all` 汇总报告固定排最前，其余按项目 key 字典序排列；`DAILY_DEV` 不入周索引，走日索引 = 按「所属日」倒序逐日成行
2. 每周齐全度 = 该周启用触发配置的报告项中已入库份数 / 应入库份数；某报告项缺失时该周标记「待补」，缺口展示快捷入口（立即生成 / 补传，仅 Web 且受按钮权限控制）；日报齐全度按日统计 = 当日已入库 `1/1`，缺失 `0/1 待补`
3. 周标签格式：`2026 年第 36 周（08-31 ~ 09-06）`，周序号按 ISO 8601 周历计算；日索引行标签格式：`2026-10-20 周二`
4. 本周行仅周日（东八区）当天起展示：发报日为周日，周中（周一 ~ 周六）窗口上界收敛为上周，避免「待补」进行态噪音；周中已提前入库的本周报告随周日到来自然可见。日报同理收口：当日行仅已入库时展示，未入库不渲染「待补」（当日数据持续产生中），昨日及更早缺失日灰显「待补」+ 快捷入口
5. 研发周报与项目进度报告的统计区间从 md 正文首部引用块解析（`统计区间：YYYY-MM-DD（周一）~ YYYY-MM-DD（周日）`）；研发日报为当日实时窗口（`统计区间：YYYY-MM-DD ~ YYYY-MM-DD（当日实时，生成时截断于 HH:mm）`，起止同日）；解析失败时元信息降级为「—」，不阻断入库
6. 月周期的项目进度报告按发报日归入所属自然周，统计区间在元信息中原样展示

## 3. 报告项目配置

### 3.1 职责边界

| 数据 | 真源 | 本模块职责 |
|------|------|-----------|
| 项目 ↔ harness 工程 / 代码服务仓 / 项目启停 | [`排期管理/功能排期`](../../../排期管理/功能排期/references/business-rule.md) §9 项目配置 | 只读引用，不复制、不另建 |
| 项目 key、分支策略（报告侧扩展） | 本模块「报告项目配置」页生效数据（变更留痕可溯） | 维护 |

### 3.2 扩展规则

1. 功能排期侧的**启用项目**自动在本模块成行（只读展示基础映射），不手工新增或删除行；基础映射在功能排期侧停用 → 本行扩展同步停用；重新启用 → 扩展保留原值，待人工确认后启用
2. **项目 key**：报告文件命名与报告项标识锚点（见 §1 命名规则）；小写字母 / 数字 / 连字符，全局唯一；**首次保存后不可改**（历史归档文件以其为锚，改动导致历史无法识别）；保留值 `_all`（全部项目汇总标识）不可被真实项目占用（格式校验天然拒绝下划线）
3. **分支策略**：统计基准分支，二选一：`master` / 最近 `release/*` 且防回退落后主干
4. 扩展未配置（缺项目 key 或分支策略）或已停用的项目**不参与项目维度报告**：不联动生成触发配置行（§4.2），推送 / 补传入库时项目 key 未命中按「无法识别」处理（见 §1）
5. 项目维度报告的生成入参 = 功能排期基础映射（harness 工程 + 代码仓清单）+ 本模块扩展（项目 key + 分支策略），两侧任一停用即不生成

### 3.3 统计人员范围

研发周报 / 研发日报与 Token 管理共用一份人员名单，用于限制所有人员维度统计；名单外的 git 作者、排期卡片负责人/开发人、Qoder 成员不计入任何人员维度，也不在报告中出现。

1. **维护项**：姓名（报告展示名，未删除人员中唯一）、别名（可选多个，覆盖 git 作者名/邮箱、Qoder 名称/邮箱、排期负责人名）、启停；变更留痕（更新时间），不提供删除，停用即保留历史
2. **匹配规则**：姓名或别名去掉空白、忽略大小写、忽略括号内职级/岗位后缀（如「张三(高级工程师)」归一为「张三」）后完全相等即视为同一人；同一提交命中多名人员时按名单顺序归入第一个命中人员，避免重复计数
3. **报告口径**：研发周报 / 研发日报的提交数、参与人数、按人员分析、各仓库提交分布、排期卡片、Qoder 用量只统计名单内人员；「团队总用量」= 名单内成员合计。项目级数据（需求吞吐、仓库清单）保持全量，其中人员姓名按名单脱敏（名单外显示「—」）
4. **数据源限制**：功能使用量与 MCP 工具用量接口只返回去重人数等聚合值，不返回人员明细，不做名单过滤，也不在按人员章节中点名
5. **名单为空**：人员产出报告拒绝生成并提示先维护名单；Token 管理「研发团队」范围返回空并提示去配置，「全部成员」范围不受影响
6. **共享账号**：团队共享账号（如 codeup 公共账号）无法归属到个人，按名单过滤时不计入；成员应使用个人 git 身份提交，或在别名中显式维护可归属的标识
7. **外部生成会话**：使用与报告配置一致的名单，不得自行扩大或缩小范围；外部会话产出入库时沿用报告归档规则，不做二次人员过滤

## 4. 报告触发配置

### 4.1 配置项

每个报告项维护一条触发配置，真源为本模块「报告触发配置」页生效数据（变更留痕可溯），不引用仓库内或本机配置文件：

| 配置项 | 说明 |
|--------|------|
| 报告项 | 报告类型 + 项目标识（`WEEKLY_DEV` / `DAILY_DEV` 无项目维度） |
| 触发方式 | 定时 / 手动，至少启用一种，可同时启用 |
| 定时规则 | 周期（每日 / 每周 / 每月）+ 星期或号（每日无需）+ 时间（东八区）；到点自动创建生成任务。计划点短暂不可用时，恢复后在下一计划点之前补跑最近一次，补跑报告的发报日与统计窗口仍按原计划点计算 |
| 类型参数 | 文档一致性校验：回看天数（增量划定检查范围）；项目进度报告：统计周期（周 / 月） |
| 启停 | 停用即不再定时触发，手动触发同步禁用；历史报告与生成记录保留可查 |

### 4.2 联动规则

项目维度报告类型（`CONSISTENCY` / `PROJECT_PROGRESS`）的配置行随「报告项目配置」联动——扩展启用即按类型各生成一条配置行（默认定时每周），扩展停用同步停用；该类配置行不可手工新增或删除，仅可编辑规则、参数与启停。`WEEKLY_DEV` 与 `DAILY_DEV` 配置行各内置唯一，不随扩展联动；`PROJECT_PROGRESS` 另内置一条 `_all`（全部项目汇总）配置行（默认定时每周），同样不随扩展联动、不可删除，仅可编辑规则、参数与启停。

### 4.3 立即生成与失败重试

- 「立即生成」手动触发创建生成任务，成功反馈后跳转生成记录；同一报告项存在进行中任务时提示并拒绝（见 §5.2）
- 生成记录按配置行归集：触发来源 / 状态 / 统计窗口 / 耗时 / 失败原因 / 产出版本；失败任务可「重试」，重试即新建任务并关联原任务

## 5. 触发、生成与入库

### 5.1 触发入口

触发入口为 §4 触发配置（定时到点或 Web 端「立即生成」），触发配置生效数据是生成流程的输入。

### 5.2 服务端生成（主通道）

1. 触发（定时到点，或 Web 端「立即生成」手动触发）创建生成任务，任务入参：报告项、计划发报日、统计窗口（按报告类型口径与计划发报日计算）、类型参数、项目映射（项目类报告；`_all` 报告项的映射 = 全部启用项目的映射集合）
2. 服务端通过 Qoder SDK 创建生成会话，工作区挂载报告类型对应的生成 skill（研发周报：[`../人员产出报告/references/dev-report.md`](../../人员产出报告/references/dev-report.md)；研发日报：[`../人员产出报告/references/daily-report.md`](../../人员产出报告/references/daily-report.md)；一致性校验：[`../文档一致性报告/references/consistency-report.md`](../../文档一致性报告/references/consistency-report.md)；项目进度报告：[`../项目进度报告/references/progress-report.md`](../../项目进度报告/references/progress-report.md)，各为该类报告生成逻辑唯一真源）；生成所需配置（工作区、项目映射、数据源基址与令牌）由服务端注入
3. 会话产出报告文件由服务端直接落库：校验命名 → 解析标题与统计区间 → 渲染 HTML 并提取大纲（§6）→ 版本递增入库（§5.5）
4. 任务状态机：`生成中 → 成功（关联产出版本）/ 失败（记录失败原因）`；失败任务可在生成记录中重试，重试即新建任务并关联原任务
5. 同一报告项同时刻仅允许一个进行中任务：定时到点时上一任务未完成则本次不并发，后续扫描在宽限窗口内继续尝试；手动触发遇进行中任务时提示并拒绝
6. 生成耗时超上限（2 小时）判定失败，不产出报告版本

### 5.3 推送上报（旁路通道）

外部生成会话（如本地排障重跑）产出的报告经推送上报入库：

- 携带：md 文件、报告类型、发报日（项目类报告带项目标识）
- 服务端按 §1 命名规则二次校验类型与发报日，不一致时**以文件名为准**并记录告警日志
- 幂等：同报告项同发报日同内容（文件哈希一致）重复上报不产生新版本，直接返回已有报告
- 鉴权失败：401（token 不匹配）/ 403（服务端未配置 token，fail-closed）

### 5.4 手动补传（兜底通道）

- 仅 Web 端开放，权限 `devhubReportUpload`
- 上传时系统按文件名自动识别类型与发报日；识别失败时由用户在表单中手动指定
- 手动补传记录上传人，来源标记为「手动补传」

### 5.5 版本规则

- 唯一键 =（报告类型 + 项目标识 + 发报日）；重复入库 → 版本号递增，旧版本保留可查
- 列表与详情默认展示**最新版本**；详情页可切换历史版本（只读）
- 版本内记录：文件名、文件哈希、来源（服务端生成 / 推送上报 / 手动补传）、入库时间、操作人
- 报告**不允许删除**（审计留痕）；错误入库的报告以新版本修正

### 5.6 文件约束

| 约束项 | 规则 | 超限处理 |
|--------|------|---------|
| 格式 | 仅 `.md`（UTF-8） | 拒绝入库，提示「仅支持 Markdown 文件」 |
| 大小 | ≤ 2MB | 拒绝入库，提示压缩图片或拆分 |
| 标题 | md 首个 `#` 一级标题作为报告标题 | 缺失时以「类型名 + 发报日」兜底 |

## 6. Markdown 渲染规则

1. **渲染时机**：入库时一次性渲染为 HTML 并随版本持久化（留痕产物 + App 端 WebView 直接取用，避免大文件卡顿与渲染口径分叉）。
   ⚠️ **Web 端例外**：Web 详情页为**前端实时渲染**——按 mdUrl 拉取原始 md，`marked(GFM)` 渲染 + `DOMPurify` 白名单过滤 + GitHub 风格样式内联展示；大纲锚点 `h-{seq}`（h2/h3 文档序）与图片占位「[图片已移除]」口径与服务端渲染保持一致。App 端 WebView 消费服务端渲染产物（产物无样式），GitHub 风格排版在内容加载前注入。服务端渲染管线与 §6.2~§6.5 规则约束 App 端与留痕产物。
2. **大纲提取**：从渲染产物的 `h2` / `h3` 标题提取锚点目录，详情页侧边（Web）/ 抽屉（App）展示，点击滚动定位
3. **安全**：渲染产物必须经 XSS 白名单过滤（仅保留排版标签与表格 / 代码块 / 列表），剥离 `<script>`、内联事件与外部资源引用；md 中的图片若为外链直接丢弃并占位「[图片已移除]」
4. **表格与代码块**：表格横向滚动容器包裹；代码块保留语言标记与等宽字体，不换行
5. 重新渲染仅发生在管理端「重新渲染」运维动作（如渲染器升级），不产生新版本号

## 7. 权限矩阵

| 权限点 | 编码 |
|--------|------|
| 报告配置菜单（报告项目配置 + 报告触发配置） | `devhubReportTriggerConfig` |
| 统计人员范围页签（查看） | `devhubReportTriggerConfig` |
| 统计人员范围页签（新增 / 编辑 / 启停） | `devhubReportTrigger` |
| 人员产出报告菜单（列表 + 详情，周报 / 日报 Tab；日报仅 Web 端） | `devhubMemberOutputReport`（仅授管理层与研发负责人） |
| 文档一致性报告菜单（列表 + 详情） | `devhubConsistencyReport` |
| 项目进度报告菜单（列表 + 详情） | `devhubProjectProgressReport` |
| 故障报告菜单（列表 + 详情） | `devhubFaultReport` |
| 手动补传按钮 | `devhubReportUpload` |
| 扩展维护触发配置管理立即生成失败重试 | `devhubReportTrigger` |
| App 菜单（按报告类型） | `devhubAppMemberOutputReport` / `devhubAppConsistencyReport` / `devhubAppProjectProgressReport` |

- 权限初始化仅登记权限点，**不指定角色**；授权范围由权限体系侧另行配置
- 版本切换、原始文件获取与生成记录查看随菜单查看同权，不单独设权限点

## 8. 术语边界（公共逻辑不引用声明）

| 关键词 | 本子域语义 | 公共逻辑真源 | 结论 |
|--------|-----------|-------------|------|
| 一致性 | 生成会话产出的**文档**一致性校验报告 | `公共数据/数据一致性`（销售 / 库存金额口径） | 语义不同域，不引用 |
| 文件获取 | 单份静态 .md 原始文件签名 URL 直接获取 | `公共功能/导出接入`（异步 Excel 导出中心） | 场景不匹配，不接入 |
| 报告告知 | 报告落库即页面可查，本子域无主动通知需求 | `公共功能/企微应用消息发送` | 不接入 |

## 9. 异常与边界场景

| 场景 | 处理 |
|------|------|
| 某周部分报告项未入库 | 周分组正常展示已入库报告，缺失项灰显「未入库」+ 立即生成 / 补传入口（Web，受按钮权限控制） |
| 日报当日未入库 | 当日行不渲染「待补」（当日实时窗口，数据持续产生中）；昨日及更早缺失日灰显「未入库」+ 立即生成 / 补传入口 |
| 生成任务失败 | 任务标记失败并记录原因，不产生报告版本；生成记录中可重试 |
| 定时到点时同报告项存在进行中任务 | 本次不并发，后续分钟继续尝试；超过该计划点的下一计划点后不再补跑 |
| 调度服务在计划点短暂不可用 | 恢复后在下一计划点前补跑最近一次，报告按原计划发报日归档；不回溯多个周期 |
| 触发配置在计划点之后变更 | 本周期不补跑，变更从下一个计划点起生效 |
| 触发配置停用 | 不再定时触发且手动生成禁用；历史报告与生成记录保留可查 |
| 功能排期新增启用项目 | 报告项目配置自动成行，扩展字段待补（标「待配置」），不联动生成触发配置行 |
| 项目 key 重复或格式非法 | 拒绝保存并提示 |
| 人员姓名重复或别名格式非法 | 拒绝保存并提示「人员姓名必填且不可重复」/「人员姓名或别名格式不正确」 |
| 统计人员范围为空或全部停用 | 人员产出报告生成失败并提示先维护名单；Token 管理「研发团队」范围展示空态与配置入口提示，「全部成员」不受影响 |
| 名单内人员无 Qoder 账号 | 该人员不进入 Token 管理成员筛选，Qoder 用量按 0 处理；报告按名单内实际有数据的人员呈现 |
| 扩展已启用但基础映射被停用 | 扩展同步停用，关联触发配置行同步停用；历史报告保留可查 |
| 扩展停用 | 关联触发配置行同步停用（不再定时触发且手动禁用）；历史报告与生成记录保留可查 |
| 发报日落在未来 | 拒绝入库（防文件名笔误），提示「发报日不可晚于今天」 |
| 补传 / 推送文件项目标识为 `_all` | 按全部项目汇总报告入库，不校验「报告项目配置」命中；仅 `PROJECT_PROGRESS` 允许，其他类型按「无法识别」处理 |
| 同一周出现两个不同发报日的同报告项报告（如周一补发） | 视为两条独立报告，均归入各自发报日所属周，不合并 |
| md 正文为空或仅标题 | 允许入库，详情页展示空态提示「报告内容为空」 |
| 服务端生成、推送上报与手动补传并发同唯一键 | 以先落库者为当前版本，后到的递增为新版本，不报错 |
| 时区 | 全部日期口径为东八区；周归属、发报日均按东八区零点切分 |
