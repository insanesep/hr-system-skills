# progress-report / 项目进度报告生成

> 一句话定位：每个统计周期只生成一份项目进度总报告，采集全部启用域的研发周报核心进展、团队人员、功能排期、Git 提交、Qoder 用量与产品文档健康度，在报告内按域及仓库分组展示。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。

## When to Use

- 用户说「生成项目进度报告 / 项目周报 / 项目月报」
- 在一份周期报告中按域查看项目核心进展、团队人员、功能排期、代码提交与 Qoder 使用，并按仓库查看 harness 文档健康度

## When Not to Use

- 需要定时自动跑 → 由研发报告模块「报告触发配置」承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报（人员维度）/ 一致性检查 → 分别由人员产出报告、文档一致性报告模块的生成 skill 承载

## 参数解析

| 参数 | 取值 | 默认 |
|------|------|------|
| 报告范围 | 固定 `_all`：全部已配置启用域的去重并集 | 服务端与外部会话均不得按组拆分生成 |
| 统计周期 | 周 / 月 | 服务端会话由触发配置的类型参数给定；外部会话默认周 |
| 代码工作区 | 绝对路径 | 服务端会话由服务端注入；外部会话读取 config.yaml 的 `workspace_dir` 并解析为绝对路径 |
| 推送 | 服务端会话固定「不推送，产出回传服务端」；外部会话默认生成后推送，用户说「仅生成」则跳过 | 按会话类型 |

**单份周期报告**：每个统计周期仅生成一份报告，周报每个自然周一份，月报每个自然月一份。`_all` 是唯一新生成报告项与文件名标识，不再按域创建生成任务、触发配置或归档报告；同周期重复生成或补传只递增该报告的版本。

**范围真源**：域展示与统计范围只读采用 [报告配置](../../报告配置/SKILL.md) 中全部已配置启用的报告范围类型、稳定引用与生效配置；域名称只读引用 [项目管理 · 项目配置与来源](../../../研发管理/项目管理/references/business-rule.md#source) 中的项目名称，以稳定项目标识关联，名称快照随版本归档，更名不改写历史；key 同源；项目进度 Git 分支固定为 `master + feature/*`，不随 `branch_policy` 收窄为单分支。外部 `projects.<key>` 仅传递同一范围快照，不另建实体或猜测归属。各组统计边界采用项目管理配置的 harness 工程与代码服务仓快照，不按一级目录拆分项目；未配置仓及跨项目同名实现不混入。卡片归属采用功能排期按源仓与启用项目映射得到的查询投影。新范围配置齐备并启用后加入下一份周期报告的分组，停用后从后续报告移除，不删历史归档。

**人员范围**：只读采用 [项目管理 · 项目成员](../../../研发管理/项目管理/references/business-rule.md#membership) 的配置，不维护第二份人员名单。人员在每个项目内独立维护，同一稳定人员可属于多个项目；当前项目的成员关系和对应稳定人员均为启用（ENABLED）时，才进入该项目的生成名单。配置成员快照只作为候选名单，该域人数取与研发周报同源的 Git 作者识别和程序校验结果，仅纳入统计窗口内有本项目有效提交的人员；不因中文姓名、英文名、拼音或邮箱未与别名完全一致而提前删除作者，不从 Git 创建或自动迁移成员归属。产品人数、研发人数、架构人数按快照角色及人员稳定 ID 分别去重计数，并在人员明细中按角色展示对应人员姓名；角色内按姓名、人员稳定 ID 排序，同人多角色在对应角色各展示一次，跨项目全量并集仅计一人，各角色的全量人数与人员明细也分别按稳定 ID 去重。成员及 Git 来源完整且确认无配置成员或无有效提交人员时人数均为 0、人员明细为「无」；成员关系、稳定人员记录、角色或本项目 Git 来源未取得时，对应人数、人员明细及依赖的人均指标标「未取得」，不使用组织全员或其它项目名单兜底。

**人员快照**：报告项目取报告扩展已配置启用的范围；任务同时携带这些项目各自的启用成员关系、启用稳定人员身份、姓名与角色，以及按人员稳定 ID 去重的全局并集，随报告版本留档，生成与历史查阅不改用实时名单。任务同时携带各项目各角色的本期首次有效提交判定及对应人员稳定 ID，供团队人员「新」标记使用；该判定复用同一 Git 采集与身份校验结果，不在 Web 详情按成员加入时间或历史版本补算。人员稳定 ID 与姓名映射同时供 Web 详情的人员周报查看及 PNG 工作明细附录使用，附录仅保留经提交过滤后进入团队明细的人员；Markdown 原件与 Web 正文中的人员明细仅保留姓名文本，不写入私有链接协议。人员产出周报、日报仍使用配置成员的全局去重并集，不按本报告的域重复生成人员产出；该并集为空或人员真源未取得时拒绝生成人员产出报告。项目进度报告中已确认的空项目名单不拒绝生成，团队人数记 0、人员明细记「无」，人均功能数和对应角色的人均提交行数记「-」。

**汇总与分组**：取全部可生成项目范围及人员并集，先按项目、卡片、人员稳定 ID 及源仓稳定 ID + commit SHA 去重后汇总，不叠加重复源事实；域人员取各项目配置成员快照并按窗口有效提交过滤，全量仅保留任一参与项目有有效提交的人员并按人员稳定 ID 去重，不从 Git 作者创建成员或自动迁移归属。代码提交与 Qoder 使用按产品、研发、架构角色分别统计；同人多角色时，其提交或用量在对应角色分别完整展示，角色指标之间不可相加。Qoder 个人用量在参与的每个项目完整展示，属于人员维度而非仓库分配；`_all` 在各角色内按人员稳定 ID、自然日及来源快照去重，同一用量在同一角色只计一次，禁止累加项目行。除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余各章节仅用一个表格；项目核心进展、团队人员、功能排期、代码提交与 Qoder 使用按项目 key 字典序列域，harness 文档健康度按仓库名字典序列仓库且不设域列；功能排期、代码提交及 Qoder 使用两张表格的末行均以加粗的「全量汇总」展示，团队人员末行以加粗的「全量汇总(去重)」展示，项目核心进展与 harness 文档健康度不设全量汇总；明细不直接相加为总数，完成率、延期率与人均指标由去重后的汇总分子、分母重新计算，不对各组百分比或人均值取平均，也不得对各组人均值求和；全量人均功能数 = 全量功能排期数 ÷ 全量有提交去重研发人数，产品 / 研发 / 架构全量人均提交行数 = 对应角色全量新增与删除行数合计 ÷ 对应角色全量有提交去重人数，产品 / 研发 / 架构 Qoder 人均指标 = 对应角色全量去重 Credits 或请求次数 ÷ 对应角色全量去重活跃成员数，产品 / 研发 / 架构平均单次请求 Credits = 对应角色全量总使用量 ÷ 对应角色全量总请求次数，不对各组次均值求和或取平均。历史单组报告保留原归档，新报告标题统一为「项目进度报告 - {yyyy-MM-dd}」，文件名统一为 `progress_yyyyMMdd__all.md`。

**统计窗口**：

- 周：最近一个以周日收尾的周一~周日（今天是周日则含今天，否则不含）
- 月：上一自然月

## 执行流程

### Step 1 读配置、定工作区

按会话类型取配置（服务端注入 / 外部会话读 config.yaml），确定：工作区绝对路径 `WS`、输出目录、报告扩展已配置启用的全部域映射、各项目启用成员关系及启用稳定人员的身份、姓名与角色快照、全局去重成员并集。两类会话均消费同一配置快照，不以 Git 采集结果重建名单。

**工作区边界**：模型仅可操作本任务约定的 `WS`，不得读取其它位置的开发者副本、采集缓存或凭据。服务端 Git 同步与采集由程序在专用缓存中完成，采用冻结仓库范围、同步后的分支事实与本任务统计窗口；模型只消费已验证的数据，不访问该缓存或重新采集。外部会话的仓库同步与采集仅限其约定工作区；不使用其它同名开发者副本作为证据。

### Step 2 同步仓库

- **外部会话**：对项目映射 `code_repos` 与 `harness_repo` 下每个仓库，仓库缺失时按会话配置 `codeup` 凭证浅克隆（命令不内嵌，按生成环境约定执行）。
- **服务端生成会话**：复用研发周报的确定性 Git 采集程序，在专用缓存中同步冻结范围中的云效仓和基础 Git 仓，按本任务统计窗口采集提交与行数；任务工作区保存输出与核验依据，各任务不回读其它任务的中间结果。采集凭据只供程序使用，不进入作者识别或最终正文会话；模型不执行克隆、同步、分支切换或重新计数。

所有域固定统计 `master + feature/*` 分支，与研发周报口径一致；`branch_policy` 不再把项目进度收窄为 master 或 release 单分支。服务端由程序在专用缓存采集，外部会话仅在 `WS` 内采集，二者均不得使用开发者副本；`wt/*` 不单独纳入，release 不另作统计分支。跨分支按 commit SHA 全局去重，剔除 merge，避免同一提交被重复计数

### Step 3 采集数据

- **功能排期卡片**：外部会话走 MCP 工具（`busyming_feature_schedule`，调用口径、字段与容错见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)），服务端会话由调用方在会话数据中直接提供。采集统计窗口内排期卡、完成时间与排期截止日，并通过卡片操作流水识别窗口内移入非需求改动的卡片；卡片项目归属采用功能排期当前源仓映射的查询投影，一张卡至多归属一个启用项目；合并卡全部子卡同属一个启用项目才归属该项目，否则为未归属项目，不重复分配到各组。`_all` 总计只汇总参与生成项目范围内的卡片并按稳定卡片 ID 去重
- **Git 提交**：外部会话以计数脚本按产品、研发、架构角色输出的提交次数、新增行数与删除行数为权威结果（按映射 `harness_repo` + `code_repos` 的 `master + feature/*` 分支），直接引用，**严禁自己再跑 git log 重新计数**；服务端会话与研发周报共用程序采集、独立作者识别及校验链路；保留全部真实作者，由独立识别阶段依据姓名、邮箱和候选成员别名给出映射，程序校验重复、遗漏和名单外映射并按稳定人员、项目关系及角色汇总。所有提交按 SHA 全局去重、剔除合并、窗口过滤，逐提交计算增删行且排除二进制；各仓小计与角色合计必须打平。最终正文只引用程序权威统计，不重新识别作者或计数。每个角色仅保留已验证到当前项目该角色配置成员的贡献；同人多角色时，其贡献在对应角色分别完整展示，角色指标不可相加。名单外或身份未匹配作者不计入分角色指标、不点名，不从 Git 创建人员或自动迁移项目归属
- **团队人员**：任务中的项目成员关系及稳定人员快照只作为候选名单，校验两者均启用后，按窗口内项目映射仓的有效提交与角色身份过滤；无提交成员从团队人数与人员明细排除，同人多角色分别展示，全量仅保留任一参与项目有有效提交的人员并按稳定 ID 去重。过滤后无人时各角色人数为 0、人员明细为「无」；成员身份、角色或本项目 Git 采集来源未取得时，对应团队人数、人员明细及依赖的人均指标标「未取得」；其它来源完整的项目正常展示，全量源不完整时不以部分项目合计冒充完整总量，不使用组织全员或其它项目名单兜底
- **Qoder 用量**：先取当前项目配置成员快照，再通过稳定身份映射取得这些成员在统计窗口内的自然日快照，按产品、研发、架构角色分别汇总 Credits 与请求次数；服务端会话由调用方注入，外部会话按既定用量接口取数。个人窗口用量在其参与的每个项目及每个已配置角色完整展示，不按仓库分配或推测分摊，角色指标不可相加；全量在各角色内按人员稳定 ID、自然日及来源快照去重，不累加项目行。活跃成员在同一项目、同一角色配置成员集合内沿用 Qoder 用量分析的正 Credits 记录口径并按稳定 ID 去重；已确认空名单时对应角色总量与活跃成员数为 0，成功查询且 Qoder 账号、稳定身份均已确认的成员在自然日无快照记录时按无用量明确补 0；无账号、身份未匹配、记录非法或来源查询失败时标「未取得」，部分成员未匹配时保留已匹配成员数据，展示已匹配/总人数与未匹配名单，合计明确标为已匹配成员非全量，仅未匹配成员标「未取得」，不冒充完整项目或角色总量或清空全部用量
- **项目核心进展**：读取同统计周期内对应自然周实际入库时间最新的 [研发周报](../../人员产出报告/references/weekly-report.md) current version，每周只选一份，月报合并各周内容并去重，不按当前项目 key 优先挑旧报告。只提取「AI 分析总结 → 核心进展」中本项目明确内容；名称匹配同时使用来源报告版本快照中相同稳定 projectId、且仓边界一致的历史 name/key，不依赖当前改名或硬编码同义词，不复制全局或跨项目同名内容。成功读取后无同周周报、无核心进展章节或无本项目明确内容为「-」；读取失败、current version 缺失或项目边界未知为「未取得」并说明原因，不退取旧版本。各组按事实逐点展示，每点正文不超过 50 字，超过时仅在事实边界内拆分；不新增分项目周报配置，不用 Git 或排期卡片推测补写
- **harness 文档健康度**：只读引用 [产品文档健康度报告](../../产品文档健康度报告/references/health-report.md) 归档，不重跑评估。本周为统计截止日所在自然周，上周为上一自然周，周报与月报均取这两周；各周只在可确定的同仓单仓域报告中，采用实际入库时间最新的 current 归档综合分 R，不混入跨域或子范围结果，不平均、不退取旧版本。成功读取但无合格归档、评分待定或不可比时对应得分与差值为「-」；查询失败、已有 current version 缺失、格式破损或仓边界未知时受影响项为「未取得」并说明原因。较上期 = 本周综合分 − 上周综合分，保留 1 位小数；正值「↑ +X.X」、负值「↓ -X.X」、零「0.0」分别使用公共成功、危险、中性色，原件、HTML 与 PNG 一致，不改评分公式。操作链接所选本周报告，无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」。仓库按名字典序排列，仍排除 common/design，不将域分数相加

### Step 4 生成报告

- 按下文章节规范与输出模板生成；全文中文。
- 报告标题：`项目进度报告 - {yyyy-MM-dd}`（生成当天日期）。
- 生成时一次性计算同版本 `_all` 去重汇总及其比率、人均与次均指标，六章汇总行与「本期概览」复用这份结果，不为概览再采集或重新计算。概览及表格的数值格式遵循下文「呈现与归档规则」。
- 当前版本生成时读取上一自然周 / 月同报告周期类型的 `_all` 全量报告当前归档结果，以四行概览归档值为基线计算「较上期」并形成对比快照随本版本归档；不得把当前报告项的历史版本 v-1 当作上期。快照生成后固定，版本切换只读各自快照；上期没有归档概览时，完成率、延期率可引用上期标准功能排期表中唯一、分子分母与比率一致的全量汇总，不拆分旧跨角色合计；其他指标由生成侧复用本次冻结的项目与人员范围，程序采集上一自然周期的排期和 Qoder 事实，并从已验证历史 Git 中按提交时间筛选同窗口、按角色去重，形成同范围回看基线；Qoder 上期必须有对应来源账号各自然日的已落库记录，缺行不能当作零值，卡片完成状态依据期末流水恢复，期后变更无法可靠还原范围时不计算该项。原件明确区分「归档概览」与「同任务范围回看」来源，比较结果与依据随本版本固定，不改写旧报告；两者均无可用事实时才为「-」。已有归档版本断裂、格式破损或事实读取失败时，受影响项保留「未取得」并说明原因；不从旧六章的跨角色合计、v-1 或前端实时数据推算。仅新增展示与归档比较，不改变六章、健康度、统计窗口及人员、代码、Qoder 指标公式。

### Step 5 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`progress_yyyyMMdd__all.md`；新报告不得使用单域 key 命名，服务端按文件名解析类型与日期
- **服务端生成会话**：产出文件回传服务端，由服务端校验、渲染并直接落库（版本递增、周索引），本 skill 不调用推送接口
- **外部会话（旁路）**：推送契约（multipart 表单 + 鉴权头，幂等）见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)；推送后把 `reportId / versionNo / duplicated` 回告用户；推送失败不删本地文件，把错误信息告知用户

## 章节规范

固定章节（顺序不可调换）：项目核心进展 / 团队人员 / 功能排期 / 代码提交 / Qoder 使用 / harness文档健康度。正文首部必须以引用块声明统计区间（归档侧解析元信息用；周期为月时不带括号注释）。每份报告包含全部启用域及健康度归档仓库；除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余每个章节仅使用一个表格。前五章第一列为「域」，表体按项目 key 字典序展示域明细，harness文档健康度第一列为「仓库」并按仓库名字典序排列。功能排期、代码提交及 Qoder 使用两张表格的末行均为加粗的「全量汇总」汇总行，团队人员末行为加粗的「全量汇总(去重)」汇总行，项目核心进展与 harness文档健康度不设全量汇总，不得按组拆成多个表格或单组报告。首列与核心进展、人员明细、操作列左对齐，其余数值列在 Markdown 分隔行用 `---:` 右对齐，Web 正文与 PNG 均按此对齐。

1. **项目核心进展**：仅展示 Step 3 所选同周最新 current 研发周报中本项目明确内容，沿用相同稳定 projectId、仓边界一致的历史 name/key 匹配；成功读取但无周报、无章节或无本项目内容为「-」，读取异常或边界未知为「未取得」并说明原因，不复制全局进展或推测补写。各组单元格保留安全无序列表，折行采用悬挂缩进；每点正文不超过 50 字，超过时仅在事实边界内拆分，不扩写或省略关键信息。原件只保留纯排版列表标记，不写脚本、内联事件或私有样式。
2. **团队人员**：标题下固定展示说明「以本周期有提交记录的人员为准」。本期新增人员是指其在该项目该角色的首次有效提交落在统计窗口内，且窗口开始前无同项目同角色有效提交，由生成侧复用 Git 采集与身份校验结果判定并随版本快照归档，不按成员加入时间或页面猜测；全量按人员稳定 ID 去重，任一参与项目符合即保留标记。HTML 姓名旁以公共 `u-success` 文字样式展示「（新）」，不使用 Tag 边框、底色或额外标签留白；Markdown 与 PNG 以「姓名（新）」表示，标记不改变团队人数、人员周报来源或点击行为。按项目成员关系及稳定人员均启用的任务快照，按人员稳定 ID 和角色分别去重展示产品人数、研发人数与架构人数，并在人员明细中按角色展示具体人员姓名，仅保留统计窗口内在项目映射仓有有效提交且身份匹配对应角色的成员，无提交成员从团队人数与人员明细排除。人员明细角色内按姓名、人员稳定 ID 排序；同人多角色在对应角色各计一次并各展示一次，同人多项目可在各组出现，全量仅保留任一参与项目有有效提交的人员，各角色人数与人员明细按全局成员并集分别去重，汇总行标签固定为「全量汇总(去重)」。源成功且确认空名单或过滤后无提交成员时各人数为 0、人员明细为「无」，成员身份、角色或本项目 Git 来源未取得时，对应人数、人员明细及依赖的人均指标标「未取得」；其它来源完整的项目正常展示，全量源不完整时不以部分项目合计冒充完整总量，不使用组织全员或其它项目名单兜底。
3. **功能排期**：展示功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率、人均功能数。
   - 功能排期数：排期日落在统计窗口内的去重功能卡数，口径与功能排期管理一致，不含非需求改动、待澄清与子卡。
   - 非需求功能数：统计窗口内发生「移入非需求改动」的去重卡片数，按卡片操作流水认定，不计入功能排期数及完成率、延期率、人均功能数的分子或分母。
   - 完成功能数：上述功能排期卡中完成时间落在统计窗口内的卡片数；完成率 = 完成功能数 ÷ 功能排期数 × 100%。
   - 延期功能数：上述功能排期卡中，统计截止时仍未完成且排期截止日不晚于统计截止日的卡片数；延期率 = 延期功能数 ÷ 功能排期数 × 100%。
   - 人均功能数 = 功能排期数 ÷ 项目窗口内有有效提交的去重研发人数。功能排期数为 0 时完成率与延期率无适用分母，显示「-」，功能数仍保留真实零值；研发人数为 0 时人均功能数显示「-」。
4. **代码提交**：按产品、研发、架构分别展示提交次数、提交行数（新增 / 删除）与人均提交行数。各角色提交次数及总行数按项目映射 `harness_repo` + `code_repos` 统计，仅保留身份匹配该项目该角色配置成员的贡献；同人多角色时其贡献在对应角色分别完整展示，角色指标不可相加，名单外或身份未匹配作者不计入分角色指标。提交行数按新增行数与删除行数分别展示；产品 / 研发 / 架构人均提交行数 = 对应角色（新增行数 + 删除行数）÷ 项目窗口内该角色有有效提交的去重人数，对应角色人数为 0 时显示「-」。
5. **Qoder 使用**：仅统计上述项目配置成员，按产品、研发、架构分别展示总使用量、人均使用量、总请求次数、人均请求次数与平均单次请求 Credits。章内先以「产品与研发」三级标题展示产品、研发指标表，再以「架构」三级标题展示架构指标表；两张表格均按域展示并各设全量汇总，不按域拆表。各角色总使用量与总请求次数为该角色配置成员窗口合计，同人个人用量完整展示于参与的每个项目及每个已配置角色，不按仓库分配，角色指标不可相加；全量在各角色内按人员稳定 ID、自然日及来源快照去重，禁止对项目行求和。产品 / 研发 / 架构人均使用量 = 对应角色总使用量 ÷ 该角色 Qoder 活跃成员数，产品 / 研发 / 架构人均请求次数 = 对应角色总请求次数 ÷ 该角色 Qoder 活跃成员数，活跃成员在项目该角色配置成员集合内沿用 Qoder 用量分析的正 Credits 记录口径并去重。产品 / 研发 / 架构平均单次请求 Credits 沿用 Qoder 用量分析的次均消耗口径，等于对应角色总使用量 ÷ 对应角色总请求次数，保留 1 位小数；总请求次数为 0 时显示「-」，全量按全量总使用量与全量总请求次数重新计算，不对各组次均值求和或取平均。配置成员已确认空时对应角色总量及活跃成员数为 0；对应角色活跃成员数为 0 时人均指标显示「-」，成员来源或用量未取得时标「未取得」。
6. **harness文档健康度**：按仓库展示上周、本周得分、较上期与操作，来源选择及缺失、异常语义沿用 Step 3。各周仅取可确定的同仓单仓域报告中实际入库最新的 current 综合分 R，保留 1 位小数，不混跨域子范围。较上期 = 本周得分 − 上周得分；正值「↑ +X.X」用公共成功色，负值「↓ -X.X」用公共危险色，零「0.0」用公共中性色；无归档、评分待定或不可比为「-」，读取异常或边界未知为「未取得」并说明原因。原件、HTML 与 PNG 一致，不改评分公式。操作链接所选本周报告，无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」。本章不设全量汇总，不重跑检查，仍排除 common/design。

比率与人均值保留 1 位小数；Credits 按 Qoder 用量分析口径整数展示；平均单次请求 Credits 保留 1 位小数，总请求次数为 0 时显示「-」。成员来源成功且确认空名单时，团队人数、人员明细、Qoder 总量及活跃成员数按上述规则处理，人均指标为「-」。成功读取后确认无归档内容或指标不适用统一使用 ASCII「-」：同周期上期归档与同冻结范围回看均无可用指标，无同周研发周报、无核心进展章节或无本项目明确内容，无健康度归档、评分待定或不可比，零人数、零请求导致的人均或次均不适用。已取得零计数、零 Credits 仍为 0，不改计量。取数异常、已有报告 current version 缺失、成员或仓边界未知、Qoder 账号或稳定身份未匹配、格式破损不能可靠读取时，受影响项仍为「未取得」并说明原因，不把失败变成 0 或「-」。其它来源完整的项目正常展示，部分数据注明「已匹配」而非全量，不以部分合计冒充全量；Qoder 失败不改变已取得的团队指标，无权限仍为「无查看权限」。

## 呈现与归档规则

### 数值与正文排版

- 计数（人数、功能数、提交次数、请求次数等）、Credits、提交新增 / 删除行数及人均指标的数值整数部分统一使用千分位；平均单次请求 Credits 与概览较上期增减值同样处理整数部分。保留既有小数精度、正负号、单位与百分号，不再次取整或改动计量；新增 / 删除分别格式化。日期、稳定 ID、文件名、链接及「—」「-」「未取得」等缺失标记不处理，不对全文数字做替换。原件、归档 HTML 与 PNG 格式一致，模板中的 N、X、Y、Z 仅代表按此规则格式化后的值。
- 健康度较上期沿用六章中的差值与精度，原件保留「↑ +X.X」「↓ -X.X」「0.0」以及空缺「-」或异常「未取得」；HTML 与 PNG 使用公共成功 / 危险 / 中性色，不仅靠颜色表达方向，空缺与异常不标涨跌，零不添加箭头或正负号。
- 核心进展单元格仅使用安全 HTML `ul` / `li` 列表，完整正文每点不超过 50 字并采用悬挂缩进；成功读取后无同周周报、无核心进展章节或无本项目明确内容为「-」，读取异常或边界未知为「未取得」并说明原因。原件允许纯排版列表标记，不包含脚本、内联事件或私有样式。
- 延续正文表格首列固定、表头按词换行、数值右对齐与等宽数字；域 / 仓库、核心进展、人员明细及操作列左对齐。详情阅读区不设大纲，不能为概览新增章节。

### 角色连续列序与双层表头

Markdown 原件保留带角色前缀的平面表头，列序必须完整匹配以下组合，不删减、合并或重算指标：

| 表格 | 首列 | 角色顺序 | 每个角色内的连续指标顺序 |
|------|------|----------|--------------------------|
| 代码提交 | 域 | 产品 → 研发 → 架构 | 提交次数 → 提交行数（新增 / 删除）→ 人均提交行数 |
| Qoder · 产品与研发 | 域 | 产品 → 研发 | 总使用量（Credits）→ 人均使用量（Credits）→ 总请求次数 → 人均请求次数 → 平均单次请求 Credits |
| Qoder · 架构 | 域 | 架构 | 总使用量（Credits）→ 人均使用量（Credits）→ 总请求次数 → 人均请求次数 → 平均单次请求 Credits |

服务端在入库时按上述确定的完整列组合生成双层 HTML 表头并随版本持久化：上层为角色，代码提交各角色 `colspan=3`，Qoder 各角色 `colspan=5`；下层为对应指标，首列「域」`rowspan=2`。HTML 与 PNG 消费同一完整双层表头；前端不从原件猜测分组、不修改原件或计量、不隐藏指标。未匹配完整组合的表格保留所有原有列，不猜测或伪造双层分组。

### 本期概览

统计区间引用块后、六个固定章节前，使用加粗文本标题「本期概览」，不是第七章，也不是章节标题。Markdown 原件仅放一个「指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比」表，固定四行并按以下顺序展示：

| 指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比 |
|------|--------|----------|--------------|------------------|
| 功能排期（完成率 / 延期率） | 完成率：同版本 `_all` 完成功能完成率<br>延期率：同版本 `_all` 功能排期延期率 | 完成：完成功能数 / 功能排期数<br>延期：延期功能数 / 功能排期数 | 完成率：本期完成率 − 上期完成率<br>延期率：本期延期率 − 上期延期率，均使用个百分点 | 完成率：增减值 ÷ 上期完成率绝对值 × 100%<br>延期率：增减值 ÷ 上期延期率绝对值 × 100% |
| 活跃人数 | 产品：同版本 `_all` 本周期有有效提交的产品角色去重人数<br>研发：同版本 `_all` 本周期有有效提交的研发角色去重人数<br>架构：同版本 `_all` 本周期有有效提交的架构角色去重人数 | 本周期有提交记录，按角色分别展示 | 按产品、研发、架构分别计算本、上期对应角色去重人数之差并分行，单位为人，不跨角色求和 | 各角色增减值 ÷ 对应角色上期去重人数绝对值 × 100%，逐角色分行 |
| Qoder 用量 | 同版本 `_all` 产品、研发、架构总使用量（Credits），在单元格内按角色分行 | 各角色平均单次请求 Credits | 按产品、研发、架构逐角色计算总 Credits 差值并分行 | 各角色增减值 ÷ 对应角色上期总 Credits 绝对值 × 100%，逐角色分行 |
| 代码提交行数（+ / -） | 同版本 `_all` 产品、研发、架构新增 / 删除行数，在单元格内按角色分行 | 新增 / 删除，按角色分别展示 | 按角色分别计算新增行、删除行差值并分行，不互抵 | 各角色新增、删除增减值分别 ÷ 对应上期行数绝对值 × 100%，逐角色分行 |

- 所有概览归档值仅复用生成时一次性计算的同版本 `_all` 去重汇总结果；Qoder 与代码提交的各角色独立去重，严禁跨角色求和或累加项目行。完成率与延期率沿用六章分子、分母和零排期规则，不创建新公式；比较列只新增展示与归档对比，不修改现有指标。
- 「较上期」统一指同报告周期类型的上一自然周期：周报为上一自然周，月报为上一自然月，不是当前报告项的历史版本 v-1。当前版本生成时读取上一期同类型 `_all` 全量报告的当前归档结果，以四行概览归档值为基线形成对比快照并随本版本归档；上期后续版本变化不改写既有快照，版本切换只读各自快照，不在详情重新选择上期或重算。上期无概览时采用生成步骤中同冻结范围的回看基线，不直接舍弃已有事实；确无可用归档或回看基线时，两个比较项才为「-」；查询失败、已有 current version 缺失或格式破损时受影响项为「未取得」并说明原因。若本期值因取数失败未取得，比较项也保持「未取得」；不按 0 处理，不从旧六章、其他期、v-1 或实时来源补齐。
- 增减值 = 本期归档值 − 上期快照基线值；正值为「↑ +X」、负值为「↓ -X」、零值为「—」，非零值保留对应精度、千分位与单位。增减百分比 = 增减值 ÷ |上期快照基线值| × 100%，保留 1 位小数；正值为「+X.X%」、负值为「-X.X%」、零值为「0.0%」。上期为 0 且本期非 0 时百分比为「-」，两期均 0 时增减值为「—」、百分比为「0.0%」；缺失不算 0。
- 完成率、延期率的绝对增减单位为「个百分点」，相对变化仍为 %；活跃人数单位为「人」，Qoder 用量单位为「Credits」，代码行单位为「行」。仅归档值所列指标参与比较，补充说明不新增对比。活跃人数卡按产品、研发、架构分别比较对应角色去重人数，不跨角色求和；Qoder 卡逐角色比较总 Credits；代码卡逐角色分别比较新增行与删除行，增减值格式为「新增 ↑ +X 行；删除 ↓ -Y 行」，百分比对应展示新增、删除双值，正负各自保留，不跨角色求和或新增删除互抵。多角色单元格均使用安全 HTML `br` 逐角色换行。
- 成功读取后对应角色或列确无归档值时，该主值或辅助项为「-」；取数异常则为「未取得」并说明原因，不影响同卡其他已取得值，辅助项缺失不清空主值。对应角色零人数的人均、零请求的平均单次请求 Credits 为「-」，已取得零计数或零 Credits 仍为 0。Qoder 仅部分成员已匹配时，概览保留与正文同一份已匹配用量及次均，注明已匹配/总人数、未匹配名单与「非全量」，不得因覆盖不完整清空已取得数据；整体读取失败时仍为「未取得」。环比逐角色按各期实际取得的汇总直接计算，不校验两期人员名单或匹配集合是否一致；完整覆盖与部分覆盖均可参与，不筛选两期名单交集，也不重算原主值。保留各期覆盖人数、未匹配名单与「非全量」说明，不将部分数据冒充全量。覆盖情况、比较口径和结果随本版本归档。
- 服务端入库只抽取该四行已经计算好的归档值、补充说明与比较结果，并将对比快照随当前报告版本持久化，用四个公共 KPI 卡替代概览表的详情展示，不重复展示同一概览表。功能排期卡内按完成率、延期率分行，活跃人数合为一张卡并按产品、研发、架构分行，Qoder 用量与代码提交行数各为一张卡并按角色分行；每卡显示「较上期」及与原件相同的增减值和百分比，正值用公共成功色、负值用公共危险色、零值用公共中性色，缺失不标涨跌。详情及 PNG 仅消费对应版本归档结果与各自快照，数据和语义色一致，不查询实时来源重算；元信息、概览、正文整体切换版本。历史原件成功读取但无概览、比较列或某项确无归档值时对应项为「-」；已有 current version 缺失、格式破损不能可靠读取或取数异常仍为「未取得」并说明原因，不得从旧六章、其他版本或实时来源补齐。
- 元信息、页头、公共骨架及分页 PNG 导出交互以 [Web UI · 报告详情](web-ui.md#report-detail) 为真源，公共渲染差异见 [报告配置 · §6](../../报告配置/references/business-rule.md#6-markdown-渲染规则)。

## 硬约束汇总

1. 单份报告红线：每个周期只创建一个生成会话、产出一份 `_all` 报告，不按域拆分任务或文件
2. 域边界红线：只统计映射内仓库、卡片与人员事实，跨项目搜到同名实现不混入
3. 计数纪律：外部会话分角色提交次数与行数以约定计数脚本输出为唯一权威（脚本由生成环境提供，不随仓维护）；服务端会话复用研发周报的程序采集、作者识别与校验链路（固定 `master + feature/*`、SHA 去重、剔 merge、窗口过滤、逐提交 numstat、二进制排除、小计与角色合计打平），正文仅引用程序权威统计
4. 工作区边界：模型与外部会话只操作约定 `WS`；服务端程序按冻结范围在专用缓存同步与采集，模型不得访问缓存或凭据（见 Step 1）
5. 人员口径：域人员以该项目成员关系及稳定人员均启用的任务快照为候选，仅保留统计窗口内在项目映射仓有有效提交且身份匹配对应角色的成员，无提交成员从团队人数、人员明细与相关人均分母排除；角色人数与姓名明细分别按稳定 ID 去重，同人多角色分别计数与展示、跨项目全量并集去重，不从 Git 创建或自动迁移成员。代码提交按产品、研发、架构角色过滤项目 `harness_repo` + `code_repos` 中身份匹配的贡献，Qoder 同样按角色过滤该项目配置成员；同人多角色的贡献在对应角色分别完整展示，角色指标不可相加。个人用量在参与项目完整展示，`_all` 在各角色内按人员稳定 ID、自然日及来源快照去重，不按仓库分配、不累加项目行，不使用组织全员或自建归属关系
6. 核心进展口径：只引用研发周报既有内容，不从其他数据源推测补写；各组按事实以项目符号逐项展示，每个小点正文不超过 50 字
7. 健康度口径：只读产品文档健康度归档的仓库综合分 R，按统计截止周与上一自然周取数；不重跑评估、不叠加多范围结果，「查看报告」只使用本周报告标准详情链接
8. 数据容错：成功读取且确认无归档内容或不适用为 ASCII「-」，已取得零值仍为 0；取数失败、已有 current version 缺失、边界未知、账号或稳定身份未匹配、格式破损时受影响项为「未取得」并说明原因，健康度不例外，不把失败变成 0 或「-」；部分数据注明「已匹配」而非全量，无权限仍为「无查看权限」
9. token 只从会话配置（服务端会话数据或 config.yaml）读取使用，禁止写进报告或 skill 文件
