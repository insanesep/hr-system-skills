# progress-report / 项目进度报告生成

## 报告形态

每次生成同时产出两份全部项目报告，不按项目或形态拆分任务。

| 形态 | 内容真源 | 标准文件名 | 导出 |
|------|----------|------------|------|
| 完整版 | [完整版内容规范](progress-report-full.md) | `progress_yyyyMMdd__all.md` | 原 1600×2000 分页 PNG、ZIP 与人员附录；独立离线 HTML |
| 简化版 | [简化版内容规范](progress-report-simple.md) | `progress_yyyyMMdd__all_simple.md` | 1600 像素宽整张 PNG，高度随内容，不分页、不打包、不加附录 |

形态不是历史版本号。两份各有原件、正文、概览、上期快照与版本序列，同任务通过生成批次关联两个具体版本，编号不要求相同。原版历史归档属于完整版，不重写原件，不自动补造简化版。

## 参数与统计窗口

**范围真源**：域展示与统计范围只读采用 [报告配置](../../报告配置/SKILL.md) 中全部已配置启用的报告范围类型、稳定引用与生效配置；域名称只读引用 [项目管理 · 项目配置与来源](../../../研发管理/项目管理/references/business-rule.md#source) 中的项目名称，以稳定项目标识关联，名称快照随版本归档，更名不改写历史；key 同源；项目进度 Git 分支固定为 `master + feature/*`，不随 `branch_policy` 收窄为单分支。外部 `projects.<key>` 仅传递同一范围快照，不另建实体或猜测归属。各组统计边界采用项目管理配置的 harness 工程与代码服务仓快照，不按一级目录拆分项目；未配置仓及跨项目同名实现不混入。卡片归属采用功能排期按源仓与启用项目映射得到的查询投影。新范围配置齐备并启用后加入下一份周期报告的分组，停用后从后续报告移除，不删历史归档。

- 范围固定 `_all`，为全部已启用报告扩展的项目并集；项目与仓边界引用 [项目管理](../../../研发管理/项目管理/references/business-rule.md#source) 和 [报告配置](../../报告配置/SKILL.md)。空范围拒绝生成，两份使用同一范围快照。
- 周报、月报各一条触发配置，不增加形态触发行。每次定时、立即生成、重试或外部生成均输出两份。
- 周报统计最近一个以周日收尾的完整周一至周日；周日可包含今天，其他日期不包含进行中的自然周。月报统计上一完整自然月。任务冻结统计窗口与发报日，两份必须相同。
- 服务端工作区由任务指定，外部会话按 config.yaml 取得绝对工作区。模型与外部采集只操作该工作区，不能使用开发者同名副本。凭据仅供授权采集程序使用，不进入正文和作者识别。
- 服务端产物回传后直接落库，不调用旁路推送。外部会话默认提交同批次两份；用户明确仅生成时保留本地两份，不推送。

## 执行流程

### 1. 冻结范围与身份

取得参与项目的稳定标识、名称、报告 key、harness 工程与代码服务仓。一个仓最多属于一个启用项目，同项目重复仓按稳定标识去重；不以目录、同名实现扩大范围。

人员输入同时保留各项目有效配置成员及角色关系供完整版使用，全部成员档案的稳定标识、姓名、别名和角色供简化版识别作者。两形态共享身份依据但分别筛选，不相互替代口径，不从 Git 修改成员档案或关系。人员产出周报与日报仍采用原有效配置成员并集。

### 2. 一次采集与校验

- Git 固定 `master + feature/*`，不受文档基准分支策略收窄；窗口过滤、剔除 merge、跨分支 SHA 去重、逐提交计算新增与删除行、排除二进制，仓与作者小计必须打平。
- 服务端程序在专用缓存同步冻结仓范围，模型只消费已验证作者映射、计数、提交说明、变更文件与 harness 变更文档，不访问缓存、凭据，不重新同步、识别或计数。外部采集只在约定工作区运行，计数脚本输出为权威，不另跑 Git 重计。
- 原始采集保留全部作者。完整版按本项目有效配置成员与角色过滤，简化版按本项目有效提交挂靠作者，不能在采集前删掉名单外作者。
- 一次取得排期卡片、完成时间、截止日、开发人与负责人及非需求流水，按卡片稳定标识去重；归属沿用源仓映射，跨项目合并卡不重复分给项目。
- Qoder 采集人员为两形态需要的去重并集，不以组织全员兜底。用量是个人周期合计，不按项目分摊；各形态全量分别按稳定人员标识、自然日与来源快照去重。完整版保留「未取得」及覆盖说明，简化版只保留概览角色汇总，不展示个人用量，整体未取得为「-」。
- 一次读取同统计周期每个自然周入库最新 current 研发周报。完整版核心进展只能提取周报本项目明确内容；简化版还可使用映射代码仓和 harness 仓提交归纳项目结论，不把提交等同上线、文档等同实现。
- 一次取得统计截止周与上一自然周的同仓健康度快照，两份使用相同分数、差值和链接，不重跑评估。
- 来源异常与成功但无事实区分；允许归档的缺失标记遵守形态规范，不等同产物生成失败。不能确定必需项目边界或身份依据时拒绝生成，不猜测补齐。

### 3. 分别生成正文

按 [完整版章节](progress-report-full.md#章节规范) 保留六章、配置成员口径与双层表头；按 [简化版章节](progress-report-simple.md#章节规范) 输出项目总览、项目进展、harness文档健康度，项目内依次为项目结论、关键指标、本期交付、风险与阻塞四块，不展示人员产出明细。

各形态一次计算自己的汇总与概览，不能强行要求人员、提交、Qoder 合计相同，不用一份概览覆盖另一份；明确配置成员或提交挂靠口径。简化版本期交付固定列序为功能、状态、开发人、排期截止日、完成时间。

上期只取同周期类型上一自然周或月的同形态 current 归档，不借另一形态概览、不用历史版本 v-1。有必要回看时按该形态规则复用本次冻结范围的历史事实；无法可靠回看为「-」，读取异常为「未取得」。基线、覆盖说明、结果随本版本固定，详情不回查或重算。

## 双产物与归档

- 完整版保持原文件名，简化版追加 `_simple` 后缀；标题为「项目进度报告（完整版）- {发报日}」「项目进度报告（简化版）- {发报日}」。文件名日期是发报日。
- 唯一报告由报告类型、`_all`、统计周期类型、统计区间及形态确定；两个形态版本独立。批次关联各自具体版本，不能按相同版本号配对。
- 服务端先校验两份的形态、日期、区间、文件与正文，再渲染并提取各自概览。两份均通过后成对入库发布；任一生成或校验失败时整个任务失败，不发布半份、不递增当前版本，已有报告保持可查。记录失败形态与原因，保留任务产物用于排查；重试新建双产物任务。
- 两份与各自已有内容均相同时，记录本批次复用，不制造空版本；只有一份变化时仅其版本递增，但仍在两份校验完成后确认批次成功。
- 外部生成也提交同批次两份，齐备校验通过才发布。传输失败、暂存或重试不冒充完整批次，不把先提交的一份发布为成功报告。数据源与鉴权沿用 [报告数据源](../../报告配置/references/data-source-api.md)，双产物业务约束以本节为准。
- 手动补传是单形态修正通道，不是生成任务；识别或明确选择形态后只更新该形态，另一份不变，此版本注明手动补传、无配对批次。
- 历史只有完整版时显示 1/2、简化版未入库，不重渲染为简化版。立即生成两份后，完整版继续版本流程，简化版从 v1 起；已存在形态照常可查。
- 不提供单项目或单形态的触发配置、立即生成、失败重试；两形态不增加报告类型或独立菜单。

## 呈现与归档规则

完整版特有列序、概览与排版见 [完整版呈现规则](progress-report-full.md#呈现与归档规则)；简化版项目结构与概览用量见 [简化版呈现规则](progress-report-simple.md#呈现与归档规则)。公共渲染安全引用 [报告配置](../../报告配置/references/business-rule.md#6-markdown-渲染规则)。

- 每份保存原件、HTML、概览、上期比较与来源快照，详情只读，不为形态或版本切换重算。
- 完整版保留原分页 PNG、ZIP 及人员附录，并保留独立 HTML 导出（内联样式、静态正文、无外部依赖）；简化版整张 PNG、不加附录，不提供独立 HTML 出口。导出只冻结当前形态与版本，不用另一形态填空。
- 页面、形态切换、历史版本与导出见 [Web UI](web-ui.md#report-detail)，不接异步导出中心，不扩大权限。
