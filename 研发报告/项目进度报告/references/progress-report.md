# progress-report / 项目进度报告生成

> 一句话定位：每个统计周期只生成一份项目进度总报告，采集全部启用项目组的功能排期、Git 提交、Qoder 用量与研发周报核心进展，在报告内按项目组分组展示。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。

## When to Use

- 用户说「生成项目进度报告 / 项目周报 / 项目月报」
- 在一份周期报告中按项目组查看功能排期、代码提交、团队人员、Qoder 使用与核心进展

## When Not to Use

- 需要定时自动跑 → 由研发报告模块「报告触发配置」承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报（人员维度）/ 一致性检查 → 分别由人员产出报告、文档一致性报告模块的生成 skill 承载

## 参数解析

| 参数 | 取值 | 默认 |
|------|------|------|
| 报告范围 | 固定 `_all`：全部已配置启用域/项目组的去重并集 | 服务端与外部会话均不得按组拆分生成 |
| 统计周期 | 周 / 月 | 服务端会话由触发配置的类型参数给定；外部会话默认周 |
| 代码工作区 | 绝对路径 | 服务端会话由服务端注入；外部会话读取 config.yaml 的 `workspace_dir` 并解析为绝对路径 |
| 推送 | 服务端会话固定「不推送，产出回传服务端」；外部会话默认生成后推送，用户说「仅生成」则跳过 | 按会话类型 |

**单份周期报告**：每个统计周期仅生成一份报告，周报每个自然周一份，月报每个自然月一份。`_all` 是唯一新生成报告项与文件名标识，不再按项目组创建生成任务、触发配置或归档报告；同周期重复生成或补传只递增该报告的版本。

**范围真源**：项目组展示与统计范围只读采用 [报告配置](../../报告配置/SKILL.md) 中全部已配置启用的报告范围类型、稳定引用与生效配置；key 与分支策略同源。外部 `projects.<key>` 仅传递同一范围快照，不另建实体或猜测归属。各组统计边界以其生效配置及生成会话快照确定，根文件不计入项目，跨项目同名实现不混入；卡片仍取功能排期事实。新范围配置齐备并启用后加入下一份周期报告的分组，停用后从后续报告移除，不删历史归档。

**人员范围**：只读采用 [报告配置 · 统计人员范围](../../报告配置/references/business-rule.md#33-统计人员范围) 引用的生成名单快照与项目组参与关系，不维护第二份人员名单。产品人数、研发人数按报告生成时的当前有效人员状态及角色分别计数，不按周期内历史状态反推；同一人员具有多个角色时在对应角色各计一次，但汇总团队去重人数时只计一人。人数及身份依据随报告版本留档。

**汇总与分组**：取全部可生成域/项目范围及人员并集，先按域稳定 ID、卡片稳定 ID、人员稳定 ID、源仓稳定 ID + commit SHA 去重后汇总，不能叠加域及子项目数据。各章节仅用一个表格，表体按项目 key 字典序列项目组；功能排期、代码提交、团队人员与 Qoder 使用末行以加粗汇总行展示全量汇总，项目核心进展不设全量汇总；明细不直接相加为总数，完成率、延期率与人均指标由去重后的汇总分子、分母重新计算，不对各组百分比或人均值取平均，也不得对各组人均值求和；全量人均功能数 = 全量功能排期数 ÷ 全量去重研发人数，全量人均提交行数 = 全量新增与删除行数合计 ÷ 全量去重研发人数，Qoder 人均指标 = 全量 Credits 或请求次数 ÷ 全量去重活跃成员数。历史单组报告保留原归档，新报告标题统一为「项目进度报告 - {yyyy-MM-dd}」，文件名统一为 `progress_yyyyMMdd__all.md`。

**统计窗口**：

- 周：最近一个以周日收尾的周一~周日（今天是周日则含今天，否则不含）
- 月：上一自然月

## 执行流程

### Step 1 读配置、定工作区

按会话类型取配置（服务端注入 / 外部会话读 config.yaml），确定：工作区绝对路径 `WS`、输出目录、全部启用项目组映射与人员范围快照。

🚨 **工作区硬约束（违反将产出错误结论）**：一切文件操作只能以 `WS` 为基准，目标仓库都是其子目录（`$WS/<repo>/`）。机器上其它位置存在同名仓库的**开发者副本**（过时、分支不同、缺最新提交），严禁用于搜索、读取或作为结论依据。Glob / Grep / Read / Bash 的路径参数必须落在 `WS` 内；工具结果中出现 `WS` 之外的路径一律忽略并重查。

### Step 2 同步仓库

- **外部会话**：对项目映射 `code_repos` 与 `harness_repo` 下每个仓库，仓库缺失时按会话配置 `codeup` 凭证浅克隆（命令不内嵌，按生成环境约定执行）。
- **服务端生成会话**：工作区即会话 cwd（起始为空）。云效仓库按会话数据「项目代码仓库」中的云效访问信息同步；基础 Git 仓库由 Agent 程序预先完整同步，并在会话追加数据中提供 repoKey 与工作区目录映射。模型只在已同步的基础 Git 目录内读取与采集，不得自行克隆、拉取或索取基础 Git 凭据；所有访问凭证仅允许用于程序解析与克隆，禁止写入报告正文或在输出中原样打印

逐项目组按其 `branch_policy` 切统计基准分支（只切 `WS` 内的工作区仓库，严禁碰开发目录）：

- `release`：取最近提交的 release 分支，但它必须包含基准分支最新提交（防倒退），否则回退 master
- `master`（缺省）：直接以 master 为基准

### Step 3 采集数据

- **功能排期卡片**：外部会话走 MCP 工具（`busyming_feature_schedule`，调用口径、字段与容错见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)），服务端会话由调用方在会话数据中直接提供。采集统计窗口内排期卡、完成时间与排期截止日，并通过卡片操作流水识别窗口内移入非需求改动的卡片；卡片归属只采用功能排期事实中的稳定域/项目集合，同一卡片涉及多个项目时各视图可展示，域及 `_all` 总计按稳定卡片 ID 去重
- **Git 提交**：外部会话以计数脚本输出的提交次数、新增行数与删除行数为权威结果（按映射 `code_repos` + 基准分支），直接引用，**严禁自己再跑 git log 重新计数**；服务端会话无脚本，由 agent 在工作区内自行采集，纪律不变——SHA 全局去重、剔除 merge（`--no-merges`）、窗口过滤（`--since`/`--until`）、逐提交 numstat、二进制文件不计行数，各仓小计与合计必须打平
- **Qoder 用量**：取 [Qoder 用量分析](../../../研发管理/Qoder用量分析/references/business-rule.md) 在统计窗口内、当前项目组人员范围内的成员自然日快照，汇总 Credits 与请求次数；服务端会话由调用方注入，外部会话按既定用量接口取数。活跃成员数沿用 Qoder 用量分析口径
- **项目核心进展**：取 [人员产出报告 · 研发周报](../../人员产出报告/references/weekly-report.md) 的「AI 分析总结 → 核心进展」，按当前项目组归属筛选。周报取相同统计窗口；月报合并窗口内各周报并去重，不改用 Git 提交或排期卡片推测替代

### Step 4 生成报告

- 按下文章节规范与输出模板生成；全文中文
- 报告标题：`项目进度报告 - {yyyy-MM-dd}`（生成当天日期）

### Step 5 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`progress_yyyyMMdd__all.md`；新报告不得使用单项目组 key 命名，服务端按文件名解析类型与日期
- **服务端生成会话**：产出文件回传服务端，由服务端校验、渲染并直接落库（版本递增、周索引），本 skill 不调用推送接口
- **外部会话（旁路）**：推送契约（multipart 表单 + 鉴权头，幂等）见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)；推送后把 `reportId / versionNo / duplicated` 回告用户；推送失败不删本地文件，把错误信息告知用户

## 章节规范

固定章节（顺序不可调换）。正文首部必须以引用块声明统计区间（归档侧解析元信息用；周期为月时不带括号注释）。每份报告包含全部启用项目组，每个章节仅使用一个表格，第一列为「项目组」，表体按项目 key 字典序展示项目组明细；功能排期、代码提交、团队人员与 Qoder 使用末行为加粗的「全量汇总」汇总行，项目核心进展不设全量汇总，不得按组拆成多个表格或单组报告。

1. **功能排期**：展示功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率、人均功能数。
   - 功能排期数：排期日落在统计窗口内的去重功能卡数，口径与功能排期管理一致，不含非需求改动、待澄清与子卡。
   - 非需求功能数：统计窗口内发生「移入非需求改动」的去重卡片数，按卡片操作流水认定，不计入功能排期数及完成率、延期率、人均功能数的分子或分母。
   - 完成功能数：上述功能排期卡中完成时间落在统计窗口内的卡片数；完成率 = 完成功能数 ÷ 功能排期数 × 100%。
   - 延期功能数：上述功能排期卡中，统计截止时仍未完成且排期截止日不晚于统计截止日的卡片数；延期率 = 延期功能数 ÷ 功能排期数 × 100%。
   - 人均功能数 = 功能排期数 ÷ 研发人数。功能排期数为 0 时完成率与延期率计 0%；研发人数为 0 时人均功能数显示「—」。
2. **代码提交**：展示提交次数、提交行数（新增 / 删除）与人均提交行数。提交行数按新增行数与删除行数分别展示；人均提交行数 =（新增行数 + 删除行数）÷ 研发人数，研发人数为 0 时显示「—」。
3. **团队人员**：展示报告生成时当前有效的产品人数与研发人数，人员范围及项目组参与关系引用报告配置，不使用组织全员兜底。
4. **Qoder 使用**：展示总使用量、人均使用量、总请求次数与人均请求次数。总使用量与总请求次数为项目组人员范围内窗口合计；人均使用量 = 总使用量 ÷ Qoder 活跃成员数，人均请求次数 = 总请求次数 ÷ Qoder 活跃成员数，活跃成员数沿用 Qoder 用量分析口径，活跃成员数为 0 时人均指标显示「—」。
5. **项目核心进展**：展示当前项目组在统计窗口内的核心进展，内容仅来源于人员产出报告中的研发周报；对应周报未取得时标「未取得」，不编造进展。

比率与人均值保留 1 位小数；Credits 按 Qoder 用量分析口径整数展示。任一数据源缺失或拉取失败时，对应指标标「未取得」，不得以 0 或推测值代替；只有数据源成功且明确返回零值才计 0。

## 硬约束汇总

1. 单份报告红线：每个周期只创建一个生成会话、产出一份 `_all` 报告，不按项目组拆分任务或文件
2. 项目组边界红线：只统计映射内仓库、卡片与人员事实，跨项目搜到同名实现不混入
3. 计数纪律：外部会话提交次数与行数以约定计数脚本输出为唯一权威（脚本由生成环境提供，不随仓维护）；服务端会话由 agent 自行采集但纪律不变（SHA 去重、剔 merge、窗口过滤、逐提交 numstat、二进制排除、小计与合计打平）
4. 工作区硬约束：只操作 `WS` 内路径（见 Step 1）
5. 人员口径：人数与人均指标只采用报告配置引用的人员快照和当前项目组参与关系，不使用组织全员或自建名单
6. 核心进展口径：只引用研发周报既有内容，不从其他数据源推测补写
7. 数据容错：任一数据源失败将对应指标标「未取得」，严禁编造数字；部分人员或日期快照不得冒充完整项目组总量
8. token 只从会话配置（服务端会话数据或 config.yaml）读取使用，禁止写进报告或 skill 文件
