# progress-report / 项目进度报告生成

> 一句话定位：以项目映射为边界，采集 git 提交与功能排期卡片事实，由模型直接生成项目维度周期报告并写入报告文件。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。

## When to Use

- 用户说「生成项目进度报告 / 项目周报 / 项目月报」
- 按项目复盘一个周期内「计划了什么、完成了什么、延期了什么」

## When Not to Use

- 需要定时自动跑 → 由研发报告模块「报告触发配置」承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报（人员维度）/ 一致性检查 → 分别由人员产出报告、文档一致性报告模块的生成 skill 承载

## 参数解析

| 参数 | 取值 | 默认 |
|------|------|------|
| 项目 | 「报告项目配置」生效数据中的项目 key（单个）；或保留值 `_all` = 全部启用项目汇总 | 服务端会话入参必传；外部会话由用户指定 |
| 统计周期 | 周 / 月 | 服务端会话由触发配置的类型参数给定；外部会话默认周 |
| 代码工作区 | 绝对路径 | 服务端会话由服务端注入；外部会话读取 config.yaml 的 `workspace_dir` 并解析为绝对路径 |
| 推送 | 服务端会话固定「不推送，产出回传服务端」；外部会话默认生成后推送，用户说「仅生成」则跳过 | 按会话类型 |

**项目映射（项目边界真源）**：harness 工程（需求/skill 仓）+ 代码仓清单 + 分支策略。服务端会话由服务端注入（harness 工程与代码仓清单取自功能排期项目配置，项目 key 与分支策略取自「报告项目配置」生效数据）；外部会话读取会话配置 `projects.<key>`。**项目边界红线**：只统计映射内仓库的提交与该项目 harness 工程内的卡片事实，跨项目搜到的同名实现不混入。

**`_all` 汇总模式**：项目参数为 `_all` 时，项目边界 = 全部启用项目的映射并集；数据按项目逐一边界采集（纪律与单项目一致），报告按「汇总 + 分项目」两层呈现：先给全量汇总指标，再按项目分节列出各项目明细。标题取「项目进度报告（全部项目） - {yyyy-MM-dd}」，文件名 `progress_yyyyMMdd__all.md`。

**统计窗口**：

- 周：最近一个以周日收尾的周一~周日（今天是周日则含今天，否则不含）
- 月：上一自然月

## 执行流程

### Step 1 读配置、定工作区

按会话类型取配置（服务端注入 / 外部会话读 config.yaml），确定：工作区绝对路径 `WS`、输出目录、项目映射。

🚨 **工作区硬约束（违反将产出错误结论）**：一切文件操作只能以 `WS` 为基准，目标仓库都是其子目录（`$WS/<repo>/`）。机器上其它位置存在同名仓库的**开发者副本**（过时、分支不同、缺最新提交），严禁用于搜索、读取或作为结论依据。Glob / Grep / Read / Bash 的路径参数必须落在 `WS` 内；工具结果中出现 `WS` 之外的路径一律忽略并重查。

### Step 2 同步仓库

- **外部会话**：对项目映射 `code_repos` 与 `harness_repo` 下每个仓库，仓库缺失时按会话配置 `codeup` 凭证浅克隆（命令不内嵌，按生成环境约定执行）。
- **服务端生成会话**：工作区即会话 cwd（起始为空）。仓库清单与云效访问凭证由调用方在会话数据「项目代码仓库」中提供，逐仓执行：
  1. 解析仓库路径：`GET {base-url}/oapi/v1/codeup/organizations/{orgId}/repositories/{repoId}`（请求头 `x-yunxiao-token: {令牌}`），取响应 `pathWithNamespace`；解析失败写一行说明并跳过该仓，不得猜测路径
  2. 克隆到当前目录：`git clone https://oauth2:{令牌}@codeup.aliyun.com/{pathWithNamespace}.git`（`pathWithNamespace` 已含组织前缀，不要再拼 orgId；需覆盖全分支，保证窗口内历史完整）；目录已存在则 `git fetch --all --prune` 增量同步
  3. 令牌敏感：仅允许用于解析与克隆，禁止写入报告正文、禁止在输出中原样打印

按项目 `branch_policy` 切统计基准分支（只切 `WS` 内的工作区仓库，严禁碰开发目录）：

- `release`：取最近提交的 release 分支，但它必须包含基准分支最新提交（防倒退），否则回退 master
- `master`（缺省）：直接以 master 为基准

### Step 3 采集数据

- **git 提交**：外部会话以计数脚本输出为权威计数（按映射 `code_repos` + 基准分支），直接引用，**严禁自己再跑 git log 重新计数**；服务端会话无脚本，由 agent 在工作区内自行采集，纪律不变——SHA 全局去重、剔除 merge（`--no-merges`）、窗口过滤（`--since`/`--until`），各仓小计与合计必须打平
- **功能排期卡片**：外部会话走 MCP 工具（`busyming_feature_schedule`，调用口径、字段与容错见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)），服务端会话由调用方在会话数据中直接提供；卡片与项目的归属以 harness 工程内事实为准
- **发版事实**：功能排期 `view=release-days` 取区间内发版日（服务端会话由调用方会话数据提供），发布内容摘要联动发布管理事实
- **需求吞吐**：提交 → 审批通过 → 已排期 → 已完成各环节数量与端到端周期，事实来自研发管理中功能排期管理的卡片流水（服务端会话由调用方会话数据提供）

### Step 4 生成报告

- 按下文章节规范与输出模板生成；全文中文
- 报告标题：`项目进度报告（{项目名}） - {yyyy-MM-dd}`（生成当天日期）

### Step 5 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`progress_yyyyMMdd_<项目key>.md`（汇总报告为 `progress_yyyyMMdd__all.md`；服务端按文件名解析类型与日期，项目 key 与「报告项目配置」生效数据一致）
- **服务端生成会话**：产出文件回传服务端，由服务端校验、渲染并直接落库（版本递增、周索引），本 skill 不调用推送接口
- **外部会话（旁路）**：推送契约（multipart 表单 + 鉴权头，幂等）见 [`data-source-api.md`](../../报告配置/references/data-source-api.md)；推送后把 `reportId / versionNo / duplicated` 回告用户；推送失败不删本地文件，把错误信息告知用户

## 章节规范

固定章节（顺序不可调换）。正文首部必须以引用块声明统计区间（归档侧解析元信息用；周期为月时不带括号注释）。`_all` 汇总模式下，各章节先给全量汇总指标，再按项目分节列明细（项目顺序按项目 key 字典序）。

1. **统计概览**：区间内功能排期卡片完成率（完成 / 在制 / 待开发 / 延期分布）、需求吞吐各环节数量、提交数、发版次数
2. **进度总览**：按功能分组的功能排期卡片完成率表
3. **需求吞吐**：提交 → 审批通过 → 已排期 → 已完成各环节数量与端到端周期
4. **延期清单**：逾期未完成的功能排期卡片明细（负责人、排期日、延期天数）
5. **发版回顾**：区间内的发版日与发布内容摘要

## 硬约束汇总

1. 项目边界红线：只统计映射内仓库与卡片事实，跨项目搜到同名实现不混入
2. 计数纪律：外部会话提交数以约定计数脚本输出为唯一权威（脚本由生成环境提供，不随仓维护）；服务端会话由 agent 自行采集但纪律不变（SHA 去重、剔 merge、窗口过滤、小计与合计打平）
3. 工作区硬约束：只操作 `WS` 内路径（见 Step 1）
4. 数据容错：任一数据源失败写一行说明，严禁编造数字
5. token 只从会话配置（服务端会话数据或 config.yaml）读取使用，禁止写进报告或 skill 文件
