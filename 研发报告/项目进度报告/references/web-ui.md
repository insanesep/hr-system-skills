# Web 端 UI 描述 · 项目进度报告

> 归档、齐全度、触发、版本、渲染与权限规则以 [报告配置 · 业务规则](../../报告配置/references/business-rule.md) 为真源；报告正文章节以 [progress-report.md · 章节规范](progress-report.md#章节规范) 为真源。
> 报告范围只读引用 [报告配置 · 业务规则](../../报告配置/references/business-rule.md#3-报告项目配置) 的全部启用项目组；新报告仅使用 `_all`，列表每周期一条，详情按项目组分组展示。
> 手动补传的通用字段、文件名识别与入库反馈以 [报告配置 · 手动补传弹窗](../../报告配置/references/web-ui.md#手动补传弹窗报告模块共用) 为真源，本文只声明本模块差异。

## 页面清单

<a id="report-list"></a>
### 报告列表

- **页面路径**：`/report/project-progress`
- **权限编码**：
  - 菜单：`devhubProjectProgressReport`
  - 按钮：`devhubReportUpload`（手动补传）、`devhubReportTrigger`（立即生成）
- **页面类型**：列表页（按周索引，每周期一份）
- **区块职责**：
  - 筛选卡：发报日期范围（默认近 90 天）、关键词（报告标题模糊查询，回车执行）；查询 / 重置。不提供项目组筛选，项目组只在报告详情内查看。
  - 结果卡统计（当前查询口径，不参与筛选）：本周已入库（0/1 或 1/1）、累计报告（按统计周期计，不含历史版本）、最近发报日、历史版本总数。
  - 结果卡工具栏：左侧「手动补传」（持上传权限可见）；右侧「刷新」。
  - 按周索引表格：按所属周倒序排列，不设置独立周分组行；统计周期与报告合并在同一行，依次展示统计周期（含齐全度徽标）、报告标题、发报日、来源、当前版本与操作。每周仅一条 `_all` 报告，操作含「查看 / 获取原件」。未入库时仅展示一条灰显「未入库」行，发报日、来源与版本显示「—」，操作按权限显示「立即生成 / 补传」。
  - 分页：按自然周计数，默认 20 条/页，可切换 20 / 50 / 100 条；查询或重置后回到第 1 页。
  - 数据区状态：加载中显示表格骨架；无结果显示「该条件下暂无报告」；加载失败显示「报告列表加载失败」与「重试」，重试保留当前筛选与页码。
  - 手动补传弹窗：报告类型固定为「项目进度报告」，报告项固定 `_all`，不提供项目组选择；发报日不可晚于今天。仅识别 `progress_yyyyMMdd__all.md`，识别成功时回填发报日，识别失败时保留手动填写。从缺失行「补传」进入时预填当周周日，并展示「已从缺口带入：全部项目组 · 发报日 {日期}」。
- **组件引用**：[Button](../../../../busyming-skills-design/components/web/docs/Button/spec.md)、[BusyInput](../../../../busyming-skills-design/components/web/docs/BusyInput/spec.md)、[DatePicker](../../../../busyming-skills-design/components/web/docs/DatePicker/spec.md)、[ProTable](../../../../busyming-skills-design/components/web/docs/ProTable/spec.md)、[Pagination](../../../../busyming-skills-design/components/web/docs/Pagination/spec.md)、[Tag](../../../../busyming-skills-design/components/web/docs/Tag/spec.md)、[Message](../../../../busyming-skills-design/components/web/docs/Message/spec.md)、[MessageBox](../../../../busyming-skills-design/components/web/docs/MessageBox/spec.md)、[Dialog](../../../../busyming-skills-design/components/web/docs/Dialog/spec.md)、[Upload](../../../../busyming-skills-design/components/web/docs/Upload/spec.md)。
- **编排标准**：[Web 操作列表页](../../../../busyming-skills-design/shared/page-standards/web-operation-list.md)；页面无批量业务，不设置勾选列与批量操作。
- **布局引用**：[assets/web/report-list.html](../assets/web/report-list.html)。

#### 导航关系

- 来源页：研发分组侧边菜单「研发报告 → 项目进度报告」。
- 去向页：已入库行「查看」→ `/report/progress/detail/:id`；缺失行「补传」→ 手动补传弹窗；「立即生成」成功 → 报告配置页对应报告项的生成记录。
- 返回行为：从详情返回时恢复原筛选条件、页码与滚动位置；面包屑「项目进度报告」停留当前页。
- 面包屑：首页 / 研发 / 研发报告 / 项目进度报告。

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 查询 | 点击「查询」或在关键词输入框回车 | 否 | 表格 loading | 列表与统计刷新 → 停留第 1 页 | BusyMessage.error「查询失败，请重试」→ 保留条件，按钮恢复 |
| 重置 | 点击「重置」 | 否 | 表格 loading | 恢复近 90 天与空关键词 → 刷新第 1 页 | BusyMessage.error「重置后加载失败，请重试」→ 保留默认条件，按钮恢复 |
| 刷新 | 点击「刷新」 | 否 | 按钮 loading + 表格 loading | 列表与统计刷新 → 停留当前筛选和页码 | BusyMessage.error「刷新失败，请重试」→ 按钮恢复 |
| 手动补传提交 | 发报日与文件校验通过 | 否 | 提交按钮 loading + disabled | BusyMessage.success「补传成功，已生成 v{N}」→ 关闭弹窗并刷新来源列表；重复内容提示「内容重复，与现有版本一致，未产生新版本」 | BusyMessageBox 展示错误详情 → 弹窗与输入保留，按钮恢复后可重试 |
| 立即生成 | 未入库行点击「立即生成」，且对应触发配置可用 | BusyMessageBox 展示报告项、统计周期与统计窗口 | 确认按钮 loading + disabled | BusyMessage.success「已创建生成任务」→ 跳转报告配置页对应报告项的生成记录 | BusyMessage.error 展示配置缺失、任务进行中或权限不足原因 → 停留本页，按钮恢复 |
| 获取原件 | 已入库行点击「获取原件」 | 否 | 按钮 loading + disabled | 下载当前版本原始 Markdown，BusyMessage.success「已开始下载 {文件名}」→ 停留本页 | BusyMessage.error 展示无原始内容或下载失败原因 → 按钮恢复后可重试 |
| 加载失败重试 | 数据区点击「重试」 | 否 | 表格 loading | 列表与统计刷新 → 停留当前筛选和页码 | BusyMessage.error「报告列表加载失败」→ 保留重试入口 |

#### 表单校验（手动补传弹窗）

- 初态：报告类型固定为「项目进度报告」、报告项固定为 `_all` 且只读；从工具栏进入时发报日默认为空，从缺失行进入时按缺口预填；无编辑模式。

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 发报日 | 是 | 不可晚于今天；文件名识别成功时自动回填 | change | 「发报日不可晚于今天」 | 否 |
| 报告文件 | 是 | 单个 UTF-8 Markdown 文件，扩展名为 .md，大小不超过 2MB；重复选择替换前次文件 | change | 「仅支持不超过 2MB 的 UTF-8 Markdown 文件」 | 否 |

- 提交成功跳转：无路由跳转；关闭弹窗并刷新来源列表。
- 提交失败展示：BusyMessageBox 展示服务端错误详情；字段错误显示在对应字段下方，已填内容与文件保留。
- 脏数据离开：已选择文件或已填写发报日时关闭，BusyMessageBox 确认「已选择文件或已填写补传信息，放弃本次补传？」。

<a id="report-detail"></a>
### 报告详情

- **页面路径**：`/report/progress/detail/:id`
- **路由名称**：`devhubProjectProgressReportDetail`，为项目进度报告的非菜单详情页。
- **权限编码**：
  - 所属菜单资源：`devhubProjectProgressReport`，不等同于详情路由名称。
  - 关联数据权限：点击人员姓名查看周报须具备 `devhubMemberOutputReport`；打开健康度报告须具备 `devhubDocHealthReport`。无对应权限时姓名仅作文本、健康度操作列为「无查看权限」，不发起数据请求。
- **页面类型**：详情页（阅读型）。
- **区块职责**：
  - 页头：保留返回链接「‹ 返回报告列表」、面包屑、报告标题、「项目进度报告」Tag 与「全部项目组」Tag；右侧仅「导出为图片（分页 PNG）/ 获取原件」，不重复设置「返回列表」按钮。
  - 历史版本警示：仅查看历史版本时展示「当前查看历史版本 v{N}（只读），最新版本为 v{M}；切换版本不改变归档内容。」
  - 元信息概览：全部项目组及组数、发报日、所属周、统计区间（历史归档缺少可解析区间时显示「—」，不代表新报告允许缺失统计区间）、来源、当前版本、文件大小、入库时间；使用公共 `tpl-overview__meta` 自动响应式多列网格，不固定行数、不使用四行 Descriptions。文件大小与入库时间使用公共次要文字样式保留，不删除；当前版本使用公共 PageableSelect 下拉，多版可切换，辅助文案为「历史版本只读可查，URL 带 ?v=N 可分享」。
  - 本期概览：统计区间后、六章前保留加粗文本「本期概览」，不是章节标题或第七章；以公共 `tpl-kpi-grid` / `tpl-kpi` 展示四张自适应 KPI 卡，不重复展示原件概览表；四卡共用同一公共网格，宽屏一行排列，窄屏自适应换行。顺序固定为功能排期（完成率 / 延期率）、活跃人数、Qoder 用量、代码提交行数（+ / -）。功能排期在同一张卡内分行展示完成率与延期率，各自保留归档值、辅助说明及较上期对比，不合并计算。活跃人数在同一张卡内按产品、研发、架构分行展示对应角色的去重人数；仅统计本周期有有效提交的人员，同人多角色在对应角色各展示一次，不将角色人数相加为概览指标。Qoder 用量卡按产品、研发、架构分行展示各角色总使用量，并在卡内列出各角色平均单次 Credits；代码提交行数卡按三角色分行展示各角色新增 / 删除行数，不跨角色求和。只消费同版本入库时从原件抽取并持久化的归档值、补充说明、比较结果及对比快照，均为生成时一次性计算的 `_all` 角色独立去重结果，严禁跨角色求和；成功读取但无概览、比较列或对应角色归档值时该项为 ASCII「-」，读取异常仍为「未取得」并说明原因，不影响同卡其他已取得值，辅助项缺失不清空主值，零人数的人均与零请求次均为「-」；历史版本不从正文、其他版本或实时来源补齐，部分合计注明「已匹配」而非全量。
  - 本期概览 · 较上期：四卡均设置「较上期」展示增减值与增减百分比，数据及逐角色 `br` 换行与原件五列表一致。完成率、延期率增减值使用「个百分点」，活跃人数卡按产品、研发、架构分别比较对应角色去重人数并以「人」为单位，不跨角色求和；Qoder 卡按产品、研发、架构逐角色展示总 Credits 的增减值及百分比；代码卡逐角色分别展示新增行、删除行的增减值及百分比，增减值采用「新增 ↑ +X 行；删除 ↓ -Y 行」，百分比为对应双值，不跨角色求和或新增删除互抵。正值用公共成功色、负值用公共危险色、零值用公共中性色，不仅以颜色表达方向；成功读取后确认无同周期上期、上期无概览或角色、列无归档基线时显示「-」；查询失败、已有 current version 缺失或格式破损时显示「未取得」并说明原因，均不标涨跌。上期基线、计算公式、零基线及缺失规则以 [生成逻辑 · 本期概览](progress-report.md#本期概览) 为单源，前端不计算；上期不是历史版本 v-1，版本切换只读各版本自身归档快照。
  - 阅读区：展示当前版本在入库时生成并持久化的服务端 HTML 产物，前端不做 Markdown 实时渲染；正文首部展示统计区间引用块，章节顺序固定为项目核心进展 / 团队人员 / 功能排期 / 代码提交 / Qoder 使用 / harness文档健康度。除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余每章仅用一个表格；前五章第一列为项目组并按项目 key 字典序展示，Qoder 两表均展示对应角色的总使用量、人均使用量、总请求次数、人均请求次数与平均单次请求 Credits，末行分别以加粗的「全量汇总」展示；项目核心进展在各项目组单元格内以安全 HTML `ul` / `li` 无序列表逐项展示，折行悬挂缩进，续行对齐正文而非列表标记；每个小点正文不超过 50 字；每周只用同周期同周实际入库最新的研发周报 current version，月报合并各周，按来源版本快照中相同稳定 projectId、仓边界一致的历史 name/key 匹配，不依赖当前改名或硬编码同义词。成功读取但无周报、无核心进展章节或无本项目明确内容为「-」，读取异常或边界未知为「未取得」并说明原因，不设全量汇总。harness文档健康度按仓库展示上周健康度得分、本周健康度得分、较上期与「查看报告」操作，不设全量汇总；团队人员标题下固定展示说明「以本周期有提交记录的人员为准」，仅展示窗口内有有效提交的各角色人数及具体人员明细，无提交成员不展示，末行以加粗的「全量汇总(去重)」展示；代码提交按产品 → 研发 → 架构连续展示各角色「提交次数 → 提交行数（新增 / 删除）→ 人均提交行数」；Qoder 产品与研发表按产品 → 研发连续展示各角色「总使用量（Credits）→ 人均使用量（Credits）→ 总请求次数 → 人均请求次数 → 平均单次请求 Credits」，架构单独表同五项。HTML 与 PNG 使用服务端入库时按确定完整列组合生成并持久化的双层表头，上层角色在代码表各 `colspan=3`、Qoder 表各 `colspan=5`，下层指标，首列「项目组」`rowspan=2`；Markdown 保留带角色前缀、同列序的平面表头，前端不改原件、不重组、不丢指标。健康度只读同仓同周可确定单仓域报告中实际入库最新的 current 归档，不混跨域子范围；成功读取后无归档、评分待定或不可比时得分与差值为「-」，查询失败、current version 缺失或仓边界未知时为「未取得」并说明原因。较上期正值「↑ +X.X」为公共成功色、负值「↓ -X.X」为公共危险色、零「0.0」为公共中性色，缺失或异常不标涨跌；操作无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」，不改上游评分公式；功能排期与代码提交末行以加粗的「全量汇总」展示。阅读区占满内容区宽度，不设大纲（见[报告配置 · Markdown 渲染规则](../../报告配置/references/business-rule.md#6-markdown-渲染规则)）；表格仅在正文容器内横向滚动，滚动时首列（项目组 / 仓库）固定，表头按词换行，数值列右对齐并使用等宽数字。计数、Credits、增删行、人均及次均指标仅对整数部分用千分位，保留既有小数精度、正负号与单位，新增 / 删除分别处理；日期、ID、文件名、链接及缺失符不处理，不对全文数字替换。原件格式与归档结果以 [呈现与归档规则](progress-report.md#呈现与归档规则) 为单源；正文为空时展示「报告内容为空」。
  - 人员周报弹窗：本期新增人员在姓名旁以公共 `u-success` 文字样式展示「（新）」，不使用 Tag 边框、底色或额外标签留白，即其在该项目该角色的首次有效提交落在统计窗口内且窗口开始前无同项目同角色有效提交；全量按人员稳定 ID 去重，任一参与项目符合即保留标记。生成侧复用 Git 采集与身份校验结果并随版本快照归档，不按成员加入时间或页面猜测；Markdown 与 PNG 以「姓名（新）」表示，标签不改变团队人数、人员周报来源或点击行为。具备人员产出报告权限时，团队人员中的姓名渲染为可点击按钮；点击后打开公共 Dialog，标题为「{姓名} · 本周研发周报」，展示统计区间、来源报告及版本，以及该人员在「按人员综合分析」下的完整小节。姓名点击与 PNG 导出均重新读取同周最新入库的当前周报版本，不复用先前弹窗或导出的旧来源内容。加载中显示局部状态；成功读取后无同周周报或人员小节时显示「-」；读取失败、已有 current version 缺失、身份未匹配或格式破损时显示「未取得」并说明原因，不推测内容。弹窗提供「查看完整周报」与「关闭」，关闭后焦点返回原姓名；切换进度报告版本前关闭弹窗。Markdown 原件与 Web 正文中姓名保持纯文本；PNG 在正文后追加「人员工作明细」附录，按去重人员展示同周研发周报个人小节，无权限显示「无查看权限」，成功读取后无同周周报或人员小节显示「-」，读取异常或身份未知显示「未取得」并说明原因。
  - 版本切换：选择历史版本后，元信息、四张概览卡与正文整体同步切换，较上期仅读取所选版本自身的对比快照；加载期间概览与正文使用公共骨架及「正在加载所选版本内容…」，不显示跨版本组合数据，成功后 URL 写入 `?v=N`；失败时停留原版本并保留原元信息、概览及正文。版本加载期间禁用导出；PNG 导出期间禁用版本下拉，禁止混版。
  - 分页 PNG 导出：点击「导出为图片（分页 PNG）」固定以普通分辨率 1600×2000 像素分页，不提供分辨率选择、不接异步导出中心；导出当前版本标题、统计区间、本期概览、六章、所有项目及仓库行和「人员工作明细」附录，不截取视口或横向滚动可见列，不裁掉指标。表头按词换行、数值对齐与健康度语义色沿用归档结果及公共样式；概览仅消费当前版本归档值与对比快照，「较上期」数据及成功 / 危险 / 中性色与 HTML 一致，附录继续按既有同周来源与权限读取。
  - 分页连续性：普通表格行不得跨页截断，剩余高度不足时整行移至下一页；续页重复对应章节，Qoder 同时保留「产品与研发」或「架构」小标题，并重复对应表格的完整表头，角色表必须重复上层角色及下层全部指标（首列跨两行）。单元格超出单页可用高度时仅按完整文本行续写，保留项目 / 仓库或人员标识与续写关系，不切字、不遗漏或重复正文；其他单层表头也完整重复。每页底部显示页码「第 p 页 / 共 P 页」，人员附录续页保留附录标题与人员标识。
  - 下载与防混版：原件文件名去扩展名为 basename，所有分页 PNG 按页序打包为 `basename_vN_png.zip` 一次下载，包内文件为 `basename_vN_p01.png`、`basename_vN_p02.png` 等，页号至少两位且按总页数补齐以保持排序。导出开始时冻结当前进度报告版本及其元信息、概览、正文和人员快照，禁用版本切换；附录本次读取完成后用于全部页，不能逐页重新读取造成混版。按钮 loading + disabled，全部分页与 ZIP 完成后才发起一次下载；失败保留当前版本和归档数据，不下载残缺包，恢复按钮与版本下拉后可重试；重试仍按既有规则重新读取同周最新归档人员小节并在本次导出内固定。
  - 异常空态：报告 ID 不存在或对应报告尚未入库时，显示「报告不存在或尚未入库」，元信息显示「—」，禁用版本切换、PNG 导出与获取原件，仅保留返回列表。

#### 导航关系

- 来源页：报告列表已入库行「查看」，路径携带报告 ID；历史版本通过 `?v=N` 直达。
- 去向页：健康度「查看报告」→ `/subapp/devhub/report/doc-health/detail/{本周报告 ID}`；人员周报弹窗「查看完整周报」→ `/subapp/devhub/report/member-output/detail/{周报报告 ID}`。「导出为图片（分页 PNG）」一次下载当前版本完整报告及人员附录的分页 PNG 压缩包 `basename_vN_png.zip`，「获取原件」下载当前展示版本 Markdown。
- 返回行为：页头「‹ 返回报告列表」或面包屑「项目进度报告」→ 报告列表，并恢复原筛选条件、页码与滚动位置；右侧无重复返回按钮。
- 面包屑：首页 / 研发 / 研发报告 / 项目进度报告 / 报告详情。
