# 项目进度报告 · 业务规则

## 1. 每周期一份，按组查看

- 每个统计周期仅生成一份项目进度报告：周报每个自然周一份，月报每个自然月一份；不得按项目组拆分生成、触发或归档。
- 报告固定使用 `_all` 报告项和 `progress_yyyyMMdd__all.md` 文件名，包含全部已配置启用的域/项目组；项目组仅作为正文分组，不再对应独立报告。
- 报告范围只读引用 [报告配置](../../报告配置/SKILL.md) 的生效数据，不另建实体；各组统计边界由其生效配置及生成会话快照确定，根文件不计入项目，跨项目同名实现不混入。
- 汇总先按域、卡片稳定 ID、人员稳定 ID 与源仓稳定 ID + commit SHA 去重，不叠加域和子项目重复数据；每章仅用一个表格，前五章按项目 key 字典序列项目组，harness文档健康度按仓库名字典序列仓库；功能排期、代码提交与 Qoder 使用末行以加粗的「全量汇总」展示，团队人员末行以加粗的「全量汇总(去重)」展示，项目核心进展与 harness文档健康度不设全量汇总，明细不直接相加为汇总。
- 项目组配置齐备并启用后加入下一份周期报告，停用后从后续报告移除；历史单组报告保留原 key、文件名和版本，不猜测或复制到其它范围。

## 2. 生成方式

1. 触发方式在 [报告配置](../../报告配置/SKILL.md) 的报告触发配置页维护：项目进度报告的周报与月报各内置一条独立 `_all` 配置行，分别使用每周 / 每月定时规则，可同时调度并支持手动立即生成；统计窗口按各自周期口径计算后随任务下发，不按项目组联动配置行。
2. 触发后服务端通过 Qoder SDK 创建一个生成会话，携带报告扩展已配置启用的全部项目组的范围类型、稳定引用、生效配置快照与统计窗口，Git 采集分支固定为 `master + feature/*`，不随 `branch_policy` 收窄为单分支；人员快照同时携带各项目的启用成员关系、启用稳定人员的身份、姓名与角色，以及按人员稳定 ID 去重的全局并集，随报告版本留档。Git 采集、作者识别与程序校验复用研发周报链路，团队和提交指标仅引用已验证的项目、人员及角色结果，最终正文不得自行识别作者或重计提交。生成逻辑唯一真源为 [progress-report.md](progress-report.md)。卡片与流水仍从功能排期管理取得，不因报告范围配置改换事实来源。
3. 产出报告由服务端直接落库归档，完成渲染、版本递增与周索引，不经过推送；外部生成会话产出可经推送上报旁路入库。
4. 模型文件操作仅限本任务约定工作区，禁止使用其它位置的同名开发者副本；服务端 Git 同步与采集由程序在专用缓存中执行，按冻结仓库范围和统计窗口提供已验证事实，模型不得访问缓存或自行采集。
5. 生成任务记录触发来源、状态、耗时与失败原因；失败可在生成记录中重试。

## 3. 报告内容口径

- 项目核心进展：优先按项目 key 引用已存在的对应研发周报；不存在时回退引用无项目维度总人员产出周报的「AI 分析总结 → 核心进展」，只提取能明确对应本项目的内容，不把全局进展复制到各组；无明确内容标「未取得」，不从其他数据源推测补写。按 key 读取仅兼容已有产物，不新增分项目周报配置。
- 团队人员：只读引用 [项目管理 · 项目成员](../../../研发管理/项目管理/references/business-rule.md#membership)，人员在每个项目内独立维护，同人可参与多个项目。当前项目成员关系和对应稳定人员均为启用（ENABLED）时纳入任务快照，仅保留统计窗口内在项目映射仓有有效提交且身份匹配对应角色的成员，无提交成员从团队人数与人员明细排除；按快照角色与人员稳定 ID 分别去重展示产品人数、研发人数与架构人数，并在人员明细中按角色展示具体人员姓名。同人多角色在对应角色各计一次并各展示一次，全量仅保留任一参与项目有有效提交的人员，各角色人数与人员明细按全局成员并集分别去重，汇总行标签固定为「全量汇总(去重)」。来源成功且确认无配置成员或过滤后无提交成员时各人数为 0、人员明细为「无」、人均功能数与对应角色人均提交行数为「—」；成员身份、角色或本项目 Git 采集来源未取得时，对应团队人数、人员明细及依赖的人均指标标「未取得」；单项目缺失不影响其它来源完整的项目，参与范围的任一项目缺失时全量团队与提交指标不展示部分合计，不以组织全员或其它项目名单兜底。
- 人员周报查看：Web 详情中，具备 `devhubMemberOutputReport` 权限的用户可点击人员明细中的姓名，通过公共 Dialog 查看该人员本周研发周报；无权限时姓名仅作文本，不发起数据请求。本周为当前查看进度报告统计窗口截止日所在自然周，读取该周无项目维度研发周报中实际入库时间最新的当前归档版本，不以发报日或报告项 ID 挑选历史重复项；每次点击姓名或导出 PNG 均重新读取来源，按人员稳定 ID 提取「按人员综合分析」下该人员的完整小节，包含代码产出、功能排期任务、Qoder 用量与综合评价，不按当前项目过滤或重复分摊。弹窗提供同来源完整周报详情链接；周报未入库、人员小节缺失或读取失败时展示「未取得」，不展示日报、不推测内容。点击只读取人员产出报告，不写回进度报告、不重算指标；Markdown 原件与 Web 正文中的姓名保持纯文本。导出 PNG 时在六章正文后追加「人员工作明细」附录，按人员稳定 ID 去重展示上述同周研发周报个人小节，包含代码产出、主要工作、功能排期任务、Qoder 用量与综合评价；附录不计入 Web 正文大纲或 Markdown 原件，无人员产出报告权限时对应人员明细显示「无查看权限」，来源缺失时显示「未取得」。
- 功能排期：按项目组展示本期功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率与人均功能数；排期、非需求改动、完成及延期事实引用功能排期管理。
- 代码提交：按产品、研发、架构分别展示本期提交次数、提交行数（新增 / 删除）与人均提交行数；各角色统计项目组映射 `harness_repo` + `code_repos` 的统计窗口，仅保留身份匹配该项目该角色配置成员的贡献。同人多角色时其贡献在对应角色分别完整展示，角色指标不可相加；未配置或身份未匹配的作者不计入分角色指标、不点名，不从 Git 创建或自动迁移项目成员。
- Qoder 使用：按同一项目配置成员快照取本期自然日用量，按产品、研发、架构分别展示总使用量、人均使用量、总请求次数与人均请求次数；各角色活跃成员沿用 Qoder 用量分析口径，在该项目该角色配置成员内按正 Credits 记录去重认定。个人用量作为人员维度完整展示于其参与的每个项目及每个已配置角色，不按仓库分配或推测分摊，角色指标不可相加；`_all` 在各角色内按人员稳定 ID、自然日及来源快照去重，同一用量在同一角色只计一次，不对项目行求和。已确认 Qoder 账号的成员在自然日无快照记录时按无用量明确补 0；配置成员已确认空时对应角色总使用量、总请求次数及活跃成员数为 0、人均指标为「—」；成员来源或成员用量未取得时标「未取得」，部分成员未匹配时保留已匹配成员数据，展示已匹配/总人数与未匹配名单，合计明确标为已匹配成员非全量，仅未匹配成员标「未取得」，不冒充完整项目或角色总量或清空全部用量。
- harness文档健康度：只读引用 [产品文档健康度报告](../../产品文档健康度报告/references/health-report.md) 的归档结果，按仓库展示上周健康度得分、本周健康度得分、较上期与「查看报告」操作。本周为报告统计窗口截止日所在自然周，上周为其上一自然周；两周分别取同仓库最新归档版本「仓库综合评分与环比」中的综合分 R，保留 1 位小数。各期得分缺失或不可比时以「-」省略；较上期 = 本周得分 − 上周得分，正数带 `+`、零为 `0.0`，任一期缺失或不可比时为「—」。同仓同周多份结果仅采用可唯一确定的域整仓结果，无法唯一确定时不挑选、不平均，分数与操作按缺失规则处理。操作链接本周健康度报告详情，沿用其查看权限；本章不设全量汇总，不触发或重跑健康度评估，沿用排除 common/design 的范围。
- 全量人均指标统一按「全量总数 ÷ 全量去重人数」计算，不对各组人均值求和或取平均；功能排期使用去重研发人数，代码提交分别使用产品、研发、架构去重人数，Qoder 使用分别使用产品、研发、架构去重活跃成员数。
- 固定章节、指标公式、顺序与输出模板详见 [progress-report.md · 章节规范](progress-report.md#章节规范)。

## 4. 归档与查阅

- 报告按统计周期建立索引，周报每个自然周仅一条报告项，月报每个自然月仅一条报告项；同周期重复入库走版本递增而非覆盖，历史版本可溯。
- 报告为静态产物：归档后只做渲染呈现，包括 Markdown 转 HTML 与大纲锚点导航，不重新计算指标；指标口径问题回溯生成侧。人员周报弹窗与健康度报告链接只读取对应来源归档，不写回当前报告。
- 详情页支持将当前查看版本的完整正文导出为 PNG，包含报告标题、统计区间、六个固定章节、全部项目组与仓库行，以及正文后的「人员工作明细」附录，不仅截取当前视口；文件名由原件文件名去扩展名后追加 `_v{版本号}.png`，不接入批量异步导出中心，权限与详情查看一致。
- 归档、触发与生成规则详见 [报告配置 · 业务规则](../../报告配置/references/business-rule.md)，数据语义详见 [报告配置 · 数据定义](../../报告配置/references/data.md)。

## 5. 关键约束

- 报告指标由功能排期卡片、映射 Harness 工程与代码仓 Git、项目管理配置成员快照、Qoder 用量、研发周报与产品文档健康度归档事实生成，不接受手工填报；核心进展只引用研发周报，健康度只引用对应归档评分。
- 报告范围以报告配置生效数据为准；每次生成只创建一个会话并传递报告扩展已配置启用的全部项目组引用、各项目成员关系快照及全局去重成员并集，不维护第二份实体、成员或映射。人员产出周报、日报仍使用配置成员的全局去重并集；并集为空或人员真源未取得时拒绝生成人员产出报告，项目进度报告的已确认空名单仍按零人数生成。
- 原始报告文件单文件直接获取，不接入批量异步导出中心；报告落库即页面可查，本子域不做主动通知。
- 项目停用只影响此后的生成，不删除历史报告。
