# 项目进度报告 · 业务规则

## 1. 每周期两份，共同生成

- 每个统计周期生成完整版与简化版各一份：周报每个自然周两份，月报每个自然月两份；同一次任务共用一次采集，不按域或形态拆分触发。两形态不是历史版本号。
- 两形态范围固定 `_all`，包含全部已配置启用的域；完整版沿用 `progress_yyyyMMdd__all.md`，简化版使用 `progress_yyyyMMdd__all_simple.md`，域仅作为正文分组，不对应独立生成任务。
- 报告范围只读引用 [报告配置](../../报告配置/SKILL.md) 的生效数据，不另建实体；各组统计边界由其生效配置及生成会话快照确定，根文件不计入项目，跨项目同名实现不混入。域展示名称只读引用 [项目管理 · 项目配置与来源](../../../研发管理/项目管理/references/business-rule.md#source) 中的项目名称，以稳定项目标识关联；新报告使用生成时的名称快照，项目更名或启停不改写历史归档的 key、文件名和统计边界。
- 完整版汇总先按域、卡片稳定 ID、人员稳定 ID 与源仓稳定 ID + commit SHA 去重，不叠加域和子项目重复数据；除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余每章仅用一个表格，前五章按项目 key 字典序排列各域，harness文档健康度按仓库名字典序列仓库；功能排期、代码提交及 Qoder 使用两张表格的末行均以加粗的「全量汇总」展示，团队人员末行以加粗的「全量汇总(去重)」展示，项目核心进展与 harness文档健康度不设全量汇总，明细不直接相加为汇总。
- 域配置齐备并启用后加入下一份周期报告，停用后从后续报告移除；历史单组报告保留原 key、文件名和版本，不猜测或复制到其它范围。

## 2. 生成方式

1. 触发方式在 [报告配置](../../报告配置/SKILL.md) 的报告触发配置页维护：项目进度报告的周报与月报各内置一条独立 `_all` 配置行，分别使用每周 / 每月定时规则，可同时调度并支持手动立即生成；统计窗口按各自周期口径计算后随任务下发，不按域或形态联动配置行；每次同时产出完整版与简化版。
2. 触发后服务端通过 Qoder SDK 创建一个生成会话，携带报告扩展已配置启用的全部域的范围类型、稳定引用、生效配置快照与统计窗口，Git 采集分支固定为 `master + feature/*`，不随 `branch_policy` 收窄为单分支；人员快照同时携带各项目的启用成员关系、启用稳定人员的身份、姓名与角色，以及按人员稳定 ID 去重的全局并集，随报告版本留档，同时携带各项目各角色的本期首次有效提交判定及对应人员稳定 ID，供团队人员「新」标记使用。Git 采集、作者识别与程序校验复用研发周报链路，团队和提交指标仅引用已验证的项目、人员及角色结果，最终正文不得自行识别作者或重计提交。任务还冻结全部成员档案身份供简化版按提交挂靠统计；完整版候选范围不扩大。共用生成入口为 [progress-report.md](progress-report.md)，内容分别见 [完整版](progress-report-full.md) 与 [简化版](progress-report-simple.md)。卡片与流水仍从功能排期管理取得，不因报告范围配置改换事实来源。
3. 两份都校验、渲染完成后成对发布，任一失败不发布半份、不覆盖已有版本；任务记录两形态的实际版本与生成批次，编号不要求相同。外部生成同批提交两份；手动补传可单形态修正，不伪造配对批次。
4. 模型文件操作仅限本任务约定工作区，禁止使用其它位置的同名开发者副本；服务端 Git 同步与采集由程序在专用缓存中执行，按冻结仓库范围和统计窗口提供已验证事实，模型不得访问缓存或自行采集。
5. 生成任务记录触发来源、状态、耗时与失败原因；失败可在生成记录中重试。

## 3. 报告内容口径

| 规则 | 完整版 | 简化版 |
|------|--------|--------|
| 正文 | 原六章，以域为第一列 | 项目总览、项目进展、末章健康度；每个域下只有项目结论、关键指标、本期交付、风险与阻塞四块 |
| 名称 | 项目管理的域名称快照，稳定项目标识关联，按项目 key 排序 | 同一域名称快照，不直接使用 key，按名称排序 |
| 人员 | 本域有效配置成员候选中有本域有效提交者 | 本域映射仓全部有效提交作者用于统计，包含非配置作者，不公开人员名单或产出明细 |
| 进展来源 | 核心进展仅引用同周最新研发周报本域明确事实 | 可从本域代码仓与 harness 仓提交、卡片和周报归纳，不把提交等同上线或文档等同实现 |
| Qoder | 本域配置成员及角色，保留原总量、请求、人均、次均和覆盖口径 | 仅概览角色去重合计，不展示个人用量，不按项目分摊，整体未取得为「-」 |
| 导出 | 原分页 PNG / ZIP 与人员附录，独立离线 HTML | 完整单张 PNG，不分页、不打包、不加人员附录、不提供独立 HTML 出口 |

- 完整版所有指标、列表、角色人数、新人员标记、双层表头、人员周报权限及健康度取数沿用 [完整版规范](progress-report-full.md)，不以简化版提交挂靠替代配置成员。
- 简化版的本期交付列序为功能、状态、开发人、排期截止日、完成时间；开发人列保留，但不添加独立人员产出明细或个人周报弹窗，内容与缺失语义见 [简化版规范](progress-report-simple.md)。
- 挂靠只用于报告统计，不新增、迁移或启用人员关系，不改变人员周/日报名单。未知作者只保留核验材料并注明人数，不猜角色。
- 两形态各自去重并归档概览、正文和比较快照，不相互覆盖数字。上期仅取同周期类型上一自然周期的同形态 current 归档；没有同形态归档时按本次冻结范围回看该形态事实，不借另一形态基线、不以 v-1 代替。
- 数值、健康度和完整归档语义沿用各规范，成功确认无事实或不适用为「-」，读取异常为「未取得」，已取得零值仍为 0；不把部分合计冒充全量，不在详情重算。

## 4. 归档与查阅

- 报告按统计周期建立索引，周报每个自然周一行、月报每个自然月一行，两形态分别归档版本；同周期同形态按内容判重，重复复用、变化递增，历史可溯。
- 报告为静态产物：入库时一次性生成并持久化 HTML、确定双层表头、抽取概览及较上期对比快照，归档后详情仅消费对应版本结果与各自快照，不重新计算指标或比较值；指标口径问题回溯生成侧。人员周报弹窗与健康度报告链接只读取对应来源归档，不写回当前报告。元信息采用公共 `tpl-overview__meta` 自动响应式多列网格与公共版本下拉，尺寸、入库时间作为次要信息保留；详情不引用 Descriptions，不设大纲。页头保留返回链接和面包屑，完整版右侧保留「导出为图片（分页 PNG）」「导出为HTML」「获取原件」，简化版仅「导出为图片（PNG）」「获取原件」，不再重复放返回按钮；公共骨架引用与页面交互见 [Web UI · 报告详情](web-ui.md#report-detail)。
- 完整版详情页「导出为图片（分页 PNG）」导出当前查看版本的报告标题、统计区间、本期概览、六个固定章节、全部域与仓库行，以及正文后的「人员工作明细」附录，不仅截取当前视口。固定普通分辨率 1600×2000 分页，每页底部标页码；跨页不截断表格行，续页重复对应章节及完整表头，角色表保留完整双层表头，超高单元格仅按完整文本行续写。全部分页 PNG 按页排序打包 ZIP，一次下载；原件去扩展名为 basename，压缩包为 `basename_vN_png.zip`，包内为 `basename_vN_p01.png` 等顺序页文件。导出期间冻结当前版本及数据并禁用版本切换，loading 与失败重试保留当前版本和数据，不接入批量异步导出中心，权限与详情查看一致；人员附录的同周来源读取及权限仍沿用 §3，分页和反馈详见 [Web UI · 报告详情](web-ui.md#report-detail)。
- 完整版详情页「导出为HTML」导出当前版本完整报告和「人员工作明细」附录，使用与分页 PNG 相同的版本及人员快照，不重新计算指标或跨版本补值；文件名为 `basename_vN.html`，内联公共样式，移除脚本、弹窗、版本切换、页面操作按钮及外部资源依赖，可离线打开。空正文禁止导出，权限与详情查看一致；具体呈现与反馈详见 [Web UI · 报告详情](web-ui.md#report-detail)。
- 简化版导出当前形态当前版本完整内容为一张 PNG，宽 1600 像素、高度随内容；包含标题、区间、概览、全部域的项目总览、四块项目进展与健康度，不添加人员附录。超过单图上限整体降低像素密度，不分页；文件为 `basename_vN.png`。所有导出期间冻结形态及版本，不混版，不下载残缺文件。
- 列表每周期一行，分别提供两形态状态、版本、查看与原件；齐全度 0/2、1/2、2/2，不含历史版本。旧版只有完整版时保留 1/2，不自动转换简化版；生成仍输出两份。只有一份变化时仅该形态递增，但两份校验完才确认批次成功。
- 归档、触发与生成规则详见 [报告配置 · 业务规则](../../报告配置/references/business-rule.md)，数据语义详见 [报告配置 · 数据定义](../../报告配置/references/data.md)。

## 5. 关键约束

- 报告指标由功能排期卡片、映射 Harness 工程与代码仓 Git、项目管理配置成员快照、Qoder 用量、研发周报与产品文档健康度归档事实生成，不接受手工填报；完整版核心进展只引用研发周报，简化版按本域已有事实归纳；健康度只引用对应归档评分。
- 报告范围以报告配置生效数据为准；每次生成只创建一个会话并传递报告扩展已配置启用的全部域引用、各项目有效成员关系与全量身份快照，不维护第二份实体、成员或映射。人员产出周报、日报仍使用配置成员的全局去重并集；并集为空或人员真源未取得时拒绝生成人员产出报告，项目进度报告的已确认空名单仍按零人数生成。
- 原始报告文件单文件直接获取，不接入批量异步导出中心；报告落库即页面可查，本子域不做主动通知。
- 项目停用只影响此后的生成，不删除历史报告。
