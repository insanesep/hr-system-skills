# 项目进度报告 · 业务规则

## 1. 每周期一份，按组查看

- 每个统计周期仅生成一份项目进度报告：周报每个自然周一份，月报每个自然月一份；不得按项目组拆分生成、触发或归档。
- 报告固定使用 `_all` 报告项和 `progress_yyyyMMdd__all.md` 文件名，包含全部已配置启用的域/项目组；项目组仅作为正文分组，不再对应独立报告。
- 报告范围只读引用 [报告配置](../../报告配置/SKILL.md) 的生效数据，不另建实体；各组统计边界由其生效配置及生成会话快照确定，根文件不计入项目，跨项目同名实现不混入。
- 汇总先按域、卡片稳定 ID、人员稳定 ID 与源仓稳定 ID + commit SHA 去重，不叠加域和子项目重复数据；除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余每章仅用一个表格，前五章按项目 key 字典序列项目组，harness文档健康度按仓库名字典序列仓库；功能排期、代码提交及 Qoder 使用两张表格的末行均以加粗的「全量汇总」展示，团队人员末行以加粗的「全量汇总(去重)」展示，项目核心进展与 harness文档健康度不设全量汇总，明细不直接相加为汇总。
- 项目组配置齐备并启用后加入下一份周期报告，停用后从后续报告移除；历史单组报告保留原 key、文件名和版本，不猜测或复制到其它范围。

## 2. 生成方式

1. 触发方式在 [报告配置](../../报告配置/SKILL.md) 的报告触发配置页维护：项目进度报告的周报与月报各内置一条独立 `_all` 配置行，分别使用每周 / 每月定时规则，可同时调度并支持手动立即生成；统计窗口按各自周期口径计算后随任务下发，不按项目组联动配置行。
2. 触发后服务端通过 Qoder SDK 创建一个生成会话，携带报告扩展已配置启用的全部项目组的范围类型、稳定引用、生效配置快照与统计窗口，Git 采集分支固定为 `master + feature/*`，不随 `branch_policy` 收窄为单分支；人员快照同时携带各项目的启用成员关系、启用稳定人员的身份、姓名与角色，以及按人员稳定 ID 去重的全局并集，随报告版本留档，同时携带各项目各角色的本期首次有效提交判定及对应人员稳定 ID，供团队人员「新」标记使用。Git 采集、作者识别与程序校验复用研发周报链路，团队和提交指标仅引用已验证的项目、人员及角色结果，最终正文不得自行识别作者或重计提交。生成逻辑唯一真源为 [progress-report.md](progress-report.md)。卡片与流水仍从功能排期管理取得，不因报告范围配置改换事实来源。
3. 产出报告由服务端直接落库归档，完成渲染、版本递增与周索引，不经过推送；外部生成会话产出可经推送上报旁路入库。
4. 模型文件操作仅限本任务约定工作区，禁止使用其它位置的同名开发者副本；服务端 Git 同步与采集由程序在专用缓存中执行，按冻结仓库范围和统计窗口提供已验证事实，模型不得访问缓存或自行采集。
5. 生成任务记录触发来源、状态、耗时与失败原因；失败可在生成记录中重试。

## 3. 报告内容口径

成功读取后确认无归档内容或指标不适用时使用 ASCII「-」：无同周期上期报告、上期原件无概览、概览角色或列确无归档值，无同周研发周报、无核心进展章节或无本项目明确内容，无健康度归档、评分待定或不可比，以及零人数、零请求导致的人均或次均不适用。已取得的零计数、零 Credits 仍为 0，不改计量。取数异常、已有报告的 current version 缺失、成员或仓边界未知、Qoder 账号或稳定身份未匹配、格式破损不能可靠读取时，受影响项仍为「未取得」并说明原因，不把失败变成 0 或「-」；部分数据标「已匹配」而非全量，无权限仍为「无查看权限」。

- 项目核心进展：读取同统计周期内对应自然周实际入库时间最新的研发周报 current version，每周只选一份，月报合并各周内容并去重，不按当前项目 key 优先挑旧报告。仅提取「AI 分析总结 → 核心进展」中明确属于本项目的内容；名称匹配同时采用来源报告版本快照中相同稳定 projectId、且仓边界一致的历史 name/key，不依赖当前改名或硬编码同义词，不将跨项目同名内容或全局进展复制到各组。成功读取后无同周周报、无核心进展章节或无本项目明确内容为「-」，读取失败或项目边界无法确认仍为「未取得」并说明原因，不从其他数据源推测补写。各组核心进展按事实在单元格内以安全 HTML `ul` / `li` 无序列表逐项展示，折行采用悬挂缩进，每个小点正文不超过 50 字；超过时在原事实边界内拆分，不扩写或省略关键信息。原件仅保留纯排版列表标记，不写脚本，空缺与异常沿用上述标记；不新增分项目周报配置。
- 团队人员：章节标题下固定展示说明「以本周期有提交记录的人员为准」。只读引用 [项目管理 · 项目成员](../../../研发管理/项目管理/references/business-rule.md#membership)，人员在每个项目内独立维护，同人可参与多个项目。当前项目成员关系和对应稳定人员均为启用（ENABLED）时纳入任务快照，仅保留统计窗口内在项目映射仓有有效提交且身份匹配对应角色的成员，无提交成员从团队人数与人员明细排除；本期新增人员是指其在该项目该角色的首次有效提交落在统计窗口内，且窗口开始前无同项目同角色有效提交，由生成侧复用 Git 采集与身份校验结果判定并随版本快照归档，不按成员加入时间或页面猜测。全量按人员稳定 ID 去重，任一参与项目符合新增条件即保留标记。HTML 姓名旁以公共 `u-success` 文字样式展示「（新）」，不使用 Tag 边框、底色或额外标签留白；Markdown 与 PNG 以「姓名（新）」表示；标记不改变团队人数、人员周报来源或点击行为。按快照角色与人员稳定 ID 分别去重展示产品人数、研发人数与架构人数，并在人员明细中按角色展示具体人员姓名。同人多角色在对应角色各计一次并各展示一次，全量仅保留任一参与项目有有效提交的人员，各角色人数与人员明细按全局成员并集分别去重，汇总行标签固定为「全量汇总(去重)」。来源成功且确认无配置成员或过滤后无提交成员时各人数为 0、人员明细为「无」、人均功能数与对应角色人均提交行数为「-」；成员身份、角色或本项目 Git 采集来源未取得时，对应团队人数、人员明细及依赖的人均指标标「未取得」；单项目缺失不影响其它来源完整的项目，参与范围的任一项目缺失时全量团队与提交指标不展示部分合计，不以组织全员或其它项目名单兜底。
- 人员周报查看：Web 详情中，具备 `devhubMemberOutputReport` 权限的用户可点击人员明细中的姓名，通过公共 Dialog 查看该人员本周研发周报；无权限时姓名仅作文本，不发起数据请求。本周为当前查看进度报告统计窗口截止日所在自然周，读取该周无项目维度研发周报中实际入库时间最新的当前归档版本，不以发报日或报告项 ID 挑选历史重复项；每次点击姓名或导出 PNG 均重新读取来源，按人员稳定 ID 提取「按人员综合分析」下该人员的完整小节，包含代码产出、功能排期任务、Qoder 用量与综合评价，不按当前项目过滤或重复分摊。弹窗提供同来源完整周报详情链接；成功读取后无同周周报或人员小节时展示「-」；读取失败、已有 current version 缺失、身份未匹配或格式破损时展示「未取得」并说明原因，不展示日报、不推测内容。点击只读取人员产出报告，不写回进度报告、不重算指标；Markdown 原件与 Web 正文中的姓名保持纯文本。导出 PNG 时在六章正文后追加「人员工作明细」附录，按人员稳定 ID 去重展示上述同周研发周报个人小节，包含代码产出、主要工作、功能排期任务、Qoder 用量与综合评价；附录不计入 Web 正文或 Markdown 原件，无人员产出报告权限时对应人员明细显示「无查看权限」，成功读取后无同周周报或人员小节为「-」，读取异常或身份未知为「未取得」并说明原因。
- 功能排期：按项目组展示本期功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率与人均功能数；排期、非需求改动、完成及延期事实引用功能排期管理。
- 代码提交：按产品、研发、架构分别展示本期提交次数、提交行数（新增 / 删除）与人均提交行数；各角色统计项目组映射 `harness_repo` + `code_repos` 的统计窗口，仅保留身份匹配该项目该角色配置成员的贡献。同人多角色时其贡献在对应角色分别完整展示，角色指标不可相加；未配置或身份未匹配的作者不计入分角色指标、不点名，不从 Git 创建或自动迁移项目成员。
- Qoder 使用：按同一项目配置成员快照取本期自然日用量，按产品、研发、架构分别展示总使用量、人均使用量、总请求次数、人均请求次数与平均单次请求 Credits；章内分为「产品与研发」「架构」两个表格，均按项目组展示并各设全量汇总。平均单次请求 Credits 沿用 Qoder 用量分析的次均消耗口径，按对应角色总使用量 ÷ 对应角色总请求次数计算，保留 1 位小数；总请求次数为 0 时显示「-」，不对各组次均值求和或取平均。各角色活跃成员沿用 Qoder 用量分析口径，在该项目该角色配置成员内按正 Credits 记录去重认定。个人用量作为人员维度完整展示于其参与的每个项目及每个已配置角色，不按仓库分配或推测分摊，角色指标不可相加；`_all` 在各角色内按人员稳定 ID、自然日及来源快照去重，同一用量在同一角色只计一次，不对项目行求和。成功查询且 Qoder 账号、稳定身份均已确认的成员在自然日无快照记录时按无用量明确补 0；配置成员已确认空时对应角色总使用量、总请求次数及活跃成员数为 0，人均指标与平均单次请求 Credits 为「-」；成员来源或成员用量未取得时标「未取得」，部分成员未匹配时保留已匹配成员数据，展示已匹配/总人数与未匹配名单，合计明确标为已匹配成员非全量，仅未匹配成员标「未取得」，不冒充完整项目或角色总量或清空全部用量。
- harness文档健康度：只读引用 [产品文档健康度报告](../../产品文档健康度报告/references/health-report.md) 归档，按仓库展示上周、本周得分、较上期与「查看报告」。本周为统计截止日所在自然周，上周为其上一自然周；各周只在可确定的同仓单仓域报告中，采用实际入库时间最新的 current 归档「仓库综合评分与环比」综合分 R，不混入跨域或子范围结果，不平均、不退取旧版本。成功读取但无合格归档、评分待定或不可比时对应得分与差值为「-」；查询失败、已有 current version 缺失、格式破损或仓边界未知时受影响项为「未取得」并说明原因。较上期 = 本周得分 − 上周得分，保留 1 位小数；正值「↑ +X.X」用公共成功色，负值「↓ -X.X」用公共危险色，零「0.0」用公共中性色；原件、HTML 与 PNG 一致，不改评分公式。操作链接所选本周报告，无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」。本章无全量汇总，不重跑评估，仍排除 common/design。
- 全量人均指标统一按「全量总数 ÷ 全量去重人数」计算，不对各组人均值求和或取平均；功能排期使用去重研发人数，代码提交分别使用产品、研发、架构去重人数，Qoder 使用分别使用产品、研发、架构去重活跃成员数。全量平均单次请求 Credits 按对应角色全量总使用量 ÷ 全量总请求次数重新计算，不对各组次均值求和或取平均。
- 本期概览：位于统计区间后、六章前，以加粗文本「本期概览」作为非章节标题；原件为一个「指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比」表，固定功能排期（完成率 / 延期率）、活跃人数、Qoder 用量、代码提交行数（+ / -）四行。功能排期在同一张卡内分行展示完成率与延期率，各自保留归档值、辅助说明及较上期对比，不合并计算。活跃人数在同一张卡内按产品、研发、架构分行展示对应角色的去重人数；仅统计本周期有有效提交的人员，同人多角色在对应角色各展示一次，不将角色人数相加为概览指标。Qoder 用量在同一张卡内按产品、研发、架构分别展示总使用量，辅助说明列出各角色平均单次 Credits；代码提交行数在同一张卡内按三角色分别展示新增 / 删除行数。全部复用生成时一次性计算的同版本 `_all` 去重汇总，角色独立去重、严禁跨角色求和；对应角色或列确无归档值时该项为「-」，取数异常仍为「未取得」并说明原因，零请求的次均为「-」。入库将归档值、补充说明、较上期对比结果及其快照随本版本持久化为四个公共 KPI 卡，详情不重算、不跨版本补齐，与元信息及正文同步切换。
- 本期概览 · 较上期：上期为同报告周期类型的上一自然周期，周报取上一自然周、月报取上一自然月，不是当前报告项的历史版本 v-1。当前版本生成时读取上一期同类型 `_all` 全量报告的当前归档结果，以其中四行概览归档值为基线形成对比快照并随本版本归档；上期后续版本变化不改写既有快照，版本切换只读各自快照。成功读取后确认无同周期上期报告、上期原件无概览或对应角色、列确无归档基线时，增减值与百分比均为「-」；查询失败、已有 current version 缺失或格式破损时受影响项为「未取得」并说明原因；本期值因取数失败未取得时比较项也为「未取得」，不按 0 处理，不从旧六章、其他期、v-1 或实时来源补齐。
- 对比计算与展示：增减值 = 本期归档值 − 上期快照基线值；正值显示「↑ +」、负值显示「↓ -」、零值显示「—」，非零值保留对应精度、千分位与单位。增减百分比 = 增减值 ÷ |上期快照基线值| × 100%，保留 1 位小数，正、负值分别带正、负号，零值为「0.0%」；上期为 0 且本期非 0 时百分比为「-」，两期均 0 时增减值为「—」、百分比为「0.0%」，缺失不算 0。完成率、延期率的绝对增减单位为「个百分点」，相对变化仍用 %；活跃人数用「人」，Qoder 用量用「Credits」，代码行用「行」。仅归档值所列指标参与比较，补充说明不新增对比。
- 对比粒度与归档呈现：活跃人数卡按产品、研发、架构分别比较对应角色去重人数，不跨角色求和；Qoder 卡按产品、研发、架构逐角色比较总 Credits；代码卡按角色分别比较新增行与删除行，增减值格式为「新增 ↑ +X 行；删除 ↓ -Y 行」，百分比对应展示新增、删除双值，正负各自保留，不跨角色求和、不以新增与删除互抵。多角色单元格使用安全 HTML `br` 逐角色换行。HTML 四卡显示「较上期」及与原件相同的增减值、百分比，正值用公共成功色、负值用公共危险色、零值用公共中性色，缺失不标涨跌；PNG 与 HTML 数据和语义色一致。具体格式以 [生成逻辑 · 呈现与归档规则](progress-report.md#呈现与归档规则) 为单源。
- 数值千分位（计数、Credits、增删行、人均）、既有精度与符号保留、角色连续列序及服务端入库确定双层表头以 [progress-report.md · 呈现与归档规则](progress-report.md#呈现与归档规则) 为真源；日期、ID、文件名与缺失符不处理，前端不得修改原件、计量或丢指标。
- 固定章节、指标公式、顺序与输出模板详见 [progress-report.md · 章节规范](progress-report.md#章节规范) 及 [输出模板](progress-report.md#输出模板)。

## 4. 归档与查阅

- 报告按统计周期建立索引，周报每个自然周仅一条报告项，月报每个自然月仅一条报告项；同周期重复入库走版本递增而非覆盖，历史版本可溯。
- 报告为静态产物：入库时一次性生成并持久化 HTML、确定双层表头、抽取概览及较上期对比快照，归档后详情仅消费对应版本结果与各自快照，不重新计算指标或比较值；指标口径问题回溯生成侧。人员周报弹窗与健康度报告链接只读取对应来源归档，不写回当前报告。元信息采用公共 `tpl-overview__meta` 自动响应式多列网格与公共版本下拉，尺寸、入库时间作为次要信息保留；详情不引用 Descriptions，不设大纲。页头保留返回链接和面包屑，右侧仅「导出为图片（分页 PNG）」「获取原件」，不再重复放返回按钮；公共骨架引用与页面交互见 [Web UI · 报告详情](web-ui.md#report-detail)。
- 详情页「导出为图片（分页 PNG）」导出当前查看版本的报告标题、统计区间、本期概览、六个固定章节、全部项目组与仓库行，以及正文后的「人员工作明细」附录，不仅截取当前视口。固定普通分辨率 1600×2000 分页，每页底部标页码；跨页不截断表格行，续页重复对应章节及完整表头，角色表保留完整双层表头，超高单元格仅按完整文本行续写。全部分页 PNG 按页排序打包 ZIP，一次下载；原件去扩展名为 basename，压缩包为 `basename_vN_png.zip`，包内为 `basename_vN_p01.png` 等顺序页文件。导出期间冻结当前版本及数据并禁用版本切换，loading 与失败重试保留当前版本和数据，不接入批量异步导出中心，权限与详情查看一致；人员附录的同周来源读取及权限仍沿用 §3，分页和反馈详见 [Web UI · 报告详情](web-ui.md#report-detail)。
- 归档、触发与生成规则详见 [报告配置 · 业务规则](../../报告配置/references/business-rule.md)，数据语义详见 [报告配置 · 数据定义](../../报告配置/references/data.md)。

## 5. 关键约束

- 报告指标由功能排期卡片、映射 Harness 工程与代码仓 Git、项目管理配置成员快照、Qoder 用量、研发周报与产品文档健康度归档事实生成，不接受手工填报；核心进展只引用研发周报，健康度只引用对应归档评分。
- 报告范围以报告配置生效数据为准；每次生成只创建一个会话并传递报告扩展已配置启用的全部项目组引用、各项目成员关系快照及全局去重成员并集，不维护第二份实体、成员或映射。人员产出周报、日报仍使用配置成员的全局去重并集；并集为空或人员真源未取得时拒绝生成人员产出报告，项目进度报告的已确认空名单仍按零人数生成。
- 原始报告文件单文件直接获取，不接入批量异步导出中心；报告落库即页面可查，本子域不做主动通知。
- 项目停用只影响此后的生成，不删除历史报告。
