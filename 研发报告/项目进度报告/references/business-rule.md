# 项目进度报告 · 业务规则

## 1. 每周期一份，按组查看

- 每个统计周期仅生成一份项目进度报告：周报每个自然周一份，月报每个自然月一份；不得按项目组拆分生成、触发或归档。
- 报告固定使用 `_all` 报告项和 `progress_yyyyMMdd__all.md` 文件名，包含全部已配置启用的域/项目组；项目组仅作为正文分组，不再对应独立报告。
- 报告范围只读引用 [报告配置](../../报告配置/SKILL.md) 的生效数据，不另建实体；各组统计边界由其生效配置及生成会话快照确定，根文件不计入项目，跨项目同名实现不混入。
- 汇总先按域、卡片稳定 ID、人员稳定 ID 与源仓稳定 ID + commit SHA 去重，不叠加域和子项目重复数据；每章仅用一个表格，表体按项目 key 字典序列项目组；功能排期、代码提交、团队人员与 Qoder 使用末行以加粗汇总行展示全量汇总，项目核心进展不设全量汇总，明细不直接相加为汇总。
- 项目组配置齐备并启用后加入下一份周期报告，停用后从后续报告移除；历史单组报告保留原 key、文件名和版本，不猜测或复制到其它范围。

## 2. 生成方式

1. 触发方式在 [报告配置](../../报告配置/SKILL.md) 的报告触发配置页维护：项目进度报告的周报与月报各内置一条独立 `_all` 配置行，分别使用每周 / 每月定时规则，可同时调度并支持手动立即生成；统计窗口按各自周期口径计算后随任务下发，不按项目组联动配置行。
2. 触发后服务端通过 Qoder SDK 创建一个生成会话，携带报告扩展已配置启用的全部项目组的范围类型、稳定引用、生效配置快照、分支策略与统计窗口；人员快照同时携带各项目的启用成员关系、启用稳定人员的身份与角色，以及按人员稳定 ID 去重的全局并集，随报告版本留档。生成逻辑唯一真源为 [progress-report.md](progress-report.md)。卡片与流水仍从功能排期管理取得，不因报告范围配置改换事实来源。
3. 产出报告由服务端直接落库归档，完成渲染、版本递增与周索引，不经过推送；外部生成会话产出可经推送上报旁路入库。
4. 仓库操作只允许落在生成会话的约定工作区内，不使用本机其它位置的同名开发者副本。
5. 生成任务记录触发来源、状态、耗时与失败原因；失败可在生成记录中重试。

## 3. 报告内容口径

- 功能排期：按项目组展示本期功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率与人均功能数；排期、非需求改动、完成及延期事实引用功能排期管理。
- 代码提交：展示本期提交次数、提交行数（新增 / 删除）与人均提交行数；提交总次数及总行数来自项目组映射代码仓的统计窗口，与配置成员名单独立，名单外作者的范围内提交仍计入项目总量。按人员展示时仅保留身份匹配该项目配置成员的贡献；未配置或身份未匹配的作者不点名，不从 Git 创建或自动迁移项目成员。
- 团队人员：只读引用 [项目管理 · 项目成员](../../../研发管理/项目管理/references/business-rule.md#membership)，人员在每个项目内独立维护，同人可参与多个项目。当前项目成员关系和对应稳定人员均为启用（ENABLED）时纳入任务快照，无须窗口内有 Git 提交；按快照角色与人员稳定 ID 分别去重展示产品人数、研发人数与架构人数，同人多角色在对应角色各计一次，全量各角色人数按全局成员并集分别去重。来源成功且确认无配置成员时各人数为 0、人均功能数与人均提交行数为「—」；成员来源未取得时对应指标为「未取得」，Git 采集失败不改变已取得的团队人数，不以组织全员或其它项目名单兜底。
- Qoder 使用：按同一项目配置成员快照取本期自然日用量，展示总使用量、人均使用量、总请求次数与人均请求次数；活跃成员沿用 Qoder 用量分析口径，在该项目配置成员内按正 Credits 记录去重认定。个人用量作为人员维度完整展示于其参与的每个项目，不按仓库分配或推测分摊；`_all` 按人员稳定 ID、自然日及来源快照去重，同一用量只计一次，不对项目行求和。配置成员已确认空时总使用量、总请求次数及活跃成员数为 0、人均指标为「—」；成员来源或成员用量未取得时标「未取得」，不以部分成员数据冒充完整项目总量。
- 项目核心进展：优先按项目 key 引用已存在的对应研发周报；不存在时回退引用无项目维度总人员产出周报的「AI 分析总结 → 核心进展」，只提取能明确对应本项目的内容，不把全局进展复制到各组；无明确内容标「未取得」，不从其他数据源推测补写。按 key 读取仅兼容已有产物，不新增分项目周报配置。
- 全量人均指标统一按「全量总数 ÷ 全量去重人数」计算，不对各组人均值求和或取平均；功能与提交行数使用去重研发人数，Qoder 使用去重活跃成员数。
- 固定章节、指标公式、顺序与输出模板详见 [progress-report.md · 章节规范](progress-report.md#章节规范)。

## 4. 归档与查阅

- 报告按统计周期建立索引，周报每个自然周仅一条报告项，月报每个自然月仅一条报告项；同周期重复入库走版本递增而非覆盖，历史版本可溯。
- 报告为静态产物：归档后只做渲染呈现，包括 Markdown 转 HTML 与大纲锚点导航，不重新计算指标；指标口径问题回溯生成侧。
- 详情页支持将当前查看版本的完整正文导出为 PNG，包含报告标题、统计区间、五个固定章节及全部项目组行，不仅截取当前视口；文件名由原件文件名去扩展名后追加 `_v{版本号}.png`，不接入批量异步导出中心，权限与详情查看一致。
- 归档、触发与生成规则详见 [报告配置 · 业务规则](../../报告配置/references/business-rule.md)，数据语义详见 [报告配置 · 数据定义](../../报告配置/references/data.md)。

## 5. 关键约束

- 报告指标由功能排期卡片、映射代码仓 Git、项目管理配置成员快照、Qoder 用量与研发周报事实生成，不接受手工填报；核心进展只引用研发周报。
- 报告范围以报告配置生效数据为准；每次生成只创建一个会话并传递报告扩展已配置启用的全部项目组引用、各项目成员关系快照及全局去重成员并集，不维护第二份实体、成员或映射。人员产出周报、日报仍使用配置成员的全局去重并集；并集为空或人员真源未取得时拒绝生成人员产出报告，项目进度报告的已确认空名单仍按零人数生成。
- 原始报告文件单文件直接获取，不接入批量异步导出中心；报告落库即页面可查，本子域不做主动通知。
- 项目停用只影响此后的生成，不删除历史报告。
