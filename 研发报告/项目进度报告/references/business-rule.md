# 研发周报 业务规则字典

> 本文件为研发周报模块的规则真源。SKILL.md 仅做导航，规则细节全部在此。

## 1. 报告类型与文件命名

模块固定承接三类报告，类型枚举不可扩展（新增报告类型须先改本字典）：

| 类型编码 | 报告名称 | 标准文件命名 | 产出方 | 内容梗概 |
|---------|---------|-------------|--------|---------|
| `WEEKLY_DEV` | 研发周报 | `weekly_dev_{yyyyMMdd}.md` | ai-checker | 提交统计、AI 分析总结、按人员分析、功能进展追踪、仓库分布、功能使用量、MCP 工具用量 |
| `CONSISTENCY_SNACKINGDOM` | 文档一致性校验（零食王国） | `consistency_{yyyyMMdd}_snackingdom.md` | ai-checker | 零食王国全模块文档与代码对齐检查 |
| `CONSISTENCY_YDTJ` | 文档一致性校验（有点推荐） | `consistency_{yyyyMMdd}_ydtj.md` | ai-checker | 有点推荐全模块文档与代码对齐检查 |

**文件命名判定规则：**
- `yyyyMMdd` 为**发报日**（报告生成日期），非统计区间
- 文件名不符合上述两种模式时，入库按「无法识别」处理，需人工指定类型与发报日（见 §3.3）
- 历史遗留命名 `consistency_{yyyyMMdd}.md`（无项目后缀）视为零食王国报告，兼容解析

## 2. 周期归属与周索引

| 概念 | 定义 | 用途 |
|------|------|------|
| 发报日 | 文件名中的 `yyyyMMdd` | 报告的唯一日期身份 |
| 所属周 | 发报日所在的**自然周**（周一 00:00 ~ 周日 24:00，东八区） | 周索引分组的唯一依据 |
| 统计区间 | 仅 `WEEKLY_DEV` 有：报告正文首部声明的「上周一 ~ 上周日」 | 详情页元信息展示，不参与分组 |

规则：
1. 周索引 = 按「所属周」倒序分组，组内按类型固定顺序排列：`WEEKLY_DEV` → `CONSISTENCY_SNACKINGDOM` → `CONSISTENCY_YDTJ`
2. 每周理论齐全度为 3/3；某类型缺失时该周标记「待补」，缺口展示快捷补传入口（仅 Web）
3. 周标签格式：`2026 年第 36 周（08-31 ~ 09-06）`，周序号按 ISO 8601 周历计算
4. 本周行仅周日（东八区）当天起展示：发报日为周日，周中（周一 ~ 周六）窗口上界收敛为上周，避免「待补」进行态噪音；周中已提前入库的本周报告随周日到来自然可见
5. 研发周报的统计区间从 md 正文首部引用块解析（`统计区间：YYYY-MM-DD（周一）~ YYYY-MM-DD（周日）`）；解析失败时元信息降级为「—」，不阻断入库

## 3. 入库与版本规则

### 3.1 自动上报（主通道）

- ai-checker 生成报告后调用上报入口，携带：md 文件、报告类型、发报日
- 服务端按 §1 命名规则二次校验类型与发报日，不一致时**以文件名为准**并记录告警日志
- 上报为幂等：同类型同发报日同内容（文件哈希一致）重复上报不产生新版本，直接返回已有报告

### 3.2 手动补传（兜底通道）

- 仅 Web 端开放，权限 `BTN:DEV_WEEKLY_REPORT:UPLOAD`
- 上传时系统按文件名自动识别类型与发报日；识别失败时由用户在表单中手动指定
- 手动补传记录上传人，来源标记为「手动」

### 3.3 版本规则

- 唯一键 =（报告类型 + 发报日）；重复入库 → 版本号递增，旧版本保留可查
- 列表与详情默认展示**最新版本**；详情页可切换历史版本（只读）
- 版本内记录：文件名、文件哈希、来源（自动 / 手动）、入库时间、操作人
- 报告**不允许删除**（审计留痕）；错误入库的报告以新版本修正

### 3.4 文件约束

| 约束项 | 规则 | 超限处理 |
|--------|------|---------|
| 格式 | 仅 `.md`（UTF-8） | 拒绝入库，提示「仅支持 Markdown 文件」 |
| 大小 | ≤ 2MB | 拒绝入库，提示压缩图片或拆分 |
| 标题 | md 首个 `#` 一级标题作为报告标题 | 缺失时以「类型名 + 发报日」兜底 |

## 4. Markdown 渲染规则

1. **渲染时机**：入库时一次性渲染为 HTML 并随版本持久化（留痕产物 + App 端 WebView 直接取用，避免大文件卡顿与渲染口径分叉）。
   ⚠️ **Web 端例外（2026-09-09 起）**：Web 详情页改为**前端实时渲染**——按 mdUrl 拉取原始 md，`marked(GFM)` 渲染 + `DOMPurify` 白名单过滤 + GitHub 风格样式内联展示，不再 iframe 消费 htmlUrl；大纲锚点 `h-{seq}`（h2/h3 文档序）与图片占位「[图片已移除]」口径与服务端渲染保持一致。App 端 WebView 仍消费服务端渲染产物（产物无样式），GitHub 风格排版在内容加载前以 document_start 脚本注入（`reportGithubCss.ts`）。服务端渲染管线与 §4.2~§4.5 规则继续约束 App 端与留痕产物。
2. **大纲提取**：从渲染产物的 `h2` / `h3` 标题提取锚点目录，详情页侧边（Web）/ 抽屉（App）展示，点击滚动定位
3. **安全**：渲染产物必须经 XSS 白名单过滤（仅保留排版标签与表格 / 代码块 / 列表），剥离 `<script>`、内联事件与外部资源引用；md 中的图片若为外链直接丢弃并占位「[图片已移除]」
4. **表格与代码块**：表格横向滚动容器包裹；代码块保留语言标记与等宽字体，不换行
5. 重新渲染仅发生在管理端「重新渲染」运维动作（如渲染器升级），不产生新版本号

## 5. 权限矩阵

| 权限点 | 编码 |
|--------|------|
| Web 菜单（列表 + 详情查看） | `MENU:RND:DEV_WEEKLY_REPORT` |
| 手动补传按钮 | `BTN:DEV_WEEKLY_REPORT:UPLOAD` |
| App 菜单 | `M:RND:DEV_WEEKLY_REPORT` |

- 权限初始化仅登记权限点，**不指定角色**；授权范围由权限体系侧另行配置
- 版本切换、原始文件获取与查看同权，不单独设权限点

| 关键词 | 本模块语义 | 公共逻辑真源 | 结论 |
|--------|-----------|-------------|------|
| 一致性 | ai-checker 产出的**文档**一致性校验报告 | `公共数据/数据一致性`（销售 / 库存金额口径） | 语义不同域，不引用 |

| 报告告知 | ai-checker 侧既有推送机制承担 | `公共功能/企微应用消息发送` | 本模块无通知需求，不接入 |

## 7. 异常与边界场景

| 场景 | 处理 |
|------|------|
| 某周部分类型未上报 | 周分组正常展示已入库报告，缺失类型灰显「未入库」+ 补传入口（Web） |
| 发报日落在未来 | 拒绝入库（防文件名笔误），提示「发报日不可晚于今天」 |
| 同一周出现两个不同发报日的同类型报告（如周一补发） | 视为两条独立报告，均归入各自发报日所属周，不合并 |
| md 正文为空或仅标题 | 允许入库，详情页展示空态提示「报告内容为空」 |
| 自动上报与手动补传并发同唯一键 | 以先落库者为当前版本，后到的递增为新版本，不报错 |
| 时区 | 全部日期口径为东八区；周归属、发报日均按东八区零点切分 |
