# 项目进度报告（完整版）

> 定位：项目进度报告完整版的正文、四卡概览与排版规则真源，按域展示核心进展、团队人员、功能排期、代码提交与 Qoder 使用，按仓库展示 harness 文档健康度。本文件是共用生成入口引用的内容规范，不是可单独生成报告的 skill。

配置、工作区、同步、采集、生成与交付统一遵循 [共用入口 · 执行流程](progress-report.md#执行流程)；双产物、批次关联、落库与推送统一遵循 [共用入口 · 双产物与归档](progress-report.md#双产物与归档)，本文件不另设执行流程或推送契约。

完整版文件名保持为 `progress_yyyyMMdd__all.md`，标题为「项目进度报告（完整版）- {yyyy-MM-dd}」，日期为生成当天。完整版与简化版分别按报告形态独立归档和递增版本，同一批次关联两个实际版本，不保证版本编号相同，不混用跨形态版本值。完整版的上期概览、归档基线与成员口径只取同周期类型的完整版，不能借用简化版数据。

## 统计与人员口径

### 范围真源

域展示名称只读引用 [项目管理 · 项目配置与来源](../../../研发管理/项目管理/references/business-rule.md#source) 中的项目名称，以稳定项目标识关联，名称快照随版本归档；更名或启停不改写历史 key、文件名和统计边界。正文第一列统一为「域」，不以报告 key 或子功能名代替配置名称。

域展示与统计范围只读采用 [报告配置](../../报告配置/SKILL.md) 中全部已配置启用的报告范围类型、稳定引用与生效配置；项目 key 同源。项目进度 Git 分支固定为主干 master 与 feature 功能分支，不因分支策略配置收窄为单分支；工作树分支不单独纳入，release 不另作统计分支。各组统计边界采用项目管理配置的 harness 工程与代码服务仓快照，不按一级目录拆分项目；未配置仓及跨项目同名实现不混入。外部会话使用同一范围快照，不另建实体或猜测归属。

卡片归属采用功能排期按源仓与启用项目映射得到的查询投影。一张卡至多归属一个启用项目；合并卡全部子卡同属一个启用项目才归属该项目，否则为未归属项目，不重复分配到各组。全量仅汇总参与生成项目范围内的卡片并按稳定卡片 ID 去重。新范围配置齐备并启用后加入后续周期报告的分组，停用后从后续报告移除，不删历史归档。

统计周期与窗口遵循 [共用入口 · 执行流程](progress-report.md#执行流程)，完整版不另行改变周报、月报窗口或采集范围。

### 人员范围与快照

只读采用 [项目管理 · 项目成员](../../../研发管理/项目管理/references/business-rule.md#membership) 的配置，不维护第二份人员名单。人员在每个项目内独立维护，同一稳定人员可属于多个项目；当前项目的成员关系和对应稳定人员均为启用时，才进入该项目的候选名单。

配置成员快照只作为候选名单，域人数取与研发周报同源的 Git 作者识别和校验结果，仅纳入统计窗口内有本项目有效提交且身份匹配对应角色的人员。无提交成员从团队人数、人员明细与相关人均分母排除；不因中文姓名、英文名、拼音或邮箱未与别名完全一致而提前删除作者，不从 Git 创建或自动迁移成员归属，不使用组织全员或其它项目名单兜底。

产品人数、研发人数、架构人数按快照角色及人员稳定 ID 分别去重计数，并在人员明细中按角色展示姓名。角色内按姓名、人员稳定 ID 排序，同人多角色在对应角色各计一次、各展示一次，同人多项目可在各组出现。全量仅保留任一参与项目有有效提交的人员并按稳定 ID 去重，各角色的全量人数与人员明细也分别按稳定 ID 去重；角色指标之间不可相加。

任务携带各启用项目的启用成员关系、启用稳定人员身份、姓名与角色，以及按稳定 ID 去重的全局并集，随完整版报告版本留档，生成与历史查阅不改用实时名单。任务同时携带各项目各角色的本期首次有效提交判定及对应人员稳定 ID；判定复用同一 Git 采集与身份校验结果，不在 Web 详情按成员加入时间或历史版本补算。

人员稳定 ID 与姓名映射同时供 Web 详情的人员周报查看及 PNG 工作明细附录使用，附录仅保留经提交过滤后进入团队明细的人员。Markdown 原件与 Web 正文中的人员明细仅保留姓名文本，不写入私有链接协议。人员产出周报、日报仍使用配置成员的全局去重并集，不按本报告的域重复生成人员产出；该并集为空或人员真源未取得时拒绝生成人员产出报告，不将此限制套用于已确认空名单的项目进度报告。

成员及 Git 来源完整且确认无配置成员或过滤后无有效提交人员时，各角色人数为 0、人员明细为「无」，人均功能数和对应角色的人均提交行数为「-」。成员关系、稳定人员记录、角色或本项目 Git 来源未取得时，对应人数、人员明细及依赖的人均指标为「未取得」。其它来源完整的项目正常展示，全量源不完整时不以部分项目合计冒充完整总量。

### 汇总与分组

取全部可生成项目范围及人员并集，先按项目、卡片、人员稳定 ID 及源仓稳定 ID 与提交 SHA 去重后汇总，不叠加重复源事实。代码提交与 Qoder 使用按产品、研发、架构角色分别统计；同人多角色时，其提交或用量在对应角色分别完整展示，角色指标不可相加。

Qoder 个人用量在参与的每个项目完整展示，属于人员维度而非仓库分配；全量在各角色内按人员稳定 ID、自然日及来源快照去重，同一用量在同一角色只计一次，禁止累加项目行。

除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余各章节仅用一个表格。前五章按项目 key 字典序列域，harness 文档健康度按仓库名字典序列仓库且不设域列。功能排期、代码提交及 Qoder 使用两张表格的末行均以加粗的「全量汇总」展示，团队人员末行以加粗的「全量汇总(去重)」展示；项目核心进展与 harness 文档健康度不设全量汇总。

明细不直接相加为总数，完成率、延期率与人均指标由去重后的汇总分子、分母重新计算，不对各组百分比、人均值或次均值求和或取平均：

- 全量人均功能数 = 全量功能排期数 ÷ 全量有提交去重研发人数。
- 产品 / 研发 / 架构全量人均提交行数 = 对应角色全量新增与删除行数合计 ÷ 对应角色全量有提交去重人数。
- 产品 / 研发 / 架构 Qoder 人均指标 = 对应角色全量去重 Credits 或请求次数 ÷ 对应角色全量去重活跃成员数。
- 产品 / 研发 / 架构平均单次请求 Credits = 对应角色全量总使用量 ÷ 对应角色全量总请求次数。

历史单组报告保留原归档，不作为新完整版全量报告的替代基线。

## 内容来源与取数口径

### 功能排期事实

采用统计窗口内排期卡、完成时间与排期截止日，并通过卡片操作流水识别窗口内移入非需求改动的卡片。卡片归属与去重遵循本文件的范围真源，具体业务事实引用 [功能排期管理](../../../研发管理/功能排期管理/SKILL.md)。

### Git 权威统计

完整版正文只引用与研发周报同源、已验证的分角色提交次数、新增行数与删除行数，不重新识别作者或自行计数。所有真实作者均保留到独立识别阶段，依据姓名、邮箱与候选成员别名映射，由校验结果确认重复、遗漏及名单外映射，再按稳定人员、项目关系及角色汇总。

统计仅覆盖项目映射的 harness 工程与代码服务仓，按既定主干与功能分支采集，跨分支按提交 SHA 全局去重、剔除合并提交、按窗口过滤，逐提交计算新增与删除行数并排除二进制；各仓小计与角色合计必须打平。每个角色仅保留已验证到当前项目该角色配置成员的贡献；同人多角色时，其贡献在对应角色分别完整展示，角色指标不可相加。名单外或身份未匹配作者不计入分角色指标、不点名，不从 Git 创建人员或自动迁移项目归属。采集与校验执行方式引用 [共用入口 · 执行流程](progress-report.md#执行流程)。

### Qoder 个人用量

先取当前项目配置成员快照，再通过稳定身份映射取得这些成员在统计窗口内的自然日快照，按产品、研发、架构角色分别汇总 Credits 与请求次数。Qoder 采用配置成员口径，不以团队人员章节的窗口提交筛选结果替代配置成员集合。

个人窗口用量在其参与的每个项目及每个已配置角色完整展示，不按仓库分配或推测分摊，角色指标不可相加；全量在各角色内按人员稳定 ID、自然日及来源快照去重，不累加项目行。活跃成员在同一项目、同一角色配置成员集合内沿用 [Qoder 用量分析](../../../研发管理/Qoder用量分析/references/business-rule.md) 的正 Credits 记录口径并按稳定 ID 去重。

已确认空名单时对应角色总量与活跃成员数为 0。成功查询且 Qoder 账号、稳定身份均已确认的成员，在自然日无快照记录时按无用量明确补 0；无账号、身份未匹配、记录非法或来源查询失败时标「未取得」。部分成员未匹配时保留已匹配成员数据，展示已匹配/总人数与未匹配名单，合计明确标为已匹配成员非全量，仅未匹配成员标「未取得」，不冒充完整项目或角色总量，也不清空全部用量。Qoder 失败不改变已取得的团队指标。

### 核心进展来源

读取同统计周期内对应自然周实际入库时间最新的 [研发周报](../../人员产出报告/references/weekly-report.md) 当前版本，每周只选一份，月报合并各周内容并去重，不按当前项目 key 优先挑旧报告。

只提取「AI 分析总结 → 核心进展」中本项目明确内容；名称匹配同时使用来源报告版本快照中相同稳定项目 ID、且仓边界一致的历史名称与 key，不依赖当前改名或硬编码同义词，不复制全局或跨项目同名内容。

成功读取后无同周周报、无核心进展章节或无本项目明确内容为「-」；读取失败、当前版本缺失或项目边界未知为「未取得」并说明原因，不退取旧版本。各组按事实逐点展示，每点正文不超过 50 字，超过时仅在事实边界内拆分，不扩写或省略关键信息。不新增分项目周报配置，不用 Git 或排期卡片推测补写。

### 健康度归档来源

只读引用 [产品文档健康度报告](../../产品文档健康度报告/references/health-report.md) 归档，不重跑评估。本周为统计截止日所在自然周，上周为上一自然周，周报与月报均取这两周。

各周只在可确定的同仓单仓域报告中，采用实际入库时间最新的当前归档综合分 R，不混入跨域或子范围结果，不平均、不退取旧版本。成功读取但无合格归档、评分待定或不可比时，对应得分与差值为「-」；查询失败、已有当前版本缺失、格式破损或仓边界未知时，受影响项为「未取得」并说明原因。

较上期 = 本周综合分 − 上周综合分，保留 1 位小数；正值「↑ +X.X」、负值「↓ -X.X」、零「0.0」分别使用公共成功、危险、中性色，原件、HTML 与 PNG 一致，不改评分公式。操作链接所选本周报告，无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」。仓库按名字典序排列，仍排除 common/design，不将域分数相加。

## 章节规范

固定章节（顺序不可调换）：项目核心进展 / 团队人员 / 功能排期 / 代码提交 / Qoder 使用 / harness文档健康度。正文首部必须以引用块声明统计区间，供归档解析元信息；周期为月时不带括号注释。

每份完整版包含全部启用域及健康度归档仓库；除 Qoder 使用分为「产品与研发」「架构」两个表格外，其余每章仅用一个表格。前五章第一列为「域」，表体按项目 key 字典序展示明细；harness文档健康度第一列为「仓库」，按仓库名字典序排列。功能排期、代码提交及 Qoder 使用两张表格末行均为加粗的「全量汇总」，团队人员末行为加粗的「全量汇总(去重)」；项目核心进展与 harness文档健康度不设汇总，不按组拆成多个表格或单组报告。首列与核心进展、人员明细、操作列左对齐，其余数值列在 Markdown 分隔行右对齐，Web 正文与 PNG 均按此对齐。

1. **项目核心进展**：仅展示 [核心进展来源](#核心进展来源) 所选同周最新当前研发周报中本项目明确内容，沿用相同稳定项目 ID、仓边界一致的历史名称与 key 匹配。各组单元格保留安全无序列表，折行采用悬挂缩进；每点正文不超过 50 字，超过时仅在事实边界内拆分。原件只保留纯排版列表标记，不写脚本、内联事件或私有样式。空缺、异常按来源规则区分，不复制全局进展或推测补写。
2. **团队人员**：标题下固定展示说明「以本周期有提交记录的人员为准」。人数与明细严格遵循 [人员范围与快照](#人员范围与快照)。本期新增人员指其在该项目该角色的首次有效提交落在统计窗口内，且窗口开始前无同项目同角色有效提交，由生成侧复用 Git 采集与身份校验结果判定并随版本快照归档，不按成员加入时间或页面猜测；全量按稳定 ID 去重，任一参与项目符合即保留标记。HTML 姓名旁用公共成功文字样式展示「（新）」，不使用 Tag 边框、底色或额外标签留白；Markdown 与 PNG 以「姓名（新）」表示。标记不改变团队人数、人员周报来源或点击行为。
3. **功能排期**：展示功能排期数、非需求功能数、完成功能数、完成率、延期功能数、延期率、人均功能数。
   - 功能排期数：排期日落在统计窗口内的去重功能卡数，口径与功能排期管理一致，不含非需求改动、待澄清与子卡。
   - 非需求功能数：统计窗口内发生「移入非需求改动」的去重卡片数，按卡片操作流水认定，不计入功能排期数及完成率、延期率、人均功能数的分子或分母。
   - 完成功能数：上述功能排期卡中完成时间落在统计窗口内的卡片数；完成率 = 完成功能数 ÷ 功能排期数 × 100%。
   - 延期功能数：上述功能排期卡中，统计截止时仍未完成且排期截止日不晚于统计截止日的卡片数；延期率 = 延期功能数 ÷ 功能排期数 × 100%。
   - 人均功能数 = 功能排期数 ÷ 项目窗口内有有效提交的去重研发人数。功能排期数为 0 时完成率与延期率无适用分母，显示「-」，功能数仍保留真实零值；研发人数为 0 时人均功能数显示「-」。
4. **代码提交**：按产品、研发、架构分别展示提交次数、提交行数（新增 / 删除）与人均提交行数。各角色提交次数及总行数按项目映射的 harness 工程与代码服务仓统计，仅保留身份匹配该项目该角色配置成员的贡献；同人多角色时其贡献在对应角色分别完整展示，角色指标不可相加，名单外或身份未匹配作者不计入分角色指标。提交行数按新增行数与删除行数分别展示；产品 / 研发 / 架构人均提交行数 = 对应角色（新增行数 + 删除行数）÷ 项目窗口内该角色有有效提交的去重人数，对应角色人数为 0 时显示「-」。
5. **Qoder 使用**：仅统计项目配置成员，按产品、研发、架构分别展示总使用量、人均使用量、总请求次数、人均请求次数与平均单次请求 Credits。章内先以「产品与研发」三级标题展示产品、研发指标表，再以「架构」三级标题展示架构指标表；两张表均按域展示并各设全量汇总，不按域拆表。
   - 各角色总使用量与总请求次数为该角色配置成员窗口合计，同人个人用量完整展示于参与的每个项目及每个已配置角色，不按仓库分配，角色指标不可相加；全量在各角色内按人员稳定 ID、自然日及来源快照去重，禁止对项目行求和。
   - 产品 / 研发 / 架构人均使用量 = 对应角色总使用量 ÷ 该角色 Qoder 活跃成员数；产品 / 研发 / 架构人均请求次数 = 对应角色总请求次数 ÷ 该角色 Qoder 活跃成员数。活跃成员在项目该角色配置成员集合内沿用 Qoder 用量分析的正 Credits 记录口径并去重。
   - 产品 / 研发 / 架构平均单次请求 Credits 沿用 Qoder 用量分析的次均消耗口径，等于对应角色总使用量 ÷ 对应角色总请求次数，保留 1 位小数；总请求次数为 0 时显示「-」。全量按全量总使用量与全量总请求次数重新计算，不对各组次均值求和或取平均。
   - 配置成员已确认空时对应角色总量及活跃成员数为 0；对应角色活跃成员数为 0 时人均指标为「-」。成员来源或用量未取得时按 [Qoder 个人用量](#qoder-个人用量) 标注，部分匹配必须保留已取得数据与覆盖说明。
6. **harness文档健康度**：按仓库展示上周、本周得分、较上期与操作，来源选择及缺失、异常语义沿用 [健康度归档来源](#健康度归档来源)。各周仅取可确定的同仓单仓域报告中实际入库最新的当前综合分 R，保留 1 位小数，不混跨域子范围。较上期 = 本周得分 − 上周得分，方向、精度、缺失标记和公共语义色在原件、HTML 与 PNG 中一致，不改评分公式。「查看报告」仅使用所选本周报告标准详情链接；无归档为「-」、读取异常为「未取得」、无权限为「无查看权限」。本章不设全量汇总，不重跑检查，仍排除 common/design。

比率与人均值保留 1 位小数；Credits 按 Qoder 用量分析口径整数展示；平均单次请求 Credits 保留 1 位小数，总请求次数为 0 时为「-」。成员来源成功且确认空名单时，团队人数、人员明细、Qoder 总量及活跃成员数按上述规则处理，人均指标为「-」。

成功读取后确认无归档内容或指标不适用统一使用 ASCII「-」：同周期上期完整版归档与同冻结范围回看均无可用指标，无同周研发周报、无核心进展章节或无本项目明确内容，无健康度归档、评分待定或不可比，零人数、零请求导致的人均或次均不适用。已取得零计数、零 Credits 仍为 0，不改计量。

取数异常、已有报告当前版本缺失、成员或仓边界未知、Qoder 账号或稳定身份未匹配、格式破损不能可靠读取时，受影响项仍为「未取得」并说明原因，不把失败变成 0 或「-」。其它来源完整的项目正常展示，部分数据注明「已匹配」而非全量，不以部分合计冒充全量；Qoder 失败不改变已取得的团队指标，无权限仍为「无查看权限」。

## 呈现与归档规则

### 数值与正文排版

- 计数（人数、功能数、提交次数、请求次数等）、Credits、提交新增 / 删除行数及人均指标的数值整数部分统一使用千分位；平均单次请求 Credits 与概览较上期增减值同样处理整数部分。保留既有小数精度、正负号、单位与百分号，不再次取整或改动计量；新增 / 删除分别格式化。日期、稳定 ID、文件名、链接及「—」「-」「未取得」等缺失标记不处理，不对全文数字做替换。原件、归档 HTML 与 PNG 格式一致，模板中的 N、X、Y、Z 仅代表按此规则格式化后的值。
- 健康度较上期沿用六章中的差值与精度，原件保留「↑ +X.X」「↓ -X.X」「0.0」以及空缺「-」或异常「未取得」；HTML 与 PNG 使用公共成功 / 危险 / 中性色，不仅靠颜色表达方向，空缺与异常不标涨跌，零不添加箭头或正负号。
- 核心进展单元格仅使用安全无序列表，完整正文每点不超过 50 字并采用悬挂缩进；成功读取后无同周周报、无核心进展章节或无本项目明确内容为「-」，读取异常或边界未知为「未取得」并说明原因。原件允许纯排版列表标记，不包含脚本、内联事件或私有样式。
- 延续正文表格首列固定、表头按词换行、数值右对齐与等宽数字；域 / 仓库、核心进展、人员明细及操作列左对齐。详情阅读区不设大纲，不能为概览新增章节。

### 角色连续列序与双层表头

Markdown 原件保留带角色前缀的平面表头，列序必须完整匹配以下组合，不删减、合并或重算指标：

| 表格 | 首列 | 角色顺序 | 每个角色内的连续指标顺序 |
|------|------|----------|--------------------------|
| 代码提交 | 域 | 产品 → 研发 → 架构 | 提交次数 → 提交行数（新增 / 删除）→ 人均提交行数 |
| Qoder · 产品与研发 | 域 | 产品 → 研发 | 总使用量（Credits）→ 人均使用量（Credits）→ 总请求次数 → 人均请求次数 → 平均单次请求 Credits |
| Qoder · 架构 | 域 | 架构 | 总使用量（Credits）→ 人均使用量（Credits）→ 总请求次数 → 人均请求次数 → 平均单次请求 Credits |

服务端入库时按上述完整列组合生成双层 HTML 表头并随版本持久化：上层为角色，代码提交每个角色跨 3 列，Qoder 每个角色跨 5 列；下层为对应指标，首列「域」跨两层。HTML 与 PNG 消费同一完整双层表头；前端不从原件猜测分组、不修改原件或计量、不隐藏指标。未匹配完整组合的表格保留所有原有列，不猜测或伪造双层分组。

### 本期概览

统计区间引用块后、六个固定章节前，使用加粗文本标题「本期概览」，不是第七章，也不是章节标题。Markdown 原件仅放一个「指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比」表，固定四行并按以下顺序展示：

| 指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比 |
|------|--------|----------|--------------|------------------|
| 功能排期（完成率 / 延期率） | 完成率：同版本全量完成功能完成率<br>延期率：同版本全量功能排期延期率 | 完成：完成功能数 / 功能排期数<br>延期：延期功能数 / 功能排期数 | 完成率：本期完成率 − 上期完成率<br>延期率：本期延期率 − 上期延期率，均使用个百分点 | 完成率：增减值 ÷ 上期完成率绝对值 × 100%<br>延期率：增减值 ÷ 上期延期率绝对值 × 100% |
| 活跃人数 | 产品：同版本全量本周期有有效提交的产品角色去重人数<br>研发：同版本全量本周期有有效提交的研发角色去重人数<br>架构：同版本全量本周期有有效提交的架构角色去重人数 | 本周期有提交记录，按角色分别展示 | 按产品、研发、架构分别计算本、上期对应角色去重人数之差并分行，单位为人，不跨角色求和 | 各角色增减值 ÷ 对应角色上期去重人数绝对值 × 100%，逐角色分行 |
| Qoder 用量 | 同版本全量产品、研发、架构总使用量（Credits），在单元格内按角色分行 | 各角色平均单次请求 Credits | 按产品、研发、架构逐角色计算总 Credits 差值并分行 | 各角色增减值 ÷ 对应角色上期总 Credits 绝对值 × 100%，逐角色分行 |
| 代码提交行数（+ / -） | 同版本全量产品、研发、架构新增 / 删除行数，在单元格内按角色分行 | 新增 / 删除，按角色分别展示 | 按角色分别计算新增行、删除行差值并分行，不互抵 | 各角色新增、删除增减值分别 ÷ 对应上期行数绝对值 × 100%，逐角色分行 |

所有概览归档值仅复用生成时一次性计算的同版本全量去重汇总结果，六章汇总行与概览共用这份结果，不为概览再采集或重新计算。Qoder 与代码提交的各角色独立去重，严禁跨角色求和或累加项目行。完成率与延期率沿用六章分子、分母和零排期规则，不创建新公式；比较列只新增展示与归档对比，不修改现有指标。

#### 上期比较快照与回看纪律

- 「较上期」统一指同报告周期类型的上一自然周期：周报为上一自然周，月报为上一自然月，不是当前报告项的历史版本前一版。只选择同形态完整版的上期全量当前归档结果，不取简化版概览、归档、成员口径或版本号；同批次两个形态的实际版本各自独立，不按相同编号关联。
- 当前完整版版本生成时，以所选上期完整版四行概览归档值为基线形成对比快照并随本版本归档。快照生成后固定，上期后续版本变化不改写既有快照；版本切换只读各自快照，不在详情重新选择上期或重算。
- 上期没有归档概览时，完成率、延期率可引用上期完整版标准功能排期表中唯一、分子分母与比率一致的全量汇总，不拆分旧跨角色合计。其他指标由生成侧复用本次冻结的项目与人员范围，取得上一自然周期的排期和 Qoder 事实，并从已验证历史 Git 中按提交时间筛选同窗口、按角色去重，形成同范围回看基线；不从简化版借用范围或事实解释。
- Qoder 上期回看必须有对应来源账号各自然日的已落库记录，缺行不能当作零值。本期与上期回看的功能排期范围及完成状态均按生成时的卡片状态统计，完成以完成时间是否落在对应窗口内判断；多次生成各以其生成时为准，不按卡片流水回溯期末状态。
- 原件明确区分「归档概览」与「同任务范围回看」来源，比较结果与依据随本版本固定，不改写旧报告。上期无概览时不直接舍弃已有事实；归档与回看均无可用事实时，两个比较项才为「-」。已有归档版本断裂、格式破损或事实读取失败时，受影响项保留「未取得」并说明原因。
- 若本期值因取数失败未取得，比较项也保持「未取得」，不按 0 处理；不从旧六章的跨角色合计、其他期、当前报告前一版本、简化版或前端实时来源补齐。生成侧唯一合格排期汇总与冻结范围回看是上述明确例外，详情不得自行回算。
- 环比逐角色按各期实际取得的汇总直接计算，不校验两期人员名单或匹配集合是否一致；完整覆盖与部分覆盖均可参与，不筛选两期名单交集，也不重算原主值。保留各期覆盖人数、未匹配名单与「非全量」说明，不将部分数据冒充全量。覆盖情况、比较口径和结果随本版本归档。

#### 比较公式与缺失语义

- 增减值 = 本期归档值 − 上期快照基线值；正值为「↑ +X」、负值为「↓ -X」、零值为「—」，非零值保留对应精度、千分位与单位。
- 增减百分比 = 增减值 ÷ 上期快照基线值的绝对值 × 100%，保留 1 位小数；正值为「+X.X%」、负值为「-X.X%」、零值为「0.0%」。上期为 0 且本期非 0 时百分比为「-」，两期均 0 时增减值为「—」、百分比为「0.0%」；缺失不算 0。
- 完成率、延期率的绝对增减单位为「个百分点」，相对变化仍为 %；活跃人数单位为「人」，Qoder 用量单位为「Credits」，代码行单位为「行」。仅归档值所列指标参与比较，补充说明不新增对比。
- 活跃人数卡按产品、研发、架构分别比较对应角色去重人数，不跨角色求和；Qoder 卡逐角色比较总 Credits；代码卡逐角色分别比较新增行与删除行，增减值格式为「新增 ↑ +X 行；删除 ↓ -Y 行」，百分比对应展示新增、删除双值，正负各自保留，不跨角色求和或新增删除互抵。多角色单元格均使用安全排版换行逐角色展示。
- 成功读取后对应角色或列确无归档值时，该主值或辅助项为「-」；取数异常则为「未取得」并说明原因，不影响同卡其他已取得值，辅助项缺失不清空主值。对应角色零人数的人均、零请求的平均单次请求 Credits 为「-」，已取得零计数或零 Credits 仍为 0。
- Qoder 仅部分成员已匹配时，概览保留与正文同一份已匹配用量及次均，注明已匹配/总人数、未匹配名单与「非全量」，不得因覆盖不完整清空已取得数据；整体读取失败时仍为「未取得」。

#### 四卡展示与版本查阅

服务端入库只抽取四行已经计算好的归档值、补充说明与比较结果，并将对比快照随当前完整版报告版本持久化，用四个公共 KPI 卡替代概览表的详情展示，不重复展示同一概览表。功能排期卡内按完成率、延期率分行，活跃人数合为一张卡并按产品、研发、架构分行，Qoder 用量与代码提交行数各为一张卡并按角色分行。

每卡显示「较上期」及与原件相同的增减值和百分比，正值用公共成功色、负值用公共危险色、零值用公共中性色，缺失不标涨跌。详情及 PNG 仅消费对应完整版版本归档结果与各自快照，数据和语义色一致，不查询实时来源重算；元信息、概览、正文整体切换版本，不混用另一形态版本。

历史原件成功读取但无概览、比较列或某项确无归档值时，对应项为「-」；已有当前版本缺失、格式破损不能可靠读取或取数异常仍为「未取得」并说明原因，不得从旧六章、其他版本、简化版或实时来源补齐。生成侧回看纪律不授权详情临时回算。六章、健康度、统计窗口、人员、代码与 Qoder 指标公式及 PNG 正文、工作明细附录规则均保持本完整版口径。

元信息、页头、公共骨架及分页 PNG 导出交互以 [Web UI · 报告详情](web-ui.md#report-detail) 为真源，公共渲染差异见 [报告配置 · Markdown 渲染规则](../../报告配置/references/business-rule.md#6-markdown-渲染规则)；完整版正文与概览的呈现真源为 [本文件 · 呈现与归档规则](#呈现与归档规则)。

### 完整版导出

- 分页 PNG 保留原 1600×2000 分页、完整双层表头、页码与「人员工作明细」附录，全部 PNG 按序打包 `basename_vN_png.zip`，不改为单张图片。
- 「导出为HTML」导出当前版本完整报告和「人员工作明细」附录，使用与分页 PNG 相同的版本及人员快照，不重新计算指标或跨版本补值；文件名为 `basename_vN.html`，内联公共样式，移除脚本、弹窗、版本切换、页面操作按钮及外部资源依赖，可离线打开。
- 人员附录只包含原团队明细的去重成员，沿用人员产出报告查看权限及同周最新归档来源；无权限显示「无查看权限」，无小节为「-」，读取失败为「未取得」。导出期间冻结当前形态、版本及本次读取的附录，禁用形态与版本切换，失败保留原归档且不下载残缺文件。
- 空正文禁止导出，权限与详情查看一致；独立 HTML 不扩展到简化版或其他报告，具体交互见 [Web UI · 报告详情](web-ui.md#report-detail)。

## 硬约束汇总

1. 完整版保留六章、全部指标、四卡概览、双层表头与 PNG 规则；执行、双产物与归档只引用共用入口，不作为独立 skill 运行。
2. 域边界只采用冻结配置中的仓库、卡片与人员事实，跨项目同名实现不混入；前五章按项目 key 排序，健康度按仓库名排序。
3. 分角色提交次数与行数只引用权威校验结果，保持提交去重、合并剔除、窗口过滤、逐提交增删行、二进制排除与小计打平，不自行重新计数。
4. 团队人员以有效配置成员为候选，并按项目窗口有效提交过滤；角色人数与明细分别按稳定 ID 去重，同人多角色分别展示、跨项目全量去重，不从 Git 创建或迁移成员。
5. Qoder 按项目配置成员及角色统计，个人用量完整展示于参与项目，不按仓分摊、不累加项目行、不跨角色求和；部分匹配保留已取得用量与覆盖说明。
6. 核心进展只引用研发周报既有本项目明确内容，按事实逐项展示，每点不超过 50 字，不从其他数据源推测补写。
7. 首次提交「新」标记按项目、角色判定，随版本固定，不按成员加入时间或历史版本猜测。
8. 健康度只读同仓单仓域健康度归档综合分 R，按统计截止周与上一自然周取数；不重跑评估、不叠加多范围，操作只链接所选本周标准详情。
9. 完整版上期只找上一自然周期同类型完整版；归档概览优先，合格排期汇总与同冻结范围回看按完整纪律使用，比较与覆盖说明随版本固定。不能借用简化版概览、归档、成员口径或跨形态版本值。
10. 成功读取且确认空缺或不适用为 ASCII「-」，真实零值为 0；取数失败、版本缺失、边界未知、账号或身份未匹配、格式破损时受影响项为「未取得」并说明原因，部分数据注明「已匹配」与「非全量」，无权限为「无查看权限」。报告不写入凭据、私有协议或实现代码。
