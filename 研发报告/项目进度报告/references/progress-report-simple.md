# 项目进度报告 · 简化版内容规范

> 简化版用于按项目阅读进展，先展示项目总览，再逐项目展开结论、指标、交付与风险，最后展示 harness 文档健康度。与完整版共用一次任务的冻结事实，不作为独立生成入口；触发、统计窗口、采集纪律与双产物归档见 [生成入口](progress-report.md)。

## 1. 人员与事实范围

- 项目范围采用本次任务全部已启用的项目及其 harness 工程、代码服务仓快照，不以代码一级目录划分项目，不混入未配置仓或跨项目同名实现。项目名称采用项目管理中的域名称（项目名称）快照，以稳定项目标识关联，不展示报告 key；项目按名称排序，同名时按稳定项目标识排序，历史不随改名变化。
- 人员按统计窗口内本项目映射仓的有效提交挂靠，不以项目成员配置筛选。有提交但未配置为本项目成员、只配置在其他项目或没有项目关系的人，同样属于本期项目人员；本项目配置成员没有提交则不计入活跃人数，报告不展开人员名单。
- 作者按全部成员档案的姓名、邮箱与别名唯一匹配，匹配成功取稳定人员标识、姓名和角色集合。未匹配或命中多人时保留源作者于核验材料，不猜测归人；报告仅注明身份待核对人数，不展开作者名单。其提交计入项目总量，不计入产品、研发或架构角色指标。
- 已识别人员按稳定人员标识去重；身份待核对作者按已验证作者名与邮箱组合去重，不把空邮箱的不同作者合并，不仅按同名推定一人。证据不足以跨仓识别同人时保留来源作者并注明全量人数的身份边界。
- 报告挂靠只用于本报告统计，不新增、迁移、启用或修改人员档案、项目成员关系，不赋予业务权限。人员产出周报、日报及完整版继续采用各自原有人员范围。
- 卡片归属采用功能排期按源仓与项目映射得到的查询投影，一张卡至多归属一个参与项目；合并卡只有全部子卡同属一个参与项目才归入该项目。

## 2. 项目结论

- 项目结论可以直接从本项目代码仓与 harness 仓库的有效提交说明、变更文件及 harness 变更文档提取归纳，并参考本项目排期卡片和同周最新 current 研发周报中明确属于本项目的内容。代码变更不等于已上线，文档方案不等于已实现；上线、验收与阻塞状态必须有对应事实。
- 周报使用同统计周期每个自然周实际入库最新的 current 版本；月报合并各周并去重。按来源版本快照中相同稳定项目标识且仓边界一致的历史名称匹配，不用硬编码同义词猜归属。
- 同一功能多次提交归为一个进展点，只写已发生事实，不预测、不评价个人、不把全局内容复制到各项目。
- 周报没有归档不阻断项目结论，仍可从本项目提交与卡片归纳。全部来源完整且无本项目事实时为「-」；本项目 Git 来源异常时为「未取得」，注明异常，保留其他已取得事实但不作完整结论。

## 章节规范

正文首部为统计区间引用块，其后是加粗文本「本期概览」，再依次展示项目总览 / 项目进展 / harness文档健康度三章。

### 项目总览

每个项目一行，列为项目、本期结论、功能排期数、完成率、延期功能数、活跃人数、提交次数、提交行数（新增 / 删除）。本期结论为项目结论的一句话概括，不超过 50 字；结论缺失或异常时保留对应标记。活跃人数为本项目有有效提交的去重作者数，包含身份待核对作者；只展示统计，不展开人员名单。

末行为「全量汇总(去重)」，本期结论为「-」。卡片、人员、源仓与提交先去重，比率按全量分子与分母重新计算，不累加项目人数，不求项目比率的平均值。任一项目来源不完整时，受影响全量项标「未取得」，不把部分合计冒充全量。

### 项目进展

每个项目一个三级标题，项目名称与总览一致；项目内依次为四个加粗文本块标题，不展示人员产出明细。

**项目结论**：无序列表，最多 5 点，每点不超过 50 字。按交付成果、文档或方案变更、进行中事项组织，不按人员拼接总结，不出现人员姓名、账号或邮箱。

**关键指标**：一个单行表格，包含以下指标。

| 指标 | 口径 |
|------|------|
| 功能排期数 | 排期日落在统计窗口内的去重功能卡数，不含非需求改动、待澄清与子卡 |
| 非需求功能数 | 窗口内发生「移入非需求改动」的去重卡片数，不进入其他排期指标的分子、分母 |
| 完成功能数 | 上述排期卡中完成时间落在窗口内的卡片数 |
| 完成率 | 完成功能数 ÷ 功能排期数，排期数为 0 时为「-」 |
| 延期功能数 | 上述排期卡中统计截止时未完成、排期截止日不晚于统计截止日的卡片数 |
| 延期率 | 延期功能数 ÷ 功能排期数，排期数为 0 时为「-」 |
| 人均功能数 | 功能排期数 ÷ 本项目有提交且已识别的研发角色人数，人数为 0 时为「-」 |
| 活跃人数（产品 / 研发 / 架构） | 按已识别人员角色集合分别去重，同人多角色分别计入，不跨角色求和；另有身份待核对作者时注明人数 |
| 提交次数 | 本项目全部有效提交，包含身份待核对作者 |
| 提交行数（新增 / 删除） | 同范围分别合计新增行、删除行，不互抵 |

**本期交付**：列序固定为功能、状态、开发人、排期截止日、完成时间，开发人位于状态后面。范围与功能排期数一致；按延期、进行中、已完成排序，同状态按排期截止日升序。完成时间落在本期为「已完成」，符合延期条件为「延期」，其余为「进行中」，仅作为本报告展示状态，不改业务状态。开发人取卡片开发人，未领取时取负责人，均无为「-」；未完成时间为「-」。无排期卡时显示「本期无功能排期」。

**风险与阻塞**：无序列表，每点不超过 50 字，只来自本项目延期卡片或研发周报中明确属于本项目的风险。没有阻塞原因的延期卡只陈述延期，不猜测接口、资源或协作原因；不出现人员姓名、账号或邮箱。无可列事项为「-」。

### harness文档健康度

作为末章，按仓库名称展示上周健康度得分、本周健康度得分、较上期、查看报告。两形态引用同一仓库健康度快照，不重跑评估，不设全量汇总，仍排除 common/design。

本周取统计截止日所在自然周，上周取其上一自然周；只用可确定同仓单仓域报告中实际入库最新的 current 综合分，周报与月报均取这两周。无归档、评分待定或不可比为「-」，读取异常、版本断裂或仓边界未知为「未取得」并说明原因。综合分及差值保留 1 位小数，差值正、负、零分别为「↑ +X.X」「↓ -X.X」「0.0」。

## 呈现与归档规则

- 简化版标题为「项目进度报告（简化版）- {发报日}」，原件文件名为 `progress_yyyyMMdd__all_simple.md`。
- 简化版不展示人员名单、个人产出或个人 Qoder 明细。概览保留按角色去重的周期用量，不按项目分摊；只合计已取得用量并注明覆盖人数，整体未取得为「-」，已确认无用量为 0。
- 其他指标取数异常保留「未取得」与原因；完整读取确认没有内容、不适用为 ASCII「-」，已取得零值为 0。部分来源保留已取得明细并注明非全量，不据此冒充完整总量。
- 计数、Credits、增删行及人均值统一千分位，百分比和人均保留 1 位小数。日期、稳定标识、文件名、链接及缺失标记不格式化。正文文本、首列左对齐，数值右对齐。
- 项目结论与风险为正文无序列表并悬挂缩进；不包含脚本、内联事件或私有样式。页面不设大纲。
- 导出当前查看的完整简化版为一张 PNG，固定宽度 1600 像素、高度随内容。超出单张图片上限时整体等比例降低像素密度，不分页、不截断、不打包 ZIP，不追加个人周报附录；文件名为原件去扩展名后的 `basename_vN.png`。导出期间禁止形态与版本切换。

## 本期概览

原件为「指标 | 归档值 | 补充说明 | 较上期增减值 | 较上期增减百分比」五列表，页面转换成四张公共 KPI 卡，不能重复展示。

| 指标 | 归档值 | 补充说明 |
|------|--------|----------|
| 功能排期（完成率 / 延期率） | 本形态全量完成率与延期率 | 对应完成数 / 排期数、延期数 / 排期数 |
| 活跃人数 | 产品、研发、架构的有提交且已识别人员去重人数 | 提交挂靠口径；注明身份待核对人数 |
| Qoder 用量 | 产品、研发、架构已取得的个人用量各自去重合计 | 每角色已匹配 / 总人数；部分覆盖标「非全量」 |
| 代码提交行数（+ / -） | 已识别人员按产品、研发、架构各自统计新增 / 删除行 | 身份待核对行数不计入角色值 |

角色指标不跨角色求和、不累加项目行。每个形态在生成时一次性计算并归档，概览与正文复用同一结果。上期仅为上一自然周或月的简化版，不能从完整版借值、转换成员口径或用当前历史版本代替；首次没有简化版上期时，可以用本次冻结范围的已验证历史事实回看，确无事实为「-」，查询异常为「未取得」。

增减值为本期减上期，正值「↑ +X」、负值「↓ -X」、零「—」；增减百分比为增减值除以上期绝对值，保留 1 位小数。上期 0、本期非 0 时百分比为「-」，两期 0 时为「0.0%」，缺失不算 0。完成率与延期率的差值单位为个百分点，人数为人、用量为 Credits、增删为行；角色与新增 / 删除分别比较，不互抵。比较基线、覆盖说明与结果随本版本固定，页面不回查上期或重算。
