# 项目进度报告

面向管理层、PM 与项目负责人的**项目维度**周期性进度报告：每个项目独立生成一份周期报告，汇总该项目「计划了什么、完成了什么、延期了什么」，替代人工汇总与全量混排的大周报。

## 服务对象与端

- **服务对象**：管理层、PM、项目负责人
- **Web 管理端**：报告索引、在线阅读、手动补传与版本回溯
- **App 查阅端**：按项目分组浏览与阅读

## 分项目生成（核心）

- 报告按「项目 × 周期（周/月）」生成，一项目一份；项目集合由「报告项目配置」生效数据驱动，不写死
- 项目边界即统计边界：报告只统计该项目映射仓库内的提交与卡片事实，跨项目搜到的同名实现不混入

## 项目配置（外部真源）

- **基础映射**（项目 ↔ harness 工程 / 代码仓清单）：唯一真源为 [`排期管理/功能排期`](../../排期管理/功能排期/SKILL.md) 的项目配置，本模块只读消费
- **报告侧扩展**（项目 key、分支策略、扩展启停）：真源为 [`报告配置`](../报告配置/SKILL.md) 模块「报告项目配置」页生效数据
- 新增项目 = 功能排期启用项目 + 报告配置完成扩展并启用，同步自动纳入触发配置（下一生成周期生效）；本模块不承载任何配置页面

## 生成方式：触发配置 + 服务端生成

1. 触发方式在 [`报告配置`](../报告配置/SKILL.md) 模块「报告触发配置」页维护：每个启用项目一条配置行（随报告项目扩展联动生成），支持定时规则（每周 / 每月）与手动「立即生成」；统计窗口按周期口径计算后随任务下发
2. 触发后服务端通过 **Qoder SDK** 创建生成会话，按项目逐一生成：会话入参携带该项目映射（harness 工程 + 代码仓清单，取自功能排期项目配置）与扩展（项目 key + 分支策略 + 统计窗口），映射与扩展均取自 Web 端生效配置；生成逻辑真源为本模块内置的生成 skill（[`references/progress-report.md`](references/progress-report.md)，随本仓库版本化），按其「读配置 → 同步仓库 → 采集数据 → 按章节规范生成 → 写文件」执行
3. 产出报告由服务端直接落库归档（渲染、版本递增、周索引），不经过推送；外部生成会话产出可经推送上报旁路入库（兜底见手动补传）
4. 仓库操作只允许落在生成会话的约定工作区内，严禁使用本机其它位置的同名开发者副本
5. 生成任务全程留痕（触发来源 / 状态 / 耗时 / 失败原因），失败可在生成记录中重试

## 报告内容（口径）

- **进度总览**：区间内排期卡片完成率（完成 / 在制 / 待开发 / 延期分布），按功能分组
- **需求吞吐**：提交 → 审批通过 → 已排期 → 已完成各环节数量与端到端周期
- **实施进度**：实施卡完成率与待实施积压
- **延期清单**：逾期未完成的卡片明细（负责人、排期日、延期天数）
- **发版回顾**：区间内的发版日与发布内容摘要（联动发布管理）

## 归档与查阅

- **项目 × 自然周（周一为起点）双维索引**；同项目同周期重复入库走版本递增而非覆盖，历史版本可溯
- 报告为静态产物：归档后只做渲染呈现（Markdown → HTML + 大纲锚点导航），不重新计算指标；指标口径问题回溯生成侧
- 归档、触发与生成规则真源见 [`../报告配置/references/business-rule.md`](../报告配置/references/business-rule.md)，数据模型见 [`../报告配置/references/data.md`](../报告配置/references/data.md)

## 关键约束

- 数据源唯一：报告指标全部由排期管理子域的卡片事实与映射代码仓的 git 事实计算，不接受手工填报
- 映射真源唯一：基础映射以功能排期项目配置为准，报告侧扩展以报告配置模块生效数据为准，生成与归档两侧均不读取仓库内或本机配置文件
- 原始报告文件单文件直接获取，不接入批量异步导出中心；报告落库即页面可查，本子域不做主动通知
- 项目停用只影响此后的生成，不删除历史报告
