# 项目进度报告

面向管理层与 PM 的周期性进度报告：以功能排期、实施管理、需求管理的卡片与流转事实为数据源，按自然周/月汇总「计划了什么、完成了什么、延期了什么」，替代人工汇总周报。

## 服务对象与端

- **服务对象**：管理层、PM（编制与查阅）
- **Web 管理端**：报告索引、在线阅读、手动补传与版本回溯
- **App 查阅端**：按周期分组浏览与阅读，面向移动查阅

## 报告内容（口径）

- **进度总览**：统计区间内排期卡片的完成率（完成 / 在制 / 待开发 / 延期分布），按项目（功能/模块）分组
- **需求吞吐**：提交 → 审批通过 → 已排期 → 已完成各环节数量与端到端平均周期
- **实施进度**：实施卡完成率与待实施积压
- **延期清单**：逾期未完成的卡片明细（负责人、排期日、延期天数）
- **发版回顾**：区间内的发版日与发布内容摘要（联动发布管理）

## 核心规则

- **数据源唯一**：报告指标全部由排期管理子域的卡片事实计算，不接受手工填报数字；指标口径变更只改生成侧，已归档报告不重算
- **周期归属**：按发报日所在自然周（周一为起点）建索引，与报告内部统计区间是两个字段
- **入库与版本**：自动生成为主、缺失周期支持手动补传；同类型同周期重复入库走**版本递增**而非覆盖，历史版本可追溯
- **静态产物**：归档后只做渲染呈现（Markdown → HTML + 大纲锚点导航），不重算报告内任何指标

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 端 | 页面 | 职责 |
| -- | ---- | ---- |
| Web | 报告列表 | 按周索引（每周齐全度与缺失快捷补传）+ 报告明细双视角；类型/日期/关键词筛选；入库进度 KPI |
| Web | 报告详情 | 元信息头（类型/发报日/统计区间/版本）+ 渲染正文 + 大纲锚点导航；版本切换回溯 |
| App | 列表 / 详情 | 按周分组浏览、渲染阅读；不提供补传与版本管理 |

## 关键约束

- 报告为生成侧产出的静态产物，归档模块不关联业务数据源重新计算；口径问题回溯生成侧
- 原始报告文件单文件直接获取，不接入批量异步导出中心
- 报告发布告知由生成侧既有机制承担，本模块不做消息通知

## 关联模块

| 模块 | 关系 |
| ---- | ---- |
| `排期管理/功能排期` / `排期管理/实施管理` / `排期管理/需求管理` | 进度与吞吐指标的事实数据源 |

| `研发报告/人员产出报告` / `研发报告/文档一致性报告` | 同属报告家族，共享归档查阅机制 |
