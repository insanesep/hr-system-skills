# 故障报告 · 业务规则

> 本文件是故障报告模块业务规则的唯一真源；SKILL.md 仅做导航，不复述规则细节。

## 1. 名词约定

| 名词 | 定义 |
| ---- | ---- |
| 故障 | 已影响或险些影响生产业务的异常事件，需复盘闭环 |
| 复盘 | 对故障时间线、根因、处置过程的结构化回顾 |
| 改进措施 | 复盘产出的可执行改进项，逐项跟踪至完成 |
| 闭环 | 全部改进措施完成且研发负责人确认，故障关闭 |

## 2. 业务流程

1. **登记**：故障发生后在 Web 端登记（标题、现象、影响范围、定级、发生/发现时间、负责人），处理过程中可随时补充修订
2. **处理**：记录处置过程，关联运维证据（错误日志指纹报表项、服务器监控快照、黑灯工厂工单），证据只读引用、不复制内容
3. **复盘**：故障处置完成后进入待复盘；填写时间线（发生 → 发现 → 处置 → 恢复）、根因分析、改进措施清单（每条含负责人与完成期限）
4. **闭环**：改进措施逐项标记完成；全部完成且研发负责人确认后闭环，闭环后故障单只读

## 3. 定级

| 定级 | 语义 |
| ---- | ---- |
| P1 | 重大：核心链路不可用或资损 |
| P2 | 严重：主要功能受损 |
| P3 | 一般：局部影响 |
| P4 | 轻微：无实质影响但需复盘 |

## 4. 状态机

`处理中 → 待复盘 → 复盘中 → 已闭环`

- 处理中「标记已恢复」（记录恢复时间）→ 待复盘
- 待复盘「提交复盘」（校验时间线 / 根因 / 改进措施齐备）→ 复盘中
- 复盘中研发负责人可「打回」（填写打回原因）→ 待复盘；全部改进措施完成后「闭环确认」（二次确认）→ 已闭环
- 已闭环：故障单只读，无操作

## 5. 时限与高亮

1. P1 / P2 故障恢复后 **3 个工作日内**必须完成复盘，超期在列表与详情高亮「逾期未复盘」
2. 改进措施逾期未完成，在故障列表与详情同时高亮

## 6. 约束

1. 故障单**不允许删除**（审计留痕）；登记错误以更正信息方式修订
2. 证据关联只读：引用的错误日志 / 监控快照 / 工单状态变更不回写故障单，仅以链接跳转溯源

## 7. 权限

| 粒度 | 编码 |
| ---- | ---- |
| 菜单 | `devhubFaultReport` |
| 登记、编辑、追加处置记录、添加与移除证据 | `devhubFaultEdit` |
| 复盘提交与打回 | `devhubFaultReview` |
| 闭环确认 | `devhubFaultClose` |

## 8. 关联模块分工

| 模块 | 关系 |
| ---- | ---- |
| 运维管理 / 错误日志管理 | 故障证据来源（指纹报表项引用） |
| 运维管理 / 服务器监控 | 故障证据来源（异常快照引用） |
| 运维管理 / 黑灯工厂管理 | 故障证据来源（工单引用）；黑灯工单 = agent 巡检产出的自动化修复闭环，故障报告 = 影响业务的故障事件的人工复盘闭环；同一事件两边互相引用、不重复展开 |
