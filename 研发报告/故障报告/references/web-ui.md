  - **分页**：本页为研发报告菜单中唯一服务端分页的列表，默认 20 条/页，页大小档位取分页组件默认集

### 故障登记 / 编辑弹窗

- **打开方式**：故障列表工具栏「+ 故障登记」/ 行内「编辑」/ 故障详情页头「编辑」（详情页进入为**简版模式**：隐藏定级 / 发生时间 / 发现时间三项，原值随提交回传不丢）
- **权限编码**：`devhubFaultEdit`
- **弹窗类型**：表单弹窗（登记态标题「故障登记」、确认钮「确认登记」；编辑态标题「编辑故障」、确认钮「保存」，预填全部字段）
- **表单字段**：
  - 标题（必填，单行，≤50 字）
  - 现象描述（必填，多行；placeholder「故障表现、报错信息、受影响的功能链路」）
  - 影响范围（多行，可空；placeholder「受影响的业务 / 门店 / 用户范围（可空）」）
  - 定级（单选 P1 / P2 / P3 / P4，默认 P3；选项附带定级口径：P1 重大-核心链路不可用或资损 / P2 严重-主要功能受损 / P3 一般-局部影响 / P4 轻微-无实质影响但需复盘）
  - 发生时间（必填，DateTimePicker，不可晚于当前时间）
  - 发现时间（DateTimePicker，可空，不早于发生时间）
  - 负责人（人员选择，可空，远程搜索）
  - 关联范围（可空；类型=域/项目 + 稳定实体引用，选项只读来自 [项目管理](../../../研发管理/项目管理/SKILL.md) 的启用有效清单，不在本页增删基础实体或维护执行映射；停用/远端确认缺失的历史引用保留只读）
- **底部固定提示**：「故障单不允许删除（审计留痕）；登记错误请以更正信息方式修订。」已闭环故障单只读，编辑入口隐藏

#### 表单校验

- 初态：登记态定级默认 P3，其余字段为空；编辑态预填全部字段，无只读字段

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 标题 | 是 | 1-50 字符 | blur / 提交 | 请输入故障标题（不超过 50 字） | 否 |
| 现象描述 | 是 | 非空 | blur / 提交 | 请填写现象描述 | 否 |
| 定级 | 是 | 单选 P1 / P2 / P3 / P4 | change | 请选择定级 | 否 |
| 发生时间 | 是 | 不晚于当前时间 | change / 提交 | 发生时间不可晚于当前时间 | 否 |
| 发现时间 | 否 | 不早于发生时间 | change / 提交 | 发现时间不可早于发生时间 | 否 |

- 提交成功：toast 成功文案 → 关闭弹窗并刷新来源列表 / 信息头（原地刷新，无跳转）
- 提交失败展示：toast error，弹窗保留、已填内容不丢
- 脏数据离开：表单有未保存变更时关闭弹窗，AcModal 确认「有未保存的修改，确认放弃？」

### 故障详情

- **页面路径**：`/subapp/devhub/report/fault/detail/:id`
- **路由名称**：`devhubFaultDetail`，为故障报告的非菜单详情页
- **权限编码**：
  - 所属菜单资源：`devhubFaultReport`，不等同于详情路由名称
  - 按钮：`devhubFaultEdit`（编辑 / 追加处置记录 / 添加与移除证据 / 标记已恢复）、`devhubFaultReview`（提交复盘 / 打回 / 添加改进措施）、`devhubFaultClose`（闭环确认）
- **页面类型**：`order-detail`（操作型）
- **区块职责**（自上而下）：
  - 页头：「‹ 返回故障列表」链接；故障标题 + 定级 Tag + 状态 Tag；右侧「编辑」（非闭环且持 `devhubFaultEdit`，开简版编辑弹窗）
  - 生命周期步骤条：登记（时间 · 登记人）→ 处理与恢复（「进行中 · 已记录 N 条处置」/「已恢复 {时间}」）→ 复盘（「待提交复盘（· 已逾期）」/「已提交 {时间} · 待研发负责人确认」）→ 闭环（「待全部措施完成」/「已闭环确认」）
  - 逾期警示（待复盘且 P1 / P2 恢复超 3 个工作日未复盘，红色警示条）：「⚠ 该 {级别} 故障恢复已超 3 个工作日仍未完成复盘，已逾期，请尽快提交复盘」
  - 故障信息区（panel）：右上留痕「登记人 {姓名} · 登记时间 {时间}（留痕不可改）」；字段：负责人、关联项目、发生时间、发现时间、恢复时间（未恢复显示 —）、定级口径（如「P1 重大：核心链路不可用或资损」）、现象描述（整行，保留换行）、影响范围（整行）
  - 处置过程记录区（panel）：处置时间线条目按时间倒序（`[MM-DD HH:mm] 内容`）；空态「暂无处置记录」；未闭环可追加记录（多行输入，placeholder「记录处置动作、结论或协同信息」+「提交记录」，持 `devhubFaultEdit`）
  - 运维证据关联区（panel）：元说明「证据只读引用，不复制内容、不回写状态」；列：证据类型（错误日志指纹报表项 红 / 服务器监控快照 橙 / 黑灯工厂工单 紫）、证据标识、备注、操作（「移除」）；未闭环支持「添加关联」（持 `devhubFaultEdit`；弹窗字段：证据类型必选 + 证据标识必填（placeholder「粘贴证据标识 / 链接，如 FP-a3f9c8d1」）+ 备注可空；重复标识拦截「该证据已关联，请勿重复添加」）；🚨 证据卡不提供「跳转溯源」链接
  - 复盘区（panel）：元信息显示「改进措施完成度 X/Y」；按状态分态——
    - 处理中：空态「故障恢复并完成处置后进入复盘（发生 → 发现 → 处置 → 恢复）」
    - 待复盘 / 复盘中：曾被打回时黄色警示条「⚠ {时间} {操作人} 打回：{原因}」；复盘时间线固定四段（发生 / 发现 / 处置 / 恢复，各需时间 + 说明，初态带入故障单已有时间，可修订）；根因分析（必填，多行）；处置回顾（可空，多行）；有上一版复盘（复盘中 / 被打回）时回显上一版；**复盘中表单整体只读**
    - 改进措施 checklist：列：完成（勾选框）/ 内容 / 负责人 / 期限 / 完成时间；期限已过未完成的红显并带「已逾期」Tag；待复盘时底部提供添加行（改进项描述 + 负责人远程搜索 + 完成期限 +「添加措施」，持 `devhubFaultReview`，不齐提示「改进措施需内容 / 负责人 / 期限齐备」）；勾选完成原地更新不刷新整页
    - 已闭环：全只读（提交人 / 提交时间、时间线、根因、处置回顾、「改进措施（X/Y 已完成）」）
  - 沉底操作栏（按状态机流转，详见 [business-rule.md §4](business-rule.md#4-状态机)；左侧逐状态提示当前可执行操作说明）：
    - 处理中 → 「标记已恢复」（持 `devhubFaultEdit`）
    - 待复盘 → 「提交复盘」（持 `devhubFaultReview`）
    - 复盘中 → 研发负责人可「打回」（持 `devhubFaultReview`）+「闭环确认」（持 `devhubFaultClose`；存在未完成改进措施时禁用，悬浮提示「存在未完成改进措施，不可闭环」）
    - 已闭环 → 只读，无操作
- **布局引用**：`参见原型 assets/web/fault-detail.html`（DOM 结构依据：`busyming-skills-design/.skills/page-blueprint/skeletons/web/detail-page.vue.tpl`）

#### 表单校验（复盘区表单）

- 初态：时间线四段默认带入登记与处置记录中的发生 / 发现 / 恢复时间，可修订；根因分析、处置回顾为空；改进措施逐条添加；有上一版复盘（复盘中 / 被打回）时回显上一版；复盘中表单整体只读
- 逐字段校验：提交复盘时集中校验；时间线四段（时间 + 说明）、根因分析、改进措施（至少 1 条，每条内容 + 负责人 + 期限齐备）任一缺失 → toast error 逐段提示（如「请补齐「发生」时间与说明」），汇总「复盘内容未齐备：请完善时间线 / 根因 / 改进措施」并定位首个缺失项
- 提交成功去向：toast「复盘已提交，等待研发负责人确认」→ 停留本页，状态 → 复盘中
- 提交失败展示：toast error + 定位缺失项，已填内容保留
- 脏数据离开：待复盘态复盘表单有未提交内容时离开页面，路由拦截确认「复盘内容未提交，确认离开？」
