# 故障报告

面向研发、运维与管理层的故障全生命周期管理：**登记 → 处理 → 复盘 → 闭环**，关联运维证据沉淀复盘资产，替代群消息散落与口头复盘。

> 归属：研发报告。与「运维管理/黑灯工厂管理」分工：黑灯工单 = agent 巡检产出的自动化修复闭环；故障报告 = 影响业务的故障事件的**人工复盘闭环**，可关联黑灯工单作为证据，同一事件两边互相引用、不重复展开。

## 服务对象与端

仅 **Web 端**（管理后台）。App 端不做。

| 端 | 范围 | 目标用户 |
|---|------|---------|
| Web | 研发报告 → 故障报告：列表页 + 登记/编辑弹窗 + 详情页 | 研发、运维、研发负责人、管理层 |

## 名词约定

| 名词 | 定义 |
| ---- | ---- |
| 故障 | 已影响或险些影响生产业务的异常事件，需复盘闭环 |
| 复盘 | 对故障时间线、根因、处置过程的结构化回顾 |
| 改进措施 | 复盘产出的可执行改进项，逐项跟踪至完成 |
| 闭环 | 全部改进措施完成且研发负责人确认，故障关闭 |

## 业务流程

1. **登记**：故障发生后在 Web 端登记（标题、现象、影响范围、定级、发生/发现时间、负责人），处理过程中可随时补充修订
2. **处理**：记录处置过程，关联运维证据（错误日志指纹报表项、服务器监控快照、黑灯工厂工单），证据只读引用、不复制内容
3. **复盘**：故障处置完成后进入待复盘；填写时间线（发生 → 发现 → 处置 → 恢复）、根因分析、改进措施清单（每条含负责人与完成期限）
4. **闭环**：改进措施逐项标记完成；全部完成且研发负责人确认后闭环，闭环后故障单只读

## 业务规则

1. **定级**：P1 重大（核心链路不可用或资损）、P2 严重（主要功能受损）、P3 一般（局部影响）、P4 轻微（无实质影响但需复盘）
2. **复盘时限**：P1 / P2 故障恢复后 3 个工作日内必须完成复盘，超期在列表与详情高亮
3. **状态机**：`处理中 → 待复盘 → 复盘中 → 已闭环`；复盘可被研发负责人打回（复盘中 → 待复盘）
4. 故障单**不允许删除**（审计留痕）；登记错误以更正信息方式修订
5. 改进措施逾期未完成，在故障列表与详情同时高亮
6. 证据关联只读：引用的错误日志 / 监控快照 / 工单状态变更不回写故障单，仅以链接跳转溯源

## 数据模型（产品语义）

| 实体 | 关键字段 | 关系 |
| ---- | -------- | ---- |
| 故障单 | 标题、现象、影响范围、定级、发生/发现/恢复时间、负责人、状态 | 主实体 |
| 运维证据关联 | 证据类型（错误日志 / 监控快照 / 黑灯工单）、证据标识、备注 | 故障单 1 ── N |
| 复盘记录 | 时间线、根因、处置回顾、提交人、提交时间、打回记录 | 故障单 1 ── N（打回后重提递增） |
| 改进措施 | 内容、负责人、期限、状态、完成时间 | 复盘记录 1 ── N |

## 页面功能概览（仅列职责）

| 页面 | 职责 |
| ---- | ---- |
| 故障列表 | KPI 卡（处理中 / 待复盘 / 逾期未复盘 / 本月新增）+ 筛选（状态 / 定级 / 日期 / 负责人 / 关键词）+ 故障表格 + 登记入口 |
| 故障登记 / 编辑弹窗 | 标题、现象、影响范围、定级、发生 / 发现时间、负责人 |
| 故障详情 | 基本信息 + 处置过程记录 + 运维证据关联区（跳转溯源）+ 复盘区（时间线 / 根因 / 改进措施 checklist）+ 状态操作（提交复盘 / 打回 / 闭环确认） |

页面区块与交互清单见 [`references/web-ui.md`](references/web-ui.md)，原型见 `assets/`。

权限：菜单 `MENU:RND:FAULT_REPORT`；登记 / 编辑 `BTN:RND:FAULT:EDIT`、复盘提交与打回 `BTN:RND:FAULT:REVIEW`、闭环确认 `BTN:RND:FAULT:CLOSE`。
