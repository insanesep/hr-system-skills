# 人员产出报告

面向管理层的周期性人员产出报告：以 git 提交事实与排期卡片流转事实为数据源，按自然周/月呈现「谁交付了什么、时效如何」，替代凭印象的绩效复盘。

## 服务对象与端

- **服务对象**：管理层、研发负责人（仅授权可见，不做全员公示）
- **Web 管理端**：报告索引、在线阅读、版本回溯
- **App 查阅端**：按周期分组浏览

## 报告内容（口径）

- **产出量**：统计区间内 commit 数、完成的功能卡数、完成的实施卡数（区分提交人与开发人/领取人口径）
- **时效**：卡片领取 → 完成的平均时长；需求关联卡的端到端周期
- **质量与纪律**：延期卡数与延期率、回退次数（DONE 被回退）
- **人员 × 维度透视**：人员 × 项目（模块）、人员 × 周的产出矩阵

## 核心规则

- **数据客观唯一**：全部指标由 git 事实与排期卡片流水计算，不引入主观评分；本模块不做「排名」「红黑榜」类产品形态
- **可见性收口**：人员维度数据敏感，仅管理层与研发负责人角色可见；不向被统计人推送
- **周期、入库、版本与静态产物规则**：与 `研发报告/项目进度报告` 同一家族口径（自然周索引、自动生成 + 手动补传、版本递增、归档不重算）

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 端 | 页面 | 职责 |
| -- | ---- | ---- |
| Web | 报告列表 | 按周索引 + 明细筛选 + 入库 KPI |
| Web | 报告详情 | 渲染正文 + 大纲导航 + 版本回溯 |
| App | 列表 / 详情 | 分组浏览与阅读 |

## 关键约束

- 人员口径必须同时支持「提交人」与「实际开发人/领取人」双视角，避免「代提交」场景产出错记
- 统计不含 NON_FEATURE / NON_IMPL 旁路态卡片（非需求改动不计入产出）
- 指标定义需在报告内附口径说明，防止跨周期比较时口径漂移

## 关联模块

| 模块 | 关系 |
| ---- | ---- |
| `排期管理/功能排期` / `排期管理/实施管理` | 卡片领取/完成/回退事实来源 |
| `研发报告/项目进度报告` | 同家族归档查阅机制与生成任务体系 |
