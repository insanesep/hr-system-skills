# 人员产出报告

面向管理层的人员维度周期性产出报告：以 git 提交事实与排期卡片流转事实为数据源，按统计周期呈现「谁交付了什么、时效如何」，替代凭印象的绩效复盘。

## 服务对象与端

- **服务对象**：管理层、研发负责人（仅授权可见，不做全员公示）
- **Web 管理端**：触发配置、报告索引、在线阅读、版本回溯
- **App 查阅端**：按周期分组浏览与阅读

## 生成方式：触发配置 + 服务端生成

报告的生成**不在本模块内重建逻辑**，而是由服务端生成会话挂载本模块内置的生成 skill 完成：

1. 触发方式在 Web 端「报告触发配置」页维护（研发周报一条配置行：定时规则 + 手动「立即生成」）；触发后服务端创建生成任务并全程留痕
2. 服务端通过 **Qoder SDK** 创建生成会话，工作区挂载 [`references/`](references/) 内的周报生成 skill（入口 [`references/dev-report.md`](references/dev-report.md)，随本仓库版本化，为生成逻辑唯一真源），统计窗口与生成配置由服务端注入会话入参
3. 会话按 skill 约定执行：读配置 → 同步代码仓 → 采集数据（git 提交权威计数 + 排期卡片与用量等数据源）→ 按章节规范生成报告（「按人员综合分析」为核心章节）→ 写报告文件
4. 产出报告由服务端直接落库归档（渲染、版本递增、周索引），不经过推送；外部生成会话产出可经推送上报旁路入库（兜底见手动补传）
5. 统计窗口、计数纪律、数据源清单与推送契约均以 skill 内规范为准，本文件不复述

## 报告内容（口径）

- **产出量**：统计区间内 commit 数、完成的功能卡数、完成的实施卡数（区分提交人与开发人/领取人双口径，避免「代提交」场景产出错记）
- **时效**：卡片领取 → 完成的平均时长；需求关联卡的端到端周期
- **质量与纪律**：延期卡数与延期率、完成回退次数
- **人员透视**：人员 × 项目（模块）、人员 × 周期的产出矩阵

## 核心规则

- **数据客观唯一**：全部指标由 git 事实与排期卡片流水计算，不引入主观评分；不做「排名」「红黑榜」类产品形态
- **可见性收口**：人员维度数据敏感，仅管理层与研发负责人角色可见；不向被统计人推送
- **归档与版本**：按报告发报日所在自然周（周一为起点）建索引；同类型同周期重复入库走版本递增而非覆盖，历史版本可追溯；报告为静态产物，归档后不重新计算指标
- **旁路态不计入**：统计不含 NON_FEATURE / NON_IMPL 旁路态卡片
- 指标定义在报告内附口径说明，防止跨周期比较时口径漂移

## 页面功能概览（仅列职责）

| 端 | 页面 | 职责 |
| -- | ---- | ---- |
| Web | 报告列表（本模块，见 [`references/web-ui.md`](references/web-ui.md)，原型见 `assets/`） | 按周索引 + 明细筛选 + 入库进度；缺失周次立即生成 / 补传 |
| Web | 报告详情（本模块） | 元信息 + 渲染正文 + 大纲锚点导航 + 版本切换回溯 |
| Web | 报告触发配置（子域统一页，见 [`../references/web-ui-trigger-config.md`](../references/web-ui-trigger-config.md)） | 研发周报配置行的触发方式、定时规则与启停；立即生成；生成记录与失败重试 |
| App | 列表 / 详情（本模块，见 [`references/mobile-ui.md`](references/mobile-ui.md)） | 按周分组浏览、渲染阅读 |
