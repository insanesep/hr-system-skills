# daily-report / 研发日报生成

> 一句话定位：采集当日 Git 提交 + 功能排期卡片流转事实，由模型直接生成研发日报，写入报告文件。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。无企微推送。

## When to Use

- 用户说「生成日报 / 跑研发日报」
- 当日复盘截至当前的研发产出（例会前、下班前快照）
- 用户说「推送日报到后台」（外部会话旁路）

## When Not to Use

- 需要定时自动跑 → 由报告配置模块「报告触发配置」页承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报 / 一致性检查 / 项目进度报告 → 分别由 [`dev-report.md`](dev-report.md)、文档一致性报告、项目进度报告模块的生成 skill 承载

## 与周报 skill 的关系

执行流程与纪律全部同 [`dev-report.md`](dev-report.md)，本文件不复述：读配置定工作区（Step 1）、工作区硬约束、仓库同步（Step 2）、Git 提交计数纪律与数据容错（Step 3）、写文件与落库 / 推送（Step 5）。本文件只声明日报的差异口径：统计窗口、数据源裁剪、输出章节与文件命名。

## 统计窗口

当日 00:00 ~ 生成时（当日实时，东八区），生成时截断。与周报「不含当天」口径相反：日报就是为当日快照而生，窗口不完整属预期，须在报告正文首部声明统计区间（`统计区间：YYYY-MM-DD ~ YYYY-MM-DD（当日实时，生成时截断于 HH:mm）`，起止同日保证可解析入库）。

## 数据源裁剪

| 数据源 | 日报是否采集 | 说明 |
|--------|-------------|------|
| Git 提交记录 | 是 | 计数纪律同 dev-report（全分支、SHA 去重、剔 merge、窗口过滤、小计与总计打平） |
| 功能排期卡片 | 是 | 当日流转事实（领取 / 完成），调用口径见共享契约 [`../../报告配置/references/data-source-api.md`](../../报告配置/references/data-source-api.md) |
| Qoder 用量（成员 + 模型） | 否 | 当天用量未入库，无数据可采；由周报承载 |
| 功能使用量 | 否 | 当日实时点击量波动大、无复盘价值；由周报承载 |
| MCP 工具用量 | 否 | 当天用量未入库；由周报承载 |

上表仅约束生成时的数据采集范围，不写入报告正文。

日报聚焦「当天谁提交了什么、功能排期卡片流转到哪」，不做用量维度分析；无法取得的统计项直接省略，不在报告中写缺失或失败说明，也不得以 0 或推测值代替。

## 人员范围

执行口径同 [`dev-report.md`](dev-report.md)：只统计数据包「统计人员范围」内人员，名单外的 git 作者与功能排期卡片负责人/开发人不计入、不在报告中出现；Git 作者按姓名/别名归一匹配，同一提交命中多人时按名单顺序归入第一个命中人员。项目级数据保持全量。

## 输出章节规范

全文中文。报告标题格式：`研发日报 - {yyyy-MM-dd}`（生成当天日期）。章节顺序不可调换：

1. **统计摘要**：统计范围（研发团队名单 N 人）；当日总提交数 / 参与开发人数 / 涉及仓库数量（均按名单内作者统计）；功能排期卡片当日完成数 / 领取数（按名单内人员统计）
2. **按人员当日产出**（核心章节）：每人当日提交次数与主要工作（合并同功能多次提交）、涉及仓库；当日功能排期卡片流转（领取 / 完成的卡片标题与时间）
3. **各仓库提交分布**：按项目分组统计各仓当日提交次数（含 0 提交仓，标注 0），口径同 dev-report 的仓库归属分组规则
4. **口径说明**：统计区间为当日 00:00 至生成时（实时截断）

### 章节输出模板

> 模板为数据齐全时的完整形态；无法取得的统计项整体不输出。

```markdown
# 研发日报 - {report_date}

> 统计区间：{report_date} ~ {report_date}（当日实时，生成时截断于 {HH:mm}）

## 统计摘要

- 统计范围: 研发团队名单（N 人）
- 当日总提交数: N
- 参与开发人数: N
- 涉及仓库: N
- 功能排期卡片: 当日完成 N 个 / 领取 M 个

## 按人员当日产出

### 张三

**代码产出**：当日 N 次提交
- 主要工作：xxx 功能开发、yyy 问题修复
- 涉及仓库：repo-a、repo-b

**功能排期卡片流转**：✅ 完成 任务A（14:20）；🔄 领取 任务B（10:05）

---

## 各仓库提交分布

### {项目名}（小计 N 次）
- **repo-a**: N 次提交

## 口径说明

- 统计区间为当日 00:00 至生成时（{HH:mm} 实时截断），非完整自然日

---
*报告生成时间: {report_date} {HH:mm}*
```

## 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`daily_dev_yyyyMMdd.md`（服务端按文件名解析类型与日期）
- 服务端生成会话回传服务端直接落库（版本递增、日索引）；外部会话按共享推送契约上报；均同 [`dev-report.md`](dev-report.md) Step 5
