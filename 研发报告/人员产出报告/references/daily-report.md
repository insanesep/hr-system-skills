# daily-report / 研发日报生成

> 一句话定位：采集前一自然日 Git 提交 + 功能排期卡片流转事实 + Qoder 用量快照，由模型直接生成研发日报，写入报告文件。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。无企微推送。

## When to Use

- 用户说「生成日报 / 跑研发日报」
- 复盘前一自然日的研发产出（上班前、早会前快照）
- 用户说「推送日报到后台」（外部会话旁路）

## When Not to Use

- 需要定时自动跑 → 由报告配置模块「报告触发配置」页承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报 / 一致性检查 / 项目进度报告 → 分别由 [`dev-report.md`](dev-report.md)、文档一致性报告、项目进度报告模块的生成 skill 承载

## 与周报 skill 的关系

执行流程与纪律全部同 [`dev-report.md`](dev-report.md)：读配置定工作区（Step 1）、工作区硬约束、仓库同步（Step 2）、全作者采集、独立模型识别与程序校验汇总（Step 3）、正文模型只引用选后统计（Step 4）、写文件与落库 / 推送（Step 5）。本文件声明日报的统计窗口、数据源裁剪、人员口径与输出要求。

## 统计窗口

前一自然日 00:00 ~ 24:00（东八区，完整单日窗口），覆盖前一自然日全天的研发活动。

**统计日期锚点**：以生成日（定时器触发日 / 手动立即生成当日）的前一日为报告日期（标题、文件名、发报日索引），统计窗口即该前一自然日全天，与 Qoder 用量快照日（成员 × 自然日，见 [`../../../研发管理/Qoder用量分析/references/business-rule.md`](../../../研发管理/Qoder用量分析/references/business-rule.md) §1）天然一致。生成时点不在本 skill 固定，由「报告配置 → 报告触发配置」的定时规则维护（见 [`../../报告配置/references/business-rule.md`](../../报告配置/references/business-rule.md)）；定时规则应配置在当日凌晨前一日用量快照同步完成之后，保证窗口与用量数据完整。

窗口为完整固定区间，不随生成时点截断；须在报告正文首部声明统计区间（`统计区间：YYYY-MM-DD 00:00 ~ 24:00`，起止同日，保证可解析入库）。

## 数据源裁剪

| 数据源 | 日报是否采集 | 说明 |
|--------|-------------|------|
| Git 提交记录 | 是 | 程序采集完整窗口全部作者，独立模型识别后由程序校验并汇总；正文只使用选后统计。采集口径同 dev-report：master 与 feature/* 分支、不统计 tag、SHA 全局去重、剔除合并提交、逐提交 numstat，二进制文件不计行数 |
| 功能排期卡片 | 是 | 窗口内流转事实（领取 / 完成），调用口径见共享契约 [`../../报告配置/references/data-source-api.md`](../../报告配置/references/data-source-api.md) |
| Qoder 用量（成员 + 模型） | 是 | 取报告日期（前一自然日）快照，与统计窗口同一自然日：Credits 用量、请求次数、次均消耗口径同 [`../../../研发管理/Qoder用量分析/references/business-rule.md`](../../../研发管理/Qoder用量分析/references/business-rule.md) §2；折算金额 = Credits 用量 × 0.15 元 |
| 功能使用量 | 否 | 点击量维度由周报承载 |
| MCP 工具用量 | 否 | 由周报承载 |

上表仅约束生成时的数据采集范围，不写入报告正文。

日报聚焦「前一日谁提交了什么、提交行数多少、功能排期卡片流转到哪、Qoder 用量与折算成本多少」；无法取得的统计项直接省略，不在报告中写缺失或失败说明，也不得以 0 或推测值代替。

## 人员范围

执行口径同 [`dev-report.md`](dev-report.md) Step 3，报告最终只统计数据包「统计人员范围」内成员，不由模型新增人员：

- Git 先采集完整窗口内 master 与 feature/* 分支的全部作者，不统计 tag，不因姓名或邮箱未与名单姓名、已登记别名完全匹配而提前删除作者。程序按 SHA 全局去重、剔除合并提交、逐提交 numstat 统计新增 / 删除行数，二进制文件不计行数
- 正文生成前由独立模型筛选阶段仅依据真实作者姓名、邮箱、现有名单与已维护别名自主识别；每位作者给出选中或排除、选中时对应名单成员姓名与理由，无法确认归属的作者排除，不进入人工确认流程。模型不得改变已采集提交或行数
- 程序验证作者来自真实采集、选中成员在名单内、每位作者恰好有一次结果；重复、遗漏或非法映射须使生成失败，不按名单顺序强行归人。校验通过后程序按映射重新汇总选中作者的总计、各仓与各人提交数及行数，三者须打平
- 正文模型只消费程序给出的选中成员、选后数字与提交说明，不能重新筛选、改写映射、重计或扩大范围
- Qoder 用量与功能排期卡片仍由代码按原名单确定匹配过滤；姓名或已维护别名去掉空白、忽略大小写、忽略括号内职级后缀后完全相等才视为同一人，沿用程序原有匹配顺序，不使用 Git 模型映射补充人员。名单外 Qoder 成员、负责人、开发人不计入、不点名；项目级数据保持全量
- 完整选中及排除映射与理由保存在任务工作区审计 JSON。报告附录只引用程序提供的选中作者姓名、邮箱、对应名单成员及理由；名单外或未选中作者的姓名、邮箱及逐人排除理由不出报告，仅展示排除作者数量

## 输出章节规范

全文中文。报告标题格式：`研发日报 - {yyyy-MM-dd}`（窗口起始日，即前一日）。章节顺序不可调换：

1. **统计摘要**：统计范围（研发团队名单 N 人）；窗口内总提交数（含新增 / 删除行数）/ 参与开发人数 / 涉及仓库数量（均按名单内作者统计）；功能排期卡片窗口内完成数 / 领取数（按名单内人员统计）；Qoder 总用量（Credits）/ 折算金额（元）/ 总请求次数 / 次均消耗（按名单内成员、前一自然日快照统计）
2. **按人员产出**（核心章节）：每人窗口内提交次数与新增 / 删除行数、主要工作（合并同功能多次提交）、涉及仓库；窗口内功能排期卡片流转（领取 / 完成的卡片标题与时间）；Qoder 用量（Credits）/ 折算金额 / 请求次数 / 次均消耗
3. **各仓库提交分布**：按项目分组引用程序提供的选后提交次数与新增 / 删除行数（成功采集且选后无提交的仓库标注 0，采集失败不补 0），口径同 dev-report 的仓库归属分组规则
4. **口径说明**：统计区间为前一自然日 00:00 至 24:00；Git 数字为程序按验证后选中映射汇总的提交数与行数；Qoder 用量按报告日期自然日快照统计（与统计窗口同一自然日）；折算金额单价
5. **附录：Git 作者筛选依据**：置于口径说明之后、报告生成时间之前；Git 成功采集时引用程序提供的选中作者姓名、邮箱、对应名单成员与理由，并展示排除作者数量。选中为空时不补作者，只引用排除数量；完整映射只留任务工作区审计 JSON，未选中作者不点名，正文不得改写已验证映射或理由

「按人员产出」中的人员默认按客观产出贡献度从高到低排序：依次比较窗口内完成的功能排期卡片数、提交次数、新增行数、Qoder Credits 用量，前一项并列再比较后一项，四项均并列时按统计人员名单顺序；某项数据源整体缺失时跳过该比较项，不按 0 补齐。不计算或展示贡献度分值与名次。

### 章节输出模板

> 模板为业务正文示意；Git 筛选附录按上一节要求追加，无法取得的统计项整体不输出。

```markdown
# 研发日报 - {report_date}

> 统计区间：{report_date} 00:00 ~ 24:00（前一自然日全天）

## 统计摘要

- 统计范围: 研发团队名单（N 人）
- 总提交数: N（新增 X 行 / 删除 Y 行）
- 参与开发人数: N
- 涉及仓库: N
- 功能排期卡片: 完成 N 个 / 领取 M 个
- Qoder 用量: 总用量 N Credits / 折算金额 ¥M / 请求 N 次 / 次均消耗 X.X Credits

## 按人员产出

### 张三

**代码产出**：N 次提交（新增 X 行 / 删除 Y 行）
- 主要工作：xxx 功能开发、yyy 问题修复
- 涉及仓库：repo-a、repo-b

**功能排期卡片流转**：✅ 完成 任务A（23:20）；🔄 领取 任务B（08:05）

**Qoder 用量**：N Credits（折算 ¥M）/ 请求 N 次 / 次均消耗 X.X Credits

---

## 各仓库提交分布

### {项目名}（小计 N 次，新增 X 行 / 删除 Y 行）
- **repo-a**: N 次提交（+X / -Y）

## 口径说明

- 统计区间为报告日期 00:00 至 24:00（东八区，前一自然日全天）；日报归属统计日（生成日的前一日）
- Git 提交数与行数为程序按验证后选中映射汇总的同一提交集合（master 与 feature/* 分支、不统计 tag、SHA 全局去重、剔 merge、逐提交 numstat，二进制文件不计行数）
- Qoder 用量、请求次数、次均消耗按报告日期自然日快照统计（与统计窗口同一自然日）
- 折算金额 = Credits 用量 × 0.15 元；次均消耗保留 1 位小数，折算金额保留 2 位小数

---
*报告生成时间: {next_date} {HH:mm}*
```

## 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`daily_dev_yyyyMMdd.md`（服务端按文件名解析类型与日期；日期取报告日期，即窗口起始日 / 前一日）
- 服务端生成会话回传服务端直接落库（版本递增、日索引）；外部会话按共享推送契约上报；均同 [`dev-report.md`](dev-report.md) Step 5
