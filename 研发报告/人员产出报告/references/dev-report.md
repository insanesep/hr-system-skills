# dev-report / 研发周报生成

> 一句话定位：采集 Git 提交 + 业务 API 数据，由模型直接生成研发周报，写入报告文件。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。无企微推送。

## When to Use

- 用户说「生成周报 / 跑研发周报」
- 每周一或周日复盘上一周研发产出
- 用户说「推送报告到后台」（外部会话旁路）

## When Not to Use

- 需要定时自动跑 → 由报告配置模块「报告触发配置」页承担定时调度，本 skill 只描述单次生成会话的执行
- 需要企微群通知 → 无此能力
- 一致性检查 / 项目进度报告 → 分别由文档一致性报告、项目进度报告模块的生成 skill 承载

## 参数解析

| 参数 | 取值 | 默认 |
|------|------|------|
| 代码工作区 | 绝对路径 | 服务端会话由服务端注入；外部会话读取 config.yaml 的 `workspace_dir` 并解析为绝对路径 |
| 推送 | 服务端会话固定「不推送，产出回传服务端」；外部会话默认生成后推送，用户说「仅生成」则跳过 | 按会话类型 |

**配置来源**：

- **服务端生成会话**：工作区即会话 cwd，由 agent 服务按任务分配；仓库范围、功能排期与用量数据由调用方提供，Git 提交与行数由 agent 服务的确定性采集程序提供。仓库凭据只用于服务间请求，不进入模型会话或报告正文，不读本机配置文件
- **外部会话**：用 Read 读取生成环境约定的 `config.yaml` 并提取：`workspace_dir`、`output.dir`、`projects`（各项目 SKILL 仓库 / skill_roots / 代码仓库清单 / code_branch_policy）、`api.devops_base_url`、`api.foundation_base_url`、`dev_report.ingest_token`、`codeup`（clone 凭证，仅仓库缺失时使用）

**统计窗口（周报与 API 拉数共用）**：最近一个以周日收尾的周一~周日。

- 今天是周日 → 窗口含今天（本周一 ~ 今天）
- 否则（周一~周六触发）→ 上周一 ~ 上周日，不含今天（当天数据不完整，Qoder/MCP 用量当天未入库）

## 执行流程

### Step 1 读配置、定工作区

按会话类型取配置（服务端注入 / 外部会话读 config.yaml），确定：工作区绝对路径 `WS`、输出目录、项目清单。

🚨 **工作区硬约束（违反将产出错误结论）**：一切文件操作只能以 `WS` 为基准，目标仓库都是其子目录（`$WS/<repo>/`）。机器上其它位置存在同名仓库的**开发者副本**（过时、分支不同、缺最新提交），严禁用于搜索、读取或作为结论依据。Glob / Grep / Read / Bash 的路径参数必须落在 `WS` 内；工具结果中出现 `WS` 之外的路径一律忽略并重查。

### Step 2 同步仓库

- **外部会话**：对 `WS` 下每个参与仓库，仓库缺失时按会话配置 `codeup` 凭证浅克隆（命令不内嵌，按生成环境约定执行）。
- **服务端生成会话**：agent 服务的确定性采集程序在生成前同步维护中项目的仓库。临时缓存缺失时重新克隆，存在时增量同步；每次统计固定本轮分支快照，避免并发同步改变结果。模型不执行克隆、同步或提交计数，只使用程序提供的权威统计与提交说明进行分析。同步失败的仓库不按零提交补齐，失败详情只记录生成日志

### Step 3 采集数据、识别 Git 作者并由程序汇总

- **人员范围（强制）**：数据包「统计人员范围」是报告最终人员名单，不能由模型新增成员。外部会话的人员范围来源必须与后台名单一致（由生成环境配置或调用报告配置接口获取），无法获取时不得生成人员维度报告
- **Git 全作者采集**：外部会话由生成环境约定的采集脚本提供提交事实，服务端会话由 agent 服务的确定性采集程序提供。两者均先覆盖统计窗口内 master 与 feature/* 分支的全部作者，不统计 tag，不因作者姓名或邮箱未与名单姓名、已登记别名完全匹配而提前删除记录。按东八区提交时间过滤完整窗口（起点包含、终点不包含），按提交 SHA 全局去重、剔除合并提交；相同 SHA 出现在多个仓库时按输入仓库顺序归入首个仓库。程序对每个提交逐条取得 numstat 新增与删除行数，二进制文件不计行数
- **独立模型识别**：在生成正文前，以独立模型筛选阶段仅查看真实采集作者的姓名、邮箱、现有人员名单及已维护别名，自主判断作者是否对应名单内成员，不要求作者标识必须与已登记别名完全相等。每个作者都须给出选中或排除结果、选中时对应的名单成员姓名及判断理由；无法确认归属的作者直接排除，不进入人工确认流程。模型只提出作者映射，不得改变已采集的提交或行数
- **程序校验与汇总**：程序验证每个作者来自真实采集、每个选中成员在现有名单内、每位作者恰好有一次选中或排除结果；重复、遗漏或非法映射须使生成失败，不按名单顺序强行归人。校验通过后，程序按映射重新汇总选中作者的提交数与新增 / 删除行数，形成总计、各仓与各人统计，三者必须打平；参与人数只计名单内有选中提交的成员。成功采集但选后无提交的仓库标注 0，采集失败的仓库不补 0
- **筛选依据留档**：完整选中及排除映射与理由保存在任务工作区审计 JSON 中。报告附录只展示程序校验后的选中作者姓名、邮箱、对应名单成员及理由；名单外或未选中作者的姓名、邮箱及逐人排除理由不出现在报告中，仅展示程序给出的排除作者数量
- **非 Git 人员口径**：功能排期卡片与 Qoder 用量仍由代码按原人员名单确定匹配过滤；姓名或已维护别名去掉空白、忽略大小写、忽略括号内职级后缀后完全相等才视为同一人，沿用程序原有匹配顺序，不使用 Git 模型映射补充人员。名单外负责人、开发人与 Qoder 成员不计入、不点名；项目级数据（需求吞吐、仓库清单）保持全量，名单外姓名显示「—」
- repo 列表：外部会话 = 各项目 SKILL 仓库 + 代码仓库 + extra 仓库（会话配置 `projects` / `extra`）；服务端会话 = 会话数据「代码仓库清单」（含项目归属分组）
- 功能排期卡片（busyming MCP `busyming_feature_schedule`）：外部会话走 MCP 工具，调用口径、字段与容错见共享契约 [`../../报告配置/references/data-source-api.md`](../../报告配置/references/data-source-api.md)（大响应自动落盘后读取分析）；服务端会话由调用方在会话数据中直接提供
- 其余 4 个用量数据源（Qoder 成员用量、Qoder 模型用量、功能使用量、MCP 工具用量）：外部会话走 HTTP 接口调用，见 [`api-endpoints.md`](api-endpoints.md)（响应较大时先落盘再读取分析）；服务端会话由调用方在会话数据中直接提供

### Step 4 生成报告

- 按 [`weekly-report.md`](weekly-report.md) 的章节规范与模板生成
- 正文模型只消费程序提供的选中成员、选后统计与提交说明，不重新筛选作者、改写映射、运行 Git 计数、重算提交或行数，也不扩大人员或提交范围；定性合并工作内容不能改变数字
- 全文中文；报告标题与日期格式见 weekly-report.md

### Step 5 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`weekly_dev_yyyyMMdd.md`（服务端按文件名解析类型与日期）
- **服务端生成会话**：报告正文作为会话最终输出直接回传服务端，由服务端校验、渲染并直接落库（版本递增、周索引），本 skill 不调用推送接口；同时在工作区按同名文件留档便于追溯
- **外部会话（旁路）**：推送契约（multipart 表单 + 鉴权头，幂等）见 [`../../报告配置/references/data-source-api.md`](../../报告配置/references/data-source-api.md)；推送后把 `reportId / versionNo / duplicated` 回告用户；推送失败不删本地文件，把错误信息告知用户

## 硬约束汇总

1. 工作区硬约束：只操作 `WS` 内路径（见 Step 1）
2. 人员范围硬约束：报告最终只统计数据包名单内成员；Git 先采集全部作者，再由独立模型识别、程序验证映射，不按已登记别名提前删作者。Qoder 与功能排期仍由代码按原名单确定匹配过滤，项目级数据（需求吞吐、仓库清单）保持全量
3. 计数纪律：master 与 feature/* 分支、不统计 tag、完整窗口、SHA 全局去重、剔除合并提交、逐提交 numstat 与二进制排除均由程序执行；选中映射校验后由程序重新汇总总计、各仓与各人提交数及行数，正文模型只能引用选后统计，不重新计数或扩大范围
4. 数据容错：任一数据源拉取失败 / 无数据，直接省略对应内容，不写入缺失或失败说明，严禁编造数字；失败详情仅记录生成日志，单数据源失败不影响其它数据源。作者映射重复、遗漏或非法时须终止生成，不能当作数据缺失省略
5. 筛选可追溯：选中作者映射与理由写入报告附录，完整映射写入任务工作区审计 JSON；名单外或未选中作者不点名，仅展示排除作者数量，不走人工确认流程
6. 服务端仓库凭据不进入模型会话，外部会话凭据仅从生成环境配置读取；均禁止写进报告或 skill 文件
