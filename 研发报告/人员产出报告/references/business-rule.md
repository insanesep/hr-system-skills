# 人员产出报告 · 业务规则字典

> 本文件为人员产出报告（研发周报 / 研发日报）模块的业务规则真源。归档 / 触发 / 版本 / 渲染 / 权限的子域共享口径以 [`../../报告配置/references/business-rule.md`](../../报告配置/references/business-rule.md) 为真源，本文件不复述。

## 1. 报告内容口径

- **产出量**：统计区间内 commit 数、完成的功能卡数（区分提交人与开发人/领取人双口径，避免「代提交」场景产出错记）
- **时效**：功能排期卡片领取 → 完成的平均时长；需求关联卡的端到端周期
- **质量与纪律**：延期卡数与延期率、完成回退次数
- **人员透视**：人员 × 项目、人员 × 周期的产出矩阵；个人保留代码产出总计、功能排期卡片与 Qoder 三项，多项目人员的代码产出内按项目展开提交次数、新增 / 删除行数、主要工作和涉及仓库，单项目人员保持简洁展示
- **项目产出归属**：采用任务创建时冻结的成员稳定标识、有效项目成员关系与项目仓库边界，由程序在作者筛选校验后归集；不按提交说明、仓库名称或当前配置猜测。主要工作只在同一项目内合并同功能提交，不跨项目混写
- **项目明细完整性**：已选中但未命中该成员项目边界的提交单列「未归属项目」，仍保留在个人总计；归属冲突同样单列，不重复计入项目。缺少项目快照标「项目归属未取得」，不等同于未归属。完整采集且无选中提交的项目显示 0；部分采集须注明已采集小计与缺失仓库，不冒充完整项目总计
- **非代码项**：功能排期卡片流转和 Qoder 用量仍按人汇总，不按项目重复计数，不做项目用量或金额分摊；个人、项目与未归属代码明细使用同一选中提交集合，不改变原有去重口径或历史报告
- **人员排序**：周报「按人员综合分析」与日报「按人员产出」默认按客观产出贡献度从高到低排列：依次比较统计窗口内完成的功能排期卡片数、commit 数、新增行数、Qoder Credits 用量，前一项并列再比较后一项，四项均并列时按统计人员名单顺序；某项数据源整体缺失时跳过该比较项，不按 0 补齐
- **统计人员范围**：代码提交、功能排期卡片、Qoder 用量等人员维度只统计「项目管理」自动报告名单快照内人员；名单外人员不计入、不点名。项目级数据（需求吞吐、仓库清单）保持全量，其中人员姓名按名单脱敏（名单外显示「—」）
- **周报口径**：研发周报统计窗口为最近一个以周日收尾的自然周（周日生成含当周）；Git 提交（次数与新增/删除行数）、功能排期卡片（排期日、领取或完成任一落在窗口内）与 Qoder 用量（Credits、折算金额、请求次数、次均消耗，窗口内各自然日快照合计）口径与日报一致，另含需求吞吐、功能使用量与 MCP 工具用量
- **日报裁剪**：研发日报统计窗口为前一自然日 00:00 至 24:00（东八区），日报归属统计日（前一日），统计日期锚定生成日（定时器触发 / 手动立即生成当日）的前一日，生成时点由「报告配置 → 报告触发配置」定时规则维护；日报含 Git 提交（次数与新增/删除行数）、功能排期卡片流转与 Qoder 用量（Credits、折算金额 = Credits × 0.15 元、请求次数、次均消耗，按统计日自然日快照取数，与窗口同日，口径见 [`../../../研发管理/Qoder用量分析/references/business-rule.md`](../../../研发管理/Qoder用量分析/references/business-rule.md)）；功能使用量、MCP 工具用量仍由周报承载

## 2. 核心规则

- **数据客观唯一**：全部指标由 git 事实与功能排期卡片流水计算，不引入主观评分；人员顺序仅按客观产出确定，不计算或展示贡献度分值与名次，不做「红黑榜」类产品形态
- **缺失数据不补零**：周报 / 日报源缺失标「未取得」，不以 0 或推测值代替；Qoder 无账号、映射或自然日快照未取得同样处理。仅成功且明确零值才能计 0，部分成员有数不得冒充完整团队总量
- **人员范围唯一口径**：只读引用 [项目管理 #report-scope](../../../研发管理/项目管理/references/business-rule.md#report-scope)；日报、周报、外部会话与 Qoder 数据包共同采用生成名单快照并保留历史。身份与别名裁决见 [#identity](../../../研发管理/项目管理/references/business-rule.md#identity)，参与关系见 [#membership](../../../研发管理/项目管理/references/business-rule.md#membership)；不复制匹配规则，不按名单首人归属；空名单或真源未取得拒绝生成
- **角色与职责**：名单按真源自动范围确定，不按研发/产品/架构/设计角色重建；同门户稳定 ID 多角色去重。角色专项分析只采用对应职责证据，不将全部产出重复归入各角色，也不扩大查阅权限
- **基础范围与去重**：项目边界只读引用 [项目管理 #consumption](../../../研发管理/项目管理/references/business-rule.md#consumption) 的生成快照，取配置的 harness 工程与代码服务仓，不按一级目录拆项目；排期卡片与流水仍归功能排期。Git 保持 SHA 全局去重后的选中事实集合，卡片按稳定 ID 去重，跨项目展示不重复计入个人或团队总计
- **可见性收口**：人员维度数据敏感，仅管理层与研发负责人角色可见；不向被统计人推送
- **归档与版本**：研发周报按发报日所在自然周（周一为起点）建周索引，研发日报按发报日建日索引；同类型同周期重复入库走版本递增而非覆盖，历史版本可追溯；报告为静态产物，归档后不重新计算指标
- **旁路态不计入**：统计不含 NON_FEATURE 旁路态卡片
- 指标定义在报告内附口径说明，防止跨周期比较时口径漂移；日报为前一自然日单日窗口，不与周报等完整周期报告直接比较
