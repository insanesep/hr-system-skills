# 人员产出报告 · 业务规则字典

> 本文件为人员产出报告（研发周报 / 研发日报）模块的业务规则真源。归档 / 触发 / 版本 / 渲染 / 权限的子域共享口径以 [`../../报告配置/references/business-rule.md`](../../报告配置/references/business-rule.md) 为真源，本文件不复述。

## 1. 报告内容口径

- **产出量**：统计区间内 commit 数、完成的功能卡数、完成的实施卡数（区分提交人与开发人/领取人双口径，避免「代提交」场景产出错记）
- **时效**：卡片领取 → 完成的平均时长；需求关联卡的端到端周期
- **质量与纪律**：延期卡数与延期率、完成回退次数
- **人员透视**：人员 × 项目（模块）、人员 × 周期的产出矩阵
- **统计人员范围**：代码提交、排期卡片、Qoder 用量等人员维度只统计「报告配置 → 统计人员范围」启用名单内人员；名单外人员不计入、不点名。项目级数据（需求吞吐、仓库清单）保持全量，其中人员姓名按名单脱敏（名单外显示「—」）
- **日报裁剪**：研发日报统计窗口为当日 00:00 至生成时（当日实时截断）；Qoder 用量、功能使用量、MCP 工具用量当天未入库，日报不含用量类维度，仅呈现提交与卡片流转事实

## 2. 核心规则

- **数据客观唯一**：全部指标由 git 事实与排期卡片流水计算，不引入主观评分；不做「排名」「红黑榜」类产品形态
- **缺失数据静默省略**：周报 / 日报任一数据源无数据或拉取失败时，对应章节、指标条目与人员字段直接省略，不在报告中写缺失或失败说明，也不以 0 或推测值代替
- **人员范围唯一口径**：名单由「报告配置 → 统计人员范围」维护，研发周报 / 日报与 Token 管理共用；名单为空时人员产出报告拒绝生成
- **可见性收口**：人员维度数据敏感，仅管理层与研发负责人角色可见；不向被统计人推送
- **归档与版本**：研发周报按发报日所在自然周（周一为起点）建周索引，研发日报按发报日建日索引；同类型同周期重复入库走版本递增而非覆盖，历史版本可追溯；报告为静态产物，归档后不重新计算指标
- **旁路态不计入**：统计不含 NON_FEATURE / NON_IMPL 旁路态卡片
- 指标定义在报告内附口径说明，防止跨周期比较时口径漂移；日报为当日实时截断窗口，不与完整周期报告直接比较
