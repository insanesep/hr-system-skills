# 文档一致性报告

面向管理层、PM 与研发的**项目维度**文档一致性检查报告：AI 校验 SKILL 文档三件套（SKILL.md / references / assets）与代码实现的对齐程度，产出偏差清单与修复方向，替代人工抽查。

## 服务对象与端

- **服务对象**：管理层、PM、研发
- **Web 管理端**：触发配置、报告索引、在线阅读、版本回溯
- **App 查阅端**：按周分组浏览与阅读

## 检查范围与内容（口径）

- 按有效域/项目范围独立生成，一范围一份；基础实体与 N:N 执行映射只读引用 [项目管理](../../研发管理/项目管理/SKILL.md)，范围与根文件消费遵守 [#consumption](../../研发管理/项目管理/references/business-rule.md#consumption)，key / 分支策略来自报告范围配置。域为整个主仓及确认映射，项目为主仓一级目录及该项目确认映射；跨项目同名实现不混比，汇总按稳定标识去重
- 范围停用或远端确认缺失停止生成、不删归档；历史旧整体项目报告只显式核对到对应域，保留 key 与文件名，不复制到各项目。以上为已确认产品目标，不表示生产上线
- 范围划定由「回看天数」参数控制：仅检查最近 N 天 SKILL 仓库发生变更的模块（增量），或全量扫描
- 五维检查：文档三件套对齐、代码实现完整性、SKILL 与 references 重复冗余、SKILL 长度、代码 → 文档反向偏差
- 检查维度、执行步骤与输出模板以本模块生成规范为唯一真源：[`references/consistency-check.md`](references/consistency-check.md)，本文件不复述

## 生成方式：触发配置 + 服务端生成

1. 触发方式在 Web 端「报告触发配置」页维护：每项目一条配置行（定时规则 + 手动「立即生成」），类型参数为回看天数
2. 触发后服务端通过 **Qoder SDK** 创建生成会话，挂载本模块内置的生成 skill（入口 [`references/consistency-report.md`](references/consistency-report.md)，随本仓库版本化，为生成逻辑唯一真源），入参携带项目、回看天数与项目映射
3. 产出报告由服务端直接落库归档（渲染、版本递增、周索引），不经过推送；外部生成会话产出可经推送上报旁路入库（兜底见手动补传）
4. 生成任务全程留痕（触发来源 / 状态 / 耗时 / 失败原因），失败可在生成记录中重试

## 归档与查阅

- 报告按「类型 + 项目」成行（类型固定为文档一致性校验，项目随「报告范围配置」生效数据），按发报日所在自然周索引；同报告项同发报日重复入库走版本递增而非覆盖，历史版本可溯
- 报告为静态产物：归档后只做渲染呈现，不重新执行检查；检查口径问题回溯生成侧
- 归档、触发与生成规则真源见 [`../报告配置/references/business-rule.md`](../报告配置/references/business-rule.md)

## 页面功能概览（仅列职责）

| 端 | 页面 | 职责 |
| -- | ---- | ---- |
| Web | 报告列表（本模块，见 [`references/web-ui.md`](references/web-ui.md)，原型见 `assets/`） | 按周索引（每项目一行）+ 项目 / 日期 / 关键词筛选；缺失项立即生成 / 补传 |
| Web | 报告详情（本模块） | 元信息 + 渲染正文 + 大纲锚点导航 + 版本切换回溯 |
| Web | 报告触发配置（报告配置模块，见 [`../报告配置/references/web-ui.md`](../报告配置/references/web-ui.md)） | 一致性报告配置行的触发方式、定时规则、回看天数与启停；立即生成；生成记录与失败重试 |
| App | 列表 / 详情（本模块，见 [`references/mobile-ui.md`](references/mobile-ui.md)） | 按周分组浏览、渲染阅读 |
