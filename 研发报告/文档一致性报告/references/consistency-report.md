# consistency-report / 文档一致性报告生成

> 一句话定位：按项目校验 SKILL 文档三件套与代码实现的一致性，由模型直接执行并写入报告文件。服务端生成会话的产出回传服务端直接落库归档；外部会话产出推送至 devops 研发报告模块（旁路通道）。

## When to Use

- 用户说「跑一致性检查 / 生成一致性报告 / 文档代码对齐检查」
- 周期性校验各项目 SKILL 仓库与代码仓的偏差

## When Not to Use

- 需要定时自动跑 → 由报告配置模块「报告触发配置」页承担定时调度，本 skill 只描述单次生成会话的执行
- 研发周报 / 项目进度报告 → 分别由人员产出报告、项目进度报告模块的生成 skill 承载

## 参数解析

| 参数 | 取值 | 默认 |
|------|------|------|
| 报告范围 | 有效已配置启用的域/项目，类型+稳定引用关联 key，可多个 | 服务端入参指定；外部默认全部可生成范围，逐范围产出，沿用原 key 文件名 |
| lookback_days | N 天 / 0=全量 | 服务端会话由触发配置的类型参数给定；外部会话默认 7 |
| 代码工作区 | 绝对路径 | 服务端会话由服务端注入；外部会话读取 config.yaml 的 `workspace_dir` 并解析为绝对路径 |
| 推送 | 服务端会话固定「不推送，产出回传服务端」；外部会话默认生成后推送，用户说「仅生成」则跳过 | 按会话类型 |

**配置来源**：

- **服务端生成会话**：工作区与连接配置由服务端注入；基础范围只读来自 [域及项目管理](../../../研发管理/域及项目管理/SKILL.md)，包含类型（域/项目）、稳定实体引用与确认 N:N 执行映射快照，范围及根文件消费遵守 [#consumption](../../../研发管理/域及项目管理/references/business-rule.md#consumption)。key / 分支策略归报告范围配置
- **共同约束**：域=整个主仓及确认映射，项目=主仓一级目录及该项目确认映射；外部配置仅传递同真源引用与快照，不另建实体。真源停用或远端确认缺失停止生成、不删归档；新范围配置齐备启用才报告，历史旧整体项目只显式核对到对应域，不复制到各项目，key / 文件名不变。以上为已确认产品目标，不表示生产已上线
- **外部会话**：用 Read 读取生成环境约定的 `config.yaml` 并提取：`workspace_dir`、`output.dir`、`projects`（各项目 SKILL 仓库 / skill_roots / 代码仓库清单 / code_branch_policy）、`api.devops_base_url`、`dev_report.ingest_token`、`codeup`（clone 凭证，仅仓库缺失时使用）

## 执行流程

### Step 1 读配置、定工作区

按会话类型取配置（服务端注入 / 外部会话读 config.yaml），确定：工作区绝对路径 `WS`、输出目录、项目清单。

🚨 **工作区硬约束（违反将产出错误结论）**：一切文件操作只能以 `WS` 为基准，目标仓库都是其子目录（`$WS/<repo>/`）。机器上其它位置存在同名仓库的**开发者副本**（过时、分支不同、缺最新提交），严禁用于搜索、读取或作为结论依据。Glob / Grep / Read / Bash 的路径参数必须落在 `WS` 内；工具结果中出现 `WS` 之外的路径一律忽略并重查。

### Step 2 同步仓库

对 `WS` 下每个参与仓库：仓库缺失时按会话配置 `codeup` 凭证浅克隆（命令不内嵌，按生成环境约定执行）。

按项目 `code_branch_policy` 切换检查基准分支（只切 `WS` 内的工作区仓库，严禁碰开发目录）：

- `release`：取最近提交的 release 分支，但它必须包含基准分支最新提交（防倒退），否则回退 master
- `master`（缺省）：直接以 master 为基准

### Step 3 逐项目检查

按 [`consistency-check.md`](consistency-check.md) 的执行步骤逐项目执行：划定检查范围（lookback_days 语义）→ 逐模块五维检查 → 完整性自校。多项目会话按项目串行产出，互不染指。

### Step 4 生成报告

- 每项目一份报告，章节与输出模板见 [`consistency-check.md`](consistency-check.md)
- 全文中文；标题：`一致性检查报告（{项目名}） - {yyyy-MM-dd}`（生成当天日期）
- 完整性红线：覆盖模块数 = 枚举模块数，严禁省略

### Step 5 写文件 + 落库 / 推送

- 写入输出目录，文件名严格遵循：`consistency_yyyyMMdd_<项目key>.md`（服务端按文件名解析类型与日期）
- **服务端生成会话**：产出文件回传服务端，由服务端校验、渲染并直接落库（版本递增、周索引），本 skill 不调用推送接口
- **外部会话（旁路）**：推送契约（multipart 表单 + 鉴权头，幂等）见 [`../../报告配置/references/data-source-api.md`](../../报告配置/references/data-source-api.md)；推送后把 `reportId / versionNo / duplicated` 回告用户；推送失败不删本地文件，把错误信息告知用户

## 硬约束汇总

1. 工作区硬约束：只操作 `WS` 内路径（见 Step 1）
2. 项目边界：只在项目内比对，跨项目搜到同名实现不算数
3. 完整性红线：报告覆盖模块数必须与划定范围内模块总数一致
4. 容错：单个模块分析失败降级为仅结构检查，不中断其它模块
5. token 只从会话配置（服务端注入或 config.yaml）读取使用，禁止写进报告或 skill 文件
