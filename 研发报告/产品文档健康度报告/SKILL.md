# 产品文档健康度报告

面向管理层、PM、产品架构师与仓库负责人的**项目维度**文档质量评估报告：按周对项目映射内全部业务需求文档进行只读检查，形成模块评分、仓库治理评分、覆盖完整性、环比变化与修复建议。固定排除 `busyming-skills-common` 与 `busyming-skills-design`，仅检查业务仓对这两个公共真源的引用，不评估其自身。报告不判断代码实现，不修改任何业务仓文档。

## 服务对象与端

- **服务对象**：管理层、PM、产品架构师、仓库负责人
- **Web 管理端**：报告索引、评分与环比阅读、治理问题与修复建议、版本回溯
- **App 查阅端**：按周浏览、评分摘要与正文阅读

## 评估口径

- **全量与只读**：按报告范围配置中的有效域/项目逐一评估；基础实体与 N:N 映射引用 [域及项目管理](../../研发管理/域及项目管理/SKILL.md)，范围、根文件与跨项目去重遵守 [#consumption](../../研发管理/域及项目管理/references/business-rule.md#consumption)。域=整个主仓及确认映射，项目=一级目录及该项目确认映射；仍排除 common/design，固定只读 commit，不修改业务仓
- **生成与历史**：新范围只自动成行，key / 分支策略齐备启用才报告；范围停用或远端确认缺失停止生成、不删归档。历史整体项目仅显式核对到对应域，不猜测或复制到各项目，沿用既有 key 文件名；以上为已确认产品目标，不表示生产上线
- **模块评分**：D1～D6 客观健康分 100 分 + 硬门禁；FAIL 保留原始分供趋势观察
- **仓库评分**：模块质量子分 80% + 仓库治理子分 20%；同一问题只在所属层级计一次
- **AI 辅助诊断**：独立检查需求逻辑闭环与跨文档一致性，必须有原文证据，不参与分数、等级或硬门禁
- **修复建议**：每个确认问题给出证据、影响、真源修复位置、修复动作、优先级与复核点，评估系统不自动执行

客观检查、评分、文件覆盖自校与环比规则唯一真源为 [`references/health-check.md`](references/health-check.md)，AI 诊断规则唯一真源为 [`references/semantic-diagnostics.md`](references/semantic-diagnostics.md)。

## 生成方式

1. 触发方式复用「报告触发配置」：每项目一条配置行，支持定时与手动「立即生成」，默认定时每周
2. 触发后服务端通过 Qoder SDK 创建生成会话，挂载本模块生成 skill（入口 [`references/health-report.md`](references/health-report.md)），入参携带项目映射、分支策略、计划发报日与规则版本
3. 生成会话依次完成只读快照、仓库 profile 识别、全文件分类、客观评分、AI 诊断、上期基线对比与覆盖自校
4. 报告由服务端直接落库归档；外部生成会话产出可经推送上报旁路入库，生成记录与失败重试复用共享规则

## 归档与环比

- 报告按「产品文档健康度 + 项目」成行，按发报日所在自然周索引；同报告项同发报日重复入库走版本递增
- 环比基线为同一报告项**上一发报日的最新归档版本**；同发报日版本修正不构成新一次评估
- 模块身份为「仓库名 + 模块相对目录」；同时呈现当前全量结果与两期同模块可比结果，新增、移除与不可比模块单列
- 报告为静态产物，归档后只做渲染，不重跑检查；历史评分以当次规则版本与各仓 commit 为准
