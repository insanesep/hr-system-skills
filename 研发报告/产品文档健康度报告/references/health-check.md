# 产品文档健康度 · 客观检查、评分与环比规范

> 本文件是全量检查、客观评分、仓库治理、覆盖自校、环比与修复建议的唯一真源。AI 语义诊断见 [`semantic-diagnostics.md`](semantic-diagnostics.md)，报告生成步骤见 [`health-report.md`](health-report.md)。

## 1. 范围与硬约束

1. 按报告范围配置中已配置启用的有效域/项目逐一生成，每周全量评估限定范围内的业务需求文档；固定排除 `busyming-skills-common` 与 `busyming-skills-design`，不使用增量回看替代全量评估。域及子项目重叠结果不能相加，范围依据见 §2；旧整体项目历史只显式核对到对应域，保留 key / 文件名，不复制到子项目，不混作同口径环比。此为已确认产品目标，不证明生产已上线
2. 业务仓全程只读：基于独立快照固定 commit，不编辑、删除、移动、回写、提交或推送，不自动修复
3. 评分只采用可重复判定的客观事实；AI 只做候选文件角色标注与语义诊断，不影响分数、等级或门禁
4. 每个文件必须进入唯一分类，无法解析或证据不足不得默认为正常，也不得直接扣分
5. 检查范围、排除范围、规则 profile、规则版本与各仓 commit 必须写入报告；口径变化不得伪装成文档质量变化

被排除的 common 与 design 不建立评估快照，不进入文件清单、模块/仓库评分、覆盖统计或环比；它们仍是公共真源，业务需求仓对 common/design 的引用具体性与可达性照常纳入 D3、D4、D6 与门禁检查。

## 3. 仓库结构 profile

| profile | 模块评分范围 | 结构及禁止内容差异 |
| --- | --- | --- |
| `BUSINESS` 业务需求仓 | 业务目录下每个含 SKILL.md 的需求模块 | AGENTS.md + 业务目录 + 模块 SKILL/references/assets；产品需求禁止研发实现细节 |
| `DEVOPS` 产研仓 | 按菜单层级组织、含 SKILL.md 的功能目录，不固定深度 | 菜单分组/功能目录结构及本仓内容红线；瘦身索引按仓规处理 |
| `EMPTY` 空仓/待建仓 | 无 | 只做仓库状态与覆盖检查，不计算模块质量子分或仓库综合分 |

profile 只定义结构规则与资产差异，不设置具体文件名豁免清单。现行 AGENTS.md 与目标结构冲突时，按目标结构检查并另记“仓规与目标结构冲突”，不得因现状已引用就认定冗余为长期必需。

## 4. 全量文件清单与引用图

### 4.1 固定快照

1. 按分支策略建立独立只读快照，记录每仓完整 commit；扫描期间不得切换分支或混入本地未提交改动
2. 仓库缺失、拉取失败或权限不足时，该仓标记检查失败，不使用其他位置的同名开发者副本
3. 扫描前建立本次稳定范围内完整文件清单，排除 `.git`、`.qoder/repowiki`、依赖目录与 profile 明确的构建生成物；`.gitkeep` 按仓内占位规则处理，系统垃圾文件进入文件卫生检查
4. 项目报告只计一级目录及其确认执行映射范围内文件与问题；读取主仓根导航和公共资料仅用于判定依赖，不将根文件或仓根治理问题重复算入各项目。范围变化须在覆盖与环比声明中标明，不能把全仓评分复制为每个项目评分；原权重、门禁与固定表格列不变

### 4.2 引用关系

- 仓库级：解析根 AGENTS.md、仓内共享文档及所有 Markdown 的相对链接与锚点
- 模块级：解析 SKILL.md 到 references、assets 的直接引用；references 是否必须直接被 SKILL 引用按仓规执行
- 原型级：解析 HTML 到本地 CSS、JS、图片等静态资源的引用；动态或无法确认的引用标记无法判定
- 路径处理：统一中文、大小写、URL 编码与相对层级，按快照文件系统实际解析；默认不跟随符号链接，嵌套仓和子模块单独登记

### 4.3 文件唯一分类

| 分类 | 判定与计分 |
| --- | --- |
| 正常 | 符合 profile 且引用/职责正常，参与该资产类型规定的检查 |
| 结构性例外 | profile 明确允许的特殊资产，按该资产所属 profile 的规则检查 |
| 客观违规 | 位置、引用、内容或重复证据明确违规，按模块或仓库规则扣分 |
| 排除 | .git、生成的 repowiki、依赖与构建生成物等，不计分 |
| 疑似待判定 | 内容角色或语义证据不足，只进 AI 观察，不扣分 |
| 检查失败 | 读取、编码、权限或解析失败，不扣分但降低覆盖完整性 |
| 特殊对象 | 符号链接、子模块、嵌套仓、无法跟进的动态资源，单独登记 |

### 4.4 结构外候选识别

结构外文件按四类证据识别，不依赖文件名：

1. 位置：是否处于目标结构允许的位置
2. 引用：是否处于有效引用链，是否直接/间接引用或无法确认
3. 内容角色：疑似平行导航、页面映射、历史映射、过程记录、重复规则或工程残留；角色标注只用于解释
4. 重复证据：是否形成第二套导航、业务真源、已迁出副本或大量失效旧路径

被 AGENTS.md 或其他文档引用不代表符合目标结构；只依据客观位置与引用事实决定计分，AI 不得凭文件名断言冗余。

## 5. 模块客观评分

### 5.1 子项评分与 N/A

每个子项按 0～3 分：3=完全符合；2=轻微缺陷；1=多处缺陷或关键部分缺失；0=不符合、缺失或无法完成检查。

```text
子项加权得分 = 子项得分 ÷ 3 × 子项权重
模块总分 = Σ适用子项加权得分 ÷ Σ适用子项权重 × 100
```

- 无 UI 的纯规则/数据模块，D5 与交互专项可标记 N/A
- 未命中某类公共能力时，对应 D3 能力子项按满分处理
- “没有检查”不等于 N/A；无法检查进入覆盖失败，不按不适用折算

### 5.2 D1 结构与模块身份（15）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 核心目录结构 | 4 | SKILL、references、按端 assets 是否符合 profile；是否有结构外文件 |
| 目录层级与命名 | 4 | 层级、目录名、frontmatter name 与一级标题是否符合目标仓约定 |
| frontmatter 完整 | 4 | name、description、Use when 场景是否完整可用于路由 |
| 模块边界与唯一性 | 3 | 是否单一业务闭环，是否重复建模块或复制跨域事实 |

### 5.3 D2 SKILL 导航化与目标态（25）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 行数控制 | 4 | 目标仓明确值优先；未明确时目标 ≤150 行、硬上限 >250 行 |
| 必含章节 | 4 | 概述、端、使用场景、Prerequisites、页面功能概览等按仓规齐全 |
| 导航化程度 | 5 | 规则、状态机、字段表、公式是否外置 references，SKILL 是否仅保留导航与指针 |
| 无研发细节 | 4 | 产品文档是否含禁止的实现内容 |
| 当前目标态表达 | 5 | 是否只描述当前最新、需要实现的目标状态，是否含明确分期实现规划 |
| 引用指针规范 | 3 | 路径、用途、章节锚点是否明确且格式统一 |

当前目标态的客观判定：

- “一期实现 A、二期实现 B”“本期只做 A、后续版本支持 B”“二期再补齐”“Roadmap/版本规划”等明确分期实现内容，本子项 0 分并触发 G8
- 判定对象是需求正文中的能力范围与实现承诺；检查规范中明确用于说明违规的反例不作为命中，业务需求中的分期内容即使写成示例也仍命中
- “不在本需求范围”等目标功能边界不属于分期规划；实施、建设、核验进度描述及按这些状态划分的目录按目标仓约定检查，不以其代替目标需求
- “未来仓”“后续处理节点”等业务术语，以及语义不明确的候选，不客观扣分，只进入 AI 观察

### 5.4 D3 公共能力真源引用（25）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 导出/导入接入 | 3 | 命中后 Prerequisites 是否指向具体真源、含用途且可达 |
| 消息与通知 | 3 | 同上 |
| 数据一致性 | 3 | 公共口径归 common、业务事实归模块，是否具体引用 |
| 第三方及平台 API | 3 | 是否指向 common/api、agent/MCP 或 agent/CLI 的具体入口 |
| 数据实体与公共模型 | 3 | 新增/扩展实体是否有产品语义定义，公共实体是否只读引用 |
| 引用具体且可达 | 5 | 是否以仓名/目录代替具体文档，公共引用是否全部可达 |
| 引用后无复述 | 5 | 是否复制字段、状态码、筛选条件、公式等公共核心定义 |

前五项未命中对应能力时按满分；命中但未引用为 0 分并触发 G2；只写“使用某中心”而无具体文件最多 1 分；有文件但缺用途最多 2 分；路径不可达为 0 分并触发 G4。

### 5.5 D4 references 治理（15）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 核心规则文档 | 3 | business-rule 是否存在并覆盖核心规则，是否只有空标题 |
| 主链路引用完整 | 3 | 每个 reference 是否被 SKILL 直接引用，是否有孤儿文件 |
| 真源唯一与交叉重复 | 3 | 同一字段、状态、公式是否只在一个文件定义 |
| 拆分合理性 | 2 | 单文件长度、主题数量与拆分命名是否符合仓规 |
| 无禁止文件和研发细节 | 2 | 是否有 api-spec、实现报文等禁止内容，按 profile 判定 |
| 专项文档完整性 | 2 | 存在状态、权限、数据或跨域事实时必须有对应专项文档；无对应事实时不建空文档 |

### 5.6 D5 assets 与原型对齐（10）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 页面覆盖率 | 3 | 页面功能概览中的页面是否有对应 HTML；未覆盖页面不得以生成进度说明替代对应原型 |
| 端型目录匹配 | 2 | Web/App 声明与 assets/web、assets/app 是否一致 |
| 组件与页面骨架 | 2 | 是否使用 design registry 已登记组件与对应端骨架 |
| Token 与样式纪律 | 2 | 是否使用 `--busy-*`，是否有硬编码主题色或私有样式体系 |
| 静态资源完整性 | 1 | HTML 引用的本地 CSS、JS、图片是否可达，是否含非运行必需过程文件 |

无 HTML 可供检查时，组件、Token 与静态资源子项不得默认满分；无 UI 且无需原型的模块整维 N/A。

### 5.7 D6 一致性与可核验性（10）

| 子项 | 权重 | 主要检查 |
| --- | ---: | --- |
| 内外部链接可达 | 4 | 相对路径、跨仓路径与锚点是否可达 |
| Prerequisites 完整 | 2 | 公共能力以外的外部依赖是否也有明确引用 |
| AGENTS.md 已登记 | 2 | 模块条目是否存在，登记路径是否与实际一致 |
| 交互与功能边界 | 2 | UI 是否含导航/反馈/表单三段；菜单归属、非菜单页面与功能边界是否准确描述 |

## 6. 模块硬门禁

| 门禁 | 条件 |
| --- | --- |
| G1 | SKILL.md 超过目标仓硬上限 |
| G2 | 命中公共能力但 Prerequisites 无对应真源引用 |
| G3 | 模块未登记所属仓 AGENTS.md |
| G4 | 存在不可达的内部或跨仓链接 |
| G5 | references/ 存在未被 SKILL.md 直接引用的孤儿文件 |
| G6 | 引用公共真源后仍复制其核心定义 |
| G7 | 出现该 profile 禁止的文件、研发实现内容或实现报文 |
| G8 | 需求包含明确的一期/二期、后续版本等分期实现规划 |

- 门禁不再额外扣分，命中即判 `FAIL`；原始健康分仍保留用于环比
- 健康等级：A≥90、B=80～89、C=70～79、D<70，均以无门禁为前提；有门禁统一 FAIL
- G7 按目标仓 profile 判定禁止内容，不因仓内已存在该类资产而豁免

## 7. 仓库评分与治理

### 7.1 综合分

```text
M = 仓内全部可评估模块原始健康分的算术平均
R = M × 80% + G × 20%
```

- 空仓库或无可评估模块时，不计算 M 与 R，只展示 G 和覆盖结果
- 模块 FAIL 数单列，不将单个模块 FAIL 扩散为全仓 FAIL

### 7.2 仓库治理子分 G

| 维度 | 权重 | 检查目标 |
| --- | ---: | --- |
| 根导航唯一与可达 | 30 | AGENTS.md 是否唯一权威、入口是否可达、是否有平行导航 |
| 需求目录规范与文件卫生 | 25 | 是否有空壳目录、临时文件、过程产物、缓存与违规层级 |
| 跨仓边界与真源唯一 | 25 | 是否有重复业务事实、迁出模块副本或绕开 common/design 的共享真源 |
| 冗余索引与历史兼容残留 | 20 | 是否有平行模块索引、页面映射、历史映射和迁移过程文件 |

各维度按 0～3 分评档后加权：3=无问题；2=只有轻微问题或单个一般问题；1=多个一般问题或一个严重问题；0=多个严重问题或已形成平行导航/真源。

“冗余索引与历史兼容残留”默认没有为正常，出现才扣分；不要求为了环比保留历史映射。内容角色无法确认时不客观扣分。

### 7.3 仓库级阻断项

- 根 AGENTS.md 缺失或无法解析，导致无法导航
- 模块索引整体不可达
- 平行导航或映射形成无法裁决的冲突
- 已迁出业务域仍保留完整规则副本，形成两个真源

命中时治理状态为 `阻断`，保留 R 供趋势观察；不把仓内所有模块判为 FAIL。

### 7.4 不重复计分

模块内断链、孤儿文件、原型过程文件只计模块；根导航、共享入口、平行索引、历史残留只计仓库治理。同一文件形成重复真源时按最严重性质处理，不在多个维度重复处罚。

## 8. 上期基线与环比

### 8.1 基线选择

- 读取同一报告项上一发报日的最新归档版本；同发报日版本递增只是当次修正
- 首次评估、基线缺失、表格缺列或解析失败时明确标记，不猜测上期分数
- 上期与本期规则版本不一致时标记口径变化；受影响结果不直接判提升或下降

### 8.2 模块身份与可比集合

- 模块身份为 `仓库名 + 模块相对目录`
- 路径变化可参考 git 重命名/迁移记录；无法确认时按移除 + 新增，不依赖历史映射文件
- 当前全量健康分反映本期全部模块；可比模块健康分只统计两期身份一致且口径可比的模块
- 新增、移除、首次评估、不可比与检查失败模块单列，不进入可比均分

### 8.3 变化判定

- 分数差 ≥ +5：提升；≤ -5：下降；其余：持平
- 本期新增模块或仓库级硬门禁，直接判质量下降，不受分数阈值影响
- 同时展示综合分变化、模块质量变化与治理子分变化，避免平均分掩盖新增风险

## 9. 问题与修复建议

每个确认问题必须输出：问题 ID、文件与证据、影响、计分位置、修复对象、修复动作、优先级与复核点。问题优先级为 A（阻断交付）、B（影响设计/验收）、C（一般治理）。

| 问题类型 | 建议与复核口径 |
| --- | --- |
| 链接失效 | 确认目标真源后修正相对路径或移除失效引用；复核所有链接可达 |
| 孤儿 reference | 有效则在 SKILL 增加直接引用与用途，失效则由仓库负责人授权治理；复核无未引用文件 |
| 未登记 AGENTS | 在正确业务域补充模块条目并核对路径；复核导航与实际目录一致 |
| 公共依赖缺失/复述 | 补充具体公共真源并删除本地核心定义；复核只保留一句话指针 |
| 平行索引/历史残留 | 将当前入口归并到唯一 AGENTS 或所属模块，历史过程由 git 承载；复核无第二套导航或平行真源 |
| 分期实现规划（G8） | 改写为当前完整目标态；范围外能力写“当前不支持/不在本需求范围”，不得以二期保留承诺；复核 SKILL、规则、UI 与原型范围一致 |

建议只供仓库负责人执行，评估系统不自动修改。AI 语义诊断的建议不得替产品经理决定业务规则。

## 10. 覆盖自校与报告输出

每仓执行：

```text
文件总数 = 正常 + 结构性例外 + 客观违规 + 排除 + 疑似待判定 + 检查失败 + 特殊对象
文件覆盖率 = 已完成检查数 ÷ 应检查文件数 × 100%
```

- 分类合计不等、存在未登记文件或模块覆盖数与枚举数不等时，自校不通过，不得宣称全量完成
- 报告必须列出覆盖率、未判定数、检查失败数、结构外文件清单与客观证据
- 无法解析、动态引用无法确认、语义相似但证据不足只列待判定，不扣分
- 报告仓库评分表与模块评分明细表使用 [`data.md`](data.md) §10 的固定列，供下一发报日基线读取
- AI 诊断未完成不影响已完成的客观评分，但必须登记诊断未覆盖范围
