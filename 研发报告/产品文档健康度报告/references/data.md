# 产品文档健康度报告 · 数据定义

> 面向产品视角定义评估任务、评分结果、问题、基线与覆盖自校的数据语义；物理存储以代码仓为准。历史评分只通过归档报告读取，不另建评分快照库。

## 1. 实体关系

```text
评估任务 1 ──── N 仓库评估
仓库评估 1 ──── N 模块评估
仓库评估 1 ──── N 文件问题 / 仓库治理问题 / 覆盖自校
模块评估 1 ──── N 模块问题 / AI 诊断
问题 1 ──── 1 修复建议
评估任务 0..1 ──── 1 基线引用
评估任务成功时 N ──── 1 报告版本
```

- 评估任务对应一次「报告类型 + 项目 + 计划发报日」的生成行为，对应共享报告生成任务
- 仓库评估按项目映射内排除 `busyming-skills-common`、`busyming-skills-design` 后的业务需求仓逐一形成；模块评估按「仓库名 + 模块相对目录」唯一确定
- 报告归档沿用共享「研发报告 + 报告版本」；同发报日重复入库只增加版本，不增加评估批次

## 2. 评估任务

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 任务 ID | 评估任务标识 | 标识 | 是 | 与共享报告生成任务关联 |
| 报告类型 | 报告种类 | 枚举 | 是 | 固定 `DOC_HEALTH` |
| 项目标识 | 项目边界 | 文本 | 是 | 命中报告项目配置的项目 key |
| 计划发报日 | 本次评估日期身份 | 日期 | 是 | 东八区；补跑保留原计划点 |
| 规则版本 | 评分与检查口径版本 | 文本 | 是 | 由生成规范统一给定，报告中可见 |
| 触发来源 | 任务来源 | 枚举 | 是 | `SCHEDULED` / `MANUAL` |
| 状态 | 执行状态 | 枚举 | 是 | `RUNNING` / `SUCCESS` / `FAILED` |
| 失败原因 | 失败说明 | 文本 | 否 | 失败时必填 |
| 开始/结束时间 | 执行耗时 | 时间 | 是 | 东八区；结束时间为终态时间 |
| 产出版本 ID | 归档结果 | 标识 | 否 | 成功时关联报告版本 |

## 3. 仓库评估

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 仓库名 | 被评估需求仓 | 文本 | 是 | 项目映射内唯一 |
| 评估 commit | 扫描基线 | 文本 | 是 | 只读快照的完整提交号 |
| 分支策略 | 统计分支口径 | 枚举 | 是 | `master` / 最近 `release/*` 且防回退 |
| 结构 profile | 仓库结构规则 | 枚举 | 是 | `BUSINESS` / `DEVOPS` / `EMPTY` |
| 模块质量子分 M | 模块原始分均值 | 小数 | 有模块时必填 | 0～100，保留 1 位小数 |
| 仓库治理子分 G | 仓库客观治理得分 | 小数 | 是 | 0～100，保留 1 位小数 |
| 仓库综合分 R | 综合结果 | 小数 | 有模块时必填 | `M × 80% + G × 20%` |
| 模块总数 | 纳入模块评分数量 | 整数 | 是 | 不含候选目录与无 SKILL 占位 |
| 模块 FAIL 数 | 命中硬门禁模块数 | 整数 | 是 | ≥0 |
| 治理状态 | 仓库级结论 | 枚举 | 是 | `通过` / `存在问题` / `阻断` / `检查失败` |
| 上次综合分 | 上期同仓结果 | 小数 | 否 | 无可比基线时为空 |
| 综合分差值 | 本次减上次 | 小数 | 否 | 保留 1 位小数并带正负号 |

## 4. 模块评估

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 模块身份 | 跨期稳定标识 | 文本 | 是 | `仓库名 + 模块相对目录` |
| 模块名称 | 展示名称 | 文本 | 是 | 取 SKILL frontmatter `name`，缺失时取目录名 |
| 模块相对目录 | 仓内位置 | 路径 | 是 | 从仓库根起算，不含 SKILL.md 文件名 |
| 维度得分 | D1～D6 得分集合 | 结构化文本 | 是 | 每维含得分、适用权重、子项明细 |
| 原始健康分 | 加权折算总分 | 小数 | 是 | 0～100，保留 1 位小数；FAIL 也保留 |
| 硬门禁 | 命中门禁集合 | 枚举列表 | 是 | `G1`～`G8`；无命中为空 |
| 健康等级 | 综合等级 | 枚举 | 是 | `A` / `B` / `C` / `D` / `FAIL` |
| 可比标识 | 是否进入两期同模块比较 | 布尔 | 是 | 两期身份一致且口径可比才为真 |
| 上次健康分 | 上期同模块结果 | 小数 | 否 | 无基线或不可比时为空 |
| 分数差值 | 本次减上次 | 小数 | 否 | 仅可比时计算 |
| 变化状态 | 环比结论 | 枚举 | 是 | `提升` / `下降` / `持平` / `新增` / `移除` / `首次评估` / `不可比` / `检查失败` |
| 问题统计 | 问题变化数量 | 结构化文本 | 是 | 新增、持续、已消除分别计数 |

## 5. 文件问题与仓库治理问题

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 问题 ID | 问题标识 | 标识 | 是 | 同一评估任务内唯一 |
| 文件路径 | 问题位置 | 路径 | 是 | 从仓库根起算 |
| 模块身份 | 所属模块 | 文本 | 否 | 仓库级问题为空 |
| 文件分类 | 扫描处置状态 | 枚举 | 是 | `正常` / `结构性例外` / `客观违规` / `排除` / `疑似待判定` / `检查失败` / `特殊对象` |
| 位置分类 | 结构位置 | 枚举 | 是 | `仓库根` / `业务分组` / `模块根` / `references` / `assets` / `生成物` / `其他` |
| 引用状态 | 引用链结果 | 枚举 | 是 | `已引用` / `未引用` / `间接引用` / `无法确认` / `不适用` |
| 内容角色 | 辅助类型标注 | 枚举 | 否 | `平行导航` / `页面映射` / `历史映射` / `过程记录` / `重复规则` / `工程残留` / `其他`；AI 标注不影响评分 |
| 问题类型 | 客观问题种类 | 文本 | 是 | 使用检查规范中的稳定问题编码与名称 |
| 严重程度 | 修复优先级 | 枚举 | 是 | `A` / `B` / `C` |
| 计分位置 | 影响范围 | 枚举 | 是 | `模块 D1` / `模块 D2` / `模块 D4` / `模块 D5` / `模块 D6` / `仓库治理` / `不计分` |
| 客观证据 | 判定依据 | 文本 | 是 | 位置、引用关系、链接结果、重复目标或原文锚点 |
| 变化状态 | 环比问题变化 | 枚举 | 是 | `新增` / `持续` / `已消除` / `不可比` |

## 6. AI 诊断

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 诊断 ID | 诊断记录标识 | 标识 | 是 | 同一评估任务内唯一 |
| 模块身份 | 所属模块 | 文本 | 是 | 与模块评估一致 |
| 诊断域 | 检查领域 | 枚举 | 是 | `业务流程` / `逆向流程` / `状态机` / `数据` / `页面操作` / `跨域与验收` / `跨文档一致性` |
| 问题类型 | 语义问题分类 | 枚举 | 是 | `明确冲突` / `覆盖缺失` / `表述歧义` / `无法核验` |
| 严重程度 | 修复优先级 | 枚举 | 是 | `A` / `B` / `C`，不参与评分 |
| 真源证据 | 权威文档依据 | 文本 | 是 | 文件、章节与原文摘要 |
| 相关证据 | 冲突或缺失位置 | 文本 | 条件必填 | 明确冲突至少两处证据；无法核验说明缺口 |
| 诊断结论 | 问题说明 | 文本 | 是 | 不补写仓库中不存在的业务事实 |
| 修复建议 | 建议动作 | 文本 | 是 | 指定建议修改真源与同步范围 |
| 计分标记 | 是否影响分数 | 枚举 | 是 | 固定 `不计分` |

## 7. 修复建议

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 问题 ID | 关联客观问题或 AI 诊断 | 标识 | 是 | 每条问题一条建议 |
| 问题与证据 | 问题定位摘要 | 文本 | 是 | 含文件与章节或客观检查结果 |
| 影响 | 业务或治理影响 | 文本 | 是 | 导航、研发理解、验收、跨仓引用或目录治理 |
| 修复对象 | 建议修改真源 | 文本 | 是 | 文件与章节；不得替产品经理决定业务规则 |
| 修复动作 | 可执行建议 | 文本 | 是 | 明确修改、补充、归并或移除建议；评估系统不执行 |
| 优先级 | 修复顺序 | 枚举 | 是 | `A` / `B` / `C` |
| 复核点 | 修复验收条件 | 文本 | 是 | 下次检查可重新判定的客观条件或人工验收点 |

## 8. 基线引用

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 上期报告 ID | 基线报告 | 标识 | 否 | 首次评估为空 |
| 上期发报日 | 上次评估日期 | 日期 | 否 | 必须早于本次发报日 |
| 上期版本号 | 使用的归档版本 | 整数 | 否 | 取上一发报日最新版本 |
| 上期规则版本 | 上期评分口径 | 文本 | 否 | 用于可比性判断 |
| 可比性 | 是否允许直接环比 | 枚举 | 是 | `可比` / `首次评估` / `口径变化` / `基线缺失` / `解析失败` / `不可比` |
| 可比性说明 | 限制与原因 | 文本 | 是 | 口径变化或解析失败必须说明影响范围 |

## 9. 覆盖自校

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
| --- | --- | --- | --- | --- |
| 文件总数 | 仓库快照内待分类文件数 | 整数 | 是 | 与完整性自校打平 |
| 正常/例外/违规/排除/疑似/失败/特殊数量 | 各处置分类数量 | 整数 | 是 | 合计必须等于文件总数 |
| 应检查文件数 | 按 profile 应完成检查的数量 | 整数 | 是 | 不含明确排除项 |
| 已完成检查数 | 实际完成检查的数量 | 整数 | 是 | 正常、例外与客观违规均计入 |
| 文件覆盖率 | 全量覆盖指标 | 百分比 | 是 | `已完成检查数 ÷ 应检查文件数 × 100%` |
| 未判定数量 | 证据不足文件数 | 整数 | 是 | 疑似待判定数量 |
| 检查失败数量 | 读取或解析失败数量 | 整数 | 是 | 不得计为正常通过 |
| 自校结果 | 扫描完整性结论 | 枚举 | 是 | `通过` / `未通过`；分类合计不等或遗漏未登记时为未通过 |

## 10. 归档基线所需固定表格

每份报告必须包含以下两张表，供下一发报日读取；列名与顺序保持稳定。

### 仓库评分表

| 仓库 | commit | 模块子分 M | 治理子分 G | 综合分 R | 模块 FAIL | 治理状态 | 上期综合分 | 差值 |
| --- | --- | ---: | ---: | ---: | ---: | --- | ---: | ---: |

### 模块评分明细表

| 仓库 | 模块相对目录 | 本次分 | 上次分 | 差值 | 变化状态 | 硬门禁 | 新增问题 | 持续问题 | 已消除问题 |
| --- | --- | ---: | ---: | ---: | --- | --- | ---: | ---: | ---: |

- 基线只读取表格中的评分与问题事实，AI 诊断文字不作为分数来源
- 上期表格缺列、模块身份无法解析或规则版本不可比时，对应记录标记不可比，不得猜测补齐
- 同一发报日的多个版本仅用于修正当次报告，不作为不同评估批次比较
