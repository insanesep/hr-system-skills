# 岗位管理

## 模块概述

人资管理 → 组织管理下的岗位主数据入口，分为「职级体系」「标准职位」「岗位映射」三个页签：

- **职级体系**：维护管理 M、专业 P、业务 S、操作 O 四条职级序列与职级矩阵，定义职级类别、职级顺序与命名规则；同时维护岗位序列（职位族）的定义、建设状态与适用范围。职级矩阵是本仓库职级、职级序列与职级类别的唯一真源。
- **标准职位**：维护公司级标准职位库，覆盖职位编码、名称、所属岗位序列、适用职级范围、职级类别、默认用工形式、职位定位与任职要求；标准职位被编制管理、招聘管理、绩效管理与员工资料只读引用。
- **岗位映射**：以员工资料当前职位、岗位序列与职级为输入，按标准职位库生成建议标准职位与匹配结果；支持单条或批量将存量岗位名称切换为标准职位名称，识别命名不一致、职级错配、层级未建设与序列未建设。

本功能不承载部门树维护、编制数量维护、招聘流程、绩效评价、员工档案维护与薪酬核算。

## 端

- **web**：人资管理 → 组织管理 → 岗位管理，仅桌面端管理后台，不提供 App 入口

## When to Use

- 查看或维护职级矩阵、职级类别、职级顺序与命名规则
- 新增、编辑或停用岗位序列，维护序列定义、建设状态与职位名称后缀
- 新建、编辑、停用标准职位，维护适用职级范围与默认用工形式
- 查询标准职位的在岗人数、编制引用与变更记录
- 生成或刷新在岗人员岗位映射，查看命名不一致、职级错配与未建设层级
- 单条或批量切换存量岗位名称，或导入在岗人员岗位明细
- 复核岗位管理与编制、招聘、绩效、员工资料的引用口径，或查询权限编码

## 职级体系

<a id="职级体系"></a>

- 职级序列固定为管理序列（M）、专业序列（P）、业务序列（S）、操作序列（O）；职级类别固定为战略决策层、总监级、经理级、主管级、员工级。
- 职级矩阵按「职级类别 × 职级序列」组织，展示每个序列下可用职级；具体职级编码、名称与顺序见 [文档/数据模型.md §职级矩阵](文档/数据模型.md#职级矩阵)。
- 岗位序列是职位族，不等同于职级序列；技术中心初始包含产品经理、产品运营、UED、PMO、后端开发、前端开发、测试、算法、数据研发、运维、实施&技术支持、安全十二个序列，安全序列处于未建设状态。
- 命名规则按职级段定义标准职位名称建议：员工级使用「初级 + 序列职位名称」，主管级使用「序列职位名称」，经理级使用「序列名称 + 专家」，总监级使用「高级 / 资深 + 序列名称 + 专家」；管理序列按管理职责命名。

## 标准职位

<a id="标准职位"></a>

- 标准职位是公司级职位档案，按岗位序列与适用职级范围定义；同一岗位序列下职位名称唯一，职位编码全局唯一。
- 标准职位的适用职级范围不得跨职级类别；跨类别时拆分为多个标准职位；默认职级必须落在适用范围内。
- 标准职位被编制明细行引用后不可删除；停用只阻止新建引用，已引用编制、在途招聘与在岗员工保留原快照。
- 标准职位修改名称、适用职级或默认用工形式时生成职位版本，历史引用不回写；新版本只影响之后创建的编制与招聘职位。

## 岗位映射

<a id="岗位映射"></a>

- 岗位映射以员工资料当前任职记录的职位名称、岗位序列与职级为输入，按标准职位库给出建议标准职位与匹配结果。
- 匹配结果分为一致、命名不一致、职级错配、层级未建设、序列未建设与无法匹配；切换只更正岗位名称与标准职位关联，不改变组织、职级、直接上级与编制行。
- 新增人员通过入职管理或调岗晋升按标准职位落位；存量人员由岗位映射按「异动窗口优先、存量分批切换」处理，批量切换逐行校验并生成成功与失败回执。
- 岗位映射的生成、切换与忽略均写入变更记录；标准职位、岗位序列或职级发生变化后，映射结果自动重新计算。

## Tips

- 职级矩阵是本仓库唯一真源；编制、招聘与绩效的职级与职级类别均引用本模块，不再在各自 `数据模型.md` 复制矩阵
- 未建设序列允许先建标准职位草稿，不允许被编制、招聘与员工异动引用；建设中序列可维护并启用标准职位，但仍不对外引用；安全序列按未建设处理，在岗人员映射标记为序列未建设
- 标准职位被编制引用后只能停用或新增版本，不提供物理删除
- 岗位映射只做名称治理，不触发调岗、晋升、降职，不改变编制与绩效归属
- 岗位映射的切换与忽略需填写原因；批量切换仅处理匹配成功且状态为待切换的记录
- 手机号、证件号码与薪酬不在本模块展示；岗位映射按员工资料数据权限过滤
- 规则查找：职级矩阵与标准职位规则看 [文档/业务规则.md](文档/业务规则.md)，字段口径看 [文档/数据模型.md](文档/数据模型.md)，页面元素看 [文档/页面元素.md](文档/页面元素.md)
