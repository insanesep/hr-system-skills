# 部门管理 · 业务规则

> 本文件描述当前生效的组织层级、部门档案维护与部门树交互规则；字段口径见 [数据模型.md](数据模型.md)，页面元素见 [页面元素.md](页面元素.md)。

## 1. 名词约定

| 名词 | 定义 |
|---|---|
| 根公司 | 组织树的唯一第 0 层节点，系统预置，不可新增同级、删除、停用或移动 |
| 层级类型 | 由部门所处深度决定：第 1 层中心、第 2 层部门、第 3 层小组、第 4 层子小组，根公司为「公司」 |
| 部门树 | 以公司为根、按上级关系逐级展开的组织结构视图 |
| 上级部门 | 当前部门的直接父节点；根公司无上级 |
| 下级部门 | 直接挂在当前部门下的部门，不含更深层节点 |
| 部门路径 | 从公司到当前部门的名称逐级串联，用于详情与删除确认 |
| 在职人数 | 本部门在职员工数量，不含下级部门员工 |
| 空叶子 | 无任何直接下级且无在职员工的部门 |
| 停用 | 部门保留在树与档案中、但不再承接组织管理动作的状态 |
| 撤销日期 | 部门停用时系统记录的日期，重新启用时清空 |
| 同级排序 | 同一上级下部门之间的展示顺序，由排序号决定 |

## 2. 功能边界

- 提供公司五级部门树的查看与维护，以及部门档案的新增、编辑、删除、启用停用、拖拽排序与上级调整。
- 根公司仅作为组织根存在：可编辑名称、负责人、成立日期与备注，不可修改编码，不可新增同级、删除、停用或移动。
- 不承载员工入职、调动与离职中的组织归属变更；不承载岗位与编制维护、组织架构图导出与分享、多公司管理。
- 在职人数作为派生统计只读展示并参与删除校验，员工与部门的任命关系不在本功能维护。
- 岗位与编制以部门为归属维度被引用，其维护规则归各自功能。

## 3. 组织层级规则

- 组织固定为五级：第 0 层公司（唯一根）、第 1 层中心、第 2 层部门、第 3 层小组、第 4 层子小组；子小组为最末层，不可再有下级。
- 层级类型由节点深度自动判定，新增时不可人工选择；例如在中心下新增的下级即为部门。
- 每个非根部门有且仅有一个直接上级；上级必须为可容纳下级的节点（公司、中心、部门、小组），子小组不可作为上级。
- 部门路径按逐级名称以「 / 」连接，详情与删除确认均展示。
- 变更上级仅通过拖拽移动完成，编辑弹窗不提供上级修改；移动后节点及其子树的层级类型按新深度重新判定。
- 拖拽移动受深度限制约束：移动后子树任一层不得超过第 4 层；超出深度、拖入自身或自身后代、拖入停用部门、移动根公司均禁止。
- 移动导致层级类型变化时，确认弹窗提示变化后的层级类型与受影响的下级数量。

## 4. 部门档案维护规则

- 新增入口为树节点行内「新增下级」与档案面板「新增下级」；选中公司时新增中心，选中子小组时入口不可用。
- 新增与编辑均以弹窗完成；新增时上级部门为当前选中部门且只读，保存成功后自动展开上级并选中新部门。
- 编辑可修改名称、负责人、编制人数、排序号、成立日期与备注；编码、上级部门与层级类型只读。
- 名称必填，1–30 个字符；同一上级下不可与任何状态的部门重名。
- 编码必填，2–32 个字符，大写字母、数字或下划线且以字母开头，全局唯一，创建后不可修改；部门删除后编码释放。
- 负责人最长 20 个字符，可为空；编制人数为 0–9999 的整数，为空表示尚未核定编制。
- 排序号 0–9999 的整数，新增时默认排在同级末尾；同级按排序号升序展示，排序号相同按创建时间升序。
- 成立日期必填且不得晚于当天；撤销日期只读，停用时由系统写入当天、启用时清空。
- 备注最长 200 个字符，可为空。
- 保存前完成必填、长度、数值范围、同级重名与编码唯一校验；校验失败时停留在弹窗并定位首个错误字段，已填内容不丢失。
- 保存成功后在当前选中状态下刷新树与档案；若部门在编辑期间已被他人删除，提示数据已失效并刷新树，不覆盖原数据。

## 5. 状态与启用停用

- 新建部门默认启用；根公司始终为启用状态且不可停用。
- 停用前须无启用状态的下级部门；存在启用下级时禁止停用，并提示先停用或移出下级。
- 部门下存在在职员工不阻止停用，但停用确认需展示在职人数。
- 停用后：部门保留在树中并灰显「停用」标签，可选中查看与编辑档案；不可新增下级、不可作为拖拽投放目标、不可承接新任职（引用侧规则归员工档案）。
- 停用部门允许调整同级排序，但不允许改变上级。
- 启用要求直接上级为启用状态；启用不改变下级状态，下级需逐级启用。
- 停用与启用均需二次确认；成功后刷新树与档案，保持选中与展开状态，并给出结果提示。

## 6. 删除规则

- 仅空叶子可删除：无任何直接下级（含停用部门）且无在职员工。
- 存在下级或在职员工时删除入口不可用，并提示原因，如「存在 2 个下级部门」「存在 5 名在职员工」。
- 根公司不可删除。
- 删除需二次确认，展示部门名称与完整路径并说明不可恢复；取消不产生变更。
- 删除成功后选中其上级部门并刷新树；被删除部门的编码释放，名称可由同级新部门复用。
- 已离职员工的历史任职记录不因部门删除而失效，其展示口径归员工资料。

## 7. 部门树交互规则

- 默认选中公司，默认展开至第 2 层（公司与中心、部门可见），小组及以下折叠。
- 「展开/收起全部」作用于未搜索状态下的全部节点。
- 点击节点即选中并刷新右侧档案，不改变展开状态。
- 搜索按名称或编码模糊匹配并忽略大小写，命中节点及其全部祖先保持展示并自动展开；无命中时展示空态「未找到匹配的部门」。
- 搜索状态下树为只读：仅可选中查看，新增、编辑、删除、启停与拖拽入口均不可用；清除搜索后恢复搜索前的选中与展开状态。
- 同父节点内拖动调整顺序；拖入节点将其上级改为目标节点。拖拽过程高亮合法投放位置，非法位置不可投放。
- 拖拽需「拖拽维护」权限，无权限时不展示拖拽交互。
- 拖拽保存失败或与最新数据冲突时，回滚至操作前顺序与上级并提示刷新重试，不静默覆盖。
- 新增保存后自动展开上级并选中新部门；删除后选中上级；切换选中不触发整页刷新。

## 8. 空态与异常

- 公司下无下级部门时，树中展示空态引导「暂无下级部门」，并在有权限时提供「新增中心」入口。
- 树或档案加载失败时在当前区块展示失败提示与「重试」，重试沿用失败时的查询条件与选中节点。
- 新增、编辑、停用、启用与删除失败时，弹窗保持打开并保留已填内容或确认上下文，展示失败原因，可重新提交。
- 操作过程中若部门被他人修改或删除，提示数据已更新或失效并刷新，避免覆盖他人变更。

## 9. 权限

- 菜单权限编码：`MENU:HR:DEPARTMENT`；未授权不展示菜单入口。
- 按钮权限编码：新增下级 `BTN:HR_DEPARTMENT:CREATE`、编辑 `BTN:HR_DEPARTMENT:EDIT`、删除 `BTN:HR_DEPARTMENT:DELETE`、拖拽维护 `BTN:HR_DEPARTMENT:DRAG`、启用停用 `BTN:HR_DEPARTMENT:STATUS`。
- 未授权按钮时不展示对应入口；因业务规则不可用（如子小组新增下级、非空叶子删除、根公司停用删除）时保留入口并置灰，提示不可用原因。
- 功能权限校验接入用户权限中心，具体能力以公共契约为准，本模块不复述接口定义。
