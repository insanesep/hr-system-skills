# 招聘管理

## 模块概述

人资管理 → HR管理 下的招聘分组，按「需求 → 过程 → 数据」三个阶段组织一条从编制缺额到人员到岗的招聘链路：

- **招聘需求管理**：从编制管理的缺额发起招聘需求，关联编制明细行并占用缺额；需求经业务终面人审批后进入招聘，支持新建、批量导入、批量授权、变更人数与关闭，按需求汇总到岗、Offer 与完成情况。
- **招聘过程管理**：以职位、应聘者、面试与 Offer 为主线推进招聘；工作台汇总待处理简历、待安排初试与待发 Offer，展示招聘日程并支持面试官快捷评价；招聘台账填写为招聘人员提供候选人级行内、抽屉与 Excel 批量录入，数据写入投递摘要并同步只读台账与数据看板；BOSS直聘同步以官方 API 授权、职位映射与待确认池将候选人导入台账填写；Offer 审批通过后转入入职管理生成入职单。
- **招聘数据看板**：按招聘季度、组织、岗位类别、岗位族、职级类别、招聘原因、渠道与时间查看招聘进度与时效预警、需求与编制达成、招聘漏斗、渠道效果、面试官与招聘HR人效、Offer 流失与薪酬涨幅；右上维护渠道费用、薪酬带宽与人效配置。

本分组只承载招聘需求到 Offer 的过程与过程数据，不承载编制维护、入职办理、员工档案维护、薪酬核算与劳动合同签订。

## 端

- **web**：人资管理 → HR管理 → 招聘管理 → 招聘需求管理 / 招聘过程管理 / 招聘数据看板，桌面端管理后台
- **app**：招聘过程管理提供 App 入口（工作台、日程、台账、职位、应聘者、面试与 Offer 高频闭环）；招聘需求管理与招聘数据看板不提供 App 入口

## When to Use

- 按编制缺额新建招聘需求，或批量导入需求、批量授权他人查看需求与进展
- 调整需求人数与期望到岗日期，查看需求到岗、Offer 与候选人漏斗，或关闭需求
- 为招聘人员按 Excel 台账录入或批量导入候选人级数据，并同步至招聘台账与数据看板
- 查看 BOSS直聘 授权与同步状态，维护职位映射，处理待确认候选人与同步批次
- 维护职位与在招人数，处理简历、锁定候选人、安排与改期面试
- 面试官查看本人场次、提交面试评价、快捷通过或淘汰
- 发起 Offer、跟进审批与发送、记录候选人接受或拒绝
- 查看招聘进度与时效预警、需求与编制达成、招聘漏斗、渠道效果、面试官与招聘HR人效、Offer 流失与薪酬涨幅
- 复核编制缺额联动、Offer 转入职与编制回写的规则，或查询权限编码与数据范围

## Tips

- 招聘需求缺额驱动：新建需求必须选择可用缺额大于零且未结束的编制明细行，需求人数不得超过可用缺额；超编需求须由中心负责人审批后以「超编需求」标记创建
- 占用口径：需求提交审批即冻结缺额，关闭与完成释放剩余占用，调减人数释放差额；编制侧调减缺额时，进行中需求标记「编制变更待处理」由招聘负责人处理
- 到岗链路：需求 → 职位 → 应聘者 → 面试 → Offer 审批通过 → 入职单（入职管理）→ 确认入职 → 需求已到岗 +1、编制明细行在编 +1（待编制确认）→ 需求到齐自动完成
- Offer 关闭或撤销时，对应入职单自动取消；已确认入职的记录不回退招聘与编制计数
- 手机号、证件号码与薪资默认脱敏，明文查看与导出需单独敏感字段权限
- 规则查找：联动与状态规则看 [文档/业务规则.md](文档/业务规则.md)，字段口径看 [文档/数据模型.md](文档/数据模型.md)，页面元素看各功能 `文档/页面元素.md`
- BOSS直聘同步只写候选人基础信息、简历与进展备注，待确认池不占名额；确认入库才按台账规则预占 1 个空缺，三面结果、Offer、待入职与薪酬仍由内部手工维护
