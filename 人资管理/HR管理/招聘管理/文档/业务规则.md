# 招聘管理 · 业务规则

> 本文件是招聘管理分组的共享规则真源：编制缺额联动、需求与招聘过程状态机、Offer 转入职与编制回写、工作台与看板口径、权限编码。字段口径见 [数据模型.md](数据模型.md)，各功能页面元素见对应 `文档/页面元素.md`。

## 1. 名词约定

| 名词 | 定义 |
|---|---|
| 编制明细行 | 编制管理维护的部门—职位—职级级编制记录，含编制数量、编制计划、职位编制起止、在岗人员与用工形式，是招聘需求的唯一来源 |
| 在编人数 | 编制明细行下已确认入职、尚未离职的人员数量，由编制管理维护 |
| 招聘占用 | 未完成、未关闭的招聘需求占用的剩余招聘人数，即需求人数与已到岗人数之差 |
| 可用缺额 | 编制明细行可继续发起招聘的人数，等于编制数量减去在编人数与招聘占用 |
| 招聘需求 | 针对一条编制明细行发起的一次招聘委托，含需求人数、招聘原因、期望到岗日期、业务终面人与招聘负责人，是招聘计数与数据统计的最小单位 |
| 岗位类别 | 招聘紧急度分类：关键岗位、S1类岗位、S2类岗位、A类岗位，紧急度依次降低 |
| 岗位族 | 岗位名称的归一分类，如后端研发、前端、测试、产品经理、产品运营、运维、算法、数据研发、数据分析、UI、PMO、数据安全、实习生、管培生 |
| 工作性质 | 内勤或外勤，需求必填，默认内勤 |
| 招聘季度 | 需求维护的季度；候选人默认继承需求季度，Offer 接受后按计划入职季度更新，确认入职后按实际入职季度更新 |
| 招聘HR | 负责候选人推进的招聘人员，人效指标按招聘HR归属；需求的招聘负责人用于承接需求计数 |
| 在招池 | 季度内首次投递且未终止的候选人数，去重并含已入职与待入职 |
| 待入职 | Offer 已接受、计划入职日期不早于今天、尚未入职且未标记爽约的候选人 |
| 爽约 | 计划入职日期已过仍未入职，由 HR 标记未到岗并记录原因；爽约不进入待入职 |
| 外包需求 | 用工形式为劳务外包的招聘需求，占用外包编制；无可用编制时按超编需求审批 |
| 外包超编 | 用工形式为劳务外包且可用缺额小于零的编制行及其在编人员 |
| 职位 | 招聘需求下对外开放招聘的岗位，承载在招人数、JD 与候选人投递，一个需求可关联多个职位 |
| 应聘者 | 进入招聘流程的候选人档案，按手机号或邮箱唯一识别，可产生多条投递记录 |
| 投递记录 | 应聘者在某一职位上的招聘流程，状态、面试与 Offer 均挂在投递记录上 |
| 面试场次 | 某轮面试的一次具体安排，含时间、面试官、方式与邀约状态 |
| 面试评价 | 面试官针对一场面试提交的结论与评语，是推进下一轮或发起 Offer 的依据 |
| Offer | 面向单一候选人的录用方案，经审批、发送与候选人确认后转入入职单 |
| 入职单 | 入职管理生成的入职办理记录，一份 Offer 对应一份入职单 |
| 到岗核销 | 入职管理确认入职后，招聘需求已到岗人数增加并占用编制在编人数的过程 |
| 渠道 | 候选人来源，含内推、猎头、RPO、招聘网站、官网投递、人才库与其他 |
| 超编需求 | 需求人数超过编制明细行可用缺额、经中心负责人审批后创建的招聘需求 |

## 2. 功能边界

- 本分组承载招聘需求（含外包需求）、职位与在招人数、应聘者与简历、面试安排与评价、Offer 审批与发送、招聘过程数据、渠道费用配置、薪酬带宽配置与招聘HR人效配置。
- 外包需求共用需求、职位、候选人与 Offer 链路；外包超编在编制管理查看，招聘侧只读引用。
- 不做：编制数量与编制明细维护、编制确认操作、入职办理与员工档案维护、劳动合同签订、薪酬核算与发放、外部招聘网站账号与发布管理。
- 编制数据只读引用编制管理，招聘侧不修改编制数量；招聘侧到岗结果以编制占用记录写入编制管理，由编制管理员确认。
- 招聘过程数据只读汇总本分组产生的需求、投递、面试与 Offer 数据，不重复存储编制数量与员工档案信息。

## 3. 编制缺额与招聘需求

- 可发起招聘的编制明细行须同时满足：编制计划为新增或保留、职位编制结束时间为空或晚于今天、可用缺额大于零。
- 可用缺额 = 编制数量 − 在编人数 − 招聘占用；招聘占用按同一编制明细行下全部「待审批」「招聘中」需求的剩余招聘人数合计。
- 新建需求必须关联一条编制明细行，组织层级、标准职位、职级、职级类别、用工形式与办公地点取自编制明细行快照，需求创建后不随编制调整自动变更。
- 需求人数须为正整数且不超过可用缺额；同一编制明细行下多个在途需求的剩余人数合计不得超过可用缺额。
- 超编需求默认拦截。确需超编招聘时，由招聘管理员标记「超编需求」并提交中心负责人审批；审批通过后创建，招聘数据看板单独统计超编需求数与超编人数。
- 需求提交审批即冻结对应缺额；审批驳回、关闭需求与完成需求时释放剩余占用；调减需求人数时释放差额。
- 编制明细行停用、结束时间到期、编制数量调减导致在途需求超出可用缺额时，相关需求标记「编制变更待处理」，不允许新增职位与发起 Offer，由招聘负责人调减人数或关闭需求。
- 需求除编制快照外，还维护招聘季度、岗位类别、岗位族、工作性质、需求对接人、部门负责人、协同招聘HR与外包需求标记；岗位类别、岗位族、工作性质与招聘季度进入职位、投递与 Offer 快照。
- 招聘季度默认按期望到岗日期所在季度，允许手工调整；需求提交审批后调整招聘季度写入操作记录。需求指标按需求招聘季度归属，候选人指标按投递记录招聘季度归属。
- 外包需求必须关联用工形式为劳务外包的编制明细行；无可用缺额时按超编需求审批，需求标记为外包需求并在需求台账的外包需求页签展示。
- 招聘天数 = 今天 − 需求提报日期（创建时间）；已完成需求以完成时间计算。未完成且招聘天数 ≥150 天进入升级预警。
- 预警状态：关键/S1 岗位完成率低于 50%，或未完成且招聘天数 ≥150 天，或期望到岗日期已过且缺口大于零为「需升级」；完成率低于 80% 或平均招聘时长 ≥90 天为「需关注」；其余为「正常」。阈值可在人效配置中调整。
- 在途进展由投递记录的进展备注与当前阶段聚合，需求详情展示最近 3 条；在途进展不改变需求与投递状态。

## 4. 需求审批与状态机

- 需求状态：草稿、待审批、招聘中、已完成、已关闭。
- 创建需求后可保存草稿或直接提交审批；草稿不占用缺额，提交后进入待审批并冻结缺额。
- 审批链：业务终面人审批；超编需求在业务终面人之后增加中心负责人审批。
- 审批通过后状态为招聘中，招聘负责人可创建职位并接收简历；审批驳回回到草稿并记录驳回原因。
- 已到岗人数达到需求人数时需求自动完成，释放剩余占用并记录完成时间；招聘负责人可在业务终面人确认后提前完成，剩余人数核销并释放占用。
- 关闭需求为终态操作，关闭后不可恢复；如需再招，按同一编制明细行新建需求。
- 统计卡口径：
  - **我的招聘需求**：当前用户为招聘负责人、业务终面人或被授权人的需求总数，含全部状态。
  - **全部招聘需求**：当前用户数据权限范围内的需求总数，含全部状态。
  - **已完成**：权限范围内状态为已完成的需求数。
  - **进行中**：权限范围内状态为待审批与招聘中的需求数。
  - **已关闭**：权限范围内状态为已关闭的需求数。
  - 草稿计入我的与全部合计，不单列卡片。

## 5. 需求变更、关闭与授权

- 草稿与待审批需求可修改全部字段，修改后重新提交审批。
- 招聘中需求可修改期望到岗日期、优先级、业务终面人、招聘负责人、职位描述与备注，变更写入操作记录。
- 招聘中需求可调整招聘季度、岗位类别、岗位族、工作性质、需求对接人、协同招聘HR；上述字段通过需求台账行内编辑或批量导入维护，新建需求弹窗不强制填写，创建时按职位映射带出默认值，无法映射时标记「岗位分类待补充」，提交审批前须确认。
- 协同招聘HR只参与展示与协作，不重复计入人效；承接需求按主招聘负责人归属。
- 招聘中需求调减人数时，新人数不得低于已到岗人数与已接受 Offer 人数之和，差额即时释放占用。
- 招聘中需求调增人数时，须重新校验可用缺额并提交变更审批；审批期间按原人数招聘，审批通过后新增人数生效并占用缺额，审批驳回保持原人数。
- 已完成与已关闭需求不可编辑。
- 关闭需求须填写关闭原因（编制取消、转内部调配、需求合并、业务调整、其他）；存在审批中、待发送或已发送未接受的 Offer 时不可关闭，须先关闭对应 Offer；存在已接受未入职的 Offer 时须由 HRBP 二次确认，取消对应入职单后方可关闭。
- 关闭需求时，在途候选人逐条终止并记录终止原因，待面试场次自动取消；已确认入职的记录不受影响。
- 批量授权将所选需求的查看权限授予指定员工，授权为只读，不授予编辑、审批与操作权限，不改变招聘负责人；授权可撤销，授权与撤销均记录操作人与时间。
- 批量导入使用统一模板，逐行校验编制明细行可匹配、可用缺额足够、日期合法与人员存在；校验通过的行生成草稿，校验失败的行不导入并生成失败原因清单，导入结果按成功与失败分别回执。
- 单次批量导入不超过 200 行。

## 6. 职位

- 职位只能由招聘中需求创建，一个需求可创建多个职位，职位的组织、标准职位、职级、职级类别、岗位类别、岗位族与工作性质默认继承需求快照，可按办公地点拆分多个职位。
- 岗位类别、岗位族、工作性质随需求快照写入职位、投递与 Offer；需求后续调整只影响新建职位，已创建职位、在途投递与已生成 Offer 保留原快照。
- 同一需求下全部在招职位的在招人数合计，不得超过需求人数减去已到岗人数与已接受未入职人数后的剩余名额。
- 职位状态为在招、暂停、已关闭；暂停后不再接收新简历与发起新面试，在途流程可继续；恢复在招后重新接收简历。
- 关闭职位前须处理在途投递：转移至同需求其他职位或终止并填写原因；职位关闭后候选人与 Offer 记录只读。
- 候选人发起 Offer 时校验需求剩余名额，名额不足时阻断并提示先确认到岗或调增需求人数。

## 7. 应聘者与简历

- 应聘者按手机号或邮箱唯一识别；重复投递时合并到同一应聘者档案，新增一条投递记录，最新投递为当前流程，历史投递只读。
- 应聘者维护当前年包、期望年包与薪酬备注，默认脱敏；年包只用于涨幅与薪酬分析，不改变 Offer 薪资结构。
- 投递记录维护招聘HR、协同招聘HR、招聘季度与进展备注；招聘HR是人效归属字段，协同人不重复计入。
- 招聘季度默认继承需求季度；Offer 接受后按计划入职日期所在季度更新；确认入职后按实际入职日期所在季度更新；手工调整写入操作记录。
- 同一应聘者在同一职位 6 个月内重复投递时提示，招聘负责人可确认重新发起流程，原流程标记为终止。
- 候选人来源渠道在投递记录上维护，内推须记录内推人，猎头与 RPO 须记录顾问或供应商；渠道停用不影响历史投递。
- 简历支持单份或批量导入，导入后解析姓名、手机号、邮箱、学历、毕业院校、工作年限、当前公司与职位等字段，解析失败转人工补录；未关联职位的简历进入未归档简历，归档后生成投递记录。
- 招聘负责人可锁定应聘者 7 天，锁定期内其他招聘负责人只读且不可发起流程，到期自动释放，可手动提前释放；锁定人优先处理该应聘者。
- 应聘者可被关注，关注为个人视图，不改变数据权限。
- 投递状态：待处理、初筛通过、初筛淘汰、面试中、Offer 审批中、已发 Offer、已接受 Offer、已入职、Offer 拒绝、已终止。
- 初筛淘汰、流程终止与 Offer 拒绝须选择原因（经验不符、薪资不符、学历不符、面试未通过、候选人放弃、需求关闭、其他）并填写说明，终止后进入人才库，可由招聘负责人重新激活发起新投递。
- 已入职为终态，不可再次流转；如需重新招聘按新投递处理。

## 7.1 台账填写

- 台账填写是招聘人员的候选人级录入界面，数据写入投递记录的台账摘要字段，不新建独立台账表；只读招聘台账、招聘进度、招聘HR人效与看板均读取同一投递记录。
- 台账录入来源：过程创建、台账填写、批量导入。过程创建的投递，台账摘要由面试评价、Offer 与入职单派生，台账页只读；台账填写或批量导入创建的投递标记为台账补录，摘要字段可编辑。
- 新增台账必须选择招聘中且剩余名额大于零的招聘需求；部门、岗位、职级按「二级部门 → 三级部门 → 招聘需求 / 职位 → 职级」四级联动，职级在需求职级范围内选择并带出对应薪标；剩余名额 = 需求人数 − 已到岗人数 − 待入职人数 − 台账在途预占数。无可用需求或名额为零时不允许新增。
- 台账预占：每条台账记录创建时按所选需求预占 1 个空缺，状态为预占中；Offer 已接受或已入职仍为预占中（继续占用），不重复计入需求的已到岗或待入职。
- 预占释放：台账记录终止、放弃 Offer、面试淘汰或删除时释放 1 个空缺，状态变为已释放；编辑台账更换招聘需求时，原需求释放 1 个、新需求预占 1 个。
- 同一招聘需求可录入多名候选人，但预占总数不得超过需求剩余名额；需求剩余名额为零时不可再新增或导入，已满需求不出现在新增下拉中。
- 台账预占只统计台账填写与批量导入创建的投递；过程创建的投递由招聘过程与岗位名额管理，不重复预占。预占不改变需求已到岗与待入职计数；正式到岗仍以入职管理确认入职核销，编制回写不变。
- 台账预占按需求编号同步至招聘需求列表与编制台账：需求列表展示在途预占与可用空缺；编制侧将台账预占计入招聘占用并扣减可用缺额。终止、放弃、淘汰或删除后同步释放。
- 台账填写的组织、岗位、职级、岗位类别、岗位族、工作性质、招聘HR与需求编号取自所选需求快照；编辑历史台账时保留原快照。
- 批量导入按二级部门、三级部门、职位与职级匹配招聘中且有空缺的招聘需求，每行预占 1 个空缺；无法匹配或名额不足的行进入失败回执，失败行不预占。
- 候选人按手机号或邮箱查重；同一候选人同一职位在 6 个月内重复录入时更新原投递摘要，不新建投递；同一候选人不同职位新建投递。
- 一面、二面、终面分别对应初试、复试、终试的轮次汇总；存在详细面试场次时以面试评价汇总为准，台账只读；无详细场次时可录入摘要。
- 台账 Offer 状态：未发起不创建 Offer 记录；审批中、待发送、已发送、已接受、已拒绝、已失效、已关闭、已入职可记录摘要状态，完整 Offer 审批、发送与关闭仍在招聘过程管理完成。
- 台账补录的已接受、已入职记录标记「线下补录」，不自动生成入职单、不触发编制回写；后续在过程管理补齐 Offer 与入职单后，以详细流程数据为准。
- 台账是否已入职：过程创建时由入职单派生，已入职需存在已确认入职单；台账补录时可手工标记，标记已入职只更新摘要，不写入员工档案、不增加编制在编；标记未到岗时等同于爽约摘要，不进入待入职统计，详细爽约仍以入职管理标记为准。
- 台账放弃原因在台账 Offer 状态为已拒绝时必填；存在详细 Offer 时同步写入 Offer 放弃原因。
- 台账实际入职职级与 Offer 职级比较生成职级差异；详细入职单存在时以入职单职级为准。
- 台账当前年包、期望年包、内部定薪年包为敏感字段，仅具备薪资权限可查看与编辑；涨幅、薪标与超限标记按 Offer 口径派生，台账页只读。
- 台账填写与导入写入操作记录（操作类型：台账填写、台账导入），记录操作人、时间、变更前后内容与来源。
- 台账补录记录在后续进入详细流程时，详细流程数据优先：面试评价、Offer、入职单产生后，摘要字段自动回写并变为只读；冲突时以详细数据为准，保留台账录入记录。
- 批量导入使用与 Excel 台账一致的模板，单次不超过 200 行；校验需求/职位可匹配、候选人可识别、日期合法、枚举合法与重复行；校验通过的行创建或更新投递摘要并标记来源批量导入，失败行生成失败回执。
- 权限：招聘HR可查看与编辑本人台账；招聘管理员与 HRBP 可查看与编辑数据权限范围内全部台账；其他角色只读。App 台账只读，新增、编辑与批量导入仅在 Web 提供。
- 渠道同步确认入库的投递按台账补录处理，录入来源为渠道同步，摘要字段可编辑；预占、查重、台账同步与看板口径不变。
- 渠道同步确认时按台账规则预占 1 个空缺；待确认池记录不预占、不计入台账与看板，批量确认仅成功行预占。

## 7.2 BOSS直聘同步

- 同步仅使用 BOSS直聘 官方 API 通道；授权、接口清单、字段与频率限制以商务开通后的官方文档为准，产品侧不假设未开通能力。
- 授权由招聘管理员在同步设置内发起，跳转 BOSS直聘 完成企业授权后回跳；授权成功前连接为未授权，不执行同步。
- 凭证仅保存于服务端并加密，前端与导出只展示指纹；授权临期 7 天提示，过期后连接标记已过期，池内数据保留，重新授权后恢复。
- 停用连接后停止定时同步，手动同步置灰；重新启用后从停用时间起增量拉取。
- 定时同步按连接的同步频率执行增量拉取，招聘HR 可在同步记录页手动触发；同一连接同一时间只允许一个进行中的批次，重复触发合并到当前批次。
- 首次同步按拉取范围回溯，后续按外部投递标识与更新时间做增量；批次完成记录拉取、新增、更新、跳过与失败数，部分失败时成功记录照常入池。
- 职位映射为多对多：一个内部职位可绑定多个 BOSS 职位，一个 BOSS 职位可绑定多个内部职位；同一「连接 + BOSS 职位 + 内部职位」组合唯一。
- 系统按 BOSS 职位名称、城市与内部职位名称、办公地点给出自动匹配建议，需管理员确认后生效；建议内部职位取同一 BOSS 职位已映射且有效、按城市匹配优先的首个内部职位。
- 内部职位暂停时映射标记冲突，不可新增确认；内部职位或所属需求关闭、BOSS 职位关闭时映射标记已失效。已确认入库的投递不受映射失效影响，仅后续同步停止。
- 未映射或冲突职位的候选人可入池但不可确认，须先完成映射；可确认时默认建议内部职位，确认前可在同一 BOSS 职位已映射且有剩余名额的内部职位中改选。
- 待确认池只暂存外部数据，不占用需求名额，不计入台账、看板与工作台待办数字。
- 入池按手机号优先、邮箱兜底与应聘者档案匹配：无匹配为新候选人；匹配到应聘者为已有应聘者；同一外部投递标识已确认入库则为已有投递，生成更新摘要类记录而非新候选人。
- 入池时按建议内部职位做名额预校验，确认时再次校验，防止并发占用；名额不足时确认失败，可更换职位、等待名额释放或忽略。
- 确认入库：新候选人创建应聘者档案与投递，已有应聘者关联新投递；同职位 6 个月内重复按既有规则更新原摘要并提示。确认成功按台账规则预占 1 个空缺。
- 批量确认逐行独立校验，成功行入库、失败行保留并展示原因；批量忽略统一填写忽略原因。单条忽略必填原因，已忽略的外部投递标识保留，后续重复拉取不再入池。
- 更新摘要记录仅更新进展备注与简历附件，不改变投递状态、轮次结果与 Offer 摘要；操作按钮显示为「确认更新」，确认后写操作记录。
- 同步确认只写基础字段、简历附件与进展备注；一面、二面、终面、Offer 状态、待入职日期、是否已入职、放弃原因、实际入职职级与薪酬年包不来自同步，保持内部手工维护。
- 内部已存在详细流程数据（面试评价、Offer、入职单）时，以内部详细数据为准；同步不覆盖人工修改过的字段。外部进展仅写入进展备注，不改变投递状态与轮次结果。
- 待确认记录默认保留 30 天，超期标记已失效；BOSS 侧职位关闭或候选人撤回时对应记录标记已失效，不自动删除；已失效记录不可确认或忽略，保留至保留期到期后自动清理。
- 批次失败支持重试，重试生成新批次并记录触发方式为重试，不覆盖历史批次；授权过期、频率超限与字段解析失败分别给出可读原因与处理指引。
- 同步配置变更、职位映射变更、确认、忽略与重试均写入操作记录；错误摘要不包含凭证、完整请求与响应报文、候选人敏感信息。
- 权限：招聘HR 仅可见与处理本人数据权限范围内的待确认记录；招聘管理员与 HRBP 按数据权限处理全部；其他角色不可见同步入口。凭证服务端加密，简历只预览不下载。

## 8. 面试与评价

- 面试轮次为初试、复试、终试；同一投递同一轮次同一时间仅保留一个有效场次，改期更新原场次时间并留痕。
- 安排面试须填写日期、时段、时长、面试方式（视频、现场、电话）、地点或会议链接与至少一名面试官；面试官在同一时段已有未取消场次时阻断保存并提示冲突。
- 面试邀约状态为待确认、已接受、已拒绝、待改期；候选人拒绝须选择原因，待改期由招聘负责人重新安排。
- 面试场次状态为待面试、已完成、已取消、爽约；达到结束时间且未录入评价的场次标记待评价。
- 每位面试官独立提交评价，结论为通过、淘汰或待定，评语必填且不超过 500 字，可补充优势与风险；评价在面试结束时间后 24 小时内提交，超时提醒招聘负责人。
- 多面试官场次的汇总规则：任一淘汰则该轮不通过；全部通过则该轮通过；存在待定且无淘汰时由招聘负责人裁决通过或淘汰并填写原因。
- 轮次通过后进入下一轮或发起 Offer；轮次淘汰或候选人放弃时投递终止并记录原因。
- 面试官仅可见本人场次与候选人必要信息（姓名、应聘职位、简历摘要、前轮评价摘要），不可见薪资与 Offer 信息。

## 9. Offer

- Offer 由终试通过后的投递发起，同一投递仅保留一个进行中的 Offer；同一候选人同时仅允许一个进行中 Offer，接受后其他投递流程终止。
- Offer 内容包含候选人、职位、组织、职级、职级类别、岗位类别、岗位族、工作性质、用工形式、办公地点、计划入职日期、薪资结构、试用期、Offer 有效期与招聘负责人；证件、手机号等候选人信息取自应聘者档案。
- 薪资结构含月度固定薪资、月度绩效基数、年度目标奖金月数与签字费，属敏感字段，默认脱敏展示。
- 年度总包按「月度固定×12 + 月度绩效基数×12 + 年度目标奖金月数×月度固定 + 签字费」折算；内部定薪年包可覆盖年度总包。涨幅 =（定薪年包 − 当前年包）÷ 当前年包；薪标上限取自薪酬带宽配置，默认涨幅预警上限 15%。
- 超薪标或超涨幅只标记不阻断，审批页提示；具备薪资权限方可查看年包、涨幅与薪标。
- 审批链：业务终面人 → HRBP → 薪酬负责人；薪资高于职级带宽上限、签字费大于零或职级与需求职级不一致时，增加中心负责人审批。
- Offer 状态：待发起、审批中、待发送、已发送、已接受、已拒绝、已失效、已关闭、已入职。
- 审批中可由发起人撤回至待发起，内容保留；审批驳回回到待发起并记录原因。
- 审批通过后进入待发送，由招聘负责人或 HRBP 发送；发送后记录发送人、发送时间与送达渠道，状态为已发送。
- Offer 有效期为 3 至 15 天，默认 7 天；有效期届满仍未接受时于次日零点自动失效，释放名额并终止投递。
- 候选人接受后状态为已接受，系统自动生成入职单并转入入职管理，计划入职日期取 Offer 约定日期；候选人拒绝时须选择放弃原因（薪酬待遇不满足、选择其他平台、地理位置、转正周期过长、家里有事、其他），放弃说明选填，投递终止，职位与需求名额释放。
- 入职管理标记爽约后，招聘侧关闭对应 Offer 并记录关闭原因「候选人爽约」，释放职位名额；需求不自动完成，可重新发起招聘。
- 确认入职后，入职单实际职级回填 Offer 并与 Offer 职级比较生成职级差异标记；差异不改变 Offer 审批结果。
- 待发送与已发送未接受的 Offer 可由招聘负责人关闭并填写原因；已接受未入职的 Offer 关闭须 HRBP 二次确认，并同步取消入职单；已入职的 Offer 不可关闭。
- 招聘侧关闭或撤销 Offer 时，对应入职单自动取消（规则见[入职管理 · 业务规则](../../入职管理/文档/业务规则.md)）。

## 10. 到岗核销与编制回写

- 链路：需求提交审批 → 审批通过进入招聘 → 创建职位 → 候选人投递与面试 → 终试通过 → Offer 审批通过 → 自动生成入职单 → 入职管理确认入职 → 招聘需求已到岗加一、投递状态已入职、Offer 状态已入职、职位在招人数减一 → 编制明细行在编人数加一（待编制确认）→ 需求人数到齐自动完成。
- 待入职只占用职位名额，不增加需求已到岗与编制在编；确认入职后才核销。
- 确认入职后，投递记录与 Offer 的招聘季度更新为实际入职日期所在季度；候选人指标按投递记录招聘季度归属。
- 入职管理标记爽约时，入职单状态为未到岗，Offer 关闭，职位名额释放，需求已到岗人数不变；招聘负责人可重新发起招聘。
- 到岗核销以入职单号为幂等键，一份入职单只核销一次；重试与重复事件不重复计数。
- 招聘需求已到岗人数按 Offer 关联需求归属；候选人跨需求竞聘时以最终入职 Offer 所属需求为准。
- 编制回写写入内容：编制明细行在编人数加一、在编人员追加（工号、姓名、职级、入职日期）、变更来源为招聘入职、关联需求号与入职单号，状态为待编制确认。
- 编制管理员在编制管理核对组织、职位、职级后确认，确认后归档；待确认期间不影响招聘计数与需求完成判定。
- 若回写后在编人数超过编制数量（编制已被调减），仍正常加一并标记超编警示，由编制管理员与中心负责人处理。
- 确认入职不可在招聘侧回退；员工后续离职由编制管理按离职事件处理，不回写招聘需求与 Offer。

## 11. 工作台待办口径

- 工作台只展示当前用户数据权限内的数据，待处理数字为当前用户实际可处理的记录数。
- **待处理简历**：当前用户负责职位下投递状态为待处理的简历数；内推与猎头为其中渠道为内推、猎头的子集。
- **待安排初试**：初筛通过且尚未安排初试的投递数。
- **待发 Offer**：审批通过且尚未发送的 Offer 数。
- **招聘日程**：今天起未来 7 天的面试场次，按日期与时间升序；勾选「仅看我安排的面试」后只展示当前用户为安排人的场次；面试官展示本人待评价场次与快捷评价入口。
- **最近访问职位**：当前用户最近查看的 5 个职位，按查看时间倒序。
- **快捷入口**：招聘台账、未归档简历、我关注的职位、我关注的应聘者、已锁定的应聘者，数字为该入口当前记录数；招聘台账展示当前用户数据权限内的候选人级汇总。
- 工作台数字随投递、面试与 Offer 状态变化即时刷新。

## 12. 招聘数据看板口径

- 默认时间范围为近半年，可选本月、本季度、近半年或自定义区间；自定义区间不超过 24 个月。另提供招聘季度筛选（如 2026Q2、Q3、Q4），需求指标按需求招聘季度归属，候选人指标按投递记录招聘季度归属，不按日期反推。
- 招聘季度归属：需求在需求上维护；候选人默认继承需求季度，Offer 接受后按计划入职季度更新，确认入职后按实际入职季度更新。人选 Q3 跟进、Q4 入职时归属 Q4。
- 人效归属：已入职、待入职、Offer、放弃 Offer、三面通过与在招池按投递记录或 Offer 的招聘HR归属；需求承接数按需求的招聘负责人归属；协同招聘HR只展示不重复计入。
- 待入职：Offer 已接受、计划入职日期不早于今天、尚未入职且未标记爽约。待入职只占用职位名额，不增加需求已到岗与编制在编。入职管理台账的「待入职」页签包含逾期待跟进记录，与本指标口径不同；看板与招聘进度统一按本口径统计。
- 台账数据：看板与招聘进度读取投递记录的台账摘要；详细面试评价、Offer 与入职单存在时优先使用详细流程数据，缺失时使用台账填写或批量导入的摘要；台账补录的已入职不增加编制在编，编制回写仍以入职管理确认入职为准。
- 编制与在编数据取查询截止日的编制管理生效口径；招聘占用取截止日在途需求的剩余人数。
- **需求指标**：招聘需求数、在招需求数、已完成需求数、到岗人数、需求完成率（已完成需求数 ÷ 需求数）、到岗率（已到岗人数 ÷ 需求人数）、平均需求周期（需求审批通过至需求完成的平均自然日）、超期需求数（超过期望到岗日期仍未完成的需求数）。
- **招聘进度**：支持按三级组织、岗位名称（岗位族）、职级取高（职级类别）、岗位类别四个维度切换；每个维度展示需求数、已入职、待入职、缺口（max(需求数 − 已入职 − 待入职, 0)）、完成率（已入职 ÷ 需求数）、预计到岗率（(已入职 + 待入职) ÷ 需求数）、平均招聘时长（未完成需求的平均招聘天数）、最长招聘时长、≥150 天数量、一面/二面/终面通过、接受 Offer、放弃 Offer 与预警状态。招聘天数未完成按今天减需求提报日期，已完成按完成时间减需求提报日期；一面、二面、终面对应初试、复试、终试。
- **招聘时效与预警**：预警状态按 §3 的阈值派生；需升级与需关注的数量进入看板汇总，支持按维度下钻到需求列表。
- **编制达成**：按组织与职级类别展示编制数、在编人数、招聘占用、可用缺额、已接受未入职的预计到岗人数、达成率（在编 ÷ 编制）与预计达成率（（在编 + 预计到岗）÷ 编制）；可用缺额为负时以超编警示展示。
- **招聘漏斗**：简历收取、初筛通过、初试通过、复试通过、Offer 审批通过、Offer 已接受、已入职七个环节的人数与环节转化率，并展示简历到入职的总转化率与各环节平均停留天数；未发生的环节显示零，除数为零时转化率显示「—」。
- **渠道效果**：各渠道的简历数、初筛通过率、Offer 数、入职数、入职转化率、渠道费用与单位入职成本；费用按渠道配置的固定单价或薪资比例计算，入职数为零时单位成本显示「—」。
- **面试官人效**：面试官维度展示面试场次、评价及时率（24 小时内提交的评价场次 ÷ 应评价场次）、通过率与平均评价时长。
- **招聘HR人效**：按招聘季度与招聘小组展示招聘HR的精力投入、投入月数、月度等效全职人力（FTE = 精力投入 × 投入月数 ÷ 3）、承接需求、已入职、待入职、在招池、一面/二面/终面通过、放弃 Offer、漏斗贡献分（一面×0.1 + 二面×0.2 + 终面×0.3 + 待入职×0.6 + 已入职×1.0，权重可配置）、单人月均产出（精力投入 × (已入职 + 待入职) ÷ 投入月数）、池→入职转化（(已入职 + 待入职) ÷ 在招池）、Offer 流失率（放弃 Offer ÷ (放弃 Offer + 已入职 + 待入职)）、折算完成率（(已入职 + 待入职) ÷ 承接需求）与季度环比。诊断标签按投入产出与流失阈值分为高效型、高量低转型、风险预警、观察期，阈值可在人效配置中调整。
- **在招池**：季度内首次投递且未终止的候选人数，去重并含已入职与待入职；跨季度重复投递按首次投递季度计数。
- **Offer 流失**：按放弃原因、组织、招聘HR与岗位类别展示放弃人数、占比与流失率；放弃原因取 Offer 放弃原因枚举。
- **薪酬涨幅**：按职级、岗位类别与组织展示预计到岗与已入职人员的当前年包、定薪年包、平均涨幅、超薪标人数与超涨幅人数；年度总包与涨幅按 §9 口径计算；仅具备薪资权限的用户可见。
- **看板洞察**：按招聘季度维护管理结论与下一阶段动作，由 HRBP 手工填写，不做自动生成；内容展示在招聘数据看板底部，更新记录操作人与时间；仅具备洞察编辑权限的用户可修改。
- 看板按当前用户的数据权限过滤组织范围；导出按当前筛选与统计口径生成汇总与明细，导出记录审计。

## 13. 渠道与费用配置

- 渠道配置为非菜单页面，入口在招聘数据看板，由招聘管理员维护；字段含渠道名称、类型、启用状态、计费方式（固定单价、年薪比例、不计费）、单价或比例与备注。
- 停用渠道不可再被投递记录选择，历史记录保留原渠道与费用口径。
- 费用口径：内推按每入职一人的固定奖金，猎头与 RPO 按约定年薪比例或固定服务费，招聘网站与官网投递按订单或不计费；费用变更只影响变更后入职的统计。
- 渠道配置变更记录操作人、时间与变更前后内容。
