# 招聘过程管理

## 模块概述

人资管理 → HR管理 → 招聘管理 下的过程入口：以「职位 → 应聘者 → 面试 → Offer」为主线推进招聘。工作台按当前用户汇总待处理简历、待处理内推与猎头简历、待安排初试与待发 Offer，展示台账同步卡、未来 7 天招聘日程并支持面试官快捷评价；招聘台账以候选人一行汇总招聘季度、招聘HR、三面结果、Offer、待入职、放弃原因、实际入职职级与薪酬年包；台账填写写入同一投递记录并同步只读台账与数据看板；BOSS直聘同步以官方 API 授权、职位映射与待确认池将候选人导入台账填写，确认入库后复用台账预占与同步口径；职位维护在招人数与 JD，应聘者承载简历、投递、锁定与状态流转，面试安排与评价驱动轮次推进，Offer 经审批、发送与候选人确认后转入入职管理生成入职单。

本功能只承载招聘过程推进与候选人级台账查看，不承载招聘需求的发起与关闭、编制维护与入职办理。

## 端

- **web**：人资管理 → HR管理 → 招聘管理 → 招聘过程管理，桌面端管理后台，覆盖全部页面
- **app**：App 首页工作台 Push 进入招聘工作台，覆盖工作台、日程、台账、职位、应聘者、面试与 Offer 的高频闭环；App 台账只读；新建/编辑职位、批量导入简历、台账填写与批量导入、发起 Offer、台账导出、职位关闭、候选人重新激活与完整简历预览在 Web 端处理

## When to Use

- 查看本人待处理简历、待安排初试与待发 Offer 数量并进入处理
- 查看今天起 7 天的招聘日程，筛选只看本人安排的面试
- 面试官查看本人待评价场次，提交评价或快捷通过、淘汰
- 按招聘季度、招聘HR、岗位类别与状态查看候选人级招聘台账
- 在台账填写页为招聘人员新增或更新候选人台账，录入三面结果、Offer 状态、待入职、放弃原因、实际入职职级与薪酬年包
- 通过 Excel 模板批量导入或更新台账，下载失败行回执
- 查看 BOSS直聘 授权状态、维护职位映射、处理待确认候选人与同步批次
- 在台账填写页打开同步抽屉，确认入库、更换职位或忽略待确认记录
- 维护候选人的当前年包、期望年包与谈薪备注，查看涨幅与薪标 / 涨幅标记
- 创建与暂停职位，维护在招人数与职位描述
- 导入简历、查重合并、锁定应聘者、初筛通过与淘汰、终止与重新激活
- 安排、改期、取消面试并跟进候选人邀约
- 发起 Offer 审批、跟进审批节点、发送 Offer、记录接受与拒绝、关闭或失效 Offer
- 记录放弃 Offer 原因、实际入职职级差异与候选人进展备注

## Tips

- 职位由招聘中需求创建，同一需求在招人数合计不得超过需求剩余名额；候选人发起 Offer 前再次校验名额
- 面试官在同一时段已有未取消场次时不可重复安排；候选人接受邀约后进入日程
- 评价在面试结束后 24 小时内提交，超时提醒招聘负责人；多人场次任一淘汰即该轮不通过
- Offer 审批链为业务终面人 → HRBP → 薪酬负责人，薪资超带宽、有签字费或职级不一致时增加中心负责人
- 招聘台账按招聘季度归属：候选人默认继承需求季度，Offer 接受后按计划入职季度更新，确认入职后按实际入职季度更新；Q3 跟进、Q4 入职计入 Q4
- 人效归属按候选人投递或 Offer 的招聘HR；协同招聘HR只展示不重复计入
- 年度总包按月度固定、绩效基数、目标奖金月数与签字费折算；内部定薪年包可覆盖；超薪标与超涨幅只标记不阻断
- Offer 接受后自动生成入职单；关闭或撤销 Offer 会取消对应入职单，已确认入职的 Offer 不可关闭；入职管理标记爽约后对应 Offer 关闭并释放职位名额
- 手机号、证件号码、薪资、年包与涨幅默认脱敏，明文查看需敏感字段权限
- 台账填写的部门、岗位、职级按「二级部门 → 三级部门 → 招聘需求 / 职位 → 职级」四级联动，仅可选招聘中且剩余名额大于零的招聘需求，职级在需求职级范围内选择并带出对应薪标；同一需求可录入多名候选人
- 台账填写按每条记录预占 1 个需求空缺，终止、放弃、淘汰或删除时释放；剩余名额 = 需求数 − 已到岗 − 待入职 − 台账在途预占；台账填写与只读台账均支持部门筛选
- 台账填写写入投递记录的台账摘要字段，不新建独立台账表；过程创建的投递由面试评价、Offer 与入职单派生，台账补录的投递可手工维护摘要，详细流程数据出现后以详细数据为准
- 台账填写、行内编辑与批量导入后，工作台「台账同步」卡、只读招聘台账与招聘数据看板即时刷新，三者读取同一投递记录
- 台账补录的已入职只更新摘要，不写入员工档案、不增加编制在编；完整入职与编制回写仍需入职管理确认
- App 端仅承载高频操作且台账只读；新建/编辑职位、批量导入简历、台账填写与批量导入、发起 Offer、台账导出、职位关闭、候选人重新激活与完整简历预览在 Web 端处理
- BOSS直聘同步待确认池不占需求名额、不计入台账与看板；确认入库才按台账规则预占 1 个空缺，批量确认仅成功行预占
- 同步只写基础信息、简历与进展备注；三面结果、Offer、待入职与薪酬仍由内部维护，详细流程数据优先
- 未映射或冲突职位的候选人不可确认；名额不足时确认拦截，可更换职位或忽略
- App 端不提供 BOSS直聘同步入口，台账保持只读
