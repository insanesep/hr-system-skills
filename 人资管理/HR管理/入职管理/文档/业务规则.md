# 入职管理 · 业务规则

> 本功能描述入职单从转入、准备到确认入职的办理规则；字段口径见 [数据模型.md](数据模型.md)，页面元素见 [页面元素.md](页面元素.md)。

## 1. 名词约定

| 名词 | 定义 |
|---|---|
| 入职单 | 一名待入职人员的入职办理记录，由招聘 Offer 转入，是台账、详情与办理操作的最小单位 |
| 信息采集 | 候选人填写个人基础信息与入职登记信息的线上采集过程，含发送、暂存、提交与退回重填 |
| 入职材料 | 入职需提交的证明与登记材料，按材料项逐项上传与确认，汇总为未提交、未交齐、已交齐 |
| 入职准备事项 | 部门与职能侧在入职日前完成的事项，如工位、办公设备、系统账号、导师指派与入职指引 |
| 必备事项 | 信息采集、必备材料与必备准备事项的统称，是提醒内容与确认入职前置条件的口径 |
| 入职状态 | 候选人到岗计划的填写结果：空（未填写）、正常、延期 |
| 到岗结果 | 候选人的实际到岗结果：待到岗、已到岗、未到岗（爽约）、已取消 |
| 爽约 | 计划入职日期已过仍未入职，由 HR 标记未到岗并记录原因；爽约不进入待入职 |
| 职级差异 | 入职确认职级与 Offer 职级不一致时的标记：低于 Offer、高于 Offer |

## 2. 功能边界

- 本功能承载入职单的跟进、信息采集、材料与准备核对、提醒、改期、确认入职与导出。
- 不做：招聘流程推进、Offer 审批与发放、候选人面试评价、员工档案的日常维护、劳动合同签订、薪酬与社保办理。
- 已入职记录只读；入职后的档案修改、合同与薪酬办理不在本功能发生。
- 本功能不提供入职材料清单与准备事项模板的配置维护。

## 3. 数据来源与档案衔接

- 招聘 Offer 审批通过后生成入职单，一份 Offer 对应一份入职单；入职单号唯一。
- 入职单的姓名、证件信息、待入职部门、职位、职级、雇佣关系、计划入职日期、招聘负责人、招聘HR、招聘季度与 Offer 发送人取自 Offer 快照；招聘侧后续变更不自动改写已生成入职单，需由招聘侧重新确认。
- 招聘侧关闭或撤销 Offer 时，对应入职单自动取消，从页签中移出并保留操作记录；已确认入职的记录不受影响。
- 确认入职后，以入职单为来源写入员工档案（员工资料），写入字段包含姓名、证件号码、待入职部门、职位、职级、雇佣关系与实际入职日期；同一入职单只写入一次。
- 确认入职后，系统按入职单试用期生成转正单；无试用期员工不生成。转正规则见[转正管理](../../转正管理/SKILL.md)。
- 确认入职后写入[员工成长记录](../../../员工档案/员工成长记录/SKILL.md)入职事件，事件快照取入职单的组织、职位、职级与入职日期。
- 确认入职后生成[合同管理](../../合同管理/SKILL.md)待签订合同，合同起始日期取实际入职日期；合同类型默认固定期限，由 HR 在签订前调整。
- 确认入职时比较入职职级与 Offer 职级，不一致时生成职级差异标记并回写 Offer；招聘季度按实际入职日期所在季度更新。
- 写入后的员工档案以员工资料为准，本功能只读引用；员工的工号与档案编号按员工档案规则生成，本功能不复述。

## 4. 页签与查询

- 台账固定四个页签：
  - **待入职**：全部未确认入职且未标记未到岗的入职单，包含计划日期为今天与已逾期的记录；按计划入职日期升序排列，同日期按入职单号升序。本页签是跟进队列，包含逾期记录；招聘看板的「待入职」指标只统计计划日期不早于今天且未爽约的记录。
  - **今日待入职**：待入职中计划入职日期为今天的记录，是待入职的子集，排序与待入职一致。
  - **已入职**：已完成确认入职的记录，按实际入职日期倒序排列。
  - **未到岗**：已标记未到岗（爽约）的入职单，按爽约确认时间倒序排列；该页签记录只读，不再提供确认入职与改期。
- 切页签保留基础筛选与高级筛选条件，页签与筛选为「且」关系；页签切换回到第一页。
- 基础筛选：姓名（模糊匹配）、待入职部门、雇佣关系、计划入职日期区间、入职状态（多选，可含空值）、招聘季度、到岗结果（多选）。
- 高级筛选：信息采集状态、入职材料状态、招聘负责人、招聘HR、Offer 发送人、是否逾期、爽约原因（多选）；高级筛选项与基础筛选项同为「且」关系。
- 筛选条件变更后即时查询，不设独立查询按钮；姓名输入在回车或失焦后触发。「清空已选」清空基础与高级全部条件并恢复页签默认排序。
- 计划入职日期早于今天且未确认入职的记录为逾期记录，在计划入职日期列以警示色标识；逾期记录仍留在待入职页签，不做自动取消。
- 逾期不等于爽约：HR 确认候选人不会到岗后，手动标记未到岗并选择爽约原因，记录进入未到岗页签；未标记前仍按待入职跟进。
- 查询结果为空时展示空态；加载失败时展示失败提示并提供重试，重试按原条件重新查询。

## 5. 信息采集

- 信息采集状态依次为：未发送、已发送、已暂存、已提交。
- 发送采集以候选人的手机号或邮箱为送达对象，首次发送后状态为已发送；重复发送不改变已提交状态。
- 候选人在采集页可暂存或提交：暂存后状态为已暂存，提交后状态为已提交；提交后采集内容冻结。
- 招聘负责人或 HRBP 可对已提交的采集执行退回重填，退回须填写原因；退回后状态回到已发送，候选人重新提交后再次冻结。
- 候选人在提交采集时一并确认到岗计划：选择正常到岗置为「正常」，选择延期置为「延期」；未选择保持「空（未填写）」。
- 信息采集内容包含个人基本信息、联系方式与紧急联系人等入职登记信息；具体字段以采集页为准，本功能不承载字段级配置。
- 已确认入职后，信息采集只读，不再提供发送、退回与修改入口。

## 6. 入职材料

- 入职材料按统一清单逐项管理，每个材料项标注是否必备；材料项状态为：未提交、已提交、已确认、已退回。
- 候选人通过信息采集入口上传材料，上传后为已提交；招聘负责人或 HRBP 核对后确认为已确认，不符合要求时退回并填写原因，退回后为已退回，候选人可重新上传。
- 入职材料汇总状态：
  - **未提交**：全部材料项均为未提交。
  - **已交齐**：全部必备材料项均为已确认。
  - **未交齐**：介于两者之间的全部情况。
- 材料状态只由材料项的实际状态推导，不手工修改；已确认入职后材料只读。
- 材料支持在线预览，预览失败时展示文件信息，不提供保存到本地。

## 7. 入职准备事项

- 入职准备事项按统一清单逐项管理，每项标注是否必备并指定负责人；事项状态为未完成、已完成。
- 入职准备进度为「已完成事项数 / 全部事项数」，随事项勾选实时变化。
- 招聘负责人、HRBP 或事项负责人可将事项标记完成或撤销完成；每次变更写入操作记录。
- 必备准备事项全部完成是确认入职的前置条件之一；非必备事项不影响确认入职。

## 8. 提醒必备事项

- 提醒对象为选中的待入职或今日待入职入职单，可单条或批量触发；已入职记录不可提醒。
- 提醒内容按入职单逐人生成，列出未完成的信息采集、未交齐的必备材料与未填写的入职状态；已完成的必备事项不进入提醒内容。
- 提醒通过候选人的信息采集送达渠道发送；每次提醒写入操作记录，记录提醒人、时间与提醒内容摘要。
- 同一入职单在 24 小时内重复提醒时，需二次确认「该人员 24 小时内已提醒，仍要再次提醒？」。

## 9. 改期入职与逾期

- 改期对象为待入职或今日待入职入职单，可单条或批量触发；已入职记录不可改期。
- 改期须填写新的计划入职日期与改期原因，新日期不得早于今天；同一入职单可多次改期，每次保留原计划日期、新计划日期、原因、操作人与时间。
- 改期后入职状态置为延期；候选人通过信息采集主动申报延期的，同样置为延期。
- 改期至今天后，记录进入今日待入职页签；改期至未来日期后，记录留在待入职页签。
- 逾期未确认入职的记录不自动取消；由招聘侧关闭 Offer 时取消入职单，或由 HR 改期继续跟进。
- 标记未到岗：对象为待入职页签中计划入职日期早于今天且未确认入职的记录；招聘负责人或 HRBP 可单条或批量标记，须选择爽约原因（个人原因、薪酬、地点、家庭、其他）并可填写说明。
- 标记后：到岗结果置为未到岗（爽约），单据状态为未到岗，记录移入未到岗页签；招聘侧对应 Offer 关闭并记录「候选人爽约」，释放职位名额，需求不自动完成。
- 未到岗为终态，不可撤销；候选人恢复入职意向时由招聘侧重新发起 Offer 并生成新的入职单。

## 10. 确认入职

- 确认入职须同时满足：计划入职日期不晚于今天、信息采集状态为已提交、入职材料汇总状态为已交齐、全部必备准备事项已完成。
- 任一条件不满足时不可确认，页面逐项列出未满足项与处理入口。
- 确认成功后：实际入职日期记为确认当天，入职状态保留最后填写结果（未填写、正常或延期），单据转入已入职页签，并写入员工档案。
- 确认入职为终态操作，不可撤销；确需更正时按员工档案的档案更正流程处理，不在本功能回退。
- 确认当天晚于计划日期的，实际入职日期以确认当天为准，并在操作记录中保留原计划日期。
- 确认入职时比较入职职级与 Offer 职级；不一致时标记低于 Offer / 高于 Offer，回写 Offer 的职级差异标记，不改变 Offer 审批结果。
- 确认入职后招聘季度按实际入职日期所在季度更新，回写投递记录与 Offer。

## 11. 导出与列设置

- 导出范围为当前页签与当前筛选条件下的全部记录，不受分页限制；导出字段按当前显示的列生成。
- 证件号码默认以脱敏形式导出（保留前六位与后四位）；具备敏感字段导出权限时可选择导出明文，选择明文导出须二次确认并记录导出审计。
- 默认列导出为每人一行的名单文件，包含姓名、待入职部门、职位、职级、计划入职日期（已入职页签导出实际入职日期）、入职状态、到岗结果、爽约原因、招聘季度、招聘HR、职级差异、信息采集状态、入职准备进度、入职材料状态、招聘负责人与 Offer 发送人。
- 列设置控制除姓名与操作外各列的显示与隐藏；设置按当前用户保留，不改变他人视图。

## 12. 状态枚举与展示

| 枚举 | 取值 | 展示 |
|---|---|---|
| 页签 | 待入职、今日待入职、已入职、未到岗 | 页签切换，显示对应记录数 |
| 入职状态 | 空（未填写）、正常、延期 | 空值以中性文本展示；正常为主色标签；延期为警示标签 |
| 到岗结果 | 待到岗、已到岗、未到岗（爽约）、已取消 | 已到岗为主色标签，未到岗为警示标签，其余为中性标签 |
| 爽约原因 | 个人原因、薪酬、地点、家庭、其他 | 文本 |
| 职级差异 | 无差异、低于 Offer、高于 Offer | 低于 / 高于 Offer 为警示标签 |
| 信息采集状态 | 未发送、已发送、已暂存、已提交 | 已提交为主色标签，其余为中性标签 |
| 入职材料状态 | 未提交、未交齐、已交齐 | 已交齐为主色标签，未交齐为警示标签，未提交为中性标签 |
| 雇佣关系 | 全职、实习、兼职、劳务 | 文本 |
| 材料项状态 | 未提交、已提交、已确认、已退回 | 已确认为主色标签，已退回为警示标签，其余为中性标签 |
| 准备事项状态 | 未完成、已完成 | 已完成为主色标签，未完成为中性标签 |

## 13. 权限编码

| 操作 | 权限编码 | 说明 |
|---|---|---|
| 菜单入口 | `MENU:HR:ONBOARDING` | 未授权不展示菜单 |
| 查看详情 | `BTN:HR_ONBOARDING:DETAIL` | 未授权不展示「详情」入口 |
| 发送 / 退回信息采集 | `BTN:HR_ONBOARDING:COLLECTION` | 招聘负责人与 HRBP 可见 |
| 提醒必备事项 | `BTN:HR_ONBOARDING:REMIND` | 未授权不展示提醒入口 |
| 改期入职 | `BTN:HR_ONBOARDING:RESCHEDULE` | 未授权不展示改期入口 |
| 材料确认 / 退回 | `BTN:HR_ONBOARDING:MATERIAL_CONFIRM` | 未授权时材料项只读 |
| 准备事项维护 | `BTN:HR_ONBOARDING:PREPARE` | 未授权时准备事项只读 |
| 确认入职 | `BTN:HR_ONBOARDING:CONFIRM` | 未授权不展示确认入口 |
| 标记未到岗 | `BTN:HR_ONBOARDING:NO_SHOW` | 未授权不展示标记入口 |
| 导出 | `BTN:HR_ONBOARDING:EXPORT` | 未授权不展示导出按钮 |
| 敏感字段明文查看 / 导出 | `BTN:HR_ONBOARDING:SENSITIVE` | 未授权时证件号码始终脱敏 |

- 数据权限：招聘负责人可见本人负责的入职单；HRBP 可见本中心范围；中心负责人本中心只读；招聘团队按负责范围可见。
- 菜单权限、按钮权限与数据权限同时校验；任一不满足时不展示对应操作。
- 功能权限校验接入用户权限中心，具体能力以公共契约为准，本模块不复述接口定义。
