00 · 为什么是现在

四个断点，让 HRBP 线一直在“补流程”

制度并不缺，缺的是一条被系统承载的事件链。

01

组织与供给脱节

编制散落在表格与个人经验里，招聘凭感觉发起；超编与缺额说不清，需求与编制两套数。

后果：该招的没招，不该招的先进来。

02

到岗与融入脱节

到岗日不等于融入日；信息采集、材料、入职准备靠人催；试用期到期靠人记。

后果：体验受损，试用期风险后置。

03

评价与用人脱节

绩效停在表格里，晋升与调岗靠印象；评价结果没有进入用人决策，也没有留下依据。

后果：管理者不敢定，员工不服气。

04

离开与补位脱节

人走了编制不减、替补临时提；交接靠自觉，账号、资产与合同风险留在组织里。

后果：编制失真，补位永远慢半拍。

真正的解法不是再加一张表 而是让编制、招聘、入转调离、绩效与档案在同一条事件链上运行

01 · 底座

主数据不稳，流程越多越乱

先把“唯一真源”立住，后面的自动化才有意义。所有流程只引用主数据，不再复制一套口径。

组织主数据

组织管理
部门

公司五级组织树：公司 → 中心 → 部门 → 小组 → 子小组。根公司唯一；删除仅限空叶子，其余只能停用，避免历史断链。

岗位

管理 M、专业 P、业务 S、操作 O 四序列，战略决策层到员工级五类职级。职级矩阵是唯一真源；标准职位带编码、适用职级范围与版本。

映射

岗位映射以员工当前职位、序列与职级为输入，按标准职位给出建议；批量切换只更正名称，不触发调岗或晋升。

编制

可用缺额 = 编制数量 − 在编人数 − 招聘占用。编制台账、年度规划、外包超编同源；调增审批，调减与停用即时生效。

员工主数据

员工档案
员工资料

基本信息、任职记录、绩效、合同、附件五个页签。只读档案视图，不承载新增与编辑，避免多入口改数。

任职记录

异动生效时结束原任职记录、新增新记录，历史不覆盖；组织、职位、职级与直接上级都可追溯。

成长记录

只读事件流水：来源单据 + 事件日期 + 当时组织职位快照。按“来源单据 + 事件类型”幂等写入，更正与撤销不删除历史。

绩效页签

只读引用绩效最终生效结果与绩效系数；过程评分、建议等级与通晒调整不写入档案，避免“半成品”进入人才判断。

一处维护，多处引用；一次变更，全程留痕。 主数据是本方案的第一优先级，也是所有自动化的前提。
引用关系：岗位 → 编制 / 招聘 / 绩效 / 档案；编制 → 招聘 / 入职 / 离职；员工资料 ← 全模块回写。

01 · 主线一 · 招聘

让每一个需求都从编制缺额出发

需求、过程、数据三段式，把“招多少人”变成“补哪个缺口”。

01

招聘需求

编制缺额是唯一入口

  • 提交审批即冻结缺额，草稿不占用
  • 超编需求须中心负责人审批
  • 招聘天数 ≥ 150 天自动升级预警
  • 按招聘季度归属，不按日期反推
02

招聘过程

职位、候选人、面试、Offer 一条线

  • 职在招人数不得超过需求剩余名额
  • 台账每条候选人预占 1 个空缺，终止或淘汰即释放
  • 面试评价 24 小时内提交，逾期提醒负责人
  • Offer 接受后自动生成入职单
03

招聘数据

不只看“招到没有”，更看“卡在哪里”

  • 漏斗转化与各环节停留天数
  • 渠道效果与单位入职成本
  • 招聘 HR 人效与面试官及时率
  • Offer 流失原因与薪酬涨幅
01

管缺口

编制、需求、入职三方同口径，超编与缺额一眼看清。

看数：编制达成率 · 超编率
02

管节奏

用招聘天数与预警跑周会，只处理卡点，不追全部需求。

看数：平均招聘周期 · ≥150 天占比
03

管质量

面试评价、试用期表现与转正结果反哺招聘标准。

看数：面试通过率 · 试用期转正率
04

管成本

渠道费用、薪酬涨幅与超带宽审批，提前拦住不合理 Offer。

看数：单位入职成本 · Offer 涨幅
硬规则Offer 接受只占职位名额；确认入职才回写编制在编，避免“人没到、编制先满”。

01 · 主线二 · 入职到转正

从到岗到融入：把试用期做成一次有节点的投资复盘

入职不是终点，转正也不是自动通过。每一步都有门槛、有责任人、有回写。

01

Offer 接受

自动生成入职单；一份 Offer 对应一份入职单，部门、职位、职级与日期以快照为准。

责任人：招聘 HR
转入职
02

到岗前准备

信息采集、入职材料、入职准备三线并行；支持批量提醒、改期留痕。

责任人：HRBP + 用人部门
可提醒 · 可改期
03

确认入职

日期已到、信息采集已交、必备材料已齐、必备准备已完成，四道门槛同时满足。

责任人：HRBP
四道门槛
04

试用期

转正单自动生成；试用期结束前 30 / 7 / 0 天提醒直接上级与 HRBP。

责任人：直接上级
自动生成
05

转正 / 未通过

四维评估；直接上级 → 部门负责人 → HRBP 审批；延期一次为限，不通过转离职单。

责任人：HRBP · 审批人

T-30目标对齐 · 中期反馈

爽约处理

逾期确认不到岗 → 标记未到岗 → 关闭 Offer、释放职位名额；需求不自动完成，恢复意向需重新发起 Offer。

合同管理

入职确认生成待签合同；30 / 7 天到期提醒；一人同一时点仅一份生效中合同；离职确认生成解除待办。

考勤管理

入职日期起算、离职日期截止；日 / 月 / 假勤 / 规则四个页签；月度确认后锁定，更正须 HRBP 审批。

HRBP 视角：试用期不是“等转正”，而是一次有目标、有反馈、有结论的投资复盘。评估在到期前完成，结论在系统中留痕。

01 · 主线四 · 异动与离职

一进一出：让“人动”有据，让“人走”闭环

异动看依据与编制，离职看交接与回写。两者共同决定组织资源是否真实流动。

调岗晋升

有据
  • 类型自动判定：目标职级高 → 晋升；低 → 降职；相同 → 调岗。
  • 发起校验：目标标准职位与职级匹配、组织启用、目标上级在职、编制有缺额。
  • 晋升依据：引用最近一次已生效绩效；缺失提示补充说明，不自动阻断。
  • 审批链：原直接上级 → 目标直接上级 → 原 / 目标部门负责人 → HRBP；晋升、降职、经理级及以上或跨中心加中心负责人。
  • 生效：生效日自动生效；校验失败进入“生效冲突”，不静默覆盖。
  • 更正：已生效不可撤销，只能发起更正异动单，重新审批与留痕。

回写：任职记录 · 编制占用 · 绩效名单组织职级 · 员工成长记录

离职管理

闭环
  • 五个页签：待审批 / 待离职 / 待确认 / 已离职 / 已撤销。
  • 一张单管全流程：离职类型、原因、最后工作日、交接负责人、是否发起替补。
  • 交接清单：工作交接、资产归还、账号停用、财务借款、合同文件、其他事项。
  • 确认四条件：最后工作日已到、审批通过、必备交接完成、无进行中异动。
  • 审批链：直接上级 → 部门负责人 → HRBP；经理级及以上、关键岗位或协商解除加中心负责人。
  • 不自动离职：试用期不通过、协商解除等场景，必须走离职单确认。
交接清单（必备未完成不可确认）
工作交接资产归还账号停用 财务借款合同文件其他事项
回写：员工状态 · 编制在编 −1 · 绩效名单 · 合同解除 · 成长记录；可发起离职替补
编制从此“只增不减”成为历史：确认离职即释放编制，替补需求再进入招聘主链；一进一出，编制才是一张活的资源表。

01 · 主线五 · 员工档案

档案是截面，成长记录是轨迹

把散落在单据里的“人”的历史，沉淀成可查询、可追溯、可复用的人才资产。

员工资料

Read-only profile
  • 五个页签：基本信息、任职记录、绩效、合同信息、附件资料。
  • 只读档案：不承载员工新增、编辑与删除；数据由业务流程回写。
  • 权限与脱敏：按组织与角色控制可见范围；证件号码、手机号默认脱敏。
  • 使用场景：入职核对、晋升评审、合同查询、离职面谈准备。
  • 附件资料：简历等附件在线预览，不提供下载与分享。
  • 越权隔离：不在数据权限内的员工不出现在列表中。

Event timeline

  • 写入规则：由来源模块在业务生效时写入，不允许手工新增、编辑或删除。

02 · 治理规则

四个统一，让系统“跑得久”

流程可以变，底层规则不能乱。统一口径与留痕，是 HRBP 敢用数据说话的前提。

RULE 01

统一口径

职级矩阵、标准职位、可用缺额、招聘季度归属，只保留一份定义；工作台与看板只读引用，不重复计算。

落地：指标字典 + 唯一真源链接
RULE 02

统一流程

每张单据有明确状态机、审批链与生效条件；审批通过不等于生效，生效才触发回写。

落地：状态机 + 审批链配置
RULE 03

统一权限

菜单、按钮与数据范围分层控制；敏感字段默认脱敏，明文查看与导出需单独授权。

落地：菜单 / 按钮 / 数据权限矩阵
RULE 04

统一留痕

修改填原因、版本可回溯、事件快照固化、重复写入幂等；撤销与更正不删除历史。

落地：修改原因 + 版本 + 快照
口径是否唯一 审批与生效是否分离 敏感字段是否脱敏 撤销与更正是否留痕
指标字典每个指标一个定义、一个来源、一个责任人。
状态机清单每张单据的状态、审批、生效与回写条件。
权限矩阵菜单、按钮、数据范围与敏感字段的可见规则。
不做薪酬核算绩效系数与考勤结果只输出，不替代薪酬与奖金发放。
不替代专业平台电子签、打卡设备与招聘平台只对接，不做底层平台。
不承载人的判断线下面谈、评价校准与管理决断仍由管理者完成。
系统负责确定性，HRBP 负责判断力。Governance before automation

03 · 落地路径

三步走：先地基，再闭环，最后做聚合

顺序不是拍脑袋，而是按“被引用程度 × 闭环价值 × 返工成本”排的。先补被多处引用的主数据与能闭合编制循环的离职。

PHASE 01 · 0–3 个月

立地基

先把唯一真源和进出闭环立住
  • 岗位管理：职级矩阵、标准职位、岗位映射
  • 离职管理 + 员工主数据可写入口
  • 转正管理与合同管理并行
交付标志主数据唯一；编制能减；入职—转正—离职闭环跑通。
PHASE 02 · 3–6 个月

通链路

让评价结果进入用人决策
  • 绩效管理：参数、目标、评价、通晒
  • 调岗晋升：编制校验、绩效依据、自动生效
  • 招聘数据看板
交付标志绩效结果可引用；异动全链可追溯；招聘用数据开会。
PHASE 03 · 6–12 个月

提效率

一屏经营，事件可追溯
  • 考勤管理
  • 员工成长记录
  • 工作台聚合：可先上最小版本
交付标志HRBP 每日一屏；员工全生命周期事件可追溯。
依赖关系 · 不可跳步
岗位主数据→编制→招聘→入职→转正→绩效→异动→离职 / 替补
先主数据，后流程被引用最多的先做，避免返工。
先闭环，后看板先让单据跑通，再谈数据分析。
先样本，后推广用一个部门跑通，再复制到全公司。
排序原则：先补被编制、招聘、绩效、档案共同引用的岗位主数据；再补能闭合“编制只增不减”的离职循环。 工作台不先做“大而全”，待办口径稳定后再扩。

03 · 成功度量

只看六个指标，判断主链是否跑通

指标不是用来考评 HRBP，而是检验系统是否真的减少了摩擦。

01 · SUPPLY

编制达成率

在编人数 ÷ 编制数量
看：缺口集中在哪些组织与职级。
配套看：超编率
02 · SPEED

招聘周期

需求提报 → 实际到岗
看：卡在需求、面试还是 Offer。
配套看：≥150 天需求占比
03 · QUALITY

试用期转正率

按期转正人数 ÷ 应转正人数
看：招聘质量还是融入问题。
配套看：试用期流失率
04 · PERFORMANCE

绩效按期完成率

按期完成考核表 ÷ 应考核人数
看：目标不清还是管理不作为。
配套看：通晒分布偏差
05 · MOVEMENT

异动生效冲突率

生效冲突单 ÷ 生效异动单
看：编制与组织数据的实时性。
配套看：更正单占比
06 · EXIT

离职交接完成率

必备交接完成 ÷ 应离职人数
看：交接责任是否真正落实。
配套看：关键岗位替补周期
领先指标 员工档案完整率 成长事件可追溯率 待办平均滞留时长
看趋势至少连续 3 个周期，避免单点误判。
看组合速度、质量、成本一起看，不做单项排名。
看行动每个偏差都要落到责任人与下一步。
指标是经营语言，不是考核武器。MEASURE WHAT MATTERS

03 · 现在开始

90 天，不追求全部上线，
先跑通一条完整样本。

DAY 01–30

统一语言

锁定职级矩阵、标准职位、编制口径与关键审批链，让 HRBP、招聘与业务说同一套话。

DAY 31–60

跑通闭环

选一个部门，跑通“需求 → 入职 → 转正 → 离职 → 替补”的完整样本，验证每一次回写。

DAY 61–90

形成节奏

工作台周例会 + 一次完整的季度绩效通晒，让数据开始进入管理例会。

系统把确定性交给流程，把判断力还给 HRBP。END OF DECK
