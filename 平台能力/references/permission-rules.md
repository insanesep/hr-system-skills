# 平台能力 · 权限与授权判定规则

> 定义功能权限、显式分配、工具与令牌交集、当前应用范围及业务身份边界。角色职责见 [业务规则](business-rule.md)；代码仓与成员事实见 [研发工具规则](../研发工具资源/references/devtool-rules.md)；数据库开放与只读约束见 [数据源规则](../数据源管理/references/datasource-rules.md)。

## 1. 权限点矩阵

- 路由编码（name）标识路由，可与门户菜单资源编码对齐，但不因此自动触发功能权限校验；菜单 / 按钮权限码定义页面可见与动作职责，不能互相替代。
- [路由守卫](../../../busyming-devhub-web/src/router/index.ts)按声明的 `meta.permCode` 检查功能权限；编辑授权范围的权限码为 `devhubMcpTokenEdit`，权限分配、数据源、研发工具资源及调用审计的路由权限分别使用本矩阵定义的查看权限码。
- 令牌详情的路由编码为 `devhubMcpTokenDetail`，生成路由为 `devhubMcpTokenCreate`，均不是菜单资源权限码；本人范围、他人详情及管理操作仍按实际权限与服务端判定，不能由路由可进入推断已授权。
- 独立布局由路由菜单标记生成菜单，微应用菜单由门户宿主提供；两种模式均按本矩阵定义页面职责与动作权限。

| 权限点 | 作用 | 令牌使用者 | 权限管理员 | MCP 管理员 | 数据源管理员 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| devhubMcpToken | 门户「我的令牌」菜单资源 | 是 | 是 | 是 | 是 |
| devhubMcpTokenEdit | 编辑本人有效令牌的名称与授权范围 | 是 | 是 | 是 | 是 |
| devhubMcpTokenAdmin | 查看全部令牌与他人详情、吊销他人令牌 | — | — | 是 | — |
| devhubMcpGrant | 权限分配、单人或批量授予与收回、授权变更记录 | — | 是 | — | — |
| devhubMcpDevtool | 查看研发代码仓与成员同步事实 | — | 是 | 是 | — |
| devhubMcpDevtoolEdit | 同步项目代码服务仓与云效研发成员事实 | — | — | 是 | — |
| devhubMcpDatasource | 查看数据源管理与详情 | — | 是 | — | 是 |
| devhubMcpDatasourceEdit | 登记数据源、同步与开放库表、绑定脱敏、启停 | — | — | — | 是 |
| devhubMcpAudit | 查看全量调用审计 | — | 是 | 是 | 是 |
| devhubMcpAuditExport | 导出调用审计 | — | — | 是 | — |

- 角色是职责组合，实际操作须持有对应功能权限；多个职责可以叠加，不能仅凭页面可见认定可写。
- 权限管理员可为本人或其他人员分配工具族与数据库权限，仍记录操作人及被分配人。令牌管理员不能代他人编辑令牌工具选择。
- 研发代码仓查看与同步权限不等于 SLS/ARMS 查询许可；项目维护、成员同步、仓成员身份均不自动授予工具 grant。
- SYSTEM 目录来自现有已注册内置业务工具，不提供第三方服务登记、工具同步或服务目录启停的管理权限。

## 2. 权限分配

### 2.1 基本原则

- SLS/ARMS 工具许可由权限管理员显式按人分配；数据库沿用实例、库、表分配。SYSTEM 已注册内置业务工具默认可选，不要求权限管理员预分配，但令牌仍必须显式勾选。
- 生成和编辑令牌必须至少选择一项当前有效 scope，不允许空权限令牌；没有观测或数据库分配的用户仍可选择有效的已注册 SYSTEM 工具。
- 对观测与数据库，令牌选择只能收窄本人当前分配，不能扩大。增加分配不自动加入已有令牌，用户须主动编辑并勾选。
- 仓成员只派生应用范围，不代替 SLS/ARMS 工具许可；拥有工具族但无有效成员范围仍不能查询应用。
- 非工具型 DEVTOOL 授权不参与有效分配或令牌范围判定，不自动升格为工具许可、不扩大已有令牌。取得观测能力须管理员重新显式授予工具族，并由用户重新选择令牌工具；数据库权限保持不变。

### 2.2 分配粒度

| 领域 | 管理员分配 | 令牌选择 | 调用目标范围 |
| ---- | ---- | ---- | ---- |
| SYSTEM 业务工具 | 不要求预分配 | 现有已注册内置工具显式勾选 | 工具自身业务权限与身份边界 |
| DEVTOOL 研发工具 | SLS、ARMS 工具族，可分别分配 | 只选已获有效分配的工具族 | 当前有效成员所在项目代码服务仓；完整 appName 在查询时定位 |
| DATABASE 数据库 | 实例、库、表 | 当前分配内的实例、库、表 | 令牌与分配共同覆盖的已开放库表 |

- DEVTOOL 不接受业务域、资源类型、具体应用或日志库、独立环境限定以及包含后续资源的授权字段。SLS/ARMS 是操作许可，不是两套资源目录。
- 同一仓的不同环境后缀各构成独立应用，但成员范围统一依据仓事实派生，不另建环境 grant。生产与非生产声明只决定连接路由。
- 工具族授权树不展开应用；当前范围由同步后的代码仓成员事实展示，完整 appName 在调用时按仓名前缀重新判定。发现新目标不自动创建 grant，也不修改令牌。
- 数据库实例或库分配继续覆盖其下之后开放的表；未开放或已删除的对象不可见。数据源业务域与环境仍沿用数据库规则，不因观测模型改变而调整。

### 2.3 分配理由

- 生产数据库的实例、库、表分配必须填写 2–200 字理由；其他分配理由可选且不超过 200 字。
- 观测工具族分配不再以环境作为高风险粒度，也不要求通过生产应用授权理由获得范围。
- 理由记入授权变更记录，不把仓成员同步记作人工分配应用。

### 2.4 有效期与收回

- 分配可长期有效或设置截止日期，新设置的截止日期须晚于当前日期；截止日期当天有效，次日 00:00 起不可调用，不依赖定时清理是否已完成。
- 权限管理员可随时收回分配；撤销、软删除与到期在后续调用中立即拒绝，令牌原选择可以保留为不可用项，不自动改变令牌生命周期。
- 账号停用或离职按门户状态即时拒绝，令牌与分配的自动处理沿用既有生命周期规范。
- 单人可增删，多人批量只追加、不覆盖其他权限；相同领域、对象类型和对象重复分配时更新有效期与理由，不新建重复有效分配。
- 多人分配在被分配人组合锁内原子保存全部变化和授权变更记录；失败整体回滚，成功提交后再通知，避免只保存部分人员或并发重复分配。

### 2.5 通知

- 分配、收回与到期收回按既有消息规则通知被分配人，内容为变化对象、有效期与摘要；分配到期前 3 天发送提醒。
- 通知发送失败不改变已经提交的授权事实，更不能恢复被撤销许可。

### 2.6 工具清单下发

- tools/list 先检查有效用户与有效令牌。SLS/ARMS 已注册工具仅按持有人当前有效工具 grant 与令牌显式工具族选择下发，不查询成员快照是否成功，也不要求存在可访问仓。
- 成员同步未执行、失败、快照过期或当前可访问仓为空，不阻止已获许可且已勾选的工具族进入清单，也不影响其作为生成、编辑令牌的有效选择；工具 grant 撤销、到期或令牌未勾选才使对应工具不下发。
- 下发清单不调用 SLS/ARMS，不以目录、PID、Prometheus 或云能力就绪作为下发前提。SYSTEM 和 DATABASE 继续采用各自的目录与范围规则，不因观测工具调整而扩权。
- 已下发工具不等于已获目标查询许可。每次目录或定向查询仍执行下一节完整实时判定；无有效成员范围不得返回受保护目标或结果，不以空成功掩盖授权失败。

## 3. 调用时授权判定

每次调用均重新判定，不以客户端已下发工具、旧目录或 PID 缓存作为放行依据。任一必需条件失败即拒绝，并按 [调用审计规则](../调用审计/references/audit-rules.md)记录原因。

1. 校验令牌存在、未吊销、仍在有效期内，持有人账号仍启用；遵守单令牌调用频率上限。
2. 校验工具属于当前已注册执行能力，并被令牌显式选择；不受支持或排除的 scope 不生效。
3. SYSTEM 工具不要求管理员预分配，仍按工具自身的功能、数据与身份校验执行，不能借令牌扩大业务权限。
4. DEVTOOL 工具要求相应有效工具 grant 与令牌选择同时成立。完整 appName 去除环境后缀后必须精确匹配当前有效仓成员范围中的唯一代码仓。
5. DEVTOOL 每次检查成员状态、至少浏览者角色、已知到期、唯一有效门户映射、代码仓及成员快照均未超过 24 小时，并按[域及项目管理 · 执行映射](../../研发管理/域及项目管理/references/business-rule.md#execution-mapping)确认仓仍存在至少一条有效且所属项目启用未删除的关系、仓名无歧义。同仓多项目按仓稳定 ID 去重，不以重复引用判冲突或扩大仓成员范围。
6. 校验 Skills 提供的 group 已在当前 MCP 配置中启用，并校验 appName 后缀与生产或非生产身份匹配；逐次核验本次能力所需云配置、凭据和只读权限。SLS 目录、Prometheus 或 PID 的失败只影响依赖该项的能力，不得扩展为其他能力失败或放宽授权。
7. DATABASE 仍取令牌选择与当前有效分配共同覆盖的库表，检查数据源启用、对象开放与存在、只读约束、脱敏、行数与超时上限；任一不可见表使查询整体拒绝。

- 云端成员移除由下一次该仓成功完整同步确认，确认后后续查询即时失效；不承诺尚未同步时实时得知。同步失败不刷新旧日期，超过快照上限后拒绝；Redis 任务进度保留 72 小时不续期两个授权快照。
- 已知账号停用、工具撤销、工具分配或成员到期即时拒绝，不等待云端同步，也不被任何缓存绕过。
- 应用范围变化不自动添加或删除令牌的工具族选择。工具选择可用不代表用户当前拥有应用范围，更不证明每项云能力就绪。
- 同一 TraceId 关联日志与调用链时仍须同一已核验连接、同一完整应用；额外应用必须分别满足当前授权，不隐式跨应用或环境。

## 4. 业务系统身份透传

- 业务工具使用令牌持有人身份及其自身契约执行，不以权限管理员、同步服务或云账号身份扩大用户的业务权力。
- 产研业务身份与局部参与关系引用[产研人员管理 · 身份](../../研发管理/产研人员管理/references/business-rule.md#identity)及[权限边界](../../研发管理/产研人员管理/references/permission-rules.md#boundaries)，不能自动授予 SLS、ARMS 或数据库权限，不能取代工具 grant、令牌选择与真实成员快照。
- 禁用产研人员只影响其相应业务身份，不等于门户账号停用、自动吊销令牌或撤销全部 MCP；门户账号确已停用或离职时仍按原生命周期即时拒绝。
- 现有业务系统的功能与数据权限，包括行、列范围仍由业务系统判定。默认可选不等于默认可执行所有业务操作。
- 业务拒绝按业务系统拒绝记录；本模块只进一步收窄接入范围，不替换工具自身权限校验。

## 5. 限流

- 单令牌默认每分钟最多 60 次调用，超出即拒绝。
- 数据库沿用实例级行数与超时上限；观测查询沿用工具时间窗、分页、响应截断与公共能力调查预算。
- 无范围、未就绪、未知字段或角色事实不足不能通过补零、空成功或切换环境规避拒绝。
