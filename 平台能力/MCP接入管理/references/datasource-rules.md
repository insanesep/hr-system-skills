# MCP接入管理 · 数据库只读查询规则

> 本文件为数据库领域的唯一规则真源：数据源登记、库表开放、只读约束、行数与超时上限、敏感字段脱敏、异常场景。
> 库表如何分配给人员见 [permission-rules.md §2](permission-rules.md#2-权限分配)；调用时授权判定顺序见 [permission-rules.md §3](permission-rules.md#3-调用时授权判定)；查询审计见 [audit-rules.md](audit-rules.md)。

---

## 1. 数据源登记

- 登记项：实例名称（唯一）、数据库类型（MySQL / PostgreSQL）、环境（生产 / 预发 / 测试 / 开发）、业务域（枚举同 [devtool-rules.md §2.1](devtool-rules.md#21-业务域)）、连接地址、只读账号、所属业务系统、负责人、单次返回行数上限、单次查询超时、启停
- **只读账号由 DBA 预先创建并仅授予查询权限**；平台不接受具备写入权限的账号，登记时执行连通性与权限探测，探测到写入权限则拒绝保存
- 只读账号密码加密保存，任何页面不回显明文，编辑时留空表示不修改
- 生产环境实例建议登记只读副本地址，避免查询影响主库
- 实例登记成功后执行「同步库表」，拉取库、表、字段清单与字段注释；之后可手动重新同步，新出现的库表默认**不开放**

## 2. 库表开放

- 开放粒度：库 / 表；数据源管理员决定哪些库表允许被分配，未开放的库表不出现在权限分配与令牌授权的可选范围中
- 库开放后，库内表默认跟随库开放；单表可单独设为不开放（如账号、密钥类表）
- 是否分配给某人由权限管理员在权限分配中决定，见 [permission-rules.md §2](permission-rules.md#2-权限分配)
- **未分配或未开放的库表对令牌完全不可见**：库清单、表清单、表结构工具均不返回；查询语句引用任一不可见表即整条拒绝
- 关闭开放立即生效，分配记录保留，重新开放后恢复；同步后已不存在的库表标记「已删除」，相关分配与授权自动失效

## 3. 只读约束

- 仅允许单条只读查询语句（查询与表结构查看）；写入、删除、结构变更、权限变更、事务控制、多语句、调用存储过程一律拒绝
- 禁止访问系统库与系统元数据表（如权限表、账号表），表结构信息只能通过表结构工具获取
- 查询所引用的全部表必须均在令牌授权范围内（含子查询、关联查询中的表）

## 4. 行数与超时上限

- 单次返回行数上限：每个实例可配置，默认 1000 行，最大 5000 行；结果超出上限时截断返回，并附提示「结果已截断，仅返回前 N 行」
- 单次查询超时：每个实例可配置，默认 10 秒，最大 30 秒；超时即中止查询并返回「查询超时」
- 上限只能由数据源管理员在数据源上配置，令牌与客户端不能突破

## 5. 敏感字段脱敏

- 数据源管理员在数据源详情中为字段绑定脱敏规则；脱敏规则复用用户权限中心的脱敏规则库，本模块只维护「字段 ↔ 规则」绑定，不另建算法
- 绑定后，该字段在任何查询结果中均按规则脱敏后返回，包括别名、表达式直接引用该字段的情况；表结构工具仍正常展示字段名与类型
- 对已绑定脱敏的字段做条件筛选允许执行，但结果中该字段仍为脱敏值
- 同步库表时，字段名或注释命中常见敏感词（手机号、身份证、银行卡、密码、住址、邮箱）的字段标记「疑似敏感」，提示管理员确认绑定；未绑定前不阻断开放
- 通过 MCP 不提供明文查看通道

## 6. 异常场景

| 场景 | 处理 |
| ---- | ---- |
| 登记时连接失败 | 提示「连接失败：{原因}」，不保存，可修改后重试 |
| 登记时探测到写入权限 | 提示「该账号具备写入权限，请更换为只读账号」，不保存 |
| 实例运行中不可达 | 查询返回「数据源不可用」，数据源列表连通状态标红；不自动停用 |
| 同步库表失败 | 保留上次同步结果，提示失败原因，可重试 |
| 数据源停用 | 所有令牌对该实例的调用拒绝，授权关系保留 |
