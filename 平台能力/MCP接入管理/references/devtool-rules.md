# MCP接入管理 · 研发工具规则

> 本文件定义 SLS/ARMS 工具许可、研发代码仓与成员同步、目标识别和查询边界。令牌与数据库规则分别见业务规则、权限规则与数据源规则。

## 1. 目标应用与工具族

- DEVTOOL 只分配 SLS 日志和 ARMS 应用监控两个工具族。管理员不逐应用、逐环境或逐业务域授权。
- 完整应用名由项目代码服务仓名加 dev、test、pre、gray、prod 后缀组成；每个完整名称都是独立查询目标，预发与灰度不能互换。
- 用户须同时具备有效工具分配、令牌显式选择和目标代码仓有效成员身份。仓成员只提供目标范围，不自动产生工具分配。
- ARMS 不通过全量应用枚举建立权限目录，也不把 PID 作为所有能力的统一前置条件。

## 2. 项目与代码仓真源

- 功能排期项目配置维护 harness 工程和代码服务仓列表。harness 是需求、文档与 Skills 真源，不自动成为研发应用仓。
- 代码服务仓列表是研发范围唯一真源；同步只处理有效云效仓 ID。通用 Git 或其他非云效仓可继续服务排期能力，但不参与云效成员同步。
- 同一代码仓只能属于一个启用项目；同一仓名对应多个有效云效仓时拒绝按名称选择，不能取首项。
- 项目不维护观测分组。group 由执行 Skills 从目标后端启动模块的 config group 明确识别，服务器只接受当前环境已配置的 group。

## 3. 代码仓与研发成员同步

- 同步逐个读取启用项目的代码服务仓资料，保存仓 ID、精确仓名、所属项目和最近成功同步时间。
- 同步读取云效直接成员和代码组继承成员；角色至少浏览者、状态有效且未到期才属于有效研发成员。
- 云效字符串身份通过组织资料邮箱规范化后唯一匹配启用门户用户。缺失或重复邮箱不授查询范围，不按姓名、昵称或数字强转猜测。
- 代码仓和成员保存按仓原子执行。成员分页必须完整读取且持续推进，仓资料、分页、成员或用户映射失败时保留旧快照和旧日期，不把失败当空结果，也不误删旧成员。
- 成功完整成员同步后，云端不再出现的成员标记移除并清空门户用户关联；下一次查询立即失效。部分或全部仓失败时手工同步返回失败，定时任务失败并触发告警，不把部分结果报告为完整成功。
- 同步不访问 SLS，不调用 GetLogStore，不枚举 ARMS 应用，不解析 PID，也不创建或调整工具 grant 与令牌范围。
- 每日 02:00 自动同步并支持管理员手动同步。代码仓和成员快照超过 24 小时后默认拒绝查询。

## 4. 查询目标解析与授权

- 调用方传入 Skills 从目标代码识别的 group，以及完整 appName。group 不是授权维度，但必须存在于当前 MCP 环境的服务器配置中。
- 服务器从 appName 去除末尾环境后缀得到 repoName，必须精确匹配一条正常、无冲突且快照新鲜的代码仓记录。
- 每次查询实时复核门户账号、工具分配、令牌选择、仓成员状态与到期、项目启用状态、仓仍属于项目、仓名唯一性及 MCP 环境身份。
- appName 后缀只用于生产或非生产连接路由，不形成用户独立环境授权。调用方不能覆盖地域、PID、云资源坐标、Prometheus 实例或凭据。
- group、repoName、appName 或连接身份不合法时先于云查询拒绝，不换 group、应用或环境兜底。

## 5. SLS 查询

- SLS 列表在用户显式调用时读取 group 对应 SLS Project，并按当前可访问代码仓的精确 repoName 前缀及连接环境过滤；不是后台同步产物。
- 已知 appName 时使用 GetLogStore 定向核对目标；失败只影响该次 SLS 能力，不自动否定 ARMS 精确查询。
- 日志查询固定为只读并执行关键字转义、时间窗、分页、返回量和脱敏限制。空结果、截断或不完整不能证明没有错误。
- 日志目录可见性不是授权证据；每次实际查询都重新执行完整权限和仓成员校验。

## 6. ARMS 查询

- Trace 搜索直接使用完整 appName，GetTrace 只返回目标应用可验证归属的 Span 子集，不扩展其他应用。
- slow_api、Trace、告警、容器指标和 JVM Prometheus 指标不做 PID 前检。
- 只有原始 appstat.vm 指标或 JVM 诊断兜底按完整 appName 定向解析唯一 PID。成功匹配可短期缓存；认证、权限或歧义失败不得写负缓存。
- Prometheus 用户、group 对应实例、地域和凭据由服务器维护。namespace 由环境后缀与 group 按部署约定推导，Pod 按 repoName 精确限定。
- 单项能力缺少 Prometheus、PID 或云权限时只报告该能力失败，不补零、不把空值解释为健康，也不连带否定其他能力。

## 7. 异常处理

| 场景 | 处理 |
| ---- | ---- |
| 非云效代码仓 | 不参与成员同步，不作为观测查询范围 |
| 同仓属于多个启用项目 | 标记冲突并拒绝同步和查询 |
| 多个云效仓使用相同仓名 | 标记冲突并拒绝按 appName 前缀选择 |
| 成员或仓快照超过 24 小时 | 拒绝查询，等待成功同步 |
| group 未配置或环境不匹配 | 在云调用前拒绝，不换配置试探 |
| SLS 目录不可用 | 列表或 SLS 查询失败；已知 appName 的 ARMS 查询仍可独立执行 |
| PID 缺失或重名 | 仅依赖 PID 的 JVM 原始指标失败 |
