# MCP接入管理 · 研发工具（SLS / ARMS）规则

> 本文件为研发工具领域的唯一规则真源：阿里云能力依据、业务域与资源目录、SLS 日志检索规则、ARMS 应用监控查询规则、异常场景。
> 权限分配粒度见 [permission-rules.md §2](permission-rules.md#2-权限分配)；阿里云调用契约真源为公共仓「阿里云渠道 · 监控与日志」，本文件不复述接口。

---

## 1. 阿里云能力依据

| 产品 | 资源层级 | 阿里云原生隔离能力 | 已封装的只读能力（阿里云渠道） |
| ---- | ---- | ---- | ---- |
| 日志服务 SLS | Project → 日志库（LogStore） | 授权可细到单个日志库；Project 可加入资源组，资源组可作为授权范围；支持标签鉴权 | Project 发现（跨地域，含资源组）、日志库发现、日志库元数据（含保留天数）、按关键字 + 时间范围 + 级别检索日志 |
| 应用实时监控 ARMS | 地域 → 应用 | 授权可细到单个应用，支持应用名称前缀、应用标签与资源组作为授权范围；只读与修改权限分离 | 按地域列出应用（含资源组、标签）、应用详情、应用拓扑、按 TraceId 查询调用链 |

**结论（本模块采用的方案）：**

- 平台以**统一服务身份**访问阿里云，该身份在阿里云侧仅授予日志只读与应用监控只读权限；不为个人创建阿里云子账号，人员级权限由本平台按「业务域 + 资源」分配控制
- 阿里云的资源组、标签与资源名称仅用作**业务域归属的识别来源**，归属结果以本平台资源目录为准
- 阿里云渠道中的写入能力（创建日志库、创建监控环境等）不得登记为 MCP 工具

参考：[日志服务鉴权规则](https://help.aliyun.com/zh/sls/developer-reference/ram-authentication-rules-1)、[设置资源组以限制查看指定 Project](https://help.aliyun.com/zh/sls/set-resource-groups-to-restrict-ram-users-from-viewing-specific-projects-in-the-sls-console)、[ARMS 应用监控自定义授权策略](https://help.aliyun.com/zh/arms/application-monitoring/security-and-compliance/application-monitoring-attach-custom-policies-to-ram-users)、[ARMS 资源组精细化资源控制](https://www.alibabacloud.com/help/zh/arms/application-monitoring/security-and-compliance/fine-grained-resource-control-using-resource-groups-6)

## 2. 业务域与资源目录

### 2.1 业务域

- 业务域枚举：商品、采购、营运、门店、客服、系统、库存、要货、产研、公共；「公共」承载网关、中间件等跨域共享资源
- 每个研发工具资源（SLS 日志库、ARMS 应用）有且仅有一个业务域与一个环境（生产 / 预发 / 测试）

### 2.2 资源同步

- 资源目录每日 02:00 自动同步，管理员可手动「同步资源」
- SLS：发现全部 Project 及其日志库，记录地域、所属资源组、标签、日志保留天数
- ARMS：按已配置地域发现全部应用，记录地域、所属资源组、标签
- 新发现的资源默认**不开放**；阿里云侧已不存在的资源标记「已删除」，相关分配与令牌授权自动失效

### 2.3 归属规则

资源的业务域与环境按以下优先级判定，先命中者生效：

1. 手工指定（管理员在资源上直接设置）
2. 标签规则：资源（SLS 为 Project，ARMS 为应用）带指定标签时归入对应业务域 / 环境，如标签「domain=store」→ 门店
3. 资源组规则：资源所属阿里云资源组映射到业务域 / 环境
4. 名称规则：资源名称前缀或后缀映射到业务域 / 环境，如前缀「store-」→ 门店、后缀「-prod」→ 生产

- 归属规则由管理员在研发工具资源页维护；规则变更后对全部非手工资源重新计算并展示受影响数量，确认后生效
- SLS 归属单位为 Project，日志库默认继承 Project 的业务域与环境，可在日志库上手工覆盖（用于多域共用一个 Project 的情况）
- 业务域或环境未能判定的资源标记「未归属」，不可开放、不可分配

### 2.4 开放

- 只有已归属且状态为「开放」的资源可被分配和授权
- 关闭开放后，所有分配与令牌中对该资源的访问立即失效，分配记录保留，重新开放后恢复
- 资源业务域或环境变更后，按业务域分配的权限随之重新计算：移出原业务域的资源不再被原分配覆盖
- 资源因归属规则变更变为「未归属」时自动关闭开放

## 3. SLS 日志检索规则

- 仅支持「关键字（TraceId、用户标识、访问路径等）+ 时间范围 + 日志级别」检索，不支持自定义查询与分析语句
- 必须指定一个已授权的日志库；不提供跨日志库或全部日志库检索
- 单次检索时间跨度上限 24 小时，起始时间不得早于该日志库的保留期
- 单次最多返回 100 条，可翻页；结果不完整时返回「结果不完整，请缩小时间范围后重试」
- 日志内容中的手机号、身份证号、银行卡号、邮箱按用户权限中心的脱敏规则掩码后返回

## 4. ARMS 应用监控查询规则

- 应用列表、应用详情、应用拓扑仅返回已授权应用；拓扑中出现的未授权应用节点只展示名称与调用指标，不可进一步查询
- 调用链按 TraceId 查询：结果仅保留已授权应用的调用片段；未授权应用的片段合并为「无权限应用」占位，只保留耗时与层级；若调用链中没有任何已授权应用，拒绝并记录「超出分配范围」
- 拓扑与调用链单次时间跨度上限 24 小时

## 5. 异常场景

| 场景 | 处理 |
| ---- | ---- |
| 同步资源失败（阿里云不可达或服务身份权限不足） | 保留上次同步结果，提示「同步失败：{原因}」，可重试 |
| 资源在阿里云侧被删除 | 标记「已删除」，相关分配与授权失效，令牌详情对应项标「已删除」 |
| 归属规则冲突（同一资源命中多条同级规则） | 按规则列表中靠前者生效，资源上标注「规则冲突」供管理员核对 |
| 日志库保留期内无数据 | 正常返回空结果，不视为失败 |
