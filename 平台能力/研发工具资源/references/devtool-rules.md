# 研发工具资源 · 研发工具规则

> 本文件定义 SLS/ARMS 工具许可、研发代码仓与成员同步、目标识别和查询边界。令牌与数据库规则分别见业务规则、权限规则与数据源规则。

## 1. 目标应用与工具族

- DEVTOOL 只分配 SLS 日志和 ARMS 应用监控两个工具族。管理员不逐应用、逐环境或逐业务域授权。
- 完整应用名由项目代码服务仓名加 dev、test、pre、gray、prod 后缀组成；每个完整名称都是独立查询目标，预发与灰度不能互换。
- tools/list 在有效用户和令牌认证后，只按有效工具 grant 与令牌显式选择下发，不要求成员同步成功或存在可访问仓。实际目标查询须同时具备有效工具分配、令牌显式选择和目标代码仓有效成员身份；仓成员只提供目标范围，不自动产生工具分配。
- ARMS 不通过全量应用枚举建立权限目录，也不把 PID 作为所有能力的统一前置条件。

## 2. 项目与代码仓真源

- 功能排期项目配置维护 harness 工程和代码服务仓列表。harness 是需求、文档与 Skills 真源，不自动成为研发应用仓。
- 代码服务仓列表是研发范围唯一真源；同步只处理有效云效仓 ID。通用 Git 或其他非云效仓可继续服务排期能力，但不参与云效成员同步。
- 同一代码仓只能属于一个启用项目；同一仓名对应多个有效云效仓时拒绝按名称选择，不能取首项。
- 项目不维护观测分组。group 由执行 Skills 从目标后端启动模块的 config group 明确识别，服务器只接受当前环境已配置的 group。

## 3. 代码仓与研发成员同步

### 3.1 手工提交与任务恢复

- 管理员手工同步采用异步任务。POST 通过权限检查并受理后立即返回 taskId，不等待云效读取或逐仓保存完成；受理成功只表示任务已进入队列，不表示同步成功。
- 同一部署环境的手工入口与 SchedulerX 共用同一分布式锁和任务状态。已有 QUEUED 或 RUNNING 任务时，手工 POST 返回同一 taskId，不重复排队或启动；并发提交也只能产生一个活动任务。锁保护完整执行期，不以页面按钮禁用代替服务端互斥。
- GET 状态支持查询最近任务或指定 taskId；最近查询优先返回当前活动任务，没有活动任务时返回最近一次执行任务。查看状态使用研发代码仓查看权限，提交仍要求同步编辑权限，不能借 taskId 绕过权限或跨环境读取。
- 任务进度、阶段统计、失败列表与时间保存在 Redis，最后更新后保留 72 小时，终态进度自完成更新起保留 72 小时；活动任务持续更新。任务记录不是数据库新表，不新增 DDL，也不是授权快照。
- 页面进入或刷新后先读取最近任务，有 QUEUED 或 RUNNING 则绑定其 taskId 恢复轮询；离开页面停止轮询但不取消后台任务。终态停止轮询并刷新仓列表；记录过期或不存在时明确显示无可查询记录，不补造成功。
- 服务重启时，将确认因执行实例停止而中断的 QUEUED 或 RUNNING 任务标为 FAILED，记录安全原因与结束时间，不自动续跑；其他存活实例的任务不得误判失败。旧快照不因重启刷新日期，确认无活动任务后才可重新提交。

### 3.2 阶段与逐仓结果

| 阶段 | 进度事实 |
| ---- | ---- |
| 项目读取 | 读取启用项目及代码服务仓真源，展示已读项目、候选仓与冲突；尚未取得总数时不显示虚假百分比 |
| 仓资料 | 按云效仓 ID 读取精确仓名与项目归属，展示当前仓及已处理仓数 |
| 成员分页与 profile | 完整读取直接成员和代码组继承成员，展示分页推进、已读成员与资料读取进度；不把部分分页当全量 |
| 用户映射 | 规范化组织资料邮箱，唯一匹配启用门户用户，展示有效研发成员与已映射人数 |
| 逐仓保存 | 当前仓资料与可用的完整成员事实按仓事务保存，展示已保存仓数及失败清单；保存仓资料不等于成功取得成员快照 |
| 完成 | 汇总处理、成功、失败与成员映射统计，记录结束时间和最终结果；百分比完成不等于全量成功 |

- 角色至少浏览者、状态有效且未到期才属于有效研发成员。云效字符串身份不得按姓名、昵称或数字强转猜测门户用户；缺失或重复邮箱的明确事实不授查询范围。
- 成员分页必须完整读取且持续推进。仓资料读取失败时保留旧仓与成员快照；分页、profile 或用户映射处理失败时保留旧成员快照与旧成功日期，已成功取得的仓资料可独立刷新。保存失败则回滚该仓事务，不把失败当空结果、不误删旧成员；其他仓已提交的结果保留。
- 只有该仓成功完整同步后，云端不再出现的成员才标记移除并清空门户关联，下一次查询立即失效。映射不足的事实与读取、解析或映射过程失败须区分，不能用异常响应推断成员已移除。
- 全部仓成功才报告 SUCCESS；部分仓失败报告 PARTIAL（部分失败），展示失败仓列表、失败阶段与安全原因；全部失败、全局阶段失败或执行中断报告 FAILED。失败列表保留在任务进度中，不以统计值或受理成功掩盖失败，定时执行的部分或全部失败仍触发失败告警。
- 同步只维护启用项目的云效代码仓和研发成员，不访问 SLS、不调用 GetLogStore、不枚举全量 ARMS 应用、不解析 PID，也不创建或调整工具 grant 与令牌范围。
- 代码仓和成员快照各自在成功同步后 24 小时失效；Redis 任务进度的 72 小时保留期不续期或放宽这两个授权新鲜度门槛。

### 3.3 SchedulerX 与运行取证

- SchedulerX 仍每日 02:00 执行，在调度线程同步完成同一同步流程并报告最终结果，不只提交异步任务后立即报成功。其进度写入同一 Redis 状态，使用同一分布式锁与阶段口径。
- 调度开始时若已有 QUEUED 或 RUNNING 任务，本次调度结果为 SKIPPED，不启动第二次同步；跳过记录关联已有 taskId，但不覆盖活动任务的状态、进度或失败列表。任务锁的生命周期与 Redis 进度保留期分开管理，不能因进度仍保留而阻止后续正常同步。
- 同步日志以 MCP_REPO_SYNC 为关键词，记录 taskId、阶段、计数及完成、partial、FAILED 或 SKIPPED 结果，并每 15 秒记录运行心跳；心跳不增加已完成计数或刷新成功快照日期；不输出令牌、云凭据、原始 profile 或完整邮箱。
- 取证按 taskId 核对任务状态、阶段日志与最终结果；未取得完成日志不能据此判断任务未启动或具体停滞阶段。

## 4. 查询目标解析与授权

- 调用方传入 Skills 从目标代码识别的 group，以及完整 appName。group 不是授权维度，但必须存在于当前 MCP 环境的服务器配置中。
- 服务器从 appName 去除末尾环境后缀得到 repoName，必须精确匹配一条正常、无冲突且快照新鲜的代码仓记录。
- 每次查询实时复核门户账号、工具分配、令牌选择、仓成员状态与到期、项目启用状态、仓仍属于项目、仓名唯一性及 MCP 环境身份。
- appName 后缀只用于生产或非生产连接路由，不形成用户独立环境授权。调用方不能覆盖地域、PID、云资源坐标、Prometheus 实例或凭据。
- group、repoName、appName 或连接身份不合法时先于云查询拒绝，不换 group、应用或环境兜底。

## 5. SLS 查询

- SLS 列表在用户显式调用时读取 group 对应 SLS Project，并按当前可访问代码仓的精确 repoName 前缀及连接环境过滤；不是后台同步产物。
- 已知 appName 时使用 GetLogStore 定向核对目标；失败只影响该次 SLS 能力，不自动否定 ARMS 精确查询。
- 日志查询固定为只读并执行关键字转义、时间窗、分页、返回量和脱敏限制。空结果、截断或不完整不能证明没有错误。
- 日志目录可见性不是授权证据；每次实际查询都重新执行完整权限和仓成员校验。

## 6. ARMS 查询

- Trace 搜索直接使用完整 appName，GetTrace 只返回目标应用可验证归属的 Span 子集，不扩展其他应用。
- slow_api、Trace、告警、容器指标和 JVM Prometheus 指标不做 PID 前检。
- 只有原始 appstat.vm 指标或 JVM 诊断兜底按完整 appName 定向解析唯一 PID。成功匹配可短期缓存；认证、权限或歧义失败不得写负缓存。
- Prometheus 用户、group 对应实例、地域和凭据由服务器维护。namespace 由环境后缀与 group 按部署约定推导，Pod 按 repoName 精确限定。
- 单项能力缺少 Prometheus、PID 或云权限时只报告该能力失败，不补零、不把空值解释为健康，也不连带否定其他能力。

## 7. 异常处理

| 场景 | 处理 |
| ---- | ---- |
| 非云效代码仓 | 不参与成员同步，不作为观测查询范围 |
| 同仓属于多个启用项目 | 标记冲突并拒绝同步和查询 |
| 多个云效仓使用相同仓名 | 标记冲突并拒绝按 appName 前缀选择 |
| 成员或仓快照超过 24 小时 | 拒绝查询，等待成功同步 |
| group 未配置或环境不匹配 | 在云调用前拒绝，不换配置试探 |
| SLS 目录不可用 | 列表或 SLS 查询失败；已知 appName 的 ARMS 查询仍可独立执行 |
| PID 缺失或重名 | 仅依赖 PID 的 JVM 原始指标失败 |
