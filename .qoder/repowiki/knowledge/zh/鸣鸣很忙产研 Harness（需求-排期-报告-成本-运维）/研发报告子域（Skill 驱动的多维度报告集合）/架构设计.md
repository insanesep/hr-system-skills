本目录按「一个三级子域 = 一份 Skill」划分，每个报告模块均遵循同一骨架：SKILL.md 声明触发规则与数据源，assets/app 与 assets/web 分别承载 App 端与 Web 端的列表/详情原型，references 下存放业务规则、数据模型与 UI 规范等真源。

跨子域的编排关系：
- 报告配置（report_configuration）是共享层，集中维护报告类型、命名、周期索引、触发生成入库、版本渲染权限等真源，其他三个报告模块通过引用其 business-rule/data-source-api 接入统一生命周期。
- 各报告模块之间不直接互相调用，而是通过配置中心的「报告类型 + 周期索引」作为间接契约；新增报告只需在配置中心注册类型并在自身 SKILL.md 中声明触发条件。
- 前端呈现采用双端分离：Web 端由配置中心托管的 project-config.html / report-trigger-config.html 提供全局管理入口，App 端由各报告模块自行提供的 report-list/report-detail 页面负责查阅。
- 文档一致性报告是唯一由服务端通过 Qoder SDK 会话主动生成并归档的报告，其余报告依赖配置中心的触发生成流程。
