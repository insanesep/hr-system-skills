# 错误日志管理

> 归属：运维管理

## 目标

基于日志平台的应用日志，每日凌晨自动扫描**前一天全天**所有 `ERROR`（含 `FATAL`）日志，按指纹聚合后落库为「每日日志异常报表」。研发在 Web 端「运维管理 → 错误日志管理」页面：

- 查看每日异常分组、出现次数、首次/最后一次发生时间、traceId 样例
- 查看完整日志详情、跳转日志控制台
- 标记已处理 / 撤销标记，附备注与处理人
- 导出报表（接入统一导出中心）

## 端

仅 **Web 端**（管理后台）。App 端不做。

| 端 | 范围 | 目标用户 |
|---|---|---|
| Web | 运维管理 → 错误日志管理：列表页 + 详情抽屉 + 标记处理弹窗 | 研发、运维、技术负责人 |

- [项目管理 · 身份](../../研发管理/项目管理/references/business-rule.md#identity)及[权限边界](../../研发管理/项目管理/references/permission-rules.md#boundaries)：产研职责身份只读引用，不替代菜单及标记、重跑、导出权限，不改写处理人与历史经办快照。
- [项目管理 · 清单](../../研发管理/项目管理/references/business-rule.md#source)及[执行映射](../../研发管理/项目管理/references/business-rule.md#execution-mapping)：仅已确认基础归属，无项目证据只域级；应用、环境、日志库与 SLS Project 仍是原日志配置，SLS Project 不是业务项目，不由参与关系自动授权。

## 名词约定

| 名词 | 定义 |
|---|---|
| 异常日志 | `level=ERROR`（含 `FATAL`，按 ERROR 处理）的单条日志记录 |
| 异常分组 | 按指纹聚合后的同源异常，主键为「日期 + 指纹」 |
| 指纹（fingerprint） | 由「应用名 + 异常类名 + 归一化异常消息 + 顶层堆栈行」生成的固定长度摘要，用于把「同一类报错」折叠为一条 |
| 报表项 | 落库后的一条聚合记录，即异常分组的一天快照 |
| 标记已处理 | 研发或运维主动把某条报表项标记为已处理，附「备注 + 处理人 + 处理时间」 |

## 业务流程

**采集链路（系统）**：每日凌晨定时任务触发 → 计算前一自然日时间窗（本地时区）→ 分页拉取 ERROR/FATAL 日志 → 计算指纹 → 聚合 → 落库（保留处理状态）→ 命中阈值时触发企微告警 → 任务执行留痕。任务参数与执行细节以代码仓为准，不内嵌。

**使用链路（研发）**：Web「运维管理 → 错误日志管理」→ 顶部统计卡 + 筛选区（日期/应用/状态/关键字）→ 命中行 → 详情抽屉看 traceId 样例 + 原始堆栈 → 跳转日志控制台 → 修复后回页面「标记已处理」或「忽略」。

## 业务规则

1. **数据来源**：默认按「应用名-环境」定位日志库；多应用/多日志库通过配置列表枚举接入
2. **时间窗**：以日志原始时间戳为准，按本地时区切日，避免跨日截断；任务执行时间晚于窗口结束至少 30 分钟，防日志写入延迟丢数据
3. **指纹归一化**：异常消息中的数字、UUID、时间戳、IP、十六进制串统一替换为占位符；堆栈仅取最顶层非框架行（过滤 JDK 与框架包）；归一化规则字典以代码仓为准，新增规则需回归验证
4. **聚合维度**：「日期 + 应用名 + 指纹」三元组唯一，为落库业务主键
5. **样例字段**：traceId 样例最多保留前 5 个（按出现先后）；异常消息与堆栈各保留首次原始内容（超长截断）
6. **状态机**：`待处理 ──标记已处理──▶ 已处理 ──撤销──▶ 待处理`；`待处理 ──忽略──▶ 已忽略`（噪声不再统计告警，但保留记录）
7. **静默丢数据防控**：查询失败、解析失败、落库失败均必须打 ERROR 日志并标记任务失败，严禁吞异常
8. **重跑幂等**：支持手动指定日期重跑；重跑只更新统计字段，处理状态（已处理/已忽略）独立存储**不被覆盖**
9. **租户隔离**：运维内部能力，不挂租户字段；页面访问受权限控制（仅运维管理菜单可见者）
10. **保留期**：报表项保留 90 天，超期由独立清理任务每日删除（禁止与采集任务串联）

## 数据模型

核心表为日志异常日报表，字段分三组（表结构与索引以代码仓为准，不内嵌）：

| 维度 | 字段 |
|---|---|
| 业务幂等键（唯一） | 日期 + 应用名 + 指纹 |
| 统计快照（重跑可覆盖） | 异常类 / 异常消息 / 出现次数 / 首次与最后发生时间 / traceId 样例 / 消息与堆栈样例 / 日志库 |
| 处理快照（重跑禁覆盖） | 状态 / 处理人 / 处理时间 / 处理备注 |

## 页面功能概览

| 页面 | 职责 |
| ---- | ---- |
| 报表列表 | 统计卡（异常分组数/出现总次数/待处理/已处理/已忽略）+ 日期/应用/状态/次数下限/关键字筛选 + 分组表格 + 手动重跑 + 导出 |
| 详情抽屉 | 聚合统计 + traceId 样例（跳日志控制台）+ 消息样例 + 折叠堆栈 |
| 标记弹窗 | 标记已处理 / 忽略共用，备注必填 |

权限：菜单挂「运维管理」；标记已处理/撤销、忽略、手动重跑、导出四个动作分别受按钮权限控制，默认授给管理员与研发负责人角色。页面原型见 `assets/`（仅视觉与交互锚定）。

## 通知集成

报表项命中告警阈值时经企微应用消息告警，受全局开关控制；触发条件、消息模板、字段约束、失败兜底见 [references/wecom-alert.md](references/wecom-alert.md)。

- [ ] 日志查询失败时任务失败重试且可观测

- [ ] 进入「运维管理 → 错误日志管理」，默认看到昨天的待处理列表
- [ ] 顶部统计卡数字与列表待处理行数一致
- [ ] 点击异常分组进入详情抽屉，能看到 traceId 样例 + 原始堆栈

## 风险与边界

| 风险 | 控制措施 |
|---|---|
| 单日 ERROR 日志爆量拖垮任务 | 单日志库单日落库上限保护；超限只取前 N 条并告警 |
| 指纹归一化漏掉变量字段导致同源被拆成多组 | 归一化规则统一维护（以代码仓为准），每次新增规则需回归测试 |
| 日志写入延迟导致任务漏数据 | 任务时间晚于窗口结束至少 30 分钟；漏数时按日期手动重跑补数 |
| 状态字段被重跑覆盖 | 业务唯一键 + 重跑仅更新统计字段 |
| 操作日志要素缺失 | 评审时强制核对 |
| 历史日志没有结构化堆栈字段 | 无结构化堆栈的历史日志以消息样例兼容 |

## 反模式

- ❌ 在接口层循环查日志平台（必须由任务落库后查库）
- ❌ 把状态字段写进唯一键（导致重跑覆盖处理状态）
- ❌ 吞异常不处理、不上报（静默丢数据）
- ❌ 自起文件上传实现导出（必须接统一导出中心）
- ❌ 文档内嵌 SQL / 代码片段 / 接口报文（实现细节以代码仓为准，见根 AGENTS.md 内容红线）
