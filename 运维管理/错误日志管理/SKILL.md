# 错误日志管理

面向研发与运维的异常日志聚合处理台：每日自动扫描前一日全部 `ERROR/FATAL` 日志，按异常指纹聚合成报表，研发在 Web 端查看分组、趋势与详情并标记处理，替代在海量原始日志里翻找问题。

## 服务对象与端

- **服务对象**：研发、运维、技术负责人
- **仅 Web 端**：管理后台运维域

## 核心逻辑

### 采集聚合（系统每日执行）

- 时间窗：以前一日 0:00~23:59（本地时区）日志原始时间戳为准；任务执行晚于窗口结束至少 30 分钟，防日志写入延迟丢数据
- **指纹归一化**：异常消息中的数字、UUID、时间戳、IP、十六进制串统一替换为 `*`；堆栈仅取最顶层非框架行（过滤 JDK/框架包）；指纹 = `MD5(应用名 + 异常类名 + 归一化消息 + 顶层堆栈行)`，32 位
- **聚合主键**：`日期 + 应用名 + 指纹` 三元组唯一；样例字段保留前 N 个 traceId、首次原始 message 与 stackTrace（截断上限）

### 处理状态机

`待处理 ──标记已处理──▶ 已处理 ──撤销──▶ 待处理`；`待处理 ──忽略──▶ 已忽略`（噪声不再统计告警但保留记录）。标记附备注 + 处理人 + 处理时间。

### 关键规则

- **重跑幂等**：支持指定日期重跑；统计字段可覆盖，**处理状态字段独立列存储不被覆盖**
- **静默丢数据防控**：查询/解析/落库失败必须打 ERROR 日志并标记任务失败，禁止吞异常
- **告警**：命中阈值（单指纹次数/新指纹出现）触发 IM 通知
- **保留期**：报表保留 N 天（如 90），独立清理任务每日执行，禁止与采集任务串联
- **分工**：本模块 = 每日全量异常聚合（只读分析 + 手工标记）；`运维管理/黑灯工厂管理` = 已分诊定级定人的问题流程闭环；同一指纹两边可现，互相引用不重复展开

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 页面 | 职责 |
| ---- | ---- |
| 报表列表 | 日期/应用/状态/关键字筛选 + 统计卡（新增指纹数/总次数/已处理率）+ 分组表格（次数、首末次时间） |
| 详情抽屉 | 异常类/归一化消息/原始堆栈样例/traceId 样例 + 日志控制台 deeplink 跳转 + 标记/忽略弹窗 |

## 关键约束

- 多应用/多日志库通过配置枚举接入，不写死
- 导出接入统一导出中心，禁止自起文件上传
- 页面访问受权限控制（运维域菜单可见者）

## 关联模块

| `运维管理/服务器监控` | 异常快照联动的数据源之一 |
| `研发报告/故障报告` | 故障证据引用源 |
