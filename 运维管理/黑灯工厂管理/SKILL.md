# 黑灯工厂管理

黑灯工厂三个 agent(错误日志自动修复 / 大SQL结果集修复 / 服务端bug扫描)每 3 小时一轮巡检的**产出收口模块**:agent 完成分诊后,把 P1/P2 条目自动建成工单——已自动修复推送的进「待复核」、没办法安全判断的按代码负责人「待认领/已指派」、业务确认不用动的「知会留痕」;研发在 Web 端完成认领 → 处理 → 复核 → 关闭的闭环。通知走**工单 + 企微应用消息按人提醒**;群机器人仅保留采集/建单失败简报。三个 agent 均**运行于服务端,由 Qoder SDK 创建定时调度会话驱动**,配置与凭证由服务端注入会话上下文(手册见下表 agent 三份)。

其中「服务端bug扫描」agent 在报错分诊之上叠加**需求口径对照**:从 SLS 日志提取错误后,按项目映射定位对应项目的 harness 工程与业务代码,评估「是不是缺陷、能不能直接修」——能安全修复的直接改代码进待复核,需人为确认的按待判断/业务确认建单(手册见 [references/agent-bug-scan.md](references/agent-bug-scan.md),口径见 business-rule §10)。

**人工报 bug 入口**不在本模块:任何人发现 bug 走「排期管理/需求管理」提交需求类型=缺陷修复的单据,审批通过后自动向本模块建单分流(来源 `reqdefect`),本模块不提供手工新建。

> 与「错误日志管理」(日志异常报表)分工:报表 = 每日全量异常指纹聚合趋势(只读分析 + 手工标记);工单 = agent 已分诊定级定人的问题**流程闭环**(自动建单 + 状态机 + SLA)。同一指纹可能两边都出现,互相引用不重复展开。

## 端

仅 **Web 端**(管理后台,运维管理菜单)。App 端不做。

| 端 | 范围 | 目标用户 |
|---|---|---|
| Web | 运维管理 → 黑灯工厂工单 列表页 + 详情抽屉 + 处理弹窗 | 后端研发(负责人/认领人)、研发负责人(复核/时效统计) |

## When to Use

- 黑灯工厂 agent 每轮巡检产出需要落库跟踪,而不是发完群消息就沉底
- 服务端 bug 扫描需要对照项目 harness 与业务代码评估 SLS 错误是否为缺陷,并按「直接修复 / 人为确认」分流建单
- 人工发现的 bug 经需求管理缺陷分流审批后自动建单,需要与 agent 巡检产出同一套闭环跟踪
- 待判断问题需要明确到具体研发负责人,跟踪认领与处理时长(SLA)
- 已自动修复的 commit 需要负责人复核确认或打回
- 业务确认类问题需要留痕,避免同一问题每轮重复告警
- 统计黑灯工厂的修复率、响应时长、复发率等运营指标

## Tips

- 工单建单来源四类:三个 agent(错误日志/大SQL结果集修复/服务端bug扫描,经内部上报工具建单)+ 需求管理缺陷分流(`reqdefect`,需求类型=缺陷修复审批通过后自动建单);Web 端不提供手工新建——**人工报 bug 走「排期管理/需求管理」提交缺陷修复单据**
- 只 P1/P2 建单;P3/噪声维持 agent 侧仅计数,不进工单,防刷屏
- 同一问题(同指纹/同 mapper/同需求编号)未关闭前**不重复建单**,只追加出现轮次与最新证据;已关闭后同源复发则原单重新打开并累计复发次数,不另开新单
- 已自动修复项建单即「待复核」状态并带 commit 哈希,复核通过才关闭,打回则重新打开
- 通知走企微应用消息按人提醒;群机器人仅保留采集失败/建单失败简报,详见 business-rule.md §6/§8
- 工单负责人由 agent 侧判定、服务端匹配在职研发及其企微账号后落单,Web 端支持改派
