# 黑灯工厂管理

> 对应脑图「黑灯工厂管理」节点：问题分级分类；特定类别的问题自动化修复。

巡检 agent 产出的收口与闭环模块：黑灯 agent（如错误日志自动修复、大 SQL 结果集修复）每轮巡检完成分诊后，把 P1/P2 问题自动建成工单——已自动修复的进「待复核」、无法安全判断的按代码负责人「待认领」、业务确认不用动的「知会留痕」；研发在 Web 端完成认领 → 处理 → 复核 → 关闭闭环，通知由群机器人泛推升级为**工单 + 按人提醒**。

## 服务对象与端

- **服务对象**：后端研发（负责人/认领人）、研发负责人（复核/时效统计）
- **仅 Web 端**：管理后台运维域

## 核心逻辑

### 问题分级分类（对应脑图）

- 分级：P1（严重，如生产报错高频/资损风险）/ P2（一般，需修复）/ P3（噪声或可暂缓）；**只 P1/P2 建单**，P3/噪声 agent 侧仅计数，防刷屏
- 分类：按来源 agent 与问题类型归类（错误日志类、大 SQL 类等），类别决定是否可走自动化修复

### 特定类别自动化修复（对应脑图）

- 对可安全自动修复的类别（如明确的空指针、典型慢 SQL 改写），agent 直接产出修复 commit 并推送；**已自动修复项建单即「待复核」并带 commit 哈希**，复核通过才关闭，打回则重新打开
- 无法安全判断的按代码负责人（按代码归属/提交历史判定）建单「待认领」，Web 端支持改派
- 业务确认无需处理的「知会留痕」，同一问题不再每轮重复告警

### 建单幂等与复发

- 同一问题（同指纹/同 mapper）未关闭前**不重复建单**，只追加出现轮次与最新证据
- 已关闭后复发才开新单并关联父单（或同单重开 + 复发计数，二选一由实现定稿）；复发次数是「顽疾」识别口径

### 状态机与 SLA

- 三入口态：`待复核`（已修复待确认）/ `待认领`（已指派待处理）/ `知会留痕`；处理闭环：认领 → 处理（解决/忽略）→ 复核 → 关闭
- SLA：认领时长、处理时长、修复率、复发率等运营指标按周期统计
- 通知：IM 应用消息**按人提醒**（负责人/认领人/复核人），替代群机器人泛推；采集/建单失败保留简报通道
- 工单**只由 agent 建单**（内部上报接口），Web 端不提供手工新建——手工问题走问题反馈类模块

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 页面 | 职责 |
| ---- | ---- |
| 工单列表 | KPI 卡 + 筛选 + 表格；默认「我的工单」视图（当前人 = 负责人或认领人） |
| 详情抽屉 / 处理弹窗 | 证据（异常指纹/SQL/堆栈/commit）+ 状态操作（认领/解决/忽略/复核通过/打回/改派）+ 时间线流水 |

## 关键约束

- 负责人与 IM 账号由 agent 侧判定落单（用户体系口径），Web 端可改派
- 列表导出复用统一导出中心
- 与 `运维管理/错误日志管理` 分工：报表 = 全量聚合只读分析 + 手工标记；本模块 = 分诊定级定人的流程闭环；同一指纹两边可现，互相引用不重复展开

## 关联模块

| 模块 | 关系 |
| ---- | ---- |
| `运维管理/错误日志管理` | 指纹口径共享与分工 |
| `运维管理/服务器监控` | 关联快照证据源 |
| `排期管理/需求管理` | bug 类需求分流至本模块自动化修复，结果回写需求 |
| `研发报告/故障报告` | 故障证据与转单来源 |
