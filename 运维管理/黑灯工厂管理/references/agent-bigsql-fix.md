# 大SQL结果集修复 — agent 手册

> 黑灯工厂来源 agent 之二（来源标识 `bigsqlfix`）。本文件为该 agent 的功能实现真源：巡检对象、分诊口径、自动修复边界与建单上报。产出收口与工单闭环见 [黑灯工厂管理](../SKILL.md) 与 [business-rule](business-rule.md)。

## 1. 定位

每 3 小时按项目巡检各服务的**大结果集 SQL 调用点**——一次性把大表 / 大集合查询结果加载进内存的 mapper 调用，是 OOM 与慢查询的主要来源。agent 定位调用点并评估修复方式，**默认只读分诊、仅提工单**；仅项目显式开启自动修复后，能安全修复的才自动改代码并提交推送，其他问题按分类建单。

业务键 = 服务名 + mapper 全限定名：同一调用点未关闭前不重复建单，只追加轮次与最新证据。

## 2. 运行方式

- **服务端运行**：由服务端通过 **Qoder SDK** 创建定时调度会话驱动执行，每 3 小时一轮，按项目拆分执行单元，无 Web 页面、不依赖本机环境
- 项目、harness 工程、代码服务仓与执行/自动修复开关复用功能排期及黑灯工厂项目配置；仅维护 harness 工程、未配置代码服务仓的项目直接跳过
- 当前项目代码仓访问与推送凭证、日志库定位等配置由服务端按项目注入会话上下文；巡检对象清单随代码仓与日志证据自动发现，无需手工维护
- 每个项目独立产出落盘巡检报告（含本轮命中调用点、结论与处置结果），路径随建单上报；单项目失败不阻塞其他项目

## 3. 巡检流程

1. **采集**：汇总当前项目两类证据——SLS 日志中的大结果集 / 慢查询告警，与代码服务仓中无分页、无限量的全量查询 mapper 调用
2. **剔除**：跳过本来源已有未关闭工单、同键已忽略（免打扰）的调用点，只对增量深析
3. **分诊**：读取 mapper 实现与调用链，评估结果集规模、调用频次与内存风险，判定级别与分类，形成修复建议与证据
4. **处置**：默认只读分诊、仅提工单；仅当前项目开启自动修复且符合 §4 修复边界时才允许改代码 commit+push，其余按分类建单
5. **上报**：汇总当前项目本轮 P1/P2 条目，经内部上报工具一次调用批量建单（见 §5）

## 4. 分诊口径与自动修复边界

### 4.1 分级

| 级别 | 判定 |
|---|---|
| P1 | 高频调用或结果集规模已构成 OOM / 超时现实风险 |
| P2 | 存在隐患（量级增长中、低频但无保护） |
| P3 | 结果集有界且可控——仅计数，不建单 |

### 4.2 三分类结论

| 分类 | 判定 | 处置 |
|---|---|---|
| `FIXED_REVIEW` 自动修复待复核 | 项目已开启自动修复，修复为纯粹技术形态且不改变业务语义 | commit+push 后建单（待复核），附 commit 哈希 |
| `PENDING_JUDGE` 待判断 | 自动修复未开启，或修复涉及调用链改造、性能取舍，需负责人裁决 | 按负责人建单待认领，带「建议：」人话结论、修复建议与证据 |
| `BIZ_CONFIRM` 业务确认 | 业务上确需全量（如导出、对账），改不改属口径问题 | 低打扰知会留痕 |

### 4.3 可自动修复的形态（且仅限这些）

**默认仅提工单**：项目自动修复开关默认关闭；关闭时不得创建分支、修改代码、commit 或 push，符合下述形态也转 `PENDING_JUDGE`。仅当前项目显式开启自动修复后，才允许以下修复：

- 全量查询改分页 / 限量查询，调用侧循环批处理
- 大结果集改流式读取
- 查询字段裁剪（只取必要列）

红线：不改变返回数据的业务语义（条数口径、排序、字段含义）；调用方依赖全量语义的不得自动改，转 `PENDING_JUDGE`。

## 5. 建单上报

- 通道：黑灯工厂内部上报工具（建单 / 回复 / 状态流转三能力，devops 内部鉴权）；单项目单轮一次批量调用，单项目失败不阻塞其他项目
- 业务键 = 服务名 + mapper 全限定名；上报内容含级别、分类、服务、标题、摘要、建议、证据（SQL 样例、调用点、趋势）与落盘报告路径
- 幂等由工单侧「来源 + 业务键」唯一键保证，失败重发安全
- 同键工单被忽略后，后续轮次该调用点仅计数不再深析

## 6. 负责人判定与失败兜底

- 负责人判定：mapper 归属代码的提交记录（git blame / log）→ 在职研发 → 其企微账号；判不出则留空待认领
- 采集失败 / 建单失败：通知开关开启时发群机器人简报（每轮最多 1 条，@ 运维负责人）；默认仅记录日志与审计，下轮重试

## 7. 反模式

- 项目未开启自动修复仍修改代码或推送（默认仅提工单红线）
- 自动修改依赖全量语义的调用方（破坏业务口径）
- 只加限量不同步调整调用侧批处理（数据被截断）
- 绕过功能排期另建项目仓库映射，或执行未配置代码服务仓的项目
- 同一调用点每轮重复建单而不走同键追加
- 把有界可控查询也上报建单（工单变报表）
