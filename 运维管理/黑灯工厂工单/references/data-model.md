# 黑灯工厂工单 — 数据模型

> 产品视角的数据模型:定义实体与字段业务语义;表结构、字段类型与索引以代码仓为准,不内嵌。

核心实体为「黑灯工厂工单」与「项目执行配置」(devops 服务自有)。工单字段分四组:业务幂等键 / 内容快照 / 流程状态 / 审计；项目执行配置只保存黑灯工厂开关，基础域项目引用[域及项目管理 · 清单](../../../研发管理/域及项目管理/references/business-rule.md#source)，项目与实现仓、确认路径引用其[执行映射](../../../研发管理/域及项目管理/references/business-rule.md#execution-mapping)，不保存基础真源副本。

## 1. 字段定义

### 1.1 业务幂等键

| 字段 | 业务含义 | 取值规则 |
|---|---|---|
| 来源 | 建单方 | `blacklight`(错误日志黑灯工厂)/ `bigsqlfix`(大SQL结果集修复)/ `bugscan`(服务端bug扫描)/ `reqdefect`(需求管理缺陷分流) |
| 业务键 | 同源问题标识 | 错误日志黑灯工厂与服务端bug扫描 = 异常指纹;大SQL结果集修复 = 服务名 + mapper 全限定名;需求管理缺陷分流 = 需求编号 |

来源 + 业务键全局唯一,是 upsert 幂等锚点(见 business-rule §4)。

### 1.2 内容快照

| 字段 | 业务含义 | 取值规则 |
|---|---|---|
| 级别 | 问题级别 | `P1` / `P2`(只建 P1/P2) |
| 分类 | 工单三分类 | `FIXED_REVIEW` / `PENDING_JUDGE` / `BIZ_CONFIRM` |
| 服务 | 问题所在微服务 | 微服务名 |
| 标题 | 一句话问题 | 必填 |
| 摘要 | 一句话根因/现状 | 可空 |
| 建议 | 人话结论 | 可空;PENDING_JUDGE 必填 |
| commit 哈希 | 自动修复提交 | 项目开启自动修复后产生的 FIXED_REVIEW 工单记录 commit 短哈希；默认仅提工单时为空 |
| 出现次数 | 累计出现次数 | upsert 累加 |
| 出现轮次 | 命中轮次数 | 建单为 1,upsert +1 |
| 证据 | 证据链 | traceId 样例、堆栈、SQL 样例、趋势(滚动保留最近 3 轮) |
| 首次出现时间 | 首次命中时间 | 建单时记录 |
| 最近出现时间 | 最近命中时间 | 每轮命中更新 |
| 报告路径 | 当轮落盘报告位置 | agent 上报 |

### 1.3 流程状态

| 字段 | 业务含义 | 取值规则 |
|---|---|---|
| 状态 | 工单状态 | `OPEN` / `CLAIMED` / `REVIEW` / `REOPENED` / `RESOLVED` / `IGNORED`,默认 OPEN |
| 负责人 | 指派的产研责任人 | 稳定门户身份，候选按当前有效人员与已确认域项目责任关系；为空 = 待认领 |
| 域 / 项目引用 | 已确认的问题归属范围 | 只读引用域及项目管理；无项目证据只保留域级，不将共享实现仓全部归给某项目 |
| 负责人姓名 | 冗余展示 | 随负责人快照 |
| 负责人企微账号 | 提醒通道地址 | 随负责人快照 |
| 认领人 / 认领时间 | 认领信息 | 认领时记录 |
| 处理人 / 关闭时间 | 关闭信息 | 解决或忽略时记录 |
| 处理备注 | 处理/忽略/打回备注 | ≤500 字,取最近一次 |
| 复核人 / 复核时间 | 复核信息 | 复核通过或打回时记录 |
| SLA 截止 | 闭环 SLA 截止时间 | 建单时按级别计算(见 business-rule §7) |
| 复发次数 | 关闭后同源复发重开的次数 | 每次复发重开 +1(见 business-rule §4) |

### 1.4 审计

| 字段 | 业务含义 | 取值规则 |
|---|---|---|
| 工单 ID | 主键 | 系统生成 |
| 工单号 | 展示用编号 | `BL-yyyyMMdd-xxxxx`(按日序列) |
| 创建人 / 创建时间 | 建单信息 | agent 建单与需求管理缺陷分流建单,创建人均记为系统 |
| 更新人 / 更新时间 | 最近修改信息 | 自动维护 |
| 删除标记 | 逻辑删除 | 默认未删除 |

## 2. 重跑（upsert）字段白名单

同业务键重复上报且工单未关闭、执行「存在即更新」时(已关闭单复发重开见 business-rule §4):

- **可更新**（快照类）：出现次数（累加）、出现轮次（+1）、最近出现时间、证据、摘要、建议、趋势、报告路径、更新时间
- **禁更新**（流程类）：状态、负责人/认领人/处理人/复核全组、SLA 截止、首次出现时间、工单编号

## 3. 口径备注

- 出现轮次是复发率的统计基础;复发次数 ≥1 视为顽疾单
- 新建/改派负责人候选与身份引用[产研人员管理](../../../研发管理/产研人员管理/SKILL.md)及[域及项目管理 · 责任关系](../../../研发管理/域及项目管理/references/business-rule.md#responsibility)，责任姓名与企微账号按建单/改派时快照保留。人员离职只按原 §5 处理当前未关闭工单，变更须留痕；不改写历史责任、认领、处理、复核或经办快照，不将禁用产研业务身份等同门户停用
- 不挂账套字段(运维内部能力,全账套共享,与错误日志管理一致)

## 4. 项目执行配置

| 字段 | 业务含义 | 取值规则 |
|---|---|---|
| 项目 | 配置归属项目 | 引用域及项目管理，一项目一份黑灯配置；不复制基础清单或执行映射 |
| 执行开关 | 是否参与三个 agent 的后续自动巡检 | 可执行项目默认开启；关闭后不扫描、不建单，不影响需求缺陷分流与存量工单 |
| 自动修复开关 | 是否允许 agent 修改并提交代码 | 默认关闭；关闭时只读分诊、仅提工单，开启后仍受各 agent 安全边界约束 |
| 通知开关 | 是否发送该项目工单通知 | 默认关闭；与黑灯工厂全局通知开关同时开启时才发送 |
| 更新人 / 更新时间 | 最近配置变更审计 | 自动维护；配置调整记录操作人、时间与变更前后值 |

- 项目有效状态与 harness 范围只读消费域及项目管理，代码服务仓与确认路径按其执行映射限定；停用、删除或无有效执行映射的项目不进入执行范围。
- 代码服务仓为空的项目固定跳过，不创建执行会话；其开关不生效，页面展示跳过原因。
- 未单独保存配置的可执行项目按「执行开启、自动修复关闭、通知关闭」处理；关闭执行时同步关闭自动修复，配置仅影响后续轮次。
