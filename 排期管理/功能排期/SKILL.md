# 功能排期

> 对应脑图「排期管理（for pm,dev）」节点：根据 git 提交自动生成卡片。

面向 PM 与研发的轻量排期工具：研发代码仓的每一次 git commit 自动生成一张待开发卡片，沉淀到待排期池（Backup），PM 拖拽将卡片排到日历指定日期，跟踪「待开发 / 开发中 / 开发完成 / 延期」，完成时可选择性关联研发仓的完成 commit，建立排期与实际交付的回执闭环。

## 服务对象与端

- **服务对象**：PM（排期与跟踪）、研发（领取与完成回执）
- **仅 Web 端**：桌面排期工具，不做移动端适配

## 产品背景

研发仓 commit 流水很细，但 PM 看不见「哪些是新需求、哪些在做、延期了没」；Excel 排期表散落无法与 git 事实对齐；完成与延期靠口述。本模块提供「git commit → 排期卡片」的双向可视化：提交即出卡、拖拽即排期、完成可回执、延期自动识别。

## 核心链路

1. **提交即出卡**：commit 采集（定时任务 / webhook）按仓库配置的路径前缀白/黑名单过滤后自动生成卡片——负责人 = 提交人、标题 = 概括（首行去 Conventional Commit 前缀截取）、内容 = 原文 message；同一 commit 不重复生成（源仓 + hash 唯一约束幂等，删除后不再触发）
2. **拖拽即排期**：待排期池卡片可拖到月历指定日期，跨天移动、拖回池中取消排期均可；不允许排到比今天更早的日期
3. **领取即开工**：状态切「开发中」自动写入开发人与领取时间
4. **完成可回执**：切换「开发完成」时可关联完成 commit（选仓库 → 选/输分支 → 搜索点选，不接受手写 hash；选填，可直接完成），建立交付回执
5. **延期自动识别**：排期截止日已过且未完成的卡片自动呈现延期态（前端渲染态，不落库；仅当月/本周口径，历史期不再标红）

## 编号与状态机

- 卡片编号 `FS-{YYYYMMDD}-{NNN}`：日期取 commit 提交的业务日期，序号同日前缀内递增（行锁保证并发单调），生成后不可变、删除不回收
- DB 四态：`PENDING（待开发）` / `IN_PROGRESS（开发中）` / `DONE（开发完成）` / `NON_FEATURE（非需求改动）`；`延期` 为前端按截止日期计算的渲染态（待开发/开发中均计入）
- 领取 `PENDING→IN_PROGRESS`（写开发人）；取消领取回退（清开发人）；标记完成（来自待开发且无开发人时自动回填当前操作人）；回退 `DONE→PENDING/IN_PROGRESS`（二次确认）
- **DONE 卡锁定**：不可拖拽改期也不可拖回待排期池，需先回退
- **NON_FEATURE 旁路态**：PM 手动「移入非需求改动」（任意状态可移入），清空排期/开发人/完成 commit，不占池与月历；可恢复为待开发；适用于文档类、杂项改动的批量清理

## 关键业务规则

- **区间排期**：卡片支持单日或起止区间；排期锚点字段与起止字段双写联动（只写锚点 → 起止=当日；写起止 → 锚点=开始日；清空排期三字段同清）；月视图按区间重叠检索，跨月区间卡两月可见
- **需求性质**：`业务功能`（默认）/ `技术支持`（文档补录、参数说明、性能优化、工具脚本等非功能性改动）；技术支持卡正常流转完成，作为实施管理聚合分流依据；存量不批量补标，日常编辑顺手勾选
- **业务对接人**：产品手工维护；**排期写入时必填**（拖拽排期/改期时无需求单关联、非技术支持卡且对接人为空则拦截，引导补录后再排期）；豁免：需求单关联卡（预填提交人可改、手改优先）、技术支持卡、非需求改动卡；建卡与纯字段保存不校验；存量不批量回填，下次改期被拦自然收口
- **合并卡**：PM 主动将 ≥2 张同模块的待开发/开发中卡合并为一张（多选或拖拽到同模块卡上触发）：生成新卡，排期日取子卡最早非空值、全空则回池；子卡快照原始状态/排期/开发人；嵌套合并扁平化——新合并卡直接继承全部原始子卡并保留原快照；合并卡上领取/完成/改期同事务扩散所有子卡（不单独写子卡流水）；DONE 后禁止解散，解散按快照恢复子卡、快照日期早于今日则置空回池
- **发版日标记**：日历日期可标记/取消发版日（幂等），用于区分常规排期日与正式发版日；发布管理的落地视图见 `排期管理/发布管理`
- **操作流水**：创建/排期/改期/编辑/领取/完成/回退/删除/合并/解散等每次变更追加一条流水，只增不删，抽屉内倒序时间线呈现
- **手动建卡**：支持选仓 → 搜索 commit → 确认建卡（幂等，已有卡提示并打开）

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 区域 | 职责 |
| ---- | ---- |
| 待排期池 | 未排期卡片分页展示（默认按创建时间倒序），支持收起为窄轨、批量移入非需求改动、创建时间与相对时间提示（超期未排期变色提醒） |
| 月历区 | 周一~周日七列月历，拖拽排期/改期，今日高亮，跨月灰显，单格溢出折叠「+N」，发版日标识 |
| 视图切换 | 月 / 周 / 列表三视图；列表支持排序与行内快捷操作（领取/完成/回退，统一二次确认）；周视图按负责人分行并提示延期数 |
| 筛选与搜索 | 状态/负责人/仓库/模块多选筛选（草稿-应用语义）+「只看自己」快捷开关（提交人或开发人双口径，作用于月历+池+统计）+ 当月关键字搜索（多词 AND 模糊，命中高亮）；均为前端临时态不落库 |
| 卡片抽屉 | 编号/标题/内容/负责人编辑、状态切换、排期修改、完成 commit 关联、需求性质与业务对接人维护、操作流水时间线；合并卡增明细 Tab（子卡只读，提示受父卡控制） |
| 统计条 | 待排期/待开发/开发中/已完成/延期真实计数，可点击快捷筛选 |
| 更多 | 合并卡片多选态、显示密度、非需求改动弹层（含总数徽标）、代码仓配置入口 |

## 关键约束

- 卡片编号只对内部生效，不出现在 commit message；研发仓提交仍按团队约定前缀
- 源仓路径过滤：按仓库配置路径白/黑名单（如只采集业务目录、过滤 `.agents/` 等），采集任务记录扫描/保留/跳过汇总日志
- 完成 commit 关联只接受选择器点选（服务端校验 hash 真实存在于该仓并拼接链接），不接受手写
- 排期约束前后端双守：排期日不早于当日；DONE 锁排期；NON_FEATURE 排期必为空且不可调状态接口；子卡一切操作拒绝并提示先解散父卡；列表查询默认过滤子卡
- 权限最小授予：仅 PM / 研发管理员可见

## 关联模块

| 模块 | 关系 |
| ---- | ---- |
| `排期管理/需求管理` | 需求单单向关联本模块卡片（只读状态）；关联卡业务对接人预填需求提交人 |
| `排期管理/实施管理` | 本模块 DONE 卡按功能聚合成实施卡；实施侧「移入非实施」回写本卡需求性质为技术支持 |
| `排期管理/发布管理` | 发版日标记为发布管理提供日历锚点 |
