# 功能排期

面向产品与项目管理人员的轻量排期工具：将研发代码仓的每一次 git commit 自动生成一张待开发卡片，沉淀到待排期池（Backup 卡片池），PM 通过拖拽将卡片排到日历指定日期，并跟踪「待开发 / 开发中 / 开发完成 / 延期」状态，完成时可选择性关联研发仓的完成 commit，用于闭环回溯。

## 端

**仅 Web 端**（管理后台 Portal 下「系统」分组）。App 端不提供此入口。

## 产品背景

现有 RBAC、使用情况分析解决了「谁能用 / 谁在用」的问题，但研发排期与实际交付之间缺乏可视化锚点：

- 研发仓 commit 流水很细，但 PM 看不见「哪些是新需求、哪些是在做、延期了没」
- 没有统一的排期视图：Excel 排期表散落在 IM 群，无法和 git 事实对齐
- 延期、完成状态靠口述，缺乏与真实 commit 的回执对应

本模块提供「git commit → 排期卡片」的双向可视化：

1. 提交即出卡：新 commit 自动生成一张待开发卡片（白色），默认负责人 = 提交人、标题 = 概括、内容 = 原文 message；若源仓配置了路径前缀白/黑名单（如 Skill 仓只采集 `鸣鸣很忙/`），则仅命中白名单的 commit 出卡
2. 拖拽即排期：待排期池的卡片可拖到月历指定日期，跨天移动亦支持
3. 完成可回执：切换「开发完成」状态时可关联研发仓 git commit（hash + 仓库链接，选填），建立排期与实际交付的回执
4. 延期自动识别：排期日已过且仍未完成的卡片在视图中自动以橙色呈现，PM 一眼看到延期项
5. 项目层级归集：卡片按源仓自动归属到「项目」，PM 可按项目聚焦视图；项目的 harness 工程与代码服务仓映射由管理员在项目配置中维护，供项目进度报告等下游聚合复用同一口径

## 页面结构

参见 `assets/feature-schedule.html`，单页「研发排期工作台」布局：

```
宽屏：
┌─────────────┬─────────────────────────────────────────────────┐
│  待排期池   │ 日期导航 │ 本月进度(行内) │ 搜索/视图/筛选/新建/更多 │
│  独立滚动   ├─────────────────────────────────────────────────┤
│  可收起     │ 月历区（周一 ~ 周日七列，5~6 行）                 │
└─────────────┴─────────────────────────────────────────────────┘

中小屏（笔记本优先）：
┌─────────────┬─────────────────────────────────────────────────┐
│  待排期池   │ 日期导航 │ 搜索/视图/筛选(N)/新建/更多（进度收浮层）│
│             ├─────────────────────────────────────────────────┤
│             │ 月历区；单格最多 3 张卡片，多余折叠为「+N」       │
└─────────────┴─────────────────────────────────────────────────┘
```

- 左侧为待排期池（服务端分页、独立滚动、可收起），右侧为单行指挥栏 + 视图区；指挥栏依次为：时间导航 → 本月进度 → 搜索 → 视图切换 → 筛选(N) → 新建 → 更多
- 页面身份由 Portal 面包屑与页签承担，业务区不重复渲染页面大标题
- 宽屏与中小屏的头部均保持单行：搜索直出于头部；状态 / 负责人 / skills 仓库 / 项目 / 模块筛选统一收进右侧筛选抽屉；「更多」菜单 = 合并卡片 / 显示密度 / 非需求改动 / 代码仓配置
- 本月进度：宽屏行内常驻于指挥栏中部；中小屏收进「进度」浮层，点击显示，浮层内统计项仍可点击快捷筛选
- 搜索框宽度随屏宽分档收缩，不挤压核心操作；较窄的中小屏下视图切换使用短标签（月 / 周 / 列表）
- 低高度屏压缩工具栏纵向间距；窄屏（非目标桌面场景）保底为纵向堆叠布局
- 各浮层默认右对齐，位于左半屏的触发器自动左对齐，均不超出视口
- 页面本身不滚动，日历在视图区内部滚动，工具栏始终可见；月视图每日「最多 3 张 + N」的密度规则在各宽度下一致

卡片抽屉（点击卡片从右侧滑入）：

- 卡片编号（只读）/ 标题 / 内容 / 负责人 / 需求性质 / 业务对接人 / 创建时间（只读）
- 状态切换（待开发 / 开发中 / 开发完成；延期为自动呈现）
- 排期区：起止日期、保存排期、移回待排期
- 「开发完成」态选填：完成 commit（仓库 + hash + 链接）
- 保存 / 删除；底部为操作记录时间线；合并卡另有「明细」页签

## 数据模型

卡片域五个实体（表结构与 DDL 以代码仓为准，不内嵌）：

- **排期卡片主表**：卡片编号、标题、内容、负责人、状态、排期日期（单日锚点与起止区间双写联动：只写锚点则起止=当日，写起止则锚点=开始日，清空排期三者同清）、需求性质（业务功能/技术支持）、业务对接人、开发人与领取时间、完成 commit 回执、合并标识与父合并卡引用；「源仓 + 源 commit hash」唯一约束保证同一 commit 不重复出卡
- **合并卡-子卡明细**：记录子卡合并前的状态/排期/开发人快照；嵌套合并扁平化——新合并卡直接继承所有原始子卡并保留原快照，解散时按快照恢复（快照日期早于当日则置空回待排期池）
- **卡片操作流水**：仅追加不删除；每次状态/排期/字段/存在性变更写一条，页面倒序时间线呈现
- **发版日标记**：日期维度轻量标记，用于区分常规排期日与正式发版日
- **项目**：项目名称（启用中唯一）、harness 工程（1 个，项目的需求/文档真源工程标识）、代码服务仓列表（N 个，引用仓名单中的仓库标识，不重复维护仓信息）、状态（启用/停用）、备注；卡片的源仓命中启用中项目的代码仓列表即归属该项目，归属为查询时动态解析（配置调整即时生效，不做快照）；一个代码仓同一时间至多归属一个启用中项目，未命中任何映射的卡片归入「未归属项目」

## 卡片编号规则

格式：`FS-{YYYYMMDD}-{NNN}`

- `FS`：全局统一前缀，与模块解耦
- `YYYYMMDD`：取 commit 作者提交时间的业务日期（东八区）
- `NNN`：同一日期内全局递增序号，3 位零填充，从 `001` 开始；并发生成时保证同日序号唯一且单调递增
- 示例：`FS-20260507-001`、`FS-20260507-002` 为同日第 1、2 张卡片；次日从 `FS-20260508-001` 重新开始
- 编号一旦生成不可变，卡片删除后序号不回收
- 来源模块标签由 commit 头部解析得到（解析规则以代码仓为准），仅用于分组与统计，不参与编号

## 状态机

```
                    ┌─────────────────────┐
     新 commit ───► │  PENDING（待开发）  │ 白底灰框
                    └──────────┬──────────┘
                     领取开发    │  ▲
                   (开发人=    ▼  │ 取消领取（清空开发人）
                    当前用户)     │
                    ┌─────────────────────┐
                    │ IN_PROGRESS（开发中）│ 紫底 + 左侧紫色强调条
                    └──────────┬──────────┘
                               │ 标记完成（保留开发人）
                               ▼
                    ┌─────────────────────┐
                    │   DONE（开发完成）   │ 绿底 + 左侧绿色强调条
                    └──────────┬──────────┘
                               │  ▲
                    回退待开发 ▼  │ 回退开发中
                    ┌─────────────────────┐
                    │  PENDING / IN_PROGRESS
                    └──────────┬──────────┘
                     手动移入   │  ▲
                               ▼  │ 恢复为待开发
                    ┌─────────────────────┐
                    │ NON_FEATURE（非需求改动）│ 黄底 + 左侧琥珀色强调条
                    └─────────────────────┘
                    约束：清空排期/开发人/完成 commit，不进待排期池与月历

                    视图层计算（不落库）：
                    未完成且截止日（单日卡即排期日）早于今天 → 呈现为「延期」（橙色）
                    口径边界：仅当月视图（月/列表）与本周视图（周）计算延期；历史期不再标红
                    开发中计入延期（与统计口径一致）；开发完成 / 非需求改动排除
```

- 持久化状态为 `PENDING` / `IN_PROGRESS` / `DONE` / `NON_FEATURE` 四种；`DELAYED`（延期）是展示态，对待开发与开发中均生效，按截止日早于今天判定，仅当月 / 本周口径
- 领取开发：`PENDING → IN_PROGRESS` 时自动将开发人与领取时间记为当前操作人，写流水「领取开发」（TAKEN）
- 取消领取：`IN_PROGRESS → PENDING` 时清空开发人信息，写流水「释放开发」（RELEASED）
- 标记完成：`PENDING / IN_PROGRESS → DONE`，完成 commit 选填（可关联一组跨仓 commit，也可不关联直接完成）；来自待开发且无开发人时自动填入当前操作人；写流水「标记完成」（MARKED_DONE）
- 回退：`DONE → PENDING`（清空完成回执与开发人）或 `DONE → IN_PROGRESS`（清空完成回执、保留开发人），均需二次确认，写流水「回退」（REVERTED）
- **开发完成卡片锁定**：不可拖拽改期，也不可拖回待排期池；需改期须先回退状态
- **非需求改动旁路态**：由 PM 在抽屉中点击「🔧 移入非需求改动」手动触发，待开发 / 开发中 / 开发完成均可移入；移入时清空排期、开发人与完成回执；不占用待排期池与月历格，不参与排期 / 领取 / 完成流程；抽屉内只允许编辑标题 / 内容 / 负责人，状态区显示「🔧 非需求改动」提示；点击「↩ 恢复为待开发」恢复为待开发；写流水「编辑」（EDITED）
- 删除卡片需二次确认，删除后源 commit 不会再次触发生成（源仓 + 源 commit 唯一约束保底）

## 交互规范

### 日历与视图

| 操作 | 规则 |
|------|------|
| 月份切换 | `<` / `>` 切换相邻月；中间年月标签点击弹下拉选年月；「今天」按钮回到本月并滚到当日那一周 |
| 日期精度 | 精确到天；跨月视图中上/下月灰显，不可接收拖拽 |
| 今日高亮 | 当日格主色边框 + 主色浅底 |
| 卡片溢出 | 单格超过 3 张折叠为「+N 张」按钮，点击弹出该日全部卡片弹层 |
| 发版日 | 点击日历空白区域（非卡片、非「+N」按钮）切换发版日标记；发版日蓝色背景 + 右上角「发版」标签；再次点击取消 |
| 视图切换 | 月 / 周 / 列表；当前视图与显示密度在本浏览器记忆，刷新后恢复；筛选类状态不记忆 |
| 列表视图 | 列：任务 / 编号 / 模块 / 提交人 / 开发人 / 开始 / 截止 / 状态 / 创建时间；开始、创建时间可排序（空值置底）；点击行打开抽屉；行内快捷操作（需标记完成权限）：待开发→领取 / 开发中→完成（不关联 commit，可在抽屉补录）/ 已完成→回退（保留开发人），统一二次确认 |
| 周视图负责人行 | 负责人列完整显示姓名（开发人优先，否则提交人）；行内「延 N」提示该负责人本周延期卡数（仅本周含今天时展示）；同时显示卡片总数 |
| 区间排期 | 卡片支持起止区间排期（与单日排期日双写联动，见数据模型），跨多日开发可直接排区间；月 / 周视图中区间卡在覆盖的每一天均显示；拖拽移动区间卡时保持时长；月历格「3 张 + 当日 +N」的密度规则不变 |
| 卡片标题换行 | 月历格与待排期池标题均最多两行、超出省略；月历格标题区恒占两行高，模块行恒占位（无模块 / 开发人的卡同高），月历格内所有卡片高度一致；+N 弹层中标题完整换行 |
| 显示密度 | 「更多 → 显示密度」两档，仅作用于月历格卡片：**标准** = 完整信息（标题 / 编号 / 提交人 / 模块 / 开发人）；**紧凑** = 隐藏编号与模块行，仅标题（两行恒高）+ 状态徽章 + 提交人；两档内卡片均严格等高；待排期池、周视图、列表视图不受密度影响 |
| 键盘快捷键 | ← / → 切换上一期 / 下一期；T 回到今天 / 本周；Esc 分层关闭（右键菜单 → 各类确认框 → 弹层 → 月份选择器 / 进度浮层 / 更多菜单 → 筛选抽屉 → 卡片抽屉 → 合并多选态）；输入框聚焦时不响应，弹层打开时 ← / → / T 失效；页面处于后台页签时不响应 |

### 拖拽与排期

| 操作 | 规则 |
|------|------|
| 拖拽起点 | 待排期池卡片、日历格内卡片均可拖拽；开发完成卡片锁定不可拖拽 |
| 拖拽目标 | 另一日期格（排期 / 改期）、待排期池（取消排期）；**只能排到今天或之后**，放到早于今天的日期时提示并拒绝 |
| 拖拽视觉 | 拖起时源卡半透明，目标格显示主色虚线描边 |
| 完成锁定 | 开发完成卡片呈锁定样式，拖起与放下均拒绝并提示；需改期请先回退状态 |
| 右键快捷菜单 | 月历格 / 待排期池 / +N 弹层卡片右键：查看详情 / 改期到今天 / 改期到明天 / 移回待排期；可用条件与拖拽一致（有编辑权限、非开发完成、非非需求改动、非子卡）；以服务端结果为准，失败时提示 |
| 抽屉修改排期 | 排期区为起止双日期选择（禁选今天之前）+ 时长「共 N 天」+「保存排期」+「移回待排期」；开发完成卡显示锁定提示，需先回退。控件规范：日期选择器与按钮统一默认尺寸、同高；按钮常态与输入框同底色，有改动可保存时为主色浅底 + 主色文字；「移回待排期」为次级危险样式（浅红底填充） |

### 卡片视觉

- 四态颜色：待开发 = 白底 + 浅灰细边框；开发中 = 浅紫底 + 左侧紫色强调条；开发完成 = 浅绿底 + 左侧绿色强调条；延期 = 浅橙底 + 左侧深橙强调条
- 非需求改动：浅黄底 + 左侧琥珀色强调条
- 合并卡：浅蓝底 + 左侧深蓝强调条，标题前缀 🔗，右上角角标显示子卡数「N 项」；合并卡处于开发中 / 开发完成时，紫 / 绿状态强调条优先于合并蓝边，背景保留浅蓝以便识别
- 发版日：日期格浅蓝背景 + 右上角「发版」小标签（深蓝字、浅蓝底）
- 模块标签：卡片元信息行显示来源模块蓝色小药丸
- 开发人标签：开发中 / 开发完成卡片在模块行右侧显示紫色「👤 开发人」小药丸

### 统计条

- 统计项：待排期（待排期池总数）/ 待开发 / 开发中 / 已完成 / 延期（当月口径），均为真实数据
- 宽屏常驻指挥栏中部；中小屏收进「进度」浮层，点击显示，浮层内点击不关闭、可连续操作
- 可点击项即快捷状态筛选（再点取消），呈状态浅底胶囊：状态浅色底 + 同色文字 + 全圆角，悬停加深一档，选中为加深底 + 状态色内描边 + ✓；「待排期」不可点击，保持纯文本对照
- 数字保持全局概览，不随筛选缩减

### 当月卡片搜索

- 搜索框直出于头部，占位符「搜索任务：标题 / 编号 / 提交人」
- 输入内容按英文逗号、中文逗号或空格拆分为多个关键字，关键字之间为 AND 关系，模糊匹配卡片的标题 + 内容 + 编号 + 提交人（大小写不敏感）
- 命中的卡片黄框高亮；日历格内未命中的卡片淡化；待排期池中未命中的卡片直接隐藏
- 仅搜当月：当前月历所属月份 + 待排期池全部；切月后关键字保留；按 Esc 清空
- 搜索词与筛选条件相互独立，清空筛选不清除搜索词

### 筛选

- 头部仅保留「筛选(N)」入口，N = 偏离默认值的筛选条件数：skills 仓库非全选、项目非全选、状态、负责人、模块各计 1，「只看自己」开启计 1；搜索词与「全部」默认值不计入
- 点击打开右侧筛选抽屉，自上而下：「只看自己」快捷开关（即时生效）→ 已选条件标签（可单项删除）→ 状态 / 负责人 / skills 仓库 / 项目 / 模块复选组
- 复选组为草稿 / 应用语义：修改只写草稿，「确定」才应用并刷新视图；「取消 / 关闭 / Esc」放弃草稿；「重置」立即清空全部筛选并生效，抽屉保持打开，搜索词不受影响
- 筛选全局生效：状态 / 负责人 / 模块同样作用于待排期池，由服务端过滤，保证分页总数同口径；选中「延期」状态时不命中待排期池卡片
- 筛选或搜索激活且视图零命中时，日历区底部浮出轻量提示「当前筛选/搜索条件下暂无任务 [清空筛选][清除搜索]」
- 筛选类状态均为页面临时状态，不落库，刷新后回到默认

**只看自己**

- 默认关闭；开启后只显示提交人或开发人为当前用户的卡片
- 作用于月历格卡片、待排期池与 +N 弹层；非需求改动弹层不受影响
- 月历格中非本人卡片不渲染（格子保留）；待排期池不显示非本人卡片；统计数字（待 / 完 / 延 / 未排）同步仅统计本人卡片
- 过滤结果全空时月历空日格正常渲染，待排期池提示「没有由你提交的卡片 / 关闭『只看自己』可查看全部」
- 可切月查看历史各月与本人相关的卡片及其领取 / 完成状态

**skills 仓库筛选**

- 默认全部选中（等价不过滤）；首行「全部」+ 分隔线 + 各 skills 仓库（取代码仓名单中标记为卡片池采集源的仓，均无标记时回退为全部研发仓）
- 「确定」后同时作用于月历格卡片与待排期池（按卡片源仓过滤）
- 由服务端过滤：全选或全不选视为全部展示，仅选中严格子集时才按仓过滤，保证待排期池分页总数准确，可与「只看自己」叠加使用

**项目筛选**

- 与 skills 仓库筛选相邻，默认全部选中（等价不过滤）；选项 = 首行「全部」+ 各启用中项目 + 末行「未归属项目」
- 卡片归属按源仓命中项目代码仓列表动态解析
- 应用后同时作用于月历格卡片、待排期池与统计数字，与 skills 仓库、状态 / 负责人 / 模块筛选叠加取交集
- 停用项目自动退出选项集，其代码仓卡片回落「未归属项目」

### 待排期池

| 操作 | 规则 |
|------|------|
| 提交时间行 | 待排期池卡片在元信息行下方显示时间行：左侧「🕒 YYYY-MM-DD HH:mm」（源 commit 提交时间，即卡片创建时间，弱化文字色）；右侧相对时间小药丸（刚刚 / X 分钟前 / X 小时前 / X 天前 / X 个月前 / X 年前），默认蓝色，超过 7 天未排期自动切换为橙色提示；月历格卡片、+N 弹层、非需求改动弹层不展示该行 |
| 收起 / 展开 | 池头右侧收起图标将池收起为窄轨道（展开图标 + 竖排「待排期」+ 计数徽标，整条轨道可点击展开），收起后日历获得横向空间；各宽度均可用，收起状态在本浏览器记忆；窄屏纵向堆叠布局下收起态为横条轨道 |
| 批量移入非需求改动 | 池头「批量」入口进入多选态：卡片显示复选框、点击卡片即勾选，底部悬浮条「已选 N 张 · 取消 / 移入非需求」；二次确认后逐卡移入，单卡失败不影响其他卡，结束后提示成功 / 失败数；适用于文档类卡片批量清理；需编辑权限，与合并多选态互斥，Esc 可退出 |

### 卡片抽屉与状态操作

| 操作 | 规则 |
|------|------|
| 卡片点击 | 右侧抽屉弹出详情 / 编辑 |
| 领取开发 | 抽屉状态切换点选「开发中」；来自待开发时保存后自动填入当前用户为开发人；切回「待开发」则清空开发人；卡片呈紫底并在右下显示开发人 |
| 完成校验 | 开发完成时完成 commit 为选填；填写时必须依次「选仓库（双行：中文名 + 仓库标识）→ 按需改分支 → 搜索 / 浏览 commit → 点选一条」，不接受手写 hash，hash 与链接由选中项自动回填；分支可输可选，候选为仓内活跃分支，默认取该仓配置的默认分支，手改的分支按仓在本浏览器记忆 |
| 完成 commit 摘要折叠 | 开发完成卡抽屉「完成 commit」区：已有 commit 时默认收起为「已关联 N 个完成 commit · 展开选择器」，新标记完成时自动展开 |
| 非需求改动 | 抽屉「🔧 移入非需求改动」手动标为非需求改动，移入时清空排期 / 开发人 / 完成 commit，不进入待排期池与月历；「更多」菜单「非需求改动」弹层展示全部非需求改动卡片（菜单项附总数徽标）；抽屉内点「↩ 恢复为待开发」恢复 |
| 创建时间 | 抽屉展示卡片创建时间（精确到分钟，即源 commit 采集入库时间），不可修改 |
| 操作记录 | 抽屉底部时间线倒序展示卡片操作流水：操作人 · 操作时间 · 行为描述 |

**需求性质**

- 抽屉「需求性质」单选：业务功能（默认）/ 技术支持（技术类、非功能性改动，如文档补录、参数说明、性能优化、工具脚本、changelog 等）
- 创建或编辑卡片时勾选，写「编辑」流水；系统不批量补标，由产品在日常编辑卡片时维护
- 技术支持卡在功能排期侧的状态流转不变（正常完成），仅作为实施排期聚合时「生成即划入非实施区」的分流依据
- 月历与列表不展示性质标识（避免视觉噪音）；合并卡不自动继承子卡性质，按普通卡规则维护

**业务对接人**

- 抽屉「业务对接人」输入框（≤64 字）由产品手工维护；单纯保存字段时随时可改，不拦截
- **排期保存时必填**：凡写入排期（拖拽排期 / 改期 / 右键快捷改期 / 抽屉保存排期，即排期日或起止日由空到有或发生变更）时，若该卡未被任何需求单（REQ）关联、需求性质不是技术支持、且业务对接人为空，则前端拦截、服务端兜底拒绝；拦截后引导打开抽屉补录对接人，补录后再排期
- 豁免：① 已关联需求单的卡片（实施聚合侧以需求单提交人兜底；抽屉输入框仍可编辑，提示「REQ 单提交人：X」，手工填写优先）② 技术支持卡（无业务对接人概念）③ 非需求改动卡（不参与排期，天然豁免）
- 不触发校验：移回待排期（清空排期）、单纯保存字段、合并卡生成时继承子卡排期日（系统派生，后续改期正常校验）；commit 采集自动建卡不校验
- 系统不批量回填：已排期但无对接人的卡片在下次改期时被拦截并补录
- 合并卡不自动继承子卡对接人，按普通卡规则维护

### 合并卡

- **多选合并**：「更多 → 合并卡片」（需编辑权限）进入多选态，月历格 / 待排期池 / +N 日详情弹层内卡片左上角出现复选框；首张勾选后锁定模块，其他模块卡片、已是子卡的卡片、开发完成 / 非需求改动卡片禁用勾选；底部悬浮条提示「已选 {N} 张 · 模块 {xxx}」+「取消 / 确认合并」；至少 2 张且同一来源模块才允许确认，确认后填写合并卡标题（≤30 字）生成合并卡；Esc 或「取消」退出多选态
- **拖拽合并**：非多选态下把一张卡片拖到另一张同模块卡片上（日历 / 待排期池 / +N 弹层均支持），目标卡蓝色虚线高亮；放下后弹出合并标题对话框并生成合并卡；校验同多选合并，跨模块 / 开发完成 / 非需求改动 / 子卡均提示拒绝
- **合并卡排期日**：默认取选中卡片中最早的非空排期日，全部未排期则进入待排期池
- **明细**：抽屉顶部页签「详情 / 明细(N) / 流水」，仅合并卡显示「明细」；明细按并入时间倒序，每行展示子卡标题 / 子卡编号 / 来源模块 / 合并前状态 / 合并前排期日；可点击跳到子卡，子卡抽屉只读并提示「当前隶属合并卡 {合并卡编号}」
- **解散**：合并卡抽屉底部「解散合并」按钮，开发完成状态禁用；二次确认后按合并前快照恢复子卡的状态 / 排期日 / 开发人，快照日期早于今日的清空排期回待排期池；随后删除合并明细与合并卡
- **状态扩散**：合并卡上的领取 / 释放 / 完成 / 回退 / 改排期操作同步写入所有子卡，同成同败；不为子卡单独写流水，合并卡流水注明「扩散至 N 张子卡」；子卡单独打开抽屉时状态 / 排期 / 开发人均只读，提示「受父合并卡 {合并卡编号} 控制」

### 新建卡片与项目配置

| 操作 | 规则 |
|------|------|
| 新建卡片 | 头部「+ 新建卡片」（需编辑权限）：选仓 → 搜索 / 浏览 commit → 单选 → 确认建卡；同一 commit 重复建卡时不新增，提示并打开已有卡片抽屉 |
| 项目配置 | 工具栏入口（需编辑权限），弹层内维护项目台账：列表列 = 项目名称 / harness 工程 / 代码服务仓（逐仓标签）/ 状态 / 操作（编辑、停用 / 启用）；表单校验：项目名称必填且启用中唯一、harness 工程必填、代码仓至少选 1 个且只能从代码仓名单（与「代码仓配置」同源）中多选引用；已被其他启用中项目占用的代码仓在选项上标注其归属项目并禁选（一仓一项目）；停用不删数据，仅退出归属解析与筛选选项；项目增改为管理动作，不影响卡片任何字段 |

## Tips

- 卡片编号只对 PM 内部生效，不出现在 commit message；研发仓提交时仍按团队约定前缀
- 同一 commit 不会重复生成卡片（源仓 + 源 commit 唯一约束保底），如需重跑先删卡片再触发
- 合并卡由 PM 主动创建，不由 commit 触发，也不占用 commit 出卡的唯一性约束
- 嵌套合并采用**扁平化策略**：新合并卡直接继承所有原始子卡，不保留中间层合并卡；原合并卡被删除，原始子卡的合并前快照保留，保证解散时能回到最初独立态
- 合并卡解散时若子卡快照日期已早于今日，统一清空排期回待排期池，避免违反「排期日不得早于今日」约束；PM 需重新拖拽排期
- 合并卡开发完成后禁止解散（保护完成回执语义）；如需解散请先回退合并卡状态
- 子卡的状态 / 排期 / 开发人变更统一经合并卡扩散，不为子卡单写流水，审计以合并卡流水为主；子卡合并前的独立流水仍保留
- 卡片标题默认截取：commit message 首行 → 去掉首个冒号及之前的类型前缀（如 `feat(scope):`）→ 去首尾空白 → 超过 30 字符截断（不加省略号）→ PM 可在抽屉中手改；细则见 [业务规则](references/business-rule.md)
- **源仓路径前缀过滤**：代码仓名单中可为每个源仓配置路径前缀白名单与黑名单（可同时使用，均为空时全量采集）；白名单非空时，commit 的变更路径须至少命中一条白名单前缀；全部变更都落在黑名单前缀下则跳过。用于实现「功能排期仅接收鸣鸣很忙目录的提交，过滤 `.agents/` 等非业务目录」；过滤生效时采集任务记录扫描 / 保留 / 跳过数量的汇总日志（实现以代码仓采集任务为准）
- 待排期池默认按创建时间倒序（最新 commit 排最上）
- 「只看自己」与「当月卡片搜索」均为页面临时状态：不落库、不写入页面地址，刷新或关闭页签后重置；搜索匹配范围即标题 + 内容 + 编号 + 提交人，仅基于页面已载入的卡片，不额外发起查询
- 待排期池卡片的相对时间基于卡片创建时间（源 commit 采集入库时间）与浏览器当前时间差计算，页面保持打开 24 小时以上建议刷新以获得准确相对值
- 延期判定仅在当月 / 本周口径计算，切换到历史期不再标红（历史期已过期，标红无意义）
- 项目归属为查询时动态解析而非出卡快照：调整项目代码仓映射后，历史卡片的归属随之变化，统计与筛选口径始终以当前生效配置为准；这与审批链快照语义相反，属刻意取舍——项目是归集视角而非流程凭证
- 「未归属项目」不是实体项目，仅是筛选项：归集所有源仓未命中任何启用中项目映射的卡片；项目配置完整覆盖仓名单后该选项自然空置
- 项目配置与代码仓名单职责分层：代码仓名单（有哪些仓、默认分支）由运维统一配置维护，项目配置只引用仓标识建立映射，不复制仓信息；仓从名单移除后，引用它的项目映射自动失效并在项目配置弹层标灰提示
- 删除与回退均保留审计：记录最后操作人与操作时间
- 权限最小授予：仅将 `MENU:SYSTEM:FEATURE_SCHEDULE` 授予 PM / 研发管理员，普通运营无此菜单
