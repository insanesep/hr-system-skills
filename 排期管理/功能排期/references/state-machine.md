# 功能排期 · 状态机

> 状态枚举、流转条件、锁定守卫与延期判定的唯一真源。字段默认值与校验见 [field-rules.md](field-rules.md)，动作所需权限见 [permission-rules.md](permission-rules.md)，合并卡的状态扩散见 [business-rule.md §8](business-rule.md#8-合并卡)。

## 1. 状态枚举

| 状态 | 编码 | 落库 | 说明 |
|------|------|------|------|
| 待开发 | `PENDING` | 是 | commit 出卡、手动新建与合并卡的初始状态 |
| 开发中 | `IN_PROGRESS` | 是 | 已领取开发，记录开发人与领取时间 |
| 开发完成 | `DONE` | 是 | 已标记完成，可附完成 commit 回执 |
| 非需求改动 | `NON_FEATURE` | 是 | 旁路态，由 PM 手动移入，不参与排期、领取与完成 |
| 延期 | `DELAYED` | 否 | 展示态，按 §3 计算，不写入卡片 |

## 2. 状态流转

| 动作 | 起始 → 目标 | 入口 | 开发人信息 | 完成回执与排期 | 二次确认 | 流水 |
|------|------------|------|-----------|---------------|---------|------|
| 领取开发 | 待开发 → 开发中 | 详情页「领取开发」；列表视图行内「领取」 | 写入当前操作人与领取时间 | 不变 | 详情页否；行内是 | 领取开发：「领取开发：{姓名}」 |
| 取消领取 | 开发中 → 待开发 | 详情页「取消领取」 | 清空 | 不变 | 否 | 释放开发：「释放开发：{原开发人}」 |
| 标记完成 | 待开发 / 开发中 → 开发完成 | 详情页「标记完成」；列表视图行内「完成」（仅开发中） | 来自待开发且开发人为空时写入当前操作人，其余保留 | 写入完成时间；完成 commit 见 field-rules.md §8，详情页标记完成时选填，行内完成不关联，可在详情页补录 | 详情页经标记完成弹窗确认；行内是 | 标记完成：描述注明是否关联完成 commit |
| 回退为待开发 | 开发完成 → 待开发 | 详情页「回退」选择待开发 | 清空 | 清空完成回执 | 是 | 回退：「已回退为「待开发」」 |
| 回退为开发中 | 开发完成 → 开发中 | 详情页「回退」选择开发中；列表视图行内「回退」 | 保留；卡片无开发人时按回退为待开发处理 | 清空完成回执 | 是 | 回退：「已回退为「开发中」，保留开发人 {姓名}」 |
| 移入非需求改动 | 待开发 / 开发中 / 开发完成 → 非需求改动 | 详情页「更多操作 → 移入非需求改动」；待排期池批量移入 | 清空 | 清空完成回执与排期 | 是 | 编辑：「从『{原状态}』移入非需求改动」 |
| 恢复为待开发 | 非需求改动 → 待开发 | 详情页「恢复为待开发」 | 不变 | 不变 | 否 | 编辑：「从非需求改动恢复为待开发」 |

- 完成回执指完成仓库、commit、链接、完成 commit 列表与完成时间；排期指排期日与起止日
- 开发人信息（开发人、开发人姓名、领取时间）的变化与状态变更同时生效
- 非需求改动只能经「恢复为待开发」回到待开发，不能直接进入开发完成
- 服务端只校验当前状态是否允许该动作，不允许时拒绝；二次确认由前端承担
- 合并卡上的状态动作同步扩散到全部子卡，子卡自身的状态动作一律拒绝

## 3. 延期判定

- **判定**：状态为待开发或开发中，且截止日早于今天；截止日取区间卡的排期结束日、单日卡的排期日
- **范围**：工作台仅当月（月视图、列表视图）与本周（周视图）计算，切换到历史月或历史周不再呈现延期；卡片详情页按卡片自身判定，不受视图范围限制
- **排除**：开发完成、非需求改动与未排期卡
- **呈现**：延期优先于待开发、开发中的状态呈现；统计「延期」与本节同口径，见 [business-rule.md §4](business-rule.md#4-统计口径)
- 不落库，不写流水

## 4. 锁定与守卫

| 卡片 | 约束 |
|------|------|
| 开发完成 | 不可拖拽改期、不可拖回待排期池、不可右键快捷改期；详情页不提供调整排期与移回待排期，需先回退状态 |
| 非需求改动 | 不进待排期池与月历，不参与排期、领取与完成；详情页仅可编辑标题、内容、负责人；编辑时跳过排期校验；标记完成一律拒绝 |
| 子卡 | 状态、排期、开发人只读；领取、释放、完成、回退、改期、移入非需求改动与删除一律拒绝 |
| 开发完成的合并卡 | 不可解散，需先回退合并卡状态 |
