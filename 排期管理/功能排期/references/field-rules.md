# 功能排期 · 字段规则

> 卡片与项目配置字段的默认值、取值与校验规则真源。字段清单与实体关系见 [data.md](data.md)，状态相关的字段写入见 [state-machine.md §2](state-machine.md#2-状态流转)，合并卡各字段取值见 [business-rule.md §8.3](business-rule.md#83-合并卡生成)。

## 1. 卡片编号

- **格式**：`FS-{YYYYMMDD}-{NNN}`，示例 `FS-20260507-001`、`FS-20260507-002` 为同日第 1、2 张卡片，次日从 `FS-20260508-001` 重新开始
- `FS` 为全局统一前缀，与模块解耦
- `YYYYMMDD` 取 commit 作者提交时间的东八区日期；合并卡取合并当日的服务端日期
- `NNN` 为同一日期内全局递增序号，三位零填充，从 `001` 开始；并发生成时同日序号唯一且单调递增，编号分配与卡片入库同时完成；当日序号超过 999 时记录告警
- 普通卡与合并卡共用同一序号序列；编号生成后不可变，卡片删除后序号不回收
- 编号只在 PM 内部使用，不出现在 commit message 中；研发提交仍按团队约定前缀

## 2. 标题与内容

- **默认标题**：取 commit message 首行 → 含半角冒号时取首个冒号之后的内容（去掉 `feat(scope):`、`fix:` 等前缀），无冒号保留整段 → 去除首尾空白 → 超过 30 字符时截取前 30 字符，不加省略号
- **编辑**：标题必填，上限 30 字符，超出时阻断输入并提示「标题最长 30 字符」；编辑后不再回读 commit；前端生成默认标题与服务端同一规则
- **内容**：默认为 commit message 原文；合并卡内容由系统合成，见 [business-rule.md §8.3](business-rule.md#83-合并卡生成)
- **合并卡标题**：合并时由用户输入，必填，上限 30 字符

## 3. 来源模块

- 由 commit 头部的 Conventional Commit 范围解析，解析不到时记为 `MISC`；解析细则以代码仓为准
- 仅用于分组、筛选与合并校验，不参与编号

## 4. 负责人

- 界面以「提交人」呈现；默认取 commit 作者在系统用户中的匹配结果
- commit 作者未匹配系统用户时，账号记为未匹配，姓名使用 commit 原文作者名
- 卡片详情页编辑卡片信息时可修改，非需求改动卡同样可改

## 5. 排期日期

- 卡片同时保存单日排期日与起止区间，二者联动：只写排期日时起止日均为当日；写起止日时排期日取开始日；清空排期时三者同时清空
- 排期日与开始日不得早于今天，写入时校验

## 6. 需求性质

- 单选：业务功能（默认）/ 技术支持；技术支持指技术类、非功能性改动，如文档补录、参数说明、性能优化、工具脚本、changelog
- **写入路径**：PM 在卡片详情页编辑卡片信息时勾选，写编辑流水
- 系统不对存量卡批量补标
- 不改变本模块的状态流转
- 月历与列表不展示性质

## 7. 业务对接人

- 选填：在卡片详情页编辑卡片信息时输入，上限 64 字，由产品手工维护；为空不影响排期写入
- 已被需求单关联的卡片：为空时以需求单提交人兜底展示，卡片详情页提示需求单提交人姓名，手工填写优先
- 所有卡片均可留空；非需求改动卡不可编辑该字段
- 排期写入、合并卡生成与 commit 采集均不校验该字段；系统不批量回填

## 8. 完成 commit 回执

- 选填：标记完成时可关联一组跨仓 commit，也可不关联直接完成
- **选择流程**：选仓库（候选为卡片归属项目的代码服务仓，显示名称与仓库标识，经云效 API 实时获取）→ 按需修改分支 → 搜索或浏览 commit → 点选一条；可重复选择以关联多条；不提供 hash 手输入口，hash 与链接由选中项回填
- **候选为空**：卡片未归属项目，或归属项目未配置代码服务仓时，无可选仓；commit 本为选填，提示后不关联直接完成
- **分支**：可输入可选择，候选为仓内活跃分支，默认取该仓在云效登记的默认分支；手改的分支按仓在本浏览器记忆
- **服务端校验**：仓库必须属于该卡片归属项目的代码服务仓；commit 必须能在该仓检索命中；未经选中直接提交的拒绝；链接由服务端按代码托管平台（云效 Codeup）的 commit 地址规则生成，组织标识取自配置
- 每条回执记录仓库、commit、短 hash、提交说明、链接、作者与提交时间
- 开发完成后关联或移除完成 commit 为单独保存，写一条编辑流水「完成 commit：{原个数} → {新个数} 个」，不与卡片信息编辑合并

## 9. 项目配置字段

- **项目名称**：必填，1–12 字；启用中项目之间唯一，停用项目不占名
- **harness 工程**：必填，指项目的需求 / 文档真源工程；从云效 API 实时获取的研发仓列表中单选（支持搜索），只存仓引用
- **代码服务仓**：选填，可为空；从同一云效仓列表多选，只存引用不复制仓信息
- **标识色**：项目创建时按 business-rule.md §9 的调色板与顺序自动分配，之后不可编辑；停用不释放，重新启用沿用原色；未归属项目固定灰色
- **占用校验**：保存时校验 harness 工程与每个代码服务仓未被其他启用中项目占用（同一项目内 harness 工程与代码服务仓允许为同一仓），冲突即拒绝并指明占用方；编辑与停用、启用走同一校验
- **状态**：启用 / 停用；停用不删数据
- **备注**：选填
- 仓在云效侧被删除或失去访问权限后，引用它的映射自动失效：配置弹层中该仓标灰提示，不阻断项目保存；失效的 harness 工程仓不再产生新卡，存量卡片仍按既有仓标识归属原项目
