# 功能排期 · 数据定义

> 面向产品视角定义本模块实体、字段语义与实体关系；表结构以代码仓为准，不在此描述。字段的默认值与校验见 [field-rules.md](field-rules.md)，状态枚举见 [state-machine.md §1](state-machine.md#1-状态枚举)。

## 1. 实体关系

| 实体 | 关系 | 说明 |
|------|------|------|
| 排期卡片 → 卡片操作流水 | 1:N | 每次状态、排期、字段或存在性变更追加一条流水 |
| 排期卡片 → 完成 commit 回执 | 1:N | 开发完成时可关联多条跨仓 commit |
| 合并卡 → 合并明细 → 子卡 | 1:N，明细与子卡 1:1 | 合并卡与子卡均为排期卡片；嵌套合并见 business-rule.md §8.5 |
| 排期卡片 → 云效代码仓 | N:1 | 按源仓引用，源仓口径见 business-rule.md §1.1 |
| 项目 → 云效代码仓 | harness 工程 1:1，代码服务仓 1:N | 占用约束见 field-rules.md §9 |
| 需求单 → 排期卡片 | N:1 | 关联关系由需求管理维护，本模块只读，见 [需求管理 business-rule §5](../../需求管理/references/business-rule.md#5-排期关联规则) |

## 2. 排期卡片

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 卡片编号 | 卡片业务编号 | 文本 | 是 | 见 field-rules.md §1 |
| 标题 | 卡片标题 | 文本 | 是 | ≤30 字符，见 field-rules.md §2 |
| 内容 | commit message 原文或合并卡子卡清单 | 长文本 | 否 | 见 field-rules.md §2 |
| 负责人 | 卡片负责人，界面以「提交人」呈现 | 人员 | 是 | 账号未匹配时仅保留姓名，见 field-rules.md §4 |
| 状态 | 持久化状态 | 枚举 | 是 | 取值与流转见 state-machine.md §1、§2 |
| 排期日 | 单日排期锚点 | 日期 | 否 | 为空表示在待排期池，见 field-rules.md §5 |
| 排期开始日、排期结束日 | 排期区间 | 日期 | 否 | 与排期日联动 |
| 需求性质 | 业务功能或技术支持 | 枚举 | 是 | 默认业务功能，见 field-rules.md §6 |
| 业务对接人 | 业务侧对接人姓名 | 文本 | 否 | ≤64 字，排期写入时条件必填，见 field-rules.md §7 |
| 开发人 | 领取开发的研发 | 人员 | 否 | 写入路径见 state-machine.md §2 |
| 领取时间 | 领取开发的时间 | 时间 | 否 | 写入路径见 state-machine.md §2 |
| 完成时间 | 标记完成的时间 | 时间 | 否 | 写入路径见 state-machine.md §2 |
| 源仓 | 出卡来源代码仓 | 引用 | 是 | 合并卡取值见 business-rule.md §8.3 |
| 源 commit | 出卡来源 commit | 文本 | 是 | 唯一性见 business-rule.md §1.2，合并卡取值见 §8.3 |
| 来源模块 | commit 头部解析出的模块 | 文本 | 是 | 解析不到时为 `MISC`，见 field-rules.md §3 |
| 合并标识 | 是否为合并卡 | 布尔 | 是 | 默认否 |
| 父合并卡 | 子卡所属的合并卡编号 | 引用 | 否 | 仅子卡有值 |
| 子卡数 | 合并卡下的子卡数量 | 数量 | 否 | 仅合并卡有值 |
| 硬件管理标记 | 卡片附带的标记 | 标记 | 否 | 合并卡取值见 business-rule.md §8.3 |
| 创建时间 | 源 commit 采集入库时间 | 时间 | 是 | 展示精确到分钟，只读 |
| 删除标记 | 软删除标识 | 布尔 | 是 | 见 business-rule.md §1.2 |
| 最后操作人、最后操作时间 | 最近一次变更的审计信息 | 人员、时间 | 是 | 删除与回退同样记录 |

## 3. 完成 commit 回执

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 仓库 | commit 所在代码仓 | 引用 | 是 | 必须属于卡片归属项目的代码服务仓，见 field-rules.md §8 |
| commit | commit 完整 hash | 文本 | 是 | 由选中项回填，不接受手输 |
| 短 hash | commit 短 hash | 文本 | 是 | 由选中项回填 |
| 提交说明 | commit message | 文本 | 是 | 由选中项回填 |
| 链接 | commit 详情地址 | 链接 | 是 | 服务端生成，见 field-rules.md §8 |
| 作者 | commit 作者 | 文本 | 是 | 由选中项回填 |
| 提交时间 | commit 提交时间 | 时间 | 是 | 由选中项回填 |

## 4. 合并明细

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 合并卡编号 | 所属合并卡 | 引用 | 是 | — |
| 子卡编号 | 并入的原始子卡 | 引用 | 是 | — |
| 并入时间 | 子卡并入时间 | 时间 | 是 | 明细按并入时间倒序展示 |
| 合并前状态 | 子卡进入首次合并前的状态快照 | 枚举 | 是 | 快照规则见 business-rule.md §8.4–§8.6 |
| 合并前排期日 | 子卡进入首次合并前的排期日快照 | 日期 | 否 | 同上 |
| 合并前开发人信息 | 子卡进入首次合并前的开发人、姓名与领取时间 | 人员、时间 | 否 | 同上 |

## 5. 卡片操作流水

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 卡片编号 | 流水所属卡片 | 引用 | 是 | 子卡变更的记录方式见 business-rule.md §8.4 |
| 流水类型 | 变更类型 | 枚举 | 是 | 见 §8 |
| 描述 | 变更内容 | 文本 | 是 | 如「排期：2026-09-30 → 2026-10-08」 |
| 操作人 | 执行变更的用户 | 人员 | 是 | — |
| 操作时间 | 变更时间 | 时间 | 是 | 页面倒序展示 |

- 流水只追加、不删除

## 6. 发版日标记

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 日期 | 被标记的发版日 | 日期 | 是 | 见 business-rule.md §3 |
| 标记人 | 设置标记的用户 | 人员 | 是 | — |
| 标记时间 | 设置标记的时间 | 时间 | 是 | — |

## 7. 项目

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 项目名称 | 项目显示名 | 文本 | 是 | 见 field-rules.md §9 |
| harness 工程 | 项目的需求 / 文档真源工程 | 引用（云效代码仓） | 是 | 见 field-rules.md §9 |
| 代码服务仓 | 归属本项目的代码仓 | 引用列表（云效代码仓） | 否 | 见 field-rules.md §9 |
| 状态 | 是否参与归属解析 | 枚举 | 是 | 启用 / 停用 |
| 备注 | 补充说明 | 文本 | 否 | — |

- 卡片不存项目字段，归属在查询时按源仓动态解析，见 [business-rule.md §9](business-rule.md#9-项目归属与配置)

## 8. 枚举

| 枚举 | 取值 |
|------|------|
| 卡片状态 | 见 state-machine.md §1 |
| 需求性质 | 业务功能 / 技术支持 |
| 项目状态 | 启用 / 停用 |
| 流水类型 | 创建卡片（`CREATED`）/ 编辑（`EDITED`）/ 排期（`SCHEDULED`）/ 取消排期（`UNSCHEDULED`）/ 调整排期（`RESCHEDULED`）/ 领取开发（`TAKEN`）/ 释放开发（`RELEASED`）/ 标记完成（`MARKED_DONE`）/ 回退（`REVERTED`）/ 删除（`DELETED`） |
