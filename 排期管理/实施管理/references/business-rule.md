# 实施排期 · 业务规则

> 所属模块：[../SKILL.md](../SKILL.md)。状态机与页面交互以 SKILL.md 为准，本文件承载生成、领取、完成、旁路与权限的规则细节。

## 1. 卡片生成规则（v1.3 三通道）

- **通道一 · 15 分钟增量任务（impl-schedule-collect 增量档，v1.3 主通道）**：每 15 分钟一次（xx:00 / 15 / 30 / 45）扫描「功能排期」新变为开发完成（DONE）的卡片，窗口 = `(上次成功运行时间 − 5 分钟, 当前时间]`，重叠 5 分钟兜底；首次运行或水位缺失时回退扫「当天 `done_at`」；水位 `last_success_at` 持久化、仅整轮成功后推进（研发选型：配置参数表 / Redis——研发待确认 T1）。
- **通道二 · 夜间全量兜底（同 Job，23:40 档）**：每天 23:40 扫描「当天 `done_at ∈ [00:00, 24:00)`」的完成卡，专收增量通道漏网（任务停机、异常中断期间的 DONE 卡）；与增量档同一 Job 不同调度档位，`uk_func_day` 幂等去重。
- **通道三 · 手动选卡（v1.3 新增）**：Backup 面板「+ 手动选卡」弹窗，实施人员勾选功能排期 DONE 卡即时生成，不必等任务。规则：
  - **候选范围**：`feat_schedule_card` 中 `status=DONE` + `deleted_flag=0` + `req_nature=BIZ` + 未被任何实施卡 `source_feat_card_nos` 引用的卡片，按 `done_at` 倒序，支持卡号 / 标题 / 功能名搜索；**TECH 卡不进入候选**（技术类完成卡由生成任务自动划入非实施区留痕、无需实施，误标者回功能排期侧改 `req_nature`）。
  - **当日幂等置灰**：候选行 `func_key` 当日已有实施卡（`uk_func_day` 命中）→ 行置灰禁选并提示「该功能今日已生成 {IS-xxx}」。
  - **提交二次校验**：弹窗打开期间候选被生成任务拉走 / 当日已有实施卡的，提交时按卡返回失败清单（含已存在实施卡号），成功与失败分列展示。
- **聚合粒度（三通道一致）**：按功能聚合 —— 每个功能生成**一张**实施卡片；同一轮同功能多张完成卡合并进同一张实施卡片。
- **分组键 `func_key`**：生产实证形态为 `DIR:{模块} · {子模块} · {功能}`（2026-09-24 实证：229 张卡中 175 张为 DIR 前缀）；非 DIR 前缀形态（FS 卡号直引、空值）属存量兜底。**模块派生**：取 `func_key` 首段（`DIR:` 后第一段）即所属模块；非 `DIR:` 前缀归「未归类」——派生为展示/筛选层实时计算，不落列、不回填。
- **需求性质分流（v1.1）**：来源功能排期卡 `req_nature=TECH`（技术支持：文档补录、参数说明、性能优化、工具脚本、changelog 等技术类/非功能性需求）时，**生成即落 `NON_IMPL` + `non_impl_source=AUTO_TECH`**（卡片标注「技术类」）——不进 Backup 池、不进月历、不参与四状态计数、不触发未领取提醒；可在非实施弹层查看留痕与恢复。`req_nature=BIZ`（默认）维持原行为。
- **业务对接人取值链（v1.1）**：生成时写入 `biz_contact_name` 快照，优先级——①功能排期卡 `biz_contact_name` 手工值（产品维护，**手工优先不被覆盖**）；②关联 REQ 单提交人：内部单 `requirement.submit_by` → `sys_user.real_name`，外部单 `requirement.external_submitter_name`（经 `requirement.linked_card_no` 同库反查，沿用「需求提交人」筛选既有链路）；③均无则 NULL。REQ 关联判定以**组内功能排期卡**逐张反查，取首个命中值。功能排期侧录入卡点（功能排期 v2.7，2026-10-08 五决策）：**排期写入时必填校验**——无 REQ 单关联且非 TECH 卡排期前必补录，REQ 关联卡预填提交人可手改覆盖，存量无对接人卡下次改期被拦自然收口；进入排期的功能卡原则上必有对接人取值来源。
- **内容生成（三通道一致）**：根据需求描述 + 代码变更（完成卡关联的 commit message）生成「变更待测试项」，实施人员可在抽屉中人工补充修正（记 `EDITED` 流水）。
- **幂等（三通道共用）**：同功能同一天只生成一张（`uk_func_day`）；删除后当天不再重新生成。
- **落点**：业务卡 `scheduled_date = NULL`，进入 Backup 卡片池，等待实施人员拖拽排期；技术类卡直落 NON_IMPL 区。
- **流水**：任务通道写 `CREATED`（operator = 系统账号 0）；手动通道写 `CREATED`（operator = 当前操作人，detail 附「手动拉取」+ 来源卡号清单）。

## 2. 领取与完成规则

- **领取实施**：仅 `PENDING` 可领取；领取人 = 当前操作人，实施开始日期 = 领取时间，二者系统写入、页面只读。
- **取消领取**：仅 `IN_PROGRESS` 可取消；清空领取人与实施开始日期。
- **点击完成**：`PENDING / IN_PROGRESS → DONE`，实施结束日期 = 点击完成按钮的时间；从「待实施」直接完成时自动回填当前操作人为领取人、实施开始日期 = 完成时间。
- **回退**：仅 `DONE` 可回退；回退待实施清空领取人 + 起止日期，回退实施中仅清空实施结束日期。回退需二次确认。
- **完成锁定**：DONE 卡片不可拖拽、不可改期；需变更必须先回退。

## 3. 排期规则

- 排期日期不得早于当前服务器日期（+08:00），前后端双重校验。
- 一张卡片只能排到一天；跨多日实施在内容中备注。
- 拖回 Backup = 取消排期（`scheduled_date = NULL`）。

## 4. 非实施需求旁路（v1.1 双来源）

- **来源一 · 人工移入（MANUAL）**：由人工在抽屉中「移入非实施需求」触发，任意状态可移入，需二次确认；移入时清空排期日期、领取人、实施开始/结束日期，`non_impl_source=MANUAL`。
  - **回写闭环（v1.1 批复⑤）**：移入成功同事务将来源功能排期卡（`source_feat_card_nos` 逐张）`req_nature` 置为 `TECH`（仅当前为 `BIZ` 的更新，已是 `TECH` 的跳过），次日聚合同类完成卡即自动分流，消除「每日重复移入」；流水 detail 附「已回写功能排期卡需求性质」。
- **来源二 · 技术类自动划入（AUTO_TECH）**：来源功能排期卡 `req_nature=TECH` 时聚合 Job 生成即落 NON_IMPL，`non_impl_source=AUTO_TECH`，卡片标注「技术类」；无需实施、留痕可查。
- NON_IMPL 卡片不进入 Backup 与月历，不参与领取 / 完成 / 排期 / 四状态计数；仅可在抽屉编辑标题与内容。
- 非实施弹层两类来源标识可区分（「技术类·自动」/「人工移入」+ 操作人）；均可「恢复为待实施」回到 `PENDING`——恢复清 `non_impl_source` 但**不回写功能排期卡 `req_nature`**（性质跟随功能粒度：恢复单张实施卡不改变功能性质，性质仍为 TECH 的功能次日新完成卡聚合仍自动分流）。

## 5. 删除规则

- 抽屉内「删除卡片」，确认弹窗二次确认后软删。
- 删除后同功能当天不再自动生成实施卡片（`uk_func_day` 保底）。

## 6. 过滤与搜索规则

- **只看自己**：按「领取人 = 当前登录用户」过滤月历格卡片、+N 弹层与统计数字；Backup 池未领取卡片不过滤（保持领取入口常开）。前端临时 UI 状态，不落库。
- **当月卡片搜索**：多关键字 AND 模糊匹配标题 / 内容 / 功能名；命中卡片高亮、未命中日历卡淡化、Backup 未命中过滤；仅搜当前视图月份。
- **模块筛选（v1.1）**：工具栏「模块」下拉单选（全部 / 供应链 / 报表 / 营运 / 财务 / 研发 / 设置 / 档案 / 仓储管理 / 未归类），按 `func_key` 首段派生值匹配；「仓储管理」选项兼容首段「仓储」「仓储管理」两种存量写法；作用于 Backup 池 + 日历格 + +N 弹层 + 四状态计数，与其他筛选 AND 叠加；前端临时 UI 状态，不落库。
- **业务对接人筛选（v1.1 批复②）**：工具栏「业务对接人」输入框模糊匹配 `biz_contact_name`；作用于 Backup 池 + 日历格 + +N 弹层 + 状态计数，与其他筛选 AND 叠加；前端临时 UI 状态，不落库。

## 7. 权限矩阵

| 能力 | 权限点 | 授予对象 |
|------|--------|----------|
| 查看页面 / 月历 / Backup | `MENU:DEV:IMPL_SCHEDULE` | 实施 / 测试负责人、研发管理员 |
| 排期 / 改期 / 编辑标题内容 | 同上 | 同上 |
| 领取 / 取消领取 / 完成 / 回退 | 同上 | 同上 |
| 手动选卡 / 生成实施卡（v1.3） | 同上 | 同上 |
| 移入非实施需求 / 恢复 / 删除 | 同上 | 同上 |

- 所有写接口后端二次校验 `MENU:DEV:IMPL_SCHEDULE`。
- 每次状态 / 排期 / 字段 / 存在性变更成功后，服务端向 `impl_schedule_card_log` 追加一条流水。

## 8. 未领取提醒（现状登记）

> 本节为生产既有机制的补登记（REQ-20260924-IMPL 需求单引用时规格库缺失，2026-10-08 按需求描述登记基线；触发时点、企微模板编码等实现细节待研发回填）。

- **触发**：实施卡片生成后**超 12 小时未被领取**（仍处 PENDING）→ 企微消息提醒**功能负责人**。
- **v1.3 联动**：生成提速后（DONE 后 ≤15 分钟生成）计时起点大幅提前——白天完成的卡当天晚间即触发提醒；12 小时阈值与提醒对象不变。
- **v1.1 决策③（2026-09-24 批复）**：提醒对象维持功能负责人，**不抄送业务对接人**；消息文案本次不改动。
- **技术类卡豁免（v1.1）**：`req_nature=TECH` 的聚合卡生成即落 NON_IMPL，不触发本提醒——消除技术类卡堆积待排期造成的提醒噪声。
