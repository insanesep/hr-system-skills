# 实施排期 · 业务规则

> 所属模块：[../SKILL.md](../SKILL.md)。状态机与页面交互以 SKILL.md 为准，本文件承载生成、领取、完成、旁路与权限的规则细节。

## 1. 卡片生成规则

- **通道一 · 15 分钟增量任务**：每 15 分钟一次（每小时的 00 / 15 / 30 / 45 分）扫描「功能排期」新变为开发完成（DONE）的卡片，扫描范围为较上次成功运行时间前推 5 分钟至当前时间，以 5 分钟重叠扫描兜底；首次运行或水位缺失时回退为扫描当天完成的卡片；水位持久化，仅整轮成功后推进（存储方式以代码仓为准）。
- **通道二 · 夜间全量兜底**：每天 23:40 扫描当天（00:00 至 24:00）完成的卡片，专收增量通道漏网（任务停机、异常中断期间完成的卡片）；与增量通道为同一生成任务的不同调度档位，按同功能同日唯一去重。
- **通道三 · 手动选卡**：Backup 面板「+ 手动选卡」弹窗，实施人员勾选功能排期已完成卡即时生成，不必等任务。规则：
  - **候选范围**：功能排期中已完成、未删除、需求性质为业务功能，且未被任何实施卡作为来源功能排期卡引用的卡片，按完成时间倒序，支持卡号 / 标题 / 功能名搜索；**技术支持卡不进入候选**（技术类完成卡由生成任务自动划入非实施区留痕、无需实施，误标者回功能排期侧修改需求性质）。
  - **当日幂等置灰**：候选行所属功能当日已有实施卡 → 行置灰禁选并提示「该功能今日已生成 {IS-xxx}」。
  - **提交二次校验**：弹窗打开期间候选被生成任务拉走 / 当日已有实施卡的，提交时按卡返回失败清单（含已存在实施卡号），成功与失败分列展示。
- **聚合粒度（三通道一致）**：按功能聚合 —— 每个功能生成**一张**实施卡片；同一轮同功能多张完成卡合并进同一张实施卡片。
- **分组键 · 功能标识**：功能标识由「模块 · 子模块 · 功能」三段组成，取首段为所属模块；无该结构的标识（直接引用功能排期卡号、空值）属存量兜底形态，归「未归类」。模块派生为展示 / 筛选层实时计算，不单独存储、不回填。
- **需求性质分流**：来源功能排期卡需求性质为技术支持（文档补录、参数说明、性能优化、工具脚本、changelog 等技术类 / 非功能性需求）时，**生成即落 NON_IMPL**，来源记为技术类自动划入（卡片标注「技术类」）——不进 Backup 池、不进月历、不参与四状态计数、不触发未领取提醒；可在非实施弹层查看留痕与恢复。需求性质为业务功能（默认）时按常规生成业务卡。
- **业务对接人取值链**：生成时写入业务对接人快照，优先级——①功能排期卡上手工维护的业务对接人（产品维护，**手工优先不被覆盖**）；②关联需求单（REQ）提交人：内部单取提交人对应的系统用户姓名，外部单取外部提交人姓名（经需求单关联的功能排期卡号反查，沿用「需求提交人」筛选既有链路）；③均无则为空。需求单关联判定以**组内功能排期卡**逐张反查，取首个命中值。功能排期侧录入卡点：**排期写入时必填校验**——无需求单关联且非技术支持卡排期前必须补录，有需求单关联的卡预填提交人、可手改覆盖，存量无对接人的卡在下次改期时同样被拦截补录；进入排期的功能卡原则上必有对接人取值来源。
- **内容生成（三通道一致）**：根据需求描述 + 代码变更（完成卡关联的 commit message）生成「变更待测试项」，实施人员可在抽屉中人工补充修正（记「编辑」操作记录）。
- **幂等（三通道共用）**：同功能同一天只生成一张（同功能同日唯一）；删除后当天不再重新生成。
- **落点**：业务卡排期日期为空，进入 Backup 卡片池，等待实施人员拖拽排期；技术类卡直落 NON_IMPL 区。
- **操作记录**：任务通道记「生成」（操作人为系统账号）；手动通道记「生成」（操作人为当前操作人，附「手动拉取」+ 来源卡号清单）。

## 2. 领取与完成规则

- **领取实施**：仅 `PENDING` 可领取；领取人 = 当前操作人，实施开始日期 = 领取时间，二者系统写入、页面只读。
- **取消领取**：仅 `IN_PROGRESS` 可取消；清空领取人与实施开始日期。
- **点击完成**：`PENDING / IN_PROGRESS → DONE`，实施结束日期 = 点击完成按钮的时间；从「待实施」直接完成时自动回填当前操作人为领取人、实施开始日期 = 完成时间。
- **回退**：仅 `DONE` 可回退；回退待实施清空领取人 + 起止日期，回退实施中仅清空实施结束日期。回退需二次确认。
- **完成锁定**：DONE 卡片不可拖拽、不可改期；需变更必须先回退。

## 3. 排期规则

- 排期日期不得早于当前服务器日期（东八区），前后端双重校验。
- 一张卡片只能排到一天；跨多日实施在内容中备注。
- 拖回 Backup = 取消排期（清空排期日期）。

## 4. 非实施需求旁路（双来源）

- **来源一 · 人工移入**：由人工在抽屉中「移入非实施需求」触发，任意状态可移入，需二次确认；移入时清空排期日期、领取人、实施开始/结束日期，来源记为人工移入。
  - **回写闭环**：移入成功时同步将各来源功能排期卡的需求性质置为技术支持（仅更新当前为业务功能的卡，已是技术支持的跳过），与移入一并生效；次日聚合同类完成卡即自动分流，避免「每日重复移入」；操作记录附「已回写功能排期卡需求性质」。
- **来源二 · 技术类自动划入**：来源功能排期卡需求性质为技术支持时，生成任务生成即落 NON_IMPL，来源记为技术类自动划入，卡片标注「技术类」；无需实施、留痕可查。
- NON_IMPL 卡片不进入 Backup 与月历，不参与领取 / 完成 / 排期 / 四状态计数；仅可在抽屉编辑标题与内容。
- 非实施弹层两类来源标识可区分（「技术类·自动」/「人工移入」+ 操作人）；均可「恢复为待实施」回到 `PENDING`——恢复清除非实施来源标记，但**不回写功能排期卡需求性质**（性质跟随功能粒度：恢复单张实施卡不改变功能性质，性质仍为技术支持的功能次日新完成卡聚合仍自动分流）。

## 5. 删除规则

- 抽屉内「删除卡片」，确认弹窗二次确认后软删。
- 删除后同功能当天不再自动生成实施卡片（同功能同日唯一保底）。

## 6. 过滤与搜索规则

- **只看自己**：按「领取人 = 当前登录用户」过滤月历格卡片、+N 弹层与统计数字；Backup 池未领取卡片不过滤（保持领取入口常开）。前端临时 UI 状态，不落库。
- **当月卡片搜索**：多关键字 AND 模糊匹配标题 / 内容 / 功能名；命中卡片高亮、未命中日历卡淡化、Backup 未命中过滤；仅搜当前视图月份。
- **模块筛选**：工具栏「模块」下拉单选（全部 / 供应链 / 报表 / 营运 / 财务 / 研发 / 设置 / 档案 / 仓储管理 / 未归类），按功能标识首段匹配；「仓储管理」选项兼容首段「仓储」「仓储管理」两种存量写法；作用于 Backup 池 + 日历格 + +N 弹层 + 四状态计数，与其他筛选 AND 叠加；前端临时 UI 状态，不落库。
- **业务对接人筛选**：工具栏「业务对接人」输入框模糊匹配业务对接人；作用于 Backup 池 + 日历格 + +N 弹层 + 状态计数，与其他筛选 AND 叠加；前端临时 UI 状态，不落库。

## 7. 权限矩阵

| 能力 | 权限点 | 授予对象 |
|------|--------|----------|
| 查看页面 / 月历 / Backup | `MENU:DEV:IMPL_SCHEDULE` | 实施 / 测试负责人、研发管理员 |
| 排期 / 改期 / 编辑标题内容 | 同上 | 同上 |
| 领取 / 取消领取 / 完成 / 回退 | 同上 | 同上 |
| 手动选卡 / 生成实施卡 | 同上 | 同上 |
| 移入非实施需求 / 恢复 / 删除 | 同上 | 同上 |

- 所有写操作在服务端二次校验 `MENU:DEV:IMPL_SCHEDULE`。
- 每次状态 / 排期 / 字段 / 存在性变更成功后，系统为该卡追加一条操作记录。

## 8. 未领取提醒

- **触发**：实施卡片生成后**超 12 小时未被领取**（仍处 PENDING）→ 企微消息提醒**功能负责人**。
- **计时起点**：为实施卡生成时间（开发完成后 15 分钟内生成），白天完成的卡当天晚间即可触发提醒。
- **提醒对象**：功能负责人，**不抄送业务对接人**。
- **技术类卡豁免**：需求性质为技术支持的聚合卡生成即落 NON_IMPL，不触发本提醒，避免技术类卡堆积待排期造成提醒噪声。
- 提醒的调度时点与企微消息模板以代码仓为准。
