# 实施管理

> 对应脑图「实施管理（for 实施）」节点：根据排期管理完成情况汇总生成卡片。

面向实施/测试负责人员的轻量排期工具：功能排期中新变为「开发完成」的卡片按功能聚合，每个功能生成一张**实施卡片**（内容 = 根据需求描述与代码变更生成的变更待测试项），沉淀到待排期池；实施人员拖拽排期到月历、领取实施、点击完成，全程三态跟踪。

## 服务对象与端

- **服务对象**：实施、测试负责人员
- **仅 Web 端**：桌面排期工具，不做移动端适配

## 产品背景

功能排期解决了「研发交付了什么、什么时候交付」，但交付之后的实施验证（部署、联调、测试、上线确认）没有可视化锚点：完成卡越积越多、哪些已实施靠口头同步；一个功能由多张开发卡组成，实施验证的对象是「功能」而非单张 commit 卡；变更影响了哪些待测试项靠人工翻记录，容易漏测。本模块提供「功能完成卡 → 按功能聚合 → 实施卡片 → 排期日历」的闭环。

## 核心链路：聚合即出卡

实施卡生成三通道，共用聚合逻辑与幂等约束：

1. **增量任务**：高频定时（如 15 分钟）扫描功能排期新 DONE 卡，窗口 = 上次成功运行时间 − 缓冲 ~ 当前，水位持久化
2. **夜间全量兜底**：每日扫当天 DONE，专收增量通道停机/中断期间的漏网卡
3. **手动选卡**：待排期面板手动勾选功能 DONE 卡即时生成，覆盖「等不及」与「补拉救援」；候选 = DONE 态、未删除、业务功能性质且未被任何实施卡引用的功能卡；同功能当日已有实施卡的行置灰禁选并提示卡号；提交时二次校验，期间被任务拉走的卡返回失败清单

聚合规则：

- 分组键 = 功能标识（功能卡关联的需求/模块决定归属；无需求关联按来源模块兜底）；同功能多张合一张
- **同功能同一天只生成一张**（唯一约束幂等）；删除后当天不再生成，次日有新完成卡时再聚合
- 卡片内容 = 变更待测试项，由任务根据需求描述 + 完成卡 commit message 汇总生成，实施人员可补充修正
- 卡片编号 `IS-{YYYYMMDD}-{NNN}`，生成时按创建日期分配，全局唯一、不回收
- **业务对接人快照**：生成时写入——功能卡手工值优先，无手工值取关联需求单提交人；只读，维护入口在功能排期侧；生成后再改对接人不影响既有卡
- **技术类自动分流**：来源功能卡需求性质 = 技术支持时，生成即落非实施区（标注「技术类·自动」），不进池/月历/计数、不触发未领取提醒（提醒降噪是该分流的核心收益）

## 状态机

- DB 四态：`PENDING（待实施）` / `IN_PROGRESS（实施中）` / `DONE（实施完成）` / `NON_IMPL（非实施需求）`
- **领取实施**：`PENDING→IN_PROGRESS`，自动写入领取人 + 实施开始日期（= 领取时间）；取消领取清空
- **点击完成**：`PENDING/IN_PROGRESS→DONE`，写入实施结束日期（= 点击时间）；来自待实施且无领取人时自动回填当前操作人、开始日期 = 完成时间
- **回退**：`DONE→PENDING`（清完成时间与领取信息）或 `DONE→IN_PROGRESS`（仅清完成时间）
- **DONE 卡锁定**：不可拖拽改期，需先回退
- **NON_IMPL 旁路态（双来源）**：
  - 人工移入：任意状态可移入，清空排期/领取人/起止日期；**同事务回写来源功能卡需求性质为技术支持**——使次日聚合同类卡自动分流，消除「每日重复移入」（闭环关键）
  - 技术类自动划入：见上
  - 两类卡共用非实施弹层（来源标识区分），仅允许编辑标题/内容，均可「恢复为待实施」；恢复只回待实施并清来源标记，**不回写功能卡性质**（性质跟随功能粒度）

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 区域 | 职责 |
| ---- | ---- |
| 待排期池 | 实施卡分页展示（创建日期倒序 + 相对时间，超期未排期变色提醒）；搜索框；「手动选卡」入口 |
| 月历区 | 拖拽排期/改期（不早于今日），今日高亮，跨月灰显，单格溢出折叠「+N」 |
| 筛选 | 模块（按功能标识首段派生，未归类兜底）、业务对接人模糊筛选、「只看自己」（仅按领取人过滤月历与统计，池保持全员可见——未领取卡需被所有人看到）；均作用于池+月历+计数，前端临时态不落库 |
| 卡片抽屉 | 编号/来源功能卡（只读）/创建·排期·实施起止日期（系统写入只读）/标题/内容（变更待测试项可编辑）/领取人/业务对接人（只读）/所属模块（只读派生）；状态切换；操作记录时间线；删除/移入非实施/恢复 |
| 卡片标识 | 功能标签 + 模块药丸 + 对接人 + 领取人药丸 |
| 非实施弹层 | 全部 NON_IMPL 卡片（带来源标识：技术类·自动 / 人工移入）与总数徽标 |

## 关键约束

- 生成提速后「超 N 小时未领取」提醒的计时起点随之前移（阈值与提醒对象 = 功能负责人不变，不抄送业务对接人）
- 排期约束前后端双守：排期日不早于当日；DONE 锁排期；NON_IMPL 排期必为空且不可调状态接口
- 手动选卡候选不含技术支持卡：误标技术性质的卡请在功能排期侧改回，待下轮任务自动聚合
- 一张实施卡只排到一天，跨多日实施在内容中备注
- 权限最小授予：仅实施/测试负责人与研发管理员可见
