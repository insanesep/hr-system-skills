# 实施排期

面向实施 / 测试负责人员的轻量排期工具：每 15 分钟增量任务（夜间 23:40 全量兜底）将「功能排期」中新完成的卡片按功能聚合，每个功能生成一张**实施卡片**（内容 = 根据需求与代码变更生成的变更待测试项），沉淀到 Backup 卡片池；亦可在 Backup 面板「手动选卡」勾选功能排期完成卡即时生成，不必等任务；实施人员拖拽排期到月历、领取实施、点击完成，全程三态跟踪（待实施 / 实施中 / 实施完成）。

## 端

**仅 Web 端**（管理后台 Portal 下「研发管理」分组）。App 端不提供此入口。

## 产品背景

功能排期（feature-schedule）解决了「研发交付了什么、什么时候交付」，但交付之后的**实施验证环节**（部署、联调、测试、上线确认）没有可视化锚点：

- 功能排期里开发完成的卡片越来越多，哪些已经实施验证、哪些还压着，靠口头同步
- 一个功能往往由多张开发卡组成，实施验证的对象是「功能」而不是单张 commit 卡片
- 变更影响了哪些待测试项，靠实施人员自己翻 commit 记录，容易漏测

本模块提供「功能排期完成卡 → 按功能聚合 → 实施卡片 → 排期日历」的闭环：

1. **聚合即出卡**：15 分钟增量任务（+ 夜间 23:40 全量兜底）扫描功能排期中新变为「开发完成」的卡片，按功能分组，每个功能生成一张实施卡片；卡片内容根据需求描述与代码变更自动生成「变更待测试项」；v1.3 起亦可在 Backup 面板「手动选卡」即时生成，不必等任务
2. **拖拽即排期**：Backup 卡片池的卡片可拖到月历指定日期，跨天移动亦支持
3. **领取即开工**：状态切到「实施中」自动写入领取人与实施开始日期（= 领取时间）
4. **完成即闭环**：点击「实施完成」自动写入实施结束日期（= 点击完成按钮的时间）

## 实施卡片字段

| 字段 | 说明 |
|------|------|
| 卡片编号 | `IS-{YYYYMMDD}-{NNN}`，生成时按创建日期分配，全局唯一、不回收 |
| 创建日期 | 生成时间（15 分钟增量任务 / 夜间兜底任务 / 手动拉取；系统写入，不可修改） |
| 实施开始日期 | = 领取时间，状态切到「实施中」自动写入；取消领取清空 |
| 实施结束日期 | = 点击「实施完成」的时间；回退清空 |
| 标题 | 默认 = 功能名概括，≤ 30 字，可手改 |
| 内容 | 变更待测试项：根据需求描述与代码变更自动生成，可人工补充修正 |
| 领取人 | 状态切到「实施中」时自动填入当前操作人；从「待实施」直接点完成时自动回填当前操作人 |
| 排期日期 | 通过拖拽改变；NULL = 在 Backup 池 |
| 来源功能排期卡 | 聚合来源的功能排期卡号集合（只读，便于回溯） |
| 所属模块 | 由 `func_key` 首段派生（`DIR:{模块} · {子模块} · {功能}`），不落列；`func_key` 非 `DIR:` 前缀（FS 卡号直引或空值）归「未归类」 |
| 业务对接人 | `biz_contact_name` 快照列：生成时写入——功能排期卡手工值优先；无手工值取关联 REQ 单提交人（内部单 `submit_by` → `sys_user.real_name`，外部单 `external_submitter_name`）；均无则空（显示「—」）。只读，维护入口在功能排期侧（功能排期 v2.7 起「排期保存时」必填校验：无 REQ 关联且非 TECH 卡排期前必补录，REQ 关联卡预填提交人可改——进入排期的功能卡原则上必有对接人取值来源） |

数据模型、编号规则与生成 Job（15 分钟增量 + 夜间兜底 + 手动拉取）等实现细节以代码仓为准，不内嵌；状态机 / 权限 / 校验规则详见 [references/business-rule.md](references/business-rule.md)。

## 状态机

```
                ┌─────────────────────┐
 任务生成/手动 ─►│  PENDING（待实施）  │ 白底灰框
   拉取         └──────────┬──────────┘
                 领取实施   │  ▲
               (领取人=   ▼  │ 取消领取（清空领取人 + 实施开始日期）
                当前用户)     │
                ┌─────────────────────┐
                │ IN_PROGRESS（实施中）│ 紫底 + 左侧 3px palette-purple-6
                └──────────┬──────────┘
                           │ 点击「实施完成」（写入实施结束日期）
                           ▼
                ┌─────────────────────┐
                │   DONE（实施完成）   │ 绿底 + 左侧 3px success-6
                └──────────┬──────────┘
                           │  ▲
                回退待实施 ▼  │ 回退实施中
                ┌─────────────────────┐
                │  PENDING / IN_PROGRESS
                └──────────┬──────────┘
                 手动移入   │  ▲
                           ▼  │ 恢复为待实施
                ┌─────────────────────┐
                │ NON_IMPL（非实施需求）│ 黄底 + 左侧 3px warning-6
                └─────────────────────┘
                约束：清空排期/领取人/实施起止日期，不进 Backup 与月历
                来源二态：人工移入（MANUAL）/ 技术类自动生成即划入（AUTO_TECH）
  生成任务（功能排期卡 req_nature=TECH）──► NON_IMPL（标注「技术类」，non_impl_source=AUTO_TECH）
```

- DB 层四态：`PENDING` / `IN_PROGRESS` / `DONE` / `NON_IMPL`
- **领取实施**：`PENDING → IN_PROGRESS`，写入 `taker_*` + `taken_at`（实施开始日期），流水 `TAKEN`
- **取消领取**：`IN_PROGRESS → PENDING`，清空 `taker_*` + `taken_at`，流水 `RELEASED`
- **点击完成**：`PENDING / IN_PROGRESS → DONE`，写入 `done_at`（实施结束日期）；若来自 PENDING 且无领取人，自动回填当前操作人为领取人、实施开始日期 = 完成时间；流水 `MARKED_DONE`
- **回退**：`DONE → PENDING`（清空 `done_at` + `taker_*` + `taken_at`）或 `DONE → IN_PROGRESS`（仅清空 `done_at`），流水 `REVERTED`
- **DONE 卡片在前端锁定**：`draggable=false`，不可拖拽改期也不可拖回 Backup；如需改期必须先回退
- **NON_IMPL 旁路态（v1.1 双来源）**：
  - **人工移入**：抽屉内点击「移入非实施需求」手动触发，任意状态可移入；移入时清空 `scheduled_date`、`taker_*`、`taken_at`、`done_at`，`non_impl_source=MANUAL`；**v1.1 起同步回写来源功能排期卡 `req_nature=TECH`（需求性质=技术支持）**，使次日聚合同类卡自动分流，消除每日重复移入；流水 `MOVED_TO_NON_IMPL`（detail 附「已回写功能排期卡需求性质」）
  - **技术类自动划入**：来源功能排期卡 `req_nature=TECH` 时，聚合 Job 生成即落 `NON_IMPL` + `non_impl_source=AUTO_TECH`（卡片标注「技术类」），不进 Backup / 月历 / 四状态计数、不触发未领取提醒；流水 `CREATED`（detail 附「技术类需求，自动划入非实施区」）
  - 两类卡共用非实施弹层（来源标识可区分），均仅允许编辑标题/内容，均可「恢复为待实施」；恢复只回 `PENDING` 并清 `non_impl_source`，**不回写功能排期卡 `req_nature`**（需求性质跟随功能粒度，恢复单张实施卡不改变功能性质——性质仍为技术支持的该功能次日新完成卡聚合仍自动分流）

|------|------|

| 拖拽视觉 | 拖起时源卡半透明 0.4，目标格黄色底 + 主色虚线 outline |
| 卡片点击 | 右侧抽屉弹出详情 / 编辑 |

| 功能标签 | 卡片展示 `func_name` 红色小药丸（聚合分类标识）；IN_PROGRESS / DONE 卡右侧显示紫色「领取人」药丸 |

| 卡片对接人标识 | 卡片标签行显示「👤{对接人}」（与模块标识同行）；空值显示「—」；详情抽屉独立字段行展示（只读，维护入口在功能排期侧） |
| 只看自己 | 工具栏右侧 AcSwitch，**默认关闭**；开启后按「领取人 = 当前登录用户」过滤**月历格卡片 + +N 弹层 + 统计数字**；Backup 池卡片均未领取，**不做过滤**（领取入口保持常开）；hint 切换为「月历仅显示领取人 = {当前用户名}；Backup 未领取卡片不受影响」；前端临时 UI 状态，不落库 |

| 完成锁定 | status=DONE 的卡片 `draggable=false` + 锁定样式，拖拽尝试在 dragstart / drop 均拒绝并 toast 提示 |
| 今日下限 | drop 时对比 `newDate < today` 则拒绝，卡片只能排到今天或之后 |
| 非实施需求 | 双来源（v1.1）：①抽屉内点击「移入非实施需求」（确认弹窗二次确认）人工移入，标注「人工移入」；②来源功能排期卡 `req_nature=TECH` 的聚合卡**生成即自动划入**，标注「技术类·自动」。两类卡均标为 NON_IMPL（黄底 + 左侧 3px warning-6），移入/生成时清空排期 / 领取人 / 实施起止日期；工具栏「非实施需求」按钮弹层展示全部 NON_IMPL 卡片（卡片带来源标识）；抽屉内可点「恢复为待实施」恢复（不清功能排期卡性质标记）。人工移入时**同步回写来源功能排期卡 `req_nature=TECH`**，次日聚合自动分流，不再重复生成业务卡 |
| 删除卡片 | 抽屉内「删除卡片」确认弹窗二次确认；软删；同功能当天已生成过（含已删除）不再重复生成 |
| 手动选卡（v1.3） | Backup 面板「+ 手动选卡」弹窗：候选 = 功能排期 DONE 态、未删除、`req_nature=BIZ` 且未被任何实施卡引用的功能卡（完成时间倒序，支持卡号 / 标题 / 功能名搜索；TECH 卡不进入候选，由生成任务自动划入非实施区留痕）；**同功能当日已有实施卡的行置灰禁选**并提示「该功能今日已生成 {IS-xxx}」；勾选确认后服务端按 `func_key` 聚合成实施卡（同功能多张合一张）落 Backup 池，**提交时二次校验**——弹窗打开期间被生成任务拉走的卡返回失败清单（含已存在实施卡号）；流水 `CREATED`（operator = 当前操作人，detail 附「手动拉取」+ 来源卡号清单） |
| 保存 | 抽屉「保存」提交标题（必填 ≤30 字）/ 内容 / 状态变更；取消按钮与遮罩点击直接关闭不保存 |
| 操作记录 | 抽屉底部时间线倒序展示 `impl_schedule_card_log`：操作人 · 操作时间 · 行为描述 |

## 前端页面

原型 `assets/web/implementation-schedule.html`，设计要点：

- Token 全部消费 `page-blueprint/tokens/web.css`（六级相对路径外链），无裸色值 / 裸间距 / 裸 z-index
- 纯 HTML + 原生 JS，不引入任何外部库；拖拽使用 HTML5 Drag & Drop API；图标统一内联 SVG（禁 emoji）
- 月历格 `min-height:120px`；Backup 固定 300px，日历自适应剩余宽度；最小宽度 1200px
- 抽屉宽 460px，含字段区 + 状态切换器 + 操作记录时间线
- 确认类操作（删除 / 移入非实施需求 / 恢复）走 AcModal 形态确认弹窗，反馈走 Toast
- 响应式不做移动端适配，实施排期仅桌面使用

## Tips

- 卡片编号只对内部生效；同一功能同一天只生成一张实施卡片（`uk_func_day` 保底），删除后当天不再生成，次日功能排期仍有新完成卡时才再次聚合生成
- **实施卡生成三通道（v1.3）**：①15 分钟增量任务（窗口 = 上次成功运行时间 − 5 分钟 ~ 当前，水位持久化，`uk_func_day` 幂等）；②夜间 23:40 全量兜底（扫当天 DONE，专收增量通道停机 / 中断期间的漏网卡）；③Backup 面板「手动选卡」即时生成。三通道共用聚合 / 技术类分流 / 对接人快照逻辑与 `uk_func_day` 幂等——DONE 后 ≤15 分钟实施卡即落 Backup，手动通道覆盖「等不及」与「补拉救援」场景
- **「超 12 小时未领取」提醒联动（v1.3）**：生成提速后计时起点从「次日 23:40」提前到「DONE 后 ≤15 分钟」——白天完成的卡当天晚间即触发提醒；12 小时阈值与提醒对象（功能负责人）不变
- 手动选卡候选不含 TECH 卡：技术类完成卡由生成任务自动划入非实施区留痕、无需实施，不提供手选；误标 TECH 的卡请在功能排期侧改回 BIZ，待下一轮任务自动聚合
- 聚合分组键 = 功能标识（`func_key`）：功能排期卡片关联的需求 / 模块决定归属；无需求关联的完成卡按 `source_module` 兜底分组
- 「变更待测试项」由任务根据需求描述 + 完成卡关联的 commit message 汇总生成，实施人员可在抽屉中补充修正（写 `EDITED` 流水）
- 「只看自己」只按领取人过滤月历与统计，Backup 池保持全员可见 —— 未领取卡片需要被所有人看到才能被领取
- Backup 池默认按创建日期倒序（最新生成的排最上）；页面保持打开 24h 以上建议刷新以获得准确相对时间
- 一张实施卡片在时间上只能排到一天；跨多日实施请在内容中备注
- 权限最小授予：仅将 `MENU:DEV:IMPL_SCHEDULE` 授予实施 / 测试负责人与研发管理员
- 模块标识与筛选均由 `func_key` 首段实时派生，不落列、不回填：存量 `func_key` 非 `DIR:` 前缀的卡（FS 卡号直引或空值）天然归「未归类」，随新卡按 DIR 口径生成，未归类占比预期下降（2026-09-24 生产实证：229 张卡中 175 张 DIR 前缀、54 张未归类）
- 业务对接人是**生成时快照**：生成后功能排期侧再改对接人不影响既有实施卡；需修正请在功能排期卡维护后等次日新卡生效，或直接忽略（展示性字段）
- 技术类卡（`req_nature=TECH`）生成即落 NON_IMPL：不占 Backup / 月历 / 状态计数、不触发「超 12 小时未领取」企微提醒——提醒降噪是该分流的核心收益之一（生产曾大量技术卡堆积待排期持续触发提醒噪声）
- 「移入非实施」回写功能排期卡性质是闭环关键：只改实施卡不回写源头时，同功能次日新完成卡会再次聚合成业务卡，造成「每日重复移入」；回写后次日自动分流
- 「超 12 小时未领取」企微提醒对象维持**功能负责人**，不抄送业务对接人（2026-09-24 批复③）
