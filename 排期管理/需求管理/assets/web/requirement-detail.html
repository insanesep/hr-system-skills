会员储值到期提醒规则调整

产品确认中
需求描述
背景：运营侧每周人工筛选 30 天内到期的储值会员并逐个电话回访，单周约 1200 人，耗时 3 人天且遗漏率高。 痛点：现有报表仅支持到期当日查询，无法提前圈选；回访记录散落在企微，无法沉淀到会员档案。 期望：1）支持按「到期天数区间」圈选储值会员（7/15/30 天档）；2）圈选结果可一键导出或推送至企微群发助手；3）回访结果回写会员档案，形成闭环。上线后预计每周节省 2.5 人天，回访覆盖率从 62% 提升至 95% 以上。

① 业务诉求是什么

运营侧希望把「储值到期会员回访」从人工筛选 + 电话回访，升级为系统圈选 + 企微触达 + 结果回写的闭环，核心收益是节省人力与提升回访覆盖率。

② 本次方案完成了什么

  • 会员圈选新增「储值到期天数区间」条件（7/15/30 天档），复用现有圈选引擎
  • 圈选结果对接企微群发助手推送，名单不落地导出（合规）
  • 回访结果页新增「回访结论」回写会员档案

③ 信息缺口与建议业务补充的内容

以下 3 项建议业务侧补充确认，不影响主流程评审：

信息缺口
  • 储值到期口径：按「储值有效期截止日」还是「最后消费日 + 365 天」？两种口径存量差约 8%
  • 回访结论的枚举值清单（已接通已续费 / 已接通无意向 / 未接通…）需业务提供终稿
  • 企微群发频次限制（同人同周 ≤1 次）是否适用于本场景
▶方案全文（七步分析）

一、诉求还原：储值会员到期回访自动化闭环。

二、存量模块排重：会员圈选引擎（member-circle）已支持 12 类条件，新增条件为低风险扩展；企微群发助手已有对接通道。

三、Tool 实查可行性：圈选条件扩展点 ConditionProvider SPI 可挂接；群发接口配额需确认。

四、端型权限：Web 管理后台，圈选页面新增条件项 + 回访结果页；权限复用 MENU:MEMBER:CIRCLE。

五、状态机通知：回访结论回写不涉及审批流；圈选任务完成走现有站内通知。

六、归属与工作量：会员域，后端 3 人日 + 前端 2 人日。

七、信息缺口：见上方清单 3 项。
