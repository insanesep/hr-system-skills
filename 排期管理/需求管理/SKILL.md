# 需求管理

面向全公司各业务线的需求受理中枢：业务线员工提交功能需求时**先选定提交对象（产品经理）**，系统按其审批链逐级或签审批（级次由配置决定，1~3 级）后，由该产品经理关联到功能排期卡片，形成「需求提出 → 审批归集 → 研发排期」的完整可追溯链路。

替代需求散落在企微群与 Excel 的现状，解决「需求谁提的、卡在哪级、有没有排上开发」三个核心问题。

需求按**产品线**分治：`SNACK`（鸣鸣很忙，再分 4 条业务线）与 `YDTJ`（有点推荐，不分业务线）。其中有点推荐额外支持内部人生成**一次性定向外链**，让外部人员免登录手填姓名与部门后提交需求（外部人无提交对象，固定走默认审批链）。

下游承接按**需求类型**分流：功能类需求审批通过后由产品经理关联功能排期卡片，系统生成 Qoder 开发会话承接实施；「缺陷修复」类单据为**人工报 bug 的唯一入口**，审批通过后不进入功能排期，自动转建黑灯工厂工单走自动化修复闭环，工单状态只读回传需求详情页（规则真源 business-rule §2.7 / §5.2）。

## 端

**Web 管理后台 + App 员工端 + 公开 H5 三端**：

- **Web 管理后台**（「研发」分组下）：需求提交与草稿编辑、审批处理、排期关联、外链生成与台账管理、审批链配置与统计导出，为主操作端；全类型附件（文档/图片/视频）上传与预览下载、SLA 催办配置与滞留看板也仅在本端提供
- **App 员工端**：轻量提交、待我审批的快速通过/驳回、我的需求进度查看，以及图片附件上传与预览；不提供审批链配置、统计导出、排期关联/解除、外链生成、文档/视频上传与 SLA 管理
- **公开 H5**（免登录，仅有点推荐）：外部人员凭定向 token 链接提交需求，仅 3 个页面（提交 / 成功 / 失效），支持受限图片上传（≤5MB/张，最多 3 张），**完全单向收口**：不可查进度、不可撤回、无草稿、无通知回传

## When to Use

- 运营 / 财务 / 供应链 / 数字化任一业务线员工需要提出系统功能需求，且需要留痕与审批
- 业务线负责人需要集中处理本业务线待审需求，判断需求合理性与优先级
- 实施负责人需要归集各业务线已审需求，确认实施可行性
- 产品经理需要接收提交给自己的需求、将已确认需求关联到功能排期卡片，向提出方回传开发进度
- 管理员需要按提交对象（产品经理）维护专属审批链、维护各产品线 / 业务线的默认链，或导出需求受理量、驳回率等统计数据
- 提交人需要附上原型图、需求文档、问题录屏等材料辅助审批人理解，或在审批中按审批人要求补传材料
- 管理员需要治理审批长期停留：配置超时催办 / 升级阈值、查看滞留需求看板、盯各业务线审批耗时与超时率
- 内部人需要向外部伙伴 / 兼职人员采集有点推荐需求，对方无系统账号，需发一个临时链接让对方自行填写提交
- 任何人（含外部人员经外链）发现系统 bug，需要提交缺陷修复单据并经审批确认后转黑灯工厂自动化修复

## 页面功能概览

### Web 管理后台（7 页）

| 页面 | 功能概述 |
|------|---------|
| 需求列表 | 全量需求分页查询与多维筛选（含产品线、提交来源）；按「我提交的 / 待我审批 / 外部提交 / 全部」分流；展示当前审批级次与关联卡片编号，支持列表导出；另提供「滞留需求」看板视角（停留时长倒序 + 行内手动催办） |
| 需求提交 | 新建 / 编辑草稿：**先选提交对象（产品经理）**（人员搜索选择器，选定后实时预览将命中的审批链级次与审批人），再填标题、描述、需求类型、优先级、产品线、业务线（选有点推荐时业务线自动隐藏）、目标完成日期；支持存草稿与正式提交；附件区支持拖拽上传文档/图片/视频（删除仅草稿态） |
| 需求详情 | 需求全量信息（含提交对象）+ 审批进度条（按快照实际级次渲染 1~3 节点）+ 审批流水时间线 + 关联排期卡片状态（功能单关联后展示 Qoder 开发会话入口；缺陷修复单替代为黑灯工厂工单状态只读回传区）+ **AI 方案确认面板**（三段式确认摘要 / 方案全文 / 信息缺口清单，仅当前级次审批人与管理员可见）；外部单额外展示「外部提交」标识与提交人/部门/手机号/邀约人区块；附件折叠面板支持在线预览（图片放大查看 / PDF 内嵌 / 视频播放）与下载，审批中可由提交人追加附件 |
| 外链管理 | 生成一次性定向外链（邀约对象备注 / 有效期 / 提交上限），展示链接与二维码供复制发送；台账查看访问/提交状态与产生的需求，支持撤销 |
| 审批链配置 | 管理员**先选提交对象（产品经理）再配置其审批流程**：专属链级次为 L1/L2/L3 任意非空子集、各级或签多人；选定 PM 后提供「AI 辅助方案确认」开关（PM 粒度，开启后需求进入产品确认节点自动生成 AI 方案草稿）；「默认链」按「产品线 × 业务线 × 需求类型 × 优先级」四维维护（SNACK 配齐 L1/L2，YDTJ 配齐三级承接外部提交）；提供受理量、通过率、平均审批时长统计与导出 |
| SLA 配置 | 管理员按「产品线 × 优先级 × 审批级次」维护审批超时催办阈值、升级阈值与催办去重窗口（与审批链配置同级菜单，改后立即对在途需求生效）。菜单权限 `MENU:RND:REQUIREMENT_SLA_CONFIG`（**写操作额外要求管理员**）|
| SLA 仪表盘 | 按业务线 / 审批级次统计平均审批耗时、提交→已关联排期的端到端平均周期、超时率与趋势图（按周/月聚合），支持下钻至滞留列表与导出。菜单权限 `MENU:RND:REQUIREMENT_SLA`（导出复用 `BTN:REQUIREMENT_STAT:EXPORT`）|

## Tips

- 需求编号 `REQ-{YYYYMMDD}-{NNN}` 一经生成不可变，驳回重提沿用原编号，不新建需求记录
- **内部提交必先选定提交对象（产品经理）**：按其专属链流转（级次为 L1/L2/L3 的任意非空子集）；候选集仅含本归属有专属链的 PM，内部提交必中专属链，「提交给谁就由谁终审」由专属链 L3 = PM 本人承载
- 提交对象候选集为**配置驱动**：按「产品线 × 业务线」过滤，仅包含该归属下配有启用中专属链的在职 PM（去重）；配置页选人走全员搜索，不用该候选集（避免新 PM 无法被配置的循环依赖）
- 外部提交（有点推荐外链）无提交对象，固定走默认链全量三级；L3 实际通过人自动记为该需求的产品经理
- 审批链在提交时快照，配置变更不影响流转中的需求，避免中途换人导致审批断链
- 各级审批均为或签：同级多人任一通过即流转，无需全员确认；审批级次由命中的链决定（1~3 级），未配置的级次直接跳过
- 排期关联为单向引用，只读取排期卡片状态，不回写卡片任何字段，避免与功能排期双向耦合
- **需求类型=缺陷修复（BUGFIX）即人工报 bug 唯一入口**：审批通过后自动分流黑灯工厂建单（待判断类，级别按 P0/P1→P1、P2/P3→P2 映射），不开放排期关联；工单状态只读回传详情页，关闭时通知提交人与产品经理（规则真源 business-rule §2.7）
- 功能类需求关联排期卡片后系统生成 Qoder 开发会话承接实施（business-rule §5.2）；缺陷单不生成开发会话，由黑灯工厂承接
- 企微群消息按产品线 / 业务线路由到对应群机器人，映射维护在审批链配置中，新增业务线需同步补齐映射否则群消息静默失败
- 需求描述质量直接影响 L1 驳回率，提交引导文案须与需求打磨规范保持同步更新
- 优先级由提交人初填、审批人可调整，最终以末级审批通过时的值为准
- 产品线与业务线是两个独立维度：`YDTJ`（有点推荐）不拆业务线，**不得为它新增业务线枚举值**
- 外部提交单**不新增任何状态**，复用同一套 10 态状态机；但草稿、驳回重提、提交人撤回、提交人即审批人自动跳过四条规则均不适用
- 外部单被驳回即真终态，如仍有价值由实施负责人新建内部单并引用原编号溯源，**不做「转内部单」功能**
- 外部提交人不建系统账号与系统部门，姓名与部门以自由文本随需求记录，严禁为外部人建临时账号或临时部门
- 外链为一次性定向发放：可重复访问但提交默认限 1 次，因不可重填所以提交前必须有预览确认弹窗
- 外部提交防刷不用短信验证码（不回传则无需验证手机号真实性），靠图形验证码 + token 提交上限 + IP 限流三道防线
- 附件存储走 OSS，按月分目录、文件名 UUID 化防重，库内只存元信息；**内部端由前端取临时凭证直传 OSS（公开 H5 例外，走后端转存），后端只收元信息并按上传来源端强校验**
- 预览与下载一律走签名 URL、不暴露 Bucket 永久直链；签名由前端自签，有效期以前端实现为准（Web 端为 1 小时）；不提供后端中转下载，鉴权前置在附件列表查询
- **不做附件内容安全审核**：未删除附件对有权看该需求的人均可见
- 外部 H5 仅开放图片上传（≤5MB/张、最多 3 张），文档/视频限内部端；三端限制一律由后端按上传来源端强校验，前端限制只是体验前置
- 审批超时催办：L1/L2 超 48h 未处理触发企微催办，超 72h 升级通知上级（紧急 P0 收紧为 24h/48h，低优先级 P3 放宽为 72h/120h）；同需求同级次在一个催办窗口（默认 24h）内只发一次
- 目标日期预警：目标完成日期临近 ≤7 天且未关联排期时推送 L2 实施负责人，每条需求每天最多一条
- SLA 仪表盘按业务线/级次统计平均审批耗时与端到端周期；**SLA 配置不做快照**（与审批链快照相反），改后立即对在途需求生效
- 附件删除仅草稿态开放，**一律只做逻辑删除、不从 OSS 物理移除**（含草稿态；异步清理失败会以「OSS 报错」形态掩盖业务首因，孤儿对象交 Bucket 生命周期规则回收）；审批中追加附件会通知当前审批人，但**不重置 SLA 停留计时**；可追加态为 `SUBMITTED` + 三个 `*_REVIEWING` 四态
- SLA 菜单拆为两个权限码：`MENU:RND:REQUIREMENT_SLA`（仪表盘）+ `MENU:RND:REQUIREMENT_SLA_CONFIG`（配置），一个权限码挂不出侧边栏两行菜单；滞留列表与手动催办沿用需求管理菜单权限 `MENU:RND:REQUIREMENT`
- 🚨 静默时段（22:00–08:00）命中催办/升级条件时**只记延后事件、不占用去重窗口**，在 08:00 那轮正常判定发送；若静默期占用了去重窗口，08:00 那轮必被跳过，催办永远发不出去；**手动催办不受静默时段限制**
- 🚨 催办去重必须区分审批轮次：驳回重提后停留时长归零、级次回 L1，不区分轮次会让新一轮催办与上一轮判为重复而被永久去重
- **AI 方案确认（规则真源 business-rule §11）**：需求进入产品确认节点（`PM_REVIEWING`）且当前级次审批人含开启「AI 辅助方案确认」开关的 PM 时，自动按固定七步分析框架（诉求还原 → 存量模块排重 → Tool 实查可行性 → 端型权限 → 状态机通知 → 归属与工作量 → 信息缺口）生成方案草稿与三段式确认摘要（业务诉求 / 本次完成内容 / 建议业务补充的信息），企微通知 PM 回详情页确认
