# 需求管理

面向业务、实施、运维的需求受理中枢：提交人先选定提交对象（产品经理），系统按其专属审批链逐级或签归集，审批确认后关联功能排期卡片，形成「需求提出 → 审批归集 → 研发排期」的可追溯链路。替代需求散落在 IM 群与 Excel 的现状，解决「谁提的、卡在哪级、有没有排上开发」三个核心问题。

## 服务对象与端

- **服务对象**：业务、实施、运维全体提交人；产品经理（审批与归集）；管理员（审批链与 SLA 配置）
- **Web 管理端**：主操作端——提交、审批、排期关联、外链台账、审批链配置、SLA 配置与统计导出
- **App 员工端**：轻量提交、待我审批快速处理、我的需求进度查看（图片附件）
- **公开 H5**（免登录）：外部人员凭一次性定向外链提交需求，单向收口——不可查进度、不可撤回、无通知回传

## 需求类型与分流

| 类型 | 去向 |
| ---- | ---- |
| 功能需求 | 审批链归集 → 产品确认 → 关联功能排期卡片（本模块主链路） |
| 需求变更 | 生成对应的 Qoder 会话，由 AI 辅助完成变更分析与实现（变更内容回写需求留痕） |
| bug | 走黑灯工厂自动化修复通道（见 `运维管理/黑灯工厂管理`），修复结果回写需求状态 |

## 核心规则

### 提交与审批

- 需求编号 `REQ-{YYYYMMDD}-{NNN}` 一经生成不可变；驳回重提沿用原编号，不新建记录
- 内部提交**先选提交对象（产品经理）**：候选集按「产品线 × 业务线」收窄为本归属下配有启用中专属链的 PM；命中专属链按链流转（级次为 L1/L2/L3 任意非空子集）
- 外部提交（免登录外链）无提交对象，固定走默认审批链全量三级，末级实际通过人写入产品经理字段
- 审批链在提交时**快照**，配置变更不影响在途需求，避免中途换人断链
- 各级审批均为**或签**：同级多人任一通过即流转；未配置的级次直接跳过
- 优先级由提交人初填、审批人可调整，以末级审批通过时的值为准

### 状态机

`草稿 → 已提交 → L1~L3 审批中（按快照级次递进） → 已确认（待关联排期） → 已关联排期`；异常出口：`已驳回`（可重提）、`已撤回`（仅审批中且提交人操作）。外部提交单不新增状态，复用同一状态机，但草稿、驳回重提、撤回规则不适用——外部单被驳回即终态，仍有价值由实施负责人新建内部单引用原编号溯源。

### 排期关联

- 审批确认后由产品经理关联到功能排期卡片（见 `排期管理/功能排期`）
- **单向引用**：只读排期卡片状态用于回传开发进度，不回写卡片任何字段，避免双向耦合

### SLA 与催办

- 按「产品线 × 优先级 × 审批级次」维护超时催办阈值、升级阈值与去重窗口；改后立即对在途需求生效（SLA 配置不做快照，与审批链快照相反）
- 命中催办/升级条件走 IM 通知；静默时段（如 22:00–08:00）只记延迟事件，次时段恢复判定
- 催办去重键必含**审批轮次**：驳回重提后停留归零、级次回 L1，缺轮次段会导致新一轮催办被永久去重
- 目标完成日期临近且未关联排期时预警实施负责人，每需求每天最多一条
- 仪表盘按业务线/级次统计平均审批耗时、端到端周期（提交 → 已关联排期）与超时率，支持滞留看板与导出

### AI 方案确认

- 需求进入产品确认节点且当前审批人开启了「AI 辅助方案确认」（per-PM 开关）时，自动按固定分析框架生成方案草稿、三段式确认摘要（业务诉求 / 本次完成内容 / 建议补充的信息）与信息缺口清单
- 三条红线：**AI 内容未经 PM 人工确认不得触达提交人**；**系统不自动审批**（「确认并通过」由 PM 点击触发、以 PM 身份执行）；**AI 生成失败不阻塞人工通道**
- 执行记录按审批轮次隔离、版本递增，支持「请求补充材料 → 再分析 → 确认」闭环

### 外部提交（免登录外链）

- 内部人生成一次性定向外链（有效期 / 提交上限可配），外部人免登录填写姓名、部门、联系方式后提交；支持受限图片附件
- 防刷不依赖短信验证码：图形验证码 + token 提交上限 + IP 限流三道防线
- 外部提交人不建系统账号，姓名与部门以自由文本落库

### 附件

- 三端差异化：Web 全类型（文档/图片/视频）、App 仅图片、公开 H5 受限图片；限制一律由后端按上传来源强校验
- 删除仅草稿态开放，一律逻辑删除不物理移除；审批中追加附件通知当前审批人但不重置 SLA 计时

## 关键约束

- 需求描述质量直接影响一级驳回率，提交引导文案须与需求打磨规范保持同步
- 产品线与业务线是两个独立维度；不拆业务线的产品线业务线字段固定写 `*`，不得新增枚举
- 审批流转统一接入流程中心类审批引擎时遵循三原则：本模块审批链配置为镜像唯一真源、页内审批入口保留、双通道（引擎待办与本模块页面）可审批；配置任何变更必须同步镜像并回归
- 权限最小授予：审批链配置与 SLA 配置仅管理员；统计导出走统一导出通道
