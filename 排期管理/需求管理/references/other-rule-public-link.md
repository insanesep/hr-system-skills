# 需求管理 · 外链邀约与外部提交

> 有点推荐（`YDTJ`）外链邀约与外部免登录提交的规则真源，仅有点推荐产品线开放；能力范式对齐采购邀约的 token 反查模式（采购邀约文档尚未迁入，见 [SKILL.md](../SKILL.md) Prerequisites）。外部单的状态差异见 [state-machine.md §6](state-machine.md#6-外部提交单差异)，H5 附件见 [other-rule-attachment.md §5](other-rule-attachment.md#5-h5-附件规则)，H5 页面见 [app-ui.md 公开 H5](app-ui.md#公开-h5)，外链台账页面见 [web-ui.md 外链管理页](web-ui.md#外链管理页)。

## 1. 外链形态

外链为一次性定向 token：

- 链接由内部人**逐个生成、定向发放**，不提供长期通用链接，不得公开张贴或群发
- **链接中唯一参数为 token**，产品线、业务线、邀约对象、有效期全部由 token 反查
- 生成后同时提供二维码（内容即完整链接），供微信 / 企微发送
- 生成时内部人必填**邀约对象备注**（公司 / 联系人），仅供内部溯源与台账识别；外部人进页后**仍需手填自己的姓名与部门**（可用备注值预填，允许修改）

## 2. 一次性语义

| 维度 | 口径 |
|------|------|
| 访问次数 | **不限制**，可重复打开（避免误关页即失效），仅计数 |
| 提交次数 | 默认上限 **1 次**，生成时可配；达上限后链接置为已提交（`USED`） |
| 达上限后访问 | 展现「已提交」提示页（带需求编号），不再展示表单 |
| 有效期 | 默认 30 天，可配 7 / 15 / 30 / 60 / 90 天；过期后无论是否提交过均置为已过期（`EXPIRED`） |
| 撤销 | 邀约人与管理员可随时撤销未使用链接，已提交产生的需求不受影响 |

- 因提交后**不可重填也不可修改**，提交前必须弹出**预览确认弹窗**，完整回显标题、描述、类型、姓名、部门、手机号与已选图片，见 [app-ui.md 需求提交页](app-ui.md#需求提交页)

## 3. 外部提交字段边界

| 字段 | 外部人是否可填 | 说明 |
|------|---------------|------|
| 需求标题 | ✅ 必填 | ≤ 128 字 |
| 需求描述 | ✅ 必填 | ≥ 20 字，≤ 2000 字（高于内部门槛，降低无效单） |
| 需求类型 | ✅ 必选 | 默认值由链接携带，可改 |
| 提交人姓名 | ✅ 必填 | ≤ 64 字 |
| 提交人部门 | ✅ 必填 | **自由文本，不关联系统部门** |
| 手机号 | ✅ 必填 | 仅格式校验，**不发短信不做真实性验证**，仅供内部回访 |
| 业务线 | ❌ 不展示 | 系统固定为不区分 |
| 优先级 | ❌ 不展示 | 统一入库为链接默认值（默认 `P2`），由审批人在审批通过时修正 |
| 附件 | ⚠️ 仅图片 | **仅开放图片上传**（≤ 5MB/张，最多 3 张，单次提交总大小 ≤ 15MB）；文档与视频不开放（免登录上传存在存储滥用与恶意文件风险），见 [other-rule-attachment.md §5](other-rule-attachment.md#5-h5-附件规则) |

- 外部提交人不建系统账号与系统部门，姓名、部门、手机号以自由文本随需求记录，严禁为外部人建临时账号或临时部门

## 4. 安全与防刷

因**不回传结果**，手机号无需真实性校验，防刷为下列四道（**不使用短信验证码**）：

| 防线 | 规则 |
|------|------|
| 外链有效性 | 非法 / 过期 / 已撤销 / 达提交上限均拒绝，不区分返回时延（防枚举） |
| 图形验证码 | 提交前必填，5 分钟有效、一次性消费；连续错 3 次强制刷新 |
| 提交次数上限 | 单个外链默认 1 次，计数递增与需求写入在同一事务内并加锁 |
| IP 频率限制 | 单 IP 对公开入口 **10 次/分钟**，超限返回统一限流文案并记限流审计事件 |

- 全部公开入口的访问记录来源 IP、客户端标识与对应外链，写入事件审计供异常回溯
- 外部提交内容进入内部列表前不做自动审查，但详情页必须显式标识「外部提交」以提醒审批人警惕

## 5. 单向收口

外部提交**完全单向**：除提交成功页展示需求编号外，系统不向外部人回传提交之后的任何信息。

- 不提供进度查询页、不发短信 / 邮件通知、不提供回执码自查
- 需求编号仅作为提交凭证展示，供外部人线下向邀约人查询使用
- 外部单的任何状态变更（通过 / 驳回 / 关联排期）均**只通知邀约人**，由邀约人自行决定是否线下告知外部人
- 外链因未命中审批链配置而提交失败时，向邀约人推送企微告警「您发放的需求外链提交失败：有点推荐审批链未配置」

## 6. 统计口径

- 需求总量、驳回率、平均审批时长等现有指标均**默认含外部单**，可按提交来源与产品线下钻
- 外链专属指标：链接生成数 / 访问转化率（已产生提交的链接数 ÷ 生成数）/ 外部单驳回率，用于评估外部需求质量
- 外部单驳回率持续偏高时，应回收对应邀约人的外链生成权限（运营措施，非系统自动）

## 7. 外链操作

**内部操作**（需登录）：

| 操作 | 规则 |
|------|------|
| 生成外链 | 填写邀约对象备注、有效期天数、提交次数上限、需求类型默认值；**只生成完整链接，二维码由前端依链接本地生成**（沿用采购邀约范式） |
| 外链台账 | 分页查询，支持状态 / 邀约对象 / 生成人 / 时间区间筛选；非管理员仅可见本人生成的链接（服务端强制收口，不依赖前端传参） |
| 撤销外链 | 仅待使用（`GENERATED`）可撤销，必填撤销原因；已提交产生的需求不受影响 |

**公开入口**（免登录）：

| 操作 | 规则 |
|------|------|
| 校验链接 | 仅凭 token 校验；返回是否可用、邀约对象备注（预填用）与需求类型可选项，不可用时返回失效原因 |
| 图形验证码 | 按 token 下发验证码图片，5 分钟有效，一次性消费 |
| 提交需求 | 提交 token、验证码、标题、描述、需求类型、姓名、部门、手机号与已转存图片；成功返回需求编号 |

- 公开入口须显式声明为免登录，**不得与内部提交共用处理入口**
- 公开入口的返回内容不得包含任何内部人员姓名、审批人信息、业务线枚举、需求列表数据（邀约对象备注除外，因其为邀约人主动填写）
- 所有公开入口调用均写入事件审计，记录来源 IP 与客户端标识
