## 端能力边界

business-rule §4.2：**App 端仅开放需求提交、L1/L2/L3 审批通过与驳回、进度查看**。审批链配置、统计导出、排期卡片关联/解除关联**不在 App 端提供**，详情页对应区块以只读形式展示。

### 外链与外部单的 App 端边界

- **外链生成与台账管理不在 App 端提供**（business-rule §4.2）：App 无「外链管理」入口，需到 Web 端操作；详情页外部提交区块内不提供任何跳外链台账的链接
- **外部提交单（`EXTERNAL`）在 App 端全程只读 + 可审批**：审批人可通过 / 驳回，但编辑、撤回、重新提交、删除四类操作**一律不渲染**（business-rule §2.6，外部单无内部提交人主体，内部人也不得代操作）
- 外部单进入 App 的唯一路径是「待我审批」Tab 与详情页 Deep-link，**不会出现在「我提交的」Tab**（外部单无内部提交人）

### 附件与 SLA 的 App 端边界

- **附件仅开放图片**（business-rule §9.1）：App 端提交页支持相册选择与拍照上传图片，单张 ≤10MB、最多 20 张；**文档与视频上传不在 App 端提供**（需到 Web 端补充），详情页遇到 Web 端上传的文档/视频只展示文件行并提供「下载」，不提供在线预览
- **图片为即时上传**：选完即上传，随提交一并归属该需求；未提交就离开页面时，已上传的图片不归属任何需求，由存储侧自动清理
- **附件不做内容安全审核**：App 端不渲染任何审核角标，未删除的图片一律进入列表且可直接预览
- **预览与下载走短时效签名链接**：仅能查看该需求的人才能获取其附件，页面不展示存储永久直链
- **附件删除仅草稿态**，而草稿编辑能力不在 App 端提供，因此 App 端**全程不渲染删除附件入口**（business-rule §9.6）
- **审批中追加附件不在 App 端提供**（追加入口仅 Web 端详情页），App 详情页附件区块为只读浏览
- **SLA 配置页与 SLA 仪表盘不在 App 端提供**（Web 端管理能力）；App 端仅承接催办通知的 Deep-link 直达详情页，页面本身不展示滞留时长与超时阈值

## 全局约定

### 状态标签色值语义

| 状态 | 标签文案 | 语义色 |
|------|---------|-------|
| `DRAFT` | 草稿 | 灰 |
| `SUBMITTED` | 已提交 | 蓝 |
| `BU_REVIEWING` | 业务线审批中 | 蓝 |
| `IMPL_REVIEWING` | 实施确认中 | 蓝 |
| `PM_REVIEWING` | 产品确认中 | 蓝 |
| `PM_SUBMITTED` | 待关联排期（缺陷修复单为「待转黑灯工厂」） | 橙 |
| `LINKED` | 已关联排期（缺陷修复单为「已转黑灯工厂」） | 绿 |
| `REJECTED` | 已驳回 | 红 |

- `BU_APPROVED` / `IMPL_CONFIRMED` 为瞬时态，App 端不展示为独立状态、不作为独立时间线节点
- 优先级标签：`P0 紧急`=红 / `P1 高`=橙 / `P2 中`=蓝 / `P3 低`=灰
- 业务线彩色药丸：运营 / 财务 / 供应链 / 数字化，四色固定，与 Web 端映射一致
- 产品线彩色药丸：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`，两色固定，与 Web 端映射一致；`YDTJ` 需求**不渲染业务线药丸**（业务线占位值 `*` 不向用户呈现）
- 提交来源标签：内部 `INTERNAL` 不展示标签（默认态）；外部 `EXTERNAL` 展示橙色「外部提交」标签，与 Web 端一致
- 排期开发状态标签：`PENDING` 待开发=灰 / `IN_PROGRESS` 开发中=蓝 / `DONE` 开发完成=绿

### 附件类型与展示形式

| 类型 | 图标语义 | 扩展名 | App 端能力 |
|------|---------|-------|-----------|
| 图片 `image` | 图片图标（蓝） | jpg / jpeg / png / webp / gif | 可上传（相册/拍照）、缩略图网格展示、可预览、可长按保存 |
| 文档 `document` | 文档图标（绿） | pdf / docx / xlsx / pptx / txt | 不可上传；文件行只读 + 「下载」（调起系统能力打开） |
| 视频 `video` | 视频图标（紫） | mp4 / mov | 不可上传；文件行只读 + 「下载」 |

### 枚举取值（以 data-model.md 为准）

- **产品线**：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`（固定 2 值）
- **业务线**：运营 `OPS` / 财务 `FIN` / 供应链 `SCM` / 数字化 `DIGITAL`；`*` 为 `YDTJ` 内部占位值，**不进入选择器选项与展示**
- **需求类型**：新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成（5 值，与 Web 端一致，不使用「其他」）
- **提交来源**：内部 `INTERNAL` / 外部 `EXTERNAL`（App 端只展示不可筛选）

| 来源 | 去向 | 触发 | 导航方式 |
|------|------|------|---------|
| 工作台 | 我的需求列表 | 点击「需求管理」入口卡片 | Push |
| 企微消息（个人/群） | 需求详情 | 点击消息内详情链接（鉴权后定向） | Push（Deep-link） |
| 我的需求列表 | 需求详情 | 点击需求卡片 | Push |

## 页面清单

### 我的需求列表

- **权限编码**：
  - 菜单：`M:RD:REQUIREMENT`
  - 独占：`M:RD:REQUIREMENT_M`
- **导航方式**：Push（从工作台「需求管理」入口进入）
- **页面类型**：列表页（卡片式）
- **区块职责**：
  - 顶部导航栏：返回按钮 + 标题「需求管理」+ 右侧「提交」文字按钮（需 `M:RD:REQUIREMENT` 权限）
  - 顶部 Tab 切换（3 个，吸顶）：
    - **我提交的**：本人提交的全部需求（含 `DRAFT`）；外部单无内部提交人，**天然不进本 Tab**
    - **待我审批**：当前登录人处于审批链快照当前级次的待审需求（**含外部单**）；**Tab 右上角显示数字角标**（>99 显示 `99+`；为 0 时不展示角标）
    - **已完成**：`LINKED` + `REJECTED` 终态需求（按角色可见范围取数，含外部单）
    - App 端**不提供「外部提交」独立 Tab**（该视角仅 Web 端提供），也不提供产品线 / 提交来源筛选器
  - 主体区：卡片列表，每张卡片自上而下：
    - 第一行：标题（最多 2 行，超长省略）；外部单标题前缀橙色「外部提交」标签
    - 第二行：产品线药丸 + 业务线彩色药丸（`YDTJ` 不渲染）+ 优先级标签 + 状态标签
    - 第三行：需求编号 + 提交时间（`DRAFT` 无提交时间时展示「未提交」）
    - 「待我审批」Tab 卡片额外展示：提交人 + 等待时长（如「已等待 2 天」）；**外部单提交人取外部提交人手填姓名** + 后跟灰色小字手填部门
    - 整卡可点击 → Push 需求详情
- **交互**：下拉刷新 / 上滑加载更多（每页 20 条）/ 空状态提示
- **布局引用**：参见原型 `assets/app/requirement-list.html`

#### 导航关系

- 来源页：工作台「需求管理」入口卡片
- 去向页：需求详情（点卡片）、需求提交（点右上角「提交」）
- 返回行为：导航栏返回按钮 Pop 回工作台
- 手势返回：允许（Pop 回工作台）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| Tab 切换 | 点击 Tab | 否 | 列表骨架屏（3 张占位卡片） | 列表按视角刷新，页码重置为 1 | 错误轻提示「加载失败」+ 保留原 Tab，提供「点击重试」 |
| 查看详情 | 点击卡片 | 否 | — | Push 到需求详情 | — |
| 提交需求 | 点击右上角「提交」 | 否 | — | Push 到需求提交页 | — |
| 下拉刷新 | 下拉手势 | 否 | 顶部刷新指示器 | 列表刷新 + 待我审批角标同步更新 | 错误轻提示「刷新失败，请重试」 |
| 上滑加载更多 | 滚动到底部且有下一页 | 否 | 底部加载指示器 | 追加数据；无更多时展示「没有更多了」 | 错误轻提示「加载失败，点击重试」 |

#### 列表三态

- **空态**：
  - 我提交的：空插图 + 「你还没有提交过需求」+「立即提交」按钮
  - 待我审批：空插图 + 「暂无待你审批的需求」
  - 已完成：空插图 + 「暂无已完成的需求」
- **加载态**：卡片骨架屏（3 张占位卡片）
- **错误态**：错误插图 + 「点击重试」按钮

### 需求详情

- **权限编码**：
  - 菜单：`M:RD:REQUIREMENT`
  - 独占：`M:RD:REQUIREMENT_M`
- **导航方式**：Push
- **页面类型**：详情页
- **区块职责**：
  - 顶部导航栏：返回按钮 + 标题「需求详情」
  - **需求信息区（卡片式）**：需求编号 + 状态标签（外部单额外跟橙色「外部提交」标签）/ 标题 / 描述（纯文本渲染，超过 5 行折叠「展开全部」）/ **提交对象（产品经理姓名；外部单 L3 通过前展示灰色「待产品确认通过后归集」）** / 产品线药丸 / 业务线药丸（`YDTJ` 不渲染该行）/ 优先级标签 / 需求类型 / 目标日期 / 提交人 / 提交时间
    - `REJECTED` 状态时卡片顶部红色提示条：展示最近一次驳回人 + 驳回意见全文；**外部单提示条追加「外部提交单驳回即终态，不可重新提交」**（business-rule §2.6）
  - **外部提交区块（卡片式，仅外部提交单渲染，置于需求信息区下方、审批时间线之上）**：
    - 卡片标题「外部提交信息」+ 橙色「外部提交」标签
    - 信息行（均只读）：提交人姓名 / 所属部门（后跟灰色小字「手填，未关联组织架构」）/ 手机号（支持长按复制）/ 提交时间 / 邀约人姓名
    - 手机号**仅供内部人员人工回访**，可长按复制或点击拨号；系统不向外部提交人发送任何短信/通知（business-rule §8.5 单向收口）
    - 区块内**不提供外链台账跳转、不提供转内部单、不提供代撤回**（外链台账仅 Web 端提供）
  - **附件区块（卡片式，置于外部提交区块下方、审批时间线之上）**：
    - 卡片标题「附件（N）」；N=0 时渲染灰字「无附件」占位行（**不隐藏卡片**，保持页面结构稳定）
    - **图片组：缩略图网格**（每行 3 张、正方形裁切、圆角），按上传时间正序；超过 9 张时默认展示前 9 张 + 末位盖一层「+N」蒙层，点击展开全部
    - 缩略图右下角小字展示上传来源（外部单图片打「外部上传」橙色角标）；不渲染任何审核角标
    - **点击缩略图** → 全屏图片浏览器（左右滑动切图、双指缩放、顶部「M/N」计数、点击空白或下滑关闭）
    - **长按缩略图或全屏图** → 底部操作面板：「保存到相册」/「查看大图」/「取消」；首次保存需申请相册写入权限，被拒时轻提示「请在系统设置中开启相册权限」
    - **文档/视频组：纵向文件行**（置于图片网格下方）：类型图标 + 文件名（超长中间省略保留扩展名）+ 文件大小 + 右侧「下载」；App 端**不提供文档/视频的在线预览**
    - 🚨 区块内**不渲染任何上传/追加/删除按钮**：追加仅 Web 端详情页提供，删除仅草稿态且草稿编辑不在 App 端（business-rule §9.4 / §9.6）
  - **审批进度时间线（纵向卡片式）**：**按审批链快照渲染 1~3 个节点**（级次集合由提交时命中的链决定，business-rule §3.4；专属链级次由配置决定，可缺级）
    - 每节点展示：级次名称 / 角色 / 审批人（或签多人未动作时展示「张三、李四（或签）」，已动作展示实际动作人）/ 状态 / 审批意见 / 操作时间
    - 节点配色：**当前节点蓝色高亮**（左侧圆点蓝 + 卡片蓝色描边 + 「审批中」角标），已完成绿色，未开始灰色，已驳回红色
    - 自动跳过节点（提交人即该级审批人）展示灰色「已自动跳过」+ 说明文案；**外部单不可能出现自动跳过节点**（business-rule §2.6）
    - 内部单产品确认（L3）节点审批人即提交对象（business-rule §3.4）；时间线中不存在指派产品经理的节点行，产品经理在提交时即已确定
    - 驳回重提场景按轮次分组：默认展示最新一轮，历史轮次折叠为「查看第 N 轮审批记录」（外部单只有一轮，不渲染分组入口）
  - **AI 方案确认卡片（卡片式，置于审批时间线下方、排期关联区上方）**：
    - 🚨 **可见性收口（business-rule §11.1 红线一）**：仅当前级次审批人与管理员渲染，**提交人与其他角色一律不渲染**（可见性由服务端收口，App 端不自行推导）；无记录时不渲染卡片
    - 卡片标题「AI 方案确认」+ 状态标签（生成中 / 待确认 / 已确认 / 已作废 / 生成失败）+ 版本「V{版本号}」
    - **生成中**：卡片内 loading 占位 + 文案「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批」；每 5 秒刷新一次状态，离开页面即停
    - **待确认**：三段式确认摘要（① 业务诉求 ② 方案完成内容 ③ 信息缺口与建议补充）以富文本渲染，超过 8 行折叠「展开全部」；「方案全文（七步分析）」点击 Push 到独立只读页展示方案全文（避免详情页超长）
    - **生成失败**：红色提示条「AI 方案生成失败：{失败原因}」+「重新生成」按钮；旁注「不影响您人工审批」
    - **已作废**：卡片置灰只读 + 「该方案已作废（需求已被处理），仅供回顾」，不渲染操作按钮
    - 卡片底部操作（仅待确认态且当前用户为当前级次审批人）：「确认并通过」（全宽主按钮，弹意见确认半屏：AI 预填可编辑 10–200 字，顶部提示「通过意见将带【AI方案确认】前缀」）/「请求补充材料」（次按钮，半屏多行编辑以信息缺口预填，标题提示「以下内容将发送给提交人」）/「重新生成」（文字按钮，确认弹窗确认）
  - **排期关联区（卡片式，只读）**：
    - 已关联：卡片编号 + 开发状态标签（带颜色）+ 排期日期 + 开发人
    - 未关联：灰色提示「待关联排期」（App 端不提供关联/解除入口，需到 Web 端操作）
    - 缺陷修复（`BUGFIX`）单替换为黑灯工厂工单区：工单号 + 工单状态 + 负责人（只读回传，business-rule §2.7）
    - 卡片已失效：黄色提示条「关联卡片已失效，请到 Web 端重新关联」
  - **底部操作栏（吸底，位于安全区内）**：
    - 当前审批人可见：通过（绿色主按钮）/ 驳回（红色次按钮），左右等宽
    - 提交人可见（`REJECTED`）：重新提交（全宽主按钮）
    - 提交人可见（`SUBMITTED`/`BU_REVIEWING`）：撤回（全宽次按钮）
    - **外部单仅渲染审批类按钮**：重新提交 / 撤回 一律不渲染，非审批人进入时不渲染操作栏（business-rule §2.6）
    - 无可执行操作时不渲染操作栏，主体区底部内边距回收

#### 驳回意见半屏

- 标题「填写驳回意见」+ 多行输入框（占屏约 50%）+ 实时字数「N/200」
- 校验：必填，10–200 字；不满足时「确认驳回」按钮置灰 + 下方提示「驳回意见不少于 10 字」
- 键盘避让：输入区随键盘上推，确认按钮始终可见
- 关闭方式：点击遮罩 / 下拉手势关闭；有输入内容时先弹确认弹窗「放弃已填写的驳回意见？」

#### 交互约束

- 审批操作响应 ≤3 秒；请求超时**不解锁按钮**，轻提示「审批处理中，请勿重复点击，稍后到列表查看结果」
- 审批操作幂等：重复提交返回当前状态而非报错，页面静默刷新详情不弹错误
- 底部操作栏按钮可见性以服务端返回的可执行操作为准，App 端不自行推导角色；外部单的可执行操作不含编辑/撤回/重提，页面也不得渲染占位按钮
- 审批成功后 Pop 回列表时必须刷新「待我审批」角标计数
- 外部单驳回不触发任何向外部提交人的通知，仅通知邀约人（business-rule §8.5）；驳回半屏内不得出现「将告知提交人」类文案
- 附件预览/下载一律使用短时效签名链接：**不缓存、不复用、不分享**，每次预览重新签发，页面不得展示存储永久直链
- 附件区块为只读浏览，**附件加载失败不阻断详情页与审批操作**：区块内 inline「附件加载失败，点击重试」，底部操作栏正常可用

## 与业务规则对齐说明

| 对齐点 | 处理方式 |
|--------|---------|
| 需求类型枚举 | 采用 business-rule §3.1 / data-model 需求类型的 5 值，不使用「其他」 |
| 驳回意见长度 | 必填且 10–200 字（下限取 business-rule §2.4 的 ≥10 字） |
| 提交对象驱动 | 内部提交必选提交对象（产品经理），选定后实时预览审批链；详情页 L3 节点审批人即提交对象；**L2 通过无指派产品经理动作**（business-rule §1.3 / §3.4） |
| 排期关联入口 | App 端只读展示，不提供关联/解除（business-rule §4.2 端能力边界） |
| 草稿能力 | App 端不提供暂存草稿与草稿编辑，「我提交的」Tab 可查看 Web 端创建的草稿但不可编辑 |
| 撤回可见范围 | `SUBMITTED` + `BU_REVIEWING` 两状态（business-rule §2.5） |
| 瞬时态展示 | `BU_APPROVED` / `IMPL_CONFIRMED` 不作为独立状态标签与时间线节点（business-rule §2.3） |
| 或签待办关闭 | 同级他人先通过后，本人「待我审批」列表项自动消失，角标同步减一（business-rule §3.5） |
| 通知触发 | App 端不触发推送，企微个人/群消息由服务端在操作成功后异步发出（business-rule §6）|
| 产品线与业务线联动 | 产品线=有点推荐 时业务线行隐藏不参与校验，系统固定写占位值 `*`（business-rule §1.1）；`*` 不向用户展示也不可选 |
| 外部单可操作面 | App 端外部单仅可审批与查看，编辑/撤回/重提/删除全部不渲染（business-rule §2.6）|
| 外部身份展示 | 外部提交人姓名/部门为手填自由文本，不关联组织架构，不提供人员/部门详情跳转（data-model §1）|
| 外链能力 | 外链生成与台账仅 Web 端提供，App 无入口也无跳转（business-rule §4.2）|
| 单向收口 | App 端不提供任何向外部提交人发送信息的入口，手机号仅供内部联系（business-rule §8.5）|
| 附件类型能力 | App 端仅开放图片上传（相册/拍照，单张 ≤10MB、最多 20 张），文档与视频需到 Web 端上传（business-rule §9.1）|
| 附件删除与追加 | 删除仅草稿态、追加仅 Web 端详情页，App 详情页附件区块**全程只读**，不渲染上传/追加/删除按钮（business-rule §9.4 / §9.6）|
| 附件上传方式 | App 端图片选完即上传，提交成功后随需求一并归属；未提交离开时已上传图片不归属任何需求，由存储侧自动清理 |
| 附件审核 | 不做内容安全审核，App 不渲染任何审核角标，图片上传后即可预览 |
| 附件预览方式 | 图片走全屏浏览器并支持长按保存相册；文档/视频不提供在线预览，只提供下载后调起系统能力打开 |
| 签名链接纪律 | 附件预览/下载统一用短时效签名链接，不缓存不复用，页面不展示存储永久直链；无该需求查看权限即无法获取附件 |
| SLA 能力边界 | SLA 配置页与 SLA 仪表盘仅 Web 端提供；App 端仅承接催办通知 Deep-link，不展示滞留时长与超时阈值 |
| 催办通知触发 | 催办 / 升级 / 目标日期预警均由服务端定时任务异步发出，App 端不参与触发也不本地计算阈值（business-rule §10.1 / §10.8）|
| 静默时段 | 22:00–08:00 命中催办/升级条件时服务端只记录延后，到 08:00 那轮再判定发送，App 端在静默期内不会收到任何催办推送（job-schedule §3.2）|
