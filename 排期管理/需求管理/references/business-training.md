# 需求管理系统 — 业务操作培训手册

> 适用对象：全公司各业务线员工、业务线负责人、实施负责人、产品经理、系统管理员
> 覆盖端：Web 管理后台 / App 员工端 / 外链 H5（外部人员）

---

## 一、系统简介

### 1.1 这个系统解决什么问题

以前提需求靠在企微群里发一句话、或者发个 Excel 给对接人。结果消息刷过去就没人管、转了几手不知道卡在谁手上、提完也没下文。需求管理系统把这件事**搬进系统、全程留痕**，一屏回答三个核心问题：

| 核心问题 | 系统怎么回答 |
| --- | --- |
| **谁提的？** | 每条需求都有唯一编号和提交人，列表和详情都能看到 |
| **卡在哪一级？** | 审批进度条，当前卡在谁那里、等了几天，一眼可见 |
| **排上开发没有？** | 审批通过后由产品经理关联「排期卡片」，开发进度回传到需求详情页 |

### 1.2 完整链路

```
提交需求（先选提交对象·产品经理） → 按提交对象的审批链逐级审批 → 产品确认 → 关联排期卡片 → 研发开发
   (你)              （级次由配置决定：业务线审批 L1 / 实施确认 L2 / 产品确认 L3，可缺级）   (产品经理)   (研发)
```

💡 **审批链怎么来的**：你提交时选的「提交对象（产品经理）」决定走哪条审批链——**候选名单里只有本业务线配了专属链的产品经理**（没配专属链的 PM 选不到），选中即按其专属链走（可以只有产品确认一级，也可以是完整三级）。**提交给谁，谁终审。**

需求先按**产品线**分家：**鸣鸣很忙**（再细分运营 / 财务 / 供应链 / 数字化四条业务线）和**有点推荐**（不分业务线）。

### 1.3 三个端怎么选

| 端 | 谁用 | 能干什么 | 定位 |
| --- | --- | --- | --- |
| **Web 管理后台** | 全公司内部员工 | 提交、存草稿、审批、关联排期、生成外链、审批链配置、导出 | **主操作端，功能最全** |
| **App 员工端** | 全公司内部员工 | 提交、审批通过/驳回、看自己需求的进度 | 轻量应急，出差路上也能审 |
| **外链 H5** | **外部人员**（无系统账号） | 凭内部人发的一次性链接，免登录填写并提交需求 | 单向收口，只能提交，看不到进度 |

💡 **一句话选端**：要填得完整、要改草稿、要做管理动作 → 上 Web；只是想快速点个「通过」 → 用 App。

## 二、角色说明

系统里一共 5 种内部角色（外部提交人不算系统角色）。**同一个人可以有多个角色**，比如业务线负责人自己也能提需求。

| 角色 | 能做什么 | ❌ 不能做什么 |
| --- | --- | --- |
| **提交人**（业务线员工） | 提交需求、编辑自己的草稿、撤回（限早期）、被驳回后修改重提、删除自己的草稿 | 不能审批自己的需求；不能改别人的需求；不能关联排期 |
| **业务线负责人**（L1） | 审批**本业务线**的需求（通过 / 驳回）、调整优先级 | 不能审批其他业务线的需求；不能关联排期；不能配置审批链 |
| **实施负责人**（L2） | 审批**全部产品线、全部业务线**的需求（归集、去重、可行性判断） | 不能关联排期；不能配置审批链 |
| **产品经理**（L3，**提交对象**） | 审批提交给自己的需求、**关联/解除排期卡片** | 不能审批没提交给自己的需求；关联排期只能在 Web 端做 |
| **管理员** | 配置审批链、导出需求列表与审批统计、查看和撤销**全部**外链、需求全部可见 | — |

### 2.1 每个人能看到哪些需求

| 你的角色 | 列表里能看到 |
| --- | --- |
| 普通员工 | 只有**自己提交**的 |
| 邀约人（发过外链的人） | 自己提交的 + **自己发的外链产生**的外部需求 |
| 业务线负责人 | 本业务线的**全部**需求（包括别人提的） |
| 有点推荐负责人 | 有点推荐产品线的全部需求（含外部提交） |
| 实施负责人 | **全部**需求 |
| 产品经理 | 提交给自己的 + 自己对口业务线的 |
| 管理员 | 全部需求 + 审批链配置 + 外链台账 + 统计 |

⚠️ 看不到某条需求不是系统出错，是**权限范围**如此。需要看请找对应负责人或管理员。

## 三、Web 端操作指南

### 3.1 提交需求

**操作路径**：侧边菜单 **研发 → 需求管理** → 点右上角「**新增需求**」

**表单一共 8 个字段**：

| 字段 | 必填 | 怎么填 / 注意什么 |
| --- | --- | --- |
| **提交对象（产品经理）** | ✅ | **先选产品线与业务线，再选提交对象**（候选名单按业务线过滤，只列本业务线配了专属链的产品经理）。选完后表单下方会实时预览这条需求将走的审批链（级次 + 各级审批人），标「专属链」。**找不到想选的人时，联系管理员先在「审批链配置」里为他配专属链**。⚠️ **提交给谁，谁就是最终审批人**；提交后不可直接改（驳回重提时可换） |
| **需求标题** | ✅ | 一句话说清要什么，不超过 128 字。别写「系统有问题」这种，写「库存查询页希望增加按仓库导出」 |
| **需求描述** | ✅ | **至少 10 字**，最多 2000 字。三件事写清楚：**业务背景 → 当前痛点 → 期望效果**。描述越完整，被驳回的概率越低 |
| **产品线** | ✅ | 鸣鸣很忙 / 有点推荐，默认「鸣鸣很忙」。⚠️ **提交后不能改** |
| **所属业务线** | 条件必填 | 运营 / 财务 / 供应链 / 数字化，默认按你所在部门预填。💡 **产品线选「有点推荐」时这一行会自动消失**，不用填。⚠️ **提交后不能改** |
| **需求类型** | ✅ | 新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成，共 5 类 |
| **优先级** | ✅ | P0 紧急 / P1 高 / P2 中 / P3 低，默认 P2。审批人有权调整，最终以末级审批通过时的值为准 |
| **目标完成日期** | ✅ | 你期望的上线时间，**不能选今天之前的日期** |

**草稿 vs 正式提交**：

| | 暂存草稿 | 提交审批 |
| --- | --- | --- |
| 校验要求 | **只要标题不为空**就能存 | 8 个字段全部校验通过 |
| 谁能看到 | **只有你自己** | 审批人、负责人、管理员按权限可见 |
| 是否进审批 | ❌ 不进 | ✅ 立刻进入审批链第一级待审 |
| 能不能改 | ✅ 随时改、随时删 | 只能撤回或等驳回后改 |

✅ **正确做法**：信息还没收集齐 → 先「暂存草稿」，凑齐了再回来提交。
❌ **错误做法**：为了赶紧提交，描述随便写两句 → 大概率被驳回，反而更慢。

⚠️ **点「提交审批」会弹二次确认**：「提交后将按提交对象的审批链流转，产品线与业务线不可修改」。这不是走过场——**产品线和业务线一旦提交就锁死了**，选错只能等驳回后重新创建一条。

### 3.2 查看需求列表

**操作路径**：侧边菜单 **研发 → 需求管理**

**顶部 4 张 KPI 卡片**（点击可直接筛选，卡片数字跟随你的可见范围）：

| KPI 卡 | 含义 | 点击后 |
| --- | --- | --- |
| 待提交数 | 你自己还没提交的草稿数 | 筛出全部草稿 |
| **待我审批数** | 轮到你审批、正等你处理的条数 | 切到「待我审批」Tab |
| 已通过数 | 已过完审批链的需求（含已关联排期） | 筛出这两种状态 |
| 已驳回数 | 被驳回的需求 | 筛出全部驳回单 |

**四个视角 Tab**（前两个所有人都有，后两个看权限）：

| Tab | 含义 | 谁能看到这个 Tab |
| --- | --- | --- |
| **我提交的** | 你本人提交的全部需求（含草稿） | 所有人 |
| **待我审批** | 正等你审批的需求 | 所有人（无待审时为空） |
| **外部提交** | 通过外链由外部人员提交的需求 | 只有**邀约人 / 有点推荐负责人 / 实施负责人 / 管理员** |
| **全部** | 可见范围内的所有需求 | 只有能看到别人需求的角色 |

**常用筛选条件**：状态、产品线、所属业务线、提交来源、优先级、需求类型、提交人、提交时间区间（默认近 30 天）。

💡 小技巧：
- 产品线选「有点推荐」后，业务线筛选会自动置灰——因为有点推荐不分业务线，这是正常的
- 时间范围默认近 30 天，**找不到老需求时先把时间放宽**
- 草稿没有提交时间，不受时间筛选影响

**表格里最该看的三列**：`当前状态`（卡在哪一步）、`当前审批人`（等谁）、`关联排期卡片`（排上没）。

### 3.3 审批操作（业务线负责人 / 实施负责人 / 产品经理）

**操作路径**：需求列表 → 「待我审批」Tab → 点需求编号进详情 → 页面底部操作栏

#### 通过（任意级次，操作都一样）

详情页看完需求内容 → 点底部「**通过**」→ 弹出确认框「确认通过该需求？通过后将流转至下一审批节点」→ 可顺手填审批意见（选填）→ 点确认 → 提示「已通过，需求流转至 XXX」，页面自动刷新进度条。

💡 审批链在提交时就已按提交对象确定，**审批人不需要再指派任何人**——包括实施负责人，点「通过」即可，产品经理由提交人选定、自动承接末级审批。

#### 驳回（任何级次都可以）

点底部「**驳回**」（红色）→ 弹出意见输入框（⚠️ **必填 10–200 字**）→ 写清楚**为什么驳回 + 希望怎么改**（提交人只能靠这段话来修改）→ 确认后需求状态变为「已驳回」，退回提交人。

✅ 好的驳回意见：「当前描述未说明涉及哪些门店和预计影响单量，请补充范围与业务价值后重提」
❌ 差的驳回意见：「不合理，先不做了」（凑够 10 字也没用，提交人不知道怎么改）

#### 或签模式（很重要）

各级审批**全部是或签**：

- 同一级配了多个审批人时，**任意一个人操作即生效**，不需要所有人都点
- 一个人通过 → 其他人的待办**自动消失**，App 角标同步减一
- 一个人驳回 → 整条需求就驳回了，不等其他人

💡 所以看到「张三、李四（或签）」时，你和同事**谁先看到谁处理**即可，不用互相等。

### 3.4 查看需求详情与审批进度

**操作路径**：列表点需求编号 或 「查看详情」

详情页从上到下四块：

1. **需求信息卡**：编号、标题、状态、描述全文、**提交对象（产品经理）**、产品线/业务线、优先级、类型、目标日期、提交人。被驳回的需求，卡片顶部有**红色提示条**展示驳回人和完整驳回意见。
2. **审批进度条**（纵向）：按提交时命中的审批链渲染 1~3 个节点（专属链级次由配置决定，可以只有产品确认一级、也可以是完整三级）。**蓝色描边 + 「审批中」角标** = 现在卡在这一级；绿色=已通过，红色=已驳回，灰色=还没走到。每个节点显示审批人姓名、审批意见、操作时间；产品确认级的审批人就是提交对象本人。如果提交人正好是这一级的审批人，需由本人在待办里自己点通过；进度条上显示「**已自动跳过**」的节点表示该级已由系统跳过，无需处理。
3. **审批时间线按轮次分组**：被驳回重提过的需求会有多轮记录。默认展开**最新一轮**，历史轮次折叠成「查看第 N 轮审批记录」，点开可对比前后的驳回意见。
4. **排期关联区**：卡片编号、排期日期、开发状态（待开发 / 开发中 / 开发完成）、开发人。

### 3.5 关联排期卡片（产品经理专用）

⚠️ **仅 Web 端可操作，App 端只能看**。操作人限**该需求的提交对象（产品经理）**或**管理员**。

**前提**：需求状态必须是「**待关联排期**」（即审批链各级全部通过）。

**关联步骤**：进需求详情页 → 下方「排期关联区」→ 点「**关联排期**」→ 弹窗里二选一：**方式一**直接输入排期卡片编号精确搜索，系统校验后显示卡片摘要（排期日期 / 开发状态 / 开发人）；**方式二**从「候选排期卡片列表」里挑一张——列表默认按月份筛选，还可叠加**开发人**、**需求提交人**两个人员筛选，已承载其他需求的卡片带「已关联 N 条需求」橙色角标（悬停可看提交人名单），选中这类卡片提交时会再弹一次「确认同挂」提示。确认后提示「已关联排期卡片 XXX」，需求状态变为「**已关联排期**」（终态）。

💡 两个筛选的口径提示：
- **开发人**：只有「开发中 / 开发完成」的卡片有开发人（待开发卡片还没人领取），所以筛开发人时看不到待开发卡片，这是正常的
- **需求提交人**：只会筛出「已被该提交人的需求关联过的卡片」，方便把同一人的同类需求挂到同一张卡片上；外链进来的外部提交人姓名是手填的、不在人员选择器里，不参与筛选

**解除关联步骤**：详情页排期区点「**解除关联**」→ 确认 → 需求状态**退回「待关联排期」**，可重新关联。

💡 关于关联的三条口径：
- 一条需求**只能关联一张**卡片
- 一张卡片**可以被多条**需求关联（同一张卡片承载多条同类需求）
- 需求只是「读取」卡片状态，**不会改动排期卡片**任何内容

⚠️ 如果卡片被删掉了，需求详情页会出现黄色提示「关联卡片已失效，请重新关联」——这时要重新关联一张。

### 3.6 撤回与重新提交

#### 撤回（提交人自己操作）

**只有两种状态能撤回**：`已提交` 和 `业务线审批中`（也就是 **L1 还没做出通过/驳回动作之前**）。

**操作**：需求列表行「撤回」或详情页底部「撤回」→ 二次确认 → 需求**回到草稿状态**，审批链作废。

⚠️ **一旦 L1 通过、进入「实施确认中」，撤回按钮就消失了**。这时想撤只能联系审批人帮你驳回。

#### 重新提交（被驳回后）

详情页 / 列表点「**编辑**」（被驳回和草稿状态才有这个按钮）→ 顶部会显示驳回意见，按意见修改内容 → 点「重新提交」→ 需求**回到「已提交」，按提交对象重新匹配审批链、从链上第一级开始重走审批**。

重提的三个要点：💡 **沿用原编号**，不会生成新需求，历史审批记录全部保留；💡 **提交对象回填原值、可以换**（换人会按新对象重新匹配审批链）；⚠️ **产品线和业务线在编辑页是只读的**，改不了，选错了只能新建一条需求。

### 3.7 外链管理（邀约人专用）

**什么场景用**：你要向**没有系统账号的外部人员**（外部伙伴、兼职人员等）收集需求。给对方发一个临时链接，对方免登录填写提交，需求直接进**默认审批链**（外部人没有提交对象，末级产品确认由默认链配置的产品经理承接）。

⚠️ **外链仅「有点推荐」产品线可用**，鸣鸣很忙不开放。

**操作路径**：侧边菜单 **研发 → 需求管理 → 外链管理**

#### 生成外链

点「**生成外链**」按钮，填写弹窗：

| 字段 | 怎么填 |
| --- | --- |
| 产品线 | 固定「有点推荐」，不可改 |
| **邀约对象备注** | 必填 2–128 字，建议写「公司 + 联系人」。**仅内部可见**，用来在台账里认人 |
| 需求类型默认值 | 5 类里选一个，对方进页面后还能改 |
| 有效期 | 7 / 15 / 30 / 60 / 90 天，默认 30 天 |
| 提交次数上限 | 1–10，**默认 1 次**（一次性定向） |

生成成功后**弹窗不会自动关闭**，就地显示完整链接 + 二维码 + 复制按钮——⚠️ **先复制或保存二维码，再关闭弹窗**。

#### 分享给对方

- **复制链接**：台账行点「复制链接」→ 粘贴到企微/微信发给对方
- **二维码**：台账行点「二维码」→ 弹窗展示二维码 + 邀约对象 + 有效期，可「下载图片」

💡 关闭生成弹窗后链接不会丢，随时可以从台账行重新复制，**链接本身不会变**。

#### 撤销外链

台账行点「**撤销**」→ 填撤销原因（必填 10–256 字）→ 确认。只有「**待使用**」状态的链接能撤销；撤销后对方打开链接看到「已失效」提示且**无法恢复**；**已经提交产生的需求不受影响**，不会跟着作废。

#### 查看外链台账

台账表格能回答「发给了谁、对方看了没、提交了什么」：

| 列 | 看什么 |
| --- | --- |
| 邀约对象 | 你填的备注 |
| 链接状态 | 待使用 / 已提交 / 已过期 / 已撤销 |
| 提交进度 | 如 `1/1`，达上限时数字变绿 |
| 访问情况 | 访问次数 + 首次访问时间；没打开过显示「未访问」 |
| 产生需求 | 需求编号（可点击进详情）+ 当前状态 |
| 有效期至 | 剩 3 天内会有橙色「即将过期」角标 |

⚠️ 台账**只能撤销不能删除**，它是溯源证据。

⚠️ 外部提交是**单向的**：系统不会给外部人发任何短信或通知，也不给他查进度的入口。审批结果只通知**你（邀约人）**，**要不要告诉对方由你线下决定**。

### 3.8 审批链配置（管理员专用）

**操作路径**：侧边菜单 **研发 → 需求管理 → 审批链配置**（只有管理员能看到这个菜单）

**配置范式**：**先选提交对象（产品经理），再为他配置审批流程**；另有一条「默认链」仅承接外部提交与防御兜底（内部提交只能选配了专属链的产品经理，不会落到默认链）。

- 页面顶部一级 Tab 选产品线，二级 Tab 选业务线（有点推荐没有二级 Tab）
- 区块二先选「**默认链（兜底）**」或「**指定产品经理**」，再维护该对象下的配置行
- **专属链**（给某个产品经理配）：级次可勾选 L1 业务线审批 / L2 实施确认 / L3 产品确认的**任意组合**（至少一级，如「仅 L3」「L2+L3」），每级可配多人（多人即或签）；未勾选的级次流转时直接跳过
- **默认链**：鸣鸣很忙各业务线保留 **L1/L2 两级**作防御兜底（正常情况下内部提交不会经过）；有点推荐须配齐 **L1/L2/L3 三级**（L3 承接外部提交单，外部提交唯一通道）
- 审批模式固定「或签」，**只读不可切换**
- 🚨 **配置后必须同步流程中心镜像**：本页任何链的新增/修改/停用，需同步维护流程中心「需求审批流程」模板的对应链并重新发布（联系流程中心管理员操作），否则两侧审批人不一致

**匹配规则**：提交需求时**按提交对象匹配专属链**（内部提交必中）；同一链内按「需求类型 × 优先级」细化匹配（需求类型和优先级支持填 `*` 表示全部，产品线和业务线必须精确匹配）：

```
内部提交：提交对象专属链（类型精确+优先级精确 → 类型精确+* → *+优先级精确 → *+*）
外部提交：默认链（同一套降级顺序，命中即止）
```

💡 实操建议：按产品经理的实际分工逐个配专属链（比如某位 PM 的需求不需要业务线预审，就只勾 L3）；**每条业务线至少要有一名 PM 配专属链**，否则该业务线的内部提交将无人可选。

**几个关键提醒**：

- ⚠️ 某个归属**没有启用中的专属链** → 红点 + 红色告警，**该归属的内部提交将无可选提交对象**；有点推荐**默认链缺级** → **外链无法生成、已发出的链接提交失败**
- 配置修改**只对新提交的需求生效**，在途需求走的是提交时的「快照」，不会中途换人
- **审批人离职/调岗**时：更新配置后，还要对在途需求点「**重建在途需求审批链**」（只替换审批人，级次保持不变）
- 群消息要单独在「群消息配置」区块绑定企微群机器人；没绑定不影响审批，只是群消息静默跳过

**审批统计与导出**：配置页底部「审批统计」区块，按当前 Tab + 时间区间统计：**受理量**（已提交条数，不含草稿）/ **内部与外部构成**（仅有点推荐 Tab）/ **通过率** / **驳回率**（可按 L1/L2/L3 下钻）/ **平均审批时长**。

点右上角「导出统计」→ 提示「导出任务已提交」→ 到**下载中心**取文件。需求列表本身也支持导出（管理员权限）。

## 四、App 端操作指南

**入口**：App 工作台 → 点「**需求管理**」入口卡片

### 4.1 提交需求

**操作路径**：需求列表页 → 右上角「**提交**」

- 字段与 Web 端**完全一致**（**先选提交对象（产品经理）**，再填标题 / 描述 / 产品线 / 业务线 / 类型 / 优先级 / 目标日期）；选定提交对象后下方会灰字预览将走的审批链
- 产品线选「有点推荐」时，业务线那一行同样自动隐藏
- ⚠️ **App 端没有「暂存草稿」按钮**，写完就是直接提交进审批
- 提交前弹确认「提交后将按提交对象的审批链流转，产品线与业务线不可修改」

💡 建议：内容简单的需求用 App 提交；需要斟酌措辞、附大段背景的，回 Web 端慢慢写草稿。

### 4.2 查看我的需求

App 列表**只有 3 个 Tab**（比 Web 少一个「外部提交」）：

| Tab | 含义 |
| --- | --- |
| **我提交的** | 你本人提交的全部需求（Web 端存的草稿也能在这里**看到**，但改不了） |
| **待我审批** | 等你审批的需求。⚠️ Tab 右上角有**数字角标**（超过 99 显示 `99+`） |
| **已完成** | 已关联排期 + 已驳回的终态需求 |

**卡片信息**（自上而下）：① 需求标题（最多 2 行）② 产品线 + 业务线 + 优先级 + 状态 四个彩色标签 ③ 需求编号 + 提交时间（草稿显示「未提交」）。「待我审批」Tab 的卡片额外显示**提交人 + 等待时长**（如「已等待 2 天」）。

交互：**下拉刷新**、上滑加载更多（每页 20 条）。点整张卡片进详情。

### 4.3 审批操作

**操作路径**：「待我审批」Tab → 点卡片进详情 → 底部操作栏（绿色「通过」/ 红色「驳回」）

| 场景 | 怎么操作 |
| --- | --- |
| **通过**（任意级次） | 点「通过」→ 底部弹确认条「确认通过该需求？」→ 可填意见 → 点确认，**一步搞定**（审批链提交时已定，无需再指派任何人） |
| **驳回** | 点「驳回」→ 弹出半屏输入框 → ⚠️ 必填 10–200 字意见（不够 10 字按钮是灰的）→ 「确认驳回」 |

💡 审批成功后返回列表，「待我审批」角标会自动刷新。
⚠️ 如果提示「审批处理中，请勿重复点击」，**不要反复点**——后台已在处理，稍后回列表看结果即可。或签场景下同事先处理了，你的待办会自动消失并提示「你不是当前节点审批人」，这是正常的。

### 4.4 App 端不支持的操作

以下 5 类操作 App 端**没有入口**，必须到 Web 端做：

| 不支持的操作 | 到哪做 |
| --- | --- |
| ❌ **草稿保存与草稿编辑** | Web 端「新增需求」页的「暂存草稿」 |
| ❌ **排期卡片关联 / 解除关联** | Web 端需求详情页排期关联区（App 只能只读查看） |
| ❌ **外链生成与台账管理** | Web 端「研发 → 需求管理 → 外链管理」 |
| ❌ **审批链配置** | Web 端「研发 → 需求管理 → 审批链配置」 |
| ❌ **列表导出 / 统计导出** | Web 端列表页「导出」、配置页「导出统计」 |

App 端也没有「外部提交」Tab、没有产品线和提交来源筛选器——外部提交的需求只会出现在你的「待我审批」里。

## 五、需求状态说明

### 5.1 状态流转图

```
【正常路径】（以完整三级专属链为例；专属链缺级时对应状态直接跳过）
草稿 DRAFT ──提交审批（选定提交对象）──▶ 已提交 SUBMITTED ──系统匹配专属链（经流程中心流转）──▶
业务线审批中 BU_REVIEWING (L1) ──L1 通过──▶
实施确认中 IMPL_REVIEWING (L2) ──L2 通过──▶
产品确认中 PM_REVIEWING (L3) ──L3 通过──▶
待关联排期 PM_SUBMITTED ──产品经理（提交对象）关联卡片──▶ 已关联排期 LINKED（终态）

【驳回路径】任意一级审批中 ──驳回──▶ 已驳回 REJECTED
   ├─ 内部需求：改完可重新提交 → 回到「已提交」，重走审批链（可换提交对象）
   └─ 外部需求：终态，不可重提

【撤回路径】已提交 / 业务线审批中 ──撤回──▶ 回到「草稿」
```

### 5.2 状态一览表

| 状态（中文 / 英文） | 什么时候进入 | 下一步变成什么 | 谁来操作 |
| --- | --- | --- | --- |
| **草稿** `DRAFT` | 填了表单点「暂存草稿」，或从「已提交/业务线审批中」撤回 | 提交 → 已提交；删除 → 记录消失 | 提交人（仅本人可见） |
| **已提交** `SUBMITTED` | 点「提交审批」成功，系统正在匹配审批链 | → 审批链第一级审批中 | 系统自动 |
| **业务线审批中** `BU_REVIEWING` | 审批链匹配完成且链上含 L1，进入 L1 | 通过 → 链上下一级；驳回 → 已驳回；撤回 → 草稿 | 业务线负责人（L1） |
| **实施确认中** `IMPL_REVIEWING` | 链上含 L2，上一级通过后自动流转 | 通过 → 链上下一级；驳回 → 已驳回 | 实施负责人（L2）|
| **产品确认中** `PM_REVIEWING` | 链上含 L3，上一级通过后自动流转 | 通过 → 待关联排期；驳回 → 已驳回 | 提交对象（产品经理，L3） |
| **待关联排期** `PM_SUBMITTED` | 审批链各级全部通过 | 关联卡片 → 已关联排期 | 产品经理（提交对象）/ 管理员（仅 Web） |
| **已关联排期** `LINKED` | 关联了排期卡片 | **终态**，只看不改；解除关联可退回「待关联排期」 | 产品经理 / 管理员 |
| **已驳回** `REJECTED` | 任意一级驳回 | 内部单：重提 → 已提交；外部单：**终态** | 提交人（重提） |

💡 你可能听研发提到 `BU_APPROVED`、`IMPL_CONFIRMED` 这两个状态——它们是系统内部**一瞬间就过去的中转态**，页面上看不到，也不用管。所以你在筛选下拉里只会看到上表这 8 个状态。

## 六、通知规则

所有通知走**企微**，分两个通道：**个人消息**（提醒你处理或告知你结果）和**业务线群消息**（让归属内其他人知情）。

| 什么操作 | 推给谁（个人） | 推群吗 |
| --- | --- | --- |
| **提交需求** | 审批链第一级审批人（待办提醒） | ✅ 推所属业务线群 |
| **L1 通过** | L2 实施负责人（待办提醒） | ✅ 推所属业务线群 |
| **L2 通过** | 提交对象（产品经理，L3 待办提醒） | ❌ **不推群**（内部流转节点） |
| **L3 通过** | 提交人（结果通知） | ✅ 推所属业务线群 |
| **驳回** | 提交人（外部需求改推**邀约人**） | ✅ 推所属业务线群 |
| **关联排期** | — | ✅ 推群，带卡片编号与预计开发日期 |

几个要点：

- 消息里带**详情页跳转链接**，点开就能审批（会先鉴权）；群消息里的驳回原因只截取**前 50 字**，完整意见到详情页看
- ⚠️ **外部提交人收不到任何通知**（他没有企微身份），外部需求的所有结果只通知邀约人
- 如果某个业务线的企微群还没配置，群消息会静默跳过，**但不影响审批流转**——需求照样往下走

## 七、常见问题 FAQ

**Q1：提交后发现产品线（或业务线）选错了怎么办？**
A：改不了。有两种处理方式：① 还在「已提交」或「业务线审批中」→ 自己**撤回**，回草稿改；② 已经进了「实施确认中」→ 联系审批人**驳回**，但驳回后编辑页的产品线/业务线仍是只读的，只能**新建一条正确的需求**，然后在描述里说明作废原单。

**Q2：审批人离职了，需求卡住了怎么办？**
A：找管理员。管理员先在「审批链配置」里更新审批人，然后对在途需求执行「**重建在途需求审批链**」——级次保持不变，换成新审批人接着审。你自己在需求页面上无法跳过审批人。

**Q3：外部提交的需求被驳回了怎么办？**
A：外部需求驳回即**终态，不能重提**。如果内部觉得这个需求还有价值，由**实施负责人新建一条内部需求**，在描述里引用原需求编号做溯源。系统不提供「转内部单」按钮。

**Q4：为什么我看不到「外部提交」这个 Tab？**
A：这个 Tab 只对**邀约人**（发过外链的人）、**有点推荐负责人**、**实施负责人**、**管理员**显示。普通员工没有这个视角，是正常的。

**Q5：App 端怎么保存草稿？**
A：**App 端没有草稿功能**。要存草稿请用 Web 端。App 端「我提交的」Tab 里能看到 Web 端存的草稿，但点进去也不能编辑。

**Q6：需求被驳回后还能修改吗？**
A：内部需求可以。详情页或列表点「编辑」，按驳回意见改完点「重新提交」，会**沿用原编号**按提交对象重新匹配审批链、从链上第一级重走审批，历史审批记录都保留着（按轮次折叠展示）。💡 提交对象回填原值、可以换；⚠️ 产品线和业务线改不了。

**Q7：一个需求可以关联多张排期卡片吗？**
A：不行，**一条需求只能关联一张卡片**。反过来可以：一张卡片能被多条需求关联（多条同类需求合并到一张卡片开发）。

**Q8：外链发出去了还能撤回吗？**
A：能，前提是对方**还没提交**（链接状态是「待使用」）。到外链管理台账点「撤销」并填原因即可。如果对方已经提交了，链接状态变成「已提交」，就不能撤销了——已产生的需求也不会作废。

**Q9：为什么提交时提示「当前归属未配置审批链」？**
A：提交对象只能选「本业务线配了专属链的产品经理」，正常选人不会出现此提示；仅当该 PM 的专属链在你选人之后被管理员停用/删除时才会命中。**联系管理员**去「审批链配置」恢复或重配这条专属链即可。

**Q10：或签模式下多个审批人都需要操作吗？**
A：不需要。同一级配多人时，**任意一人处理即生效**：一人通过就往下走，其他人待办自动消失；一人驳回整条就驳回了。谁先看到谁处理。

**Q11：撤回按钮不见了，为什么？**
A：撤回只在「**已提交**」和「**业务线审批中**」两个状态开放。一旦 L1 通过、进入「实施确认中」，按钮就隐藏了。这时只能请审批人驳回。

**Q12：草稿里的需求，别人能看到吗？**
A：不能。草稿**仅你本人可见**，也不会推任何通知。只有点了「提交审批」才会进入审批人视野。

**Q13：我的需求为什么一直显示「待关联排期」？**
A：说明审批链已全部通过，正等**产品经理（提交对象）关联排期卡片**。详情页信息卡上能看到提交对象是谁，直接找他跟进。关联后状态会变「已关联排期」，并能看到开发进度。

**Q14：详情页排期区提示「关联卡片已失效」是什么意思？**
A：原先关联的排期卡片被删掉了。需要产品经理或管理员到 Web 端**重新关联**一张卡片。

**Q15：外部人员提交需求需要收验证码短信吗？**
A：不需要。外部页面用的是**图形验证码**，手机号只做格式校验、仅供内部必要时联系，系统**不会给外部人发任何短信**。

**Q16：对方说链接打开显示「已失效」，怎么排查？**
A：四种可能：① 已经提交过了（默认只能提交 1 次）；② 超过有效期；③ 被撤销了；④ 链接复制时被截断。到台账查这条链接的状态即可确认，需要的话重新生成一条发过去。另外提醒：外部人**查不到自己需求的进度**，只在提交成功页看到一个需求编号作为凭证，结果要靠邀约人线下转达。

## 九、注意事项（千万别）

1. ⚠️ **千万别在 App 端找草稿功能** —— App 不支持暂存草稿，也不能编辑草稿。写到一半退出去就没了，要存草稿请上 Web。

2. ⚠️ **千万别在提交时随便选产品线和业务线** —— 这两个字段**提交后永久锁死**，连驳回重提时都是只读的。选错就只能作废重建。

3. ⚠️ **千万别指望进了「实施确认中」还能撤回** —— 撤回窗口只有「已提交」和「业务线审批中」两个状态，过了就只能求审批人驳回。

4. ⚠️ **千万别不选提交对象就提交** —— 提交对象（产品经理）是表单第一个必填项，**提交给谁就由谁终审**；选错了只能等驳回后重提时再换。

5. ⚠️ **千万别用一句话敷衍驳回意见** —— 意见是提交人唯一的修改依据。凑够 10 字但没说清怎么改，只会来回踢皮球。

6. ⚠️ **千万别把外链当通用链接群发或公开张贴** —— 外链是**一次性定向**发放，默认只能提交 1 次；而且**只有有点推荐**产品线可用，鸣鸣很忙不开放。

7. ⚠️ **千万别以为外部人能收到审批结果** —— 外部提交完全单向，系统不给外部人发任何通知。结果只推给**邀约人**，要不要转达由邀约人决定。

8. ⚠️ **千万别忽略配置红色告警** —— 两类红点要立刻处理：① 某归属**没有启用中的专属链** → 该业务线内部提交将无人可选，需立刻给对口产品经理配链；② 有点推荐**默认链缺级** → **外链无法生成、已发出的链接提交失败**。另外本页配置改动后**必须同步流程中心镜像**（联系流程中心管理员），否则两侧审批人不一致。

9. ⚠️ **千万别反复点审批按钮** —— 提示「审批处理中」时后台正在处理，连点可能导致重复通知；也别去台账找删除按钮，外链记录**只能撤销不能删除**，它是溯源证据。
