> 页面元素与交互声明以本文件为准，原型见 `assets/web/`。组件白名单、Token 纪律、卡片化拓扑、三态等硬约束见 [page-gen.prompt.md](../../../../busyming-skills-design/.skills/page-blueprint/prompts/page-gen.prompt.md)【2. 硬约束】，交互三维度按 [interaction-spec.md](../../../../busyming-skills-common/workflow/PM/references/interaction-spec.md) 填写。业务规则只引用、不复述，规则文件入口见 [SKILL.md](../SKILL.md) Prerequisites；公开 H5 三页见 [app-ui.md 公开 H5](app-ui.md#公开-h5)。

## 全局约定

### 状态与标签

视觉色值以设计系统的状态语义与 Tag 色板为准，本文件只声明语义，不定义私有颜色。

| 状态 | 标签文案 | 状态语义 |
|------|---------|---------|
| `DRAFT` | 草稿 | default |
| `SUBMITTED` | 已提交 | processing |
| `BU_REVIEWING` | 业务线审批中 | processing |
| `IMPL_REVIEWING` | 实施确认中 | processing |
| `PM_REVIEWING` | 产品确认中 | processing |
| `PM_SUBMITTED` | 待关联排期（缺陷修复单为「待转黑灯工厂」） | warning |
| `LINKED` | 已关联排期（缺陷修复单为「已转黑灯工厂」） | success |
| `REJECTED` | 已驳回 | danger |

- 瞬时态不展示为独立状态与独立节点，筛选下拉与状态标签均不出现，见 [state-machine.md §3](state-machine.md#3-级次递进)
- 优先级 Tag：`P0 紧急` 红 / `P1 高` 橙 / `P2 中` 蓝 / `P3 低` 灰
- 业务线 Tag：运营 蓝 / 财务 紫 / 供应链 青 / 数字化 金，全模块复用同一映射
- 产品线 Tag：鸣鸣很忙 品牌红 / 有点推荐 洋红；有点推荐行的业务线位置展示 `—`
- 提交来源：内部不展示标签；外部展示橙红「外部提交」Tag，全模块统一
- 外链状态：待使用 processing / 已提交 success / 已过期 default / 已撤销 danger
- 排期开发状态：待开发 default / 开发中 processing / 开发完成 success
- 枚举取值以 [data.md §12](data.md#12-枚举) 为准；有点推荐的业务线占位值不进入任何下拉选项与展示

### 附件展示

| 类型 | 图标 | 扩展名 |
|------|------|-------|
| 图片 | 图片图标 | jpg / jpeg / png / webp / gif |
| 文档 | 文档图标 | pdf / docx / xlsx / pptx / txt |
| 视频 | 视频图标 | mp4 / mov |

- 上传限制、追加与删除规则见 [other-rule-attachment.md](other-rule-attachment.md)；页面限制只作体验前置，以服务端校验结果为准
- Web 是唯一开放文档与视频上传的端；附件对有权查看该需求的用户一律可见，不展示审核状态
- 审批中追加的附件额外渲染「审批中追加」标签

### SLA 滞留程度

滞留时长相对命中阈值的展示口径，滞留需求视角与 SLA 仪表盘复用：

| 滞留程度 | 判定 | 状态语义 |
|---------|------|---------|
| 正常 | 滞留时长 < 催办阈值 | default |
| 已催办 | 催办阈值 ≤ 滞留时长 < 升级阈值 | warning |
| 已升级 | 滞留时长 ≥ 升级阈值 | danger |

- 阈值按产品线 × 优先级 × 审批级次逐行取（[other-rule-sla.md §3](other-rule-sla.md#3-差异化配置)），**前端不写死 48 / 72 小时**，一律以服务端返回的命中阈值为准
- 滞留时长展示为「N 小时」，≥ 48h 时换算为「N 天 M 小时」

### 通用约定

- 列表与详情的可见范围由服务端按角色裁剪，见 [permission-rules.md §3](permission-rules.md#3-数据可见范围)，前端不做兜底过滤
- 页面不触发任何推送：企微个人消息与群消息由服务端在操作成功后异步发出，页面只用 AcMessage 反馈业务结果
- 按钮显隐以服务端返回的可执行操作为准，前端不自行推导角色
- 外部提交人姓名、部门为手填自由文本，不关联组织架构，页面不提供人员或部门详情链接

## 页面清单

### 需求列表页

- **菜单名称**：需求工单管理（侧边菜单与页面标题取此名）
- **页面路径**：`/snackingdom/portal/requirement/list`；视角、筛选与页码同步至页面地址
- **权限编码**：
  - 路由：`MENU:RND:REQUIREMENT`
  - 按钮：`BTN:REQUIREMENT:CREATE`（新增需求）、`BTN:REQUIREMENT:WITHDRAW`（撤回）、`BTN:REQUIREMENT:DELETE`（删除草稿）、`BTN:REQUIREMENT:EXPORT`（导出），控制范围见 [permission-rules.md §1](permission-rules.md#1-权限编码)
- **页面类型**：`order-list`
- **页面定位**：一屏回答「需求谁提的、卡在哪级、有没有排上开发」
- **区块职责**：
  - KPI 统计卡（4 张横排，点击下钻）：待提交数（本人草稿数，点击筛选草稿）/ 待我审批数（当前登录人处于快照当前级次的待审数，点击切至「待我审批」视角）/ 已通过数（待关联排期 + 已关联排期，点击筛选该两状态）/ 已驳回数（点击筛选已驳回）；取数跟随当前角色可见范围，与表格筛选同源
  - 视角 Tab：我提交的 / 待我审批 / 外部提交 / 滞留需求 / 全部
    - 「外部提交」仅对邀约人、有点推荐负责人、实施负责人、管理员展示，取数口径见 [permission-rules.md §3](permission-rules.md#3-数据可见范围)
    - 「滞留需求」对全部能看到需求列表的角色展示，筛选口径与排序见 [other-rule-sla.md §5](other-rule-sla.md#5-滞留需求看板)，可见范围与其他视角一致
    - 「全部」仅对可见范围含他人需求的角色展示
  - 筛选区：
    - 状态：下拉多选（草稿 / 已提交 / 业务线审批中 / 实施确认中 / 产品确认中 / 待关联排期 / 已关联排期 / 已驳回）
    - 产品线：下拉单选（鸣鸣很忙 / 有点推荐），置于业务线之前
    - 所属业务线：下拉单选（运营 / 财务 / 供应链 / 数字化）；产品线选「有点推荐」时置灰并清空
    - 提交来源：下拉单选（内部提交 / 外部提交），仅对可见外部单的角色展示；「外部提交」视角下锁定为外部提交并置灰
    - 优先级：下拉多选（P0 紧急 / P1 高 / P2 中 / P3 低）
    - 需求类型：下拉单选（新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成）
    - 提交人：输入框模糊搜索，同时匹配内部提交人姓名与外部提交人手填姓名；仅可见范围含他人需求的角色展示
    - 提交时间：日期范围选择器，默认近 30 天；从未提交的草稿不受该条件过滤
    - 操作：查询 / 重置
  - 操作区：新增需求（主按钮）/ 导出
  - 主体区：数据表格，列定义如下

| 列名 | 取值说明 |
|------|---------|
| 需求编号 | `REQ-{YYYYMMDD}-{NNN}`，链接样式，点击进详情；外部单编号后跟「外部提交」Tag；从未提交的草稿展示 `—` |
| 标题 | 超长省略 + 气泡提示全文 |
| 产品线 | 产品线 Tag |
| 所属业务线 | 业务线 Tag；有点推荐行展示 `—` |
| 提交人 | 内部单展示提交人姓名；外部单展示外部提交人手填姓名，副行展示手填部门（超长省略 + 气泡提示） |
| 当前状态 | 状态标签 |
| 当前审批人 | 快照当前级次审批人；或签多人展示「张三 等 N 人」+ 气泡提示全名单；草稿与终态展示 `—` |
| 优先级 | 优先级 Tag |
| 关联排期 / 工单 | 功能类：关联卡片编号链接（新标签页打开功能排期），未关联展示 `—`，卡片已失效时编号后加「已失效」角标；缺陷修复单：黑灯工厂工单号，未建单展示 `—` |
| 附件 | 附件数量 + 附件图标，点击进详情并展开附件面板；无附件展示 `—`；「滞留需求」视角不展示本列 |
| 停留时长 | 🚨 仅「滞留需求」视角：当前级次停留时长 + 滞留程度标签；默认排序列（倒序） |
| 滞留级次 | 🚨 仅「滞留需求」视角：级次名称（业务线审批 / 实施确认 / 产品确认）+ 当前审批人 |
| 催办情况 | 🚨 仅「滞留需求」视角：已催办次数 + 最近催办时间；已升级时追加「已升级」标签 |
| 操作 | 查看详情 / 编辑 / 撤回 / 删除；「滞留需求」视角另有「手动催办」 |

- **操作列可见性**：
  - 查看详情：全部行可见
  - 编辑：提交人本人 + 草稿或已驳回，点击进需求提交页编辑态
  - 撤回：提交人本人 + 已提交或业务线审批中；进入实施确认中及之后隐藏
  - 删除：提交人本人 + 草稿；已提交需求不提供删除入口
  - 手动催办：「滞留需求」视角 + 当前用户为管理员或实施负责人
  - **外部单只渲染「查看详情」与「手动催办」**：编辑、撤回、删除全部不渲染（无提交人主体，内部人也不得代操作）
  - 单行按钮超过 3 个时第 4 个起收入「更多」
- **分页**：默认 20 条/页，可选 20 / 50 / 100，展示总条数
- **布局引用**：`参见原型 assets/web/requirement-list.html`（整页范例 `busyming-skills-design/web/templates/order-list.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/web/list-page.vue.tpl`）

#### 导航关系

- 来源页：侧边菜单「研发 / 需求管理 / 需求工单管理」；需求提交页暂存或提交成功后跳回；SLA 仪表盘点击「超时率」跳入「滞留需求」视角；企微个人消息与群消息中的详情链接先鉴权再定向至需求详情页
- 去向页：需求详情页（点编号或「查看详情」）、需求提交页（点「新增需求」，或点「编辑」进入编辑态）、功能排期卡片（点卡片编号，新标签页）
- 返回行为：模块入口页，无上级返回；从详情页、提交页经面包屑「需求工单管理」或浏览器后退返回时恢复原视角、筛选与页码
- 面包屑：首页 / 研发 / 需求管理 / 需求工单管理

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 查询 | 无（可空条件） | 否 | 表格区加载指示 | 表格刷新，信息条展示「共 N 条」→ 停留 | AcMessage.error「需求列表加载失败，请重试」+ 表格错误态「点击重试」 |
| 重置 | 无 | 否 | 表格区加载指示 | 恢复默认筛选（近 30 天）并重新查询 → 停留 | 同查询 |
| 视角切换 | 点击 Tab | 否 | 表格骨架屏 | 表格按视角刷新，页码重置为 1 → 停留 | AcMessage.error「加载失败，请重试」+ 保留原视角 |
| KPI 下钻 | 点击任一 KPI 卡 | 否 | 表格区加载指示 | 筛选条件回填并刷新，被选卡片高亮 → 停留 | AcMessage.error「加载失败，请重试」+ 筛选恢复原值 |
| 撤回 | 提交人本人 + 已提交 / 业务线审批中 | AcPopconfirm「撤回后需求回到草稿、审批链作废，确认撤回？」 | 按钮 loading + disabled | AcMessage.success「需求 {编号} 已撤回至草稿」→ 停留并刷新当前页 | AcMessage.error（服务端返回「需求已进入实施确认，不可撤回」时同步刷新行状态）+ 按钮恢复 |
| 删除草稿 | 提交人本人 + 草稿 | AcPopconfirm「删除后该草稿不可恢复，确认删除？」 | 按钮 loading + disabled | AcMessage.success「草稿已删除」→ 停留并刷新当前页，待提交数同步减一 | AcMessage.error（服务端返回「需求已提交，不允许删除」时同步刷新行状态）+ 按钮恢复 |
| 导出 | 具导出权限且当前筛选有结果 | 否 | 按钮 loading | AcMessage.success「导出任务已提交，请在下载中心查看」→ 停留 | AcMessage.error「导出失败，请重试」+ 按钮恢复 |
| 手动催办 | 「滞留需求」视角 + 当前用户为管理员或实施负责人 | AcPopconfirm「将向当前审批人发送企微催办消息，确认催办？」 | 按钮 loading + disabled | AcMessage.success「已向 {审批人} 发送催办」→ 停留并刷新该行催办情况 | AcMessage.error（窗口内已催办时原样展示「该需求本轮已催办过，下次可催办时间 {时间}」）+ 按钮恢复 |

#### 表格三态

- **空态**：当前筛选无数据 → 空状态插图 +「暂无符合条件的需求」+「新增需求」引导按钮（有权限时）；「滞留需求」视角改为「很好，当前没有超时未处理的需求」，不渲染引导按钮
- **加载态**：表格骨架屏（10 行占位）
- **错误态**：表格区错误插图 +「点击重试」

- **页面类型**：`order-detail`
- **区块职责**（自上而下）：
  - 需求信息卡：
    - 主标题行：需求编号 + 标题 + 当前状态标签
    - 信息栅格：描述（保留换行，超长折叠「展开全部」）/ 提交对象（产品经理姓名；外部单 L3 通过前展示灰字「待产品确认通过后归集」）/ 产品线 / 业务线（有点推荐展示 `—`）/ 优先级 / 需求类型 / 目标完成日期 / 提交人 / 提交时间
    - 右上角「编辑」：提交人本人 + 草稿或已驳回时可见；外部单永不渲染
    - 已驳回时卡片顶部红色警示条展示最近一次驳回人与驳回意见全文；外部单追加一行「外部提交单驳回后为终态，不支持重提；如仍有价值请新建内部单并引用本编号溯源」
  - 外部提交区块（仅外部单渲染，置于需求信息卡下方）：
    - 标题「外部提交信息」+「外部提交」Tag
    - 信息栅格：提交人姓名 / 所属部门（后跟灰字「手填，未关联组织架构」）/ 手机号 / 提交时间 / 来源 IP
    - 邀约溯源行：邀约人姓名 + 邀约对象备注 +「来源外链」链接（跳外链管理页并高亮该行）
    - 手机号仅内部可见、仅供内部联系，系统不向外部提交人发送任何短信或通知（[other-rule-public-link.md §5](other-rule-public-link.md#5-单向收口)）；区块内不提供向外部回复、转内部单、代撤回按钮
  - 附件区块（折叠面板，置于外部提交区块之下）：
    - 面板标题「附件（N）」；N > 0 时默认展开，N = 0 时保持折叠并显示灰字「无附件」，不隐藏面板
    - 文件行：类型图标 + 文件名（超长中间省略、保留扩展名，气泡提示全名）+ 文件大小 + 上传人 + 上传时间 + 右侧「预览」「下载」
    - 按类型分组：图片 → 文档 → 视频，组内按上传时间正序；图片组可切换缩略图网格
    - 在线预览分类型：图片 → 图片查看层（左右切图、缩放、Esc 关闭）；PDF → 弹层内嵌预览；视频 → 弹层内播放（不自动播放）；docx / xlsx / pptx / txt 不提供在线预览，只渲染「下载」
    - 右上角「追加附件」：提交人本人 + 已提交 / 业务线审批中 / 实施确认中 / 产品确认中时渲染，旁侧气泡提示「追加后将通知当前审批人，不会重置审批计时」
    - 🚨 详情页不提供删除附件入口（删除仅草稿态，且只在编辑页操作）
    - 外部单附件（H5 上传的图片）同样展示于本区块，上传人列展示外部提交人手填姓名 + 灰字「外部上传」
  - AI 方案确认面板（置于附件区块之下、审批时间线之上）：
    - 🚨 仅当前级次审批人与管理员渲染，提交人与其他角色一律不渲染；可见性由服务端判定（[other-rule-ai-plan.md §1](other-rule-ai-plan.md#1-定位与红线)）；无方案记录时不渲染
    - 面板标题「AI 方案确认」+ 状态标签（生成中 processing / 待确认 warning / 已确认 success / 已作废 default / 生成失败 danger）+ 版本号「V{N}」+ 触发方式标签（自动 / 手动）
    - 生成中：面板内加载指示 + 文案「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批，AI 结果将自动作废」；页面每 5 秒刷新生成状态，离开页面即停止
    - 待确认：主区域渲染三段式确认摘要（① 业务诉求是什么 ② 本次方案完成了什么 ③ 信息缺口与建议业务补充的内容）；下方折叠「方案全文（七步分析）」；信息缺口以清单列出
    - 生成失败：红色警示条「AI 方案生成失败：{失败原因}」+「重新生成」+ 灰字「不影响您人工审批」
    - 已作废：面板置灰只读，顶部提示「该方案已作废（需求已被处理），仅供回顾参考」，不渲染操作按钮
    - 底部操作（仅待确认且当前用户为当前级次审批人时可点）：「确认并通过」（主按钮）/「请求补充材料」（次按钮，已发出过时旁侧灰字「已于 {时间} 发出」）/「重新生成方案」（文字按钮）
  - 审批进度时间线：
    - 纵向步骤条按审批链快照渲染 1~3 个节点，级次集合由提交时命中的链决定（默认链为业务线审批 → 实施确认 → 产品确认，专属链可缺级）
    - 每节点：级次名称 / 角色名 / 审批人（或签未动作时展示全部候选人「张三、李四（或签）」，已动作展示实际动作人）/ 节点状态（待审 / 已通过 / 已驳回 / 已自动跳过）/ 审批意见 / 操作时间
    - 当前待审节点高亮并带「审批中」角标；自动跳过节点展示「已自动跳过」+ 流水说明
    - 驳回重提按审批轮次分组：默认展开最新一轮，历史轮次折叠为「查看第 N 轮审批记录」
    - 内部单产品确认节点的审批人即提交对象
  - 排期关联区：
    - 未关联：占位「未关联排期卡片」+「关联排期」按钮（待关联排期 + 当前用户为该需求的产品经理或管理员时可见，其余角色与状态仅见灰色提示）
    - 已关联：卡片编号（新标签页打开功能排期）/ 排期日期 / 开发状态标签 / 开发人 +「解除关联」（权限同关联）+ 区内「刷新」图标
    - 已关联时追加「Qoder 开发会话」入口（仅产品经理、管理员与卡片开发人可见，[business-rule.md §5.2](business-rule.md#52-qoder-开发会话)）；重新关联后保留旧会话链接备查
    - 卡片已被删除：黄色警示条「关联卡片已失效，请重新关联」+「重新关联」
    - 开发状态实时读取功能排期，本模块只读不回写
    - **缺陷修复单整区替换为「黑灯工厂工单区」**（[business-rule.md §2](business-rule.md#2-缺陷修复需求分流)）：不渲染关联与解除按钮；待关联排期起展示「已转黑灯工厂自动化修复」+ 工单号（链接跳黑灯工厂工单）+ 工单级别 / 状态 / 负责人只读回传；建单失败展示红色警示条「转黑灯工厂建单失败，系统将自动重试」
  - 底部固定操作栏：
    - 当前审批人：通过（主按钮）+ 驳回（危险按钮）
    - 提交人（已驳回）：重新提交
    - 提交人（已提交 / 业务线审批中）：撤回
    - 外部单只渲染审批人的「通过 / 驳回」，重新提交与撤回永不渲染
    - 无可执行操作时不渲染操作栏

#### 表单校验

**通过确认弹窗**

- 初态：审批意见为空；优先级预填需求当前值

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 审批意见 | 否 | 选填，不超过 200 字 | blur | 「审批意见不超过 200 字」 | 否 |
| 优先级 | 是 | 单选组（P0 紧急 / P1 高 / P2 中 / P3 低），默认当前值，可调整（[business-rule.md §1.3](business-rule.md#13-流程约束)） | change | 「请选择优先级」 | 否 |

- 提交成功跳转：关闭弹窗，停留本页并刷新详情与时间线，无延迟
- 提交失败展示：弹窗顶部 AcAlert，输入保留
- 脏数据离开：本场景不需要（意见选填、优先级有默认值）

**驳回意见弹窗**

- 初态：驳回意见为空

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 驳回意见 | 是 | 10–200 字，实时字数「N/200」 | blur | 「驳回意见不少于 10 字」 | 否 |

- 提交成功跳转：关闭弹窗，停留本页并刷新详情，无延迟
- 提交失败展示：弹窗顶部 AcAlert，意见保留
- 脏数据离开：已输入内容时关闭弹窗 → AcModal「放弃已填写的驳回意见？」

**关联排期弹窗**

- 方式一：输入卡片编号精确搜索，校验存在后展示卡片摘要（排期日期 / 开发状态 / 开发人）供确认
- 方式二：从候选排期卡片列表中选择（规则见 [business-rule.md §5.1](business-rule.md#51-候选卡片列表)）
  - 筛选：月份（默认当月）+ 开发人（人员选择器，单选可清空）+ 需求提交人（人员选择器，单选可清空，仅内部提交人）；开发人选择器旁常驻灰字「仅已被领取开发 / 已完成的卡片有开发人，待开发卡片不参与该筛选」
  - 列表列：卡片编号 / 标题 / 排期日期 / 开发状态 / 开发人（待开发卡展示 `—`）/ 已关联需求数（已关联其他需求时展示「已关联 N 条需求」角标，悬停展示已关联需求的提交人名单，含外部提交人手填姓名）
  - 单行选中；切换月份或筛选条件时清空已选行并重新查询
  - 列表空态：无筛选时「当月暂无排期卡片」；有筛选时「无符合条件的卡片，可调整筛选或改用编号搜索」
- 两种方式互斥，选定卡片后「确认关联」才可点击；一条需求只能关联一张卡片，同一卡片允许被多条需求关联
- 初态：默认方式一，编号为空；方式二月份为当月、筛选为空、未选中卡片

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 卡片编号 | 方式一必填 | 精确匹配有效排期卡片 | blur | 「卡片不存在或已删除」 | 是（存在性校验） |
| 候选卡片 | 方式二必选 | 单选一行 | change | 「请选择一张排期卡片」 | 否 |

- 提交成功跳转：关闭弹窗，停留本页并刷新排期区，无延迟
- 提交失败展示：弹窗顶部 AcAlert，保留输入与已选行
- 脏数据离开：本场景不需要（未提交前不产生任何数据）

**追加附件弹窗**

- 初态：拖拽上传区 + 空的待上传列表；限制说明同需求提交页附件组

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |

- 初态：产品线固定展示「有点推荐」且只读（仅有点推荐开放外链）；需求类型默认值为新功能；有效期 30 天；提交次数上限 1；邀约对象备注为空

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 邀约对象备注 | 是 | 2–128 字；提示「建议填「公司 + 联系人」，仅内部可见，用于台账识别」 | blur | 「请填写邀约对象备注（2–128 字）」 | 否 |
| 需求类型默认值 | 是 | 下拉单选（5 类，不提供 `*` 通配），外部人可在 H5 重选 | change | 「请选择需求类型默认值」 | 否 |
| 有效期 | 是 | 单选组（7 / 15 / 30 / 60 / 90 天），下方展示换算后的到期日期 | change | 「请选择有效期」 | 否 |
| 提交次数上限 | 是 | 1–10 整数；气泡提示「默认仅可提交 1 次；超过上限后链接仍可打开但不再受理提交」 | change | 「提交次数上限需为 1–10 的整数」 | 否 |

- 提交成功跳转：弹窗**不关闭**，就地切换为生成结果态（链接全文 + 二维码 + 复制按钮 +「我已复制，关闭」），避免用户没拿到链接就关窗；结果态只展示一次，关闭后可从台账行「复制链接」重新取得，链接不重新生成
- 提交失败展示：弹窗顶部 AcAlert，字段值全部保留
- 脏数据离开：表单态有修改时关闭弹窗 → AcModal「您有未提交的外链信息，确认关闭？」；结果态关闭不确认

**撤销原因弹窗**

- 初态：撤销原因为空；弹窗内提示「撤销后对方打开链接将看到已失效提示，且无法恢复」

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 撤销原因 | 是 | 10–256 字 | blur | 「请填写撤销原因（10–256 字）」 | 否 |

- 提交成功跳转：关闭弹窗，停留本页并刷新表格，无延迟
- 提交失败展示：弹窗顶部 AcAlert，原因保留
- 脏数据离开：已输入内容时关闭弹窗 → AcModal「放弃已填写的撤销原因？」

#### 表格三态

- **空态**：当前筛选无数据 → 空状态插图 +「暂无外链记录」+「生成外链」引导按钮（有权限时）
- **加载态**：表格骨架屏（10 行占位）
- **错误态**：表格区错误插图 +「点击重试」

#### 交互约束

- 台账列表不展示完整链接凭证，仅在复制链接与二维码弹窗内可见，避免截屏外泄
- 已过期为服务端按到期时间实时判定的展示态，前端不自行比对时间
- 生成操作幂等：重复点击「确认生成」不产生多条外链，按钮点击后立即 disabled 直至返回

#### 表单校验

**配置弹窗（新增 / 编辑）**

- 初态：新增时催办阈值 48、升级阈值 72、去重窗口 24，其余为空；编辑时回填，产品线、优先级、审批级次只读

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 产品线 | 是 | 下拉单选（鸣鸣很忙 / 有点推荐），🚨 不提供 `*` | change | 「请选择产品线」 | 否 |
| 优先级 | 是 | 下拉单选（P0 / P1 / P2 / P3 + `*` 全部） | change | 「请选择优先级或全部通配」 | 否 |
| 审批级次 | 是 | 下拉单选（L1 / L2 / L3） | change | 「请选择审批级次」 | 是（产品线 + 优先级 + 级次唯一性校验） |
| 催办阈值 | 是 | 1–720 整数（小时） | change | 「催办阈值需为 1–720 的整数（小时）」 | 否 |
| 升级阈值 | 是 | 1–720 整数（小时），🚨 必须大于催办阈值 | change（与催办阈值联动校验） | 「升级阈值必须大于催办阈值」 | 否 |
| 去重窗口 | 否 | 1–168 整数（小时） | change | 「去重窗口需为 1–168 的整数（小时）」 | 否 |
| 配置说明 | 否 | 不超过 256 字 | blur | 「配置说明不超过 256 字」 | 否 |

- 弹窗底部常驻灰字：「保存后**立即对在途需求生效**（SLA 不做快照），与审批链配置「仅对新提交生效」不同」
- 提交成功跳转：关闭弹窗，停留本页并刷新表格，无延迟
- 提交失败展示：弹窗顶部 AcAlert，字段值保留
- 脏数据离开：弹窗内有修改时关闭 → AcModal「您有未保存的配置修改，确认关闭？」

- **区块职责**（自上而下）：

  - 图表二 · 趋势图（折线图，双 Y 轴：左轴耗时小时 / 右轴超时率）：🚨 X 轴严格按日期正序（最早在左），不按数值 Top N 重排、不设「其他」汇总柱；区间内无数据的周 / 月**不补 0 值点**，折线断开并在图例下注明「无数据区间已留空」
