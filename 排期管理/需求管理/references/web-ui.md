## 全局约定

### 状态标签色值语义

| 状态 | 标签文案 | 语义色 |
|------|---------|-------|
| `DRAFT` | 草稿 | 灰（default） |
| `SUBMITTED` | 已提交 | 蓝（processing） |
| `BU_REVIEWING` | 业务线审批中 | 蓝（processing） |
| `IMPL_REVIEWING` | 实施确认中 | 蓝（processing） |
| `PM_REVIEWING` | 产品确认中 | 蓝（processing） |
| `PM_SUBMITTED` | 待关联排期 | 橙（warning） |
| `LINKED` | 已关联排期 | 绿（success） |
| `REJECTED` | 已驳回 | 红（error） |

- `BU_APPROVED` / `IMPL_CONFIRMED` 为同事务内瞬时态（business-rule §2.3），**前端不展示为独立状态与独立节点**，筛选下拉与状态标签均不出现该两值
- 优先级标签：`P0 紧急`=红 / `P1 高`=橙 / `P2 中`=蓝 / `P3 低`=灰
- 业务线标签（药丸）：运营 `OPS` / 财务 `FIN` / 供应链 `SCM` / 数字化 `DIGITAL`，四色固定，全模块复用同一映射
- 产品线标签（药丸）：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`，两色固定；`YDTJ` 行的业务线列展示 `—`（`biz_line=*` 不向用户呈现）
- 提交来源标签：内部 `INTERNAL` 不展示标签（默认态）；外部 `EXTERNAL` 展示橙色「外部提交」标签，全模块统一

### 外链邀约状态标签色值语义

| 状态 | 标签文案 | 语义色 |
|------|---------|-------|
| `GENERATED` | 待使用 | 蓝（processing） |
| `USED` | 已提交 | 绿（success） |
| `EXPIRED` | 已过期 | 灰（default） |
| `REVOKED` | 已撤销 | 红（error） |

### 枚举取值（以 data-model.md 为准）

- **产品线**：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`（固定 2 值，data-model.md `requirement.product_line` 真源）
- **业务线**：运营 `OPS` / 财务 `FIN` / 供应链 `SCM` / 数字化 `DIGITAL`（固定 4 值，不支持自定义扩展）；`*` 为 `YDTJ` 内部占位值，**不进入任何下拉选项与展示**
- **需求类型**：新功能 `NEW_FEATURE` / 功能优化 `OPTIMIZE` / 缺陷修复 `BUGFIX` / 数据报表 `REPORT` / 系统集成 `INTEGRATION`（5 值，data-model.md `requirement.type` 真源）
- **提交来源**：内部 `INTERNAL` / 外部 `EXTERNAL`（data-model.md `requirement.submit_source` 真源）
- **外链有效期**：7 / 15 / 30 / 60 / 90 天（默认 30，data-model.md `requirement_public_link.valid_days` 真源）
- **审批级次**：1~3 级由命中的审批链决定（PM 专属链可配 `{1,2,3}` 任意非空子集，默认链为完整三级，business-rule §3.2）；详情页与提交预览按快照/预检返回的级次动态渲染，**前端不固定渲染 3 个节点**
- **审批模式**：各级审批**固定或签**（business-rule §3.5 明确不引入全员确认/并签模式），配置页该列为只读展示，不提供切换

### 附件类型与图标映射

三类附件图标与色值全模块复用同一映射（上传限制真源 business-rule §9.1）：

| 类型 | 图标语义 | 扩展名 | Web 端限制 |
|------|---------|-------|-----------|
| 图片 `image` | 图片图标（蓝） | jpg / jpeg / png / webp / gif | 单张 ≤10MB，最多 20 张 |
| 文档 `document` | 文档图标（绿） | pdf / docx / xlsx / pptx / txt | 单个 ≤50MB，最多 10 个 |
| 视频 `video` | 视频图标（紫） | mp4 / mov | 单个 ≤200MB，最多 3 个 |

> **实现落地差异（2026-08-19，已随代码实现确认）**：
> 1. 🚨 **内容安全审核本期不做**（用户裁决）：Web 端**一律不渲染审核角标**（详情页 / 编辑页的「审核中」橙标与「未通过」红标、编辑页「审核不阻塞提交」灰字均不存在）；接口也不返回 `contentCheckStatus`。
> 2. **附件改为前端 OSS STS 直传**：前端调 `/busyming-foundation/web/oss/token/get` 取临时凭证直传 OSS，再调 `POST /attachment/save` 上报元信息（或随表单 `attachments` 一并提交）；预览 / 下载由前端 `keyToUrl(ossKey)` 自签，**无后端下载端点**。
> 3. **前端限制仍需保留**（体验层），但安全边界在后端：`save` 时后端按 `uploadSource` 强校验扩展名 / 大小 / 张数上限。

### SLA 滞留程度色值语义

滞留时长相对命中阈值（business-rule §10.3）的展示口径，滞留看板与 SLA 仪表盘复用：

| 滞留程度 | 判定 | 语义色 |
|---------|------|-------|
| 正常 | `staleHours < remindHours` | 灰（default） |
| 已催办 | `remindHours ≤ staleHours < escalateHours` | 橙（warning） |
| 已升级 | `staleHours ≥ escalateHours` | 红（error） |

- 阈值按【产品线 × 优先级 × 审批级次】逐行取，**前端不硬编 48/72**，一律用接口返回的 `remindHours` / `escalateHours`（api-spec §6.1）
- 滞留时长展示为「N 小时」，≥ 48h 时换算为「N 天 M 小时」

### 数据可见范围

列表与详情的可见范围由后端按角色裁剪（business-rule §4.1），前端不做兜底过滤：业务线员工仅见本人提交、邀约人见本人提交 + 本人生成外链产生的外部单、业务线负责人见本业务线全部、有点推荐负责人见 `YDTJ` 全部、实施负责人见全部、产品经理见被指派 + 本人对口业务线、管理员见全部。

- **外部单的 Tab 归属**：外部单 `submit_by` 为 NULL，天然不进「我提交的」；统一归入「外部提交」Tab，以 `submit_source=EXTERNAL` 取数（business-rule §4.1），避免外部单落在所有 Tab 之外

## 页面清单

### 需求列表页

- **页面路径**：`/requirement/list`
- **权限编码**：
  - 路由：`MENU:RND:REQUIREMENT`
  - 按钮：`BTN:REQUIREMENT:CREATE`（新增需求）/ `BTN:REQUIREMENT:WITHDRAW`（撤回）/ `BTN:REQUIREMENT:DELETE`（删除草稿）/ `BTN:REQUIREMENT:EXPORT`（导出，仅管理员）
- **页面类型**：列表页
- **页面定位**：需求全景浏览与管理入口 —— 一屏回答「需求谁提的、卡在哪级、有没有排上开发」
- **区块职责**：
  - KPI 统计卡区（4 张，横排，点击可下钻筛选）：
    - 待提交数：本人 `DRAFT` 状态需求数 → 点击筛选 `status=DRAFT`
    - 待我审批数：当前登录人在审批链快照当前级次的待审数 → 点击切至「待我审批」Tab
    - 已通过数：`PM_SUBMITTED` + `LINKED` 合计 → 点击筛选该两状态
    - 已驳回数：`REJECTED` 状态数 → 点击筛选 `status=REJECTED`
    - KPI 取数口径跟随当前角色可见范围，与表格筛选结果同源
  - 视角 Tab（KPI 卡下方）：我提交的 / 待我审批 / 外部提交 / **滞留需求** / 全部
    - 「外部提交」以 `submit_source=EXTERNAL` 取数，仅对邀约人 / 有点推荐负责人 / 实施负责人 / 管理员展示；其余角色不渲染该 Tab
    - 「滞留需求」走 `/sla/stale-list` 取数（api-spec §6.1），筛选口径为「当前级次停留 ≥ 命中的 `remindHours` 且未处理」，**按停留时长倒序**（business-rule §10.5）；对全部能看到需求列表的角色展示，🚨 **可见范围与其他 Tab 完全一致，不因滞留视角放宽**
    - 「全部」仅对可见范围含他人需求的角色展示
  - 工具栏-筛选区：
    - 状态：Select 多选（草稿/已提交/业务线审批中/实施确认中/产品确认中/待关联排期/已关联排期/已驳回，不含瞬时态）
    - 产品线：Select 单选（鸣鸣很忙/有点推荐），置于业务线之前
    - 所属业务线：Select 单选（运营/财务/供应链/数字化）；**产品线选「有点推荐」时本项置灰并清空**（`YDTJ` 不区分业务线）
    - 提交来源：Select 单选（内部提交/外部提交），仅对可见外部单的角色展示；在「外部提交」Tab 下自动锁定为「外部提交」且置灰
    - 优先级：Select 多选（P0 紧急/P1 高/P2 中/P3 低）
    - 需求类型：Select 单选（新功能/功能优化/缺陷修复/数据报表/系统集成）
    - 提交人：Input 模糊搜索（仅可见范围含他人需求的角色展示）；**同时匹配内部提交人姓名与外部提交人姓名**（`external_submitter_name`）
    - 时间范围：AcRangePicker 日期选择器（按提交时间 `submit_at` 过滤，默认近 30 天，草稿无提交时间不受该条件过滤）
    - 操作：查询 / 重置
  - 工具栏-操作区：新增需求（主按钮）/ 导出
  - 主体区：数据表格，列定义如下

| 列名 | 取值说明 |
|------|---------|
| 需求编号 | `REQ-{YYYYMMDD}-{NNN}`，链接样式，点击进详情；外部单编号后跟橙色「外部提交」标签 |
| 标题 | 超长省略 + AcTooltip 全文 |
| 产品线 | 彩色药丸标签（鸣鸣很忙/有点推荐） |
| 所属业务线 | 彩色药丸标签；`YDTJ` 行展示 `—` |
| 提交人 | 内部单取 `submit_by_name`；外部单取 `external_submitter_name` + 灰色副行展示手填部门（`external_submitter_dept`，超长省略 + AcTooltip） |
| 当前状态 | 状态标签（见全局约定色值） |
| 当前审批人 | 取审批链快照当前级次审批人姓名；或签多人时展示「张三 等 N 人」+ AcTooltip 全名单；终态/草稿展示 `—` |
| 优先级 | 优先级标签 |
| 关联排期卡片 | `linked_card_no` 链接（新标签页跳 feature-schedule）；未关联展示 `—`；卡片已失效展示编号 + 红色「已失效」角标 |
| 附件 | 附件数量（如 `3`）+ 图钉图标，点击进详情页并展开附件面板；无附件展示 `—`（**仅滞留需求 Tab 外的常规视角展示**） |
| 停留时长 | 🚨 **仅「滞留需求」Tab 渲染**：`staleHours`（≥48h 换算为「N 天 M 小时」）+ 滞留程度色值标签；默认排序列 |
| 滞留级次 | 🚨 **仅「滞留需求」Tab 渲染**：`approvalLevelName`（业务线审批 / 实施确认 / 产品确认）+ 当前审批人姓名 |
| 操作 | 查看详情 / 编辑 / 撤回 / 删除 |

- **操作列可见性**：
  - 查看详情：全部行可见
  - 编辑：仅提交人本人 + 状态为 `DRAFT` 或 `REJECTED` 时可见，点击进需求编辑页
  - 撤回：仅提交人本人 + 状态为 `SUBMITTED` 或 `BU_REVIEWING`（即 L1 尚未做出通过/驳回动作）时可见；进入 `IMPL_REVIEWING` 及之后隐藏（business-rule §2.5）
  - 删除：仅提交人本人 + 状态为 `DRAFT` 时可见（business-rule §2.2 草稿可删除）；已提交需求不提供删除入口
  - **外部单（`submit_source=EXTERNAL`）只渲染「查看详情」**：编辑 / 撤回 / 删除全部不渲染（无提交人主体，内部人也不得代操作，business-rule §2.6）
- **分页**：默认 20 条/页，可选 20/50/100，展示总条数
- **布局引用**：`参见原型 assets/web/requirement-list.html`（起手范本：`page-blueprint/skeletons/web/preview/list-page.html`）

#### 导航关系

- 来源页：侧边菜单「研发 / 需求管理」；需求提交页提交/暂存成功后跳回；企微个人消息与群消息内的详情链接（先鉴权再定向）
- 去向页：需求详情（点编号或「查看详情」）、需求提交页（点「新增需求」）
- 返回行为：浏览器后退回上一页；筛选条件写入 URL query，从详情返回时保留筛选与页码
- 面包屑：首页 / 研发 / 需求管理

#### 关联排期弹窗（AcModal）

- 方式一：输入 `card_no` 精确搜索 → 校验存在后展示卡片摘要（排期日期/开发状态/开发人）供确认
- 方式二：从「候选排期卡片列表」中选择（规则真源 business-rule §5.1）：
  - **筛选区**：月份（AcMonthPicker，默认当月）+ 开发人（人员选择器，单选可清空）+ 需求提交人（人员选择器，单选可清空，仅内部提交人）；开发人选择器旁常驻灰字说明「仅已被领取开发 / 已完成的卡片有开发人，待开发卡片不参与该筛选」
  - **列表列**：卡片编号 / 标题 / 排期日期 / 开发状态 / 开发人（`PENDING` 卡展示 `—`）/ 已关联需求数（`linkedReqCount > 0` 时展示「已关联 N 条需求」橙色角标，悬停 tooltip 展示已关联需求的提交人名单，含外部提交人手填姓名）
  - 单行选中（AcRadio 行选），切换月份或筛选条件时清空已选行并重新查询
  - 列表空态：无筛选时「当月暂无排期卡片」；带筛选时「无符合条件的卡片，可调整筛选或改用编号搜索」
- 二者互斥，选定后「确认关联」按钮才可点击
- 一条需求只能关联一张卡片；同一卡片允许被多条需求关联，不做去重拦截；选中已关联卡（`linkedReqCount > 0`）提交时弹窗内二次确认「该卡片已承载 N 条需求（提交人：{名单}），确认将本需求同挂到该卡片？」，确认后才调 `/link-card`

#### 交互约束

- 审批接口 SLA ≤3 秒；前端 axios 超时**不解锁按钮**，toast 提示「审批处理中，请勿重复点击，稍后到列表查看结果」，避免连点导致重复推送
- 附件签名 URL 有效期 ~~5 分钟~~ → **前端自签，当前实现 1 小时**（阿里云 STS `DurationSeconds` 下限 15 分钟，5 分钟不可达），前端**不缓存不复用**：每次预览/下载重新自签，页面长时间停留后点预览不得因使用过期 URL 报错（business-rule §9.2）
- 审批类接口幂等：重复提交返回当前状态而非报错，前端按返回状态静默刷新详情，不弹错误
- 详情页所有按钮可见性以后端返回的 `actions` 能力字段驱动，前端不自行推导角色
