## 全局约定

### 状态标签色值语义

| 状态 | 标签文案 | 语义色 |
|------|---------|-------|
| `DRAFT` | 草稿 | 灰（default） |
| `SUBMITTED` | 已提交 | 蓝（processing） |
| `BU_REVIEWING` | 业务线审批中 | 蓝（processing） |
| `IMPL_REVIEWING` | 实施确认中 | 蓝（processing） |
| `PM_REVIEWING` | 产品确认中 | 蓝（processing） |
| `PM_SUBMITTED` | 待关联排期 | 橙（warning） |
| `LINKED` | 已关联排期 | 绿（success） |
| `REJECTED` | 已驳回 | 红（error） |

- `BU_APPROVED` / `IMPL_CONFIRMED` 为同事务内瞬时态（business-rule §2.3），**前端不展示为独立状态与独立节点**，筛选下拉与状态标签均不出现该两值
- 优先级标签：`P0 紧急`=红 / `P1 高`=橙 / `P2 中`=蓝 / `P3 低`=灰
- 业务线标签（药丸）：运营 `OPS` / 财务 `FIN` / 供应链 `SCM` / 数字化 `DIGITAL`，四色固定，全模块复用同一映射
- 产品线标签（药丸）：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`，两色固定；`YDTJ` 行的业务线列展示 `—`（有点推荐的业务线占位值不向用户呈现）
- 提交来源标签：内部 `INTERNAL` 不展示标签（默认态）；外部 `EXTERNAL` 展示橙色「外部提交」标签，全模块统一

### 外链邀约状态标签色值语义

| 状态 | 标签文案 | 语义色 |
|------|---------|-------|
| `GENERATED` | 待使用 | 蓝（processing） |
| `USED` | 已提交 | 绿（success） |
| `EXPIRED` | 已过期 | 灰（default） |
| `REVOKED` | 已撤销 | 红（error） |

### 枚举取值（以 data-model.md 为准）

- **产品线**：鸣鸣很忙 `SNACK` / 有点推荐 `YDTJ`（固定 2 值）
- **业务线**：运营 `OPS` / 财务 `FIN` / 供应链 `SCM` / 数字化 `DIGITAL`（固定 4 值，不支持自定义扩展）；`*` 为 `YDTJ` 内部占位值，**不进入任何下拉选项与展示**
- **需求类型**：新功能 `NEW_FEATURE` / 功能优化 `OPTIMIZE` / 缺陷修复 `BUGFIX` / 数据报表 `REPORT` / 系统集成 `INTEGRATION`（5 值）
- **提交来源**：内部 `INTERNAL` / 外部 `EXTERNAL`
- **外链有效期**：7 / 15 / 30 / 60 / 90 天（默认 30）
- **审批级次**：1~3 级由命中的审批链决定（产品经理专属链可配 L1/L2/L3 中任意非空组合，默认链为完整三级，business-rule §3.2）；详情页与提交预览按审批链快照/预检结果的级次动态渲染，**前端不固定渲染 3 个节点**
- **审批模式**：各级审批**固定或签**（business-rule §3.5 明确不引入全员确认/并签模式），配置页该列为只读展示，不提供切换

### 附件类型与图标映射

三类附件图标与色值全模块复用同一映射（上传限制真源 business-rule §9.1）：

| 类型 | 图标语义 | 扩展名 | Web 端限制 |
|------|---------|-------|-----------|
| 图片 `image` | 图片图标（蓝） | jpg / jpeg / png / webp / gif | 单张 ≤10MB，最多 20 张 |
| 文档 `document` | 文档图标（绿） | pdf / docx / xlsx / pptx / txt | 单个 ≤50MB，最多 10 个 |
| 视频 `video` | 视频图标（紫） | mp4 / mov | 单个 ≤200MB，最多 3 个 |

- 前端限制为体验层前置校验，安全边界在后端：保存附件时后端按上传来源强校验扩展名、大小与数量上限
- 附件对有权查看该需求的用户一律可见
- 审批中追加的附件额外渲染灰色「审批中追加」标签
- 🚨 Web 端是**唯一开放文档与视频上传的端**；App 仅图片（[mobile-ui.md](mobile-ui.md)），公开 H5 仅受限图片（[public-ui.md](public-ui.md)）

### SLA 滞留程度色值语义

滞留时长相对命中阈值（business-rule §10.3）的展示口径，滞留看板与 SLA 仪表盘复用：

| 滞留程度 | 判定 | 语义色 |
|---------|------|-------|
| 正常 | 滞留时长 < 催办阈值 | 灰（default） |
| 已催办 | 催办阈值 ≤ 滞留时长 < 升级阈值 | 橙（warning） |
| 已升级 | 滞留时长 ≥ 升级阈值 | 红（error） |

- 阈值按【产品线 × 优先级 × 审批级次】逐行取，**前端不固定写死 48/72 小时**，一律以后端返回的命中催办阈值与升级阈值为准
- 滞留时长展示为「N 小时」，≥ 48h 时换算为「N 天 M 小时」

### 数据可见范围

列表与详情的可见范围由后端按角色裁剪（business-rule §4.1），前端不做兜底过滤：业务线员工仅见本人提交、邀约人见本人提交 + 本人生成外链产生的外部单、业务线负责人见本业务线全部、有点推荐负责人见 `YDTJ` 全部、实施负责人见全部、产品经理见被指派 + 本人对口业务线、管理员见全部。

- **外部单的 Tab 归属**：外部单无内部提交人，天然不进「我提交的」；统一归入「外部提交」Tab，按提交来源 `EXTERNAL` 取数（business-rule §4.1），避免外部单落在所有 Tab 之外

## 页面清单

### 需求列表页

- **权限编码**：
  - 路由：`MENU:RND:REQUIREMENT`
  - 按钮：`BTN:REQUIREMENT:CREATE`（新增需求）/ `BTN:REQUIREMENT:WITHDRAW`（撤回）/ `BTN:REQUIREMENT:DELETE`（删除草稿）/ `BTN:REQUIREMENT:EXPORT`（导出，仅管理员）
- **页面类型**：列表页
- **页面定位**：需求全景浏览与管理入口 —— 一屏回答「需求谁提的、卡在哪级、有没有排上开发」
- **区块职责**：
  - KPI 统计卡区（4 张，横排，点击可下钻筛选）：
    - 待提交数：本人 `DRAFT` 状态需求数 → 点击筛选状态为草稿
    - 待我审批数：当前登录人在审批链快照当前级次的待审数 → 点击切至「待我审批」Tab
    - 已通过数：`PM_SUBMITTED` + `LINKED` 合计 → 点击筛选该两状态
    - 已驳回数：`REJECTED` 状态数 → 点击筛选状态为已驳回
    - KPI 取数口径跟随当前角色可见范围，与表格筛选结果同源
  - 视角 Tab（KPI 卡下方）：我提交的 / 待我审批 / 外部提交 / **滞留需求** / 全部
    - 「外部提交」按提交来源 `EXTERNAL` 取数，仅对邀约人 / 有点推荐负责人 / 实施负责人 / 管理员展示；其余角色不渲染该 Tab
    - 「滞留需求」筛选口径为「当前级次停留 ≥ 命中的催办阈值且未处理」，**按停留时长倒序**（business-rule §10.5）；对全部能看到需求列表的角色展示，🚨 **可见范围与其他 Tab 完全一致，不因滞留视角放宽**
    - 「全部」仅对可见范围含他人需求的角色展示
  - 工具栏-筛选区：
    - 状态：下拉多选（草稿/已提交/业务线审批中/实施确认中/产品确认中/待关联排期/已关联排期/已驳回，不含瞬时态）
    - 产品线：下拉单选（鸣鸣很忙/有点推荐），置于业务线之前
    - 所属业务线：下拉单选（运营/财务/供应链/数字化）；**产品线选「有点推荐」时本项置灰并清空**（`YDTJ` 不区分业务线）
    - 提交来源：下拉单选（内部提交/外部提交），仅对可见外部单的角色展示；在「外部提交」Tab 下自动锁定为「外部提交」且置灰
    - 优先级：下拉多选（P0 紧急/P1 高/P2 中/P3 低）
    - 需求类型：下拉单选（新功能/功能优化/缺陷修复/数据报表/系统集成）
    - 提交人：输入框模糊搜索（仅可见范围含他人需求的角色展示）；**同时匹配内部提交人姓名与外部提交人手填姓名**
    - 时间范围：日期范围选择器（按提交时间过滤，默认近 30 天，草稿无提交时间不受该条件过滤）
    - 操作：查询 / 重置
  - 工具栏-操作区：新增需求（主按钮）/ 导出
  - 主体区：数据表格，列定义如下

| 列名 | 取值说明 |
|------|---------|
| 需求编号 | `REQ-{YYYYMMDD}-{NNN}`，链接样式，点击进详情；外部单编号后跟橙色「外部提交」标签 |
| 标题 | 超长省略 + 气泡提示全文 |
| 产品线 | 彩色药丸标签（鸣鸣很忙/有点推荐） |
| 所属业务线 | 彩色药丸标签；`YDTJ` 行展示 `—` |
| 提交人 | 内部单展示提交人姓名；外部单展示外部提交人手填姓名 + 灰色副行展示手填部门（超长省略 + 气泡提示） |
| 当前状态 | 状态标签（见全局约定色值） |
| 当前审批人 | 取审批链快照当前级次审批人姓名；或签多人时展示「张三 等 N 人」+ 气泡提示全名单；终态/草稿展示 `—` |
| 优先级 | 优先级标签 |
| 关联排期卡片 | 关联卡片编号链接（新标签页跳 feature-schedule）；未关联展示 `—`；卡片已失效展示编号 + 红色「已失效」角标 |
| 附件 | 附件数量（如 `3`）+ 图钉图标，点击进详情页并展开附件面板；无附件展示 `—`（**仅滞留需求 Tab 外的常规视角展示**） |
| 停留时长 | 🚨 **仅「滞留需求」Tab 渲染**：当前级次停留时长（≥48h 换算为「N 天 M 小时」）+ 滞留程度色值标签；默认排序列 |
| 滞留级次 | 🚨 **仅「滞留需求」Tab 渲染**：滞留级次名称（业务线审批 / 实施确认 / 产品确认）+ 当前审批人姓名 |
| 操作 | 查看详情 / 编辑 / 撤回 / 删除 |

- **操作列可见性**：
  - 查看详情：全部行可见
  - 编辑：仅提交人本人 + 状态为 `DRAFT` 或 `REJECTED` 时可见，点击进需求编辑页
  - 撤回：仅提交人本人 + 状态为 `SUBMITTED` 或 `BU_REVIEWING`（即 L1 尚未做出通过/驳回动作）时可见；进入 `IMPL_REVIEWING` 及之后隐藏（business-rule §2.5）
  - 删除：仅提交人本人 + 状态为 `DRAFT` 时可见（business-rule §2.2 草稿可删除）；已提交需求不提供删除入口
  - **外部单只渲染「查看详情」**：编辑 / 撤回 / 删除全部不渲染（无提交人主体，内部人也不得代操作，business-rule §2.6）
- **分页**：默认 20 条/页，可选 20/50/100，展示总条数
- **布局引用**：`参见原型 assets/web/requirement-list.html`（起手范本：`page-blueprint/skeletons/web/preview/list-page.html`）

#### 导航关系

- 来源页：侧边菜单「研发 / 需求管理」；需求提交页提交/暂存成功后跳回；企微个人消息与群消息内的详情链接（先鉴权再定向）
- 去向页：需求详情（点编号或「查看详情」）、需求提交页（点「新增需求」）
- 返回行为：浏览器后退回上一页；筛选条件写入页面地址，从详情返回时保留筛选与页码
- 面包屑：首页 / 研发 / 需求管理

- **权限编码**：

- **区块职责**：

    - 主标题行：需求编号 + 标题 + 当前状态标签

    - 邀约溯源行：邀约人姓名 + 邀约对象备注 + 「来源外链」链接（点击跳外链管理页并高亮该行）

  - **附件区块（折叠面板，置于审批时间线上方、外部提交区块之下）**：
    - 面板标题「附件（N）」；N>0 时**默认展开**，N=0 时渲染折叠态 + 灰字「无附件」（不隐藏面板，保持页面结构稳定）
    - 文件列表（每行）：类型图标 + 文件名（超长中间省略保留扩展名 + 气泡提示全名）+ 文件大小 + 上传人 + 上传时间 + 右侧「预览」/「下载」操作

    - 右上角「追加附件」按钮：**仅提交人本人 + 状态为 `SUBMITTED` / `BU_REVIEWING` / `IMPL_REVIEWING` / `PM_REVIEWING` 之一**时渲染（business-rule §9.4）；旁侧气泡提示「追加后将通知当前审批人，**不会重置审批计时**」

    - 每节点展示：级次名称 / 角色名 / 审批人姓名（或签多人时展示实际动作人；未动作时展示全部候选人「张三、李四（或签）」）/ 节点状态（待审 灰 / 已通过 绿 / 已驳回 红）/ 审批意见 / 操作时间
    - 当前待审节点高亮（蓝色描边 + 「审批中」角标）；自动跳过（`AUTO_SKIP`，提交人即该级审批人）节点展示「已自动跳过」+ 流水说明文案
    - 驳回重提场景按审批轮次分轮展示：默认展开最新一轮，历史轮次折叠为「查看第 N 轮审批记录」
    - 内部单产品确认（L3）节点的审批人即提交对象（内部单必中专属链，business-rule §3.4）
  - **AI 方案确认面板（置于审批时间线上方、附件区块之下）**：
    - 🚨 **可见性收口（business-rule §11.1 红线一）**：仅当前级次审批人与管理员渲染，**提交人与其他角色一律不渲染**（可见性由后端判定，前端不自行推导）；无方案记录时不渲染面板，未开启 AI 辅助的产品经理无感知

    - **生成中（`GENERATING`）**：面板内加载指示 + 文案「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批，AI 结果将自动作废」；页面每 5 秒自动刷新生成状态，离开页面即停止

    - 面板底部三个操作按钮（仅 `READY` 且当前用户为该需求当前级次审批人时可点）：
      - **确认并通过**（主按钮）：弹出意见确认框（内容为 AI 预填的审批意见，可编辑，10–200 字）
      - **请求补充材料**（次按钮）：弹窗内以信息缺口清单预填多行文案（可编辑，10–500 字），标题明确提示「以下内容将发送给提交人」；已发出过时在按钮旁追加「已于 {时间} 发出」灰字
      - **重新生成方案**（文字按钮）：气泡确认「将基于当前需求信息重新分析并生成新版本方案，确认重新生成？」
  - 下部-排期关联区：
    - 未关联：占位提示「未关联排期卡片」+「关联排期」按钮（仅状态 `PM_SUBMITTED` 且当前用户为该需求的产品经理（内部单=提交对象，外部单=L3 实际通过人）或管理员时可见；其余角色/状态仅见灰色提示）
    - 已关联：卡片编号（链接，新标签页跳 feature-schedule）/ 排期日期 / 开发状态标签（`PENDING` 待开发 灰 / `IN_PROGRESS` 开发中 蓝 / `DONE` 开发完成 绿）/ 开发人 +「解除关联」按钮（同关联按钮权限）

    - 开发状态为实时读取 feature-schedule，本模块只读不回写（business-rule §5 单向关联）
    - **缺陷修复（`BUGFIX`）单整区替换为「黑灯工厂工单区」**（business-rule §2.7）：不渲染排期关联与解除按钮；`PM_SUBMITTED` 起展示「已转黑灯工厂自动化修复」+ 工单号（链接跳运维管理 · 黑灯工厂工单）+ 工单级别 / 状态 / 负责人只读回传；建单失败展示红色警示条「转黑灯工厂建单失败，系统将自动重试」
  - 底部固定操作栏：
    - 当前审批人可见：通过（主按钮）+ 驳回（危险按钮）

#### 关联排期弹窗

- 方式一：输入卡片编号精确搜索 → 校验存在后展示卡片摘要（排期日期/开发状态/开发人）供确认
- 方式二：从「候选排期卡片列表」中选择（规则真源 business-rule §5.1）：
  - **筛选区**：月份（月份选择器，默认当月）+ 开发人（人员选择器，单选可清空）+ 需求提交人（人员选择器，单选可清空，仅内部提交人）；开发人选择器旁常驻灰字说明「仅已被领取开发 / 已完成的卡片有开发人，待开发卡片不参与该筛选」
  - **列表列**：卡片编号 / 标题 / 排期日期 / 开发状态 / 开发人（`PENDING` 卡展示 `—`）/ 已关联需求数（已关联其他需求时展示「已关联 N 条需求」橙色角标，悬停气泡提示展示已关联需求的提交人名单，含外部提交人手填姓名）
  - 单行选中，切换月份或筛选条件时清空已选行并重新查询
  - 列表空态：无筛选时「当月暂无排期卡片」；带筛选时「无符合条件的卡片，可调整筛选或改用编号搜索」
- 二者互斥，选定后「确认关联」按钮才可点击
- 一条需求只能关联一张卡片；同一卡片允许被多条需求关联，不做去重拦截；选中已关联其他需求的卡片提交时弹窗内二次确认「该卡片已承载 N 条需求（提交人：{名单}），确认将本需求同挂到该卡片？」，确认后才提交关联

#### 交互约束

- 审批处理 SLA ≤3 秒；请求超时时**不解锁按钮**，toast 提示「审批处理中，请勿重复点击，稍后到列表查看结果」，避免连点导致重复推送
- 附件预览/下载链接有效期 1 小时，前端**不缓存不复用**：每次预览/下载重新获取链接，页面长时间停留后点预览不得因使用过期链接报错（business-rule §9.2）
- 审批类操作幂等：重复提交返回当前状态而非报错，前端按返回状态静默刷新详情，不弹错误
- 详情页所有按钮可见性以后端返回的可操作能力驱动，前端不自行推导角色

## 与业务规则对齐说明

| 对齐点 | 处理方式 |
|--------|---------|
| 需求类型枚举 | 采用 business-rule §3.1 / data-model 的 5 值（新功能/功能优化/缺陷修复/数据报表/系统集成），不使用「其他」 |
| 审批模式 | 各级固定或签，配置页该列只读，不提供并签选项（business-rule §3.5） |
| 驳回意见长度 | 必填且 10–200 字（下限取 business-rule §2.4 的 ≥10 字） |
| 撤回可见范围 | `SUBMITTED` + `BU_REVIEWING` 两状态（business-rule §2.5），非仅 `SUBMITTED` |
| 提交对象驱动 | 内部提交必选提交对象（产品经理），候选为本归属下配有启用中专属审批链的产品经理；选定后实时预览将命中的审批链；详情页内部单 L3 节点审批人即提交对象；L2 通过不存在指派产品经理动作（business-rule §1.3 / §3.4） |
| 关联排期操作人 | 该需求产品经理（内部单=提交对象，外部单=L3 实际通过人）+ 管理员（business-rule §5），非仅产品经理 |
| 瞬时态展示 | `BU_APPROVED` / `IMPL_CONFIRMED` 不进入筛选项、不作为独立时间线节点（business-rule §2.3） |
| 通知触发 | 前端不触发推送，所有企微个人/群消息由后端在业务操作成功后异步发出（business-rule §6），页面仅通过 toast 反馈业务结果 |
| 产品线与业务线联动 | 产品线=有点推荐 时业务线字段隐藏不参与校验，由后端以占位值 `*` 落库（business-rule §1.1）；`*` 不向用户展示也不可选 |
| 外部单可操作面 | 列表与详情均仅保留审批类与排期类操作，编辑/撤回/删除/重提全部不渲染（business-rule §2.6） |
| 外部身份展示 | 外部提交人姓名/部门为手填自由文本，不关联组织架构，前端不提供人员/部门详情链接（data-model §1） |
| 外链手机号用途 | 仅内部可见、仅供内部联系，页面不提供任何向外部发送短信/通知的入口（business-rule §8.5 单向收口） |
| 外链 token 展示 | 台账列表不展示完整 token，仅在复制/二维码弹窗内可见（business-rule §8.4 防刷约束） |
| 公开 H5 边界 | 公开 H5 不属本文作用域，不共用侧边菜单/面包屑/登录态组件，规范见 [public-ui.md](public-ui.md) |
| 附件三端差异 | Web 端为唯一支持图片/文档/视频全类型的端；App 仅图片、H5 仅受限图片，前端限制只是体验前置，**类型与大小一律由后端按上传来源强校验**（business-rule §9.1） |
| 附件删除边界 | 仅草稿态可删且入口只在编辑页；详情页与已提交态一律不渲染删除按钮，已提交后的删除为逻辑删除、文件不物理移除（business-rule §9.6） |
| 附件与审批计时 | 审批中追加附件只通知当前审批人，**不重置 SLA 停留计时**，前端文案须明确提示（business-rule §9.4 / §10.1） |
| 附件访问 | 预览/下载链接有效期 1 小时，每次重新获取；附件访问权限跟随需求可见范围，看不到需求即无法获取其附件（business-rule §9.2） |
| 附件追加态 | 可追加状态为 `SUBMITTED` + 三个 `*_REVIEWING`（共四态，business-rule §9.4） |
| SLA 菜单权限码 | **两个菜单码**：`MENU:RND:REQUIREMENT_SLA`（SLA 仪表盘）/ `MENU:RND:REQUIREMENT_SLA_CONFIG`（SLA 配置），两页在侧边栏各占一行同级菜单 |
| SLA 阈值来源 | 滞留判定与色值分档一律以后端返回的命中催办阈值与升级阈值为准，**前端不固定写死 48/72 小时**（business-rule §10.3 阈值按产品线×优先级×级次逐行取） |
| SLA 配置不做快照 | 与审批链快照机制相反：SLA 配置改后立即对在途需求生效，配置页调紧阈值需二次确认并提示受影响在途条数（business-rule §10.3） |
| SLA 缺配处理 | 未命中任何启用配置行时走系统默认 48h/72h/24h，仅顶部 warning 提示，**不阻断催办**（区别于审批链缺级直接拒绝提交） |
| 催办去重窗口 | 手动催办与定时自动催办共用同一去重窗口（默认 24h），前端不自行计算窗口，按后端返回的最近催办时间与错误文案原样展示（business-rule §10.7）；**手动催办不受静默时段限制** |
| 仪表盘指标取数 | 四张卡为平均审批耗时 / 端到端平均周期 / 超时率（按后端给出的百分数直接展示）/ 当前滞留条数（**实时值，不受区间筛选影响**）；端到端起算取首次提交时间，超时率按各级实际停留时长实算（business-rule §10.6） |
| 趋势图排序 | X 轴严格按日期正序排列（最早在左），不得按数值 Top N 重排、不设「其他」汇总柱；无数据区间不补 0 值点 |
| 仪表盘只读 | SLA 仪表盘不提供任何写操作，催办入口统一收口在需求列表「滞留需求」Tab 行内 |
