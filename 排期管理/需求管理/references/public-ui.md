## 端能力边界

公开 H5 是**免登录、仅供外部人使用的单向采集端**，只服务有点推荐（`YDTJ`）产品线。

- **仅 3 个页面**：需求提交页 / 提交成功页 / 链接失效页，**无第 4 个页面**
- **完全单向收口**（business-rule §8.5）：不提供进度查询、不提供撤回/修改、不提供草稿、不发任何短信或通知
- **无登录态**：不渲染侧边菜单、面包屑、顶部用户信息、退出登录等任何管理后台外壳；页面不经登录拦截
- **唯一入口**：外部人凭内部人发放的专属链接访问；链接本身不携带任何业务上下文，邀约信息全部由服务端按链接识别（business-rule §8.1）
- **三页共用同一专属链接**：按链接校验结果与提交结果在页内切换渲染，**不设独立访问地址**（防止外部人直达成功页 / 失效页）
- **不展示任何内部信息**：审批链、审批人姓名、业务线枚举、其他需求数据、内部人员组织架构一律不出现在页面与服务端返回中
- **仅开放受限图片上传**（business-rule §9.5）：可从相册选图，**单张 ≤5MB、最多 3 张、单次提交总大小 ≤15MB**；🚨 **文档与视频上传不开放**，页面不渲染任何文件选择入口；图片**随表单一并提交归属**（需配合图形验证码），不存在免链接校验的上传通道；详见下方「图片上传限制（公开 H5 专属）」

## 全局约定

### 进页链接校验流程

进页第一件事是校验链接，校验结果决定渲染哪个页面，**外部人无法通过任何方式绕过**：

| 校验结果 | 渲染页面 | 说明 |
|---------|---------|------|
| 可用（`GENERATED` 且未过期、未达提交上限） | 需求提交页 | 同时回填邀约对象备注与需求类型默认值 |
| 达提交上限（`USED`） | 链接失效页 - 已提交态 | 携带已产生的需求编号 |
| 已过期（`EXPIRED`） | 链接失效页 - 已过期态 | — |
| 已撤销（`REVOKED`） | 链接失效页 - 已撤销态 | 不展示撤销原因（内部信息） |
| 链接凭证缺失 / 非法 / 查不到 | 链接失效页 - 链接无效态 | 与「已撤销」返回时延一致（business-rule §8.4 防枚举） |

- 链接缺少凭证参数时**不发起校验**，直接渲染「链接无效」态
- 校验期间展示整页加载态（骨架屏），不闪现表单
- 校验请求失败（网络异常/服务端错误）不等于失效：展示整页错误态 + 「重新加载」按钮，与失效页文案严格区分

### 状态与标签

- 公开 H5 **不展示需求状态标签**：外部人只在提交成功页看到需求编号，看不到 `SUBMITTED` 等任何状态
- 公开 H5 **不展示业务线与优先级**：业务线由系统固定写占位值 `*`，优先级取链接默认值（business-rule §8.3）
- 唯一对外可见的枚举是**需求类型**：新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成（5 值，`*` 不出现）

### 图片上传限制（公开 H5 专属）

| 项 | 限制 | 说明 |
|----|------|------|
| 支持类型 | 仅图片：jpg / jpeg / png / webp / gif | 🚨 文档（pdf/docx/xlsx/pptx/txt）与视频（mp4/mov）**不开放** |
| 单张大小 | ≤5MB | 低于内部端 10MB 阈值 |
| 张数上限 | 最多 3 张 | 低于内部端 20 张阈值 |
| 单次提交总大小 | ≤15MB | 选图即累加校验，超限拒收最后一张 |
| 选图渠道 | **仅相册选择** | 🚨 **不提供拍照入口**（不申请相机权限，避免外部人权限疑虑） |

- 图片为**选填**：不上传任何图片也可正常提交
- 图片经服务端代为存储：外部人免登录，不向公网暴露任何存储写入凭证，避免存储滥用（business-rule §9.5）
- 图片与表单**一并提交归属**：选图后即通过带链接校验的上传通道上传，上传后暂不归属任何需求；提交成功时才与需求一并写入并归属。上传通道与提交共用同一链接校验与 IP 限流计数，不开放无链接校验的上传通道
- 外部上传的类型、大小、张数限制由服务端强制校验，页面限制仅作体验前置
- 附件不做内容安全审核，页面不展示任何审核态
- 🚨 图片上传失败**不阻塞提交**（business-rule §9.5）：外部人只有一次提交机会，不得因图片问题让其丢失提交能力

## 页面间导航总表

| 来源 | 去向 | 触发 | 导航方式 |
|------|------|------|---------|
| 外部渠道（微信/企微消息、二维码扫码） | 需求提交页 | 打开专属链接且校验通过 | 浏览器直接打开 |
| 外部渠道（同上） | 链接失效页 | 打开专属链接且校验不通过 | 浏览器直接打开（同一链接内渲染切换） |
| 需求提交页 | 提交成功页 | 预览确认弹窗内点「确认提交」且服务端返回成功 | 页面内容整体替换（Replace，**不入历史栈**） |
| 需求提交页 | 链接失效页 | 提交时服务端返回链接已失效 / 已达上限 | 页面内容整体替换（Replace） |
| 提交成功页 | — | — | **终点页，无任何去向** |
| 链接失效页 | — | — | **终点页，无任何去向** |

- 三页共用同一专属链接，按链接校验结果与提交结果在页内切换渲染，**不设独立访问地址**，避免外部人直接访问成功页伪造凭证
- 成功页与失效页均为终点：**不提供返回按钮、不提供再次提交入口**；浏览器后退回到提交页时须重新走链接校验（此时已 `USED`，落到失效页-已提交态）

## 页面清单

### 需求提交页

- **访问方式**：凭专属链接访问
- **权限编码**：**无**（免登录页面，不做权限校验，鉴权凭据即专属链接本身）
- **页面类型**：表单页（分组表单，单页无分步）
- **页面定位**：外部人一次性填写并提交需求 —— 一屏回答「我是谁、我要什么」
- **区块职责**：
  - 顶部说明区（非导航栏，**无返回按钮**）：
    - 主标题「有点推荐 - 需求提交」
    - 副标题灰色小字「本表单由 {邀约对象备注} 的邀约链接进入，提交后由内部团队评估处理」
    - inline 提示条（常驻，浅蓝）：「本链接**仅可提交 1 次**，提交后无法修改或撤回，请确认内容后再提交」（次数取链接实际提交次数上限）
  - 表单-需求信息组（分组卡片）：
    - 需求标题（单行输入）
    - 需求描述（多行输入，实时字数「N/2000」）
    - 需求类型（选择器，默认值由链接携带）
    - 描述框下方灰色引导文案：「请说明你遇到的问题、期望的效果，以及大致的使用场景；描述越具体越容易被采纳」
  - 表单-图片组（分组卡片，置于需求信息组下方、提交人信息组之上）：
    - 分组标题「相关图片（N/3）」+ 右侧灰字「选填」
    - 引导文案（灰字）：「可上传问题截图或现场照片帮助内部团队理解；最多 3 张，单张不超过 5MB」
    - 横向缩略图行（正方形、圆角）：已选图片 + 右上角删除叉标，末位为虚线「+」添加卡（达 3 张上限时添加卡置灰 + 轻提示「最多只能上传 3 张图片」）
    - 🚨 点「+」**直接拉起系统相册选择器**（支持多选），**不弹「拍照 / 从相册选择」选源面板、不调用相机**（不申请相机权限）
    - 上传中缩略图蒙上半透明层 + 环形百分比进度；单张失败置红边 + 中心感叹号，**点击可单张重试**（不影响其余图片与表单）
    - 分组底部实时展示累计大小「已选 N 张，共 X.X MB / 上限 15MB」；超限时拒收最后一张 + 轻提示「本次提交图片总大小不得超过 15MB」
    - 页面不展示任何审核状态，外部人只看到「上传成功」
  - 表单-提交人信息组（分组卡片）：
    - 姓名（单行输入，可用邀约对象备注预填，允许修改）
    - 所属部门（单行输入，**自由文本**，下方灰色小字「填写你所在的公司或部门名称即可」）
    - 手机号（单行输入，唤起数字键盘，下方灰色小字「仅供内部团队必要时联系你，不会收到任何短信」）
  - 表单-验证组：
    - 图形验证码（输入框 + 右侧验证码图片，点击图片刷新）
  - 底部固定操作栏（安全区内）：提交按钮（全宽主按钮，文案「提交需求」）
    - **不提供暂存草稿、不提供重置表单**
  - 页脚：灰色小字「本页面为一次性邀约链接，请勿转发他人」
- **不出现的元素**（红线）：文档上传、视频上传、拍照入口、业务线选择、优先级选择、目标日期、登录/注册入口、客服入口、进度查询入口
  - 🚨 **图片上传开放**（≤5MB/张，最多 3 张，仅相册），见上方「表单-图片组」；红线仅适用于文档与视频（business-rule §9.5）
- **布局引用**：参见原型 `assets/h5/requirement-public-submit.html`

#### 表单初态

- 需求类型：预填链接携带的默认值（可改）
- 姓名：以邀约对象备注预填（可清空改写）；备注为公司名时允许外部人直接覆盖为本人姓名
- 部门 / 手机号 / 标题 / 描述：空
- 图片：空（仅展示虚线「+」添加卡与限制说明）
- 图形验证码：进页即请求一张，5 分钟内有效
- **无编辑态**：本页只有新建一种形态，不存在回填历史提交内容的场景

#### 导航关系

- 来源页：外部渠道链接 / 二维码扫码（无站内来源）
- 去向页：提交成功页（成功）/ 链接失效页（链接在提交瞬间失效）
- 返回行为：**无返回按钮**；浏览器后退等于离开本站，不做拦截
- 面包屑：**不渲染**（无站内层级）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 链接校验 | 进入页面自动执行 | 否 | 整页骨架屏 | 渲染表单并回填默认值（无轻提示） | 失效 → 切换为链接失效页；网络异常 → 整页错误态 + 「重新加载」 |
| 选择需求类型 | 点击选择项 | 否 | — | 选择器关闭并回填选中值 | — |
| 刷新验证码 | 点击验证码图片 | 否 | 图片区局部 loading | 图片替换为新验证码，输入框清空 | 错误轻提示「验证码加载失败，请点击重试」 |
| 添加图片 | 点「+」卡且已选 <3 张 | 否（直接拉起相册） | 缩略图位蒙层 + 环形进度 | 进度跑满后取消蒙层，计数与累计大小同步更新（**无轻提示**） | 单张置红边 + 中心感叹号，点击单张重试；超张数/超单张大小/超总大小/格式不支持时错误轻提示展示具体限制文案，**已传成功的图片与表单内容均不受影响** |
| 删除已选图片 | 点缩略图右上叉标 | 否（外部人场景不加确认摩擦） | 缩略图位 loading | 缩略图行重排，计数与累计大小同步减少（**无轻提示**） | 错误轻提示「移除失败，请重试」，缩略图保留 |
| 预览已选图片 | 点缩略图本体（非叉标） | 否 | — | 打开全屏图片查看层（可左右切图、点击关闭） | — |
| 提交需求 | 全部必填字段校验通过 | **必须**：预览确认弹窗（见下节），弹窗内「确认提交」为真正提交动作 | 弹窗确认按钮 loading + disabled | 页面整体替换为提交成功页（展示需求编号） | 按失败原因分流（见下表）+ 字段值全部保留 + 按钮恢复 |

**提交失败分流：**

| 服务端返回 | 页面处理 |
|---------|---------|
| 验证码错误 | 关闭弹窗，验证码输入框标红「验证码错误，请重新输入」+ 自动刷新验证码；连续错 3 次强制刷新并清空输入（business-rule §8.4） |
| 图片相关 | 关闭弹窗，图片组标红并展示服务端文案原文（如超张数 / 超大小 / 格式不支持 / 图片已失效），**表单其余字段全部保留**，外部人可移除问题图片后重提；🚨 **不消耗提交次数** |
| 链接已达提交上限 / 已过期 / 已撤销 | 关闭弹窗，页面整体替换为链接失效页对应形态，**不保留表单** |
| IP 限流 | 关闭弹窗，整页 inline 提示「操作过于频繁，请 1 分钟后再试」，表单内容保留 |
| 审批链未配置 | 关闭弹窗，错误轻提示「提交失败，请联系邀约人处理」（**不暴露「审批链未配置」内部原因**），表单内容保留 |
| 其他服务端错误 / 超时 | 关闭弹窗，错误轻提示「提交失败，请稍后重试」，表单内容保留；**不自动重试**（避免重复提交占用唯一次数） |

#### 提交前预览确认弹窗

因提交后不可重填也不可修改（business-rule §8.2），本弹窗为**强制环节，不可跳过、不提供「不再提示」**。

- 形式：底部半屏弹层（占屏约 70%，内容超出可滚动）
- 标题「请确认提交内容」
- 副标题红色小字「提交后**无法修改、无法撤回**，本链接也将失效」
- 内容区：以只读信息行完整回显 6 项 —— 需求标题 / 需求描述（全文，不折叠）/ 需求类型 / 姓名 / 所属部门 / 手机号
- 已选图片时在需求类型下方**追加一行图片回显**（第 7 项）：行标题「相关图片（N 张）」+ 横向缩略图（只读，**不带删除叉标**，可点击看大图）；未选图片时该行**不渲染**（不展示「无图片」占位）
- 底部按钮：左「返回修改」（次按钮，关闭弹窗回表单，字段值保留）/ 右「确认提交」（主按钮，等宽）
- 关闭方式：点击遮罩 / 下拉手势 / 「返回修改」，三者行为一致（回到表单，不消耗提交次数）
- 确认按钮点击后立即 disabled 直到服务端返回，**防止重复提交耗尽唯一次数**

| 相关图片 | 否 | 仅 jpg/png/webp/gif；**单张 ≤5MB、最多 3 张、单次总大小 ≤15MB**；仅相册选图；页面选图即校，服务端强制终校 | 选择后立即 | 「图片最多 3 张」/「单张图片不得超过 5MB」/「本次提交图片总大小不得超过 15MB」/「不支持的图片格式」 | 是（经带链接校验的上传通道上传） |

- 提交时全表单校验，首个错误字段滚动至可视区并聚焦
- 提交成功跳转：页面内容整体替换为提交成功页，**不做延迟、不用轻提示中转**（避免用户误关页面而看不到需求编号）
- 提交失败展示：字段值全部保留可编辑，仅验证码按失败原因清空
- 脏数据离开：**不做拦截**（无登录态、无草稿，拦截提示对外部人无意义且干扰体验）
- 键盘避让：描述多行输入与手机号输入聚焦时自动滚动至可视区，底部提交按钮随键盘上移
- 安全区：底部提交按钮避开屏幕底部安全区

#### 交互约束

- 提交**防重复保护不可省**：页面按钮 disabled + 服务端对单链接提交计数做并发互斥，双重防护（business-rule §8.4）
- 请求超时**不解锁按钮**，提示「提交处理中，请勿重复点击，请稍后重新打开链接确认结果」
- 页面不接入任何前端埋点以外的第三方脚本，不采集除 IP / UA（服务端记录）之外的设备信息
- 页面不在浏览器本地缓存表单内容：避免公用设备泄露填写人信息
- 🚨 **图片不阻塞提交**：图片为选填，未上传也可提交；仅当存在「上传中」图片时提交按钮置灰 + 下方灰字「图片上传中，请稍等」；存在失败图片时预览弹窗内红字提示「有 N 张图片上传失败，确认提交将不包含这些图片」（仍可确认提交）
- 图片上传**必须经链接校验**，与提交共用同一链接校验与 IP 限流计数；链接失效时上传直接报错，**但不因上传失败就把页面切到失效页**（仅提交返回失效时才整页切换）
- 已选图片仅在本次访问内有效，**不在浏览器本地缓存**；刷新页面后需重新选图（与表单不缓存口径一致），已上传但未提交的图片不归属任何需求，由存储侧自动清理

### 提交成功页

- **访问方式**：与需求提交页同一专属链接内渲染切换，**无独立访问地址**
- **权限编码**：无（免登录）
- **页面类型**：结果页（单栏居中）
- **页面定位**：给外部人一张提交凭证 —— 一屏回答「提交上了吗、凭证是什么、然后呢」
- **区块职责**：
  - 成功插图 + 主标题「提交成功」
  - 需求编号区（视觉重点，最大字号）：`REQ-{YYYYMMDD}-{NNN}` + 右侧「复制编号」文字按钮
  - 说明文案区（灰色，3 行）：
    - 「请保存该编号作为提交凭证」
    - 「内部团队将对需求进行评估，**处理结果由邀约人线下告知你**」

  - 底部 inline 提示（浅灰）：「本链接已完成提交，再次打开将不能再填写」
- **不出现的元素**（红线）：查看进度按钮、再次提交按钮、返回按钮、修改按钮、客服/联系入口、任何指向内部系统的链接
- **布局引用**：参见原型 `assets/h5/requirement-public-result.html`（成功态，与失效态同一原型文件内以形态切换展示）

### 链接失效页

- **访问方式**：与需求提交页同一专属链接内渲染切换，**无独立访问地址**
- **权限编码**：无（免登录）
- **页面类型**：结果页（单栏居中）
- **页面定位**：告诉外部人「这个链接现在不能填了」，并把出路统一收敛到「联系邀约人」
- **区块职责**：
  - 状态插图（按形态区分：已提交=成功系插图；其余=失效系插图）
  - 主标题 + 说明文案（按形态差异化，见下表）
  - 统一引导文案（灰色）：「如仍需提交需求，请联系向你发送链接的邀约人重新获取」
  - 「已提交」形态额外展示需求编号（可复制），其余形态不展示任何编号
- **不出现的元素**（红线）：重试提交按钮、返回按钮、任何内部人姓名/手机号/组织信息、撤销原因原文
- **布局引用**：参见原型 `assets/h5/requirement-public-result.html`（失效态，与成功态同一原型文件内以形态切换展示）

#### 四类失效形态文案差异化

| 形态 | 触发条件 | 主标题 | 说明文案 | 额外内容 |
|------|---------|-------|---------|---------|
| 已提交 | 链接 `USED`（达提交上限） | 该链接已完成提交 | 你已通过本链接提交过需求，每个链接仅可提交 {提交次数上限} 次 | 需求编号（可复制） |
| 已过期 | 链接 `EXPIRED` | 链接已过期 | 该邀约链接已超过有效期，无法继续提交 | 无（**不展示过期时间**，避免暴露内部有效期策略） |
| 已撤销 | 链接 `REVOKED` | 链接已失效 | 该邀约链接已被发放人收回，无法继续提交 | 无（**不展示撤销原因与撤销人**） |
| 链接无效 | 链接凭证缺失 / 格式非法 / 查无此链接 | 链接无效 | 链接不完整或已失效，请确认是否从邀约人处完整复制 | 无 |

- 「已撤销」与「链接无效」的服务端返回时延须一致，**页面也不得因形态不同产生可观测的加载差异**（business-rule §8.4 防枚举）
- 四类文案均不出现「审批」「业务线」「产品线」等内部术语

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 复制编号 | 「已提交」形态点击「复制编号」 | 否 | — | 成功轻提示「需求编号已复制」，停留本页 | 错误轻提示「复制失败，请手动长按选中编号」 |

#### 页面三态

- **空态**：不适用（本页本身即结果态）
- **加载态**：链接校验期间的整页骨架屏（与提交页共用同一加载态，校验完成后才决定渲染哪一页）
- **错误态**：校验请求网络异常 / 服务端错误时展示错误插图 + 「重新加载」按钮；**与四类失效形态严格区分**，不得把网络错误误报为链接失效

| 选图渠道 | **仅相册选择，不提供拍照**（不调用相机、不申请相机权限），与 App 端可拍照的口径区分 |
| 图片不本地缓存 | 已选图片仅在本次访问内有效，不在浏览器本地缓存，与表单不缓存口径一致 |
| SLA 与催办 | 审批超时催办 / 升级 / 目标日期预警均为**内部机制**，公开 H5 不展示任何时效信息，也不向外部提交人发任何催办类通知（business-rule §8.5 / §10） |
