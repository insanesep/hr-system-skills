# 需求管理 · App 端 UI 描述

> 覆盖 App 员工端 3 页与公开 H5 3 页（外部人在移动端浏览器免登录访问），页面元素与交互声明以本文件为准，原型见 `assets/app/`。视觉润色、Token 纪律、触控尺寸、三态、组件白名单等硬约束见 [page-gen.prompt.md](../../../../busyming-skills-design/.skills/page-blueprint/prompts/page-gen.prompt.md)【2. 硬约束】，交互三维度按 [interaction-spec.md](../../../../busyming-skills-common/workflow/PM/references/interaction-spec.md) 填写。业务规则只引用、不复述，规则文件入口见 [SKILL.md](../SKILL.md) Prerequisites。

## 全局约定

- 状态标签、优先级 / 业务线 / 产品线 Tag、提交来源标签与排期开发状态的文案与语义同 [web-ui.md 全局约定](web-ui.md#全局约定)；有点推荐需求不渲染业务线 Tag
- 瞬时态不展示为独立状态与独立时间线节点
- 枚举取值以 [data.md §12](data.md#12-枚举) 为准；提交来源在 App 端只展示、不可筛选
- 按钮显隐以服务端返回的可执行操作为准，页面不自行推导角色；页面不触发推送，企微消息由服务端在操作成功后发出

## App 员工端

### 端能力边界

App 端开放与仅 Web 可用的能力见 [permission-rules.md §4](permission-rules.md#4-权限约束)；以下为 App 端的页面表现：

- **外链**：App 无「外链管理」入口，详情页外部提交区块不提供跳外链台账的链接
- **外部提交单**：全程只读 + 可审批，编辑、撤回、重新提交、删除一律不渲染（[state-machine.md §6](state-machine.md#6-外部提交单差异)）；外部单只出现在「待我审批」「已完成」与详情 Deep-link，不进「我提交的」
- **草稿**：不提供暂存草稿与草稿编辑；「我提交的」可查看 Web 端创建的草稿，详情页不渲染编辑入口，需到 Web 端编辑
- **附件**：仅开放图片上传（相册 / 拍照），文档与视频只展示文件行并提供下载，不提供在线预览；图片选完即上传，未提交就离开时已上传图片不归属任何需求，由存储侧自动清理；不渲染任何审核角标；删除附件与审批中追加均不在 App 端提供，详情页附件区块只读（[other-rule-attachment.md](other-rule-attachment.md)）
- **预览与下载**：一律使用短时效签名链接，不缓存、不复用、不分享，页面不展示存储永久直链
- **SLA**：SLA 配置与仪表盘不在 App 端提供；App 只承接催办通知的 Deep-link 直达详情页，不展示滞留时长与超时阈值

| 附件类型 | 图标 | 扩展名 | App 端能力 |
|---------|------|-------|-----------|
| 图片 | 图片图标 | jpg / jpeg / png / webp / gif | 可上传（相册 / 拍照）、缩略图网格展示、全屏预览、长按保存 |
| 文档 | 文档图标 | pdf / docx / xlsx / pptx / txt | 不可上传；文件行只读 +「下载」（调起系统能力打开） |
| 视频 | 视频图标 | mp4 / mov | 不可上传；文件行只读 +「下载」 |

### 我的需求列表

- **页面路径**：App 内页面，由菜单 `M:RD:REQUIREMENT` 映射进入，无路由参数；具体路由以 App 菜单路由映射为准
- **权限编码**：
  - 菜单：`M:RD:REQUIREMENT`
  - 独占：`M:RD:REQUIREMENT_M`
- **导航方式**：Push（从工作台入口进入）
- **页面类型**：`list`
- **区块职责**：
  - 顶部导航栏：返回 + 标题「需求管理」+ 右侧「提交」文字按钮（具菜单权限时）
  - 顶部 Tab（3 个，吸顶）：
    - **我提交的**：本人提交的全部需求（含草稿）
    - **待我审批**：当前登录人处于快照当前级次的待审需求（含外部单）；Tab 右上角数字角标（> 99 显示 `99+`，为 0 时不展示）
    - **已完成**：已关联排期 + 已驳回的终态需求（按角色可见范围取数，含外部单）
    - 不提供「外部提交」视角，也不提供产品线 / 提交来源筛选器
  - 主体区：卡片列表，每张卡片自上而下：
    - 第一行：标题（最多 2 行，超长省略）；外部单标题前加「外部提交」Tag
    - 第二行：产品线 Tag + 业务线 Tag（有点推荐不渲染）+ 优先级 Tag + 状态标签
    - 第三行：需求编号 + 提交时间（从未提交的草稿展示「未提交」）
    - 「待我审批」卡片额外展示：提交人 + 等待时长（如「已等待 2 天」）；外部单提交人取外部提交人手填姓名，后跟灰字手填部门
    - 整卡可点击 → Push 需求详情
  - 交互：下拉刷新 / 上滑加载更多（每页 20 条）
- **布局引用**：`参见原型 assets/app/requirement-list.html`（整页范例 `busyming-skills-design/mobile/templates/list.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/list-page.tsx.tpl`）

#### 导航关系

- 来源页：工作台「设置」分组下的「需求管理」入口
- 去向页：需求详情（点卡片）、需求提交（点右上角「提交」）
- 返回行为：导航栏返回按钮 Pop 回工作台
- 手势返回：允许（Pop 回工作台）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| Tab 切换 | 点击 Tab | 否 | 列表骨架屏（3 张占位卡片） | 列表按视角刷新，页码重置为 1 → 停留 | AcToast error「加载失败」+ 保留原 Tab，列表区「点击重试」 |
| 下拉刷新 | 下拉手势 | 否 | 顶部刷新指示器 | 列表刷新 + 待我审批角标同步更新 → 停留 | AcToast error「刷新失败，请重试」，可再次下拉 |
| 上滑加载更多 | 滚动到底部且有下一页 | 否 | 底部加载指示器 | 追加数据；无更多时展示「没有更多了」→ 停留 | 底部 inline「加载失败，点击重试」 |

#### 列表三态

- **空态**：我提交的「你还没有提交过需求」+「立即提交」；待我审批「暂无待你审批的需求」；已完成「暂无已完成的需求」
- **加载态**：卡片骨架屏（3 张占位卡片）
- **错误态**：错误插图 +「点击重试」

#### 交互约束

- 或签同级他人先处理后，本人「待我审批」列表项自动消失，角标同步减一
- 从详情页审批成功 Pop 回列表时必须刷新「待我审批」角标

### 需求详情

- **页面路径**：App 内页面，以需求标识为参数直达，支持企微消息 Deep-link；具体路由以 App 菜单路由映射为准
- **权限编码**：
  - 菜单：`M:RD:REQUIREMENT`
  - 独占：`M:RD:REQUIREMENT_M`
- **导航方式**：Push
- **页面类型**：`detail`
- **区块职责**（自上而下）：
  - 顶部导航栏：返回 + 标题「需求详情」
  - 需求信息卡：需求编号 + 状态标签（外部单另加「外部提交」Tag）/ 标题 / 描述（纯文本，超过 5 行折叠「展开全部」）/ 提交对象（产品经理姓名；外部单 L3 通过前展示灰字「待产品确认通过后归集」）/ 产品线 / 业务线（有点推荐不渲染该行）/ 优先级 / 需求类型 / 目标完成日期 / 提交人 / 提交时间
    - 已驳回时卡片顶部红色提示条展示最近一次驳回人与驳回意见全文；外部单追加「外部提交单驳回即终态，不可重新提交」
  - 外部提交卡（仅外部单，置于需求信息卡下方）：标题「外部提交信息」+「外部提交」Tag；只读信息行：提交人姓名 / 所属部门（后跟灰字「手填，未关联组织架构」）/ 手机号（支持长按复制或点击拨号，仅供内部人员人工回访）/ 提交时间 / 邀约人姓名；不提供外链台账跳转、转内部单、代撤回
  - 附件卡（置于外部提交卡下方）：
    - 标题「附件（N）」；N = 0 时展示灰字「无附件」占位行，不隐藏卡片
    - 图片组：缩略图网格（每行 3 张、正方形裁切），按上传时间正序；超过 9 张时展示前 9 张，末位叠加「+N」，点击展开全部；缩略图右下角小字展示上传来源，外部单图片打「外部上传」角标
    - 点击缩略图 → 全屏图片浏览器（左右滑动切图、双指缩放、顶部「M/N」计数、点击空白或下滑关闭）
    - 长按缩略图或全屏图 → 底部操作面板「保存到相册」/「查看大图」/「取消」；首次保存申请相册写入权限，被拒时提示「请在系统设置中开启相册权限」
    - 文档 / 视频组：纵向文件行（类型图标 + 文件名中间省略保留扩展名 + 文件大小 + 右侧「下载」）
    - 🚨 卡内不渲染任何上传、追加、删除按钮
  - 审批时间线（纵向卡片式）：按审批链快照渲染 1~3 个节点，级次由提交时命中的链决定
    - 每节点：级次名称 / 角色 / 审批人（或签未动作时展示「张三、李四（或签）」，已动作展示实际动作人）/ 状态 / 审批意见 / 操作时间
    - 当前节点高亮并带「审批中」角标；已通过、未开始、已驳回按状态语义区分；自动跳过节点展示「已自动跳过」+ 说明，外部单不会出现自动跳过
    - 内部单产品确认节点的审批人即提交对象
    - 驳回重提按轮次分组：默认展示最新一轮，历史轮次折叠为「查看第 N 轮审批记录」；外部单只有一轮，不渲染分组入口
  - AI 方案确认卡（置于审批时间线下方、排期关联卡上方）：
    - 🚨 仅当前级次审批人与管理员渲染，提交人与其他角色一律不渲染，可见性由服务端收口（[other-rule-ai-plan.md §1](other-rule-ai-plan.md#1-定位与红线)）；无方案记录时不渲染
    - 标题「AI 方案确认」+ 状态标签（生成中 / 待确认 / 已确认 / 已作废 / 生成失败）+ 版本「V{N}」
    - 生成中：卡内加载占位 + 文案「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批」；每 5 秒刷新一次状态，离开页面即停止
    - 待确认：三段式确认摘要（① 业务诉求 ② 方案完成内容 ③ 信息缺口与建议补充），超过 8 行折叠「展开全部」；「方案全文（七步分析）」点击 Push 到只读子页
    - 生成失败：红色提示条「AI 方案生成失败：{失败原因}」+「重新生成」+ 旁注「不影响您人工审批」
    - 已作废：卡片置灰只读 +「该方案已作废（需求已被处理），仅供回顾」，不渲染操作按钮
    - 卡片底部操作（仅待确认且当前用户为当前级次审批人）：「确认并通过」（全宽主按钮）/「请求补充材料」（次按钮）/「重新生成」（文字按钮）
  - 排期关联卡（只读）：
    - 已关联：卡片编号 + 开发状态标签 + 排期日期 + 开发人
    - 未关联：灰字「待关联排期」（App 不提供关联与解除入口，需到 Web 端操作）
    - 卡片已失效：黄色提示条「关联卡片已失效，请到 Web 端重新关联」
    - 缺陷修复单替换为黑灯工厂工单区：工单号 + 工单状态 + 负责人（只读回传，[business-rule.md §2](business-rule.md#2-缺陷修复需求分流)）
  - 底部操作栏（吸底，位于安全区内）：
    - 当前审批人：通过（主按钮）/ 驳回（危险次按钮），左右等宽
    - 提交人（已驳回）：重新提交（全宽主按钮）
    - 提交人（已提交 / 业务线审批中）：撤回（全宽次按钮）
    - 外部单只渲染审批类按钮；非审批人进入外部单详情时不渲染操作栏；无可执行操作时不渲染操作栏并回收底部内边距
- **布局引用**：`参见原型 assets/app/requirement-detail.html`（整页范例 `busyming-skills-design/mobile/templates/detail.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/detail-page.tsx.tpl`）

#### 导航关系

- 来源页：我的需求列表（点卡片）；企微个人消息与业务群消息内详情链接（Deep-link）
- 去向页：需求提交（已驳回时点「重新提交」，原内容预填）；方案全文只读子页（AI 方案卡内）；撤回成功后 Pop 回我的需求列表
- 返回行为：导航栏返回按钮 Pop 回我的需求列表，并触发列表刷新与角标更新；Deep-link 进入时返回至工作台
- 手势返回：允许；半屏输入打开时先关闭半屏，不直接 Pop

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|

| 预览图片 | 点击附件区缩略图 | 否 | 全屏浏览器内图片加载占位 | 打开全屏图片浏览器，无提示 → 停留 | 浏览器内 inline「图片加载失败，点击重试」，不关闭浏览器 |

| 下载文档 / 视频 | 点击文件行「下载」 | 否 | 行内进度指示器 | 下载完成后调起系统能力打开，无提示 → 停留 | AcToast error「下载失败，请重试」（签名链接失效时自动重新签发一次） |

- 「重新提交」为跳转：Push 到需求提交页并预填原内容，在提交页校验后提交

#### 表单校验

## 公开 H5

外部人在移动端浏览器凭外链免登录访问的单向采集端，仅服务有点推荐产品线；外链形态、字段边界、防刷与单向收口规则见 [other-rule-public-link.md](other-rule-public-link.md)，H5 附件规则见 [other-rule-attachment.md §5](other-rule-attachment.md#5-h5-附件规则)。

### H5 端能力边界

- **仅 3 个页面**：需求提交页 / 提交成功页 / 链接失效页
- **完全单向收口**：不提供进度查询、撤回、修改、草稿，不发任何短信或通知
- **无登录态**：不渲染侧边菜单、面包屑、顶部用户信息、退出登录等任何管理后台外壳，页面不经登录拦截
- **唯一入口**：凭内部人发放的专属链接访问；链接只携带 token，邀约信息全部由服务端按链接识别
- **三页共用同一专属链接**：按链接校验结果与提交结果在页内切换渲染，不设独立访问地址（防止外部人直达成功页或失效页伪造凭证）
- **不展示任何内部信息**：审批链、审批人姓名、业务线枚举、其他需求数据、内部组织架构一律不出现在页面中（邀约对象备注除外）
- **不展示状态、业务线与优先级**：外部人只在提交成功页看到需求编号；唯一对外可见的枚举是需求类型（5 类，不出现 `*`）

### 链接校验流程

进页第一件事是校验链接，校验结果决定渲染哪个页面，外部人无法绕过：

| 校验结果 | 渲染页面 | 说明 |
|---------|---------|------|
| 可用（待使用且未过期、未达提交上限） | 需求提交页 | 同时回填邀约对象备注与需求类型默认值 |
| 达提交上限（已提交） | 链接失效页 · 已提交 | 携带已产生的需求编号 |
| 已过期 | 链接失效页 · 已过期 | — |
| 已撤销 | 链接失效页 · 已撤销 | 不展示撤销原因 |
| 凭证缺失 / 非法 / 查不到 | 链接失效页 · 链接无效 | 与「已撤销」返回时延一致（防枚举） |

- 链接缺少凭证参数时不发起校验，直接渲染「链接无效」
- 校验期间展示整页骨架屏，不闪现表单
- 校验请求失败（网络异常 / 服务端错误）不等于失效：展示整页错误态 +「重新加载」，与失效页文案严格区分

### H5 页面间导航

| 来源 | 去向 | 触发 | 导航方式 |
|------|------|------|---------|
| 外部渠道（微信 / 企微消息、二维码扫码） | 需求提交页 | 打开专属链接且校验通过 | 浏览器直接打开 |
| 外部渠道（同上） | 链接失效页 | 打开专属链接且校验不通过 | 浏览器直接打开（同一链接内渲染切换） |
| 需求提交页 | 提交成功页 | 预览确认弹层内点「确认提交」且服务端返回成功 | 页面内容整体替换（Replace，不入历史栈） |
| 需求提交页 | 链接失效页 | 提交时服务端返回链接已失效或已达上限 | 页面内容整体替换（Replace） |

- 提交成功页与链接失效页均为终点页：不提供返回按钮与再次提交入口；浏览器后退回到提交页时重新走链接校验（此时已提交，落到失效页 · 已提交）

### 需求提交页

- **页面路径**：外链专属链接（唯一参数为 token，由外链管理生成）；与提交成功页、链接失效页共用同一地址
- **权限编码**：无（免登录，鉴权凭据即专属链接本身，准入见 [other-rule-public-link.md §4](other-rule-public-link.md#4-安全与防刷)）
- **导航方式**：浏览器直接打开；提交后页内 Replace
- **页面类型**：`form`
- **页面定位**：外部人一次性填写并提交需求——一屏回答「我是谁、我要什么」
- **区块职责**：
  - 顶部说明区（非导航栏，无返回按钮）：主标题「有点推荐 - 需求提交」；副标题灰字「本表单由 {邀约对象备注} 的邀约链接进入，提交后由内部团队评估处理」；常驻提示条「本链接**仅可提交 {N} 次**，提交后无法修改或撤回，请确认内容后再提交」（N 取链接提交次数上限）
  - 需求信息组：需求标题（单行）/ 需求描述（多行，实时字数「N/2000」，下方灰字「请说明你遇到的问题、期望的效果，以及大致的使用场景；描述越具体越容易被采纳」）/ 需求类型（选择器，默认值由链接携带）
  - 图片组（需求信息组下方）：标题「相关图片（N/3）」+ 灰字「选填」；引导文案「可上传问题截图或现场照片帮助内部团队理解；最多 3 张，单张不超过 5MB」；横向缩略图行（已选图片 + 右上角删除叉标，末位「+」添加卡，达 3 张时置灰并提示「最多只能上传 3 张图片」）
    - 🚨 点「+」直接拉起系统相册（支持多选），不弹选源面板、不调用相机、不申请相机权限
    - 上传中缩略图叠加半透明层 + 环形进度；单张失败置红边 + 中心感叹号，点击单张重试
    - 分组底部实时展示「已选 N 张，共 X.X MB / 上限 15MB」，超限时拒收最后一张并提示「本次提交图片总大小不得超过 15MB」
    - 页面不展示任何审核状态，外部人只看到「上传成功」
  - 提交人信息组：姓名（可用邀约对象备注预填，允许修改）/ 所属部门（自由文本，下方灰字「填写你所在的公司或部门名称即可」）/ 手机号（唤起数字键盘，下方灰字「仅供内部团队必要时联系你，不会收到任何短信」）
  - 验证组：图形验证码输入框 + 右侧验证码图片（点击图片刷新）
  - 底部固定操作栏（安全区内）：「提交需求」全宽主按钮；不提供暂存草稿与重置表单
  - 页脚灰字：「本页面为一次性邀约链接，请勿转发他人」
  - **不出现的元素**：文档上传、视频上传、拍照入口、业务线、优先级、目标完成日期、登录 / 注册入口、客服入口、进度查询入口
- **布局引用**：`参见原型 assets/app/requirement-public-submit.html`（整页范例 `busyming-skills-design/mobile/templates/form.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/form-grouped.tsx.tpl`）

#### 导航关系

- 来源页：外部渠道链接或二维码扫码（无站内来源）
- 去向页：提交成功页（提交成功）；链接失效页（链接在提交瞬间失效）
- 返回行为：无返回按钮；浏览器后退即离开本页，不做拦截
- 手势返回：允许（等同浏览器后退离开本页）

#### 提交前预览确认弹层

因提交后不可重填也不可修改，本弹层为**强制环节**，不可跳过、不提供「不再提示」。

- 形式：底部半屏弹层（占屏约 70%，内容超出可滚动）
- 标题「请确认提交内容」+ 红色小字「提交后**无法修改、无法撤回**，本链接也将失效」
- 内容区以只读信息行完整回显：需求标题 / 需求描述（全文不折叠）/ 需求类型 / 姓名 / 所属部门 / 手机号
- 已选图片时在需求类型下方追加「相关图片（N 张）」行，横向只读缩略图（不带删除叉标，可点击看大图）；未选图片时不渲染该行；存在上传失败图片时红字提示「有 N 张图片上传失败，确认提交将不包含这些图片」，仍可确认提交
- 底部按钮：左「返回修改」（次按钮）/ 右「确认提交」（主按钮），等宽
- 关闭方式：点击遮罩、下拉手势、「返回修改」三者一致，回到表单且不消耗提交次数
- 「确认提交」点击后立即 disabled 直到服务端返回，防止重复提交耗尽唯一次数

#### 表单校验

- 初态：需求类型预填链接默认值（可改）；姓名以邀约对象备注预填（可清空改写）；部门、手机号、标题、描述为空；图片为空（仅展示「+」添加卡与限制说明）；进页即请求一张图形验证码（5 分钟有效）；本页只有新建形态，不回填历史提交内容

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 需求标题 | 是 | 1–128 字 | blur | 「请输入需求标题（不超过 128 字）」 | 否 |
| 需求描述 | 是 | 20–2000 字，实时字数提示 | blur | 「请填写需求描述，不少于 20 字」 | 否 |
| 需求类型 | 是 | 选择器（新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成），默认值由链接携带 | change | 「请选择需求类型」 | 否 |
| 姓名 | 是 | 1–64 字，去首尾空格后非空 | blur | 「请填写你的姓名」 | 否 |
| 所属部门 | 是 | 1–128 字，自由文本，不做组织架构匹配、不提供下拉联想 | blur | 「请填写你所在的公司或部门」 | 否 |
| 手机号 | 是 | 11 位大陆手机号格式，仅格式校验 | blur | 「请填写正确的 11 位手机号」 | 否 |
| 图形验证码 | 是 | 4 位，大小写不敏感，服务端校验，一次性消费 | 提交时 | 「请输入验证码」/「验证码错误，请重新输入」 | 是（提交时服务端校验） |
| 相关图片 | 否 | 类型、单张大小、张数与总大小见 [other-rule-attachment.md §5](other-rule-attachment.md#5-h5-附件规则)；仅相册选图 | 选择后立即 | 「图片最多 3 张」/「单张图片不得超过 5MB」/「本次提交图片总大小不得超过 15MB」/「不支持的图片格式」 | 是（经带链接校验的上传通道上传） |

- 提交成功跳转：页面内容整体替换为提交成功页，不做延迟、不用提示中转（避免用户误关页面而看不到需求编号）
- 提交失败展示：按上方失败分流处理，字段值保留，仅验证码按失败原因清空；提交时全表单校验，首个错误字段滚动至可视区并聚焦
- 脏数据离开：本场景不需要（无登录态、无草稿，拦截对外部人无意义且干扰体验）
- 键盘避让：描述与手机号输入聚焦时自动滚动至可视区，底部提交按钮随键盘上移
- SafeArea：底部提交按钮避开屏幕底部安全区

#### 交互约束

- 提交防重复保护不可省：按钮 disabled + 服务端对单链接提交计数做并发互斥
- 请求超时不解锁按钮，提示「提交处理中，请勿重复点击，请稍后重新打开链接确认结果」
- 页面不接入前端埋点以外的第三方脚本，不在浏览器本地缓存表单内容与已选图片（避免公用设备泄露填写人信息）；刷新页面后需重新选图
- 🚨 图片不阻塞提交：图片为选填；仅当存在上传中的图片时提交按钮置灰 + 下方灰字「图片上传中，请稍等」
- 图片上传必须经链接校验，与提交共用同一链接校验与 IP 限流计数；链接失效时上传直接报错，但不因上传失败就把页面切到失效页（仅提交返回失效时才整页切换）

### 链接失效页

- **页面路径**：与需求提交页同一专属链接内渲染切换，无独立访问地址
- **权限编码**：无（免登录）
- **导航方式**：浏览器直接打开或页内 Replace
- **页面类型**：`detail`
- **页面定位**：告诉外部人「这个链接现在不能填了」，并把出路统一收敛到「联系邀约人」
- **区块职责**：
  - 状态插图（已提交为成功系插图，其余为失效系插图）+ 主标题 + 说明文案（按形态差异化，见下表）
  - 统一引导文案（灰色）：「如仍需提交需求，请联系向你发送链接的邀约人重新获取」
  - 「已提交」形态额外展示需求编号（可复制），其余形态不展示任何编号
  - **不出现的元素**：重试提交、返回、任何内部人员姓名 / 手机号 / 组织信息、撤销原因原文

| 形态 | 触发条件 | 主标题 | 说明文案 | 额外内容 |
|------|---------|-------|---------|---------|
| 已提交 | 链接已达提交上限 | 该链接已完成提交 | 你已通过本链接提交过需求，每个链接仅可提交 {提交次数上限} 次 | 需求编号（可复制） |
| 已过期 | 链接已过期 | 链接已过期 | 该邀约链接已超过有效期，无法继续提交 | 无（不展示过期时间） |
| 已撤销 | 链接已撤销 | 链接已失效 | 该邀约链接已被发放人收回，无法继续提交 | 无（不展示撤销原因与撤销人） |
| 链接无效 | 凭证缺失 / 格式非法 / 查无此链接 | 链接无效 | 链接不完整或已失效，请确认是否从邀约人处完整复制 | 无 |

- **布局引用**：`参见原型 assets/app/requirement-public-result.html`（失效态，与成功态同一原型文件内切换；整页范例与 DOM 依据同提交成功页）

#### 页面三态

- **空态**：不适用（本页即结果态）
- **加载态**：链接校验期间的整页骨架屏（与提交页共用，校验完成后才决定渲染哪一页）
- **错误态**：校验请求网络异常或服务端错误时展示错误插图 +「重新加载」；与四类失效形态严格区分，不得把网络错误误报为链接失效
