# 发布管理

> 对应脑图「发布管理」节点：根据代码仓提交自动生成卡片。

面向 PM 与研发的发布跟踪工具：代码仓的发版类提交（发版分支合并、生产发布执行回流）自动生成发布卡片，PM 在月历上安排发版日并跟踪发布执行状态，形成「实施完成 → 待发布 → 已发布」的最后一棒闭环。

## 服务对象与端

- **服务对象**：PM（发版安排与跟踪）、研发（发布执行与回执）
- **仅 Web 端**：与功能排期/实施管理一致的桌面排期工具形态

## 产品背景

功能排期回答「什么时候开发完」，实施管理回答「什么时候验证完」，但「什么时候上生产、这次上了什么」仍靠发布平台记录与口头同步。本模块把发布事实沉淀为卡片：提交即出卡、拖台即排期（发版日）、执行可回执。

## 核心链路

1. **提交即出卡**：监听代码仓发版类事件（发版分支合并入主干、发版 tag、生产发布单执行回流）自动生成发布卡片——标题 = 版本/发布单概括，内容 = 本次发布包含的变更摘要；同一来源事件幂等不重复生成
2. **拖拽即排期**：待发布池卡片拖到月历发版日；发版日标识与功能排期的发版日标记同源共享
3. **执行即回执**：发布执行（对接发布平台或人工确认）切换状态并写入执行人、执行时间与发布单链接

## 状态机

- `PENDING（待发布）` / `RELEASING（发布中）` / `RELEASED（已发布）`
- 发布中 → 已发布：完成回执（发布单/版本号关联，选填）；失败可回退待发布（二次确认）
- 已发布卡锁定不可拖拽；延期为前端渲染态（排期日已过仍未发布）

## 关键业务规则

- 卡片编号 `REL-{YYYYMMDD}-{NNN}`，家族统一编号规则，生成后不可变、不回收
- 每次发布卡片可关联其覆盖的功能/实施卡集合，用于回答「这次发了什么」；关联为单向引用，不回写上游卡片
- 操作流水只增不删：创建/改期/状态变更/删除均留痕
- 排期约束与家族一致：不排早于当日、已发布锁定、删除需二次确认

## 页面功能概览（仅列职责，UI 风格与原型暂不产出）

| 区域 | 职责 |
| ---- | ---- |
| 待发布池 | 未排期发布卡（创建时间倒序） |
| 月历区 | 发版日视角的发布卡排期与改期，今日高亮，发版日标识 |
| 卡片抽屉 | 标题/内容/变更摘要、关联功能/实施卡清单（只读）、状态切换、发布单回执、操作流水 |

## 待定口径（评审清单）

- 出卡触发源：发版分支合并 / 发版 tag / 发布平台执行回流，三者取其一还是组合
- 发布卡与功能/实施卡的关联粒度：按功能聚合还是按发布单聚合
- 是否回流状态到功能排期/实施管理（家族单向引用原则下默认不回流）
- 与功能排期「发版日标记」的合并/分工：标记下沉为本模块能力，功能排期只读展示

## 关联模块

| 模块 | 关系 |
| ---- | ---- |
| `排期管理/功能排期` | 发版日标记同源；发布卡内容的部分变更摘要来源 |
| `排期管理/实施管理` | 实施完成的功能构成待发布范围 |
