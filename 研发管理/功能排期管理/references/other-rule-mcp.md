# 功能排期 · MCP 能力

> 功能排期全部能力经 DevHub MCP 开放的规则真源：能力分组、工具清单、权限对应与调用约束。业务规则以 [business-rule.md](business-rule.md)、[state-machine.md](state-machine.md)、[field-rules.md](field-rules.md) 为准，MCP 是与 PC 并列的入口，不另设业务规则；令牌生成、能力勾选与调用审计见 [MCP接入管理](../../../平台能力/SKILL.md)。

## 1. 定位

- 产品与研发的 agent 经 MCP 直接完成查询、排期、分配、需求澄清与卡片维护，与 PC 端同权同规则
- 以令牌持有人身份执行：权限按 [permission-rules.md §1](permission-rules.md#1-权限编码) 同一编码校验；流水、澄清记录与通知中的操作人为令牌持有人，澄清记录与流水注明渠道为 MCP
- 每次调用留存审计（持有人、工具、目标卡片、结果与原因），审计查看见 MCP接入管理

## 2. 能力分组

令牌按分组勾选工具：分组只决定令牌能看到哪些工具，是否放行仍按持有人的功能排期权限判定。

| 分组 | 类型 | 覆盖能力 | 适用场景 |
|------|------|---------|---------|
| 研发排期卡片查看与分配 | 只读为主，含分配与排期 | 查看项目与卡片、按视图查卡、卡片详情与澄清记录、检索 commit、分配或领取、排期 | 自动分配、研发开工、日常查询 |
| 研发排期需求澄清 | 写入 | 转待澄清、完成澄清、撤回澄清 | 研发识别出需求问题、产品处理澄清 |
| 研发排期卡片维护 | 写入，含破坏性操作 | 新建、编辑、移回待排期、领取与取消领取、标记完成、回退、完成 commit、非需求改动、合并与解散、删除、发版日 | 产品或研发负责人经 agent 维护排期 |

- 「研发排期卡片查看与分配」只追加只读工具，已勾选该分组的令牌不会因此获得新的写入能力；写入工具需在令牌中显式勾选对应分组

## 4. 调用约束

- **参数严格**：未声明的参数、格式不符的卡片编号与日期一律拒绝，不做猜测补全
- **规则一致**：状态流转与守卫按 state-machine.md 执行，不满足时返回拒绝原因，卡片不变；卡片已处于目标状态时同样返回拒绝原因，分配给已在开发的同一开发人时返回已分配
- **只分配已排期卡**：分配工具拒绝未排期卡片；排期工具仅在研发或产品本人明确要求为某张卡排期时调用，自动分配不得先排期再分配
- **破坏性操作**：移入非需求改动、解散合并、删除与停用项目在客户端调用前须经使用人确认
- **轮次绑定**：卡片详情与按视图查卡返回的澄清均带澄清记录标识；基于已查看的问题提交完成或撤回操作时须携带该标识，不省略；明确要求处理调用当时最新轮次的操作可不指定标识，服务在执行时读取并绑定当前轮次。携带标识时只处理这一轮，该轮已被处理或卡片已重新发起澄清时返回「澄清已变化」，需重新查询后再操作；撤回时是否为发起人按实际撤回的这一轮判定
- **已并入的编号**：查询已在后续完成澄清中并入新合并卡的中间合并卡编号时，卡片详情返回最新合并卡并注明原编号；写入工具使用此类编号时拒绝并提示新编号
- **返回内容**：卡片附 PC 端卡片详情链接；列表类工具有返回上限，超出时注明已截断
- **命中 commit**：新建卡片、完成澄清、标记完成与关联完成 commit 接受 commit 标识，由服务端到云效核验并回填提交说明、作者与提交时间，未命中拒绝；完成commit须在该卡片关联项目已确认的执行映射范围内，见 [field-rules.md §8](field-rules.md#8-完成-commit-回执)

## 5. 需求澄清的 agent 约定

- **提交前确认**：agent 识别出需求问题后，先把问题清单交研发本人确认，确认后再调用转待澄清，问题写法见 field-rules.md §10
- **完成澄清**：产品修订需求文档并提交后，以修订 commit 标识调用完成澄清，规则见 [business-rule.md §11.3](business-rule.md#113-完成澄清与自动合并)；结果返回新合并卡编号与澄清记录
- **编号续接**：卡片详情与按视图查卡的结果注明「当前澄清」与「澄清来源」，澄清来源由早到晚列出全部前序卡片编号（含已并入的中间合并卡）；agent 以澄清来源把原卡与新合并卡对应起来，续接原有工作，不按新编号重复开工
