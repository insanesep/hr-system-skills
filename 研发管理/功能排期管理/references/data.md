# 功能排期 · 数据定义

> 面向产品视角定义本模块实体、字段语义与实体关系；表结构以代码仓为准，不在此描述。字段的默认值与校验见 [field-rules.md](field-rules.md)，状态枚举见 [state-machine.md §1](state-machine.md#1-状态枚举)。

## 1. 实体关系

| 实体 | 关系 | 说明 |
|------|------|------|
| 排期卡片 → 卡片操作流水 | 1:N | 每次状态、排期、字段或存在性变更追加一条流水 |
| 排期卡片 → 完成 commit 回执 | 1:N | 开发完成时可关联多条跨仓 commit |
| 合并卡 → 合并明细 → 子卡 | 1:N，明细与子卡 1:1 | 合并卡与子卡均为排期卡片；嵌套合并见 business-rule.md §8.5 |
| 排期卡片 → 代码仓库 | N:1 | 按源仓引用，支持云效与通用 Git，源仓口径见 business-rule.md §1.1 |
| 排期卡片 → 项目 | N:0..1（查询投影） | 按源仓匹配启用项目的 harness 工程仓；合并卡仅在全部子卡同属一个项目时归属，不保存卡片项目关联事实 |
| 需求单 → 排期卡片 | N:1 | 关联关系由需求管理维护，本模块只读，见 [需求管理 business-rule §5](../../../需求管理/references/business-rule.md#5-排期关联规则) |
| 排期卡片 → 澄清记录 | 1:N | 每次转待澄清生成一条；同一卡片同一时刻至多一条待澄清，见 [business-rule.md §11](business-rule.md#11-需求澄清) |
| 澄清记录 → 修订卡片 | 1:N | 完成澄清时并入的修订卡 |
| 澄清记录 → 合并后卡片 | N:1 | 完成澄清生成的合并卡；同一合并卡可承接多轮澄清 |

## 2. 排期卡片

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 卡片编号 | 卡片业务编号 | 文本 | 是 | 见 field-rules.md §1 |
| 标题 | 卡片标题 | 文本 | 是 | ≤30 字符，见 field-rules.md §2 |
| 内容 | commit message 原文或合并卡子卡清单 | 长文本 | 否 | 见 field-rules.md §2 |
| 负责人 | 卡片负责人，界面以「提交人」呈现 | 人员 | 是 | 账号未匹配时仅保留姓名，见 field-rules.md §4 |
| 状态 | 持久化状态 | 枚举 | 是 | 取值与流转见 state-machine.md §1、§2 |
| 排期日 | 单日排期锚点 | 日期 | 否 | 为空表示在待排期池，见 field-rules.md §5 |
| 排期开始日、排期结束日 | 排期区间 | 日期 | 否 | 与排期日联动 |
| 需求性质 | 业务功能或技术支持 | 枚举 | 是 | 默认业务功能，见 field-rules.md §6 |
| 业务对接人 | 业务侧对接人姓名 | 文本 | 否 | ≤64 字，选填；被需求单关联时空值展示提交人兜底，见 field-rules.md §7 |
| 开发人 | 领取开发的研发 | 人员 | 否 | 写入路径见 state-machine.md §2 |
| 领取时间 | 领取开发的时间 | 时间 | 否 | 写入路径见 state-machine.md §2 |
| 完成时间 | 标记完成的时间 | 时间 | 否 | 写入路径见 state-machine.md §2 |
| 源仓 | 出卡来源代码仓 | 引用 | 是 | 合并卡取值见 business-rule.md §8.3 |
| 源 commit | 出卡来源 commit | 文本 | 是 | 唯一性见 business-rule.md §1.2，合并卡取值见 §8.3 |
| 提交时间 | 源 commit 的提交时间 | 时间 | 是 | 自动采集与手动新建出卡时均由源 commit 回填；合并卡为空 |
| 来源模块 | commit 头部解析出的模块 | 文本 | 是 | 解析不到时为 `MISC`，见 field-rules.md §3 |
| 所属项目 | 源仓匹配启用项目的归集视角 | 引用（查询投影） | 否 | 按 business-rule.md §9 解析唯一项目；合并卡全部子卡同属该项目才归属，否则显示「未归属项目」；不落卡片字段 |
| 项目标签样式 | 所属项目名称与固定标识色 | 展示投影 | 是 | 读取项目管理的名称与创建顺序固定配色，未归属为灰色，见 business-rule.md §9 |
| 当前澄清 | 待澄清卡的未处理澄清记录 | 引用（查询投影） | 否 | 仅状态为待澄清时有值，含问题、发起人、发起时间与澄清前状态，见 §8。不落卡片表 |
| 澄清来源 | 由完成澄清生成的合并卡所承接的原卡 | 引用列表（查询投影） | 否 | 仅完成澄清生成的合并卡有值，见 §8。不落卡片表 |
| 合并标识 | 是否为合并卡 | 布尔 | 是 | 默认否 |
| 父合并卡 | 子卡所属的合并卡编号 | 引用 | 否 | 仅子卡有值 |
| 子卡数 | 合并卡下的子卡数量 | 数量 | 否 | 仅合并卡有值 |
| 硬件管理标记 | 卡片附带的标记 | 标记 | 否 | 合并卡取值见 business-rule.md §8.3 |
| 创建时间 | 源 commit 采集入库时间 | 时间 | 是 | 展示精确到分钟，只读 |
| 删除标记 | 软删除标识 | 布尔 | 是 | 见 business-rule.md §1.2 |
| 最后操作人、最后操作时间 | 最近一次变更的审计信息 | 人员、时间 | 是 | 删除与回退同样记录 |

- 「所属项目」「项目标签样式」「当前澄清」「澄清来源」均为查询或展示投影；项目映射变更重新计算归属、名称与配色，不保存卡片与项目的事实关联，不覆盖源仓、源 commit、状态、排期、回执和既有流水。

## 3. 完成 commit 回执

|--------|----------|------|------|----------|
| 仓库 | commit 所在代码仓 | 引用 | 是 | 新增关联时属于卡片当前归属项目的代码服务仓，按 field-rules.md §8 核验；映射变更不改写已有回执 |

| 提交时间 | commit 提交时间 | 时间 | 是 | 由选中项回填 |

## 7. 项目

项目、仓库与成员关系实体统一见[项目管理数据](../../项目管理/references/data.md#entities)，本模块不维护副本。卡片项目仅为查询投影，归属与合并卡处理见 [business-rule.md §9](business-rule.md#9-项目归属与配置)。

成员字段及关系只读引用[项目成员数据](../../项目管理/references/data.md#members)；排期经办人仍为公共系统用户，统计成员引用不替代账号或授予操作权。

### 7.1 仓库只读引用

仓库身份、来源类型、地址、默认分支、启停及访问配置见[项目管理仓库定义](../../项目管理/references/data.md#repositories)。候选由云效 Codeup 目录与启用通用 Git 配置组成，按来源类型与稳定仓标识引用；同一项目可同仓兼任 harness 工程和代码服务仓，任一仓至多被一个启用项目占用，停用项目不占用。排期不维护仓配置、凭据或环境信息，不依赖目录结构同步或新增外部授权；远端读取失败不清除卡片源事实，临时缓存重建不影响持久化卡片、回执及采集水位。

## 8. 澄清记录

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 卡片编号 | 发起澄清的卡片 | 引用 | 是 | 合并卡发起时为合并卡编号 |
| 轮次 | 该卡片的第几次澄清 | 数量 | 是 | 从 1 开始按卡片累计 |
| 状态 | 澄清记录状态 | 枚举 | 是 | 见 §9 |
| 澄清问题 | 研发提出的待澄清问题 | 长文本 | 是 | 见 field-rules.md §10 |
| 发起人 | 发起澄清的用户 | 人员 | 是 | MCP 发起时为令牌持有人 |
| 发起时间 | 转待澄清的时间 | 时间 | 是 | 待澄清列表据此排序与计算等待时长 |
| 发起渠道 | 发起澄清的入口 | 枚举 | 是 | 见 §9 |
| 澄清前状态 | 转待澄清前的卡片状态 | 枚举 | 是 | 待开发 / 开发中；完成或撤回澄清时据此恢复 |
| 原排期 | 转待澄清前的排期起止 | 日期区间 | 否 | 原本未排期时为空；仅展示，不用于恢复 |
| 处理人 | 完成或撤回澄清的用户 | 人员 | 否 | 待澄清时为空；MCP 处理时为令牌持有人；删除卡片关闭时为删除人 |
| 处理时间 | 完成或撤回澄清的时间 | 时间 | 否 | 待澄清时为空 |
| 处理渠道 | 完成或撤回澄清的入口 | 枚举 | 否 | 待澄清时为空，见 §9 |
| 修订 commit | 完成澄清时记下的修订 commit 快照：修订卡编号、仓库、hash、提交说明首行、作者与提交时间 | 列表 | 否 | 仅已澄清时有值；不随修订卡此后的变化而变，见 business-rule.md §11.3 |
| 合并后卡片 | 完成澄清生成的合并卡编号 | 引用 | 否 | 仅已澄清时有值 |
| 撤回理由 | 撤回澄清的说明 | 文本 | 否 | 见 field-rules.md §12 |

- 澄清记录只新增与推进状态，不删除；卡片删除后其澄清记录保留

## 9. 枚举

| 枚举 | 取值 |
|------|------|
| 卡片状态 | 见 state-machine.md §1 |
| 需求性质 | 业务功能 / 技术支持 |
| 项目状态 | 启用 / 停用，只读引用项目管理；停用项目不参与当前卡片归属 |
| 成员全局状态、项目成员关系状态 | 只读引用项目管理生命周期，用于显示与报告统计范围，不控制公共系统用户的排期操作权 |
| 澄清记录状态 | 待澄清（`OPEN`）/ 已澄清（`RESOLVED`）/ 已撤回（`WITHDRAWN`） |
| 操作渠道 | PC（`WEB`）/ MCP（`MCP`） |
| 流水类型 | 创建卡片（`CREATED`）/ 编辑（`EDITED`）/ 排期（`SCHEDULED`）/ 取消排期（`UNSCHEDULED`）/ 调整排期（`RESCHEDULED`）/ 领取开发（`TAKEN`）/ 释放开发（`RELEASED`）/ 标记完成（`MARKED_DONE`）/ 回退（`REVERTED`）/ 删除（`DELETED`）/ 发起澄清（`CLARIFY_RAISED`）/ 澄清完成（`CLARIFY_RESOLVED`）/ 撤回澄清（`CLARIFY_WITHDRAW`） |
