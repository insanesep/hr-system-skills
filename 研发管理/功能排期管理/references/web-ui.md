# 功能排期 · Web 端 UI 描述

> 页面元素与交互声明以本文件为准，原型见 `assets/web/feature-schedule.html`（研发排期工作台）与 `assets/web/feature-schedule-detail.html`（卡片详情页），两页共用 `assets/web/feature-schedule-data.js` 的演示数据。视觉统一取设计系统组件与状态语义，本文件不定义私有颜色与布局；业务规则只引用、不复述。

## 页面清单

### 研发排期工作台

- **页面路径**：`/subapp/devhub/feature-schedule`
- **权限编码**：
  - 路由：`devhubFeatureSchedule`
  - 按钮：`devhubFeatureScheduleEdit`、`devhubFeatureScheduleDelete`、`devhubFeatureScheduleMarkDone`、`devhubFeatureScheduleReleaseDay`，控制范围见 [permission-rules.md §1](permission-rules.md#1-权限编码)
- **页面类型**：`order-list`
- **埋点**：页面浏览由 SDK 自动上报；点击埋点的功能编码前缀为 `RND.MANAGE.FEATURE_SCHEDULE`，命名与登记规则见 [功能使用情况分析 business-rule §1.4](../../功能使用情况分析/references/business-rule.md#14-功能编码命名规范)
- **区块职责**：
  - 工具栏：单行指挥栏，承载时间导航、本月进度、搜索、视图切换、待澄清入口、筛选、新建卡片与更多菜单
  - 主体区：月视图 / 周视图 / 列表三种视图，展示当前期的排期卡片
  - 侧边栏：待排期池，展示未排期卡片，可收起，池内独立滚动
- **布局引用**：`参见原型 assets/web/feature-schedule.html`（DOM 结构依据：page-blueprint `patterns/web` 区块装配，page-root + dual-pane + table-card；参考骨架 `skeletons/web/list-page.vue.tpl`）

#### 区块与元素

**A. 指挥栏**

| 编号 | 元素 | 说明 |

| A3 | 本月进度 | 待排期、待开发、开发中、已完成、延期五项计数，口径见 [business-rule.md §4](business-rule.md#4-统计口径)；待排期取池内全量总数，为纯文本，其余为单选开关式快捷筛选（再点取消），选中项带选中态；与筛选抽屉的状态条件交集为空时状态条件置空 |
| A4 | 进度入口 | 视口较窄时本月进度收进「进度」浮层，浮层内统计项同样可点击筛选，点击后浮层不关闭 |
| A5 | 搜索框 | 占位「搜索任务：标题 / 编号 / 提交人」，待排期池由服务端按关键字分页查询并回到第 1 页，规则见 [business-rule.md §5](business-rule.md#5-搜索规则) |
| A6 | 视图切换 | 月视图 / 周视图 / 列表，视口较窄时显示为月 / 周 / 列表 |
| A7 | 筛选 | 打开筛选抽屉；偏离默认值的条件数大于 0 时显示计数，计数规则见 [business-rule.md §6.1](business-rule.md#61-通用) |
| A8 | 新建卡片 | 主按钮，打开新建卡片弹窗 |
| A9 | 更多 | 下拉菜单：合并卡片、显示密度（标准 / 紧凑，当前项带选中态）、非需求改动（附全量总数）；不含项目配置、Git 仓库配置、环境信息或项目管理快捷入口 |
| A10 | 待澄清 | 「待澄清 N」按钮，位于视图切换与筛选之间；N 为全量待澄清卡数，口径见 [business-rule.md §4](business-rule.md#4-统计口径)；N 大于 0 时为警示样式；点击打开待澄清列表弹层（G13） |

**B. 待排期池**

| 编号 | 元素 | 说明 |
|------|------|------|
| B1 | 池头 | 「待排期」标题与池内全量总数，「批量」与收起按钮 |
| B2 | 池卡片 | 标题（超长省略）、状态、项目标签、提交人、来源模块；合并卡另有合并标识与子卡数；编号位替换为创建时间「YYYY-MM-DD HH:mm」与相对时间标签（刚刚 / X 分钟前 / X 小时前 / X 天前 / X 个月前 / X 年前），超过 7 天未排期时标签为警示样式 |
| B3 | 分页条 | 池底服务端分页条，默认每页 10 张，可切 10 / 20 / 50；显示「共 N 张」、上一页、页码、下一页；池宽不足时页码折叠省略号、分页条换行，不横向溢出；只有 1 页时保留总数与每页条数 |
| B4 | 批量多选态 | 卡片显示勾选框，点击卡片即勾选；池头「批量」变为「退出批量」；底部操作条显示「已选 N 张」与取消、移入非需求；切换页码保留勾选，筛选、搜索或只看自己变化时退出多选态并清空已选 |
| B5 | 空态 | 无卡片时「待排期池已清空」；只看自己无结果时「没有由你提交的卡片」，并提示「关闭『只看自己』可查看全部」 |
| B6 | 分页行为 | 搜索、筛选或只看自己变化后回到第 1 页；移入日历或批量移入非需求后刷新当前页，当前页为空且不是第 1 页时回退上一页；移回待排期后回到第 1 页；从卡片详情页返回恢复进入前的页码与每页条数，刷新页面回到第 1 页 |

**H. 键盘与本机记忆**

- 快捷键：← / → 切换上一期 / 下一期；T 回到今天或本周；Esc 分层关闭，顺序为右键菜单 → 气泡确认 → 二次确认 → 澄清弹窗 → 弹层 → 年月选择、进度浮层、更多菜单 → 筛选抽屉 → 多选态；分页器与每页条数选择支持 Tab 聚焦、Enter 确认；输入框聚焦时不响应，弹层打开时 ← / → / T 失效，页面处于后台页签时不响应
- 本浏览器记忆：当前视图、显示密度、待排期池收起状态；筛选与搜索不记忆，仅在从卡片详情页返回时恢复进入前的状态与待排期池页码 / 每页条数，刷新页面回到第 1 页

**I. 布局**

- 页面身份由 Portal 面包屑与页签承担，业务区不渲染页面大标题
- 指挥栏在宽屏与中小屏下均保持单行；搜索框宽度随屏宽分档收缩，不挤压核心操作
- 待排期池固定宽度，视图区自适应剩余宽度；池内卡片区随池整体独立滚动，分页条位于列表之后；分页条使用紧凑尺寸，允许在池宽内换行
- 页面本身不滚动，视图区内部滚动，指挥栏始终可见；低高度屏压缩指挥栏纵向间距
- 窄屏（非目标桌面场景）保底为纵向堆叠布局
- 浮层默认右对齐，触发器位于左半屏时自动左对齐，均不超出视口

#### 导航关系

- 来源页：Portal 菜单「研发 / 研发管理 / 功能排期管理」进入，本页为模块入口页；卡片详情页经「返回」、面包屑，或删除卡片、解散合并成功后回到本页
- 去向页：卡片详情页（点击卡片、列表行，日详情弹层、非需求改动弹层与待澄清列表弹层中的卡片，右键「查看详情」，新建卡片命中已有卡片）；其余排期操作均在本页浮层内完成，不设置基础配置跳转
- 返回行为：面包屑「首页」返回 Portal 首页；各浮层经关闭按钮、遮罩或 Esc 回到工作台；从卡片详情页返回时恢复进入前的视图、期、筛选、搜索与待排期池页码 / 每页条数，刷新页面仍按默认值
- 面包屑：首页 / 研发 / 研发管理 / 功能排期管理
- 页面可直达：路径无参数即可打开；视图、显示密度与池收起状态从本浏览器记忆恢复；待排期池从第 1 页开始

- **菜单名称**：功能排期管理下的详情子页，不单独占菜单
- **页面路径**：功能排期管理（`/subapp/devhub/feature-schedule`）下的详情子页，以卡片编号为路径参数直达，具体路由以前端路由配置为准
- **权限编码**：
  - 路由：`devhubFeatureSchedule`
  - 按钮：`devhubFeatureScheduleEdit`、`devhubFeatureScheduleDelete`、`devhubFeatureScheduleMarkDone`，控制范围见 [permission-rules.md §1](permission-rules.md#1-权限编码)

- **页面定位**：一屏回答「这张卡片现在什么状态、排在哪天、谁在开发、交付了哪些 commit」，待澄清时说明卡在什么问题上，并在本页推进状态、调整排期与维护卡片信息
- **区块职责**（自上而下）：页头（含右上角操作区）→ 业务提示 → 开发进度 → 关键摘要 → 任务内容 → 页级 Tab（基本信息 / 子卡明细 / 完成 commit / 澄清记录 / 操作日志）

**N. 整页状态、键盘与布局**

- 整页状态：加载时为骨架屏；加载失败为「卡片详情加载失败」与「重新加载」；卡片编号不存在、卡片已删除或合并卡已解散时为「卡片不存在或已删除」与「返回研发排期工作台」；中间合并卡编号已在后续完成澄清中并入新合并卡时跳转到最新合并卡，见页面间导航

#### 表单校验

**编辑卡片信息弹窗**

- 初态：字段取卡片当前值；合并卡提示保存后标题、内容与负责人扩散至子卡；非需求改动卡需求性质与业务对接人置灰

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 标题 | 是 | 1–30 字符，超出阻断输入 | input / 保存时 | 「请输入标题」「标题最长 30 字符」 | 否 |
| 内容 | 否 | — | — | — | 否 |
| 负责人 | 是 | 从公共有效系统用户中选择，按公共账号核验，不要求项目成员登记，不覆盖源作者；成员身份仅用于显示与报告映射 | change及提交 | 「请选择有效系统用户」 | 是（系统用户有效性核验） |
| 需求性质 | 是 | 单选，默认业务功能 | change | — | 否 |
| 业务对接人 | 否 | 选填，最长 64 字 | input | 「业务对接人最长 64 字」 | 否 |

- 提交成功跳转：关闭弹窗，停留本页并刷新，无延时
- 提交失败展示：弹窗顶部 AcAlert，保留输入
- 脏数据离开：有修改时关闭弹窗，AcModal「当前卡片有未保存的修改，确认放弃？」
