# 功能排期 · 字段规则

> 卡片与需求澄清字段的默认值、取值与校验规则真源；项目和成员配置只读引用项目管理。字段清单与实体关系见 [data.md](data.md)，状态相关的字段写入见 [state-machine.md §2](state-machine.md#2-状态流转)，合并卡各字段取值见 [business-rule.md §8.3](business-rule.md#83-合并卡生成)。

## 1. 卡片编号

- **格式**：`FS-{YYYYMMDD}-{NNN}`，示例 `FS-20260507-001`、`FS-20260507-002` 为同日第 1、2 张卡片，次日从 `FS-20260508-001` 重新开始
- `FS` 为全局统一前缀，与模块解耦
- `YYYYMMDD` 取 commit 作者提交时间的东八区日期；合并卡取合并当日的服务端日期
- `NNN` 为同一日期内全局递增序号，三位零填充，从 `001` 开始；并发生成时同日序号唯一且单调递增，编号分配与卡片入库同时完成；当日序号超过 999 时记录告警
- 普通卡与合并卡共用同一序号序列；编号生成后不可变，卡片删除后序号不回收
- 编号只在 PM 内部使用，不出现在 commit message 中；研发提交仍按团队约定前缀

## 2. 标题与内容

- **默认标题**：取 commit message 首行 → 含半角冒号时取首个冒号之后的内容（去掉 `feat(scope):`、`fix:` 等前缀），无冒号保留整段 → 去除首尾空白 → 超过 30 字符时截取前 30 字符，不加省略号
- **编辑**：标题必填，上限 30 字符，超出时阻断输入并提示「标题最长 30 字符」；编辑后不再回读 commit；前端生成默认标题与服务端同一规则
- **内容**：默认为 commit message 原文；合并卡内容由系统合成，见 [business-rule.md §8.3](business-rule.md#83-合并卡生成)
- **合并卡标题**：合并时由用户输入，必填，上限 30 字符；完成澄清的自动合并取原卡标题，见 [business-rule.md §11.3](business-rule.md#113-完成澄清与自动合并)

## 3. 来源模块

- 由 commit 头部的 Conventional Commit 范围解析，解析不到时记为 `MISC`；解析细则以代码仓为准
- 仅用于分组、筛选与合并校验，不参与编号

## 4. 负责人

- 界面以「提交人」呈现；默认按公共系统用户规则匹配 commit 作者账号，不以项目配置替换作者。显示名、别名及报告映射只读引用[项目成员身份](../../项目管理/references/business-rule.md#identity)，不替代公共账号匹配。
- 源作者未唯一匹配系统用户时保留原作者姓名并标注账号未匹配，不按同名取首人；历史卡片身份不因成员改名、全局停用或退出项目统计范围丢失。
- 卡片详情编辑可修改业务提交人，候选为公共有效系统用户，不要求已登记为项目成员；修改记录为本次业务变更，不回写源 commit 作者。非需求改动卡同样适用。

## 5. 排期日期

- 卡片同时保存单日排期日与起止区间，二者联动：只写排期日时起止日均为当日；写起止日时排期日取开始日；清空排期时三者同时清空
- 排期日与开始日不得早于今天，写入时校验

## 6. 需求性质

- 单选：业务功能（默认）/ 技术支持；技术支持指技术类、非功能性改动，如文档补录、参数说明、性能优化、工具脚本、changelog
- **写入路径**：PM 在卡片详情页编辑卡片信息时勾选，写编辑流水
- 系统不对存量卡批量补标
- 不改变本模块的状态流转
- 月历与列表不展示性质

## 7. 业务对接人

- 选填：在卡片详情页编辑卡片信息时输入，上限 64 字，由产品手工维护；为空不影响排期写入
- 已被需求单关联的卡片：为空时以需求单提交人兜底展示，卡片详情页提示需求单提交人姓名，手工填写优先
- 所有卡片均可留空；非需求改动卡不可编辑该字段
- 排期写入、合并卡生成与 commit 采集均不校验该字段；系统不批量回填

## 8. 完成 commit 回执

- 选填：标记完成时可关联一组跨仓 commit，也可不关联直接完成
- **选择流程**：从卡片当前归属项目的代码服务仓中选仓，映射只读引用[项目管理执行映射](../../项目管理/references/business-rule.md#execution-mapping)；合并卡按 [business-rule.md §9](business-rule.md#9-项目归属与配置) 解析唯一项目，不取子卡代码仓并集。显示名称、来源类型和仓标识，再选分支、检索并点选 commit；可关联多条，按仓与 commit 去重，不提供 hash 手输入口。
- **候选为空**：卡片未归属项目，或项目未配置代码服务仓时无可选仓，提示后允许不关联直接完成；如需维护映射，从研发管理菜单进入项目管理；本页不提供配置快捷入口，不以完成操作强制配置项目。
- **分支**：可输入可选择，候选来自仓内分支，默认取该仓默认分支；手改的分支按仓在本浏览器记忆。分支列表加载失败时提示原因，允许手填分支继续检索
- **服务端校验**：仓库必须属于写入时卡片当前归属项目的代码服务仓，commit 必须能在该仓检索命中，通用 Git 同时校验指定分支可达性；不按提交路径增加范围限制。未经选择核验的提交拒绝；托管平台无已确认详情地址时不生成猜测链接。映射变更不改写已经保存的回执。
- 每条回执记录仓库、commit、短 hash、提交说明、链接、作者与提交时间
- 开发完成后关联或移除完成 commit 为单独保存，写一条编辑流水「完成 commit：{原个数} → {新个数} 个」，不与卡片信息编辑合并

## 9. 项目字段引用

- 项目与仓字段只读引用[项目管理实体](../../项目管理/references/data.md#entities)，配置校验见[项目管理规则](../../项目管理/references/business-rule.md#source)；本页不复制字段定义、校验或配置表单。
- 所属项目与项目标签仅为查询投影，按源仓匹配当前启用项目，不按目录或路径限定范围；配色读取项目创建时固定的蓝、青、紫、金、品红、橙红循环序列，未归属为灰色。归属与显示规则见 [business-rule.md §9](business-rule.md#9-项目归属与配置)，不另设可编辑卡片项目字段。
- 成员显示与报告映射见[成员身份](../../项目管理/references/business-rule.md#identity)，项目统计范围见[成员关系](../../项目管理/references/business-rule.md#membership)与[生命周期](../../项目管理/references/business-rule.md#lifecycle)；实际人员选择仍使用公共有效系统用户，不把成员名单作为排期账号准入条件。
- 仓不可达时明确反馈，不因查询失败清除源事实、仓引用或卡片归属；存量卡片仍按既有仓标识与当前启用项目映射解析。

## 10. 澄清问题

- 必填，1–2000 字，保留换行；PC 与 MCP 同一规则，首尾空白不计入字数
- 写明问题所在的需求文档位置或功能点、当前描述的缺失或矛盾、对开发的影响与期望的澄清结果；多个问题逐条编号
- 提交后不可修改；需要补充时撤回后重新发起
- 流水、通知与列表中的问题摘要取前 50 字，超出以「…」省略

## 11. 修订 commit

- 必填，至少 1 条、至多 20 条，同一 commit 不重复
- **候选仓**：卡片的 harness 工程，普通卡为其源仓；合并卡为其子卡的源仓，多个时可选
- **PC 选择**：选仓（仅一个候选时自动选中）→ 按需修改分支 → 搜索或浏览 commit → 点选，可重复点选以选多条；列表标注已出卡的卡片编号，卡片已删除的 commit 禁选；不提供 hash 手输入口
- **MCP 提交**：以 commit 标识提交，接受完整 hash 或不少于 7 位的前缀；服务端在候选仓内核验，未命中或前缀命中多条时拒绝
- 不可选择卡片自身或其子卡的源 commit
- 修订卡的出卡、沿用与拒绝规则见 [business-rule.md §11.3](business-rule.md#113-完成澄清与自动合并)

## 12. 撤回理由

- 选填，上限 200 字；未填写时流水与通知不展示理由
- 删除待澄清卡片时由系统记为「卡片已删除」
