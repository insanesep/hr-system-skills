# 项目管理 · 权限规则

<a id="boundaries"></a>
## 1. 功能权限与入口

项目管理是研发管理下独立菜单，项目、仓库和成员维护不复用功能排期编辑或报告配置权限。菜单资源编码、路由名称与按钮权限分别由公共权限体系登记，不以项目成员或统计角色代替授权。

| 权限职责 | 控制范围 | 无权限时表现 |
| --- | --- | --- |
| 项目管理查看 | 项目列表、映射、成员和公共环境信息的查询 | 项目管理菜单隐藏，直达访问拒绝；排期和报告不提供基础配置入口 |
| 项目维护 | 新建、编辑、项目启停与环境信息保存 | 隐藏新建、编辑、启停和环境信息保存，允许已授权查看 |
| Git 仓库维护 | 仓配置查询、新增、编辑、连接测试、启停与删除 | 隐藏 Git 仓库配置入口，拒绝读取凭据配置资料与相关操作 |
| 成员维护 | 项目内新增或关联、共享资料编辑、人员及关系启停 | 成员管理可只读查看，不显示维护按钮 |

功能排期只读消费项目清单与仓映射，报告配置只读消费项目和成员快照；允许其业务消费不等于授予本菜单维护权限。服务端按实际操作校验权限和当前引用状态，不能仅靠按钮隐藏防越权。

## 2. 成员与外部权限边界

- 成员的产品、研发、UI、架构角色只用于参与与统计，不产生门户角色、代码仓成员、MCP 工具、数据库或发布权限。
- 项目参与关系不等于项目负责人任命、域负责人任命或人资直属上级；本功能不从角色或姓名推定这些关系。
- 编辑人员启停只改变报告统计范围，不禁用门户主账号，不自动收回云效或 Git 访问，不替所属业务模块交接待办。
- 连接凭据只用于授权范围内的仓查询，存储加密、读取不回显，不进入会话、日志、文档或报告。连接测试不改变远端仓内容。
- Git 仓引用保护在服务端执行；仓被引用时不能通过修改隐藏字段绕过地址、停用或删除限制。

## 3. MCP 配置边界

项目保存与启停的既有工具名称为 `schedule_save_project`、`schedule_set_project_status`；其配置职责归本功能，调用按项目维护权限校验，不以排期编辑权限代替。规则见 [项目配置](business-rule.md#source) 与 [状态保护](business-rule.md#lifecycle)。停用项目前须明确确认，重复提交不产生新项目或重复启停效果。

项目查询工具可继续向排期消费方提供只读数据。工具族开放、令牌范围与实际权限分别判断；不因移出菜单或工具名称含 schedule 就保留另一份项目台账，不编造未登记的仓库或成员写入工具。
