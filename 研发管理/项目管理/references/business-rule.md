# 项目管理 · 业务规则

<a id="source"></a>
## 1. 项目配置与来源

项目台账由本功能唯一维护，功能排期和报告均使用同一稳定项目标识。项目不是代码仓的一级目录，也不是门户产品线、业务线、云服务项目或组织部门的别名。

- 人工新建、编辑项目，维护项目名称、harness 工程、代码服务仓、备注和启停；不从目录结构自动新增项目，不在消费方重复建项目。
- 项目名称必填，去除首尾空白后 1–12 字；启用项目之间名称唯一，停用项目不占名。稳定项目标识不随更名或启停改变。
- harness 工程必填、单选，为项目需求或文档真源仓；代码服务仓选填、可多选，为实现事实范围。两者均从云效仓库与启用通用 Git 配置组成的候选中点选，不手填仓标识。
- 一个仓最多被一个启用项目占用，不论其作为 harness 工程还是代码服务仓。同一项目内允许两种用途选择同一仓；停用项目不占用仓。保存与重新启用均校验仓库可用性及占用冲突，并指出冲突项目。
- 项目标识色创建时按设计系统蓝、青、紫、金、品红、橙红顺序循环分配，之后不可编辑；停用不释放颜色，重新启用沿用原色。颜色仅表达项目归属，不表达状态，不以颜色作为项目身份。
- 不提供项目删除。停用保留项目、成员关系、仓库映射、环境信息与历史报告；项目改名和仓映射变更不改写卡片源提交、经办人与已归档证据。

<a id="execution-mapping"></a>
## 2. 项目仓库映射

- harness 工程决定自动出卡的采集源与卡片的项目归属；代码服务仓提供完成 commit 候选及报告的实现代码范围，不参与出卡归属判定。
- 项目范围取其已配置 harness 工程和代码服务仓，不自动拆分一级目录或引入未配置的实现路径。同项目重复仓按稳定仓标识去重。
- 云效仓与通用 Git 仓分别采用其来源稳定标识，同名仓不归并。通用 Git 引用不能因名称或连接账号变化指向另一仓。
- 仓不可达或失去访问权时明确提示来源异常，不当作零提交或来源已删除；历史映射保留，不自动改选其他仓。

<a id="repositories"></a>
## 3. Git 仓库配置

云效仓资料从云效目录读取，本页只维护通用 Git 配置；两类来源共用项目选仓列表，不在本功能创建远端仓。

- 操作包括新增、编辑、连接测试、启停与删除。配置名称必填、最多 256 字，名称不区分大小写判重；标准化仓地址不能重复。
- 仓地址仅支持 HTTP 或 HTTPS 克隆地址，最多 2048 字，必须包含仓路径，不含账号密码、查询参数或片段。主机大小写、默认端口与末尾斜杠差异不产生新仓。
- 访问账号默认 `git`，可调整；密码或令牌新增必填，最多 256 字，加密保存，不回显、不进入模型会话、日志、备注和文档。编辑留空沿用旧值，设置新值替换旧值。
- 默认分支选填；为空时从远端发现。名称、账号与分支最多 256 字，均不允许控制字符。
- 连接测试可对未保存草稿执行，读取远端分支并反馈结果；编辑时密码留空使用旧凭据。测试不保存配置、不建立项目关系或改动远端内容。测试成功不代表配置已保存。
- 被任何项目引用的仓不能删除或更换地址，包含停用项目；被启用项目引用时不能停用。阻断时列出引用项目，先在对应项目解除引用或按规则停用项目，不自动删引用。
- 分支、提交与默认分支以远端事实为准；临时查询缓存重建不清除项目、卡片、回执或采集水位。读取失败明确反馈，不用空集合冒充成功。

<a id="identity"></a>
## 4. 成员与身份

本功能承接报告人员范围的姓名、角色、别名及启停配置。成员是统计与参与关系对象，不是另建的集团门户账号；公共用户状态、组织任职与具体业务操作身份仍由各自真源判定。

- 成员具有稳定标识、展示姓名、角色集合、别名集合及人员启停状态；同一成员跨项目共用基础信息，不在不同项目复制档案。
- 姓名必填、最多 64 字，在全部成员中唯一，包含停用人员；已有同名成员应按稳定成员标识关联，不通过重建档案绕过唯一性。姓名不是跨项目去重主键。
- 角色至少一项，可同时选择产品、研发、UI、架构；角色是统计职责，不等于功能授权。
- 别名用于匹配 Git 作者名或邮箱、排期人员名、Qoder 名称或邮箱；最多 50 条，每条最多 128 字，去掉首尾空白、统一大小写后去重。空值不作为别名。
- 匹配结果必须唯一。身份未匹配或同时命中多名成员时保留源事实并标记待核对，不按名单顺序取首人，不以项目负责人、操作人或共享账号猜测个人。
- 不自动创建或修改云效、Qoder、企微及门户账号，不把手工别名登记当作外部账号已核验的证据。已有产出事实、历史报告不随姓名或别名变更重归人。

<a id="membership"></a>
## 5. 项目成员关系

维护入口固定为项目列表行「成员管理」。必须先明确项目，再新增人员或关联已有人员；不存在独立的无项目人员新增入口，也不能从报告配置直接维护成员。

- 在启用项目中新增成员时，人员档案和当前项目关系同时保存；校验失败或取消不留下孤立人员。停用项目不允许新增或关联，但可维护已有成员的共享资料、人员状态及原关系状态；这些操作不使停用项目进入有效统计范围。
- 关联已有成员从共用成员中选择，展示姓名、角色、人员状态及已参与项目；允许选择在其他项目出现的同一成员，包括人员停用的档案，但不自动启用其人员状态。
- 一人可参与多个项目。同一项目与成员只保留一条关系；关系已存在时打开原关系，已停用时恢复该关系，不重复新增档案或关系。
- 人员启停与项目成员关系启停分开。关系停用或恢复只影响当前项目；人员停用则退出所有项目的有效统计范围，人员重新启用不自动恢复已停用关系。
- 共享姓名、别名、角色与人员状态的编辑影响该人员所有项目，页面列出受影响项目并在提交前确认。只调整当前项目参与状态不修改其他项目关系。
- 项目停用使其全部关系退出有效范围，保留各关系原状态；重新启用后按人员状态和关系状态重新判定，不自动启用其他项目或人员。
- 成员不能通过解除最后一条关系成为无项目档案；本功能使用关系停用而非删除，保留挂靠与历史。不提供人员删除或自动迁移成员到另一项目。

<a id="report-scope"></a>
## 6. 有效人员范围与报告快照

有效项目成员同时满足项目启用、人员启用、成员关系启用。人员是否有本期 Git 提交不决定成员资格，零提交人员仍属于项目团队。

- 人员产出周报、日报及 Qoder 产研团队名单取全部启用项目的有效成员并集，按稳定成员标识去重；同人多项目、多角色只计一人，不按项目另生成人员产出报告。
- 项目进度报告各组使用该项目有效成员；参与生成的项目组仍由报告配置已启用的报告范围扩展决定，不能因有人参与就绕过报告范围启停。
- 项目进度团队产品、研发与架构人数按成员角色计数，同人多角色在对应角色各计一次，全量团队人数按稳定成员标识去重。不用项目仓提交人自动新增、移动或分配成员。
- 报告任务创建时取得项目、人员、关系、角色与身份匹配依据的同一快照，任务内保持一致，外部会话使用同一来源；后续成员变更只影响新任务，不修改已归档版本。
- 人员产出报告的去重名单为空或来源未取得时拒绝生成并提示到项目管理核验；项目成员明确为空时项目进度团队计 0、人员明细为「无」，无研发成员的人均功能数显示「—」，无产品或研发成员时对应角色人均提交行数显示「—」。来源失败标「未取得」，不当作空名单。
- Qoder 无账号、快照缺失或来源失败标「未取得」，不补 0；只有完整成功且明确零值才计 0。多项目同人可在各组展示同一期间的个人用量，不解释为按项目分摊；全量按成员和自然日用量快照去重，不能相加组值。

<a id="consumption"></a>
## 7. 产研消费边界

- 功能排期只读项目与仓库映射，一条源仓 commit 只出一张卡。卡片按源仓命中启用项目的 harness 工程取得项目归属；无命中显示「未归属项目」，这不是可维护实体。
- 合并卡仅在全部子卡同属一个启用项目时归入该项目，否则为「未归属项目」。项目筛选与归属使用当前有效映射的查询投影，改配置不写卡片流程字段，不覆盖归档报告。
- 报告范围配置以稳定项目标识关联项目，只维护报告 key、分支策略及报告扩展启停；触发、文件命名与版本归报告配置。项目启停、改名不更改已锁定 key 或旧报告文件名。
- 项目进度代码提交仍按项目映射仓归集，成员关系不改变仓边界；人员维度只匹配本项目快照成员，名单外不点名、不计入个人产出，不能借别名或成员关系扩大项目仓范围。
- 排期分配、审批、运维和发布继续按各模块的实际系统身份与操作权限执行；纳入统计名单不赋予办理权，不把成员关系推定为负责人任命或人资直属上级。

<a id="history"></a>
## 8. 状态与引用保护

项目、仓库、人员、成员关系各自为启用或停用，互不代替；仓库另有满足引用保护条件的删除动作。所有增改、启停和删除保留操作人、时间及目标信息。

- 停用项目需确认影响：不参与新出卡采集与当前项目归属，关联报告扩展及触发停用，该项目成员退出后续统计范围；同人其他启用项目关系继续有效。
- 恢复项目须重新校验名称、仓占用及来源有效性；保留原色、成员关系和报告 key。关联报告扩展和触发仍由报告配置核验后启用，不把恢复项目当作允许自动生成。
- 停用人员或关系只改变后续名单，不清除卡片、提交作者、待办和报告历史，不替各业务模块交接或改终态。
- 重复关联、重复启停不产生重复关系；保存时复核当前项目、人员、关系及仓引用状态，冲突提示刷新，不覆盖已被他人更新的配置。

<a id="environment"></a>
## 9. 项目环境信息

项目的环境信息入口随项目配置归本功能，按当前 DevHub 部署环境保存项目公共上下文；启停项目不清除原信息。

- 信息包含本环境入口、应用、测试库定位、可复用数据、数据规则、外部依赖和需人工配合事项；部署环境与修订号只读。
- 不填写个人账号、密码、令牌及连接凭据；个人测试资料按 RD 测试环境规则保存在本机，文档只描述公共业务含义，不内嵌配置报文。
- 当前部署环境未知时不可保存。按读取到的修订提交，发生并发冲突先重新加载后再编辑，不覆盖另一人的变更。
