# Qoder 用量分析 业务规则字典

> 本模块业务规则唯一真源。SKILL.md 仅导航，不复述本文定义。

## 1. 公共筛选与日期约束

- Web 筛选区：日期范围选择器（单个范围控件）+ 部门（单选）+ 统计范围（产研团队 / 全部成员）+ 成员多选 + 查询 / 重置按钮
- App 筛选区：日期预设选择器（今日 / 昨日 / 前 7 天 / 近 30 天 / 自定义）+ 部门（单选）+ 统计范围 + 成员多选 + 查询 / 重置按钮（筛选元素与 Web 对齐，日期控件为预设形态）
- 部门单选：全部（默认）/ 数字化中心 / 创新业务部；一个 Qoder 组织对应一个部门，成员 → 部门归属以 Qoder 组织配置为准（数字化中心 / 创新业务部各对应一个组织与独立 API Key），本模块只读引用
- 部门与成员联动：成员多选的可选清单 = 当前部门 ∩ 当前统计范围；切换部门时清空已选成员，成员清单与全部视图按新部门重查
- 统计范围默认「产研团队」：人员范围只读引用[项目管理 · 报告范围](../../项目管理/references/business-rule.md#report-scope)，成员清单与用量日快照按该范围及[跨源身份映射](../../项目管理/references/business-rule.md#identity)过滤；身份歧义不取首人、不猜姓名。切换「全部成员」仍查看原 Qoder 组织全量，不按产研人员状态裁剪或扩展组织成员范围
- 产研团队范围下名单为空或名单内无 Qoder 成员时，页面提示「产研团队人员范围为空或名单内无 Qoder 成员，请到「项目管理」核对人员范围与身份映射」
- 部门与统计范围取交集后无成员时，全部视图按空态处理（见 §7）
- 数据来源与刷新：Qoder Credits 用量按成员 × 自然日（东八区）同步落库为日快照，看板查询读取快照；每日凌晨同步前一日数据，历史区间需补数后展示；Qoder 未配置时看板可正常查询已同步历史数据
- 默认范围：前 7 天（不含今天，T-7 ~ T-1）
- 范围上限：起止跨度不超过 31 天（产品侧约束；上游 Qoder Teams OpenAPI 单次查询跨度硬约束为 7 天，由服务端按 7 天窗口切分拉取后合并，公共接入能力由 busyming-skills-common 承载）；前端对超范围查询拦截并提示「日期范围不能超过 31 天」
- 成员筛选为空 = 当前部门与统计范围交集内全部成员
- 所有视图（KPI / 柱状图 / 两张透视表）随公共筛选联动刷新，单视图不设独立筛选
- 两张透视表按成员行分页展示（默认 20 人/页），合计行统计全部匹配成员，不随页码变化

## 2. KPI 计算口径

| 指标 | 口径 | 精度 |
|------|------|------|
| 总用量 | 筛选范围内全部用量事件的 Credits 之和（统计范围=产研团队时仅名单内成员） | 整数展示 |
| 总请求数 | 筛选范围内用量事件条数 | 整数 |
| 次均消耗 | 总用量 ÷ 总请求数 | 1 位小数 |
| 人均用量 | 总用量 ÷ 活跃成员数 | 整数 |
| 活跃成员 | 筛选范围内 Credits 大于 0 的去重成员数 | 整数 |

周环比 = (本期值 − 上周同期值) ÷ 上周同期值的绝对值 × 100%；上周同期 = 本期起止日期各前移 7 天。上周同期值为 0 时环比记 0%（避免除零）。正值 ↑、负值 ↓、0 为 —。

## 3. 成员 × 日期透视表

- 行维度：成员，按选定期间成员 Credits 合计**降序从上往下**排列
- 列维度：日期（按天，升序从左往右）
- 单元格：该成员当日 Credits 合计
- 行合计：该成员期间之和；列合计：当日全员之和；末行末列为总计

## 4. 模型用量透视表（成员 × 模型等级）

- 行维度：成员名（不展示用户 ID）
- 列维度：模型等级，取选定期间实际出现的取值按该列合计降序排列，仅展示前 5 个；其余模型等级（含空值「未标注」）归入「其他模型」列，固定排在最后（与 §6 堆叠图归并口径一致）
- 单元格：该成员该模型等级的 Credits 合计，**保留两位小数**（汇总后四舍五入到分位，避免浮点累加误差）
- 行合计 / 列合计 / 总计同为两位小数
- 合计行（tfoot）每个数值单元格展示「合计值(列占比)」，格式 `10000.00(10%)`：列占比 = 该列合计 ÷ 总计 × 100%，四舍五入取整数百分比；总计单元格占比固定 100%，总计为 0 时各占比记 0%（避免除零）
- 负向 Credits 照常参与汇总

## 5. 负向 Credits 与活跃成员

- 上游事件的 Credits 可为负数（退款 / 冲正），聚合时照常参与求和
- 活跃成员判定仅统计 Credits 大于 0 的记录
- 负值不在界面单独标色（透视表仅展示汇总值）

## 6. 日消耗堆叠柱形图（按模型分类）

- 每日一根堆叠柱：当日 Credits 合计按模型分类分段堆叠，柱高 = 当日全员 Credits 合计（= 成员×日期透视表列合计）
- 模型分类：按接口返回的模型标识合计降序取前 6 个分段堆叠，其余（含空值「未标注」）归入「其他」堆叠于顶层；系列清单随数据动态生成
- 堆叠顺序：各模型系列自下而上按固定顺序堆叠，「其他」位于最顶层；图例同色展示于面板头部右侧
- 分段配色：取设计规范的浅色阶（柱体大面积填充时柔和且色相可辨），每个分类固定一色、双端一致，「其他」固定为灰色
- 周环比对比不在本图呈现，由 KPI 卡片区统一承担（见 §2）

## 7. 三态与空态

- 加载态：Web 面板骨架屏 / App 品牌 Loading 动效
- 空态：筛选范围内无事件时，图表与表格区显示「暂无用量数据」
- 错误态：上游调用失败显示错误提示 + 重试按钮，不暴露内部细节
