# 人员活跃看板 · 业务规则字典

> 本模块业务规则唯一真源。SKILL.md 仅导航，页面区块见 [web-ui.md](web-ui.md)，字段与枚举见 [data.md](data.md)。

<a id="terms"></a>
## 1. 术语

| 术语 | 含义 |
|------|------|
| 活跃信号 | 每日提交活动与 Qoder 用量两类信号；提交活动包含 Git 提交及产品人员在云效创建研发需求（见 [§4](#signals)） |
| 活跃日等级 | 人员单个自然日的绿 / 黄 / 红判定结果，另有「休息」「未取得」两种不参与三级判定的结果（见 [§6.1](#day-level)） |
| 应出勤日 | 按考勤需要出勤的自然日，是红色判定与活跃率分母的唯一依据（见 [§5](#attendance)） |
| 活跃率 | 应出勤日中绿或黄的天数 ÷ 应出勤天数 |
| 周期等级 | 人员或组织节点在筛选期间内按活跃率得出的绿 / 黄 / 红结论（见 [§6.2](#period-level)） |
| 角色指标 | 外部效能平台按开发、产品、测试角色提供的质量、稳定性、产出与交付指标，本模块只读展示（见 [§8](#role-metrics)） |

<a id="org-scope"></a>
## 2. 组织维度与人员范围

- 组织维度取用户权限中心「职能域」当前生效组织树，层级为中心 → 部门 → 子部门 → 小组，例如「数字化中心 → 创新业务部 → 成员」。组织树与主职任职只读引用公共真源，本模块不维护组织。
- 组织选择器从中心一级起选，必须选定一个中心；可继续选中心以下任一层级节点，选中节点即统计根节点。默认选中当前登录人主职所在中心；无主职或主职中心不在可见范围时取可见范围内第一个中心。
- 可选组织节点按当前登录人在用户权限中心的组织数据权限裁剪，只展示有权查看的节点及其祖先路径；祖先节点仅作路径展示，不可选中。无任何可见节点时页面不查询，提示「暂无可查看的组织，请联系管理员开通组织数据权限」。
- 统计人员 = 统计根节点及其全部下级节点中，以该节点为主职的在职人员。兼职任职不重复计入，同一人只出现在主职节点下一次。
- 组织归属以查询时的当前生效组织树为准，期间内调岗的人员整期归入当前主职节点，历史日不按旧组织拆分；已离职人员不在当前组织树中，不展示。
- 成员多选的可选清单 = 统计根节点下的统计人员，支持按姓名搜索；未选成员 = 统计根节点下全部统计人员。切换组织时清空已选成员。

<a id="identity"></a>
### 2.1 跨源身份对应

- 组织人员与 Git 作者、Qoder 账号的对应沿用[项目管理 · 成员与身份](../../项目管理/references/business-rule.md#identity)：以组织人员的姓名与企业邮箱匹配项目管理成员，再经该成员的别名对应 Git 作者与 Qoder 账号，结果必须唯一。
- 排期卡片的负责人使用公共系统用户身份，直接按组织人员的门户用户对应，不经项目管理别名。
- 组织人员在项目管理中无对应成员时标「身份未登记」，命中多名成员时标「身份待核对」；两种情况下 Git 数据与 Qoder 用量信号均为「未取得」，不按姓名猜测、不取首人。产品云效需求创建仍按 [§4.1](#requirement-creates) 的独立身份对应结果取得；排期卡片、考勤与角色指标仍按各自来源展示。
- 本模块只读消费身份结果，不创建或修改项目管理成员、别名及外部账号。

<a id="filters"></a>
## 3. 公共筛选与日期约束

- 筛选项：组织（必选）、日期范围、成员多选、查询、重置。组织与日期变更后需点「查询」生效；切换组织即时清空已选成员。
- 日期按自然日（东八区）计算。默认范围为本月 1 日至昨日；今天为每月 1 日时默认取上月整月。
- 不可选择今天及以后的日期；起止跨度不超过 31 天，超出时前端拦截并提示「日期范围不能超过 31 天」。
- 红、黄、绿仅用于活跃状态与周期等级展示，不作为筛选条件；KPI、组织汇总与人员行统一按组织、日期和成员筛选。
- 全部视图（KPI、活跃甘特、提交散点、角色指标）共用同一组织、日期和成员筛选；选择部门时包含该部门及下级节点的统计人员，角色页签仅作用于角色指标视图。
- 数据按日汇总：每日凌晨汇总前一日活跃日记录，看板读取已汇总的记录；当日数据次日可查。

<a id="signals"></a>
## 4. 活跃信号口径

| 信号 | 当日成立条件 | 口径真源 |
|------|-------------|---------|
| 提交活动 | 当日至少 1 次有效 Git 提交，或产品人员当日至少创建 1 条云效研发需求 | Git 口径沿用[研发周报计数纪律](../../../研发报告/人员产出报告/references/weekly-report.md#计数纪律必须遵守)，仓库范围不变；云效创建事实见 [§4.1](#requirement-creates) |
| Qoder 用量 | 当日 Credits 合计大于 500 | 日快照、补 0 与「未取得」口径沿用 [Qoder 用量分析 §1](../../Qoder用量分析/references/business-rule.md#1-公共筛选与日期约束)，负向 Credits 照常参与当日合计 |

- 500 Credits 为固定活跃阈值，当日合计恰为 500 不成立。
- Git、产品云效需求创建与 Qoder 分别记录取得状态。提交活动的任一适用来源已确认有事实，即成立；全部适用来源完整且均无事实，才是不成立；没有已确认事实且适用来源中至少一项未取得，则提交信号为未取得。非产品角色不依赖云效需求来源，不因该来源失败改变其提交信号。
- 排期卡片的领取、完成动作及当日 Qoder 未达阈值的用量只作为明细展示，不参与活跃判定。

<a id="requirement-creates"></a>
### 4.1 产品云效需求创建

- 仅产品角色适用：在统计范围内的云效项目中成功创建一条研发需求，按原始创建人归属为一次提交；不是按负责人、修改人、审批人或领取人归属。
- 云效项目属于已授权统计范围；需求创建人与组织人员通过云效账号稳定标识唯一对应，未匹配或歧义事实不归给任何人员，不按同名、负责人或共享账号猜测。
- 每条需求按「云效组织 + 工作项唯一标识」计一次，跨项目查询、分页、重试与重复采集不增加次数；标题不是去重依据，两个不同唯一标识的同名需求各计一次。
- 时间采用原始创建时间，按东八区自然日归入甘特日期；修改、审批、关闭、重开、分配以及只更新同步时间均不产生新的创建提交。任务、缺陷等非研发需求不计入。
- Git 与云效需求是不同事实来源，分别去重后相加为提交总次数；不根据标题或时间相近猜测两者是同一次操作，也不把一次创建拆成多个提交。
- 产品创建需求与 Git 有提交属于同一个提交活跃信号：仅创建需求而 Qoder 未达阈值为黄，两者同时满足为绿；并不要求同日还必须有 Git 提交。
- 需求创建不折算新增或删除代码行数；代码行数和次均代码提交量仍仅来自 Git。成功取得且无创建记录为 0；云效身份未对应、创建事实读取失败或覆盖不完整为未取得，不当成 0。
- 只读消费已有需求创建事实，本看板不提供创建云效需求、修改成员映射或更改项目授权的操作。

<a id="attendance"></a>
## 5. 考勤状态与背景

考勤状态与工作日历来自外部考勤数据（随外部效能平台只读接入），按人员 × 自然日取一个状态：

| 考勤状态 | 判定 | 是否应出勤日 | 甘特背景 |
|---------|------|:-----------:|---------|
| 出勤 | 正常打卡，含出差、外出、外勤；当日请假不足一个工作日也按出勤，提示中展示请假时长 | 是 | 无底色 |
| 请假 | 当日请假满一个工作日 | 否 | 斜纹浅底 |
| 休息日 | 排班或工作日历中的休息日，含周末与法定节假日 | 否 | 灰色浅底 |
| 考勤异常 | 应出勤但缺卡、旷工且无请假 | 是 | 浅红底边 |
| 未取得 | 考勤来源查询失败或无该人员该日记录 | 未知，不推测是否应出勤 | 灰色斜纹，提示注明「考勤未取得」 |

- 考勤只用于区分是否应出勤与背景展示，不改变活跃信号本身；休息日或请假日有活跃信号时照常着绿 / 黄色。
- 无考勤依据时不按周一至周五推测应出勤，不判红；已取得的活跃信号继续展示。

<a id="levels"></a>
## 6. 活跃等级判定

<a id="day-level"></a>
### 6.1 活跃日等级

按人员 × 自然日，依次判定，命中即止：

| 顺序 | 结果 | 条件 |
|:---:|------|------|
| 1 | 绿 · 活跃 | 提交活动与 Qoder 用量两项信号均成立 |
| 2 | 黄 · 部分活跃 | 恰有一项信号成立 |
| 3 | 未取得 | 无信号成立，且至少一项信号未取得或是否应出勤无法确认 |
| 4 | 红 · 不活跃 | 两项信号均已取得且都不成立，且当日为应出勤日 |
| 5 | 休息 | 两项信号均已取得且都不成立，且当日非应出勤日 |

- 一项信号「未取得」而另一项成立时按黄判定，提示中注明未取得项，不推定为绿。
- 红只出现在应出勤日；未取得不判红，避免把数据缺失记为不活跃。

<a id="period-level"></a>
### 6.2 人员周期等级

- 应出勤天数 = 期间内应出勤日中活跃日等级不为「未取得」的天数；未取得天数单独统计，不进分母。
- 活跃率 = 应出勤日中绿或黄的天数 ÷ 应出勤天数，百分比保留 1 位小数。
- 周期等级：数据完整时，活跃率 ≥ 80% 为绿，50%（含）至 80% 为黄，低于 50% 为红；全部日期已确认且应出勤天数为 0 时为「无应出勤」，活跃率显示「-」。存在活跃日等级未取得或无法确认是否应出勤的日期时，周期等级为「未取得」，不参与三色人数统计；有已取得数据时保留已取得范围的活跃率并注明「非完整周期」。
- 活跃天数 = 期间内全部日期中绿或黄的天数（含休息日与请假日的活跃）；休息日活跃天数 = 非应出勤日中绿或黄的天数，单独展示。

<a id="org-level"></a>
### 6.3 组织节点等级

- 组织活跃率 = 节点下全部统计人员已取得应出勤日中绿或黄的人天合计 ÷ 已取得应出勤人天合计；阈值与人员周期等级相同。节点内任一人员周期数据不完整时，组织等级为「未取得」，保留已取得范围的活跃率并注明「非全量」。
- 当日活跃人数 = 节点下当日活跃日等级为绿或黄的去重人数；当日应出勤人数 = 当日为应出勤日且等级不为「未取得」的人数。
- 汇总只按统计人员去重，不跨节点重复累加；成员筛选后的汇总只统计所选成员。

<a id="gantt"></a>
## 7. 活跃甘特图

- 横轴为筛选期间内每个自然日，升序从左到右；纵轴为组织分组与人员行。
- 首行为「当日活跃人数」汇总行：每个日期展示统计根节点下当日活跃人数，悬浮展示当日应出勤人数。
- 分组：按统计根节点以下的组织层级逐级分组。每个组织节点一行分组头，展示节点名称、统计人数与组织活跃率，日期格展示该节点当日活跃人数；直属该节点的人员排在其下级节点之前。
- 人员排序：同一组织节点内按活跃天数降序，相同时按活跃率降序，再按姓名拼音升序。
- 日期格着色按 §6.1 活跃日等级：绿、黄、红为对应等级色块，相邻同等级日期连成一段条形；「未取得」为灰色斜纹块；「休息」不着色，仅显示考勤背景。考勤背景按 §5 叠加在色块之下。
- 人员行右侧仅展示活跃天数与活跃率，不展示等级列；身份未登记或待核对的人员在姓名后展示对应标签。
- 悬浮日期格展示：日期与星期、考勤状态（含请假时长）、活跃日等级、提交总次数、Git 次数、产品云效需求创建次数、Git 新增 / 删除行数、Qoder Credits 及是否超过 500、当日领取与完成的排期卡片数、未取得的信号或考勤。
- 分组头可折叠 / 展开；统计人员超过 100 人时默认只展开统计根节点的下一级分组，否则默认全部展开。
- 图例固定展示：绿 · 提交 + 用量、黄 · 仅一项、红 · 应出勤无活跃、灰斜纹 · 数据未取得；背景：休息日、请假、考勤异常。

<a id="commit-scatter"></a>
### 7.1 提交散点图

- 「提交散点」与「活跃甘特」「角色指标」同级切换，复用顶部组织、日期和成员筛选；组织到部门、子部门和小组均可选择，不增加颜色筛选。
- 每个点代表一名统计人员在选定期间的提交情况，不按天或项目重复出点，也不受角色页签影响。
- 横轴为期间提交总次数（Git 提交 + 产品云效需求创建），单位「次」；纵轴为「次均代码提交量（新增行 / Git 次）」：Git 新增行数 ÷ Git 有效提交次数，保留 1 位小数，以未舍入值定位。需求创建次数不加入代码均值分母，新增和删除不互抵。
- Git 提交与代码行数、云效需求创建次数分别沿用 §4 的口径；本图是数量分布，不把点的位置解释为个人质量、绩效或效率评分。
- 点颜色沿用周期等级绿、黄、红；周期等级未取得或无应出勤为灰色，图例同时给出文字含义，不参与筛选。
- 适用来源均已取得且提交总次数为 0 时不绘点，计入「无提交 N 人」；仅有云效需求创建、Git 次数为 0 时次均代码量为「-」，不画成 0 行，单独计入「仅需求提交 N 人」。提交总次数或 Git 行数未取得、适用来源覆盖不完整时不绘点，计入「提交数据未取得 N 人」。考勤或 Qoder 数据缺失不妨碍展示完整取得的提交散点。
- 图上显示「已绘制 N 人 / 统计 M 人」、无提交、仅需求提交与提交数据未取得人数；坐标轴使用从 0 起的线性刻度，范围随当前筛选数据自动扩展，人数不受分页或甘特折叠影响。
- 悬浮或键盘聚焦点，展示姓名、组织路径、角色、提交总次数、Git 次数、云效需求创建次数、Git 新增与删除行数、次均代码新增行数和周期等级；点击点打开同一人员详情抽屉，返回保持散点视图与筛选。
- 完全相同坐标的人员共用带人数标识的点，提示列出各人员及其详情入口，不通过偏移坐标虚构差异；只有一人时可直接点击进入详情。
- 组织无人员时显示「所选组织暂无在职人员」；筛选内无人具有可绘制数据时显示「暂无可绘制的提交数据」并保留无提交和未取得人数；查询失败与加载状态沿用看板公共反馈。

<a id="role-metrics"></a>
## 8. 角色指标

- 角色指标与人员角色（开发 / 产品 / 测试）均由外部效能平台提供，本模块只读展示，不重算、不改写口径；指标定义与风险规则以外部效能平台为准。
- 统计月为筛选结束日期所在自然月（当月），全年为该自然年 1 月 1 日至筛选结束日期；指标不随日期范围逐日拆分，视图顶部注明统计月份与「外部效能平台口径」。
- 人员只归入外部效能平台给定的一个角色页签；未在外部效能平台登记角色的统计人员不进入任何页签，页签栏展示「未匹配角色 N 人」。
- 某项指标未取得时单元格显示「未取得」，已取得为零时显示 0；比率类指标分母为零时显示「-」。

各角色在列表中展示的指标列与展开后的分组卡片：

| 角色 | 列表指标列 | 展开分组与指标项 |
|------|-----------|-----------------|
| 开发 | Bug 数（当月 / 全年）、重开率、当月故障（负责 / 直接）、线上问题（当月 / 全年）、准时交付率 | 质量：Bug 当月 / 全年、重开率、缺陷密度、致命 / 严重 / 一般 / 轻微（个数 · 处理时长）；稳定性：当月故障 负责 / 直接、全年故障 负责 / 直接、线上问题 当月 / 全年、故障分 当月 / 全年；产出：代码行 当月 / 全年、当月任务、已上线任务、准时完成任务、实际工时；交付：准时交付率、准时发布率、冒烟通过率、冒烟用例数 |
| 产品 | 需求变更率、一次评审通过率、PRD 按时评审率 | 需求：需求 当月 / 全年、已评审、规划评审、变更数；质量：需求变更率、一次评审通过率、PRD 按时评审率；产出：需求产出量、故障分 当月 / 全年 |
| 测试 | 缺陷逃逸率、缺陷驳回率、线上问题 | 缺陷：当月缺陷、全年缺陷、逃逸率、驳回率；稳定性：当月线上故障、线上问题；产出：当月任务、已上线任务、用例执行、实际工时 |

- 三个页签共有列：姓名（含组织路径）、活跃天数 / 应出勤天数、排期卡片（完成 / 领取）、Qoder Credits、操作；不展示等级列。
- 列表按周期等级红 → 黄 → 绿排序，同等级按活跃率升序；数值指标列支持点击表头升降序。分页默认 20 人 / 页。

<a id="schedule-qoder"></a>
## 9. 排期卡片与 Qoder 用量汇总

- 排期卡片按卡片负责人归属人员，动作与状态以[功能排期管理状态机](../../功能排期管理/references/state-machine.md#1-状态枚举)及[卡片操作流水](../../功能排期管理/references/data.md#5-卡片操作流水)为准：
  - 领取数 = 期间内该人员的领取动作次数；完成数 = 期间内完成动作次数；被回退后重新完成的按动作各计一次。
  - 进行中 = 筛选结束日时该人员负责且处于已领取未完成状态的卡片数。
  - 延期数 = 进行中卡片中按[延期判定](../../功能排期管理/references/state-machine.md#3-延期判定)已延期的卡片数。
- Qoder 用量汇总：期间 Credits 合计、请求数、次均消耗与超过 500 Credits 的天数；Credits 与次均精度沿用 [Qoder 用量分析 §2](../../Qoder用量分析/references/business-rule.md#2-kpi-计算口径)。
- 提交活动汇总：展示期间提交总次数、Git 提交次数、产品云效需求创建次数与 Git 新增 / 删除行数。适用来源全部完整时才展示精确总次数；部分来源未取得时总次数标未取得，但保留已取得的来源计数，不伪装成完整总量。口径同 §4。

<a id="kpi"></a>
## 10. KPI 口径

| 指标 | 口径 |
|------|------|
| 统计人数 | 组织与成员筛选后的统计人员数；副文案展示其中身份未登记与待核对人数 |
| 组织活跃率 | 统计根节点的组织活跃率（§6.3），按组织等级着色 |
| 人员等级分布 | 周期等级为绿 / 黄 / 红的人数，另注明「无应出勤」与「未取得」人数 |
| 不活跃人天 | 期间内全部统计人员活跃日等级为红的人天合计 |

- KPI 不设环比；数值取整，百分比保留 1 位小数。

<a id="permission"></a>
## 11. 权限

- 页面仅向有菜单权限的管理层与研发负责人开放，不做全员公示；组织数据范围按 §2 裁剪。
- 人员详情、角色指标与排期卡片均按同一组织数据范围展示，不因直接打开详情链接而越过组织范围；详情链接指向的人员不在可见范围时提示「无权查看该人员」并关闭抽屉。
- 本页全部为只读查询，无写操作与导出。

<a id="states"></a>
## 12. 三态与异常边界

- 加载态：KPI、甘特与角色指标区分别骨架屏占位。
- 空态：统计人员为 0 时甘特与角色指标区展示「所选组织暂无在职人员」；角色页签无人员时展示「该角色暂无人员」。
- 错误态：活跃日记录查询失败时 KPI 与甘特区展示错误提示与「重试」，不暴露内部细节；外部效能平台不可用时仅角色指标与考勤降级为「未取得」，活跃甘特照常展示并在视图顶部提示「外部效能平台数据未取得，保留已取得活跃信号，不推测出勤」。
- 部分来源失败不清空已取得数据，按 §4、§5、§8 的「未取得」规则逐项标注。
