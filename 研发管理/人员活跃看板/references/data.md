# 人员活跃看板 · 数据定义

> 产品视角的数据定义，判定规则见 [business-rule.md](business-rule.md)。本模块不新增可编辑单据，以下实体均为按日汇总或只读引用的查询投影。

## 1. 实体关系

| 实体 | 归属 | 关系 |
|------|------|------|
| 人员活跃日记录 | 本模块新增（汇总投影） | 统计人员 1 : N 活跃日记录，每人每自然日一条 |
| 角色指标快照 | 本模块新增（外部只读投影） | 统计人员 1 : N 角色指标快照，每人每统计月一条 |
| 统计人员 | 只读引用用户权限中心组织树与主职任职 | 组织节点 1 : N 统计人员（按主职从属） |
| 项目管理成员 | 只读引用[项目管理](../../项目管理/references/data.md) | 统计人员 N : 1 项目管理成员（身份对应，结果须唯一） |
| 排期卡片与操作流水 | 只读引用[功能排期管理](../../功能排期管理/references/data.md) | 统计人员 1 : N 卡片（按负责人） |
| Qoder 用量日快照 | 只读引用 [Qoder 用量分析](../../Qoder用量分析/references/business-rule.md#1-公共筛选与日期约束) | 汇总进人员活跃日记录，不另存副本 |

## 2. 人员活跃日记录

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|---------|------|:---:|---------|
| 统计人员 | 门户用户身份 | 引用 | 是 | 只读，来自组织树主职任职 |
| 统计日期 | 自然日（东八区） | 日期 | 是 | 每人每日唯一 |
| 身份对应状态 | 与项目管理成员的对应结果 | 枚举 | 是 | 见 §4.1 |
| 考勤状态 | 当日考勤 | 枚举 | 是 | 见 §4.2 |
| 请假时长 | 当日请假时长 | 时长（小时） | 否 | 仅请假不足一个工作日时有值 |
| 是否工作日 | 工作日历判定 | 布尔 | 否 | 工作日历未取得时为空，不按星期推测出勤 |
| Git 提交次数 | 当日有效 Git 提交次数 | 整数 | 否 | Git 来源未取得时为空 |
| 云效需求创建次数 | 产品人员当日创建的云效研发需求数 | 整数 | 否 | 产品来源未取得时为空；非产品不适用，计 0 |
| 云效需求取得状态 | 云效创建事实是否完整 | 枚举 | 是 | 已取得 / 未取得 / 不适用 |
| 提交总次数 | Git 提交与产品云效需求创建合计 | 整数 | 否 | 全部适用提交来源完整时相加，否则为空 |
| 新增行数 / 删除行数 | 当日有效 Git 提交的行数 | 整数 | 否 | Git 未取得时为空；需求创建不折算行数 |
| 提交信号状态 | 提交活动信号结果 | 枚举 | 是 | 见 §4.3 与 [业务规则 §4](business-rule.md#signals) |
| Qoder Credits | 当日 Credits 合计 | 数值（2 位小数） | 否 | Qoder 信号未取得时为空 |
| Qoder 请求数 | 当日请求次数 | 整数 | 否 | 同上 |
| Qoder 信号状态 | Qoder 用量信号结果 | 枚举 | 是 | 见 §4.3 |
| 卡片领取数 / 卡片完成数 | 当日该人员的领取、完成动作次数 | 整数 | 是 | 无动作为 0 |
| 活跃日等级 | 当日判定结果 | 枚举 | 是 | 见 §4.4 |
| 汇总时间 | 本条记录生成时间 | 时间 | 是 | 每日凌晨汇总前一日 |

### 2.1 云效需求创建事实（只读）

云效需求创建事实按创建人对应统计人员，1 名人员可对应多条需求；每条需求仅计一次，详见 [业务规则 §4.1](business-rule.md#requirement-creates)。

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|---------|------|:---:|---------|
| 云效组织 | 需求所在云效企业 | 引用 | 是 | 与工作项唯一标识共同去重 |
| 工作项唯一标识 | 原始需求身份 | 标识 | 是 | 不以标题或项目内编号代替 |
| 所属云效项目 | 需求项目归属 | 引用 | 是 | 仅消费已授权统计范围 |
| 工作项类别 | 是否为研发需求 | 枚举 | 是 | 本投影只收研发需求，其他工作项不计入 |
| 原始创建人 | 云效创建账号 | 标识 | 是 | 必须唯一对应产品角色统计人员，不以负责人代替 |
| 原始创建时间 | 云效成功创建的时间 | 时间 | 是 | 含明确时区，按东八区自然日归属，不以修改时间代替 |
| 身份对应结果 | 创建人与人员是否唯一匹配 | 枚举 | 是 | 已对应 / 未对应 / 歧义；未对应或歧义不猜测归人 |

## 3. 角色指标快照

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|---------|------|:---:|---------|
| 统计人员 | 门户用户身份 | 引用 | 是 | 只读 |
| 统计月 | 指标所属自然月 | 年月 | 是 | 每人每月唯一 |
| 角色 | 外部效能平台人员角色 | 枚举 | 否 | 见 §4.5；未登记角色时为空 |
| 角色指标 | 各角色指标项的当月与全年值 | 数值 / 百分比 / 时长 | 否 | 指标项清单见 [business-rule.md §8](business-rule.md#role-metrics)，值与口径只读取自外部效能平台 |
| 取得状态 | 本条快照的来源状态 | 枚举 | 是 | 已取得 / 未取得；单项缺失时该项为空并展示「未取得」 |
| 同步时间 | 最近一次从外部效能平台取得的时间 | 时间 | 是 | 按日同步 |

### 3.1 提交散点查询投影（只读）

每人每查询期间一条，不新增持久实体；分别汇总 Git 与适用于产品的云效需求创建事实，代码均值仍只用 Git 次数作为分母。计算与排除规则见 [business-rule.md §7.1](business-rule.md#commit-scatter)。

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|---------|------|:---:|---------|
| 统计人员 | 点代表的人员 | 引用 | 是 | 复用组织范围与身份对应 |
| 查询期间 | 共用筛选中的起止日期 | 日期区间 | 是 | 与看板其他视图一致 |
| 期间提交总次数 | 散点横轴，Git 与产品云效需求创建合计 | 整数 | 否 | 任一适用提交来源未取得时为空 |
| 期间 Git 提交次数 / 云效需求创建次数 | 两类提交来源计数 | 整数 | 否 | 来源取得状态各自独立 |
| 期间新增行数 / 删除行数 | 提交增删汇总 | 整数 | 否 | 取同一完整有效提交集合 |
| 次均代码提交量 | 散点纵轴，新增行 / Git 次 | 数值 | 否 | Git 完整且 Git 次数大于 0 时计算；仅需求提交时为「-」 |
| 提交数据状态 | 是否可绘制点 | 枚举 | 是 | 可绘制 / 无提交 / 仅需求提交 / 提交数据未取得；Git、产品云效创建与考勤、Qoder 完整度分开 |

## 4. 枚举

### 4.1 身份对应状态

| 值 | 含义 |
|----|------|
| 已对应 | 唯一对应一名项目管理成员 |
| 身份未登记 | 项目管理中无对应成员 |
| 身份待核对 | 命中多名项目管理成员 |

### 4.2 考勤状态

出勤、请假、休息日、考勤异常、未取得；判定与背景见 [business-rule.md §5](business-rule.md#attendance)。

### 4.3 信号状态

| 值 | 含义 |
|----|------|
| 成立 | 当日满足该信号条件 |
| 不成立 | 已取得数据但不满足条件 |
| 未取得 | 身份未对应、来源失败或未覆盖该日 |

### 4.4 活跃日等级

绿（活跃）、黄（部分活跃）、红（不活跃）、休息、未取得；判定顺序见 [business-rule.md §6.1](business-rule.md#day-level)。

### 4.5 角色

开发、产品、测试。

### 4.6 周期等级

绿、黄、红、无应出勤、未取得；判定见 [business-rule.md §6.2](business-rule.md#period-level)，不落库，查询时计算。
