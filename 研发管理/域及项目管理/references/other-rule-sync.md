# 域及项目管理 · 结构同步规则

<a id="sync"></a>
## 1. 来源与过程

结构同步读取已批准接入的代码托管组织或代码组范围，域取仓库清单，项目取每仓版本树的一级目录。来源范围和凭据沿用公共接入体系，不由模型猜测组织、账号或路径。

- 仓稳定标识、远端精确名称、默认分支和存在性由来源取得；一级目录读取使用该仓明确的同步基准分支，页面显示实际基准与核验时间。
- 仓列表、成员或目录分页必须完整读取；仅第一页、不完整树或部分响应不能作为完整清单。
- 同步只读取结构信息，不在工作区克隆或生成项目目录，不显式或隐式创建 `.build`、构建缓存或安装依赖。
- 每次提交展示活动任务与逐仓结果；已存在活动任务复用，不通过重复点击创建并发任务。页面离开不取消已受理任务，重新进入取得真实状态。
- 同步后自动新增来源对象，保留首次发现与最新完整核验信息；新对象默认停用，负责人、备注和执行映射不靠来源名称自动补造。
- 结构新增不自动扩展任何个人授权、报告触发或巡检开关。

## 2. 逐仓保存与异常

- 来源范围完整成功后才可确认域消失；该仓完整目录读取成功后才可确认项目消失。读取失败保留上次已核验结构及时间，展示本轮失败，不刷新成功日期。
- 一个仓的资料和一级目录完整结果按该仓保存；该仓失败不伪造空目录或删除项目，其他完整成功仓可保留结果，并明确整体部分失败。
- 仓名称冲突保留不同稳定身份，不按首项选择。未取得唯一身份或默认分支时明确阻断该仓核验。
- 断网、无访问权、外部限流或执行中断都不是来源删除证据。失败原因安全展示，允许具权限人员重新同步。
- 业务启停、负责人或执行映射并发变更时，同步只更新来源事实，不以旧值覆盖人工维护字段。

## 3. 目录变化与引用保护

- 仓更名沿用稳定仓身份并更新展示名，特殊域资格规则仍绑定原身份。
- 同仓同一级目录路径重新出现时沿用已存在身份和历史记录，但不凭重新出现自动恢复业务启用或权限。
- 路径更名无稳定目录身份可确认时，旧路径记来源消失、新路径作为停用对象同步；只有取得明确更名证据并由管理员确认，才允许关联历史身份与责任，不按同名、相似名或位置顺序猜测。
- 目录移到另一仓不静默迁移负责人、成员或报告key；分别核对源与目标身份、责任及历史范围。
- 来源确认消失后停止新业务使用，保留稳定历史引用并触发人员权限重算。项目、卡片、审批和报告不因目录消失删除。

<a id="dependency-gate"></a>
## 4. 公共接入边界

[已登记云效渠道](../../../../busyming-skills-common/api/mmhm/devops/阿里云渠道/references/code-flow-api.md)能够描述仓库查询，但该文档未登记一级目录树的完整读取契约；现有排期分支和commit能力不等于结构读取已可用。

完整代码仓结构读取、通用Git结构读取与稳定身份/更名证据都需从已获授权的公共入口核验。无法取得完整树时只展示来源核验缺口，不允许人工捏造项目清单、不直接在业务规则嵌入接口报文或绕过公共层调用第三方。

缺少可访问真源阻断真实结构同步接入及生产验收；离线原型只验证结构读取结果的展示与交互，不以模拟数据声明远端同步成功。规则定稿和原型可操作均不证明生产联动已实现。
