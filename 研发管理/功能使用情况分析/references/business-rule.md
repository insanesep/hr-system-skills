# 功能使用情况分析 业务规则

> 本文件是[功能使用情况分析](../SKILL.md)三个菜单功能共用的业务规则真源，统一事件采集、统计、打标、功能注册与权限口径；页面正文归各菜单功能。

## 产品背景

现有 RBAC 只规定了「谁能用」，但缺失「谁真的在用、用得多还是少」的闭环观测：新功能上线后多少人在用？同一报表究竟是哪个角色在用？哪些功能可以下线、哪些应加入工作台宫格？

功能使用情况分析按 RBAC 三层模型延伸一层「行为事实层」：记录各业务系统的前端事件 → 聚合成使用情况 → 自动打标（高/中/低频、广度、角色偏好），为产品迭代与权限优化提供量化依据。DevHub 自身与其他业务系统（Web 管理后台、门户微应用、App）统一经埋点 SDK 接入，按接入系统隔离查看。

## 数据模型

本模块包含 4 个实体，与用户 / 角色 / 权限体系协作。物理结构、字段、索引等实现细节以[表结构](../../../../busyming-devhub/docs/2026-10-29/liucao/2026-10-29-usage-tracking.sql)与代码仓为准，不内嵌。

| 实体 | 职责 |
|------|------|
| 接入系统 | 上报来源登记：系统编码、名称、AppKey、允许来源域名、负责人、启停与最近上报时间；是流水、目录与打标的隔离维度（即本模块的「账套」） |
| 事件流水 | 记录每一次前端事件，是全部统计与打标的事实来源；采集项见 [§1.5](#15-采集信息) |
| 功能目录 | 接入系统 × 功能编码的注册表，记录首次上报路由与二级路由，与菜单权限对应；自动注册与运营补全元数据、启停的分工见 [§11](#11-功能目录自动注册机制) |
| 打标结果快照 | 三维度打标结果，按「接入系统 × 功能 × 统计周期」唯一，每次重算整期覆盖；固定阈值见 [§2](#2-打标算法三维度独立判定)，默认周周期见 [§3](#3-聚合周期) |

报表与流水查询均按接入系统、时间窗与筛选条件对事件流水实时聚合，查询跨度上限 90 天（见 [§6](#6-流水查询边界)）。

**登记一致性硬约束**：新增菜单时菜单权限、功能目录、前端路由表三处必须同步登记，不允许任一处缺失；路由元信息同时声明页面主功能编码（见 [§1.4](#14-功能编码命名规范)），浏览事件据此归类。本模块自身三个页面的编码前缀、路由与父权限同源关系见 [§1.4](#14-功能编码命名规范)；路由统一使用扁平短横线命名。

**保留期策略**：事件流水保留期与归档由 DBA 按需执行，不做自动分区滚动。用户 / 角色 / 权限的结构定义以 busyming-portal 代码仓为准。

全部接口的契约（参数、返回、错误码）以及后端责任矩阵、限流、权限校验的实现以[代码仓](../../../../busyming-devhub/busyming-devhub-service/src/main/java/io/busyming/basic/devhub/service/usage)为准，不内嵌；对外上报协议见[埋点接入 skill](../../../../busyming-devhub-web/sdk/usage-tracker/references/report-api.md)。

## 1. 埋点上报规则

### 1.1 事件类型与触发时机

| 事件类型 | 触发位置 | 功能编码取值策略 |
|----------|----------|------------------|
| `VIEW`（页面浏览） | 路由切换 / 首屏加载 | 路由声明的页面主功能；未声明时服务端按功能目录中同路由、以 `.VIEW` 或 `.PAGE` 结尾的启用功能归类，仍未命中记为空 |
| `CLICK`（点击） | 已声明功能编码的元素被点击 | 元素上声明的功能编码（必填） |
| `SUBMIT`（提交） | 表单成功提交 / 业务操作调用成功 | 调用时传入的功能编码（必填） |
| `STAY`（页面停留） | 离开页面（切换路由、关闭或隐藏后离开） | 同所离开页面的 `VIEW` |

- **未声明功能编码的点击不采集**（避免噪声）；禁用状态的元素不采集。
- 停留时长只累计页面可见时间，不足 1 秒不上报，上限 24 小时。
- **停留事件只承载时长**：不计入事件数、用户数、功能数与打标，仅用于路由聚合的「平均停留」。

### 1.2 批量与防抖

| 场景 | 规则 |
|------|------|
| 批量策略 | 本地队列 **≥ 20 条或每 5 秒** 触发一次上报 |
| 防抖 | 同一功能编码 3 秒内重复点击 / 提交视为同一次（前端防抖，避免连点污染频次） |
| 页面浏览去重 | 同一路由 3 秒内去重；仅查询串或锚点变化不算新的浏览 |
| 离开兜底 | 页面隐藏或关闭时以不阻塞卸载的方式发送剩余队列；仅收到服务端确认后移除事件，未获确认的事件保留原 ID 供下次加载补报 |
| 失败容错 | 网络异常时退避重试，连续 3 次失败后停止本页上报，事件暂存本地队列，下次加载自动补报 |
| 队列上限 | 500 条，溢出按先进先出丢弃最早记录；队列按接入系统隔离 |
| 单次上报上限 | 单次上报最多 50 条事件，超出整批拒绝 |
| 重复上报 | 每条事件携带客户端事件 ID，同一接入系统内重复 ID 视为重试，忽略不重复入库 |
| 限流 | 同一接入系统同一用户（未登录按会话）每秒最多 10 次上报请求，超限拒绝并由 SDK 稍后重试 |
| 补报时效 | 只接收 7 天内、且不晚于服务器时间 10 分钟的事件 |

### 1.3 信息来源与信任边界

| 信息 | 来源 | 信任 |
|------|------|------|
| 接入系统 | 服务端按上报携带的 AppKey 识别 | AppKey 无效或接入系统停用时拒绝；浏览器来源须在接入系统「允许来源域名」内 |
| 端类型、页面路由、功能编码、功能名称、事件类型、事件时间、页面标题、停留时长、自定义属性 | 前端 SDK 上报 | 采信前端传值，服务端按 [§1.4](#14-功能编码命名规范) 与协议约束校验 |
| 用户 ID、姓名、角色、手机号、所属组织 | 接入系统从自身登录态取值，经 SDK 随事件上报 | 采信接入系统传值；身份真实性由接入系统负责，DevHub 不回查用户中心 |
| 客户端 IP、操作系统、浏览器 / 容器 | 服务端从请求中解析 | 以服务端为准，前端不传 |

产研身份对照只读引用[项目管理 · 身份](../../项目管理/references/business-rule.md#identity)及[权限边界](../../项目管理/references/permission-rules.md#boundaries)；已核对基础归属引用[项目管理 · 清单](../../项目管理/references/business-rule.md#source)与[执行映射](../../项目管理/references/business-rule.md#execution-mapping)。不将菜单业务分类、功能编码或路由名称直接当作仓域 / 项目；无项目证据不把共享实现仓全部归某项目。全部业务用户的行为采集范围、门户 RBAC、账套、角色偏好与事件当时身份快照不变，不用当前产研名单或责任关系裁剪、回写历史行为。

- 接入系统隔离：流水、目录、打标与报表查询必须限定在所选接入系统内。
- 页面地址与来源页入库前去除查询串，避免带出令牌等参数；自定义属性不得包含令牌、密码、证件号等敏感信息。
- 手机号在页面与导出中脱敏展示（保留前 3 后 4 位）。
- 事件时间按东八区、精确到毫秒上报，仅接受约定的单一时间格式（格式以[上报协议](../../../../busyming-devhub-web/sdk/usage-tracker/references/report-api.md)为准）。

### 1.4 功能编码命名规范

- **格式**：功能编码采用「模块.页面.动作」三段式，全大写、点号分隔；需定位到组件时可扩展为「模块.页面.子区域.动作」四段
- **模块段选取原则**：与菜单权限同源。以本模块为例，父权限 `devhubRndManage` 对应编码前两段 `RND.MANAGE`；其他模块（如 `INVENTORY.REPORT.*`、`ANALYSIS.NEG_GP.*`）的模块段为业务域名，与菜单树上一级节点一一对应
- **页面主功能**：每个菜单页面声明一个以 `.VIEW` 结尾的页面主功能编码，浏览与停留事件归入该功能
- **App 端前缀**：App 端上报的功能编码统一加 `APP` 前缀（**硬性约束，未加整批拒绝**），用于区分 Web/App 来源；Web 端不加前缀，加了同样整批拒绝
- **本模块编码（三条）**：
  - `RND.MANAGE.USAGE_EVENTS.<动作>` —— 事务流水明细页（路由 `/portal/usage-events`，权限 `devhubUsageEvents`）
  - `RND.MANAGE.USAGE_REPORT.<动作>` —— 使用情况报表页（路由 `/portal/usage-report`，权限 `devhubUsageReport`）
  - `RND.MANAGE.USAGE_CATALOG.<动作>` —— 功能目录管理页（路由 `/portal/usage-catalog`，权限 `devhubUsageCatalog`）
- **其他模块示例**：
  - Web：`INVENTORY.REPORT.EXPORT`、`ANALYSIS.NEG_GP.QUERY`、`PRODUCT_APPLY.LIST.CREATE_NEW`
  - App：`APP.STORE_REQUEST.PRODUCT.ADD_TO_CART`、`APP.HARDWARE.MANAGE.BATCH_SEND`、`APP.WORKBENCH.NAV.CLICK`
- **入库校验**：事件写入时按上述格式校验功能编码——去掉 `APP` 前缀后为三段或四段、每段以大写字母开头且仅含大写字母 / 数字 / 下划线、总长不超过 128；点击与提交事件缺少功能编码同样整批拒绝
- **未注册编码**：上报的功能编码不在功能目录时走「自动注册」（§11），事件流水仍记录真实功能编码。仅当浏览 / 停留事件既未声明也无法按路由归类时记为空、报表归入「未归类」桶
- **埋点方式**：
  - **页面浏览自动上报**：Web 与 App 均在路由 / 页面切换时由 SDK 统一上报页面浏览与停留，**不需逐页 / 逐屏手工埋页面浏览**
  - **点击仅对已声明元素采集**：Web 在元素上声明功能编码（点击子元素向上查找最近的声明）；App 两种方式二选一——以埋点组件包裹触发元素（单按钮场景，首选），或在点击回调中以函数方式上报（适用于回调内有多个副作用、组件包裹会产生歧义的场景）

### 1.5 采集信息

| 分类 | 采集项 | 来源 |
|------|--------|------|
| 事件 | 事件 ID、事件类型、事件时间、功能编码、功能名称、触发元素文本、停留时长、自定义属性 | SDK |
| 页面 | 页面路由、二级路由（服务端归一）、页面标题、页面地址、来源页 | SDK / 服务端 |
| 用户 | 用户 ID、姓名、角色编码与名称、手机号、所属组织 | 接入系统登录态 |
| 会话与终端 | 会话 ID（每次打开浏览器标签或 App 冷启动生成）、设备 ID（本机持久）、屏幕分辨率、接入系统版本、SDK 版本 | SDK |
| 网络与环境 | 客户端 IP、操作系统、浏览器或容器（企业微信、微信、钉钉、Chrome 等） | 服务端解析 |
| 接收 | 接入系统、服务端接收时间 | 服务端 |

二级路由取页面路由前两个非动态段，纯数字、UUID、路由参数与单号类段视为动态段，例如详情页 `/requirement/detail/1024` 归入 `/requirement/detail`。

## 2. 打标算法（三维度独立判定）

聚合数据源：当前周期内的事件流水（不含停留事件），按接入系统、功能编码分组。

### 2.1 频次标签

按周期内该功能的事件总数与阈值比较判定：事件总数 ≥ 高频阈值为高频（`HIGH`），< 低频阈值为低频（`LOW`），其余为中频（`MID`）。

阈值（固定）：高频阈值 500，低频阈值 50。

### 2.2 人次标签

按周期内使用该功能的去重用户数与阈值比较判定：去重用户数 ≥ 广度上阈值为广（`WIDE`），< 广度下阈值为窄（`NARROW`），其余为中（`MID`）。未登录事件不计入用户数。

阈值（固定）：广度上阈值 20，广度下阈值 3。

### 2.3 角色偏好标签

按角色统计该功能在周期内的事件数，事件数最多的角色为头部角色；头部角色事件数占该功能事件总数之比 ≥ 角色主导比例时判定为角色偏好（`ROLE_BIASED`），并记录头部角色；否则为均衡（`BALANCED`），头部角色仍记录但不展示徽章。

阈值（固定）：角色主导比例 0.70。

### 2.4 边界与约定

| 场景 | 处理 |
|------|------|
| 周期内事件总数为 0 | 不参与打标，打标结果中无该功能 |
| 功能编码为空（未归类） | **不**参与打标 |
| 并列第一（两个角色占比相同） | 按角色编码字典序取第一个，保证幂等 |
| 角色为空（未上报角色） | 不参与头部角色竞争，但计入占比分母 |
| 某条快照缺失 | 下钻用功能目录兜底：事件数 / 用户数仍可计算，三维标签为空，前端展示「—」 |
| 角色在事件发生后被删除 | 仍按事件发生时记录的角色聚合（不回查当前角色） |

## 3. 聚合周期

| 周期 | 起止 |
|------|------|
| `DAY` | 自然日 00:00:00.000 ~ 23:59:59.999 |
| `WEEK`（默认） | 周一 00:00 ~ 周日 23:59 |
| `MONTH` | 自然月首日 00:00 ~ 末日 23:59 |

- 打标默认使用 `WEEK`，周期不对外开放配置；如需调整需发版。
- 报表的趋势与 KPI 迷你图按页面所选聚合粒度（日 / 周 / 月）切片，与打标周期相互独立。
- **跨周期查询**：路由下钻与打标清单取最近一期已生成的快照

## 4. 打标重算策略

| 触发时机 | 范围 | 方式 |
|---------|------|------|
| 每日 01:00 定时任务 | 每个启用的接入系统，前一日所在周期 | 整期重算并覆盖该周期快照；多实例仅一个执行 |
| 首次部署 / 数据补录 | 指定接入系统与日期所在周期 | 管理员经运维接口手动触发，不提供页面入口 |

**关键约定**：阈值采用固定值（见 §2），不对外开放运行时调整；历史快照保留原有标签语义。定时任务可经配置中心关闭。

## 5. 报表计算规则

所有指标限定在所选接入系统、时间范围、端、角色与功能内；停留事件不计入事件数、用户数与功能数。

### 5.1 KPI 卡

| 指标 | 口径 | 迷你图 |
|------|------|------|
| 总事件 | 查询区间内的事件条数；副文显示日均 | 各时间桶事件数 |
| 活跃功能 | 查询区间内的去重功能数（不含未归类）；副文显示功能目录启用数 | 各时间桶去重功能数 |
| 活跃用户 | 查询区间内的去重用户数（不含未登录）；副文显示当前周期角色偏好功能数 | 各时间桶去重用户数 |
| 不活跃功能 | 功能目录启用项中查询区间内零触发的功能数；副文显示占启用比例 | 各时间桶零触发启用功能数 |

### 5.2 趋势图

- 按聚合粒度切片（日 / 周 / 月），周桶以周一为起点、月桶以月初为起点；无事件的桶补 0，至少返回 1 个点
- 双 Y 轴：左轴事件数、右轴活跃用户数

### 5.3 TOP 功能柱状

- 默认按事件总数降序，取 **Top10**，标签为「功能名 · 二级路由」
- 功能编码为空的事件合并为一行「未归类」，参与排名

### 5.4 路由聚合主表

| 列 | 计算 |
|------|------|
| 路由 | 按二级路由分组，附页面标题 |
| 功能数 | 该路由下出现过的去重功能数（未归类桶按 0 计） |
| 事件数 | 该路由下事件总数 |
| 用户数 | 该路由下去重用户数 |
| 占比 | 该路由事件数 ÷ 总事件数，保留 4 位小数 |
| 平均停留 | 该路由停留事件的平均时长，无停留事件为空 |
| 状态 | 功能目录启用项所在路由在区间内零触发时为 `INACTIVE` |

默认按事件数降序、零触发置末尾，支持「仅未触发」筛选。

### 5.5 路由下钻

- **交互方式**：在路由聚合表当前行下方展开嵌套二级表，不跳转页面
- **触发**：点击操作列「下钻」按钮或表格内置展开 / 收起按钮，切换展开 / 收起
- **数据加载**：首次展开时按该路由与当前筛选条件异步加载
- 返回该路由下全部功能明细（含功能编码为空的一行「未归类」，以及该路由下零触发的启用功能）
- **嵌套表列**：功能编码 | 功能名称 | 事件数 | 用户数 | 三维标签
- 三维标签取最近一期打标快照，缺失为空

### 5.6 打标清单

- 列出最近一期快照中的功能，按周期事件数降序，可按频次、人次、角色偏好任一维度筛选
- 点击任一徽章即按该维度值筛选清单

## 6. 流水查询边界

| 场景 | 处理 |
|------|------|
| 未选择接入系统 | 默认上次选择，其次 DevHub 自身，其次第一个接入系统 |
| 未指定时间范围 | 流水默认近 24 小时；报表默认近 30 天（含今天） |
| 跨度 > 90 天 | 拒绝查询（避免全量扫描） |
| 用户筛选 | 用户 ID 精确或姓名前缀匹配，联想取近 90 天活跃用户 |
| 路由关键词模糊查询 | 仅支持前缀匹配，不支持任意位置模糊匹配 |
| 功能筛选选择「未归类」 | 筛选功能编码为空的事件 |
| 导出 ≤ 5 万行 | 直接下载 CSV（UTF-8 带 BOM，Excel 可直接打开；公式字符开头的单元格加防注入前缀） |
| 导出 > 5 万行 | 不直接下载，提交到导入导出中心的离线导出任务，完成后在任务列表下载 |

| 场景 | 处理 |

| 浏览 / 停留事件未声明功能编码 | 按功能目录同路由页面主功能归类；未命中记为空入库 |

## 9. 异常与降级

| 场景 | 处理 |
|------|------|
| 埋点上报超时 / 网络异常 | 前端退避重试 3 次，仍失败暂存本地队列，下次加载补报 |
| AppKey 无效、接入系统停用或来源不在白名单 | 拒绝；SDK 停止本页上报并保留本地队列 |
| 单批事件部分字段非法 | **整批拒绝**并返回第几条与原因（前端需保证质量，避免拆分重试逻辑复杂化）；SDK 静默丢弃该批，不向业务界面提示异常 |
| 限流组件不可用 | 放行，由单批上限与应急熔断兜底 |
| 功能自动注册失败 | 仅告警，事件照常入库 |
| 打标任务失败 | 单个接入系统失败记录错误日志，不影响其他接入系统 |
| 打标结果为空 | 报表降级，三维标签全部为空，前端展示「尚未生成标签」 |

埋点 SDK 是旁路观测能力：初始化、采集、缓存及上报异常均在 SDK 内部消化，不弹出异常提示，不将异常抛向业务调用方，也不影响路由、点击、提交或卸载流程。业务操作不等待上报结果；仅接入方主动开启调试时记录诊断日志，上报失败后的队列、重试与暂停规则保持不变。

## 11. 功能目录自动注册机制

功能目录在本模块中不仅作为功能下拉字典，还承担「首次出现即入库」的自动注册职责。

| 维度 | 说明 |
|------|------|
| 触发点 | 埋点事件批量写入事件流水前执行功能目录自动注册 |
| 注册条件 | 本批事件中出现的功能编码不在该接入系统的功能目录中 |
| 写入方式 | 按「接入系统 + 功能编码」先查后写并加锁去重，已存在则忽略、不报错 |
| 功能名称兜底链 | 埋点上报值 → 元素声明名称 / 按钮文本 → 以功能编码占位（管理页标记「待补全」，运营人工补全）；占位名称在后续上报带出名称时自动补上 |
| 路由 | 记录首次上报的页面路由与二级路由，用于浏览事件归类与零触发路由统计 |
| 错误处理 | 最佳努力原则：注册失败仅记录告警日志，**不阻塞埋点主链路** |
| 默认值 | 默认启用、排序为 0、所属菜单权限为空（由运营手动关联菜单） |

**设计取舍**：自动注册采用同步登记而非异步队列，以降低运维复杂度。

**管理页与自动注册的分工**：自动注册只负责「有就不插、没有就插」的基础登记；人工运营通过功能目录管理页（[Web UI §3](../功能目录管理/references/web-ui.md#3-功能目录管理)）补全功能名称 / 所属菜单权限 / 排序并按需启停。两者互不冲突：管理页不开放新增 / 物理删除，避免与自动注册冲突。停用的功能不出现在筛选下拉、不参与不活跃统计与浏览归类。

## 12. SDK 接入与运维

本节说明埋点 SDK 的接入开关、本地模式、紧急熄火、后端限流熔断、新增 / 删除埋点流程与铺点优先级。在「自动注册」（§11）机制下，不另维护前端逐条埋点清单，功能目录即为事实来源。各系统的接入步骤、示例与排查统一见[埋点接入 skill](../../../../busyming-devhub-web/sdk/usage-tracker/SKILL.md)，SDK 实现见[源码](../../../../busyming-devhub-web/sdk/usage-tracker/src/index.ts)。

### 12.1 SDK 首次开启（真实上报）

**接入系统登记**：在功能目录管理「接入系统」页签登记系统并取得 AppKey；浏览器端接入填写允许来源域名（支持子域通配），App 原生请求留空。

**Web 端**：SDK 随应用启动初始化，自动监听路由切换上报浏览与停留，并挂载全局点击委托采集已声明元素；开启后按批量策略向上报接口发送。SDK 随 DevHub 发版提供脚本与模块两种引用方式。DevHub 自身经同一 SDK 接入，未配置 AppKey 时不启用。

**App 端**：应用启动时初始化并声明端类型为 App；按页面显示 / 隐藏上报浏览与停留；应用切到后台时自动发送队列中的剩余事件，冷启动补报本地缓存。

### 12.2 本地模式（默认，零网络副作用）

- 未配置上报地址时，Web 与 App 均只将事件输出到调试日志并暂存本地队列，不发起网络请求
- 用途：不配置上报地址的本地铺点、非生产环境调试、合规审计期「静默采集」

### 12.3 紧急熄火（运行时，不用发版）

| 端 | 操作 | 效果 |
|---|---|---|
| Web | 在浏览器本地存储写入 SDK 禁用标记后刷新 | SDK 初始化直接退出，零采集零网络 |
| App | 远端下发或本地写入 SDK 禁用标记后冷启动 | 同上 |
| 接入系统 | 在接入系统页签停用 | 服务端拒绝该系统全部上报，SDK 停止上报 |
| 恢复 | 清除禁用标记后刷新 / 冷启动，或重新启用接入系统 | 恢复正常采集 |

### 12.4 后端限流 / 应急熔断（配置热更新）

单用户上报限流阈值通过配置中心热更新：

| 场景 | 限流阈值 | 接口行为 |
|---|---|---|
| 正常 | 每秒 10 次（默认） | 单用户 ≤ 10 次/秒正常落库；超限拒绝 |
| 压力偏高 | 每秒 3 或 5 次 | 降低写库压力；超限拒绝 |
| **应急熔断** | **0** | 请求返回成功但全部事件标记为未接收；完全不落库、不触发前端重试 |

修改立即生效，无需重启。前端 SDK 收到「全部未接收」的回执后暂停上报 5 分钟（自愈熔断）。单次上报条数上限、补报时效与跨域回写开关同样经配置中心调整。

### 12.5 新增 / 删除埋点流程

**新增——Web**：在触发元素上声明功能编码（大写三段式），可附中文名称，不改业务逻辑；提交类操作在成功回调中调用提交上报。首次上报后后端自动注册到功能目录，运营在功能目录管理页补全功能名称即可。

**新增——页面**：新增菜单页面时在路由元信息中声明页面主功能编码（`.VIEW` 结尾），与菜单权限、功能目录同步登记。

**新增——App（组件包裹首选）**：用埋点组件包裹触发元素，声明功能编码与中文描述。

**新增——App（函数式兜底）**：在点击回调首行上报，必须容错兜底、不阻断业务逻辑。

**删除**：仅需移除页面中的埋点声明或上报调用；功能目录**保留记录**（仅改状态为停用），避免历史数据失联。

### 12.6 铺点优先级与命名检查

| 优先级 | 动作类型 | 原因 |
|---|---|---|
| 高 | 提交 / 保存 / 审核 / 删除 / 导出 / 分享 | 业务价值高，分析核心动作 |
| 中 | 查询 / 筛选 / 重置 / 刷新 | 反映使用频次 |
| 低 | 详情 / 跳转 / 展开 | 页面浏览已自动上报，点击埋点可选 |
| 不铺 | 翻页 / 排序 / 纯 UI 开关 / 关闭弹窗 | 噪声大、价值低 |

**命名检查清单**（参 §1.4）：三段式 / 全大写 / 与同模块动词风格一致 / 与功能目录中同名编码一致。
