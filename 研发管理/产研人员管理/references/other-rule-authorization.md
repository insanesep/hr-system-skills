# 产研人员管理 · 代码仓授权联动

<a id="policy"></a>
## 1. 权限政策与目标

自动开仓仅由有效产品角色触发；研发、架构、设计业务角色本身不自动新增仓权限。其既有独立授权仍受原管理体系校验，不因产研登记提升权限。

- 有效产品人员按[参与关系](business-rule.md#membership)取得有效域主仓集合，含直接域参与、有效项目所属域及有效负责人任命的参与范围；同域多项目只计算一次仓权限。
- 自动权限为普通分支读写，允许读取、克隆及按仓既有规则提交普通分支；不新增仓库管理、保护分支写入、合并审批豁免或发布权限。
- 最终授权档位应在公共渠道映射为满足本政策的现有权限角色；没有经核验的最小满足档位时停止开通，不能选择更高角色兜底。
- 关联实现仓不自动开通；只有该仓自身作为有效域参与时才进入目标。不能借实现映射扩大产品范围。
- 启用、重新启用、产品角色增减、归属和负责人变更、域项目停用及来源确认消失都重新计算目标。保留仍有效的同仓关系，不因移除一条项目关系误收回其他有效关系需要的仓。
- 目标与实际权限分开；保存人员只反馈人员业务状态已保存，不立即报告全部仓授权成功。

<a id="closure"></a>
## 2. 全部访问关闭

产品禁用、删除、退出域或移除产品角色后，对已经纳入该人员产品授权联动、且不再属于其有效产品目标的仓，关闭目标是该人员对该仓全部访问，而不只是撤销本功能新增的直接成员关系。

- 关闭须核验直接成员、人工授予、代码组继承及其他有效通路；移除直接成员后仍可访问不能判定关闭成功。
- 同人其他业务角色或独立授权仍要求该仓访问时，列出政策冲突并转管理员裁决，不静默保留访问、不擅自撤销其其他系统权限。管理员应按用户确认的全部关闭目标收口或明确记录不满足目标的原因。
- 代码组继承或公共共享策略不能由本功能擅自整体关闭；需要管理员在明确授权范围内处理该人员的有效访问，不影响组内其他人员和 unrelated 仓。
- common/design共享资料的开放、强制引用政策与人员关闭目标发生冲突时明确列为治理事项；不能通过删除公共资料、改变全组权限或放宽验收掩盖冲突。
- 外部成员写入失败、凭据无权、身份不明或读取不完整时显示未达目标；明确原因并保留重试或管理员处理入口，不把失败当无人授权。
- 多仓关闭逐仓核验，仅全部目标仓确认不可访问才反馈全部关闭；记录核验时间与依据，不把异步受理或旧成员快照当关闭证明。

## 3. 执行与审计

联动状态见[state-machine.md](state-machine.md#authorization-states)。每轮按人员、仓、最新目标版本执行，重复保存不重复新增有效授权；重试在当前目标上执行，不使用旧角色与旧归属复活权限。

快速连续启禁或迁域时，执行前及远端变更后再次核对最新目标；旧请求已生效的按当前目标纠偏，不能以过期成功回执覆盖最新关闭状态。

审计区分业务操作、远端权限变化及核验结果，展示授权来源、差异、操作者与时间；不输出令牌、密码、原始身份凭据或未经脱敏的外部资料。

人员禁用对本系统业务准入即时生效，外部仓实际关闭是待核验联动结果；本系统不能承诺撤回已经克隆到他人本机的资料，也不执行本机资料删除。

<a id="dependency-gate"></a>
## 4. 公共依赖门禁

当前[已登记云效渠道](../../../../busyming-skills-common/api/mmhm/devops/阿里云渠道/references/code-flow-api.md)包含组织、代码仓查询，但未提供代码仓成员增删改及完整有效权限关闭的公共契约。目录结构与成员继承读取的接入证据同样必须核对，不以原型、工具同名或文档存在推定可调用。

该缺口阻断自动开关仓权限的接入和验收；不得拿流水线或主机组成员接口代替代码仓权限，也不在业务模块编造公共接口、权限枚举、空契约或凭据配置。

公共能力负责人需提供并核验稳定人员映射、仓成员读写、继承权限检查、最小权限档位及有效访问核验的真源；取得授权并完成非生产验证后才能判定联动可用。本功能规则定稿不代表上述能力已登记或已运行。
