# 产研人员管理 · 业务规则

<a id="identity"></a>
## 1. 人员与身份

本功能是产研业务人员、角色、跨数据源身份及参与关系的唯一维护入口。门户账号、基础档案、组织任职和在职状态引用公共身份，不新增一套公司账号；业务档案删除、禁用不直接删除、禁用门户主账号。

- 新增人员从搜索弹窗进入：输入完整姓名，去掉首尾空白后按集团人员姓名精确匹配，不按工号、别名或姓名片段模糊检索。空姓名不提交集团查询，也不默认展示集团全量名单。
- 查询结果只包含公共身份有效且尚无产研档案的集团人员；已有档案按稳定门户标识过滤，包含启用、禁用和已删除。不同集团人员允许同名，同名已有人员不能导致其他同名但不同标识的人员被误过滤。
- 搜索结果显示姓名、工号、部门供区分，最多勾选一名。唯一勾选后下一步进入人员资料编辑页，集团身份以稳定标识带入并只读，不靠姓名再次取首人，也不允许在编辑页改选其他集团人员。
- 修改搜索姓名或重新查询清空原勾选；下一步须复核该人仍有效且未建立产研档案。下一步不提前创建档案、不授权，取消搜索或编辑不留下空档案。
- 编辑页直接访问、保存前及并发保存均复核集团身份和档案唯一性；已存在或已失效的身份拒绝新增，返回原档案维护或重新搜索，不通过修改地址或隐藏字段绕过过滤。
- 业务角色包含研发、产品、架构、设计，可在同一人员档案中并存；角色集合至少一项。角色是工作职责，不自动取得本功能管理权或仓库管理权。
- 新增默认禁用。已有业务档案不可重复新增；逻辑删除人员重新纳入时沿用稳定身份与历史关联，经核对后恢复为禁用，再执行启用。
- 姓名、工号、部门及门户状态只读引用公共档案；报告展示名可单独维护，不反写公共姓名。
- 身份映射固定按阿里云身份、Qoder身份、企业微信身份三个维度展示与维护；各维度记录对应外部系统的稳定账号标识及核验结果，不维护混合来源的通用身份输入框。
- 阿里云身份用于已核验的云效及代码仓用户关联；Qoder身份用于成员与用量归属；企业微信身份用于企微人员关联和触达。没有取得映射时明确显示未维护或未核验，不从姓名、另一系统账号或历史别名推断。
- 唯一性按来源系统与稳定账号共同校验。同一系统标识不可同时有效关联多人，冲突阻断保存；不同系统出现相同标识文本不等于同一身份，不跨系统判重。
- 修改映射不创建或修改外部账号，不以手工登记值作为已完成真实身份核验的证据；阿里云身份变更后，原身份仓权限与新身份分别重新核验，不沿用旧账号的授权成功结果。已发生的提交作者与报告归属保留原证据，历史别名不自动归入某个新维度。
- 共享账号不能自动归属个人。未匹配作者保留源事实并标记待核对，不凭负责人或操作人推定提交作者。

<a id="membership"></a>
## 2. 域项目参与关系

人员参与范围使用[域及项目真源](../../域及项目管理/references/business-rule.md#source)的稳定引用，可同时参与多个域与项目。项目归属域由真源派生，不手填第二份所属域。

- 人员可直接参与域，也可参与域内项目；参与关系记录职责及有效性，不等于负责人任命。
- 每个参与域或项目的身份必须是该人员基本业务身份集合的非空子集；身份指工作角色，不指阿里云、Qoder或企业微信账号。选项只来自已选基本角色，不能在参与关系中增加新的基本角色。
- 基本角色收窄后，已不属于基本身份的参与职责清空并标记待选择，不自动改为另一个角色；保存前须重新选择或解除相应参与关系。负责人职责不满足时仍按任命守卫交接，不因移除页签放宽校验。
- 前端角色选项联动和服务端保存、启用校验采用同一子集规则；即使请求含越界角色也拒绝，不只依赖下拉隐藏。
- 域与项目列表必须使用同步清单，候选不能由本页临时新增；来源已确认缺失、停用或未核验的对象不能新增为有效参与范围。
- 负责人关系只读来自[责任归属](../../域及项目管理/references/business-rule.md#responsibility)。有效负责人任命也构成其对应职责的有效参与范围，不要求手工再配同一关系；取消参与关系不能偷偷解除负责人任命。
- 人员详情显示直接参与域、参与项目、项目状态、负责人身份及每个项目的域负责人上级；一人跨域时可有多个项目上级，不合成为人资直属上级。
- 修改角色、参与关系或负责人任命后，按当前关系重算[仓授权目标](other-rule-authorization.md#policy)与报告范围，保留历史引用；同步失败不能恢复已失效的业务参与关系。

<a id="lifecycle"></a>
## 3. 生命周期与交接

人员状态及动作守卫见[状态规则](state-machine.md#states)。新增、编辑、启用、禁用与删除均记录操作人、时间、目标人员、变化内容和原因；删除为逻辑删除，不清除提交作者、报告版本、单据经办人或审计流水。

- 启用需公共账号有效、业务角色有效；具有产品角色时还需已核对有效域归属及云效身份，否则拒绝启用并说明缺口。
- 禁用、删除后立即退出新产研候选及本人员身份相关的新业务办理，退出后续报告名单；产品仓权限按[全部关闭规则](other-rule-authorization.md#closure)处理，不承诺外部权限即时完成。
- 删除不可使在途工作无责任主体。操作前列出域负责人、项目负责人、待办审批、待澄清卡、开发卡和未关闭工单的交接清单；唯一域负责人应先或随操作替换，在途流程按其所属模块完成交接。
- 人员持有其他有效角色、其他域参与关系或仍为负责人时，移除产品角色同样按最新角色目标关闭产品自动授权，但不删除其他职责。
- 外部公共账号已失效时，后续产研操作立即拒绝，标记交接异常；不能为等待交接而继续放行。系统不凭此自动重建在途审批链、代签或改变任务终态。
- 恢复及重新启用使用当前角色、归属和权限策略，不直接恢复旧授权快照。

<a id="report-scope"></a>
## 4. 报告人员范围

启用、未删除、公共身份有效且具有本功能业务角色的人员自动进入产研报告人员范围。研发、产品、架构、设计使用同一名单，一人多角色只计一次，不在报告配置或本机另建名单、文件或角色专属副本。

- 人员产出报告的日报、周报与 Qoder 用量分析的产研团队范围共同消费该名单；组织全部成员查询的已有权限与范围不因此改变。
- 人员启禁、角色或公共身份变更影响后续生成与当前人员候选。报告任务创建时取得有效名单、角色及身份映射版本，任务内使用同一快照；已归档正文、版本与当时人员范围不被当前变化覆盖。
- 已归档报告重新生成时产生新版本并记录本次范围，不偷偷修改旧版本或旧作者事实。
- 按实际职责分析产出：产品文档与需求办理、研发交付、架构公共规则与设计资产分别识别，不以提交多寡替代职责完成，也不把产品推进卡片当研发完成。
- 名单外身份不计入人员维度、不点名；名单内未取得某来源数据时显示未取得，不编造零用量或完成事实。源确认完整且无记录才可作为零活动。
- 名单为空时人员报告拒绝生成并提示到本功能维护；团队看板展示明确空态，不自动切全员扩大范围。
- 人员纳入报告、仓授权目标及远端授权成功独立。授权失败仍展示该有效人员及失败事实，不伪装成人员停用。
- 报告生成、版本、指标排序、域项目报告范围及查看权限归[报告配置](../../../研发报告/报告配置/SKILL.md)与各报告功能；本模块不自动生成每个人的需求文档或新增报告类型。

<a id="list-filter"></a>
## 5. 人员列表级联筛选

域、项目条件引用同步结构中的稳定对象标识；未选域时不能单独选项目，选择域后只可选择其一级目录项目。只选域时匹配直接参与该域或其项目的人员，负责人任命按既有参与关系计入；再选项目时仅匹配该项目的参与和责任关系，不因人员是域负责人自动推定其参与全部项目。

切换或清空域时清空项目；没有项目的域仍可按域查询。项目与当前域不一致的查询拒绝执行，不混合不同域的同名项目。域项目条件与其他已应用条件取交集，按稳定人员身份去重；筛选不改变业务参与关系、负责人、报告名单或仓权限。

<a id="history"></a>
## 6. 历史与消费边界

人员历史关联保持稳定，不因姓名、部门、角色变化改变已发生的责任。排期卡片提交人、开发人、审批人、故障处理人是各来源业务的事实，不用当前域项目负责人覆盖。

产研功能选择新的研发、产品等职责人员时引用本功能；非产研业务提交人或业务审批人仍使用公共身份，不强迫注册为产研人员。实际写入继续遵守来源业务的角色和功能权限。
