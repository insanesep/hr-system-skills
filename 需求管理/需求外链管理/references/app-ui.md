# 需求外链管理 · App 端 UI 描述

> 本文件承载本功能页面正文；全局约定见 [需求管理 · App 共享 UI](../../references/app-ui.md)，业务与权限规则见 [功能入口](../SKILL.md)。正文为产品目标要求，不以代码缺口删减；原型见本功能资产目录。

## 公开 H5

外部人在移动端浏览器凭外链免登录访问的单向采集端，仅服务有点推荐产品线；外链形态、字段边界、防刷与单向收口规则见 [other-rule-public-link.md](other-rule-public-link.md)，H5 附件规则见 [other-rule-attachment.md §5](../../references/other-rule-attachment.md#5-h5-附件规则)。

### H5 端能力边界

- **仅 3 个页面**：需求提交页 / 提交成功页 / 链接失效页
- **完全单向收口**：不提供进度查询、撤回、修改、草稿，不发任何短信或通知
- **无登录态**：不渲染侧边菜单、面包屑、顶部用户信息、退出登录等任何管理后台外壳，页面不经登录拦截
- **唯一入口**：凭内部人发放的专属链接访问；链接只携带 token，邀约信息全部由服务端按链接识别
- **三页共用同一专属链接**：按链接校验结果与提交结果在页内切换渲染，不设独立访问地址（防止外部人直达成功页或失效页伪造凭证）
- **不展示任何内部信息**：审批链、审批人姓名、业务线枚举、其他需求数据、内部组织架构一律不出现在页面中（邀约对象备注除外）
- **不展示状态、业务线与优先级**：外部人只在提交成功页看到需求编号；唯一对外可见的枚举是需求类型（5 类，不出现 `*`）

### 链接校验流程

进页第一件事是校验链接，校验结果决定渲染哪个页面，外部人无法绕过：

| 校验结果 | 渲染页面 | 说明 |
|---------|---------|------|
| 可用（待使用且未过期、未达提交上限） | 需求提交页 | 同时回填邀约对象备注与需求类型默认值 |
| 达提交上限（已提交） | 链接失效页 · 已提交 | 携带已产生的需求编号 |
| 已过期 | 链接失效页 · 已过期 | — |
| 已撤销 | 链接失效页 · 已撤销 | 不展示撤销原因 |
| 凭证缺失 / 非法 / 查不到 | 链接失效页 · 链接无效 | 与「已撤销」返回时延一致（防枚举） |

- 链接缺少凭证参数时不发起校验，直接渲染「链接无效」
- 校验期间展示整页骨架屏，不闪现表单
- 校验请求失败（网络异常 / 服务端错误）不等于失效：展示整页错误态 +「重新加载」，与失效页文案严格区分

### H5 页面间导航

| 来源 | 去向 | 触发 | 导航方式 |
|------|------|------|---------|
| 外部渠道（微信 / 企微消息、二维码扫码） | 需求提交页 | 打开专属链接且校验通过 | 浏览器直接打开 |
| 外部渠道（同上） | 链接失效页 | 打开专属链接且校验不通过 | 浏览器直接打开（同一链接内渲染切换） |
| 需求提交页 | 提交成功页 | 预览确认弹层内点「确认提交」且服务端返回成功 | 页面内容整体替换（Replace，不入历史栈） |
| 需求提交页 | 链接失效页 | 提交时服务端返回链接已失效或已达上限 | 页面内容整体替换（Replace） |

- 提交成功页与链接失效页均为终点页：不提供返回按钮与再次提交入口；浏览器后退回到提交页时重新走链接校验（此时已提交，落到失效页 · 已提交）

### 需求提交页

- **页面路径**：外链专属链接（唯一参数为 token，由外链管理生成）；与提交成功页、链接失效页共用同一地址
- **权限编码**：无（免登录，鉴权凭据即专属链接本身，准入见 [other-rule-public-link.md §4](other-rule-public-link.md#4-安全与防刷)）
- **导航方式**：浏览器直接打开；提交后页内 Replace
- **页面类型**：`form`
- **页面定位**：外部人一次性填写并提交需求——一屏回答「我是谁、我要什么」
- **区块职责**：
  - 顶部说明区（非导航栏，无返回按钮）：主标题「有点推荐 - 需求提交」；副标题灰字「本表单由 {邀约对象备注} 的邀约链接进入，提交后由内部团队评估处理」；常驻提示条「本链接**仅可提交 {N} 次**，提交后无法修改或撤回，请确认内容后再提交」（N 取链接提交次数上限）
  - 需求信息组：需求标题（单行）/ 需求描述（多行，实时字数「N/2000」，下方灰字「请说明你遇到的问题、期望的效果，以及大致的使用场景；描述越具体越容易被采纳」）/ 需求类型（选择器，默认值由链接携带）
  - 图片组（需求信息组下方）：标题「相关图片（N/3）」+ 灰字「选填」；引导文案「可上传问题截图或现场照片帮助内部团队理解；最多 3 张，单张不超过 5MB」；横向缩略图行（已选图片 + 右上角删除叉标，末位「+」添加卡，达 3 张时置灰并提示「最多只能上传 3 张图片」）
    - 🚨 点「+」直接拉起系统相册（支持多选），不弹选源面板、不调用相机、不申请相机权限
    - 上传中缩略图叠加半透明层 + 环形进度；单张失败置红边 + 中心感叹号，点击单张重试
    - 分组底部实时展示「已选 N 张，共 X.X MB / 上限 15MB」，超限时拒收最后一张并提示「本次提交图片总大小不得超过 15MB」
    - 页面不展示任何审核状态，外部人只看到「上传成功」
  - 提交人信息组：姓名（可用邀约对象备注预填，允许修改）/ 所属部门（自由文本，下方灰字「填写你所在的公司或部门名称即可」）/ 手机号（唤起数字键盘，下方灰字「仅供内部团队必要时联系你，不会收到任何短信」）
  - 验证组：图形验证码输入框 + 右侧验证码图片（点击图片刷新）
  - 底部固定操作栏（安全区内）：「提交需求」全宽主按钮；不提供暂存草稿与重置表单
  - 页脚灰字：「本页面为一次性邀约链接，请勿转发他人」
  - **不出现的元素**：文档上传、视频上传、拍照入口、业务线、优先级、目标完成日期、登录 / 注册入口、客服入口、进度查询入口
- **布局引用**：参见原型 [requirement-public-submit.html](../assets/app/requirement-public-submit.html)（整页范例 `busyming-skills-design/mobile/templates/form.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/form-grouped.tsx.tpl`）

#### 导航关系

- 来源页：外部渠道链接或二维码扫码（无站内来源）
- 去向页：提交成功页（提交成功）；链接失效页（链接在提交瞬间失效）
- 返回行为：无返回按钮；浏览器后退即离开本页，不做拦截
- 手势返回：允许（等同浏览器后退离开本页）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 链接校验 | 进入页面自动执行 | 否 | 整页骨架屏 | 渲染表单并回填默认值，无提示 → 停留 | 失效 → 切换为链接失效页；网络异常 → 整页错误态 +「重新加载」 |
| 刷新验证码 | 点击验证码图片 | 否 | 图片区局部 loading | 图片替换为新验证码，输入框清空 → 停留 | AcToast error「验证码加载失败，请点击重试」 |
| 添加图片 | 点「+」且已选少于 3 张 | 否（直接拉起相册） | 缩略图位蒙层 + 环形进度 | 进度跑满后取消蒙层，计数与累计大小同步更新，无提示 → 停留 | 单张置红边 + 中心感叹号，点击单张重试；超张数 / 超单张大小 / 超总大小 / 格式不支持时 AcToast error 展示具体限制，已上传图片与表单内容不受影响 |
| 删除已选图片 | 点缩略图右上叉标 | 否（外部人场景不加确认摩擦） | 缩略图位 loading | 缩略图行重排，计数与累计大小同步减少，无提示 → 停留 | AcToast error「移除失败，请重试」，缩略图保留 |
| 提交需求 | 全部必填字段校验通过 | **必须**：预览确认弹层，弹层内「确认提交」为真正提交动作 | 弹层确认按钮 loading + disabled | 页面整体替换为提交成功页（展示需求编号），不做延迟 | 按失败原因分流（见下表）+ 字段值保留 + 按钮恢复 |

**提交失败分流**：

| 服务端返回 | 页面处理 |
|-----------|---------|
| 验证码错误 | 关闭弹层，验证码输入框标红「验证码错误，请重新输入」并自动刷新验证码；连续错 3 次强制刷新并清空输入 |
| 图片相关 | 关闭弹层，图片组标红并展示服务端文案原文（超张数 / 超大小 / 格式不支持 / 图片已失效），表单其余字段保留，外部人可移除问题图片后重提；🚨 不消耗提交次数 |
| 链接已达提交上限 / 已过期 / 已撤销 | 关闭弹层，页面整体替换为链接失效页对应形态，不保留表单 |
| IP 限流 | 关闭弹层，整页 inline 提示「操作过于频繁，请 1 分钟后再试」，表单内容保留 |
| 审批链未配置 | 关闭弹层，AcToast error「提交失败，请联系邀约人处理」（不暴露内部原因），表单内容保留 |
| 其他服务端错误 | 关闭弹层，AcToast error「提交失败，请稍后重试」，表单内容保留；不自动重试（避免重复提交占用唯一次数） |
| 请求超时 | 弹层与「确认提交」按钮保持 loading 不解锁，提示「提交处理中，请勿重复点击，请稍后重新打开链接确认结果」（同下方交互约束） |

#### 提交前预览确认弹层

因提交后不可重填也不可修改，本弹层为**强制环节**，不可跳过、不提供「不再提示」。

- 形式：底部半屏弹层（占屏约 70%，内容超出可滚动）
- 标题「请确认提交内容」+ 红色小字「提交后**无法修改、无法撤回**，本链接也将失效」
- 内容区以只读信息行完整回显：需求标题 / 需求描述（全文不折叠）/ 需求类型 / 姓名 / 所属部门 / 手机号
- 已选图片时在需求类型下方追加「相关图片（N 张）」行，横向只读缩略图（不带删除叉标，可点击看大图）；未选图片时不渲染该行；存在上传失败图片时红字提示「有 N 张图片上传失败，确认提交将不包含这些图片」，仍可确认提交
- 底部按钮：左「返回修改」（次按钮）/ 右「确认提交」（主按钮），等宽
- 关闭方式：点击遮罩、下拉手势、「返回修改」三者一致，回到表单且不消耗提交次数
- 「确认提交」点击后立即 disabled 直到服务端返回，防止重复提交耗尽唯一次数

#### 表单校验

- 初态：需求类型预填链接默认值（可改）；姓名以邀约对象备注预填（可清空改写）；部门、手机号、标题、描述为空；图片为空（仅展示「+」添加卡与限制说明）；进页即请求一张图形验证码（5 分钟有效）；本页只有新建形态，不回填历史提交内容

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 需求标题 | 是 | 1–128 字 | blur | 「请输入需求标题（不超过 128 字）」 | 否 |
| 需求描述 | 是 | 20–2000 字，实时字数提示 | blur | 「请填写需求描述，不少于 20 字」 | 否 |
| 需求类型 | 是 | 选择器（新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成），默认值由链接携带 | change | 「请选择需求类型」 | 否 |
| 姓名 | 是 | 1–64 字，去首尾空格后非空 | blur | 「请填写你的姓名」 | 否 |
| 所属部门 | 是 | 1–128 字，自由文本，不做组织架构匹配、不提供下拉联想 | blur | 「请填写你所在的公司或部门」 | 否 |
| 手机号 | 是 | 11 位大陆手机号格式，仅格式校验 | blur | 「请填写正确的 11 位手机号」 | 否 |
| 图形验证码 | 是 | 4 位，大小写不敏感，服务端校验，一次性消费 | 提交时 | 「请输入验证码」/「验证码错误，请重新输入」 | 是（提交时服务端校验） |
| 相关图片 | 否 | 类型、单张大小、张数与总大小见 [other-rule-attachment.md §5](../../references/other-rule-attachment.md#5-h5-附件规则)；仅相册选图 | 选择后立即 | 「图片最多 3 张」/「单张图片不得超过 5MB」/「本次提交图片总大小不得超过 15MB」/「不支持的图片格式」 | 是（经带链接校验的上传通道上传） |

- 提交成功跳转：页面内容整体替换为提交成功页，不做延迟、不用提示中转（避免用户误关页面而看不到需求编号）
- 提交失败展示：按上方失败分流处理，字段值保留，仅验证码按失败原因清空；提交时全表单校验，首个错误字段滚动至可视区并聚焦
- 脏数据离开：本场景不需要（无登录态、无草稿，拦截对外部人无意义且干扰体验）
- 键盘避让：描述与手机号输入聚焦时自动滚动至可视区，底部提交按钮随键盘上移
- SafeArea：底部提交按钮避开屏幕底部安全区

#### 交互约束

- 提交防重复保护不可省：按钮 disabled + 服务端对单链接提交计数做并发互斥
- 请求超时不解锁按钮，提示「提交处理中，请勿重复点击，请稍后重新打开链接确认结果」
- 页面不接入前端埋点以外的第三方脚本，不在浏览器本地缓存表单内容与已选图片（避免公用设备泄露填写人信息）；刷新页面后需重新选图
- 🚨 图片不阻塞提交：图片为选填；仅当存在上传中的图片时提交按钮置灰 + 下方灰字「图片上传中，请稍等」
- 图片上传必须经链接校验，与提交共用同一链接校验与 IP 限流计数；链接失效时上传直接报错，但不因上传失败就把页面切到失效页（仅提交返回失效时才整页切换）

### 提交成功页

- **页面路径**：与需求提交页同一专属链接内渲染切换，无独立访问地址
- **权限编码**：无（免登录）
- **导航方式**：页内 Replace
- **页面类型**：`detail`
- **页面定位**：给外部人一张提交凭证——一屏回答「提交上了吗、凭证是什么、然后呢」
- **区块职责**：
  - 成功结果区：成功插图 + 主标题「提交成功」
  - 需求编号区（视觉重点，最大字号）：标签「需求编号」+ `REQ-{YYYYMMDD}-{NNN}` + 右侧「复制编号」文字按钮；编号支持长按选中复制
  - 说明文案（灰色，3 行）：「请保存该编号作为提交凭证」/「内部团队将对需求进行评估，**处理结果由邀约人线下告知你**」/「系统不会向你发送短信或其他通知」
  - 底部提示（浅灰）：「本链接已完成提交，再次打开将不能再填写」
  - **不出现的元素**：查看进度、再次提交、返回、修改、客服 / 联系入口、任何指向内部系统的链接
- **布局引用**：参见原型 [requirement-public-result.html](../assets/app/requirement-public-result.html)（成功态，与失效态同一原型文件内切换；整页范例 `busyming-skills-design/mobile/templates/detail.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/detail-page.tsx.tpl`）

#### 导航关系

- 来源页：需求提交页（提交成功后页面内容整体替换）
- 去向页：无（终点页）
- 返回行为：页面不提供返回入口；浏览器后退将重新走链接校验，落到链接失效页 · 已提交
- 手势返回：允许（等同浏览器后退，重新走链接校验）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 复制编号 | 点击「复制编号」 | 否 | 按钮瞬时 loading（复制完成即恢复） | AcToast「需求编号已复制」→ 停留 | AcToast error「复制失败，请手动长按选中编号」，可再次点击 |

#### 交互约束

- 本页只依赖提交返回的编号，不再发起任何查询请求（单向收口，不给外部人任何查询通道）
- 刷新页面即离开本页（重新走链接校验），因此编号必须在页面上一次性给足且醒目

### 链接失效页

- **页面路径**：与需求提交页同一专属链接内渲染切换，无独立访问地址
- **权限编码**：无（免登录）
- **导航方式**：浏览器直接打开或页内 Replace
- **页面类型**：`detail`
- **页面定位**：告诉外部人「这个链接现在不能填了」，并把出路统一收敛到「联系邀约人」
- **区块职责**：
  - 状态插图（已提交为成功系插图，其余为失效系插图）+ 主标题 + 说明文案（按形态差异化，见下表）
  - 统一引导文案（灰色）：「如仍需提交需求，请联系向你发送链接的邀约人重新获取」
  - 「已提交」形态额外展示需求编号（可复制），其余形态不展示任何编号
  - **不出现的元素**：重试提交、返回、任何内部人员姓名 / 手机号 / 组织信息、撤销原因原文

| 形态 | 触发条件 | 主标题 | 说明文案 | 额外内容 |
|------|---------|-------|---------|---------|
| 已提交 | 链接已达提交上限 | 该链接已完成提交 | 你已通过本链接提交过需求，每个链接仅可提交 {提交次数上限} 次 | 需求编号（可复制） |
| 已过期 | 链接已过期 | 链接已过期 | 该邀约链接已超过有效期，无法继续提交 | 无（不展示过期时间） |
| 已撤销 | 链接已撤销 | 链接已失效 | 该邀约链接已被发放人收回，无法继续提交 | 无（不展示撤销原因与撤销人） |
| 链接无效 | 凭证缺失 / 格式非法 / 查无此链接 | 链接无效 | 链接不完整或已失效，请确认是否从邀约人处完整复制 | 无 |

- 「已撤销」与「链接无效」页面不得因形态不同产生可观测的加载差异（防枚举）；四类文案均不出现「审批」「业务线」「产品线」等内部术语
- **布局引用**：参见原型 [requirement-public-result.html](../assets/app/requirement-public-result.html)（失效态，与成功态同一原型文件内切换；整页范例与 DOM 依据同提交成功页）

#### 导航关系

- 来源页：外部渠道打开专属链接且校验不通过；需求提交页在提交瞬间收到链接失效
- 去向页：无（终点页）
- 返回行为：页面不提供返回入口；浏览器后退即离开本页
- 手势返回：允许（等同浏览器后退）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 复制编号 | 「已提交」形态点击「复制编号」 | 否 | 按钮瞬时 loading（复制完成即恢复） | AcToast「需求编号已复制」→ 停留 | AcToast error「复制失败，请手动长按选中编号」，可再次点击 |
| 重新加载 | 链接校验请求失败的整页错误态 | 否 | 整页骨架屏 | 重新校验并渲染对应页面 → 停留 | 整页错误态保留「重新加载」 |

#### 页面三态

- **空态**：不适用（本页即结果态）
- **加载态**：链接校验期间的整页骨架屏（与提交页共用，校验完成后才决定渲染哪一页）
- **错误态**：校验请求网络异常或服务端错误时展示错误插图 +「重新加载」；与四类失效形态严格区分，不得把网络错误误报为链接失效
