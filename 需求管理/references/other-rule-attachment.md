# 需求管理 · 附件管理

> 附件为需求描述的补充证据（截图 / 原型 / 说明文档 / 录屏），文件实体落 OSS，库内只存元信息。本文件为三端附件上传、存储、追加与删除规则的真源；附件字段见 [data.md §7](data.md#7-需求附件)，各端展示见 [web-ui.md](web-ui.md) 与 [app-ui.md](app-ui.md)。

## 1. 上传限制

| 类型 | 允许扩展名 | 单个大小上限 | 数量上限 | 开放端 |
|------|-----------|-------------|---------|--------|
| 图片 | `jpg` / `jpeg` / `png` / `webp` / `gif` | ≤ 10MB（H5 ≤ 5MB） | 内部端 ≤ 20 张；H5 ≤ 3 张 | Web / App / H5 |
| 文档 | `pdf` / `docx` / `xlsx` / `pptx` / `txt` | ≤ 50MB | ≤ 10 个 | **仅 Web** |
| 视频 | `mp4` / `mov` | ≤ 200MB | ≤ 3 个 | **仅 Web** |

- 数量上限**按类型分别计算**，不合并计数（单条需求最多 20 图 + 10 文档 + 3 视频）
- 校验以**服务端为准**：按上传来源端分别强校验扩展名白名单、大小上限与按类型分别计数的数量上限；附件类型由扩展名反推，不信任前端传值；前端限制仅作体验优化，不作为安全边界
- 安全边界为扩展名白名单 + 登录态 / 外链约束（内部端附件由前端直传，服务端不校验文件内容的 MIME 类型）；`exe` / `sh` / `bat` / `js` 等可执行扩展名不在白名单内，一律拒收
- App 端仅开放图片（相册 / 拍照），**不开放文档与视频**（移动网络下大文件上传成功率低，且缺少文件管理器语义）

## 2. 存储规则

- 内部端（Web / App）附件由前端取临时凭证**直传 OSS**，服务端只接收元信息并按 §1 强校验；公开 H5 例外，走服务端转存（§5）
- 上传不依赖需求已落库：新建表单即可上传，附件元信息随表单提交一并入库；未提交就离开产生的孤儿对象交 Bucket 生命周期规则回收
- OSS 按月分目录存放（具体路径规则以代码仓为准），便于批量回溯与生命周期管理
- 文件名 **UUID 化防重**：原始文件名仅作展示与下载回写，不进存储路径（避开中文 / 特殊字符 / 同名覆盖三类问题）
- 下载与预览一律走 **OSS 签名 URL**，由前端自签，有效期以前端实现为准（Web 端为 1 小时）；不暴露 Bucket 直链，不开放公共读；不提供服务端中转下载
- 鉴权前置在附件列表查询：无权查看该需求就拿不到附件存储标识，也就无法签出访问链接
- Bucket 名随附件记录，不取运行时配置，保证 Bucket 迁移后历史附件仍可访问

## 3. 内容安全审核

不做附件内容安全审核（图片 / 视频 / 文档均不过内容安全）：未删除的附件对有权查看该需求的人一律可见，三端不展示任何审核状态；内容风险依靠类型白名单 + 登录态 / 外链约束兜底。

## 4. 审批中追加附件

- 已提交（已提交 / 业务线审批中 / 实施确认中 / 产品确认中）的需求，**允许提交人追加附件**，用于响应审批人的补材要求，避免为了传一张图而驳回重提；已提交是提交后到 L1 审批人接手前的瞬时过渡态，同样按「追加」放行，避免提交人卡在纯技术状态上
- 追加的附件标记为「审批中追加」，详情页以「审批中追加」角标与提交时附件区分
- 追加成功后**自动通知当前级次全部审批人**（企微个人消息），文案「{提交人} 为需求 {编号} 补充了 {N} 个附件」
- 追加**不重置审批级次、不重建快照、不重算节点停留时长**（不得以追加附件刷新 SLA 计时规避催办，见 [other-rule-sla.md §1](other-rule-sla.md#1-催办触发)）
- 只能追加不能删除（§6）；外部单**不支持追加**（无登录主体，且链接已提交）
- 追加入口仅在 Web 端详情页提供

## 5. H5 附件规则

外部免登录提交（公开 H5）的附件能力为**受限开放**，与内部端口径不同。

公开 H5 是**唯一不走前端直传的端**：免登录拿不到临时凭证，且把 OSS 写凭证暴露给公网正是本节要防的存储滥用，故由服务端转存——外部人凭 token 上传图片，服务端转存 OSS 后**只返回元信息、不落库**，元信息随需求提交在**同一事务**内写入；转存与提交**共用同一外链校验链与 IP 限流计数**。

| 维度 | H5 口径 |
|------|---------|
| 类型 | **仅图片**（`jpg` / `jpeg` / `png` / `webp`）；文档与视频不开放 |
| 大小 | 单张 ≤ 5MB，**单次提交总大小 ≤ 15MB** |
| 数量 | 最多 3 张 |
| 提交时机 | 图片元信息随表单**一并提交**，需配合图形验证码校验通过；转存须带 token，不存在免验证的独立落库通道 |
| 上传人 | 无系统用户，上传来源记为 H5，上传人姓名取外部提交人手填姓名 |
| 内容安全 | 不做内容审核（§3）；风险控制为外链校验 + 图形验证码 + IP 限流 + 扩展名白名单 |
| 失败降级 | 图片上传失败**不阻塞需求提交**：需求主体先落库，失败图片写入失败审计事件，页面提示「需求已提交，部分图片上传失败」 |
| IP 限流 | 与公开提交入口共用同一限流计数（[other-rule-public-link.md §4](../需求外链管理/references/other-rule-public-link.md#4-安全与防刷)），不单独放宽 |

- 🚨 开放图片不改变[单向收口口径](../需求外链管理/references/other-rule-public-link.md#5-单向收口)：外部人不可查看已上传附件、不可删除、不可补传（提交即终止）

## 6. 附件删除

附件删除**一律只做逻辑删除，不从 OSS 物理移除**（异步清理失败会以「OSS 报错」形态掩盖业务首因），孤儿对象交 Bucket 生命周期规则回收。

| 需求状态 | 删除行为 |
|---------|---------|
| 草稿 | 提交人可删，仅逻辑删除 |
| 已提交（审批中 / 终态） | **不提供删除入口**；如内容不当需管理员介入，仅逻辑删除 |
| 已驳回后重提 | 历史附件全部保留且不可删；修改阶段只能新增（保证审批人能看到驳回时的原始材料） |

- 删除一律写事件审计，记录操作人与文件名
- 需求本体软删（草稿删除）时级联逻辑删除其全部附件
- 附件元信息随表单提交做全量同步：不在本次提交清单中的已有附件，**仅草稿态允许逻辑删除**，驳回重提**只能新增不能删**（与本表第 3 行一致）
