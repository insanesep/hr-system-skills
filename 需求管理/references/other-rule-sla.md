# 需求管理 · 审批时效与 SLA

> 解决「需求提上去就没人理」的治理缺口：以可配置阈值驱动自动催办与升级，并把时效沉淀为可计量指标。本文件为催办、升级、目标日期预警、滞留看板、SLA 仪表盘指标与定时扫描的规则真源；SLA 配置字段见 [data.md §8](data.md#8-sla-配置)，页面见 [web-ui.md](web-ui.md) 的 SLA 配置页与 SLA 仪表盘页。

## 1. 催办触发

- 审批节点停留时长超过催办阈值（默认 48h）仍未操作，系统自动向**当前级次全部审批人**发送企微催办消息（或签模式下同级多人均收到，任一人处理即停止催办）
- **停留时长起算点**：当前审批轮次进入本级的时间（即上一级通过时间；L1 取提交时间），与审批流水记录的节点耗时同源口径
- **自然时间计算**，不扣除周末与法定节假日（阈值本身已含缓冲，引入工作日日历会大幅抬高实现与解释成本）
- 只对**审批中**状态生效：业务线审批中 / 实施确认中 / 产品确认中；草稿、已提交（瞬时态）、待关联排期、已关联排期、已驳回均不纳入
- 追加附件、刷新页面、审批人查看详情等行为**均不重置计时**；仅当前级次发生通过 / 驳回 / 撤回才重算

## 2. 升级触发

- 节点停留超过升级阈值（默认 72h）仍未操作，系统通知**该审批人的直接上级 + 需求提交人**
- 上级取数：相关需求带有已核对项目、且审批人确有该项目产研参与关系时，上级可引用[项目管理 · 责任关系](../../研发管理/项目管理/references/permission-rules.md#boundaries)中的项目所属域负责人；人员身份与参与关系见[项目管理](../../研发管理/项目管理/SKILL.md)。无已核对项目或非产研审批人仍取公共组织中审批人所属部门的部门负责人，不靠姓名或实现仓猜项目，不回写 HR 组织；取不到有效上级时**降级通知实施负责人**（L2 审批人）兼作治理兼管人，不得静默丢弃。负责人变化只影响后续通知取数，不自动重建在途审批链或改写历史快照
- 外部单的「提交人通知」**改推邀约人**（对齐 [business-rule.md §4.1](business-rule.md#41-双通道推送) 与[单向收口](../需求外链管理/references/other-rule-public-link.md#5-单向收口)，不推外部人）
- 升级**不改变审批权限**：上级仅收到知晓消息，**不获得代审权**（代审会穿透审批链快照，与 [permission-rules.md §4](permission-rules.md#4-权限约束) 冲突）；如确需换人走管理员「审批链重建」（[business-rule.md §3.6](business-rule.md#36-快照机制)）
- 升级后**仍继续按催办窗口周期性催办**，直至节点被处理

## 3. 差异化配置

默认阈值矩阵（初始化写入，管理员可在「SLA 配置」页调整）。🚨 **优先级沿用本模块 `P0` / `P1` / `P2` / `P3` 枚举**，不引入第二套命名：

| 优先级 | 催办阈值（小时） | 升级阈值（小时） |
|--------|----------------|------------------|
| `P0` | 24 | 48 |
| `P1` | 48 | 72 |
| `P2` | 48 | 72 |
| `P3` | 72 | 120 |

- 三个级次（L1 / L2 / L3）默认**共用同一套阈值**，但配置支持按级次单独调整（如 L2 实施归集需更长思考时间可单独放宽）
- `P1` 与 `P2` 默认同口径（普通档），避免档位过细导致审批人无法预期
- 约束：升级阈值必须 **大于催办阈值**，且二者均为 1–720 的整数；保存时前后端双校
- 产品线必须等值命中，优先级支持通配降级；均未命中任何启用配置时按系统默认 48h 催办 / 72h 升级 / 24h 去重窗口执行（匹配顺序以代码仓为准）
- 系统预置 24 行默认配置（2 产品线 × 4 优先级 × 3 级次）
- **SLA 配置不做快照**（与审批链快照相反）：改后立即对在途需求生效

## 4. 目标日期预警

- 目标完成日期距今 **≤ 7 天**且需求仍未达已关联排期时，推送预警给 **L2 实施负责人**（全公司统一归集入口，最有条件协调资源）
- 预警文案：「需求 {编号}「{标题}」目标完成日 {目标完成日期} 仅剩 {N} 天，当前仍在 {当前节点}，尚未关联排期」
- 同一需求在整个预警窗口内（距目标日 7 天内）**每天最多推 1 次**，按自然日去重
- 目标完成日期已过且仍未达已关联排期时**持续日推**，文案改为「已超目标完成日 {N} 天」，直至已关联排期或已驳回
- 预警与催办**互不抵消**：两者触发条件与接收人不同，可同时发出
- 目标日期预警**同样纳入静默时段延后**（§7）：00:00–08:00 命中时延到 08:00 那轮仍属同一自然日，当天照发不丢；静默期内只记延后事件，不占去重窗口

## 5. 滞留需求看板

- Web 需求列表提供「滞留需求」视角：筛选条件为「**当前级次停留 ≥ 命中的催办阈值且未处理**」
- 默认排序：**停留时长倒序**（滞留最久的在最前）
- 可见范围沿用 [permission-rules.md §3](permission-rules.md#3-数据可见范围)：业务线负责人只看本业务线滞留单，实施负责人与管理员看全部；**不为本视角放宽任何可见范围**
- 看板行展示：停留时长（天 / 小时）/ 当前级次与审批人 / 已催办次数 / 是否已升级，支持导出
- 看板提供「手动催办」（管理员 / 实施负责人）：立即发一次催办，**共用 §7 去重窗口**（窗口内已催过则提示已催办时间，不重发）
- 🚨 **手动催办不受静默时段限制**（人在页面上主动点击，抑制发送违背操作意图），只受去重窗口约束

## 6. SLA 仪表盘指标

| 指标 | 取数口径 |
|------|---------|
| 各业务线平均审批耗时 | 按审批流水记录的节点耗时聚合均值，**按 L1 / L2 / L3 拆分**；可按产品线 / 业务线下钻 |
| 端到端平均周期 | **首次提交时间** → 达已关联排期的时间差均值；未达已关联排期的需求**不入分母**（避免在途单拉低均值） |
| 超时率 | **区间内节点实际耗时超过命中催办阈值的节点数** ÷ 区间内受理需求数，以百分数展示 |
| 趋势图 | 上述三项按**周 / 月**聚合；X 轴**按日期正序排列**（最早在左），不用 Top N 排序也不设「其他」汇总柱 |
| 当前滞留条数（实时） | 当前处于审批中且停留 ≥ 命中催办阈值的条数，**实时值，不受时间区间筛选影响**（区间筛选描述的是历史样本，滞留是「此刻」的治理压力） |

- **首次提交时间取自审批流水中的首次提交记录**，而非需求上记录的提交时间——后者在驳回重提时被覆盖，直接用会让端到端周期系统性偏短，恰好掩盖返工成本；流水取不到时退回需求提交时间
- 🚨 **超时率按节点实际耗时实算，不依赖是否发生过催办事件**——否则催办机制生效前的历史数据、静默延后的、推送失败的节点都会被误判为「未超时」
- 统计口径**默认含外部单**（对齐 [other-rule-public-link.md §6](../需求外链管理/references/other-rule-public-link.md#6-统计口径)），可按提交来源与产品线下钻
- 驳回重提的需求：审批耗时**按轮次分开统计**，端到端周期**取首次提交起算**（不因重提而重置，否则会掩盖来回返工成本）
- 与审批链配置页「审批统计」区块的分工：后者看**单一归属**的受理量 / 通过率 / 驳回率，SLA 仪表盘看**跨归属的时效横向对比与趋势**，指标不重复定义

## 7. 催办去重

- 同一需求同一级次同一审批轮次在一个催办窗口内（默认 **24h**，可配置）**仅发送一次**催办，避免逐小时骚扰审批人
- 去重维度：事件类型 + 需求 + 审批轮次 + 级次 + 催办窗口序号（停留小时数按窗口时长取整），具体去重标识规则以代码仓为准
- 🚨 **审批轮次必须参与去重**：驳回重提后停留时长归零、级次回到 L1，若不区分轮次，新一轮前几个窗口的去重标识会与上一轮已记录的完全相同，导致新一轮催办被永久去重跳过
- 升级消息（`SLA_ESCALATED`）**独立去重**，不与催办共用窗口计数；同一节点升级同样按 24h 窗口去重
- 级次变更（通过进入下一级）后去重计数**自然重算**；驳回重提靠审批轮次隔离
- 🚨 **静默时段（22:00–08:00）不发送也不占用去重窗口**：命中催办 / 升级条件时只记延后事件（`SLA_DEFERRED`），不记催办（`SLA_REMINDED`）/ 升级（`SLA_ESCALATED`）事件，延后事件不参与去重；静默结束后 08:00 那轮按正常流程重新判定并发送。若静默期占用了去重窗口，08:00 那轮必被去重跳过，催办将永远发不出去
- **手动催办不受静默时段限制**（§5），只受本节去重窗口约束
- 企微推送失败不重试不回滚，写推送失败审计；**失败也占用去重窗口**（否则企微持续异常时会在恢复后集中重发）
  - ⚠️ 此条**仅适用于真实尝试推送的场景**；静默时段属于「根本没尝试推送」，只记延后事件，**不占用去重窗口**

## 8. 定时扫描

- **每小时整点**执行一次扫描，检查全部审批中需求当前节点的停留时长，对比 SLA 配置触发催办 / 升级
- 同一次扫描一并处理 §4 目标日期预警，不另起扫描
- 单机执行、并发度 1；幂等依赖 §7 去重，**重复执行不会重发**；触发策略与执行细节以代码仓为准
- 🚨 **定时扫描不做业务判定外的任何写入**：不改需求状态、不改审批级次、不自动通过也不自动驳回（时效治理只推人，不代人做决策）；小时级扫描意味着**催办最大延迟 1 小时**，属可接受误差
- 流程中心通道单的催办同样由本扫描承接，流程中心节点催办全部关闭，见 [other-rule-flow-center.md §3](other-rule-flow-center.md#3-流程中心配置)
