# 需求管理 · 流程中心接入

> 审批流转接入流程中心（M4 外部表单模式），参考库存调整的流程中心接入实践；流程中心负责审批引擎与实例流转，依赖职责见 [SKILL.md](../SKILL.md) Prerequisites。**提交表单（提交对象选择 / 附件 / 外链 H5 / AI 面板）全部留在本模块**，仅审批流转引擎接入平台。本模块状态机见 [state-machine.md](state-machine.md)，审批链配置见 [business-rule.md §3](business-rule.md#3-审批链配置规则)。

## 1. 接入规则

- **新单全量经流程中心**：所有新提交单（内部 + 外部）审批流转全部经流程中心；自研审批引擎保留作回切兜底（总开关关闭即恢复自研接新单，见 §4 第⑦条）与外部单邀约人失效时的回退通道；自研通道单按自研快照走完，不回填流程实例
- **提交对象候选集收窄**：候选为有效产研产品人员与所选「产品线 × 业务线」下启用专属链的交集，按稳定门户身份去重；唯一规则见[business-rule.md §3.2](business-rule.md#32-专属链与默认链)。内部提交必中专属链，默认链不承接内部单
- **外部提交单以邀约人身份代提**：外部人无系统账号，以外链邀约人为发起人建实例（§4 第②条）；流程中心的发起人通知发给邀约人，与「结果由邀约人线下告知」的单向收口兼容，外部人零感知
- **自审场景接受平台原生行为**：提交人即链上审批人时，流程中心停在该节点由本人自行通过（多一步操作、语义不变）
- **页内审批权限收口平台**：命中流程单时页内「通过 / 驳回」豁免本模块快照权限校验，以流程中心判定为准（[permission-rules.md §4](permission-rules.md#4-权限约束)）
- **表单数据携带字段中文名**：提交与重提时随表单数据携带全部展示字段的中文名映射，随表单数据同快照入库，流程中心审批 / 详情页渲染中文名、无映射时降级显示原字段名；映射由本模块维护，平台不另建配置（防双真源漂移，对齐 §6）

## 2. 并行原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **本模块配置为镜像唯一真源** | 本模块审批链配置保持原样运行；流程中心模板链是它的逐条镜像（§3），**任何配置变更必须同步镜像**（纪律见 §6） |

## 4. 对接规则

**① 内部单建实例与重提**：内部单提交时，以提交人为发起人在流程中心建实例。

- 业务类型为需求，业务单号为需求编号（驳回重提沿用原编号，与平台「同业务单号防重 / 续审」口径兼容）；每次提交带幂等标识
- 表单数据必须包含链匹配与流转所需的需求编号、提交对象、产品线、业务线、需求类型、优先级、提交来源；同时携带标题、需求类型名称、优先级名称、业务线名称、提交对象姓名、目标完成日期、描述摘要，供审批详情只读展示
- 字段中文名映射须覆盖全部展示字段：需求编号、提交对象ID、产品线、业务线、需求类型、优先级、提交来源、需求标题、需求类型名称、优先级名称、业务线名称、提交对象、目标完成日期、需求描述、需求ID；内部单已有已核对产研域 / 项目引用时附只读展示名称与来源引用，不纳入链条件、不改写旧实例快照；外部单另补外部提交人、外部提交人部门、邀约人。新增或更名表单字段时本清单必须同步（并入 §6 镜像纪律）
- 建实例与续审一律在本模块业务事务提交后触发；建实例成功后由本模块补发群消息（[business-rule.md §4.2](business-rule.md#42-群消息推送规则)），失败则回退自研通道并补发全量通知
- 驳回重提（[state-machine.md §4](state-machine.md#4-驳回与重提)，可更换提交对象）：业务侧修改后对原实例发起续审并携带最新表单数据（提交对象可能已变，平台按新值重新匹配链）；禁止重新建实例

**② 外部单邀约人代提**：外部单（仅有点推荐外链）提交落库后，以**邀约人**身份建实例。

- 发起人为外链邀约人，须为在职系统用户；邀约人已离职或失效时回退自研通道并告警管理员
- 表单数据同 ① 必带项，但**不带提交对象**（外部单无提交对象），落默认·YDTJ 链；另带提交来源为外部、外部提交人姓名与部门、邀约人姓名供审批详情展示；字段中文名映射同 ① 清单（含外部单三项）
- 语义兼容：外部单驳回即真终态、不可撤回、不可重提（[state-machine.md §6](state-machine.md#6-外部提交单差异)）——平台驳回策略「退回发起人重提」仅表示允许发起人重提，本模块外部单无重提入口，驳回回写置为已驳回终态即闭环；平台发起人通知发邀约人，与[单向收口](../需求外链管理/references/other-rule-public-link.md#5-单向收口)天然兼容

**③ 双向审批同步**：

| 方向 | 规则 |
|------|------|
| 本模块页面 → 流程中心 | 页内「通过 / 驳回」命中流程单时，服务端以当前操作人身份代为调用流程中心审批，成功后才写本模块审批流水；页内交互不变；权限判定收口平台（[permission-rules.md §4](permission-rules.md#4-权限约束)），驳回意见不少于 10 字的校验保留；流程中心明确拒绝时向操作人透传平台错误文案；页内操作按钮显隐仍按本地快照判定（转审 / 加签受让人由流程中心待办承接） |
| 本模块页面 → 流程中心（撤回） | 页内撤回命中流程单时先代为调用流程中心撤回，失败则阻断本地撤回（防双通道分叉）；实例已回到草稿且为同一发起人时视为撤回成功 |
| 流程中心 → 本模块 | 订阅本模块模板的流程中心实例事件：节点通过 → 按映射级次推进当前级次与快照节点状态，推进至产品确认节点时按 [other-rule-ai-plan.md §2](other-rule-ai-plan.md#2-触发条件) 判定 AI 方案触发；流程完成 → 需求置为待关联排期（等待产品经理关联排期，[business-rule.md §5](business-rule.md#5-排期关联规则)）；驳回 → 置为已驳回并记录驳回原因；撤回 → 回到草稿；本模块当前级次已越过事件级次时跳过（幂等） |
| 并发防撞 | 平台侧幂等，业务侧以平台返回为准；审批流水记录操作来源通道（页内 / 流程中心） |
| 状态机映射 | 平台 6 态 ↔ 本模块状态机：审批中（`APPROVING`）↔ 业务线审批中 / 实施确认中 / 产品确认中（按节点顺序与链上已配置级次的**有序位置映射**回写，如 L1+L3 子集链第 2 个节点对应 L3）；已完成（`COMPLETED`）→ 待关联排期；已驳回（`REJECTED`）→ 已驳回；已作废（`CANCELLED`）→ 不回写（本模块无对应终态，作废由本模块删除 / 驳回通道承担）；瞬时态不映射（由本模块在节点推进时自行产生） |
| 个人通知让位 | 流程单的个人待办 / 结果通知由流程中心消息模板承担，本模块不再重复发送（防双发）；发送时点重新判断需求是否关联流程实例，回退自研通道的需求个人通知照常发出 |

**④ 页内审批进度渲染**：详情页审批进度条 / 时间线按本模块快照级次渲染，由实例事件回写同步快照节点状态，页内展示与自研通道一致。需求记录所关联的流程实例，未关联即为自研通道单。

**⑤ 提交对象候选集过滤**：有效产研产品人员与本归属有效专属链取交集，身份、去重与新提交复核统一见[business-rule.md §3.2](business-rule.md#32-专属链与默认链)，不并入默认链 L3 审批人；候选为空时阻断内部提交并提示核对人员与专属链。在途实例及 §3 已登记审批链不因人员、域负责人变化自动重建或换人。

**⑥ 自审处置**：流程单遇提交人即审批人的节点，由本人在流程中心待办或页内自行通过；本模块「提交人即审批人自动跳过」（[permission-rules.md §4](permission-rules.md#4-权限约束)）仅作用于自研通道单。

**⑦ 总开关与回切**：流程中心接入总开关开启即新单全量走流程中心（外部单含 ② 代提）；回切时关闭总开关即恢复自研引擎接新单，流程中心在途实例继续走完（快照隔离），不回切。前置条件：流程中心系企微消息模板须处于启用状态。

**⑧ 审批详情回跳**：流程中心审批详情「查看业务单据」以需求编号为锚点回跳本模块详情页；外部表单模式下审批人不可在流程中心编辑需求字段，修改由提交人在本模块完成（驳回重提语义不变）。

## 6. 配置镜像同步纪律

**本模块审批链配置的任何变更，必须同事务考虑流程中心镜像**：新增 / 修改 / 停用专属链或默认链后，同步维护流程模板的链与节点审批人 → 重新发布模板 → 链路预览回归（至少覆盖变更归属的专属链与默认链命中）→ 同步更新 §3 镜像表。**表单数据契约同理**：新增 / 更名 / 下线表单字段时，必须同事务检查链条件、字段中文名映射清单（§4 第①条）与平台快照展示效果。

两侧配置无强制同步机制，镜像滞后会导致需求错落链路、终审错人，本条纪律为唯一防线。
