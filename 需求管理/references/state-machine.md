# 需求管理 · 状态机

> 需求状态枚举、流转、级次递进、驳回重提与撤回的唯一真源。级次集合由提交时命中的审批链决定，见 [business-rule.md §3](business-rule.md#3-审批链配置规则)；操作的权限校验见 [permission-rules.md §4](permission-rules.md#4-权限约束)；流程中心通道的状态映射见 [other-rule-flow-center.md §4](other-rule-flow-center.md#4-对接规则)。

## 1. 状态流转

完整三级链的正向路径为：草稿 → 已提交 → 业务线审批中（L1）→ 实施确认中（L2）→ 产品确认中（L3）→ 待关联排期 → 已关联排期。任一审批中级次均可驳回为已驳回，内部单可重新提交回到已提交。

链上未配置的级次直接跳过，不产生对应状态与流水，例如专属链仅配 L3 时为「已提交 → 产品确认中」。

| 动作 | 起始 → 目标 | 执行人 | 规则 |
|------|------------|--------|------|
| 暂存草稿 | 新建 → 草稿 | 提交人 | 不生成审批链快照 |
| 提交审批 | 新建 / 草稿 → 已提交 | 提交人 | 生成需求编号，按 [business-rule.md §3.4](business-rule.md#34-匹配顺序) 匹配审批链并写入快照 |
| 匹配审批链 | 已提交 → 链上第一级的审批中状态 | 系统 | 内部单匹配提交对象专属链，外部单匹配默认链 |
| 审批通过 | 审批中 → 链上下一已配置级次的审批中状态；末级通过 → 待关联排期 | 当前级次审批人 | 递进规则见 §3；通过时可调整优先级，见 [business-rule.md §1.3](business-rule.md#13-流程约束) |
| 驳回 | 审批中 → 已驳回 | 当前级次审批人 | 见 §4 |
| 重新提交 | 已驳回 → 已提交 | 提交人（仅内部单） | 见 §4 |
| 撤回 | 已提交 / 业务线审批中 → 草稿 | 提交人（仅内部单） | 见 §5 |
| 删除草稿 | 草稿 → 记录逻辑删除 | 提交人 | 附件级联逻辑删除，见 [other-rule-attachment.md §6](other-rule-attachment.md#6-附件删除) |
| 关联排期 | 待关联排期 → 已关联排期 | 产品经理 / 管理员 | 仅功能类需求，见 [business-rule.md §5](business-rule.md#5-排期关联规则) |
| 解除关联 | 已关联排期 → 待关联排期 | 产品经理 / 管理员 | 仅功能类需求 |
| 转黑灯工厂 | 待关联排期 → 已关联排期 | 系统 | 缺陷修复单建单成功后，见 [business-rule.md §2](business-rule.md#2-缺陷修复需求分流) |

## 2. 状态定义

| 状态 | 编码 | 含义 | 当前级次 | 可执行操作 |
|------|------|------|---------|-----------|
| 草稿 | `DRAFT` | 草稿，仅提交人可见 | 0 | 编辑 / 提交 / 删除 |
| 已提交 | `SUBMITTED` | 已提交，等待系统匹配审批链（内部单匹配提交对象专属链，外部单匹配默认链） | 1 | 撤回 |
| 业务线审批中 | `BU_REVIEWING` | 业务线负责人审批中 | 1 | L1 通过 / L1 驳回 / 提交人撤回 |
| 业务线审批通过 | `BU_APPROVED` | 瞬时态 | 1→2 | 自动流转至链上下一已配置级次 |
| 实施确认中 | `IMPL_REVIEWING` | 实施负责人审批中 | 2 | L2 通过 / L2 驳回 |
| 实施确认完成 | `IMPL_CONFIRMED` | 瞬时态 | 2→3 | 自动流转至链上下一已配置级次 |
| 产品确认中 | `PM_REVIEWING` | 产品经理审批中 | 3 | L3 通过 / L3 驳回 |
| 待关联排期 | `PM_SUBMITTED` | 全部审批通过，待关联排期；缺陷修复单为待系统转黑灯工厂 | 链上最大级次 | 关联排期卡片（仅功能类） |
| 已关联排期 | `LINKED` | 已关联下游承接单（排期卡片或黑灯工厂工单），终态 | 链上最大级次 | 仅查看，排期状态 / 工单状态实时刷新；功能类可解除关联 |
| 已驳回 | `REJECTED` | 被驳回，终止态 | 保留驳回时级次 | 内部单：提交人重新提交；外部单：无（真终态） |

- 缺陷修复单在「待关联排期」「已关联排期」两态的展示名分别为「待转黑灯工厂」「已转黑灯工厂」，编码不变

## 3. 级次递进

- 当前级次记录当前待审级次：`0` 未提交、`1` 业务线审批、`2` 实施确认、`3` 产品确认
- 最大级次由提交时命中的审批链决定：默认链固定为 3；专属链取其配置的级次集合中的最大值，见 [business-rule.md §3.2](business-rule.md#32-专属链与默认链)
- 每级审批通过后流转至**链上下一个已配置级次**（非机械 +1，未配置的级次直接跳过）；达到最大级次且通过后置为待关联排期
- 业务线审批通过、实施确认完成为同事务内的瞬时中间态，用于流水记录与消息推送打点，前端不展示为独立状态与独立节点；级次被跳过时对应瞬时态不产生

## 4. 驳回与重提

- 任意级次均可驳回，驳回意见必填且不少于 10 字，意见记为需求驳回原因并写入审批流水
- 驳回后状态置为已驳回，保留驳回发生时的当前级次供统计分析
- 提交人可在已驳回状态下修改内容并重新提交：状态回到已提交，当前级次重置为**链上第一级**，重新生成审批链快照；重提时**可更换提交对象**（默认回填原值），更换后按新对象重新匹配审批链
- 重提沿用原需求编号，不新建需求记录；历史审批流水全部保留，按审批轮次区分
- **仅内部提交单可重提**；外部提交单的已驳回为真终态，见 §6

## 5. 撤回

- 已提交、业务线审批中两态下提交人可撤回，状态回到草稿，审批链快照作废
- 进入实施确认中及之后不允许撤回，需由审批人驳回
- 撤回记录写入事件审计，不写审批流水
- **外部提交单不支持撤回**：无账号即无撤回主体，且无草稿可回退

## 6. 外部提交单差异

外部提交单**不新增任何状态**，完全复用本文件的状态机，仅以下规则不适用：

| 不适用规则 | 原因 | 外部单实际表现 |
|-----------|------|---------------|
| 草稿态（§2） | 无登录态，无法回取未完成表单 | 提交即生成已提交，无暂存入口 |
| 驳回重提（§4） | 不回传结果，外部人无从得知驳回 | 已驳回即真终态，不提供重提入口 |
| 提交人撤回（§5） | 无账号主体 | 无撤回按钮，内部人也不得代撤回 |
| 提交人即审批人自动跳过（[permission-rules.md §4](permission-rules.md#4-权限约束)） | 外部人不可能是审批人 | 完整走 L1/L2/L3 三级，不会发生跳级 |
| 提交人结果通知（[business-rule.md §4.1](business-rule.md#41-双通道推送)） | 无企微身份且不回传 | 仅推送内部审批人与邀约人，不推外部提交人 |

**驳回后的价值回收路径**：外部单被驳回后如内部认为仍有价值，由**实施负责人新建一条内部单**并在描述中引用原需求编号溯源；**不提供「转内部单」功能**，避免状态机分叉与归属变更。
