# 需求管理 · 数据定义

> 面向产品视角定义本模块实体、字段语义与实体关系；表结构以代码仓为准，不在此描述，公共数据库定义由 busyming-skills-common 承载。需求状态见 [state-machine.md §2](state-machine.md#2-状态定义)，产品线与业务线见 [business-rule.md §1.1](business-rule.md#11-产品线与业务线)，其余枚举见 §12。

## 1. 实体关系

| 实体 | 关系 | 说明 |
|------|------|------|
| 需求 → 审批链快照 | 1:N | 每轮提交按命中审批链写入，同轮同级多行即或签 |
| 需求 → 审批流水 | 1:N | 只追加不删除，按审批轮次区分 |
| 需求 → 需求附件 | 1:N | 附件可先于需求上传，随表单提交归属 |
| 需求 → AI 方案记录 | 1:N | 按审批轮次隔离、版本递增 |
| 需求 → 开发会话记录 | 1:N | 每次关联排期生成一条，解除关联不回收 |
| 需求 → 事件审计 | 1:N | 撤回、关联、附件、推送、SLA、AI 等事件留痕 |
| 外链邀约 → 需求 | 1:N | 外部单由外链产生，单个外链的提交次数受上限约束 |
| 审批链配置 → 审批链快照 | 1:N 引用 | 快照生成后流转期间不再回查配置 |
| 需求 → 排期卡片 | N:1 | 只读引用功能排期卡片，见 [business-rule.md §5](business-rule.md#5-排期关联规则) |
| 需求 → 黑灯工厂工单 | 1:1 | 缺陷修复单只读引用工单，见 [business-rule.md §2](business-rule.md#2-缺陷修复需求分流) |
| 需求 → 流程中心实例 | 1:1 | 驳回重提续审原实例，未关联即自研通道单，见 [other-rule-flow-center.md §4](other-rule-flow-center.md#4-对接规则) |

## 2. 需求

| 字段名 | 业务含义 | 类型 | 必填 | 取值规则 |
|--------|----------|------|------|----------|
| 需求编号 | 需求业务编号 | 文本 | 提交后必填 | `REQ-{YYYYMMDD}-{NNN}`；提交审批时生成，生成后不可变，驳回重提沿用原编号 |
| 标题 | 需求标题 | 文本 | 是 | 1–128 字 |
| 描述 | 业务背景、当前痛点与期望效果 | 长文本 | 是 | 内部提交 10–2000 字；外部提交 20–2000 字 |
| 需求类型 | 需求分类，决定下游承接 | 枚举 | 是 | 见 §12；缺陷修复审批通过后分流黑灯工厂 |
| 优先级 | 处理优先级 | 枚举 | 是 | 见 §12，默认 `P2`；审批通过时可调整，以末级审批通过时的值为准 |
| 产品线 | 第一层归属 | 枚举 | 是 | 默认鸣鸣很忙；提交后不可修改 |
| 业务线 | 第二层归属 | 枚举 | 条件必填 | 仅鸣鸣很忙必选；有点推荐记为「不区分」，不展示不可选；提交后不可修改 |
| 产研域 / 项目引用 | 已核对的交付范围 | 引用 | 否 | 引用[域及项目管理 · 清单](../../研发管理/域及项目管理/references/business-rule.md#source)；项目所属域按真源关联，无项目证据不补造；不替代产品线、业务线，不新增审批链匹配维度或改写在途快照 |
| 提交对象 | 承接终审与排期关联的产品经理 | 人员 | 内部单必填 | 内部单提交时写入，草稿与驳回重提时可更换；外部单提交时为空，L3 通过时记为实际通过人 |
| 目标完成日期 | 提交人期望的完成日期 | 日期 | 内部单必填 | 不早于填写当天；外部单不采集 |
| 状态 | 当前状态 | 枚举 | 是 | 见 [state-machine.md §2](state-machine.md#2-状态定义) |
| 当前审批级次 | 当前待审级次 | 数量 | 是 | 0–3，见 [state-machine.md §3](state-machine.md#3-级次递进) |
| 最大审批级次 | 命中审批链的最大级次 | 数量 | 提交后必填 | 默认链为 3，专属链取其配置的最大级次 |
| 审批轮次 | 当前审批轮次 | 数量 | 提交后必填 | 首次提交为第 1 轮，驳回重提递增 |
| 提交来源 | 内部或外部提交 | 枚举 | 是 | 见 §12 |
| 提交人 | 内部提交人 | 人员 | 内部单必填 | 取登录态；外部单为空 |
| 提交人部门 | 内部提交人所属部门 | 组织 | 内部单必填 | 取登录态；外部单为空 |
| 外部提交人姓名、部门、手机号 | 外部人手填身份信息 | 文本 | 外部单必填 | 自由文本，不关联系统账号与部门，见 [other-rule-public-link.md §3](../需求外链管理/references/other-rule-public-link.md#3-外部提交字段边界) |
| 来源外链 | 产生外部单的外链 | 引用 | 外部单必填 | 邀约人即该外链的生成人 |
| 提交时间 | 最近一次提交时间 | 时间 | 提交后必填 | 驳回重提时覆盖；首次提交时间以审批流水为准 |
| 驳回原因 | 最近一次驳回意见 | 长文本 | 否 | 历史意见按轮次见审批流水 |
| 关联卡片编号 | 关联的排期卡片 | 引用 | 否 | 功能类需求关联后写入，解除关联时清空 |
| 关联工单号 | 缺陷修复单对应的黑灯工厂工单 | 引用 | 否 | 建单成功后写入，不占关联卡片编号 |
| 流程实例 | 关联的流程中心实例 | 引用 | 否 | 未关联即自研通道单 |
| 删除标记 | 草稿删除标识 | 布尔 | 是 | 仅草稿可删，逻辑删除 |

## 12. 枚举

| 枚举 | 取值 |
|------|------|
| 需求类型 | 新功能 `NEW_FEATURE` / 功能优化 `OPTIMIZE` / 缺陷修复 `BUGFIX` / 数据报表 `REPORT` / 系统集成 `INTEGRATION`；不设「其他」 |
| 优先级 | `P0` 紧急 / `P1` 高 / `P2` 中 / `P3` 低 |
| 提交来源 | 内部 `INTERNAL` / 外部 `EXTERNAL` |
| 需求状态 | 见 [state-machine.md §2](state-machine.md#2-状态定义) |
| 审批级次 | 见 [state-machine.md §3](state-machine.md#3-级次递进) |
| 快照节点状态 | 待审 / 已通过 / 已驳回 / 已自动跳过 |
