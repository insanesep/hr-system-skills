# 需求工单管理 · App 端 UI 描述

> 本文件承载本功能页面正文；全局约定见 [需求管理 · App 共享 UI](../../references/app-ui.md)，业务与权限规则见 [功能入口](../SKILL.md)。正文为产品目标要求，不以代码缺口删减；原型见本功能资产目录。

## App 员工端

### 端能力边界

App 端开放与仅 Web 可用的能力见 [permission-rules.md §4](../../references/permission-rules.md#4-权限约束)；以下为 App 端的页面表现：

- **外链**：App 无「外链管理」入口，详情页外部提交区块不提供跳外链台账的链接
- **外部提交单**：全程只读 + 可审批，编辑、撤回、重新提交、删除一律不渲染（[state-machine.md §6](../../references/state-machine.md#6-外部提交单差异)）；外部单只出现在「待我审批」「已完成」与详情 Deep-link，不进「我提交的」
- **草稿**：不提供暂存草稿与草稿编辑；「我提交的」可查看 Web 端创建的草稿，详情页不渲染编辑入口，需到 Web 端编辑
- **附件**：仅开放图片上传（相册 / 拍照），文档与视频只展示文件行并提供下载，不提供在线预览；图片选完即上传，未提交就离开时已上传图片不归属任何需求，由存储侧自动清理；不渲染任何审核角标；删除附件与审批中追加均不在 App 端提供，详情页附件区块只读（[other-rule-attachment.md](../../references/other-rule-attachment.md)）
- **预览与下载**：一律使用短时效签名链接，不缓存、不复用、不分享，页面不展示存储永久直链
- **SLA**：SLA 配置与仪表盘不在 App 端提供；App 只承接催办通知的 Deep-link 直达详情页，不展示滞留时长与超时阈值

| 附件类型 | 图标 | 扩展名 | App 端能力 |
|---------|------|-------|-----------|
| 图片 | 图片图标 | jpg / jpeg / png / webp / gif | 可上传（相册 / 拍照）、缩略图网格展示、全屏预览、长按保存 |
| 文档 | 文档图标 | pdf / docx / xlsx / pptx / txt | 不可上传；文件行只读 +「下载」（调起系统能力打开） |
| 视频 | 视频图标 | mp4 / mov | 不可上传；文件行只读 +「下载」 |

### 我的需求列表

- **页面路径**：App 内页面，由菜单 `devhubAppRequirement` 映射进入，无路由参数；具体路由以 App 菜单路由映射为准
- **权限编码**：
  - 菜单：`devhubAppRequirement`
  - 独占：`devhubAppRequirementM`
- **导航方式**：Push（从工作台入口进入）
- **页面类型**：`list`
- **区块职责**：
  - 顶部导航栏：返回 + 标题「需求管理」+ 右侧「提交」文字按钮（具菜单权限时）
  - 顶部 Tab（3 个，吸顶）：
    - **我提交的**：本人提交的全部需求（含草稿）
    - **待我审批**：当前登录人处于快照当前级次的待审需求（含外部单）；Tab 右上角数字角标（> 99 显示 `99+`，为 0 时不展示）
    - **已完成**：已关联排期 + 已驳回的终态需求（按角色可见范围取数，含外部单）
    - 不提供「外部提交」视角，也不提供产品线 / 提交来源筛选器
  - 主体区：卡片列表，每张卡片自上而下：
    - 第一行：标题（最多 2 行，超长省略）；外部单标题前加「外部提交」Tag
    - 第二行：产品线 Tag + 业务线 Tag（有点推荐不渲染）+ 优先级 Tag + 状态标签
    - 第三行：需求编号 + 提交时间（从未提交的草稿展示「未提交」）
    - 「待我审批」卡片额外展示：提交人 + 等待时长（如「已等待 2 天」）；外部单提交人取外部提交人手填姓名，后跟灰字手填部门
    - 整卡可点击 → Push 需求详情
  - 交互：下拉刷新 / 上滑加载更多（每页 20 条）
- **布局引用**：参见原型 [requirement-list.html](../assets/app/requirement-list.html)（整页范例 `busyming-skills-design/mobile/templates/list.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/list-page.tsx.tpl`）

#### 导航关系

- 来源页：工作台「设置」分组下的「需求管理」入口
- 去向页：需求详情（点卡片）、需求提交（点右上角「提交」）
- 返回行为：导航栏返回按钮 Pop 回工作台
- 手势返回：允许（Pop 回工作台）

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| Tab 切换 | 点击 Tab | 否 | 列表骨架屏（3 张占位卡片） | 列表按视角刷新，页码重置为 1 → 停留 | AcToast error「加载失败」+ 保留原 Tab，列表区「点击重试」 |
| 下拉刷新 | 下拉手势 | 否 | 顶部刷新指示器 | 列表刷新 + 待我审批角标同步更新 → 停留 | AcToast error「刷新失败，请重试」，可再次下拉 |
| 上滑加载更多 | 滚动到底部且有下一页 | 否 | 底部加载指示器 | 追加数据；无更多时展示「没有更多了」→ 停留 | 底部 inline「加载失败，点击重试」 |

#### 列表三态

- **空态**：我提交的「你还没有提交过需求」+「立即提交」；待我审批「暂无待你审批的需求」；已完成「暂无已完成的需求」
- **加载态**：卡片骨架屏（3 张占位卡片）
- **错误态**：错误插图 +「点击重试」

#### 交互约束

- 或签同级他人先处理后，本人「待我审批」列表项自动消失，角标同步减一
- 从详情页审批成功 Pop 回列表时必须刷新「待我审批」角标

### 需求详情

- **页面路径**：App 内页面，以需求标识为参数直达，支持企微消息 Deep-link；具体路由以 App 菜单路由映射为准
- **权限编码**：
  - 菜单：`devhubAppRequirement`
  - 独占：`devhubAppRequirementM`
- **导航方式**：Push
- **页面类型**：`detail`
- **区块职责**（自上而下）：
  - 顶部导航栏：返回 + 标题「需求详情」
  - 需求信息卡：需求编号 + 状态标签（外部单另加「外部提交」Tag）/ 标题 / 描述（纯文本，超过 5 行折叠「展开全部」）/ 提交对象（产品经理姓名；外部单 L3 通过前展示灰字「待产品确认通过后归集」）/ 产品线 / 业务线（有点推荐不渲染该行）/ 优先级 / 需求类型 / 目标完成日期 / 提交人 / 提交时间
    - 已驳回时卡片顶部红色提示条展示最近一次驳回人与驳回意见全文；外部单追加「外部提交单驳回即终态，不可重新提交」
  - 外部提交卡（仅外部单，置于需求信息卡下方）：标题「外部提交信息」+「外部提交」Tag；只读信息行：提交人姓名 / 所属部门（后跟灰字「手填，未关联组织架构」）/ 手机号（支持长按复制或点击拨号，仅供内部人员人工回访）/ 提交时间 / 邀约人姓名；不提供外链台账跳转、转内部单、代撤回
  - 附件卡（置于外部提交卡下方）：
    - 标题「附件（N）」；N = 0 时展示灰字「无附件」占位行，不隐藏卡片
    - 图片组：缩略图网格（每行 3 张、正方形裁切），按上传时间正序；超过 9 张时展示前 9 张，末位叠加「+N」，点击展开全部；缩略图右下角小字展示上传来源，外部单图片打「外部上传」角标
    - 点击缩略图 → 全屏图片浏览器（左右滑动切图、双指缩放、顶部「M/N」计数、点击空白或下滑关闭）
    - 长按缩略图或全屏图 → 底部操作面板「保存到相册」/「查看大图」/「取消」；首次保存申请相册写入权限，被拒时提示「请在系统设置中开启相册权限」
    - 文档 / 视频组：纵向文件行（类型图标 + 文件名中间省略保留扩展名 + 文件大小 + 右侧「下载」）
    - 🚨 卡内不渲染任何上传、追加、删除按钮
  - 审批时间线（纵向卡片式）：按审批链快照渲染 1~3 个节点，级次由提交时命中的链决定
    - 每节点：级次名称 / 角色 / 审批人（或签未动作时展示「张三、李四（或签）」，已动作展示实际动作人）/ 状态 / 审批意见 / 操作时间
    - 当前节点高亮并带「审批中」角标；已通过、未开始、已驳回按状态语义区分；自动跳过节点展示「已自动跳过」+ 说明，外部单不会出现自动跳过
    - 内部单产品确认节点的审批人即提交对象
    - 驳回重提按轮次分组：默认展示最新一轮，历史轮次折叠为「查看第 N 轮审批记录」；外部单只有一轮，不渲染分组入口
  - AI 方案确认卡（置于审批时间线下方、排期关联卡上方）：
    - 🚨 仅当前级次审批人与管理员渲染，提交人与其他角色一律不渲染，可见性由服务端收口（[other-rule-ai-plan.md §1](../../references/other-rule-ai-plan.md#1-定位与红线)）；无方案记录时不渲染
    - 标题「AI 方案确认」+ 状态标签（生成中 / 待确认 / 已确认 / 已作废 / 生成失败）+ 版本「V{N}」
    - 生成中：卡内加载占位 + 文案「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批」；每 5 秒刷新一次状态，离开页面即停止
    - 待确认：三段式确认摘要（① 业务诉求 ② 方案完成内容 ③ 信息缺口与建议补充），超过 8 行折叠「展开全部」；「方案全文（七步分析）」点击 Push 到只读子页
    - 生成失败：红色提示条「AI 方案生成失败：{失败原因}」+「重新生成」+ 旁注「不影响您人工审批」
    - 已作废：卡片置灰只读 +「该方案已作废（需求已被处理），仅供回顾」，不渲染操作按钮
    - 卡片底部操作（仅待确认且当前用户为当前级次审批人）：「确认并通过」（全宽主按钮）/「请求补充材料」（次按钮）/「重新生成」（文字按钮）
  - 排期关联卡（只读）：
    - 已关联：卡片编号 + 开发状态标签 + 排期日期 + 开发人
    - 未关联：灰字「待关联排期」（App 不提供关联与解除入口，需到 Web 端操作）
    - 卡片已失效：黄色提示条「关联卡片已失效，请到 Web 端重新关联」
    - 缺陷修复单替换为黑灯工厂工单区：工单号 + 工单状态 + 负责人（只读回传，[business-rule.md §2](../../references/business-rule.md#2-缺陷修复需求分流)）
  - 底部操作栏（吸底，位于安全区内）：
    - 当前审批人：通过（主按钮）/ 驳回（危险次按钮），左右等宽
    - 提交人（已驳回）：重新提交（全宽主按钮）
    - 提交人（已提交 / 业务线审批中）：撤回（全宽次按钮）
    - 外部单只渲染审批类按钮；非审批人进入外部单详情时不渲染操作栏；无可执行操作时不渲染操作栏并回收底部内边距
- **布局引用**：参见原型 [requirement-detail.html](../assets/app/requirement-detail.html)（整页范例 `busyming-skills-design/mobile/templates/detail.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/detail-page.tsx.tpl`）

#### 导航关系

- 来源页：我的需求列表（点卡片）；企微个人消息与业务群消息内详情链接（Deep-link）
- 去向页：需求提交（已驳回时点「重新提交」，原内容预填）；方案全文只读子页（AI 方案卡内）；撤回成功后 Pop 回我的需求列表
- 返回行为：导航栏返回按钮 Pop 回我的需求列表，并触发列表刷新与角标更新；Deep-link 进入时返回至工作台
- 手势返回：允许；半屏输入打开时先关闭半屏，不直接 Pop

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 通过 | 当前登录人在快照当前级次审批人清单内 | 通过确认半屏「确认通过该需求？通过后流转至下一节点」，含可选审批意见与优先级 | 半屏确认按钮 loading + disabled | AcToast「已通过，需求流转至{下一节点名称}」→ 关闭半屏，停留并刷新详情与时间线 | AcToast error（「你不是当前节点审批人」时强制刷新详情）+ 输入保留 + 按钮恢复 |
| 驳回 | 同上 | 驳回意见半屏（必填 10–200 字）+ 底部「确认驳回」 | 半屏确认按钮 loading | AcToast「已驳回，需求已退回提交人」（外部单为「已驳回，外部提交单为终态，已通知邀约人」）→ 关闭半屏，刷新详情 | 半屏顶部错误提示 + 意见保留 + 按钮恢复 |
| 确认并通过 | 当前级次审批人 + AI 方案待确认 | 意见确认半屏（AI 预填可编辑，必填 10–200 字）+「确认通过」 | 半屏确认按钮 loading | AcToast「已确认方案并通过，需求进入待关联排期」→ 关闭半屏，刷新详情 | 半屏顶部错误提示（方案失效时强制刷新详情）+ 意见保留 + 按钮恢复 |
| 请求补充材料 | 当前级次审批人 + AI 方案待确认 | 补材编辑半屏（信息缺口预填，必填 10–500 字；标题提示「以下内容将发送给提交人」） | 半屏确认按钮 loading | AcToast「补材请求已发送给提交人」→ 关闭半屏，刷新 AI 方案卡 | 半屏顶部错误提示 + 文案保留 + 按钮恢复 |
| 重新生成方案 | 当前级次审批人 + 产品确认中 + 已开启 AI 辅助 | AcConfirmSheet「将重新分析并生成新版本方案，确认？」 | 卡片局部 loading，转为生成中 | 卡片切换为生成中并开始刷新状态，无提示 → 停留 | AcToast error + 卡片恢复原态 |
| 撤回 | 提交人本人 + 已提交 / 业务线审批中 | AcConfirmSheet「撤回后需求回到草稿、审批链作废，确认撤回？」 | 按钮 loading | AcToast「需求 {编号} 已撤回至草稿」→ 1.5s 后 Pop 回列表 | AcToast error（「需求已进入实施确认，不可撤回」时刷新详情）+ 按钮恢复 |
| 刷新排期状态 | 进入页面自动加载 | 否 | 排期区局部骨架 | 卡片状态与排期日期更新，无提示 → 停留 | 排期区 inline「排期状态获取失败，点击重试」，不阻断其余内容 |
| 预览图片 | 点击附件区缩略图 | 否 | 全屏浏览器内图片加载占位 | 打开全屏图片浏览器，无提示 → 停留 | 浏览器内 inline「图片加载失败，点击重试」，不关闭浏览器 |
| 保存图片到相册 | 长按后选「保存到相册」 | 否（底部操作面板本身即确认） | 半透明蒙层 loading | AcToast「已保存到相册」→ 停留 | AcToast error（无权限时为「请在系统设置中开启相册权限」），可重试 |
| 下载文档 / 视频 | 点击文件行「下载」 | 否 | 行内进度指示器 | 下载完成后调起系统能力打开，无提示 → 停留 | AcToast error「下载失败，请重试」（签名链接失效时自动重新签发一次） |

- 「重新提交」为跳转：Push 到需求提交页并预填原内容，在提交页校验后提交

#### 表单校验

**通过确认半屏**

- 初态：审批意见为空；优先级预填需求当前值

| 字段名 | 必填 | 校验规则 | 触发时机 | 错误文案 | 异步? |
|--------|-----|---------|---------|---------|------|
| 审批意见 | 否 | 选填，不超过 200 字，实时字数「N/200」 | blur | 「审批意见不超过 200 字」 | 否 |
| 优先级 | 是 | 选项组（P0 紧急 / P1 高 / P2 中 / P3 低），默认当前值，可调整（[business-rule.md §1.3](../../references/business-rule.md#13-流程约束)） | change | 「请选择优先级」 | 否 |

- 提交成功跳转：关闭半屏，停留本页并刷新，无延迟
- 提交失败展示：页面顶部 AcToast error（持续 3s），输入保留
- 脏数据离开：本场景不需要（意见选填、优先级有默认值）

#### 交互约束

- 审批操作响应 ≤ 3 秒；请求超时**不解锁按钮**，AcToast「审批处理中，请勿重复点击，稍后到列表查看结果」
- 审批操作幂等：重复提交返回当前状态而非报错，页面静默刷新详情
- 外部单驳回只通知邀约人（[other-rule-public-link.md §5](../../需求外链管理/references/other-rule-public-link.md#5-单向收口)）
- 附件区块加载失败不阻断详情页与审批操作：区块内 inline「附件加载失败，点击重试」，底部操作栏正常可用

### 需求提交

- **页面路径**：App 内页面，无路由参数；从详情页「重新提交」进入时以需求标识为参数预填；具体路由以 App 菜单路由映射为准
- **权限编码**：
  - 菜单：`devhubAppRequirement`
  - 独占：`devhubAppRequirementM`
- **导航方式**：Push
- **页面类型**：`form`
- **区块职责**：
  - 顶部导航栏：返回 + 标题「提交需求」
  - 表单（分组卡片）：
    - 需求信息组：标题（单行）、描述（多行，下方灰字引导「请说明业务背景、当前痛点与期望效果，描述越完整通过率越高」）
    - 归属与分级组：产品线、所属业务线（选「有点推荐」时整行隐藏）、提交对象（产品经理，紧随业务线，点击打开人员搜索半屏）、需求类型、优先级、目标完成日期
    - 审批链预览（只读，归属与分级组末尾）：选定提交对象后实时预检，灰字展示将命中的链（来源「专属链」+ 级次与各级审批人，如「L1 业务线审批 → L3 产品确认（提交对象）」）；未命中任何配置时红字「当前归属未配置审批链，请联系管理员」且提交按钮置灰
    - 图片附件组（表单末尾）：标题「图片（N/20）」+ 灰字「选填」；限制说明「支持 jpg/png/webp/gif，单张 ≤10MB，最多 20 张」；九宫格编辑网格（每行 3 个）：已选缩略图 + 右上角删除叉标，末位为「+」添加卡（达 20 张时置灰）；点「+」弹底部操作面板「拍照」/「从相册选择」（支持多选）/「取消」，首次使用申请相机或相册权限，被拒时提示「请在系统设置中开启{相机/相册}权限」；上传中缩略图叠加半透明层 + 环形进度，单张失败置红边 + 中心感叹号，点击单张重试；分组底部灰字「需上传文档或视频请到 Web 端操作」
  - 底部固定操作栏（安全区内）：提交（全宽主按钮）；不提供暂存草稿
  - **本页仅用于内部提交**：提交人与部门取登录态，不提供任何手填提交人或部门的入口
- **布局引用**：参见原型 [requirement-submit.html](../assets/app/requirement-submit.html)（整页范例 `busyming-skills-design/mobile/templates/form.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/app/form-grouped.tsx.tpl`）

#### 导航关系

- 来源页：我的需求列表右上角「提交」；需求详情已驳回时「重新提交」
- 去向页：提交成功后 Pop 回我的需求列表
- 返回行为：导航栏返回按钮 Pop 回来源页；有脏数据时先弹确认
- 手势返回：有脏数据时禁止直接手势返回，弹 AcConfirmSheet「你有未提交的内容，确认离开？」

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 选择提交对象 | 已选产品线与业务线，点击选择项 | 否 | 人员搜索半屏内列表加载 | 半屏关闭并回填选中值，同时刷新审批链预览 → 停留 | 半屏内 inline「加载失败，点击重试」 |
| 添加图片 | 点「+」卡且已选少于 20 张 | 否（底部操作面板选源） | 缩略图位蒙层 + 环形进度 | 进度跑满后取消蒙层并计数 +1，无提示 → 停留 | 单张置红边 + 中心感叹号，点击单张重试；超张数 / 超大小 / 格式不支持时 AcToast error 原样展示服务端文案，已上传成功的图片不回退 |
| 删除已选图片 | 点缩略图右上叉标 | AcConfirmSheet「确认移除该图片？」 | 缩略图位 loading | 网格重排 + 计数 -1，无提示 → 停留 | AcToast error「移除失败，请重试」，缩略图保留 |

#### 表单校验

- 初态：
  - 新建：提交对象为空（必选，无默认值）；优先级默认 `P2 中`；产品线默认鸣鸣很忙；业务线按当前登录人所属组织预填（可改）；其余字段为空
  - 从详情页「重新提交」进入：全字段预填原需求内容；提交对象回填原值、允许更换（更换后按新对象重新匹配审批链）；产品线与所属业务线只读；顶部展示驳回意见提示条
