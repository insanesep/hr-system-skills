# 需求工单管理 · Web 端 UI 描述

> 本文件承载本功能页面正文；全局约定与跨页导航见 [需求管理 · Web 共享 UI](../../references/web-ui.md)，业务与权限规则见 [功能入口](../SKILL.md)。正文定义产品交互要求；原型见本功能资产目录，仅作视觉参考。

### 需求列表页

- **菜单名称**：需求工单管理（侧边菜单与页面标题取此名）
- **页面路径**：`/requirement/list`；视角（view）与产品线、业务线支持地址参数带入（供看板下钻），其余筛选与页码不入地址
- **route.name**：`devhubRequirementList`；`/subapp/devhub` 仅为部署 base
- **权限编码**：
  - 菜单资源码：`devhubRequirementList`
  - 按钮：`devhubRequirementCreate`（新增需求）、`devhubRequirementWithdraw`（撤回）、`devhubRequirementDelete`（删除草稿）、`devhubRequirementExport`（导出），控制范围见 [permission-rules.md §1](../../references/permission-rules.md#1-权限编码)
- **页面类型**：`order-list`
- **页面定位**：一屏回答「需求谁提的、卡在哪级、有没有排上开发」
- **区块职责**：
  - KPI 统计卡（4 张横排，点击下钻，各卡带「?」口径悬浮说明）：待提交数（本人草稿数，点击切「我提交的」视角并筛选草稿）/ 待我审批数（当前登录人处于快照当前级次的待审数，点击切至「待我审批」视角）/ 已通过数（待关联排期 + 已关联排期合计；点击回填「待关联排期」筛选）/ 已驳回数（点击筛选已驳回）；取数跟随当前角色可见范围
  - 视角 Tab：我提交的 / 待我审批（带待办数角标）/ 外部提交 / 滞留需求 / 全部
    - 五个视角对所有进入页面的用户渲染，不做角色裁剪；数据可见范围由服务端按角色裁剪（[permission-rules.md §3](../../references/permission-rules.md#3-数据可见范围)），「外部提交」与「全部」对无他人需求可见范围的角色表现为空数据
    - 支持以地址参数带入：`view`（视角，非法值回退「全部」）、`productLine`、`bizLine`（供 SLA 看板下钻）；「滞留需求」筛选口径与排序见 [other-rule-sla.md §5](../../references/other-rule-sla.md#5-滞留需求看板)
  - 筛选区：
    - 状态：下拉单选（草稿 / 已提交 / 业务线审批中 / 实施确认中 / 产品确认中 / 待关联排期 / 已关联排期 / 已驳回），默认全部
    - 产品线：下拉单选（鸣鸣很忙 / 有点推荐），置于业务线之前
    - 所属业务线：下拉单选（运营 / 财务 / 供应链 / 数字化）；产品线选「有点推荐」时置灰并清空
    - 需求类型：下拉单选（新功能 / 功能优化 / 缺陷修复 / 数据报表 / 系统集成）
    - 优先级：下拉单选（P0 紧急 / P1 高 / P2 中 / P3 低）
    - 关键词：输入框模糊搜索标题与编号，回车触发
    - 操作：查询 / 重置（清空除视角外全部筛选并重新查询）
  - 操作区：新增需求（主按钮）/ 导出
  - 主体区：数据表格，列定义如下

| 列名 | 取值说明 |
|------|---------|
| 需求编号 | `REQ-{YYYYMMDD}-{NNN}`，等宽字体链接样式，点击进详情；外部单编号后跟「外部提交」Tag；从未提交的草稿展示 `—` |
| 标题 | 超长省略 + 气泡提示全文 |
| 产品线 | 产品线 Tag |
| 所属业务线 | 业务线 Tag；有点推荐行展示 `—` |
| 提交人 | 内部单展示提交人姓名；外部单展示外部提交人手填姓名，副行展示手填部门 +「外部」 |
| 当前状态 | 状态标签 |
| 当前审批人 | 快照当前级次审批人，多人顿号拼接 + 气泡提示；草稿与终态展示 `—` |
| 附件 | 📎 + 附件数量；无附件展示 `—`；「滞留需求」视角不展示本列 |
| 优先级 | 优先级 Tag |
| 关联排期 / 工单 | 功能类：关联卡片编号链接（页内跳功能排期卡片详情），未关联展示 `—`；缺陷修复单：黑灯工厂工单号纯文本，未建单展示 `—` |
| 提交时间 | `YYYY-MM-DD HH:mm` |
| 操作 | 查看详情 / 编辑 / 撤回 / 删除；「滞留需求」视角另有「手动催办」 |

- **「滞留需求」视角独立列集**：需求编号 / 标题 / 产品线 / 优先级 / 当前状态 / 停留时长（当前级次停留时长，≥ 48h 换算「N 天 M 小时」）/ 滞留级次（业务线审批 / 实施确认 / 产品确认）/ 提交时间 / 操作（含「手动催办」）
- **操作列可见性**：
  - 查看详情：全部行可见
  - 编辑 / 撤回 / 删除：仅「我提交的」视角的内部单行展示（列表无行级权限标记，服务端二次校验）
  - 编辑：草稿或已驳回，点击进需求提交页编辑态
  - 撤回：审批中四态（已提交 / 业务线审批中 / 实施确认中 / 产品确认中）
  - 删除：仅草稿；已提交需求不提供删除入口
  - 手动催办：「滞留需求」视角全部行；无前端权限点，由服务端按管理员口径拦截
  - 单行按钮超过 3 个时第 4 个起收入「更多」
- **分页**：默认 20 条/页，页大小档位取分页组件默认集（10 / 20 / 30 / 40 / 50 / 100），展示总条数
- **布局引用**：参见原型 [requirement-list.html](../assets/web/requirement-list.html)（整页范例 `busyming-skills-design/web/templates/order-list.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/web/list-page.vue.tpl`）

#### 导航关系

- 来源页：侧边菜单「需求管理 / 需求工单管理」；需求提交页暂存或提交成功后跳回；SLA 仪表盘点击「超时率」跳入「滞留需求」视角；企微个人消息与群消息中的详情链接先鉴权再定向至需求详情页
- 去向页：需求详情页（点编号或「查看详情」）、需求提交页（点「新增需求」，或点「编辑」进入编辑态）、功能排期卡片详情页（点卡片编号，页内跳转）
- 返回行为：模块入口页，无上级返回；从详情页、提交页经面包屑「需求工单管理」或浏览器后退返回时恢复原视角、筛选与页码
- 产品目标面包屑：首页 / 研发 / 需求管理 / 需求工单管理

#### 操作反馈清单

| 操作名 | 触发条件 | 二次确认? | Loading 形式 | 成功反馈+去向 | 失败反馈+重试 |
|--------|---------|----------|-------------|-------------|-------------|
| 查询 | 无（可空条件） | 否 | 表格区加载指示 | 表格刷新，信息条展示「共 N 条」→ 停留 | AcMessage.error「需求列表加载失败，请重试」+ 表格错误态「点击重试」 |
| 重置 | 无 | 否 | 表格区加载指示 | 清空除视角外全部筛选并重新查询 → 停留 | 同查询 |
| 视角切换 | 点击 Tab | 否 | 表格加载指示 | 表格按视角刷新，页码重置为 1 → 停留 | AcMessage.error「加载失败，请重试」+ 保留原视角 |
| KPI 下钻 | 点击任一 KPI 卡 | 否 | 表格区加载指示 | 视角与筛选条件回填并刷新，被选卡片高亮 → 停留 | AcMessage.error「加载失败，请重试」+ 筛选恢复原值 |
| 撤回 | 「我提交的」视角 + 内部单 + 审批中四态 | AcPopconfirm「撤回后需求回到草稿、审批链作废，确认撤回？」 | 按钮 loading + disabled | AcMessage.success「需求 {编号} 已撤回至草稿」→ 停留并刷新当前页 | AcMessage.error（服务端返回「需求已进入实施确认，不可撤回」时同步刷新行状态）+ 按钮恢复 |
| 删除草稿 | 「我提交的」视角 + 内部单 + 草稿 | AcPopconfirm「删除后该草稿不可恢复，确认删除？」 | 按钮 loading + disabled | AcMessage.success「草稿已删除」→ 停留并刷新当前页，待提交数同步减一 | AcMessage.error（服务端返回「需求已提交，不允许删除」时同步刷新行状态）+ 按钮恢复 |
| 导出 | 具导出权限且当前筛选有结果 | 否 | 按钮 loading | AcMessage.success「导出任务已提交，请在下载中心查看」→ 停留 | AcMessage.error「导出失败，请重试」+ 按钮恢复 |
| 手动催办 | 「滞留需求」视角 | AcPopconfirm「将向当前审批人发送企微催办消息，确认催办？」 | 按钮 loading + disabled | AcMessage.success「已向当前审批人发送催办」→ 停留并刷新该行 | 去重窗口命中时 AcMessage.warning「去重窗口内已催办过，本次未重复发送」；其余失败 AcMessage.error + 按钮恢复 |

#### 表格三态

- **空态**：当前筛选无数据 → 空状态插图 +「暂无符合条件的需求」；「滞留需求」视角改为「很好，当前没有超时未处理的需求」
- **加载态**：表格骨架屏（10 行占位）
- **错误态**：表格区错误插图 +「点击重试」

### 需求详情页

- **菜单名称**：非菜单详情页，归需求工单管理；实际路由标题为「需求详情」
- **页面路径**：`/requirement/detail/:id`，以需求标识为路径参数直达；企微消息链接直达本页
- **route.name**：`devhubRequirementDetail`，不是父菜单资源码 `devhubRequirementList`
- **权限编码**：
  - 所属菜单资源码：`devhubRequirementList`（服务端按可见范围二次校验，越权时展示「无权查看该需求」）
  - 按钮：`devhubRequirementApprove`（通过）、`devhubRequirementReject`（驳回）、`devhubRequirementLinkCard`（关联与解除排期）、`devhubRequirementResubmit`（重新提交）、`devhubRequirementWithdraw`（撤回），控制范围见 [permission-rules.md §1](../../references/permission-rules.md#1-权限编码)
- **页面类型**：`order-detail`
- **区块职责**（自上而下）：
  - 需求信息卡：
    - 主标题行：需求编号（草稿展示「未提交草稿」）+ 标题 + 当前状态标签 + 外部单「外部提交」Tag
    - 信息栅格：描述（保留换行）/ 提交对象（产品经理姓名；外部单 L3 通过前展示灰字「待产品确认通过后归集」）/ 产品线 / 业务线（有点推荐展示 `—`）/ 优先级 / 需求类型 / 目标完成日期 / 提交人 / 提交时间
    - 编辑不放在本卡：草稿或已驳回的修改入口为列表行「编辑」与本页底部「重新提交」，跳需求提交页
    - 已驳回时卡片顶部红色警示条展示最近一次驳回人与驳回意见全文；外部单追加一行「外部提交单驳回后为终态，不支持重提；如仍有价值请新建内部单并引用本编号溯源」
  - 外部提交区块（仅外部单渲染，置于需求信息卡下方）：
    - 标题「外部提交信息」+「外部提交」Tag
    - 信息栅格：提交人姓名 / 所属部门（后跟灰字「手填，未关联组织架构」）/ 手机号（前端脱敏展示，形如 `138****1234`）/ 提交时间
    - 邀约溯源行：邀约人姓名 + 邀约对象备注 +「来源外链」链接（跳外链管理页，在台账中按提交进度反查）
    - 手机号仅内部可见、仅供内部联系，系统不向外部提交人发送任何短信或通知（[other-rule-public-link.md §5](../../需求外链管理/references/other-rule-public-link.md#5-单向收口)）；区块内不提供向外部回复、转内部单、代撤回按钮
  - 附件区块（置于外部提交区块之下）：
    - 区块内列出全部附件：文件名链接 + 文件大小 + 上传人 + 上传时间；审批中追加的附件带「审批中追加」标签
    - 点击文件名获取签名链接新窗口打开（链接有效期 1 小时，每次点击重新获取）；不提供页内预览层
    - 🚨 详情页不提供上传、追加与删除附件入口（Web 端附件来源为公开 H5 外部提交上传）
    - 无附件时显示灰字「无附件」；外部单附件（H5 上传的图片）同样展示，上传人列展示外部提交人手填姓名
  - AI 方案确认面板（置于附件区块之下、审批时间线之上）：
    - 存在方案记录时渲染（取当前审批轮次最高版本）；可见性与数据下发由服务端判定（[other-rule-ai-plan.md §1](../../references/other-rule-ai-plan.md#1-定位与红线)）；面板内操作仅当前级次审批人与管理员可点
    - 面板标题「AI 方案确认」+ 状态标签（生成中 processing / 待确认 warning / 已确认 success / 已作废 default / 生成失败 danger）+ 版本号「V{N}」+ 触发方式标签（自动触发 / 手动触发）
    - 生成中：面板内提示「AI 方案生成中，通常 1–3 分钟；您也可以直接人工审批，AI 结果将自动作废」；页面不自动轮询，刷新页面获取最新状态
    - 待确认：主区域渲染三段式确认摘要（① 业务诉求是什么 ② 本次方案完成了什么 ③ 信息缺口与建议业务补充的内容）；下方折叠「方案全文（七步分析）」；信息缺口以清单列出
    - 生成失败：红色警示条「AI 方案生成失败：{失败原因}」+「重新生成」+ 灰字「不影响您人工审批」
    - 已作废：面板置灰只读，顶部提示「该方案已作废（需求已被处理），仅供回顾参考」，不渲染操作按钮
    - 底部操作（仅待确认且当前用户为当前级次审批人时可点）：「确认并通过」（主按钮）/「请求补充材料」（次按钮，已发出过时旁侧灰字「已于 {时间} 发出」）/「重新生成方案」（文字按钮）
  - 审批进度时间线：
    - 纵向步骤条渲染「提交申请（发起）→ 按审批链快照的 1~3 个级次节点」，级次集合由提交时命中的链决定（默认链为业务线审批 → 实施确认 → 产品确认，专属链可缺级）
    - 每节点：级次名称 / 审批人（或签未动作时展示全部候选人「张三、李四（或签）」，已动作展示实际动作人 + 候选人列表）/ 节点状态（待审 / 已通过 / 已驳回 / 已自动跳过）/ 审批意见（驳回意见红显）/ 操作时间 / 「用时 X 小时 Y 分」
    - 级次节点聚合规则：任一通过 → 已通过；任一驳回 → 已驳回；全部跳过 → 已自动跳过；否则待审
    - 当前待审节点高亮并带「当前节点」角标
    - 草稿态展示「草稿态尚未生成审批链快照，提交后展示审批进度」
    - 驳回重提按审批轮次分组：默认展示最新一轮，历史轮次折叠为「查看第 N 轮审批记录」
    - 内部单产品确认节点的审批人即提交对象
  - 排期关联区：
    - 未关联且待关联排期：黄色警示「需求已通过全部审批，待关联排期卡片」+「关联排期」按钮（当前用户为该需求的产品经理或管理员时可操作，其余角色仅见提示）
    - 未关联且其余状态：灰字「未关联排期卡片（全级审批通过后进入「待关联排期」，由产品经理或管理员关联）」
    - 已关联：卡片编号（页内跳功能排期卡片详情）/ 卡片标题 / 排期日期区间 / 开发状态标签 / 开发人 +「解除关联」（权限同关联）
    - 卡片已被删除（关联仅余编号）：黄色警示条「关联卡片已失效，请重新关联」+「重新关联」
    - 开发状态实时读取功能排期，本模块只读不回写
    - **缺陷修复单整区替换为「黑灯工厂工单」区**（[business-rule.md §2](../../references/business-rule.md#2-缺陷修复需求分流)）：不渲染关联与解除按钮；已转单展示「已转黑灯工厂工单」+ 工单号与优先级（纯文本）；待关联排期状态展示「已通过全部审批，待系统转黑灯工厂建单」；更早状态展示「缺陷修复单审批通过后将由系统转黑灯工厂建单，无需关联排期」
  - 底部固定操作栏：
    - 当前审批人：通过（主按钮）+ 驳回（危险按钮），栏内提示「您是当前节点审批人；审批类操作幂等，重复提交返回当前状态。」
    - 提交人（已驳回，非外部单）：重新提交（跳需求提交页重提态修改后再提交）
    - 提交人（已提交 / 业务线审批中，非外部单）：撤回
    - 外部单只渲染审批人的「通过 / 驳回」，重新提交与撤回永不渲染
    - 无可执行操作时不渲染操作栏
- **布局引用**：参见原型 [requirement-detail.html](../assets/web/requirement-detail.html)（整页范例 `busyming-skills-design/web/templates/order-detail.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/web/detail-page.vue.tpl`）

#### 导航关系

- 来源页：需求列表页（点编号或「查看详情」）；企微个人消息与群消息中的详情链接
- 去向页：需求提交页重提态（点「重新提交」）；功能排期卡片详情（点卡片编号，页内跳转）；外链管理页（外部单点「来源外链」）；撤回成功后回需求列表页

### 需求提交页

- **页面形态**：新增、编辑（草稿）、驳回重提三态共用同一表单页，以 `?id=` 需求标识区分编辑与重提；**本页仅用于内部提交**，提交人与部门取登录态，不提供手填入口，外部提交走公开 H5
- **进入守卫**：编辑 / 重提态加载后需求状态非草稿或已驳回时，AcMessage「当前状态不可编辑」并弹回需求详情页
- **菜单名称**：非菜单提交页，归需求工单管理；路由固定标题为「需求提交」，表单按形态展示新增 / 编辑标题，产品目标为「新增需求」或「编辑需求」
- **页面路径**：`/requirement/submit`；编辑与重提态以 `?id=` 携带需求标识直达，所属工单入口为 `/requirement/list`，不是该列表路径下的嵌套路由
- **route.name**：`devhubRequirementSubmit`，不是父菜单资源码 `devhubRequirementList`
- **权限编码**：
  - 所属菜单资源码：`devhubRequirementList`
  - 按钮：`devhubRequirementCreate`（提交审批）、`devhubRequirementSaveDraft`（暂存草稿）、`devhubRequirementResubmit`（驳回重提提交），控制范围见 [permission-rules.md §1](../../references/permission-rules.md#1-权限编码)
- **页面类型**：`order-form`
- **区块职责**：
  - 顶部：页面标题「新增需求」/「编辑需求」；已驳回进入重提时顶部红色警示条展示驳回意见，提示「该需求已被驳回，请按驳回意见修改后重新提交」
  - 表单（单列长表单，卡片分组）：
    - 需求信息组：标题、描述（下方灰字引导「请说明业务背景、当前痛点与期望效果」）
    - 归属与分级组：产品线、所属业务线（选「有点推荐」时整行隐藏）、提交对象（产品经理，紧随业务线）、需求类型、优先级、目标完成日期
    - 审批链预览（只读，归属与分级组末尾）：选定提交对象后系统预检并展示将命中的审批链——来源标签「专属链」+ 级次与各级审批人摘要（形如 `L1 张三/李四 · L2 王五`）；变更提交对象、产品线、业务线、需求类型、优先级后实时刷新；未选中提交对象时占位「选择提交对象后，将展示命中的审批链预览」；未命中任何配置时红色警示条「当前归属未配置审批链，请联系管理员」且「提交审批」置灰
    - 附件组：仅展示说明文案「选填；附件不阻塞提交。附件可在需求详情页追加。」，本页不提供上传入口（Web 端附件能力见全局约定 · 附件展示）
  - 底部固定操作栏：取消（文字按钮）｜ 暂存草稿（次按钮）｜ 提交审批（主按钮）；栏上常驻提示「暂存草稿不生成审批链快照；提交审批后将按提交对象的审批链流转，产品线与业务线不可修改。」
- **布局引用**：参见原型 [requirement-submit.html](../assets/web/requirement-submit.html)（整页范例 `busyming-skills-design/web/templates/order-form.html`；DOM 结构依据 `busyming-skills-design/.skills/page-blueprint/skeletons/web/form-grouped.vue.tpl`）
